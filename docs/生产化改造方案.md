> 不改任何应用代码，只动平台层。

| 改造项 | 本地开发 | Docker 部署 | 影响 |
|---|---|---|---|
| 数据库 | SQLite（本地文件） | PostgreSQL | 应用代码零改动 |

## 一、数据库双模（SQLite ↔ PostgreSQL）

### 新增文件

**`fde_platform/db.py`**（约 150 行）

数据库抽象层，对外暴露 `get_connection(app_name)`：

```
if 配了 DATABASE_URL → 连接 PostgreSQL（用 schema: <组>_<应用名>）
else                 → 连接 SQLite（同名 .db 文件，行为不变）
```

内部负责：
- SQL 方言翻译（`AUTOINCREMENT` → PG `IDENTITY`，`datetime('now')` → `NOW()`）
- 连接池管理（PG 用 `psycopg2.pool.ThreadedConnectionPool`，最小 2 最大 10）
- Schema 自动创建与 `search_path` 限定

### 修改文件

| 文件 | 改动 | 行数 |
|---|---|---|
| `fde_platform/runtime.py` | `_init_app_connection` 里的 `sqlite3.connect()` 换 `db.get_connection()` | ~10 行 |
| `config/.env.example` | 加 `# DATABASE_URL=`（注释掉的，本地不配 = SQLite） | 2 行 |
| `requirements.txt` | 加 `psycopg2-binary>=2.9`（可选，不装 = SQLite） | 1 行 |
| `docker-compose.yml` | 加 postgres 服务 + fde-v2 环境变量 `DATABASE_URL` | ~15 行 |

### 效果

```bash
# 本地：啥也不配，SQLite
python main.py

# Docker：自动走 PG
docker compose up -d   # PG + FDE + nginx 三个容器
```

## 三、Session 密钥（✅ 已完成）

未配置 `SECRET_KEY` 时自动生成随机 64 位 hex 密钥写入 `config/.secret_key`，不在代码里留硬编码回退值。

## 四、Docker 部署 + HTTPS

### 已就绪的文件

| 文件 | 作用 |
|---|---|
| `Dockerfile` | 构建 FDE 镜像 |
| `docker-compose.yml` | 编排 FDE + nginx（+ PG） |
| `nginx.conf` | TLS 终止 + 反向代理 |
| `scripts/gen-cert.sh` | 生成自签证书 |

### 部署方式

| 场景 | 命令 |
|---|---|
| 内网 HTTP | `docker build -t fde-v2 . && docker run ...` |
| HTTPS | `bash scripts/gen-cert.sh && docker compose up -d` |

## 五、待实施：首次登录强制改密

**修改文件：`fde_platform/auth.py` + `fde_platform/users.py`**

逻辑：
1. `users` 表加 `password_changed` 字段（默认 0）
2. admin/admin 播种时 `password_changed = 0`
3. `auth.gate()` 里：已登录但 `password_changed = 0` → 强制跳到 `/change-password` 页
4. 改密后设 `password_changed = 1`

约 40 行代码。
