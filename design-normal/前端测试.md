# 前端测试 · 第⑧步技能规格（生成前端视图测试用例）

> **版本**: v1.1（2026-08-08 粒度重构）  **创建日期**: 2026-08-02
> **适用人员**: 应用构建第⑧步的执行体（AI / 工程师）
> **目的**: 在第⑥步前端设计完成后，**逐应用**基于其《前端详设》各生成**一份**前端测试用例（覆盖该页的渲染 / 列表 / 模态 / 表单 / 本会话 0 报错），另生成**一份组级补充**用例（壳启动与菜单序 / 受限用户菜单收敛 / dashboard 页 / 组级会话 0 报错），供第⑨步逐应用翻译成 playwright 脚本执行。
> **本步只生成「测试用例」（数据/文档），不生成可执行测试脚本、不运行测试**——生成与执行解耦，与后端第④⑤步同一约定；用例文件是第⑨步执行器的唯一接口。

## 🧭 使用契约：作为「前端测试用例生成」技能（应用组构建 · 第⑧步）

### 技能定位（九步法）

```text
第⑥步  前端设计（《前端设计.md》）          _contracts.md + 各应用详设 → 逐应用 前端详设.md + dashboard 设计  ← 已定义
            ↓
第⑦步  前端编码（《前端编码.md》）          前端详设.md → app/<组>/<应用>/view.{js,html}            ← 已定义
            ↓
★第⑧步  前端测试用例（本文件）              逐应用前端详设 → 逐应用 前端测试用例.md + 组级补充一份   ← 本规格
            ↓
第⑨步  前端测试执行（《前端测试执行.md》）  逐应用用例 → app/<组>/tests/verify_view_<组>_<应用>.py + app/<组>/tests/verify_view_<组>.py（0 报错跑通）← 已定义
```

> 第⑧步与「前端测试执行」分离（生成与执行分离）：本步**只生成用例**，由**第⑨步《前端测试执行.md》**把用例逐应用翻译成 playwright 脚本并跑通。用例的**五要素**（见下）即为第⑨步执行器预留的接口。
>
> **粒度（v1.1 重构）**：用例与执行均以**应用为单位**——每应用一份用例、一个脚本，可单独生成、单独跑、单独 triage；天然属于组级的维度（壳/菜单序/受限用户/dashboard）收进**一份薄的组级补充**，覆盖不丢。逐应用用例住应用文件夹（与 应用详设 / 前端详设 / view.* 同处——「一个应用 = 一个文件夹 = 整份交付」），组级补充沿用 `app/<组>/前端测试用例.md` 路径。
>
> **顺序（显式声明）**：与后端 ③④ 顺序一致——**编码（⑦）先于用例（⑧）**，用例逐应用落文件；「生成与执行分离」——本步只生成、执行归第⑨步。

## 用例五要素（每条用例必含，执行器接口）

1. **页面**：断言针对哪个页面（`<组>:<页key>`，如 `sales:sales_order`；看板 `sales:dashboard`）。逐应用文件内恒为本页，可在文件头声明一次、条目内省写；组级补充文件逐条注明。
2. **前置造数**：本断言依赖的数据——经哪些 `应用.服务(参数)` 创建（服务名/参数以 `_contracts.md` 为准），可引用 §0 数据字典；造数走真实 REST（浏览器内 fetch，pitfalls #18），跨应用前置（如订单页需客户/物料）在本字典内自足。
3. **操作**：浏览器动作序列（进入路由 `#/<key>` / 点单号 `b-link` / 填表单字段 / 点按钮 / 切换受限会话）。
4. **断言**：**可机器校验**的期望——DOM 文本含某字段值、列表行数 ≥ 1、模态 KV 含全部业务字段、toast 文案、菜单项集合、**0 报错**。
5. **选择器注意**（按需）：该断言触发的已知陷阱与规避（`:visible` 限定 / `.modal-bd.first` / `wait_modal` 轮询 `.loadbox` 消失 / 精确单号 `has_text`）。

## 覆盖要求（六类断言，按两级分派，缺一即不完整）

| 部分 | 归属 | 内容 |
|---|---|---|
| **§0 测试数据字典** | 逐应用各自一份 + 组级薄字典 | 逐应用：冻结**本页断言所需**的造数标识（含跨应用前置，如 SO 页字典含客户 C001 / 物料 M001 的造数服务），可与后端第④步 `app/<组>/测试用例.md` 的 §0 字典**同源复用**；组级：仅 dashboard 探测与受限会话所需的最小集。 |
| **§1 渲染** | **拆分** | 逐应用：本页路由 `#/<key>` 渲染有内容（`.card` > 0）+ **挂载防粘滞**：非看板页断言 `.kpi` 数 == 0（pitfalls #2）。组级：壳启动（侧栏品牌 / 菜单按 PAGE_META.order 升序）+ dashboard 页渲染断言（KPI / 管道 / 待办区块存在）。 |
| **§2 造数后列表有数据** | 逐应用 | 浏览器内 fetch `/api/apps/<应用>/call/<服务>` 造数（带会话 Cookie，走真实 REST，pitfalls #18）→ 列表含所造单号（精确 `has_text` 定位，不假设顺序，pitfalls #17）+ 搜索条件抽样生效。 |
| **§3 模态全字段** | 逐应用 | 点单号开模态：`wait_modal()` 等 `.loadbox` 消失（pitfalls #16）→ 断言模态含详设 §2.2 列出的**全部业务字段**标签/值（多 `.modal-bd` 用 `.first`，pitfalls #15）→ 页脚按状态的操作按钮可见性。 |
| **§4 表单落库回显** | 逐应用 | 可写应用：填创建表单（详设 §2.3 字段集）→ 提交 → toast 成功 + 列表回显新单；有编辑入口的应用补编辑态断言（键字段 `:disabled`、保存后字段变更回显）。纯回调型应用按详设豁免项。 |
| **§5 受限用户菜单收敛** | **仅组级** | 播种受限角色（仅授「看板 + 一两个应用页 + `_platform:agent`」）→ 新会话登录：菜单收敛为授权集；**直访无授权 hash 路由回落菜单首项**；授权页经 `X-Fde-Page` 隐式放行**仍有数据**（受限会话的 403 属预期执法，豁免报错统计）。角色播种与授权清单是组级配置，不可按应用切分。 |
| **§6 0 报错红线** | 各自会话 | 逐应用文件：本脚本会话全程 0 console error / 0 pageerror / 0 HTTP ≥ 400；组级文件：其会话（壳/菜单/受限）同红线。favicon 除外；受限会话 403 豁免。跨脚本的「整组零干扰」由逐应用脚本各自守红线自然达成。 |

- 用例编号：逐应用文件内用 `VT-<段>-<序号>`（如 `VT-LIST-01` / `VT-MODAL-02` / `VT-FORM-01`，**文件作用域**——triage 报告按脚本名 `verify_view_<组>_<应用>.py` 定位应用）；组级补充文件用段名区分：`VT-SHELL-*`（壳与菜单）/ `VT-DASH-*`（看板页）/ `VT-PERM-*`（受限用户）。

## 编写规则（铁律）

- 造数的服务名/参数名**以 `_contracts.md` 为准**，不臆造不存在的服务/参数。
- 断言必须**可机器校验**（文本包含 / 计数 / 集合相等 / 0 报错），不写「页面正常显示」这类模糊结论。
- **逐应用字典自足**：本脚本运行于独立隔离库（dbguard），不依赖其他脚本造的数据；跨应用前置（客户/物料/手册等）写进本字典。
- **受限角色授权清单与页面集逐字对应**（pitfalls #38）：组级补充 §5 的 `limited_role` 授权清单 = 看板 + 选定的应用页 key（`<组>:<key>` 格式）+ `_platform:agent`；新增/调整页面后本清单与回落断言**必须同步改**——用例里直接写明完整清单，第⑨步逐字搬进脚本。
- 选择器规避逐条标注：隐藏 ≠ 不存在（`:visible` 限定，pitfalls #14）、模态加载态抢跑（#16）——写进用例的「选择器注意」要素，第⑨步不重新踩坑。
- 只输出**结构化 Markdown 正文**（数据用 markdown 表格），不要 ``` 代码围栏包裹整篇。

## 验收标准

- **逐应用文件**：每份含 §0–§4 + §6（纯回调型应用按详设豁免 §4 并注明）；§1 带防粘滞断言；造数服务名/参数名能在 `_contracts.md` 中找到对应（不臆造）；每条用例五要素齐全；断言可机器校验。
- **组级补充文件**：含 §1（壳 + 菜单序 + dashboard）+ §5（受限三连）+ §6；受限角色授权清单与页面集逐字对应；回落断言目标 = 菜单首项。
- **交叉完整性**：逐应用文件集 = 组内全部含 `前端详设.md` 的应用（含指定子集时 = 子集）；菜单序断言列出的 key 集 = 逐应用页面集 ∪ dashboard。
- 数据字典标识前后一致；逐应用字典自足（含跨应用前置）。

## 平台化入口（第⑧步自动化任务）

平台 `/groupbuild` 页面 ⑪ 前端测试（任务 `kind="ftest"`，`fde_platform/groupbuild_runner.py`）
把本步产品化为一键任务：

- `gather`：硬预检 `_contracts.md`（⑧契约冻结屏障，缺 → 失败指回⑧）+ 逐目标应用 `前端详设.md`（缺 → 失败指回⑨）+ 组级 `前端详设/dashboard.md`（缺 → 失败指回⑨，组级补充用例依赖）；组级单元另从各详设 §1 提取 PAGE_META 菜单序总表（VT-SHELL 菜单序断言依据）。
- `gen`：N 应用 job + 1 组级补充 job 摊平并发（`GROUPBUILD_FTEST_PARALLEL` 默认 6）；每 job 输入 = 铁律 preamble（五要素 + 六类两级分派 + 造数服务名以契约为纲 + 禁围栏包裹）+ 本规格全文 + pitfalls 选择器规则 + 本应用前端详设全文 + 契约切片（组级 job：dashboard 详设 + 菜单序总表 + 契约摘要）；门禁（逐应用查六类断言节 + VT 编号 + 五要素标记；组级查 VT-SHELL/VT-DASH/VT-PERM + 授权清单 + 菜单序；整篇围栏包裹判不合格）不过 → 整份重出（≤`GROUPBUILD_FTEST_REPAIR` 轮，默认 2）；失败单元跳过记日志、全败才 raise。
- `write`：逐应用 `app/<组>/<应用>/前端测试用例.md` + 组级补充 `app/<组>/前端测试用例.md`。

API：`POST/GET/DELETE /api/groupbuild/groups/<组>/ftest`（POST body `{app_names?}` 缺省全部已有前端详设的应用；GET `?zip=1` 打包、`/ftest/_group` 下载组级补充）。与手工流程同产物、同规格、可互换。
