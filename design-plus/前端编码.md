## 🧭 使用契约：作为「前端编码」技能（应用组构建 · 第⑦步）

> 本文件是第⑦步技能规格。编码所遵循的前端视图约定（三层结构与生成边界 / 页面自描述 PAGE_META + 默认导出工厂 / 列表·模态·表单解剖结构 / 菜单与授权机制 / 硬性规则 11 条）**全部见 `design-plus/VIEW_CONVENTION.md`**，参考资料见 `design-plus/view-convention/`（architecture / patterns / design-system / pitfalls）。

            ↓

### 必给参数
- 英文应用组名 `<组>`（snake_case），逐字绑定 `app/<组>/`。
- （可选）`<应用名>` 子集：只编码指定的某些应用页；缺省＝组内**全部**已有《前端详设》的应用 + 组级 dashboard。

### 产出（每个应用，落其后端文件夹）
- `app/<组>/<应用>/view.js`——自描述 `PAGE_META` + **默认导出**页面工厂（`Alpine.reactive` 体）。
- `app/<组>/<应用>/view.html`——Alpine 模板片段（列表 / 详情模态 / 表单三段式）。
- **组级看板**：`app/<组>/dashboard.js` + `dashboard.html`（key=`dashboard`，PAGE_META.order 最小；无对应后端应用，故不住应用目录）。
- **不生成、不修改**：`view/lib/`（api / shell / alpine / styles）、`view/pages/`（Agent / 服务台）、平台通用壳 `view_shell.html`、任何后端 `.py`——均为只读环境前提（VIEW_CONVENTION 生成边界）。新组件样式确需扩充时追加在规范表 `fde_platform/static/fde.css`（属公共层演进，**先向用户说明**；勿扩写 `view/lib/styles.css` 别名）。

### 前端详设 → 代码映射
| 前端详设（第⑥步） | → 视图代码（按 VIEW_CONVENTION） |
|---|---|
| §1 PAGE_META | `export const PAGE_META = {key, name, ic, title, crumb, order}`（key=应用名，order 用详设给定值） |
| §2.1 列表区块 | 列表三段式模板 + `pageable()` 分页；搜索控件对应 `self.filter`/`self.keyword`，loader 闭包读当前值（patterns §2） |
| §2.2 详情模态 | 模态三段式：墨青头带（docno + 状态徽章）/ `.kv` 分组体（全字段 + 子账本 + 折叠原始 JSON）/ `.modal-ft` 按状态操作（patterns §3） |
| §2.3 表单区块 | `.collapse` 表单容器 + `save()`（create/update 分流，编辑态键字段 `:disabled`，可选项「更多字段 ▾」折叠）（patterns §4） |
| §3 svc 字面量清单 | 逐项落为 `svc("应用", "服务", {参数})` **字面量**调用（可闭包逐项写，绝不变量拼名）；清单内 `quiet` 项用 `svc(..., {quiet: true})` + `.catch` 零值兜底 |
| §4 数据来源 / 下拉 | 主数据下拉经对应应用 `list` 拉取（quiet 探测）；契约 payload 字段映射进模板 `x-text`/`x-model` |
| §5 交互要点 | 状态驱动 `x-show` 行内动作、模态加载态、toast 反馈；字段顺序统一（单号→状态→归属→数量金额→时间） |

### 编码铁律（详见 VIEW_CONVENTION 与 pitfalls，关键几条）
- 顶部**绝对路径** import：`import { svc, hue, fmt, toast } from "/view/lib/api.js"` + `import { pageable } from "/view/lib/shell.js"`——相对路径迁入应用目录后会断（pitfalls #5）。
- **工厂必须默认导出**：`export default function pageXxx()`（壳读 `mod.default`；漏 `default` 静默坏页，`node --check` 查不出——pitfalls #26）；函数保留 `pageXxx` 专名。
- **必须 `Alpine.reactive({...})`**：裸对象赋值不触发重渲染（pitfalls #3）；状态写 `self` 上、方法里一律 `self.xxx =`，**不用 `this`**。
- **reactive 状态同步先行**：工厂体内一切被模板引用的状态（`tpl`、含空 `items:[]` 的 `list = pageable(...)`、各模态对象）必须在**第一个 `await` 之前**同步建好，再 await 拉数（pitfalls #37）。
- **模板抓取**：`self.tpl = await fetch(new URL("view.html", import.meta.url)).then(r => r.text())`——应用页模板**固定名 `view.html`**（端点只认它；pitfalls #35）；组级页模板与页面同名（`dashboard.html`）。
- **svc 一律字面量**（pitfalls #8）；**页面零鉴权**（不判断权限，401 由 api.js 跳登录）；dashboard 探测性加载必 `quiet`（pitfalls #10）。
- **展示工具统一**：`hue()`/`dash()`/`fmt()`/`fmtTime()`/`tryParse()`，不自造格式化；`dash`/`fmtTime`/`tryParse` 是 window 全局（模板直接用），`hue`/`fmt` 放进 `self`。
- **dashboard 必备**：新建组必产 `app/<组>/dashboard.{js,html}`——缺它壳默认路由静默崩溃（pitfalls #36）。
- **每个 js 写完即 `node --check`**（语法错误最便宜的发现方式；但它查不出漏默认导出，须自检 #26）。

### 收尾衔接
- **零接线**：文件落盘即进启动清单（菜单/路由）与角色授权清单、svc 隐式放行派生边（平台 mtime 缓存，浏览器刷新生效；管理页「重新扫描」立即刷新）。无任何框架文件需要登记。
- 全组页面完成后向用户报告：入口 URL（`http://127.0.0.1:4000/view/<组>/`）+ 页面清单（order 序）+ 待授权提示（受限角色须在管理页授页面）。

### 验收标准（可机器化）
- 每个 `view.js`：`node --check` 通过；含 `export const PAGE_META`（`order` 为数字、显式给定）与 `export default function`；import 全为绝对路径 `/view/lib/*`。
- svc 调用全字面量（`grep -n "svc(" view.js` 逐项可审，无变量拼名/三元拼名）。
- 模板名正确（应用页 `view.html`，组级页同名 html），经 `import.meta.url` 抓取。
- 列表列 ⊆ 详情字段集；表单字段 ＝ 详设 §2.3 可写字段集；字段顺序列表/详情/表单一致。
- dashboard 存在且 quiet 探测 + 零值兜底。
- 未触碰 `view/lib/`、`view/pages/`、`view_shell.html`、后端 `.py`（`git status` 可核）。

### 命名与边界铁律
- 应用页 `PAGE_META.key` 逐字取自应用文件夹名；组级页 key 取自文件名。
- 一个应用 = 一个文件夹 = 前后端整份交付（CONVENTION 核心约定在前端侧的对称体现）。
- 不臆造：详设/契约未说清的字段标「待确认」，不编造区块；详设与契约漂移时回第⑥步修详设。

- **覆盖度门禁**：本步产出须经独立的覆盖度检查——对照本规格规定的上游输入，逐项验证覆盖完整性。覆盖度 < 100% 不得进入下一步。具体门禁条件见 `design-plus/工具链使用说明.md` 对应步骤的「完成门禁」段。

## 平台化入口（第⑦步自动化任务）

平台 `/groupbuild` 页面 ⑩ 前端编码（任务 `kind="fcode"`，`fde_platform/groupbuild_runner.py`）
把本步产品化为一键任务：

- `gather`：硬预检 `_contracts.md`（⑧契约冻结屏障，缺 → 失败指回⑧）+ 逐目标应用 `前端详设.md`（缺 → 失败指回⑨）+ 组级 `前端详设/dashboard.md`（缺 → 失败指回⑨）；规格四件（本规格 / VIEW_CONVENTION 正本 / patterns / pitfalls）缺一即失败。
- `gen`：单元 = 应用 + dashboard 同池摊平并发（`GROUPBUILD_FCODE_PARALLEL` 默认 4），**单元内两阶段串行**——先 `view.js`（js 门禁：默认导出 / PAGE_META key 逐字+order 数字 / 零相对 import / svc 全字面量 / 零 this / Alpine.reactive / 模板抓取名；dashboard 追加 quiet≡svc 计数；软 `node --check`，环境无 node 则 warn 跳过）→ 再 `view.html`（注入定稿 js，门禁：非空 + Alpine 指令；dashboard 追加 KPI/管道/待办区块）；每阶段门禁不过 → usr_fix 尾追加整份重出（≤`GROUPBUILD_FCODE_REPAIR` 轮，默认 2）；js 修复耗尽仍失败 → 该单元失败（html 跳过）、全败才 raise。每阶段输入 = 铁律 preamble + 本规格/约定/patterns/pitfalls（html 阶段省规格与 pitfalls 控 token）+ 本应用前端详设全文 + 契约切片（dashboard：`前端详设/dashboard.md` + 契约全文）。
- `write`：逐应用 `app/<组>/<应用>/view.{js,html}` + 组级 `app/<组>/dashboard.{js,html}`（第二棵落点根）；零接线，落盘即进菜单/路由/授权清单。

API：`POST/GET/DELETE /api/groupbuild/groups/<组>/fcode`（POST body `{app_names?}` 缺省全部已有前端详设的应用；GET `?zip=1` 全组打包、`/fcode/<应用>` 单元 mini-zip 下载、`/fcode/dashboard` 看板单元）。与手工流程同产物、同规格、同门禁口径，可互换。
