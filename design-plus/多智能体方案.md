# 多智能体方案（AgentScope 2.0.6 Team 能力接入）

> 状态：方案已定稿，裸跑已验证。本文档固化调研结论 + 双进程架构 + 四个集成点 + 角色工具隔离结论，供后续编码（第 ①～⑤ 步）与评审对照。

## 一、背景与结论

FDE 现有 Agent 后端（`fde_platform/agent_agentscope.py`）用的是 AgentScope **最底层的单 `Agent`**（`agentscope.agent.Agent` + `Toolkit` + `reply_stream`）。AgentScope 2.0.6 往上还有一整套 **`app` 框架**（FastAPI 服务），内置了多智能体（team）、定时（schedule）、消息总线、工作区、渠道（飞书等）能力——**FDE 整层未接**。

多智能体的官方范式**不是手工写 Pipeline**，而是 **「Leader 自治建队」**：编排 Agent 持有一把建队工具，遇复杂任务时自己组建团队、生成 worker、派活、收结果。

**结论**：FDE 接多智能体 = 引入 AgentScope `app` 框架作为独立「智能体编排层」，通过 `extra_agent_tools` 把 FDE 业务服务桥接进去，通过 `custom_subagent_templates` 定义领域角色。不换业务层、不重写 Agent 核心。

## 二、AgentScope 2.0.6 多智能体真相（已核源码）

| 内置工具 | 作用 |
|---|---|
| `TeamCreate` | 建团队，team 章程注入每个成员 system prompt |
| `AgentCreate` | 按 `SubAgentTemplate` 生成 worker（跑自己的 ReAct 循环） |
| `AgentInvite` | 邀请已有 agent 入队 |
| `TeamSay` | 给成员派活 / 收结果（消息经 message_bus，包 `<team-message from=...>`） |
| `TeamDelete` | 解散团队 |

集成入口唯一：`create_app()`（`agentscope.app`，返回 FastAPI）。关键参数：

```python
create_app(
    storage=AsyncSQLAlchemyStorage("sqlite+aiosqlite:///...", create_tables=True),
    message_bus=InMemoryMessageBus(),
    workspace_manager=LocalWorkspaceManager(basedir="..."),
    extra_agent_tools=fde_tool_factory,          # ★ 业务工具注入
    custom_subagent_templates=[...],             # ★ 领域角色
    extra_agent_middlewares=fde_auth_factory,    # ★ 身份/鉴权
)
```

- `extra_agent_tools` 签名：`(user_id, agent_id, session_id) -> Awaitable[list[ToolBase]]`，每次组装 agent 调用，返回工具进 toolkit `"basic"` 组。
- `SubAgentTemplate` 的 `system_prompt_template` 占位符：`{team_name}/{team_description}/{member_name}/{member_description}/{leader_name}`。

## 三、架构（双进程）

```
浏览器 ── HTTP/SSE ──▶ FDE Flask（web.py）        FDE 现有：业务应用/授权/文件/HITL桥
                          │  /api/agent2/* 反向代理
                          ▼ （内网 HTTP）
                     AgentScope agent_service（独立 FastAPI，:4100）
                       create_app(...)
                         ├─ storage = SQLStorage(sqlite)  ← 复用 FDE 同款 SQLite
                         ├─ message_bus = InMemory
                         ├─ workspace = LocalWorkspaceManager
                         ├─ extra_agent_tools = FDE 业务工具工厂（带授权过滤）
                         ├─ custom_subagent_templates = 销售/计划/库存/交付
                         └─ extra_agent_middlewares = FDE 身份桥
```

独立进程原因：team 能力深耦合在 AgentScope 的 `ChatService`（FastAPI），无法硬拆进 Flask；官方 `examples/agent_service` 也本就是独立后端。FDE 用 Flask 做薄代理挡在鉴权后面。

## 四、四个集成点

### ① 工具工厂（最关键）

桥接 `agentscope_bridge.tool_schemas()` 到 AgentScope 的 `FunctionTool`：

```python
async def fde_tool_factory(user_id, agent_id, session_id) -> list[ToolBase]:
    user = fde_users.resolve(user_id)   # FDE 用户 → 服务授权
    tools = []
    for t in agentscope_bridge.tool_schemas(fde_platform, user):
        name = t["function"]["name"]
        tools.append(FunctionTool(
            _make_call(name),             # 复用 bridge.execute 路由（fail-closed）
            name=name, description=t["function"]["description"],
        ))
    return tools
```

基本是现有 `agent_agentscope.py._build_toolkit` 的搬移，`bridge.execute` 的授权原样保留。

### ② 角色模板（psc 四角色）

```python
SubAgentTemplate(
    type="sales",
    description="销售预测、历史、策略拟合专家（sales_forecast/sales_history/strategy_fitting）",
    system_prompt_template=(
        "你是{member_name}，销售需求专家，隶属团队'{team_name}'（由{leader_name}领导）。"
        "团队目标：{team_description}。分工：{member_description}。"
        "只做销售域工作，排产/库存交给对应成员，用 TeamSay 回报{leader_name}。"
    ),
    permission_context=PermissionContext(mode=PermissionMode.ALLOW),
)
```

四个 type：`sales` / `planning`（master_plan/demand/demand_pool/md_project*）/ `inventory`（inventory_*/md_material/md_breakpoint/md_part_replace）/ `delivery`（outbound_plan/attainment）。

### ③ 鉴权中间件

`extra_agent_middlewares` 把 FDE 登录态映射成 agent_service 的 `user_id`，隔离租户、注入审计。

### ④ 存储/总线/工作区

`SQLStorage(sqlite)` 复用 FDE 的 SQLite（未来 `DATABASE_URL` 切 PG 同样生效）、`InMemoryMessageBus`（单机）、`LocalWorkspaceManager`，零新增外部依赖（除 AgentScope 声明的 service/storage-sql extras）。

## 五、角色工具隔离（已确认结论）

**原生不支持**，三条证据（均核过源码）：

1. `SubAgentTemplate` 无 `tools` 字段（`app/_types.py:89`）。
2. `extra_agent_tools` 对所有 agent 一视同仁，全量进 toolkit（`app/_service/_toolkit.py:246`）。
3. worker 的 `AgentData` 不存 `subagent_type`（`AgentCreate` 只把它烧进 `system_prompt`，`app/_tool/_agent_create.py:454`），能查到的只有 `source`（`user`=leader / `team`=worker）和 `data.name`。

**但能通过官方 middleware 实现**，两条路：

| 钩子 | 隔离级别 |
|---|---|
| `on_model_call`（改 `tools: list[dict]`） | 软隔离：LLM 看不到越权工具 |
| `on_check_permission`（返回 DENY） | 硬兜底：调了越权工具也执行不了 |

**身份标记取舍**（需决策，当前定 A）：

- **A. 约定 name**（零改 AgentScope）：worker 名字用固定角色词，middleware 按 `data.name` 映射角色过滤。依赖 leader LLM 起对名字，可控性中等，但 `on_check_permission` 硬兜底保证安全底线是硬的。
- **B. 微改 AgentScope**：给 `AgentData` 加 `subagent_type` 字段。最干净，但要 fork/patch 源码，升级时重打。

FDE 工具名本身结构化（`组__应用__服务`），「角色 → 允许应用集 → 工具名前缀过滤」现成可做。

## 六、端到端验证（已通过）

- 依赖：`fastapi` / `apscheduler` / `ag-ui-protocol` / `sqlalchemy[asyncio]` / `alembic`（AgentScope `service` + `storage-sql` extras 缺失项，已装）。
- 入口：`fde_platform/agent_service.py`，`python -m fde_platform.agent_service` → `http://127.0.0.1:4100`。
- 关键端点：`/agent/` CRUD、`/chat/`、`/sessions/`（含 `/stream` SSE + `/interrupt`）、`/schedule/`、`/hub/mcp`、`/hub/skill`、`/workspace/`、`/channels/`（飞书等）。
- team 操作**无独立 HTTP 端点**——由 leader 在对话中经 `TeamCreate`/`AgentCreate`/`TeamSay` 工具调用，印证「Leader 自治建队」范式。

**端到端验证链路**（`fde_platform/_verify_agent_service.py`，临时脚本）：

1. `POST /credential/`（`deepseek_credential`，复用 FDE `llm.db` 解密出的 key）
2. `POST /agent/`（leader + system_prompt 引导建队）
3. `POST /sessions/`（带 `chat_model_config: {type, credential_id, model, parameters}`）
4. `POST /chat/`（触发，异步返回 `{status:"started"}`）
5. `GET /sessions/{id}/stream?agent_id=...`（SSE 流，事件帧 `data: {...}`）

**验证结果（真实 LLM 对话，非空壳）**：

- 模型连通：SSE 流完整 `REPLY_START → MODEL_CALL_START → TEXT_BLOCK_DELTA* → MODEL_CALL_END → REPLY_END`，deepseek 流式回复正常。
- team 建队：leader **真实调用** 1 次 `TeamCreate` + 3 次 `AgentCreate`，组建销售/计划/库存三人专家团队并回报。tool call 事件序列在 SSE 流中清晰可见（`TOOL_CALL_START {tool_call_name: TeamCreate/AgentCreate}`）。
- FDE 工具调用（第 2 步）：leader 真实调用 `psc__md_customer__list`，`bridge.execute` 返回 20 条客户数据，leader 生成中文结构化回复（客户分类表格）。

**关键坑（均已踩过并解决）**：

1. **FunctionTool 默认 `check_permissions` 返回 ASK**——每次工具调用都会停车等人工确认，SSE 流卡住无事件。解决：工厂里覆盖 `ft.check_permissions`，普通工具返回 `PermissionBehavior.ALLOW`，危险工具（`_is_dangerous`，与 `agent_agentscope.is_dangerous_tool` 同口径）返回 `ASK` 走 HITL。
2. **`PermissionDecision` 的 `message` 是必填字段**——`PermissionDecision(behavior=ALLOW)` 会抛 `TypeError`，必须带 `message=""`。
3. **全量工具（admin 197 个）导致 LLM 首 token 极慢（>120s）**——工具 schema 全塞 context 触发超时。故加了临时收窄开关 `FDE_AGENT_TOOL_APPS`（只注入指定应用 + `propose_skill`，验证时 9 工具秒级响应）。这印证了第 4 步「工具过滤」是**必须项**，不是优化。

**关键 API 契约**（后续 FDE 反代/联调复用）：

- 所有请求带 `X-User-ID` header（租户隔离，将来换 JWT）。
- `Msg` 格式：`{role, name, content: [{type:"text", text}]}`。
- SSE 事件类型：`REPLY_START` / `TEXT_BLOCK_DELTA` / `TOOL_CALL_START`（含 `tool_call_name`）/ `TOOL_CALL_END` / `REPLY_END`。
