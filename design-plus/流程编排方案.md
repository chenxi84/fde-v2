# 流程编排方案（Flow · 声明式 DAG 工作流）

> 状态：方案已定稿、功能已落地。本文档固化**组级流程声明文件**的格式正本 + 执行语义 + 平台能力，供组内声明 `_flow_<key>.yaml` 与前端编排页对照。
> 本文档自包含（内联样例），不依赖任何实现文件路径；「声明文件落点」是本规范的组成部分，非外部引用。

## 一、背景与定位

流程编排 Flow 是智能体编排的**声明式**方式：预先用 YAML 声明好 DAG，跑起来可复现、可审计。

- **平台级能力**：组级声明文件 `app/<组>/_flow_<key>.yaml`，平台扫描装配，**零平台代码改动**。
- **可选增强**：九步法之外的可选步（第⑪步），不做也满足九步法完成门禁。
- **前提不是「智能体实例」**：执行一条 flow 不需要预先存在任何智能体。节点按 `type` 分流执行（见 §2.6）：
  - `agent`（默认）：现场起「轻量 ReAct 循环」（LLM 多轮调工具），需 LLM 已配置；
  - `call` / `skill`：确定性直调服务 / 跑技能，**不经过 LLM**。
  - 三项前提——业务服务可用、（可选）角色声明 `_roles.py`（`agent` 节点的 `role` 引用它做工具隔离）、LLM 已配置（仅 `agent` 节点需要）。

## 二、声明文件格式（正本）

### 2.1 落点与命名

- 落点：`app/<组>/_flow_<key>.yaml`。
- `key`：英文标识；缺省从文件名推导（`_flow_<key>.yaml` → `key`）。
- 平台扫描 `app/<组>/_flow_*.yaml` 装配；某份声明有误**仅跳过该份**，不阻断平台启动。

### 2.2 顶层字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 显示名（列表 / 进度用） |
| `key` | 否 | 英文标识，缺省从文件名推导 |
| `description` | 否 | 描述 |
| `nodes` | 与 `steps` 二选一 | DAG 节点列表（见 2.3） |
| `steps` | 与 `nodes` 二选一 | 顺序简写（见 2.5） |

### 2.3 节点字段（`nodes` 每项）

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 节点 id，`depends_on` 据此引用 |
| `type` | 否 | 节点类型：`agent`（默认）/ `call` / `skill`，见 §2.6 |
| `role` | 否 | 仅 `agent` 节点：引用 `_roles.py` 的 `type`；命中则按角色过滤工具，未命中用全量工具 |
| `task` | `agent` 必填 | 仅 `agent` 节点：任务文本，可用 `{结果键}` 占位 |
| `call` | `call` 必填 | 仅 `call` 节点：`{service, args}`，直调应用服务（见 §2.6） |
| `skill` | `skill` 必填 | 仅 `skill` 节点：`{name, args}`，跑已发布技能（见 §2.6） |
| `output` | 否 | 结果键：写入共享 state，供下游 `input` / 本节点 `until` 引用 |
| `input` | 否 | 上游结果键列表，用于填充 `task` / `call.args` / `skill.args` 里的 `{键}` 占位符 |
| `depends_on` | 否 | 依赖的节点 id 列表（拓扑分层的依据） |
| `when` | 否 | 条件分支 `{key, op, value}`：执行前判断，不满足则跳过 |
| `until` | 否 | 循环 `{key, op, value}`：执行后判断，不满足则重跑 |
| `max_loop` | 否 | 循环最大次数（默认 1） |

### 2.4 完整样例（内联，自包含）

```yaml
# app/<组>/_flow_<key>.yaml
name: 示例工作流
description: 顺序 → 条件分支 → 汇聚循环 的最小示例
nodes:
  - id: scan
    role: sales                      # 引用 _roles.py 的 type
    task: "分析数据，给出结论。"
    output: result                   # 写入共享 state
  - id: branch_a
    role: sales
    task: "基于「{result}」做 A 处理。"
    input: [result]                  # 填充 task 里的 {result}
    depends_on: [scan]               # 依赖 scan
    when: {key: result, op: not_empty}   # result 非空才执行
    output: a
  - id: branch_b
    role: sales
    task: "基于「{result}」做 B 处理。"
    input: [result]
    depends_on: [scan]
    when: {key: result, op: empty}       # result 为空才执行
    output: b
  - id: retry
    role: sales
    task: "汇总 A/B 结果并重试处理，直到满足。"
    input: [a, b]
    depends_on: [branch_a, branch_b]     # 汇聚：两分支都完成后才执行
    until: {key: a, op: contains, value: "ok"}   # 循环直到 a 含 ok
    max_loop: 3
    output: final
```

### 2.5 顺序简写（`steps`）

```yaml
# app/<组>/_flow_<key>.yaml
name: 顺序简写示例
steps:
  - {id: s1, role: sales, task: "第一步", output: r1}
  - {id: s2, role: sales, task: "基于「{r1}」第二步", output: r2}
```

等价于：每步自动 `depends_on` 前一步、`input` 引用前一步的 `output`。

### 2.6 条件 DSL（`when` / `until` 的 `op`）

`contains / equals / not_empty / empty / gt / lt / gte / lte`。`value` 可省略（缺省视 `op` 而定，如 `not_empty` / `empty` 不需要 `value`）。

### 2.7 节点类型（`type`）

| type | 说明 | 声明字段 | 走 LLM |
|---|---|---|---|
| `agent`（默认） | 智能体自由决策（现状） | `task` + `role` | ✅ |
| `call` | 确定性直调应用服务 | `call: {service, args}` | ❌ |
| `skill` | 确定性跑已发布技能 | `skill: {name, args}` | ❌ |

- `call.service`：`app.service`（应用短名.服务名），执行时由 flow 归属组补全为 `group__app__service` 工具名。
- `call.args` / `skill.args`：参数对象，字符串值可用 `{结果键}` 占位符（从上游 `output` 填充）。
- `skill.name`：已发布技能名（`skills.run_skill` 校验须为 `approved`）。
- 控制流 `when` / `until` / `depends_on` 对三种 type 通用。

```yaml
# 混合节点示例（确定性 → 确定性 → 智能体）
nodes:
  - id: load_pred
    type: call
    call: {service: sales_forecast.predict, args: {material_no: M001}}
    output: pred
  - id: review
    type: skill
    skill: {name: 复核预测, args: {pred: "{pred}"}}
    output: review
  - id: writeup
    type: agent
    role: 计划员
    task: "根据「{review}」写说明"
    depends_on: [review]
```

## 三、执行语义

1. **拓扑分层**：按 `depends_on` 分层；同层无依赖的节点**并行**执行，依赖多上游的节点自然汇聚。
2. **条件分支**：节点 `when` 不满足 → 跳过（`output` 不写 state）。
3. **循环**：节点 `until` 不满足 → 重跑（最多 `max_loop` 次）。
4. **节点执行按 `type` 分流**：`agent` → 轻量 ReAct（LLM 多轮调工具，工具按 `role` 过滤，返回文本结论）；`call` → 直调服务（`bridge.execute`，无 LLM）；`skill` → 跑已发布技能（`skills.run_skill`，无 LLM）。结果写入 `output`。
5. **进度上报**：最近一次执行进度写入平台进度库（仅保留最近一次），供前端编排页与智能体读取。
6. **防死循环**：循环依赖或缺失上游 → 终止，不空转。

## 四、平台能力

### 4.1 平台工具（供智能体对话调用）

| 工具 | 可用范围 |
|---|---|
| `platform_list_flows` / `platform_run_flow` / `platform_flow_progress` | 全员 |
| `platform_save_flow` / `platform_delete_flow` | 仅 admin（危险操作走 HITL） |

### 4.2 HTTP API（前端编排页使用）

| 端点 | 说明 |
|---|---|
| `GET /api/flows` | 列表（可 `?group=` 过滤） |
| `POST /api/flows` | 保存（支持结构化 `nodes` 或 `yaml_text`，仅 admin） |
| `DELETE /api/flows/<组>/<key>` | 删除（仅 admin） |

### 4.3 前端编排页

平台公共页「流程编排」，三标签：

- **画布**：拖拽节点 + 连线（建边自动同步 `input`）+ 自动布局 + 坐标落盘（节点 `x/y`）。
- **表单**：逐字段编辑节点。
- **YAML 源码**：直接编辑声明文本。

坐标 `x/y` 作为节点可选字段随 `nodes` 落盘，**仅画布布局用，执行时忽略**；YAML 源码视图不输出坐标（源码保存后回画布自动布局重建）。

## 五、与角色声明（`_roles.py`）的关系

- flow 节点的 `role` 引用 `_roles.py` 的 `type`（格式见《智能体角色声明.md》）**仅作工具隔离**：命中则按角色过滤工具，未命中用全量工具。
- 二者均为可选增强（九步法第⑩⑪步）：可只声明角色、只声明流程、或两者都做。
- 可组合：智能体可调 `platform_run_flow` 触发一条已声明的 flow。

## 六、注意

- 组级声明文件，平台扫描装配；声明有误仅跳过该份。
- `key` 在组内唯一，重复则覆盖。
- `x/y` 属画布布局，不进 YAML 源码视图。
