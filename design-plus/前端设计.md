## 🧭 使用契约：作为「前端设计」技能（应用组构建 · 第⑥步）

### 技能定位（九步法）

```text
第①步  聚合根识别（《架构设计.md》）        业务说明 → app/<组>/architecture.md                   ← 已定义
            ↓
第②步  逐聚合根应用设计（《应用设计.md》）   architecture.md + brd/ → 每聚合根一份 应用详设.md      ← 已定义
            ↓
第③步  应用编码（《应用编码.md》）          应用详设.md → app/<组>/<应用>/<应用>.py + README.md     ← 已定义
            ↓
第④步  测试用例生成（《应用测试.md》）      architecture.md + 各详设 + _contracts.md → app/<组>/测试用例.md   ← 已定义
            ↓
第⑤步  测试执行（《测试执行.md》）          测试用例.md → app/<组>/tests/verify_chain_<组>.py（跑通） ← 已定义
            ↓（第⑤步跑绿后无条件重跑 contract_dump **最终冻结** _contracts.md 方可开工——依赖屏障）
★第⑥步  前端设计（本文件）                 _contracts.md + 各应用详设 → 逐应用 前端详设.md + 组级 dashboard 设计  ← 本规格

第⑦步  前端编码（《前端编码.md》）          前端详设.md → app/<组>/<应用>/view.{js,html}            ← 已定义
```

- （可选）`<应用名>` 子集：只设计指定的某些应用页；缺省＝组内**全部**应用各出一份 + 组级 dashboard。

### 产出
- **逐应用**：`app/<组>/<应用>/前端详设.md`——按下方「输出模板」填写的字段级页面设计，与该应用后端文件同文件夹。

### 契约 → 前端详设映射
| 契约 / 详设（上游） | → 前端详设（本步） |
|---|---|
| `list` 服务签名（过滤参数 + 返回项字段） | 列表区块：关键业务列（单号/状态/归属/数量金额/时间/关联单号，宁多勿少）+ 搜索控件与过滤参数**一一对应**（状态→chips、归属→下拉、关键字→输入框） |
| `get` 真实返回（全字段） | 详情模态区块：全部业务字段按语义分 `.kv` 组 + `.sec` 小节；`*_json` 字段标注 `tryParse()` 结构化；子账本（行项目/流水）用表格 |
| `create` / `update` / `set_*` / `import_batch` **接受的参数** | 表单区块：可写业务字段三分类（create 进创建 / 仅 update 进编辑 / 快照字段只展示不进表单）；枚举选项与后端校验值完全一致 |
| 详设 §3.4 状态机 | 列表行内动作 + 模态页脚操作：按状态 `x-show` 的动作清单（提交/撤回/审批/重投…） |
| 详设 §5 角色 / PERM | **不设计任何页面鉴权**——仅注明受限角色的页面授权清单建议（菜单收敛由 shell 负责、数据闸门在后端） |
| architecture.md 关系图 / 主链 | dashboard 区块：KPI 指标带 / 主链管道（各应用状态分布）/ 待办队列，每区块注明跳转目标应用页 |

### 设计铁律（详见 VIEW_CONVENTION，关键几条）
- **契约先行，不猜字段**：模态字段以 `get` 真实返回为准；表单字段以写服务**实际接受参数**为准——详情展示字段 ≠ 创建可传参数（pitfalls #11）。
- **svc 字面量清单必须完整且字面**：逐项列出页面将调用的 `svc("应用","服务")`（含 dashboard 的 quiet 探测）——授权隐式放行派生表靠扫描字面量，变量拼名扫不到（pitfalls #8）。
- **菜单即应用**：一个应用一页，除 dashboard 外**禁止合并工作台**；dashboard 每组建一份。
- **`PAGE_META.order` 显式编排**：dashboard 给最小（如 10）居首，各应用按业务分段、10 步长递增（单据与其变更单相邻）。
- **列表列 ⊆ 详情字段集**；搜索控件与后端 `list` 参数一一对应，后端不支持的维度**不自造假过滤**。
- **主数据选择控件**：客户/物料/车型/用户等主数据字段**必须**使用内联 autocomplete 下拉（点击输入框弹出匹配列表，输入关键字过滤，选中回填），**禁止**使用普通 `<select>` 下拉（数据量大时无法选择）。枚举值字段不受此限，仍可用 `<select>` 或 chips。
  - **实现要点**：① 为每个主数据源单独声明扁平数组（`partOptions`/`custOptions`/`vehOptions`/`userOptions`），**禁止**用嵌套对象 `autoOptions[field]` 存储（Alpine reactive 对嵌套属性追踪不稳定）；② 用 `@click.stop` 切换展开/收起 + `@input` 实时过滤 + `@click.away` 关闭；③ 过滤逻辑同时匹配代号和名称；④ 列表项显示「代号 + 名称」双行，选中后表单存代号；⑤ 主数据源在 `init()` 中用 `{quiet:true}` 加载，加载失败静默降级为空数组。
- **同组一致性**：所有应用页共用列表三段式 / 模态三段式 / 表单布局；字段顺序统一（单号→状态→归属→数量金额→时间）。

### 验收标准（可机器化）
- 组内每个应用有一份 `前端详设.md`，且有一份 `app/<组>/前端详设/dashboard.md`。
- 每份含：`PAGE_META` 六字段齐全（`order` 为数字、显式给定）；区块构成覆盖列表 / 详情模态 / 表单（纯回调型应用可豁免表单，注明理由）；svc 清单全为字面量。
- 表单字段集 ＝ 后端写服务接受的业务参数集（审计字段除外）；列表列 ⊆ 详情字段集。
- 搜索控件与 `list` 签名过滤参数一一对应；枚举选项与后端校验值一致。

### 命名与边界铁律
- 应用页 `PAGE_META.key` ＝ 应用文件夹名（与后端应用名、page_id 对齐）；dashboard 的 key 固定 `dashboard`。
- 不臆造：契约/详设未说清的字段标「待确认」，不编造区块或交互。
- 本步**不触碰** `view/lib/`、`view/pages/`、平台通用壳——那是只读环境前提（VIEW_CONVENTION 生成边界）。

- **覆盖度门禁**：本步产出须经独立的覆盖度检查——对照本规格规定的上游输入，逐项验证覆盖完整性。覆盖度 < 100% 不得进入下一步。具体门禁条件见 `design-plus/工具链使用说明.md` 对应步骤的「完成门禁」段。

## 内嵌范例：task 前端详设（单据型代表作）

> 摘自真实交付物 `app/e2e/task/前端详设.md`（e2e 模块实跑产出，仅将步骤引用改为本体系编号）。单据型页面（列表 + 详情模态 + 创建表单 + 状态机动作 + 跨应用下拉）是系统中最常见的形态，**产出第⑥步文档时照此填充**；其他形态按解剖结构裁剪（如主数据型无编辑入口/行动作，见 `app/e2e/member/前端详设.md` 按需参考）。

````markdown
# task（任务管理）前端详设
> 来源：app/e2e/_contracts.md（冻结契约）+ app/e2e/task/应用详设.md；产出供第⑦步前端编码 / 第⑧步前端测试用例
> 落位：`app/e2e/task/view.js` + `app/e2e/task/view.html`（与 `task.py` 同文件夹，落盘即进启动清单与授权清单，零接线）；import 一律绝对路径 `/view/lib/*`；模板经 `new URL("view.html", import.meta.url)` 抓取；工厂 `export default function pageTask()`（保留专名）

## 1. 页面元数据 PAGE_META

| 字段 | 值 | 说明 |
|---|---|---|
| key | `task` | = 应用文件夹名，page_id 为 `e2e:task` |
| name | 任务管理 | 侧栏菜单名 |
| ic | ☑ | 菜单图标字 |
| title | 任务管理 | 主区页面头 |
| crumb | 事务单据 · 创建 / 指派 / 启动 / 完成 / 退回 | 头部副题 |
| order | 20 | 已按业务序预分配，直接用；升序即菜单序 |

- 页面零鉴权：无任何权限判断；菜单按页面授权渲染在 shell，数据范围（PERM-5~7 成员仅本人任务）由后端闸门执法，401 由 api.js 自动跳登录。
- 本应用契约**无 update / set_* / import_batch / delete** → 无编辑入口、无删除按钮；单据变更仅经状态机动作（start / complete / reopen）。

## 2. 区块构成

### 2.1 列表区（查）—— 三段式：过滤条 / 表格 / 分页条

**用途**：任务台账，按状态机三态与指派维度筛选，承载行内状态流转动作。

**过滤控件（与 `task.list(status, assignee_member_no, priority, page, page_size)` 可过滤参数一一对应；契约无 keyword 参数 → 不设关键字搜索框，禁止前端假过滤）**：

| 控件 | 对应参数 | 选项 |
|---|---|---|
| 状态 chips | `status` | 全部 / 待办 / 进行中 / 已完成（BR-9 枚举，原值传参） |
| 负责人下拉 | `assignee_member_no` | 来自 `member.list` quiet 加载（见 §4）；选项 value=member_no，label=成员姓名 |
| 优先级下拉 | `priority` | 全部 / low / high（BR-4 枚举） |
| 分页 | `page` / `page_size` | `pageable()` 分页条（契约签名 string 型，照传即可） |

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集；字段序与详情/表单一致）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 任务编号 | `task_no` | `.b-link`，点击开详情模态 |
| 标题 | `title` | 单行省略 |
| 状态 | `status` | `hue()` 徽章 |
| 负责人 | `assignee_member_no` | 编号正文 + memberMap 命中时附姓名小字 |
| 优先级 | `priority` | `hue()` 徽章（low / high 双色） |
| 描述 | `description` | `.cell-ellipsis` 省略，空值 `dash()` |
| 创建时间 | `created_at` | `fmtTime()` |
| 更新时间 | `updated_at` | `fmtTime()` |
| 操作 | — | 按 `status` 的行内动作，`x-show`（见 §5.1） |

**交互**：任一过滤变化 → 重置回第 1 页重载；状态动作成功后刷新当前页；空结果显示空态文案（不喷 toast）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 状态徽章 / KV 分组体 / 状态操作页脚

**用途**：点 `task_no` 弹出，展示 `task.get` 返回的**全部**业务字段。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `task_no` + `status` 徽章 | 墨青头带，徽章 `hue()` |
| 基本信息 | `task_no` / `title` / `status` / `priority` | `.kv`；`task_no` 注明「系统生成 · 全局唯一」（BR-7） |
| 指派信息 | `assignee_member_no` | `.kv`，memberMap 命中附姓名；注明「弱引用 member 主数据」 |
| 任务描述 | `description` | 多行文本，空值 `dash()` |
| 时间信息 | `created_at` / `updated_at` | `fmtTime()`；`updated_at` 注明「状态变更时刷新」（BR-15） |
| 原始数据 | get 返回全量 JSON | 底部折叠 |

**交互**：页脚 `.modal-ft` 按当前状态放状态机按钮（逻辑同 §5.1，与行内动作共用一处 `x-show` 判定）；动作成功后用返回对象原地刷新模态字段 + 列表行；初始 `status` 恒「待办」（BR-8）只展示、不进表单。

### 2.3 创建表单（增）—— 模态表单

**用途**：覆盖 `task.create` 接受的**全部**可写业务参数（title / description / assignee_member_no / priority）。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `title` | input，maxlength=200 | ★ 必填 | BR-1 / BR-2 |
| `assignee_member_no` | select（成员下拉，见 §4） | ★ 必填 | BR-5 / BR-6（后端经 member.get 跨应用校验存在性，成员不存在时由后端 FdeError toast 呈现） |
| `priority` | select：low / high，默认 low | ★ 必填 | BR-4（契约签名虽 optional，但后端枚举校验拒空，故 UI 必填） |
| `description` | textarea，maxlength=2000 | 可选，收进「更多字段 ▾」折叠区 | BR-3 |

- **不进表单**：`task_no` / `status`（系统生成，BR-7 / BR-8，仅详情展示并注明）、`created_at` / `updated_at`（系统写入）。
- 布局：必填先行、frow 语义分组、底部右对齐提交按钮；校验 = 必填红星 + toast 警告（标题/负责人为空不发请求）。
- 提交成功：toast 带出新 `task_no` → 关闭模态 → 重置过滤重载列表（新任务恒「待办」）。

## 3. svc 字面量清单（授权派生依据——必须字面量 svc("应用","服务")）

| 区块 | 调用（应用.服务） | 参数 | 说明 |
|---|---|---|---|
| 列表区 | `svc("task","list")` | `{status, assignee_member_no, priority, page, page_size}` | 过滤查询；空条件传 undefined 不带 |
| 列表区 / 创建表单 | `svc("member","list")` | `{page:1, page_size:200}` | 负责人下拉数据源，quiet 探测；**跨应用调用，字面量产生 e2e:task → member.list 派生边** |
| 详情模态 | `svc("task","get")` | `{task_no}` | 全字段详情 |
| 行内 / 模态页脚 | `svc("task","start")` | `{task_no}` | 待办 → 进行中（BR-10） |
| 行内 / 模态页脚 | `svc("task","complete")` | `{task_no}` | 进行中 → 已完成（BR-11） |
| 行内 / 模态页脚 | `svc("task","reopen")` | `{task_no}` | 进行中 → 待办（BR-12） |
| 创建表单 | `svc("task","create")` | `{title, description, assignee_member_no, priority}` | 创建；返回含 task_no 的任务对象 |

> 以上 7 处必须在 view.js 中以字面量逐项书写（可包在闭包里），**勿用变量拼名**——这是页面授权隐式放行派生扫描的唯一来源。

## 4. 数据来源与下拉

**负责人下拉（过滤条与创建表单共用一份 memberList / memberMap）**：
- 页面初始化一次性 `svc("member","list")` `{page:1, page_size:200}`，`quiet:true` 探测：失败不喷 toast；零值兜底 → 过滤下拉仅「全部」、创建表单下拉显示「暂无可指派成员」禁用项（提交时再 toast 提示）。
- 由返回项构建 `memberMap = {member_no: name}`，供列表「负责人」列与详情模态姓名回显；未命中则原样展示 member_no。
- member 列表项字段以 member 契约为准，本页仅用 `member_no` / `name`（email / role 不展示）。

**契约 payload → 区块字段映射**：

| 来源 | payload 字段 | 去向 |
|---|---|---|
| `task.list` 项 | task_no, title, description, assignee_member_no, priority, status, created_at, updated_at | 列表区表格列（1:1） |
| `task.get` | 同上（全量） | 详情模态全部 KV 分组 + 原始数据折叠 |
| `task.create` 返回 | 任务对象（含 task_no，status=待办） | toast 展示 task_no → 列表重载 |
| `task.start / complete / reopen` 返回 | 任务对象（新 status、刷新 updated_at） | 原地更新已开模态 + 列表行 |
| `member.list` 项 | member_no, name | 负责人下拉选项 + memberMap |

## 5. 交互要点

1. **按状态的行内动作（状态机，行操作列与模态页脚共用判定）**：
   - `status=待办` → 【启动】；
   - `status=进行中` → 【完成】【退回】；
   - `status=已完成` → 终态，无任何按钮（BR-13）。
   - 动作成功：toast（如「已启动 · T…」）+ 刷新列表；非法流转（如对已完成点启动）由后端 FdeError 经 api.js 统一 toast，页面不硬编状态机校验。
2. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 状态徽章。
3. **折叠「更多字段 ▾」**：仅 `description` 一个可选字段。
4. **quiet 探测性加载**：member 下拉 quiet + 零值兜底，失败不喷 toast；任务列表本身正常加载，错误走 api.js 统一通道。
5. **展示工具**：`hue()`（状态/优先级徽章）、`dash()`（空描述）、`fmtTime()`（两个时间字段）；本页无 `*_json` 快照字段，无需 `tryParse()`；无金额字段，无需 `fmt()`。
6. **toast**：创建成功 / 状态流转成功 / 必填未填警告；其余错误一律由 api.js 统一呈现。

## 6. 验收关注点（供第⑧步前端测试用例）

1. **路由渲染**：`#/task` 挂载出列表三段式（过滤条 + 表格 + 分页条），**页面无 `.kpi`**（防看板挂载粘滞假过）；菜单「☑ 任务管理」按 order=20 定位。
2. **造数后列表有数据**：先造 member（M001）→ 经 `task.create` 造多条任务（覆盖 待办/进行中/已完成 与 low/high）→ 列表行数正确，task_no / title / status / priority / assignee 列非空。
3. **过滤一一对应**：status=待办 chips 仅待办行；负责人=M001；priority=high；三条件组合（US-3-AC4）；无匹配显示空态且不抛错（US-3-AC5）。
4. **模态全字段**：点 task_no 开模态，断言 task_no / title / description / assignee_member_no / priority / status / created_at / updated_at 全部可见 + 「原始数据」可展开；已完成任务的模态页脚无动作按钮。
5. **表单落库**：创建表单填 title / assignee_member_no / priority（★）+「更多字段」description → 提交 → 列表出现新任务且 status=待办（US-1-AC1）；空标题提交 → toast 警告且不发请求；造不存在成员编号 → 后端 FdeError toast（BR-6）。
6. **写操作真实回显**：待办行【启动】→ 行与模态 status=进行中（US-4）；进行中行【完成】/【退回】→ status=已完成 / 待办（US-5 / US-6）。
7. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP≥400（受限会话 403 属预期执法单独豁免；member 角色下列表自然收敛为本人任务，页面不做任何判断）。
````
