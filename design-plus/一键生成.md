# 流程规格：一键生成（从材料到可运行系统）

> **类型**：**流程编排**（不产出文档，只定义顺序 / 停止点 / 交接 / 完成判据）
> **入口**：用户只做两件事 —— 建目录、扔材料 —— 然后说一句话
> **上游**：无
> **下游**：串联《从材料到BRD.md》→《架构设计.md》→ ②–⑨ 各步规格 →《验证门禁.md》

---

## ⚠ 本文件不复述细则（纪律）

每一步「怎么做」「什么算达标」「怎么判定」，**一律以各步规格为准**。

本文件只回答三件事：**按什么顺序走、在哪停、什么算全部完成。**

改细则请去改**对应规格**，**不要**在这里补细节——否则两处真相源必然漂移。

---

## 用户要做的（就两件 + 一句话）

1. 建目录 `app/<组>/book/`
2. 把原始材料扔进去（pdf / epub / docx / html / md / txt 任意格式）
3. 说：

```
请基于 design-plus/一键生成.md，把 app/<组> 从材料做到可运行系统
```

没有第 4 步。不需要声明"要建什么系统"——分类从材料提炼（理由见《从材料到BRD.md》）。

`x-html="tpl"` 对 undefined 求值、整片报错（见 `VIEW_CONVENTION.md` §2 与 `view-convention/pitfalls.md` #36；
2026-08 e2e 模块与本次 nasa_pms 各踩过一次）。**每个新模块必产。**

## 为什么全流程只停一处

两条理由，**任何一条都足以设停止点**：

1. **判不了「哪个对」** —— "哪个对象该独立成一个 FDE 应用"是**设计决策**，不是机械判定。
   能机械判定的（转换非空、类型表忠实性、各步门禁）都已交给校验，**不该浪费人的注意力**。
2. **成本闸门** —— **① 之后的 token 成本显著上升**：逐聚合根详设、编码、测试、前端四步，
   每一步都按应用数放大。方向错了，浪费的是真实的算力与钱。
   **在最贵的一段之前停一次，是最便宜的保险。**

这正对应本平台的分工：**自动的那一半交给门禁，人工的那一半只留在真正判不了的地方。**

## 完成判据（全流程，缺一不算完成）

- [ ] `brd/` 有分章 md（**只放业务正文**），且**忠实性校验通过**（无空框 / 无错框 / 落空率已复核）
- [ ] **组根**有《本体对象.md》与《术语表.md》（**不在 `brd/` 里** —— 后者会被索引吃回图谱）
- [ ] ① 的产出**命名取自术语表**（核心术语逐字取用）
- [ ] `architecture.md` + `architecture_review.md`（**处置表已由人确认**）
- [ ] 每个聚合根：`应用详设.md` → 应用代码 → 测试用例 → 测试脚本**跑通**
- [ ] `_contracts.md` **已冻结**
- [ ] 前端四步产物齐，`verify_view` 通过
- [ ] `python scripts/run_gates.py` **通过**；页面**验收通过**
- [ ] **模块级必备页**：`app/<组>/dashboard.{js,html}` 存在（key=`dashboard`、order 最小、quiet 探测 + 零值兜底）
- [ ] **（可选）数字员工**：`app/<组>/_roles.py` / `_flow_*.yaml` —— **不做也满足完成判据**
