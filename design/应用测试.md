# 应用测试 · 第④步技能规格（生成应用组整体测试用例）

> **版本**: v1.0  **创建日期**: 2026-08-02
> **适用人员**: 应用构建第④步的执行体（AI / 工程师）
> **目的**: 在第③步编码完成后，为**整个应用组**生成**一份**结构化测试用例文件，覆盖完整业务流程（含主链、关键分支与异步回执模拟），并内置自洽的测试数据。
> **本步只生成「测试用例」（数据/文档），不生成可执行测试脚本、不运行测试**——生成与执行解耦，用例文件是通往未来任意执行器（LLM Agent 或脚本）的桥。

---

## 🧭 使用契约：作为「测试用例生成」技能（应用组构建 · 第④步）

### 技能定位（九步法 · 后端段）

```text
第①步  聚合根识别（《架构设计.md》）      业务说明 → app/<组>/architecture.md                 ← 已定义
            ↓
第②步  逐聚合根应用设计（《应用设计.md》） architecture.md + brd/ → 每聚合根一份 应用详设.md    ← 已定义
            ↓
第③步  应用编码（《应用编码.md》）        应用详设.md → app/<组>/<应用>/<应用>.py + README.md   ← 已定义
            ↓
★第④步  测试用例生成（本文件）           architecture.md + 各详设 + 代码签名 → app/<组>/测试用例.md  ← 本规格
            ↓
第⑤步  测试执行（《测试执行.md》）       app/<组>/测试用例.md → app/<组>/tests/verify_chain_<组>.py（跑通）  ← 已定义
```

> 第④步与「测试执行」分离（生成与执行分离）：本步**只生成用例**，由**第⑤步《测试执行.md》**把用例翻译成可运行脚本并跑通。用例的**四要素**（见下）即为第⑤步执行器预留的接口。

> 后端段（①–⑤）之后是前端段（⑥–⑨，契约冻结后开工）：《前端设计.md》→《前端编码.md》→《前端测试.md》→《前端测试执行.md》；全景见《工具链使用说明.md》。

### 必给参数
- 英文应用组名 `<组>`（snake_case），逐字绑定 `app/<组>/`。

### 输入
| 来源 | 位置 | 说明 |
|---|---|---|
| ① 架构（**必需**） | `app/<组>/architecture.md` | 第①步产出：聚合根总表、关系图、跨应用调用链、状态机、外部系统——**主业务链与异步回执点的依据**。缺失则停下、先跑第①步。 |
| ② 各应用详设（**必需**） | `app/<组>/<应用>/应用详设.md` | 第②步产出：US/BR/FUNC/PERM、字段表、状态机、外部依赖——**用例步骤、数据、断言、错误分支的依据**。任一聚合根缺详设则停下、先跑第②步。 |
| ③ 服务契约（**强烈建议**） | `app/<组>/_contracts.md` | 第③步收尾**初始冻结**（参考版）的真实服务签名 + 返回。**有则用例的服务名/参数名最准**；无则以详设§4功能清单为准。注意：第④⑤步可能修复后端代码，前端段消费的是第⑤步跑绿后重跑的**最终冻结**（见《工具链使用说明.md》第 6 步两级冻结）。 |
| ④ 本规格 | `design/应用测试.md` | 用例方法论与输出模板（本文件）。 |

### 产出（整组唯一一份）
- `app/<组>/测试用例.md`——结构化 Markdown，结构见下「输出模板」。
- **不产出**可执行脚本、不运行测试、不写 `.db`。

## 用例四要素（每条用例必含，执行器接口）

1. **步骤**：调哪个应用·哪个服务，写作 `<应用>.<服务>(<参数>)`（服务名/参数名以 `_contracts.md` 或详设§4 为准）。
2. **测试数据**：本步的具体入参（引用数据字典里的标识，见下）。
3. **期望**：**可校验**的结果——某服务返回含某字段=某值、某状态机进入某态，**或**应抛 `FdeError` 且消息含某关键词（错误分支用例）。
4. **回执模拟点**（仅涉异步外部系统的用例需要）：在哪一步**主动调用回写服务**（如 `on_settlement_result` / `on_sap_result`）模拟外部系统（SAP/APS/MOM/WMS/MDM）的异步回执，及其入参（成功/失败两路）。

> 出向适配器（`_send_e14` 等）默认走本地 stub，**无需**在用例里模拟；需要模拟的是**异步回执**——这是联通测试能闭环的关键。

---

## 数据字典冻结铁律（生成质量的命门）

- **先冻结、后引用**：先生成「§0 测试数据字典」，把贯穿全链的标识一次性定死（客户 `C001`、物料 `CTCT-0001`、组织 `ORG-1`、手册 `C12345678`、各单据号…）。
- **后续用例只引用、不新造**：主链/分支用例里的标识必须出自字典，**禁止**临时另起新标识导致前后对不上。
- **数据须自洽且合规**：引用关系一致（单据引用的客户/物料/组织都在字典内）、符合各应用 BR（数量>0、CTCT 必填、允差范围、取值枚举等）。

---

## 覆盖要求

| 部分 | 内容 |
|---|---|
| **§0 测试数据字典** | 冻结全链标识 + 关键值（主数据为主：客户/物料/组织/手册等）。 |
| **§1 主数据准备** | 主数据应用的建数/同步用例（customer/product/sales_org/bonded_handbook 等）。 |
| **§2 主业务链（happy path）** | 按架构关系图从主数据沿主链推进到终态的完整用例序列；**异步外部系统处标注回执模拟点**（成功路）。 |
| **§3 分支 / 异常用例** | 关键错误与分支：撤回、驳回、超额阻止、失败重试、幂等、状态非法转换等；**期望多为 `抛 FdeError 含『…』`**。异步外部系统的**失败路**（如 SAP 退回→重提）也在此。 |

- 用例编号：`TC-<段>-<序号>`（如 `TC-DM-01`/`TC-SO-01`/`TC-ERR-01`）。
- 步骤可串联：一条用例可含多步（造数→推进→断言），按执行顺序列。

---

## 编写规则（铁律）

- 服务名/参数名**以 `_contracts.md` 或详设§4 功能清单为准**，不臆造不存在的服务/参数。
- 期望必须**可机器校验**（字段=值 / 状态 / `抛 FdeError 含『关键词』`），不写「应该成功」这类模糊结论。
- 不臆造业务：架构/详设未说清的链路标『待确认』，不编造步骤或断言。
- 只输出**结构化 Markdown 正文**（数据用 markdown 表格），不要 ``` 代码围栏包裹整篇。

## 输出模板（`app/<组>/测试用例.md` 骨架）

```markdown
# 应用组 `<组>` 测试用例（<中文名>）

> 产出技能：测试用例生成（第④步，规格 design/应用测试.md）。
> 输入：architecture.md + 各应用详设 + _contracts.md（若有）。本文件为整组联通测试用例，含自洽测试数据；生成与执行分离。

## §0 测试数据字典（冻结）
| 标识 | 类型 | 含义 | 关键值 |
|---|---|---|---|
| C001 | 客户 | … | 名称=…, 类型=外贸 |
| CTCT-0001 | 物料 | … | 单位=吨, SAP物料号=… |
| ORG-1 | 销售组织 | … | 层级=1 |

## §1 主数据准备
- **TC-DM-01 同步客户**
  - 步骤: `customer.sync()`
  - 期望: 返回 `synced >= 1`
- **TC-DM-02 创建销售组织**
  - 数据: org_no=ORG-1, org_name=…, org_level=1
  - 步骤: `sales_org.create(org_no=ORG-1, org_name=…, org_level=1)`
  - 期望: 创建成功

## §2 主业务链
- **TC-SO-01 创建销售订单（草稿）**
  - 数据: customer_no=C001, lines=[{ctct_code: CTCT-0001, demand_qty: 10000, …}]
  - 步骤: `sales_order.create(customer_no=C001, lines=[…], trading_entity=…)`
  - 期望: 返回 `status=草稿`
- …（沿主链推进：审批→生效→FO→DN→RECON→结算）…
- **TC-SETTLE-01 结算过账（含 SAP 回执模拟）**
  - 步骤: `reconciliation.settle(recon_no=R1)`
  - 回执模拟: 调 `reconciliation.on_settlement_result(recon_no=R1, result=COMPLETED)`
  - 期望: `reconciliation.get(recon_no=R1)` 返回 `status=已结算`

## §3 分支 / 异常用例
- **TC-ERR-01 同 CTCT 拆单拦截**
  - 数据: 两行同 ctct_code=CTCT-0001
  - 步骤: `sales_order.create(…两行同CTCT…)`
  - 期望: 抛 `FdeError` 含『拆分为不同行项目』
- **TC-ERR-02 结算 SAP 退回→重提**
  - 步骤: `reconciliation.settle(recon_no=R2)`
  - 回执模拟（失败路）: 调 `on_settlement_result(recon_no=R2, result=SAP_REJECTED, reason=…)`
  - 期望: `status=SAP退回`；再 `resubmit(recon_no=R2)` + 成功回执 → `status=已结算`

## §4 待确认（如有）
- …（架构/详设未说清、用例无法确定的链路）…
```

## 验收标准

- `app/<组>/测试用例.md` 含 §0 数据字典 + §1 主数据 + §2 主业务链 + §3 分支用例四部分。
- 主业务链覆盖架构关系图的主链应用（无遗漏关键环节）；异步外部系统处有回执模拟点。
- 用例步骤的服务名/参数名能在 `_contracts.md` 或详设§4 中找到对应（不臆造）。
- 全链标识出自 §0 字典、前后一致；数据符合各应用 BR。
- 每条用例四要素齐全（步骤/数据/期望，按需含回执模拟）；期望可机器校验。
