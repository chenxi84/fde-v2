# groupbuild 使用说明（平台轨）

> `/groupbuild` 页面把九步法工具链产品化为**一键任务卡片**：每步一个任务 kind，后台 worker 串行执行，产物与手工轨**同规格、同落点、可互换**（同一应用组可一轨起步、另一轨续跑）。
> 手工 / Claude Code 直接执行请走 **《工具链使用说明.md》（手工执行轨）**——本文只讲平台卡片的用法与顺序。

## 前置条件

| 条件 | 说明 |
|---|---|
| 平台服务器 | `python main.py`（默认 `http://127.0.0.1:4000`），管理员登录 |
| LLM 配置 | builder 档案已配置并启用（平台「LLM 配置」页）——所有生成任务共用 |
| playwright（仅 ⑫） | `pip install playwright && python -m playwright install chromium` |

## 使用顺序（自上而下点卡片）

| # | 卡片 | kind | 前置 / 屏障 | 产出 | 说明 |
|---|---|---|---|---|---|
| ① | 新建应用组 | — | — | `app/<组>/` | 英文名 snake_case、按字面绑定；中文名仅显示用 |
| ② | 业务设计文件 | — | ① | `app/<组>/brd/` | 上传 BRD（md/html/图片）；可缺省（③ 改用文字描述） |
| ③ | 架构创建 | `arch` | ①+② | `architecture.md` | 输入业务描述长文本；产出聚合根清单总表 + 卡 + 关系图 |
| ④ | 应用详设 | `detail` | ③ | 逐聚合根 `应用详设.md` | 可指定聚合根子集；逐聚合根摊平并发生成 |
| ⑤ | 应用编码 | `code` | ④ | 逐聚合根 `<应用>.py` + `README.md` | 写完自动跑 scanner 契约检查（仅警告）；重跑覆盖旧码 |
| ⑥ | 测试用例 | `testcase` | ④（契约冻结后更佳） | `测试用例.md`（整组一份） | 先冻结数据字典，主链 + 分支两段 |
| ⑦ | 测试执行 | `testexec` | ⑥ | `app/<组>/tests/verify_chain_<组>.py` 脚本集 + 测试报告 | **真实树直跑 · 清表初始化：⚠️ 运行会清空该组全部业务数据**（config/ 平台库不受影响）；verdict 三态 PASS/PARTIAL/CRASH，仅 CRASH/全败触发修脚本重跑 ≤3 轮 |
| — | BUG 修复回路 | `bugfix` → `bugfix-apply` | ⑦ 报告有失败 | 修复提案 → 应用 + 自动重测对账 | **人工闸门**：LLM 只提案，页面逐条批准后才落码；应用后自动派生一次重测、转绿自动勾销 |
| ⑧ | 契约冻结 | `contracts` | ⑤（组内 ≥1 应用已编码） | `_contracts.md` | 隔离沙箱 dump（不碰真实库）；组内有 `seed_contracts.py` 造数链则造数级样例，否则签名级；**前端段的依赖屏障**；代码变更后重跑刷新 |
| ⑨ | 前端详设 | `fdesign` | ⑧ + 各应用详设 | 逐应用 `前端详设.md` + 组级 `前端详设/dashboard.md` | 确定性菜单序分配；门禁（六节 + PAGE_META + svc 字面量）不过整份重出 ≤2 轮 |
| ⑩ | 前端编码 | `fcode` | ⑧ + ⑨ | 逐应用 `view.{js,html}` + `view/<组>/dashboard.{js,html}` | 单元 js→html 两阶段生成 + 确定性机检门禁（默认导出 / svc 字面量 / 绝对 import / 软 node --check）；**零接线**，落盘即进菜单 |
| ⑪ | 前端测试 | `ftest` | ⑧ + ⑨（含组级 dashboard 详设） | 逐应用 `前端测试用例.md` + 组级补充一份 | 六类断言两级分派；门禁（断言节 + VT 编号 + 五要素）不过整份重出 ≤2 轮 |
| ⑫ | 前端测试执行 | `fverify` | ⑪ + playwright | 逐应用 `app/<组>/tests/verify_view_<组>_<应用>.py` + 组级脚本 + verdict 报告 | 生成 + **逐脚本串行真跑**（单脚本超时 600s，失败 LLM 修脚本重跑 ≤2 轮）；硬指标：全 PASS ∧ 各会话 0 console error / 0 pageerror / 0 HTTP≥400 |

## 卡片编号与九步法对照

卡片 ③–⑦ = 九步法 ①–⑤（后端段）；⑧ = 第③步收尾的契约冻结；⑨–⑫ = 九步法 ⑥–⑨（前端段）。①② 为组建立与输入准备。

## 任务监控与操作

- **任务列表**：每组卡片下方，徽章显示 kind（架构/详设/编码/用例/测试/契约/前端详设/前端编码/前端测试/前端测试执行）与状态（排队中/运行中/已完成/失败/已终止）。
- **日志**：任务日志含逐节点进度（gather/gen/write/run）与门禁重出记录；失败任务看 error 字段。
- **终止**：运行中任务可终止（协作式取消，检查点感知）。
- **断点续跑**：worker 重启后自动续跑未完成任务（SqliteSaver 断点）。
- **串行队列**：单 worker 串行消费，多任务按提交顺序排队；无需担心并行互扰。
- **产物操作**：各卡片内下载 / zip 打包 / 删除产物；删除后可重新生成。

## 红线与注意

1. **⑦ 测试执行清数据**：清表初始化清空该组全部业务数据——生产性数据先备份或在空库组运行。
2. **⑫ fverify 与宿主服务器**：脚本在真实树跑 dbguard 隔离（移库运行 + 退出还原）。Windows 下宿主平台持有 `.db` 句柄可能导致隔离冲突——若 ⑫ 报隔离失败，**停掉平台服务器单独跑完再启动**。
3. **契约重冻结时机**：重编码（⑤）或 BUG 修复回路改动应用代码后，重跑 ⑧ 刷新 `_contracts.md`，再按需重跑 ⑨ 之后的前端卡片。**推荐实践（两级冻结，与手工轨一致，见《工具链使用说明.md》第 6 步）**：编码完成后先跑一次 ⑧ 作初始冻结（⑥ 测试用例的签名参照）；**⑦ 测试执行跑绿后再跑一次 ⑧ 作最终冻结**——此后端代码已定型，⑨–⑫ 前端卡片只消费这一版，勿依赖「逢改手动刷新」的自觉。
4. **覆盖语义**：生成类卡片重跑会**覆盖**既有产物（含手工精修过的文档/页面）——卡片带 ⚠️ 覆盖警告与 confirm，确认再点。
5. **屏障执法在 API 预检**：缺前置产物时 POST 直接 400 并指回上游步骤（如 ⑨ 缺契约指回⑧、⑩ 缺前端详设指回⑨），不会带病开工。
