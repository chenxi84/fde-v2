# 前端测试执行 · 第⑨步技能规格（测试用例 → 可运行视图验收脚本）

> **版本**: v1.1（2026-08-08 粒度重构：逐应用执行 + 组级补充脚本）  **创建日期**: 2026-08-02
> **适用人员**: 应用构建第⑨步的执行体（AI / 工程师）
> **目的**: 把第⑧步产出的用例**逐应用翻译成可直接运行的 playwright 视图验收脚本**（每应用一个），另把组级补充用例翻译成一个组级脚本，在 dbguard 隔离 + 无头 Chromium 下真实驱动浏览器跑通，每个脚本各自达成 **0 console error · 0 pageerror · 0 HTTP≥400** 的硬指标。
> **本步只消费第⑧步用例文件**——它们是怎么测的唯一设计来源；本规格规定「如何把用例落成脚本并跑通」，不另起测试设计、不绑定具体应用组。

## 🧭 使用契约：作为「前端测试执行」技能（应用组构建 · 第⑨步）

### 技能定位（九步法）

```text
第⑥步  前端设计（《前端设计.md》）          _contracts.md + 各应用详设 → 逐应用 前端详设.md + dashboard 设计  ← 已定义
            ↓
第⑦步  前端编码（《前端编码.md》）          前端详设.md → app/<组>/<应用>/view.{js,html}            ← 已定义
            ↓
第⑧步  前端测试用例（《前端测试.md》）      逐应用前端详设 → 逐应用 前端测试用例.md + 组级补充一份   ← 已定义
            ↓
★第⑨步  前端测试执行（本文件）              逐应用用例 → app/<组>/tests/verify_view_<组>_<应用>.py + app/<组>/tests/verify_view_<组>.py（0 报错跑通） ← 本规格
```

> 第⑧步与第⑨步即「生成与执行分离」的两半（与后端 ④⑤ 同构）：第⑧步产出**用例（数据）**，第⑨步把用例**逐应用翻译成 playwright 脚本并运行**。
>
> **粒度（v1.1 重构）**：逐应用脚本各管一页（admin 会话：本页渲染/列表/模态/表单 + 本会话 0 报错），可单独跑、单独 triage、单页演进只改一个脚本；组级脚本 `verify_view_<组>.py` 管壳/菜单序/dashboard/受限用户。逐应用脚本是范式 `design/前端验收样板/verify_view_e2e.py` 的**按页切片**，组级脚本与之**同构**（去掉逐应用段）。

### 必给参数
- 英文应用组名 `<组>`（snake_case），逐字绑定 `app/<组>/`。
- （可选）`<应用名>` 子集：只翻译/运行指定应用的脚本；缺省＝全部逐应用脚本 + 组级脚本。
- 会话范围：**逐应用脚本恒为 admin 单会话**；受限会话（受限用户菜单收敛）**仅在组级脚本**。

## 用例五要素 → 脚本映射（核心方法论）

| 用例要素 | 脚本落地（照 `verify_view_e2e.py` 范式） |
|---|---|
| **页面** `<组>:<key>` | `goto` 入口 URL + `location.hash = '#/<key>'`；逐应用脚本只切到本页（切页后断言主区重建，`page-in` 实例换新）；组级脚本遍历菜单。 |
| **前置造数** `应用.服务(参数)` | `pg.evaluate` 内 `fetch('/api/apps/<应用>/call/<服务>', {method:'POST', body: JSON.stringify(参数)})`——带会话 Cookie 走**真实 REST**（pitfalls #18），不绕平台直连 DB；单据号从响应 `data` 捕获串联。逐应用脚本按本用例 §0 字典**自足造数**（含跨应用前置），不依赖其他脚本的残留数据。 |
| **操作** 浏览器动作 | playwright locator：点单号 `button.b-link:visible:has-text("<精确单号>")`、填表 `fill`、点按钮 `button:visible:has-text(...)`（隐藏 ≠ 不存在，pitfalls #14）。 |
| **断言** 模态全字段 | `wait_modal()`：轮询 `.modal-mask:visible .loadbox` 消失再断言（pitfalls #16）；多 `.modal-bd` 取 `.first.inner_text()`（#15）；逐字段标签/值 `assert in`。 |
| **断言** 挂载防粘滞 | 非看板页 `assert pg.locator(".kpi").count() == 0`（看板特征元素，pitfalls #2）——**不可省**，否则首页粘滞会假过。dashboard 页断言相反（`.kpi` > 0），在组级脚本。 |
| **断言** 受限菜单（**仅组级脚本**） | 播种受限角色 `users.set_role_page_grants("limited_role", [...])`（清单逐字取自组级用例 §5）→ 新 browser context 登录 → 菜单项集合断言 + 直访无授权 hash 回落断言（目标 = 菜单首项，pitfalls #38）。 |
| **断言** 0 报错 | 每个脚本会话起始挂 `page.on("console"/"pageerror"/"response")` 收集器；结尾 `assert` 三个集合为空（favicon 404 除外；受限会话 403 属预期执法，豁免）。 |

## 执行环境与隔离（铁律，见 VIEW_CONVENTION §工作流第 4 步与 pitfalls #39）

1. **路径锚定**：脚本在 `app/<组>/tests/` 下，项目根经范式 `_project_root()` **向上查找 `fde_platform/`** 定位（落点深度不固定，勿写死 `parents[N]`）；`os.chdir(ROOT)`；`sys.path` 加 `ROOT`（import `fde_platform`、`fde_platform.dbguard`）。
2. **数据库隔离**：进入即 `isolate_dbs().__enter__()` + `atexit` 注册退出还原——空库起步、跑完删除测试残料、原样还回用户真实数据（分毫不丢）。**每个脚本各自隔离**：脚本间不共享任何数据，各自从空库造数。
3. **跑前杀 dev server**：Windows 下运行中的 `main.py` 占用 `.db` 句柄会导致隔离失败——执行本步**先终止**一切 dev server 进程。
4. **动态端口起平台子进程**：脚本自行 subprocess 起 `main.py`（随机空闲端口），跑完（含失败，经 atexit）终止；不依赖外部已起的服务器。注意：逐应用脚本也起**全组平台**（页面依赖跨应用服务与壳），隔离粒度在数据库、不在平台。
5. **串行**：dbguard 持跨进程独占锁（`fde_platform/.dbguard.lock`），并行跑多个 verify（前端/后端皆然）会被干净拒绝——**勿绕**（2026-07-30 并行踩踏曾洗掉用户库）。逐应用脚本因此天然顺序执行，无额外编排成本。
6. **playwright 前置**：`pip install playwright && python -m playwright install chromium`（无头 Chromium）。

## 执行铁律

- **真实链路**：造数走 REST、页面经平台壳真实渲染（动态 import 工厂 + x-html 装配），不 mock 前端、不直连 DB。
- **数据字典只引用不新造**：§0 冻结标识贯穿全脚本；单据号一律从造数响应捕获串联。
- **逐应用先、组级后**：先跑绿全部（或指定）逐应用脚本，再跑组级脚本——单页渲染不通时，菜单/受限断言连环 fail，无从 triage。逐应用脚本内部单会话直跑（无 phase 之分）。
- **切页必 reload 场景意识**：注册表 mtime 缓存——新写/改页面后首次验证要 `pg.reload()` 才重扫（pitfalls #6）。

## 失败 triage（首轮几乎不会全绿，须归类）

用例是**未运行**生成的，选择器/字段标签为推断，故首跑必有出入。每个 FAIL 归三类（报告按脚本名定位应用）：

1. **脚本 / 用例翻译错**——选择器没加 `:visible`、模态 `.modal-bd` 撞 strict mode、字段标签文案不符、造数入参名不对 → **修脚本或回填用例**（并据实修正对应用例文件 §7 待确认）。
2. **前端代码 bug**——第⑦步视图缺陷（漏字段、svc 变量拼名致受限 403、reactive 未同步建好喷 null、漏默认导出空页）→ **记录**，反馈第⑦步修复，不在本步擅自改 `view.*`。
3. **真实应用 bug**（少见）——后端服务返回结构与契约不符等 → 记录，反馈第③步。

报告须能逐条定位：失败在哪个脚本、哪个 `step`、哪条用例、实际 DOM/报错是什么。

## 验收标准

- **每个脚本**可独立运行：`python app/<组>/tests/verify_view_<组>_<应用>.py` / `python app/<组>/tests/verify_view_<组>.py`（跑前无 dev server、无并行 verify）。
- 全部逐应用脚本 + 组级脚本用例**全绿**，或每个 FAIL 已明确 triage 并记录。
- **0 console error · 0 pageerror · 0 HTTP≥400**（favicon 除外；受限会话 403 豁免）——**按脚本会话计**，任一脚本任一非豁免报错即该脚本不通过。
- 运行**不污染用户真实数据**（每个脚本 dbguard 退出后原样还原）。
- 报告逐脚本、逐条 PASS/FAIL + 失败定位 + triage 归类；向用户报告入口 URL + 页面清单 + 各脚本验证结果。

## 收尾衔接

- **白名单**：新脚本的精确命令（逐应用 `Bash(python app/<组>/tests/verify_view_<组>_<应用>.py)` ×N + 组级 `Bash(python app/<组>/tests/verify_view_<组>.py)`）加进 `.claude/settings.json`。
- **页面演进同步**（pitfalls #38）：此后新增/调整页面——新应用各加一个逐应用脚本；**组级脚本**里 `limited_role` 授权清单与直访回落断言、菜单序断言必须逐字对齐当前菜单（本耦合极易漏，改页面即改组级脚本）。
- **视图资源红线自检**：验收中如发现需要 `/app/<名>/<path>` 通配 serve 才能过——**是设计错误**（视图只经写死端点 `/app/<名>/view.{js,html}`，同目录 `.py`/`.db` 绝不暴露；见 README §测试与验收红线），修页面而非改平台。

## 命名与边界

- 脚本落点 `app/<组>/tests/`（产物随应用组归档）：
  - 逐应用 `app/<组>/tests/verify_view_<组>_<应用>.py`（应用名逐字取文件夹名，如 `sales` 组的 `sales_order` 应用 → `verify_view_sales_sales_order.py`）；
  - 组级 `app/<组>/tests/verify_view_<组>.py`（与范式 `verify_view_e2e.py` 同构）。
  与后端第⑤步**同落点**——前后端测试产物统一随组归档于 `app/<组>/tests/`（各带 `verify_view_` / `verify_chain_` 前缀与组后缀报告，互不冲突）。
- 本步**只翻译并运行测试**，不改前端 / 应用代码；发现的 bug 分别反馈第⑦ / 第③步。
- 测试设计**只来自第⑧步用例文件**（逐应用 + 组级补充），不凭前端详设另起用例（保持「生成与执行」单一数据源）。

## 平台化入口（第⑨步自动化任务）

平台 `/groupbuild` 页面 ⑫ 前端测试执行（任务 `kind="fverify"`，`fde_platform/groupbuild_runner.py`）
把本步产品化为一键任务（生成 + 运行一体）：

- `gather`：硬预检逐目标应用 `前端测试用例.md` + 组级补充用例（⑪产出，缺 → 失败指回⑪）+ `playwright` 可导入（不可用 → 失败带安装命令 `pip install playwright && python -m playwright install chromium`）+ 范式 `design/前端验收样板/verify_view_e2e.py` 存在。
- `gen`：N 应用脚本 + 1 组级脚本同池摊平生成（`GROUPBUILD_FVERIFY_PARALLEL` 默认 4）；每脚本输入 = 铁律 preamble（基建段照抄范式 / 造数组限定 REST / 选择器规避 / PASS·FAIL@STEP 骨架 / 只写脚本不改码）+ 执行规格摘要 + 范式全文 + pitfalls + 对应用例全文；门禁（语法可编译 + PASS/FAIL@ 骨架 + dbguard 隔离 + playwright 启动）不过 → 整份重出（≤`GROUPBUILD_FVERIFY_REPAIR` 轮，默认 2）。
- `run`：脚本落 `app/<组>/tests/verify_view_<组>_<应用>.py` + `app/<组>/tests/verify_view_<组>.py`，**逐脚本串行真跑**（dbguard 跨进程锁天然互斥；单脚本动态端口子进程 + 超时 `GROUPBUILD_FVERIFY_RUN_TIMEOUT` 默认 600s）；verdict 按 rc + PASS 打印解析，失败步取 `FAIL @`/`ERROR @` 行；单脚本失败 → LLM 修脚本重跑 ≤2 轮（错误签名去重提前终止；triage 纪律：脚本错自动修，前端/后端 bug 保持忠实断言只记录）；单脚本失败不阻断后续，全败才 raise。
- `write`：报告 `app/<组>/tests/前端测试报告.md`（逐脚本 verdict 表 + 失败尾摘 + triage 去向）；最终判据 = 全部脚本 PASS ∧ 各会话 0 报错。

API：`POST/GET/DELETE /api/groupbuild/groups/<组>/fverify`（POST body `{app_names?}` 缺省全部已有用例的应用；GET `?report=1` 下载报告、`?zip=1` 脚本包；DELETE 删该组全部脚本 + 报告）。隔离语义：dbguard 移走真实库运行、退出还原——**用户数据零污染**（运行期间避免对该组做业务操作，移库窗口内写入会随还原丢弃）。
