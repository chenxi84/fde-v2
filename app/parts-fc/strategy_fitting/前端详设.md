# strategy_fitting（策略仿真拟合）前端详设
> 来源：app/parts-fc/_contracts.md（冻结契约）+ app/parts-fc/strategy_fitting/应用详设.md；产出供第⑦步前端编码 / 第⑧步前端测试用例
> 落位：`app/parts-fc/strategy_fitting/view.js` + `app/parts-fc/strategy_fitting/view.html`（与 `strategy_fitting.py` 同文件夹，落盘即进启动清单与授权清单，零接线）；import 一律绝对路径 `/view/lib/*`；模板经 `new URL("view.html", import.meta.url)` 抓取；工厂 `export default function pageStrategyFitting()`（保留专名）

## 1. 页面元数据 PAGE_META

| 字段 | 值 | 说明 |
|---|---|---|
| key | `strategy_fitting` | = 应用文件夹名，page_id 为 `parts-fc:strategy_fitting` |
| name | 策略拟合 | 侧栏菜单名 |
| ic | 🎯 | 菜单图标字 |
| title | 策略仿真拟合 | 主区页面头 |
| crumb | 策略拟合 · 滚动回测 · 候选策略打分排名 | 头部副题 |
| order | 80 | 已按业务序预分配，直接用；升序即菜单序 |

- 页面零鉴权：无任何权限判断；菜单按页面授权渲染在 shell，数据范围由后端闸门执法，401 由 api.js 自动跳登录。
- 本应用契约**无 update / set_* / import_batch / delete** → 无编辑入口、无删除按钮；单据变更仅经状态机动作（add_candidate / run_backtest / select_strategy）与创建。
- 回测执行由后端 `run_backtest` 触发，前端仅发请求并刷新。

## 2. 区块构成

### 2.1 列表区（查）—— 三段式：过滤条 / 表格 / 分页条

**用途**：拟合任务台账，按零件号、状态筛选，承载行内操作入口。

**过滤控件（与 `svc("strategy_fitting","list")` 可过滤参数 part_no, status 一一对应；契约无 keyword 参数 → 不设关键字搜索框，禁止前端假过滤）**：

| 控件 | 对应参数 | 选项 |
|---|---|---|
| 零件号输入 | `part_no` | 文本输入框，精确匹配 |
| 状态下拉 | `status` | 全部 / 拟合中 / 已选定 / 生效中（value 为后端真实值，源码枚举：拟合中→已选定→生效中） |
| 分页 | `page` / `page_size` | `pageable()` 分页条 |

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集；字段序与详情/表单一致）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 拟合单号 | `fit_no` | `.b-link`，点击开详情模态 |
| 零件号 | `part_no` | 正文 |
| 车型 | `veh_model` | 正文 |
| 需求形态 | `demand_shape` | `hue()` 徽章（五色：稳定/波动/季节/短生命周期/断续） |
| 历史数据区间 | `data_range` | 正文，空值 `dash()` |
| 回测规格 | `backtest_spec` | 正文，空值 `dash()` |
| 状态 | `status` | `hue()` 徽章（三色：拟合中=蓝 / 已选定=橙 / 生效中=绿） |
| 拟合人 | `fitter` | 正文 |
| 拟合日期 | `fit_date` | `fmtTime()` |
| 操作 | — | 按 `status` 的行内动作，`x-show`（见 §5.1） |

**交互**：任一过滤变化 → 重置回第 1 页重载；操作成功后刷新当前页；空结果显示空态文案（不喷 toast）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 状态徽章 / KV 分组体 + 候选明细子表 / 状态操作页脚

**用途**：点 `fit_no` 弹出，展示 `svc("strategy_fitting","get")` 返回的**全部**业务字段（含候选明细列表）。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `fit_no` + `status` 徽章 + `demand_shape` 徽章 | 墨青头带，徽章 `hue()` |
| 基本信息 | `fit_no` / `part_no` / `veh_model` / `demand_shape` | `.kv`；`fit_no` 注明「系统生成 · 全局唯一」 |
| 回测配置 | `data_range` / `backtest_spec` | `.kv`；空值 `dash()` |
| 拟合信息 | `fitter` / `fit_date` | `.kv`；`fmtTime()` |
| 审计时间 | `created_at` / `updated_at` | `fmtTime()` |
| 候选策略明细（子表） | 见下方候选明细表 | 内嵌表格 `.tbl.tight`，回测后显示指标 |
| 原始数据 | get 返回全量 JSON | 底部折叠 |

**候选策略明细子表（`.tbl.tight` + `.scroll-x`）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 序号 | `cand_no` | 正文 |
| 策略 | `strategy` | 正文（方法+参数） |
| 配套库存策略 | `inv_policy` | 正文 |
| MAPE | `mape` | `fmt()` 百分比，空值 `dash()` |
| Bias | `bias` | `fmt()` 百分比 + 正负方向标注，空值 `dash()` |
| 服务水平 | `service_level` | `fmt()` 百分比，空值 `dash()` |
| 库存代价 | `inv_cost` | `fmt()`，空值 `dash()` |
| 综合分 | `score` | `fmt()`，排名高亮 |
| 排名 | `rank` | 正文，#1 绿色标记 |
| 选定标记 | `selected` | ★ 星标或 `hue()` 徽章 |

**交互**：页脚 `.modal-ft` 按当前状态放状态机按钮（逻辑同 §5.1）；动作成功后用返回对象原地刷新模态字段 + 列表行。

### 2.3 创建表单（增）—— 模态表单

**用途**：覆盖 `svc("strategy_fitting","create")` 接受的**全部**可写业务参数。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `part_no` | input | ★ 必填 | 须在 vehicle_part_map 中存在生效映射行（BR-07） |
| `veh_model` | input | ★ 必填 | 须在 vehicle_part_map 中存在生效映射行（BR-07） |
| `demand_shape` | select：稳定 / 波动 / 季节 / 短生命周期 / 断续（value 为后端真实值，原样传参） | ★ 必填 | 系统建议 + 人工确认（BR-08） |
| `data_range` | input，格式 `YYYY-MM~YYYY-MM` | 可选 | 历史数据区间，默认 None |

- **不进表单**：`fit_no`（系统生成）、`status`（初始"拟合中"）、`fitter` / `fit_date` / `backtest_spec` / `created_at` / `updated_at`（系统写入）。
- 布局：必填先行、frow 语义分组、底部右对齐提交按钮；校验 = 必填红星 + toast 警告（必填为空不发请求）。
- 提交成功：toast 带出新 `fit_no` → 关闭模态 → 重置过滤重载列表。

#### 2.3.2 添加候选策略（行内操作 / 模态内操作）

**用途**：在拟合单详情模态中，点击【添加候选】按钮弹出子表单，覆盖 `svc("strategy_fitting","add_candidate")` 接受的参数。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `fit_no` | 隐藏（当前拟合单） | ★ 必填 | 从当前详情模态继承 |
| `strategy` | input，如 `指数平滑 α=0.3` | ★ 必填 | 方法名 + 参数键值对（BR-12） |
| `inv_policy` | input，如 `安全库存 3 天 / 周补货` | ★ 必填 | 安全库存天数 + 补货频率（BR-13） |

- 提交成功：toast → 候选明细子表追加新行 → 列表行刷新。

## 3. svc 字面量清单（授权派生依据——必须字面量 svc("应用","服务")）

| 区块 | 调用（应用.服务） | 参数 | quiet | 说明 |
|---|---|---|---|---|
| 列表区 | `svc("strategy_fitting","list")` | `{part_no, status, page, page_size}` | — | 过滤查询；空条件传 undefined 不带 |
| 详情模态 | `svc("strategy_fitting","get")` | `{fit_no}` | — | 全字段详情（含候选明细列表） |

| 行内 / 模态页脚 | `svc("strategy_fitting","add_candidate")` | `{fit_no, strategy, inv_policy}` | — | 添加候选策略 |
| 行内 / 模态页脚 | `svc("strategy_fitting","run_backtest")` | `{fit_no}` | — | 执行滚动回测；后端异步计算 |

> 以上 7 处必须在 view.js 中以字面量逐项书写（可包在闭包里），**勿用变量拼名**——这是页面授权隐式放行派生扫描的唯一来源。

## 4. 数据来源与下拉

**本页无跨应用下拉数据源**（需求形态、状态均为契约固定枚举，非动态从其他应用拉取）。

**契约 payload → 区块字段映射**：

| 来源 | payload 字段 | 去向 |
|---|---|---|
| `svc("strategy_fitting","list")` 项 | fit_no, part_no, veh_model, demand_shape, data_range, backtest_spec, status, fitter, fit_date, created_at, updated_at | 列表区表格列（1:1） |
| `svc("strategy_fitting","get")` | 同上全量 + 候选明细列表（cand_no, strategy, inv_policy, mape, bias, service_level, inv_cost, score, rank, selected） | 详情模态全部 KV 分组 + 候选明细子表 + 原始数据折叠 |
| `svc("strategy_fitting","create")` 返回 | 拟合单对象（含 fit_no, status=拟合中） | toast 展示 fit_no → 列表重载 |
| `svc("strategy_fitting","add_candidate")` 返回 | 新增候选明细行 | 候选明细子表追加 → 列表行刷新 |
| `svc("strategy_fitting","run_backtest")` 返回 | 拟合单对象（候选明细 mape/bias/service_level/inv_cost/score/rank 已填充） | 原地更新已开模态候选子表 + 列表行 |
| `svc("strategy_fitting","select_strategy")` 返回 | 拟合单对象（selected=True, status=生效中） | 原地更新已开模态候选子表 selected 标记 + 列表行 status |

## 5. 交互要点

1. **按状态的行内动作（状态机，行操作列与模态页脚共用判定）**：
   - `status=拟合中` → 【添加候选】【执行回测】（若候选 >= 2）【选定策略】（若回测已完成，即 score/rank 已填充）；
   - `status=已选定` → 模态页脚【选定策略】（`select_strategy` 将状态变为"生效中"并标记 selected=1）；
   - `status=生效中` → 无操作按钮（策略已锁定，重拟合由后端触发）；
   - 动作成功：toast + 刷新列表；非法流转由后端 FdeError 经 api.js 统一 toast。
2. **候选策略选定**：在候选明细子表中，每行根据 `status=拟合中` 且回测已完成（有 score/rank）展示【选定策略】按钮；调用 `select_strategy` 后该行 selected=True 标记 ★，拟合单 status 直接变为"生效中"（一步完成，无中间状态）。
3. **回测执行反馈**：点击【执行回测】后显示加载态（回测可能耗时），完成后 toast + 刷新候选子表指标列；回测中途错误由 api.js 统一 toast。
4. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 状态徽章 + 需求形态徽章。
5. **候选明细子表**：位于详情模态中段，回测前仅显示 cand_no / strategy / inv_policy；回测后追加 mape / bias / service_level / inv_cost / score / rank / selected 列；rank=1 绿色高亮。
6. **展示工具**：`hue()`（demand_shape 五色、status 三色徽章：拟合中/已选定/生效中）、`dash()`（空值字段）、`fmtTime()`（fit_date / created_at / updated_at）、`fmt()`（mape / bias / service_level / score 等数字）；本页无 `*_json` 快照字段，无需 `tryParse()`。
7. **toast**：创建成功 / 添加候选成功 / 回测完成 / 选定成功；其余错误一律由 api.js 统一呈现。

## 6. 验收关注点（供第⑧步前端测试用例）

1. **路由渲染**：`#/strategy_fitting` 挂载出列表三段式（过滤条 + 表格 + 分页条），**页面无 `.kpi`**（防看板挂载粘滞假过）；菜单「🎯 策略拟合」按 order=80 定位。
2. **造数后列表有数据**：经 `svc("strategy_fitting","create")` 造多条拟合单（覆盖 拟合中/已选定/生效中 与 稳定/波动/季节等形态）→ 列表行数正确，fit_no / part_no / veh_model / demand_shape / status 列非空。
3. **过滤一一对应**：status=拟合中 下拉仅拟合中行；part_no 输入框精确匹配；无匹配显示空态且不抛错。
4. **模态全字段**：点 fit_no 开模态，断言 fit_no / part_no / veh_model / demand_shape / data_range / backtest_spec / status / fitter / fit_date / created_at / updated_at 全部可见 + 候选明细子表 + 「原始数据」可展开；生效中拟合单的模态页脚无动作按钮。
5. **候选明细子表**：回测前仅战略/库存策略列；回测后 mape/bias/service_level/inv_cost/score/rank/selected 列填充；rank=1 高亮绿。
6. **表单落库**：创建表单填 part_no / veh_model / demand_shape（★）+ data_range → 提交 → 列表出现新拟合单且 status=拟合中；必填为空 toast 警告且不发请求。
7. **添加候选**：在拟合中拟合单详情模态中点击【添加候选】，填 strategy / inv_policy → 提交 → 候选子表新增一行。
8. **回测执行**：拟合中拟合单（候选 >= 2）点击【执行回测】→ 显示加载态 → 完成后候选子表指标列填充、排名生成。
9. **选定策略**：回测完成后在候选行点【选定策略】→ 调用 `select_strategy(fit_no, cand_no)`，系统自动将该候选标记为 selected 并将拟合单状态直接置为"生效中"（一步完成选定+生效，无需额外确认步骤）。
10. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP>=400（受限会话 403 属预期执法单独豁免）。
