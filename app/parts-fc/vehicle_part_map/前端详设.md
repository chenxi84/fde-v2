## 2. 区块构成

### 2.1 列表区（查）—— 三段式：过滤条 / 表格 / 分页条

**用途**：车型零件映射总览，按零件号/车型/生命周期阶段/状态维度筛选，承载行内量纲变更与停用入口。

**过滤控件（与 `vehicle_part_map.list(part_no, veh_model, lc_stage, status, page, page_size)` 可过滤参数一一对应；契约无 keyword 参数 → 不设关键字搜索框，禁止前端假过滤）**：

| 控件 | 对应参数 | 选项 |
|---|---|---|
| 零件号输入框 | `part_no` | 文本输入，模糊匹配（若后端支持；否则精确匹配） |
| 车型输入框 | `veh_model` | 文本输入 |
| 生命周期阶段下拉 | `lc_stage` | 全部 / 爬坡 / 成熟 / 衰退 / EOP临近（BR-9 枚举，原值传参） |
| 状态 chips | `status` | 全部 / 生效 / 停用（BR-12 枚举） |
| 分页 | `page` / `page_size` | `pageable()` 分页条（契约签名 string 型，照传即可） |

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集；字段序与详情/表单一致）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 零件号 | `part_no` | `.b-link`，点击开详情模态 |
| 车型 | `veh_model` | `.b-link`，点击开详情模态 |
| 平台 | `platform` | 正文，空值 `dash()` |
| 单车用量 | `usage` | 数字 `fmt()` |
| 份额 | `share` | 百分比 `fmt()` |
| 生命周期阶段 | `lc_stage` | `hue()` 徽章（爬坡→蓝 / 成熟→绿 / 衰退→橙 / EOP临近→红） |
| 生命周期形态 | `lc_shape` | 正文（传统 / 上市高后下滑） |
| SOP | `sop` | `fmtTime()` 日期 |
| EOP | `eop` | `fmtTime()` 日期，空值 `dash()` |
| 映射依据 | `source` | 单行省略 `.cell-ellipsis` |
| 状态 | `status` | `hue()` 徽章（生效→绿 / 停用→灰） |
| 创建时间 | `created_at` | `fmtTime()` |
| 更新时间 | `updated_at` | `fmtTime()` |
| 操作 | — | 按 `status` 的行内动作，`x-show`（见 §5.1） |

**交互**：任一过滤变化 → 重置回第 1 页重载；量纲变更/停用/编辑成功后刷新当前页；空结果显示空态文案（不喷 toast）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 状态徽章 / KV 分组体 / 页脚操作

**用途**：点 `part_no` 或 `veh_model` 弹出，展示 `vehicle_part_map.get` 返回的**全部**业务字段 + 量纲历史版本子表。

**头带**：`part_no` + `veh_model` + `status` 徽章（`hue()`）。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 基本信息 | `part_no` / `veh_model` / `platform` / `status` / `source` | `.kv`；`part_no` + `veh_model` 注明「联合业务键 · 全局唯一」（BR-1） |
| 量纲信息 | `usage` / `share` | `.kv`，数字高亮；注明「权威源 · 变更走 set_usage/set_share 生成历史版本」（BR-2） |
| 生命周期 | `lc_stage` / `lc_shape` / `sop` / `eop` | `.kv`；`lc_shape` 为"上市高后下滑"时注明「驱动衰减模型」（BR-4） |
| 时间信息 | `created_at` / `updated_at` | `fmtTime()`；注明 `created_by` / `updated_by` |
| 量纲历史版本 | `usage_history` 子表 | `.tbl.inside` 表格，列：`field_type` / `old_value` / `effective_from` / `effective_to` / `change_basis` / `changed_at`；按 `changed_at` 倒序 |
| 原始数据 | get 返回全量 JSON | 底部折叠 |

**页脚操作**：按当前 `status` 提供操作按钮（`.modal-ft`），见 §5.1。

**交互**：页脚操作按钮按当前状态 `x-show`；量纲变更成功后用返回对象原地刷新模态字段 + 列表行。

### 2.3 创建表单（增）—— 模态表单

**用途**：覆盖 `vehicle_part_map.create` 接受的**全部**可写业务参数。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `part_no` | input | ★ 必填 | BR-5（后端经物料主数据校验存在性，不存在时 FdeError toast） |
| `veh_model` | input | ★ 必填 | BR-6（后端经车型主数据校验存在性） |
| `platform` | input | 可选 | BRD 标注「上移预测场景必填」 |
| `usage` | number input，>=0 | ★ 必填 | BR-7 |
| `share` | number input，0~100 | ★ 必填 | BR-8 |
| `lc_stage` | select：爬坡 / 成熟 / 衰退 / EOP临近 | ★ 必填 | BR-9 |
| `lc_shape` | select：传统 / 上市高后下滑，默认传统 | ★ 必填 | BR-10 / BR-4 |
| `sop` | date input | ★ 必填 | BR-11（须 < eop） |
| `eop` | date input | 可选 | BR-11 |
| `source` | input，maxlength=200 | ★ 必填 | BR-13 |
| `status` | select：生效 / 停用，默认生效 | 可选（系统默认，UI 展示但不可改） | BR-12（新建恒生效） |

- **不进表单**：`created_at` / `updated_at` / `created_by` / `updated_by`（系统写入）。
- 布局：必填先行、frow 语义分组、底部右对齐提交按钮；校验 = 必填红星 + toast 警告。
- 提交成功：toast 带出新记录 `part_no` + `veh_model` → 关闭模态 → 重置过滤重载列表。

## 3. svc 字面量清单（授权派生依据——必须字面量 svc("应用","服务")）

| 区块 | 调用（应用.服务） | 参数 | 说明 |
|---|---|---|---|
| 列表区 | `svc("vehicle_part_map","list")` | `{part_no, veh_model, lc_stage, status, page, page_size}` | 过滤查询；空条件传 undefined 不带 |
| 详情模态 | `svc("vehicle_part_map","get")` | `{part_no, veh_model}` | 全字段详情 + usage_history |

| 创建表单 | `svc("vehicle_part_map","create")` | `{part_no, veh_model, platform, usage, share, lc_stage, lc_shape, sop, eop, source}` | 创建新映射；status 默认"生效" |
| 编辑表单 | `svc("vehicle_part_map","update")` | `{part_no, veh_model, kwargs}` | 更新一般属性（不含量纲字段）；kwargs 仅含变更字段 |
| 用量变更弹窗 | `svc("vehicle_part_map","set_usage")` | `{part_no, veh_model, new_usage, effective_date, basis}` | 变更单车用量；旧值写入 usage_history |

> 以上 8 处必须在 view.js 中以字面量逐项书写（可包在闭包里），**勿用变量拼名**——这是页面授权隐式放行派生扫描的唯一来源。

## 4. 数据来源与下拉

**无外部下拉数据源**：本应用为主数据型页面，过滤下拉选项均来源于契约枚举值（lc_stage / status），不涉及跨应用主数据下拉。

**lc_stage 下拉选项**（来自 BR-9 枚举 + list 返回项去重补充）：
- 全部 / 爬坡 / 成熟 / 衰退 / EOP临近

**status chips 选项**（来自 BR-12 枚举）：
- 全部 / 生效 / 停用

**契约 payload → 区块字段映射**：

| 来源 | payload 字段 | 去向 |
|---|---|---|
| `vehicle_part_map.list` 项 | part_no, veh_model, platform, usage, share, lc_stage, lc_shape, sop, eop, status, source, created_at, updated_at, created_by, updated_by | 列表区表格列（1:1） |
| `vehicle_part_map.get` | 同上（全量）+ usage_history 子表 | 详情模态全部 KV 分组 + 量纲历史版本表格 + 原始数据折叠 |
| `vehicle_part_map.get_usage_history` | part_no, veh_model, effective_from, effective_to, field_type, old_value, change_basis, changed_at | 详情模态量纲历史版本子表 |
| `vehicle_part_map.create` 返回 | 完整记录（含 status=生效） | toast 展示 part_no+veh_model → 列表重载 |
| `vehicle_part_map.update` 返回 | 更新后完整记录 | 原地更新已开模态 + 列表行 |
| `vehicle_part_map.set_usage` 返回 | 更新后完整记录 + 新 usage_history 记录 | toast → 原地更新模态 + 列表行 |
| `vehicle_part_map.set_share` 返回 | 更新后完整记录 + 新 usage_history 记录 | toast → 原地更新模态 + 列表行 |
| `vehicle_part_map.disable` 返回 | 更新后记录（status=停用） | toast → 原地更新模态 + 列表行 |

## 5. 交互要点

1. **按状态的行内动作 + 模态页脚共用判定**：
   - `status=生效` → 【编辑】【变更用量】【变更份额】【停用】。
   - `status=停用` → 无操作按钮（终态，不可逆）（BR-12）。
   - 动作成功：toast + 刷新列表；非法操作（如对停用映射点变更用量）由后端 FdeError 经 api.js 统一 toast，页面不硬编状态机校验。

2. **用量/份额变更走专用弹窗**：
   - update 接口不含量纲字段（usage/share）——编辑表单中不显示这两个字段。
   - set_usage / set_share 各为独立小型模态弹窗，包含 `new_value` + `effective_date` + `basis` 三个字段。
   - 弹窗内显示当前值作为参考，提交时前端校验 new_value 合法性（usage>0, share 0~100），不合法则 toast 警告不发请求。

3. **停用确认**：
   - 停用为不可逆操作，弹出确认框（非小型模态表单），需用户二次确认。
   - reason 必填（BR-15），空 reason 提交时 toast 警告。

4. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 状态徽章。

5. **编辑表单与量纲变更的分工**：
   - 编辑表单（update）：更新 platform / lc_stage / lc_shape / sop / eop / source 等一般属性。
   - 用量变更弹窗（set_usage）：仅变更 usage，生成历史版本。
   - 份额变更弹窗（set_share）：仅变更 share，生成历史版本。
   - 停用确认弹窗（disable）：仅变更 status，不生成历史版本。

6. **量纲历史版本子表**：在详情模态中以内嵌表格展示；按 `changed_at` 倒序；支持展开/折叠。

7. **展示工具**：`hue()`（lc_stage / status / lc_shape 徽章）、`dash()`（空值字段）、`fmtTime()`（sop/eop/created_at/updated_at）、`fmt()`（usage/share 数字千分位/百分比）、`tryParse()`（若存在 JSON 字段）。

8. **toast**：创建成功 / 编辑成功 / 用量变更成功 / 份额变更成功 / 停用成功 / 必填未填警告；其余错误一律由 api.js 统一呈现。

9. **lc_shape="上市高后下滑" 高亮**：在列表和详情中对此值使用醒目样式（如橙黄色文字 + 虚线底边），提示计划关注衰减模型。

## 6. 验收关注点（供第⑧步前端测试用例）

1. **路由渲染**：`#/vehicle_part_map` 挂载出列表三段式（过滤条 + 表格 + 分页条），**页面无 `.kpi`**（防看板挂载粘滞假过）；菜单「🔗 车型零件映射」按 order=30 定位。

2. **造数后列表有数据**：经 `vehicle_part_map.create` 造多条映射记录（覆盖不同 lc_stage/status 组合）→ 列表行数正确，part_no / veh_model / usage / share / lc_stage / status / source 列非空。

3. **过滤一一对应**：lc_stage=成熟下拉仅成熟行；status=生效 chips 仅生效行；part_no 输入框过滤正确；多条件组合；无匹配显示空态且不抛错。

4. **模态全字段**：点 part_no 开模态，断言 part_no / veh_model / platform / usage / share / lc_stage / lc_shape / sop / eop / status / source / created_at / updated_at 全部可见 + 「量纲历史版本」子表可展开 + 「原始数据」可展开；停用映射的模态页脚无操作按钮。

5. **创建表单落库**：创建表单填 part_no / veh_model / usage=1 / share=100 / lc_stage=爬坡 / lc_shape=传统 / sop / source → 提交 → 列表出现新记录且 status=生效（US-1-AC1）；空 part_no 提交 → toast 警告且不发请求。

6. **编辑表单落库**：生效行点击【编辑】→ 修改 lc_stage 从"爬坡"改为"成熟" → 提交 → toast → 模态回显 lc_stage=成熟；编辑表单中无 usage/share 字段（已走专用入口）。

7. **用量变更真实回显**：生效行【变更用量】→ 填写 new_usage=2 + effective_date + basis → toast「用量已变更：1 → 2」→ 列表行 usage=2 → 详情模态 usage_history 新增一条记录（US-5-AC1）；new_usage=0 提交 → toast 警告不发请求（US-5-AC2）；basis 为空提交 → 后端 FdeError toast（US-5-AC3）。

8. **份额变更真实回显**：生效行【变更份额】→ 填写 new_share=60 + effective_date + basis → toast「份额已变更：55% → 60%」→ 列表行 share=60 → usage_history 新增一条（US-6-AC1）；new_share=120 提交 → toast 警告不发请求（US-6-AC2）；new_share=0 提交允许（退出供应，US-6-AC3）。

9. **停用不可逆**：生效行【停用】→ 确认框 → 填写 reason → toast「映射已停用」→ 行 status=停用 → 行操作列无任何按钮 → 模态页脚无操作按钮（US-7-AC1）；已停用行再次点停用 → 后端 FdeError toast（US-7-AC2）。

10. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP≥400（受限会话 403 属预期执法单独豁免）。
