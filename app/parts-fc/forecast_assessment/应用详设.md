## 1. 需求概览

### 1.1 基本信息

| 属性 | 值 |
|---|---|
| 应用名 | forecast_assessment |
| 类名 | ForecastAssessment |
| 业务定义 | 事后闭环——转单率 / FVA / 达成率考核与归因，反哺信任折扣 / 策略重拟合 / 参数校准 |

### 1.2 需求背景

#### 1.2.1 为什么需要这个需求？

毛需求加工链从 OEM 收集、基线生成、销售修正、核对、汇总、牛鞭修正到发布，已解决了"怎么加工预测"的问题。但还有两个核心问题未闭合：

1. **如何保证报数质量？** 销售天然存在放大偏置（报多有动机——抢分配、留缓冲、保达成），修正值不默认采信，需要事后核验"当时报了什么 vs 实际发生了什么"。
2. **如何持续改进预测体系？** 系统需要从偏差中学习，把每次偏差转化为下次更准的输入——即控制层"不断把缺乏考虑的因素纳入体系"的数据依据。

同时，业务层有三个管控手段需要在考核中落地：
- **可控性原则**：只追销售可控的偏差，OEM 需求塌方等不可控因素须剔除
- **双口径各评各的**：转单率（发运口径）评报数质量，FVA/准确率（消耗口径）评预测能力
- **通用件上移**：通用件呆滞难归因到个人，考核不下沉到个别销售

#### 1.2.2 期望达到什么目标？

1. **激励闭环**：让报数的人有动机报实——转单率 + 呆滞归因 -> 分配优先 / 呆滞考核 -> 如实报数
2. **数据闭环**：实际（结算 / 发运）-> 指标（准确率 / Bias / 达成率 / FVA / 转单率）-> 反哺（信任折扣 / D10 / 拆解参数 / 修正规则）
3. **控制层闭环**：月度复盘 -> 归因发现 -> 纳入遗漏因素（新事件类别 -> D06 / 新形态 -> 拆解 / 新阈值）

### 1.3 需求范围

#### 1.3.1 包含哪些功能？

1. **考核记录创建**：系统根据发布快照（R 版）和实际结算/发运数据自动生成考核记录
2. **指标计算**：转单率、偏差量、FVA（基线误差 - 核定误差）、OEM 预测达成率、基线准确率 / Bias
3. **归因认定**：四分类归因（销售多报 / OEM 需求塌方 / 事件影响 / 基线方法失准）+ 举证
4. **考核结论**：计入考核 / 免责剔除 / 归因流程·策略
5. **信任折扣获取**：按客户 / 零件维度输出达成率数据，反哺 D04 信任校准视角
6. **FVA 数据获取**：输出基线/修正/核定/实际四列数据，供修正规则评估
7. **申诉功能**：一线销售对已归档结论发起申诉（附证据），回退到待归因状态重审
8. **列表查询**：按零件号 / 期间 / 考核期等维度筛选考核记录

#### 1.3.2 不包含哪些功能？

1. 计划达成率的考核计算（计划达成率属于产销协同层级，不在本应用中计算，仅作为月度复盘参考指标引用）
2. 呆滞库存的具体责任分摊与财务处理（本应用输出归因结论供呆滞考核使用，呆滞的具体处理在 ERP/履约系统中）
3. 分配优先的实际库存分配操作（本应用输出转单率数据供分配决策参考，分配操作在执行系统）
4. 信任折扣 / D10 重拟合 / 参数表更新的自动执行（本应用输出反哺数据，具体更新动作在目标应用内完成）
5. 申诉审批工作流引擎（申诉结论由总部计划人工复核决定，本应用提供状态扭转与留痕，不内置审批工作流）

## 3. 业务场景

### 3.1 业务流程描述

#### 场景一：月度考核常规闭环流程

**触发条件**：每月结算关账、发运数据到达并对账完成后

**步骤**：

1. **数据到达与对账**（由外部系统完成）：
   - 结算实际数据（IF-A1：零件×客户×期间，消耗口径）到达
   - 发运实际数据（IF-A4：调拨/订单执行量，发运口径）到达
   - 与 R 版发布快照完成对账，确认数据完整可考核

2. **创建考核记录**（系统自动）：
   - 系统调用 `demand_release.get` 取 R 版发布快照作为预测基准（fcst_qty）
   - 系统调用 `demand_processing.get_approved` 取基线值/修正值快照（base_qty / adj_qty）用于 FVA 计算
   - 对每个零件×车型×期间生成一条考核记录
   - 自动计算转单率、偏差量
   - 通用件生成总量行（跨客户汇总）
   - 初始状态：**待归因**

3. **归因认定**（总部计划）：
   - 总部计划逐条审查偏差记录（优先审查超容忍区间的记录）
   - 按四分类归因：销售多报 / OEM 需求塌方 / 事件影响 / 基线方法失准
   - 每项归因须附证据（外部减产公告 / 结算趋势 / 收发货记录 / 三件套登记等）
   - 确认归因后状态变为：**待结论**

4. **考核结论**（总部计划）：
   - 基于归因认定给出结论：计入考核 / 免责剔除 / 归因流程·策略
   - 结论确认后状态变为：**已归档**
   - 反哺数据自动可供下游引用

5. **反哺动作**（跨应用联动）：
   - 信任折扣更新 -> D04 信任校准视角
   - 基线准确率异常 -> D10 重拟合触发
   - FVA 汇总 -> D04 修正规则调整
   - 转单率 -> 分配优先 / 呆滞考核
   - 归因发现 -> 控制层新事件类别/新形态/阈值修订

6. **月度复盘**（总部计划 + 销售管理）：
   - 与月度产销平衡会节奏联动
   - 复盘预测准确率、Bias、计划达成率
   - 输出下一轮需求计划的改进动作

#### 场景二：销售申诉重审流程

**触发条件**：一线销售对"已归档"考核结论有异议

**步骤**：

1. **发起申诉**（一线销售）：
   - 销售查看本人考核记录，对结论有异议
   - 提交申诉申请，**必须附新证据**（不得超过原结论中未出现的证据）
   - 考核记录状态：**已归档 -> 待归因**

2. **重新归因**（总部计划）：
   - 总部计划收到重审通知
   - 结合申诉证据重新审查归因
   - 可维持原归因或修正归因
   - 状态回到：**待归因 -> 待结论**

3. **重新结论**（总部计划）：
   - 总部计划给出新的考核结论
   - 归档，申诉记录留痕

#### 场景三：通用件总量层考核流程

**触发条件**：通用件（part_kind = 通用）的考核周期触发

**步骤**：

1. **总量行生成**：系统为通用件生成总量行考核记录（跨客户汇总），不下沉到单个销售的客户维度
2. **总量层归因**：归因在总量层面进行，不区分个别销售贡献
3. **结论备案**：通用件考核结论为"总量层备案"，呆滞考核上移至总量/后端层面

### 3.2 业务规则

#### BR-01：快照不可变原则

考核引用 R 版发布快照（预测值）与实际结算/发运快照，"当时报了什么、实际是什么"不可变。任何后续修订须走新版本，不得覆盖已归档的考核记录。

#### BR-02：可控性原则

只追可控偏差，剔除不可控偏差。OEM 需求塌方（车型减产/召回/骤停）属不可控，销售免责。但塌方认定**必须举证**（外部减产信息 / 车型销量骤降 / 结算趋势 / 客户函件），不以销售自述免责。

#### BR-03：容忍区间规则

设考核容忍区间（默认 ±10%，全局参数可配置，来源 BRD §2.16.2）。偏差在容忍区间内的记录自动标记"区间内免追责"提示，系统仍生成待归因记录，最终由总部计划确认是否追责。若连续多期处于容忍区间内、信誉累计良好，可在复盘时适度放宽。

#### BR-04：双口径各评各的

- **转单率（发运口径）**：实际转单（调拨/发运）/ 核定毛需求（发布口径，含事件加项），评报数质量，用于分配优先和呆滞考核
- **FVA/准确率（消耗口径）**：结算实际 vs 基线/核定值，评预测能力，用于修正规则评估和策略重拟合

两套口径不得混用。转单率不用结算量，FVA 不用发运量。

#### BR-05：通用件考核上移

通用件跨多个客户且呆滞难归因到个人，考核在总量/后端层面进行：
- 考核记录生成总量行（跨客户汇总），不下沉到个别销售
- 归因在总量层完成
- 呆滞考核上移至总量/后端层面
- 个别销售有实证多报的除外（可单独追溯）

#### BR-06：归因必须举证

任何归因认定必须附证据：
- 销售多报：须对比三件套登记、同期无外部减产/塌方证据、无断点漏登
- OEM 需求塌方：须附外部减产公告/车型销量骤降数据/结算趋势/客户函件
- 事件影响：须关联 D06 事件单号、漏登或误判的具体依据
- 基线方法失准：须附多期准确率趋势、方法评估对比

#### BR-07：申诉必须附新证据

一线销售发起申诉时，必须附上新证据（申诉时尚未在记录中出现的证据），不得无证据申诉。已归档记录回退为"待归因"时，原归因结论和证据保留为历史版本，申诉证据以增补方式记录。

#### BR-08：FVA 计算公式

FVA（预测增值）= 基线误差 - 核定误差，其中：
- 基线误差 = |基线值 - 结算实际|
- 核定误差 = |核定毛需求（发布口径）- 结算实际|
- FVA > 0：修正带来预测增值（修正后更接近实际）
- FVA < 0：修正拉低准确率（修正后更远离实际）

FVA 分层呈现：销售修正 vs 基线（一线贡献）、核定 vs 修正（总部校准贡献），归因到环节。

#### BR-09：字段级校验规则

| 规则编号 | 字段 | 规则 | 触发时机 |
|---|---|---|---|
| BR-09-01 | fa_no | 格式 `FA-YYYYMM-NNN`，唯一约束 | create |
| BR-09-02 | period | 格式 YYYY-MM，不能为未来期间 | create |
| BR-09-03 | fcst_qty | 必须 > 0 | create |
| BR-09-04 | settle_qty | 必须 >= 0 | create |
| BR-09-05 | actual_qty | 必须 >= 0 | create |
| BR-09-06 | base_qty / adj_qty | 快照自 D04，不得手工输入 | create |
| BR-09-07 | conv_rate | 系统计算 = actual_qty / fcst_qty（发运口径），不可手工输入 | create / update |
| BR-09-08 | dev_qty | 系统计算 = actual_qty - fcst_qty，不可手工输入 | create / update |
| BR-09-09 | attribution | 归因认定时必填，含类别（枚举）+ 证据（文本，非空） | attribute |
| BR-09-10 | result | 结论时必填，枚举值：计入考核 / 免责剔除 / 归因流程·策略 | conclude |
| BR-09-11 | assessor | 归因认定和结论时自动记录当前操作人 | attribute / conclude |
| BR-09-12 | cycle | 考核期 = period 所在月度 + T+1 月关账后，系统自动赋值 | create |
| BR-09-13 | part_no | 必须引用系统中存在的零件号（弱引用物料主数据） | create |
| BR-09-14 | veh_model | 对专用件必填，通用件总量行可为空或标记为总量行 | create |

#### BR-10：状态迁移规则

| 规则编号 | 规则 | 说明 |
|---|---|---|
| BR-10-01 | "创建"只能落为"待归因" | 新考核记录初始状态必为"待归因" |
| BR-10-02 | "待归因 -> 待结论"需归因完整 | attribution 字段非空且证据完整 |
| BR-10-03 | "待结论 -> 已归档"需结论完整 | result 字段非空 |
| BR-10-04 | "已归档 -> 待归因"仅限申诉 | 且须附新证据 |
| BR-10-05 | "已归档"后不可直接修改 | 只能通过申诉流程重审 |

#### FUNC-01：创建考核记录（create）

**功能描述**：系统在结算/发运数据到达并对账完成后，自动基于 R 版发布快照和实际数据创建考核记录。系统自动取数、自动计算指标，不依赖人工录入。

**用户流程**：
1. 外部实际数据（IF-A1 结算、IF-A4 发运）到达，对账完成
2. 系统触发考核创建（定时或事件驱动）
3. 系统逐零件×车型×期间生成考核记录
4. 自动计算 conv_rate、dev_qty
5. 通用件生成总量行
6. 记录初始状态为"待归因"

**输入数据**：

| 输入项 | 来源 | 说明 |
|---|---|---|
| 零件号 | 物料主数据 | 考核粒度 |
| 客户·车型 | D01 / 物料主数据 | 考核粒度（专用件），通用件总量行可为空 |
| 期间 | 对账期间 | 被考核的月度 |
| 预测值（fcst_qty） | D09 R 版快照 | 调用 demand_release.get 获取 |
| 实际转单值（actual_qty） | IF-A4 发运系统 | 调拨/发运量 |
| 结算实际（settle_qty） | IF-A1 ERP 结算 | 消耗口径 |
| 基线值（base_qty） | D04 基线快照 | 调用 demand_processing.get_approved 获取 |
| 修正值（adj_qty） | D04 修正快照 | 调用 demand_processing.get_approved 获取 |
| 考核期（cycle） | 系统自动 | 按期间+T+1月赋值 |

**输出数据**：
- 一条考核记录（fa_no、part_no、veh_model、period、fcst_qty、actual_qty、conv_rate、dev_qty、settle_qty、base_qty、adj_qty、cycle），状态为"待归因"

**业务规则**：
- BR-01：fcst_qty 来自 R 版快照，不可变
- BR-04：双口径数据分别获取
- BR-05：通用件生成总量行
- BR-09-01 至 BR-09-08：字段校验规则
- BR-10-01：初始状态"待归因"

**特殊处理**：
- 同一零件×期间已存在考核记录时，不重复创建（幂等）
- 如果对应的 D09 R 版不存在或 D04 快照缺失，记录创建失败并返回明确错误
- 容忍区间检查：偏差量在 ±10% 内的记录自动标记"区间内"提示，但仍需归因

**跨应用调用**（self.fde.call）：
- 调用 `demand_release.get(rel_no)` -> 取 R 版发布快照，获取预测值（fcst_qty）
- 调用 `demand_processing.get_approved(proc_batch, part_no, period)` -> 取基线值（base_qty）和修正值（adj_qty）快照

**业务实体**：

| 实体 | 说明 |
|---|---|
| ForecastAssessment（考核单头） | 考核记录主体，一条对应一个零件×车型×期间 |

**字段表**：

| 字段名 | 代码 | 类型 | 必填 | 默认值 | 业务逻辑 |
|---|---|---|---|---|---|
| 考核单号 | fa_no | String | 是 | 系统生成 | 格式 `FA-YYYYMM-NNN`，全局唯一 |
| 零件号 | part_no | Ref | 是 | — | 弱引用物料主数据 |
| 客户·车型 | veh_model | Ref | 条件必填 | — | 专用件必填，通用件总量行可为空或标记"TOTAL" |
| 期间 | period | YYYY-MM | 是 | — | 被考核期间，不能为未来期间 |
| 预测值 | fcst_qty | Decimal | 是 | — | 核定毛需求发布口径（含事件加项），快照自 D09 R 版 |
| 实际转单值 | actual_qty | Decimal | 是 | 0 | 调拨/发运量（发运口径），来源 IF-A4 |
| 转单率 | conv_rate | Decimal | 是 | 系统计算 | = actual_qty / fcst_qty，发运口径 |
| 偏差量 | dev_qty | Decimal | 是 | 系统计算 | = actual_qty - fcst_qty |

| 基线值 | base_qty | Decimal | 是 | — | FVA 计算用，快照自 D04 基线 |

| 考核结论 | result | Enum | 否 | — | 计入考核 / 免责剔除 / 归因流程·策略 |
| 考核期 | cycle | Ref | 是 | 系统赋值 | 月度，T+1 月关账后 |

#### FUNC-02：查询考核详情（get）

**输出数据**：

- 一线销售仅能查看本人负责零件的考核记录（数据权限控制）

| cycle | Ref | 考核期 |
| status | Enum | 待归因 / 待结论 / 已归档 |
| attribution | Enum | 归因类别（销售多报 / OEM 需求塌方 / 事件影响 / 基线方法失准） |
| result | Enum | 考核结论 |

**输出数据**：
- 考核记录列表（分页），每条含 fa_no、part_no、period、fcst_qty、actual_qty、conv_rate、dev_qty、attribution、result、status

**业务规则**：
- 一线销售仅返回本人负责零件的记录（数据权限过滤）
- 总部计划和销售管理可查看全部记录

**特殊处理**：
- 默认按 dev_qty 降序排列（偏差最大的在前），方便重点审查
- 支持按 conv_rate 排序（转单率最低的在前）

**原型参考**：参考 BRD §2.9.9 表样 ① 考核表布局，列表视图为该表样的筛选版。

#### FUNC-04：归因认定（attribute）

**功能描述**：总部计划对处于"待归因"状态的考核记录进行四分类归因认定，附上业务证据。

**用户流程**：
1. 总部计划在考核列表中选中待归因记录
2. 进入归因工作台，查看到完整的偏差数据和相关上下文（D04 三件套登记、D06 事件关联、外部减产信息等）
3. 选择归因类别（四选一）：销售多报 / OEM 需求塌方 / 事件影响 / 基线方法失准
4. 填写证据（文本，必填，不可为空）
5. 确认提交

**输入数据**：

| 输入项 | 类型 | 必填 | 说明 |
|---|---|---|---|
| fa_no | String | 是 | 考核单号 |
| attribution_cat | Enum | 是 | 销售多报 / OEM 需求塌方 / 事件影响 / 基线方法失准 |
| attribution_evidence | Text | 是 | 证据描述（非空），可含附件链接/关联单据引用 |
| 关联 D06 事件 | Ref | 条件必填 | 归因"事件影响"时必填，关联 event_no |

**输出数据**：
- 考核记录 attribution 字段已更新，状态变更为"待结论"

**业务规则**：
- BR-06：归因必须举证，evidence 不可为空
- BR-10-02：归因完整后状态才能从"待归因"变更为"待结论"
- 归因"事件影响"时必须关联 D06 事件单号
- 归因"OEM 需求塌方"时证据须含外部客观信息，不能仅凭销售自述
- 仅总部计划角色可操作

**特殊处理**：
- 支持暂存归因草稿（attribution 已填写但未确认），状态不改变
- 归因"基线方法失准"时，系统自动生成 D10 重拟合提示（待结论确认后触发）
- 归因"事件影响"时，系统提示"请确认 D06 事件是否已登记/已关闭"（流程反哺）

**跨应用调用**（self.fde.call）：
- 归因"事件影响"时，可调用 `independent_event.get(event_no)` 查看事件详情辅助判断（可选，非强制）

**原型参考**：参考 BRD §2.9.9 归因工作台布局（四类归因选择 + 证据区 + 关联单据）。

#### FUNC-05：考核结论（conclude）

**功能描述**：总部计划在归因认定完成的基础上，给出最终考核结论。结论确定后记录归档，反哺数据可被下游引用。

**用户流程**：
1. 总部计划在考核列表中选中待结论记录
2. 确认归因认定无误
3. 选择考核结论（三选一）：计入考核 / 免责剔除 / 归因流程·策略
4. 确认提交

**输入数据**：

| 输入项 | 类型 | 必填 | 说明 |
|---|---|---|---|
| fa_no | String | 是 | 考核单号 |
| result | Enum | 是 | 计入考核 / 免责剔除 / 归因流程·策略 |

**输出数据**：
- 考核记录 result 字段已更新，状态变更为"已归档"

**业务规则**：
- BR-02：可控性原则——销售多报归为"计入考核"，OEM 需求塌方归为"免责剔除"
- BR-03：容忍区间规则——区间内偏差由总部计划酌情决定是否追责
- BR-10-03：结论完整后归档
- 销售多报 -> 一般归为"计入考核"（转呆滞的按呆滞考核）
- OEM 需求塌方 -> 归为"免责剔除"
- 事件影响 -> 归为"归因流程"（反哺 D06/拆解）
- 基线方法失准 -> 归为"归因策略"（反哺 D10）
- 仅总部计划角色可操作

**特殊处理**：
- 结论确认后，系统自动标记反哺数据就绪状态，供下游引用
- 归档后不可直接修改，只能通过申诉流程回退

**原型参考**：参考 BRD §2.9.9 结论列（计入考核 / 免责剔除 / 归因流程·策略 标注）。

#### FUNC-06：获取信任折扣（get_trust_discount）

**功能描述**：按客户×零件（或客户汇总）维度输出历史达成率数据与信任折扣建议，供 D04 毛需求加工的信任校准视角调用。

**用户流程**（跨应用调用）：
1. D04 在信任校准视角中需要获取某客户×零件的历史达成率
2. D04 调用 get_trust_discount(oem_code, part_no?)
3. 本应用查询已归档的考核记录，汇总历史达成率、偏差方向
4. 返回汇总数据与折扣建议系数

**输入数据**：

| 输入项 | 类型 | 必填 | 说明 |
|---|---|---|---|
| oem_code | Ref | 是 | 客户编码 |
| part_no | Ref | 否 | 零件号，不传则返回该客户全部零件的汇总 |

**输出数据**：

| 输出项 | 类型 | 说明 |
|---|---|---|
| 达成率汇总 | Decimal / JSON | 达成率 = 结算实际 / OEM 原始预测（V 版快照），多期均值+趋势 |
| 偏差方向 | Enum | 一贯多报 / 一贯少报 / 达成率高 / 无明显偏置 |
| 建议折扣系数 | Decimal | 多报扣减（如 1.05）、少报补足（如 0.95）、高信任直采（如 1.0） |
| 数据期数 | Int | 纳入计算的历史期数 |
| 最近考核期 | Ref | 最新一期考核期 |

**业务规则**：
- 仅统计已归档的考核记录
- 折扣系数自动计算为主（D12 月度自动），人工可覆盖但须理由留痕（在信任折扣库中记录）
- 无历史数据时返回默认系数 1.0 并标注

**特殊处理**：
- 按客户汇总时不区分零件（返回客户整体画像），按零件查询时返回该客户×零件的精准折扣
- 达成率高（如 > 95%）且无系统偏置 -> 建议系数 1.0（直接采用）

**跨应用调用**：
- 被 `demand_processing` 的信任校准视角调用（D04 七类校准之一）

#### FUNC-07：获取 FVA 数据（get_fva）

**功能描述**：按零件×期间输出 FVA 完整数据（基线/修正/核定/实际四列 + 基线误差/核定误差/FVA），供 D04 修正规则评估和 D10 重拟合触发。

**用户流程**（跨应用调用）：
1. D04/D10 需要获取某零件×期间的 FVA 数据
2. 调用 get_fva(part_no, period)
3. 本应用查询已创建的考核记录（至少对账完成），计算并返回 FVA 数据

**输入数据**：

| 输入项 | 类型 | 必填 | 说明 |
|---|---|---|---|
| part_no | Ref | 是 | 零件号 |
| period | YYYY-MM | 是 | 被考核期间 |

**输出数据**：

| 输出项 | 类型 | 说明 |
|---|---|---|
| 结算实际 | Decimal | 地面真相，消耗口径 |
| 基线值 | Decimal | D04 统计基线快照 |
| 基线误差 | Decimal | = |基线 - 结算实际| |
| 核定值 | Decimal | D04 核定毛需求（消耗口径） |
| 核定误差 | Decimal | = |核定 - 结算实际| |
| FVA | Decimal | = 基线误差 - 核定误差（正=增值） |
| 销售修正 FVA | Decimal | 销售修正 vs 基线（一线贡献） |
| 总部校准 FVA | Decimal | 核定 vs 修正（总部校准贡献） |

**业务规则**：
- BR-08：FVA 计算公式强制执行
- 数据来源为 D04 快照，不可变
- 考核记录至少已创建（对账完成）即可获取 FVA，不要求已归档

**特殊处理**：
- FVA 分层呈现：销售修正 vs 基线（一线贡献）、核定 vs 修正（总部校准贡献）
- 多期 FVA 汇总趋势可标识"持续增值者""持续拉低者"

**跨应用调用**：
- 被 `demand_processing` 调用（评估修正规则是否需要收紧/放松）
- 被 `strategy_fitting` 调用（基线准确率持续恶化告警触发重拟合）

#### FUNC-08：申诉（appeal）

**功能描述**：一线销售对已归档的考核结论有异议时，发起申诉并附新证据，记录回退为"待归因"状态供总部计划重审。

**用户流程**：
1. 一线销售查看本人考核记录详情
2. 对某条"已归档"的结论有异议
3. 发起申诉操作，填写申诉证据（必填，非空）
4. 确认提交
5. 记录状态回退"待归因"，总部计划收到重审通知

**输入数据**：

| 输入项 | 类型 | 必填 | 说明 |
|---|---|---|---|
| fa_no | String | 是 | 考核单号 |
| appeal_evidence | Text | 是 | 申诉新证据（必填，不可为空，不可与原归因证据完全相同） |

**输出数据**：
- 考核记录状态回退为"待归因"
- 申诉证据附加到记录的操作日志中
- 原归因结论和证据保留为历史版本

**业务规则**：
- BR-07：申诉必须附新证据，不得无证据申诉
- BR-10-04：仅"已归档"状态可发起申诉
- 仅考核记录对应零件的负责销售可发起申诉（数据权限）
- 同一记录可多次申诉（每次须附新证据）

**特殊处理**：
- 申诉操作写入操作日志，记录申诉人、时间、证据
- 通知总部计划工作台"申诉待重审"
- 原归因和结论不删除，以历史版本保留

**原型参考**：参考 BRD §2.9.9 申诉入口（考核详情页的"申诉"操作按钮 + 证据上传区）。

### 6.2 非功能验收标准

| 验收项 | 标准 |
|---|---|

| 接口响应 | get/list 操作 < 2s；get_trust_discount 跨期聚合查询 < 5s |
| 通用件处理 | 通用件总量行数据正确跨客户汇总，不包含专用件数据 |

### 6.3 已知问题或限制

| 编号 | 问题/限制 | 影响 | 建议/备注 |
|---|---|---|---|
| LIM-01 | 计划达成率指标引用外部生产系统数据，本应用不计算计划达成率 | 月度复盘中计划达成率需人工关联或从外部系统获取 | BRD §2.9.3 明确"计划达成率"为产销协同层级联动指标，由外部系统提供 |
| LIM-02 | 实际数据（IF-A1/A4）依赖外部系统对账完成，延迟将顺延考核创建 | 若外部实际数据迟迟不到，考核记录无法生成 | BRD §2.9.7 明确 T+1 月出考核，对账先行 |
| LIM-03 | 信任折扣更新和 D10 重拟合为跨应用联动动作，本应用仅输出数据，不负责自动更新目标应用 | 反哺链路需要总部计划手动触发或定时任务触发 | 后续可考虑实现消息驱动自动反哺 |
| LIM-04 | 通用件总量行不区分个别销售贡献，但若个别销售有实证多报需单独追溯 | 通用件单独追溯需额外人工处理 | BRD §2.9.4 明确"个别销售有实证多报的除外" |
| LIM-05 | 当前版本申诉仅支持一次回退到"待归因"，不支持多级审批工作流 | 复杂的申诉审批流程需总部计划线下协调 | 后续版本可扩展为多级申诉审批 |
| LIM-06 | 容忍区间参数（±10%）为全局默认值，未按零件类别细化 | 不同品类零件可能有不同的考核敏感度 | 参数配置表（§2.16.2）支持按维度配置，待运营数据积累后细化 |

### 7.4 备注

1. **考核不是终点，反哺才是**：本应用是控制层闭环的数据依据，设计上注重"输出反哺数据"的能力，而不只是"出考核结论"。
2. **通用件考核上移**：通用件呆滞难归因到个人，考核在总量层完成，这是与 D07 通用件汇总修正中"总量责任制"的一致性设计。
3. **双口径不可混用**：转单率（发运口径）和 FVA/准确率（消耗口径）分别对应不同的业务目的，在数据存储和计算中须严格区分。
4. **快照引用是硬约束**：一切考核数据引用 R 版/D04 快照，不引用当前值。这是整个 parts-fc 系统"锁定链"规则（R 版发布 -> D04 锁定 -> D03 V 版锁定）在考核环节的延伸。
5. **待确认项**：
   - 计划达成率指标的具体数据接口与取数方式（是否由本应用计算还是纯引用）——待与产销协同团队确认
   - 容忍区间参数是否需要在考核记录创建时按零件类别差异化取值——待运营数据积累后确认
   - 申诉流程是否需要多级审批工作流——当前版本仅支持一次回退重审，复杂场景待后续迭代
