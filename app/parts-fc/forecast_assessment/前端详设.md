# forecast_assessment（预测考核）前端详设
> 来源：app/parts-fc/_contracts.md（冻结契约）+ app/parts-fc/forecast_assessment/应用详设.md；产出供第⑦步前端编码 / 第⑧步前端测试用例
> 落位：`app/parts-fc/forecast_assessment/view.js` + `app/parts-fc/forecast_assessment/view.html`（与 `forecast_assessment.py` 同文件夹，落盘即进启动清单与授权清单，零接线）；import 一律绝对路径 `/view/lib/*`；模板经 `new URL("view.html", import.meta.url)` 抓取；工厂 `export default function pageForecastAssessment()`（保留专名）

## 1. 页面元数据 PAGE_META

| 字段 | 值 | 说明 |
|---|---|---|
| key | `forecast_assessment` | = 应用文件夹名，page_id 为 `parts-fc:forecast_assessment` |
| name | 预测考核 | 侧栏菜单名 |
| ic | 📝 | 菜单图标字 |
| title | 预测转单率考核 | 主区页面头 |
| crumb | 事后闭环 · 转单率/FVA/达成率 · 归因反哺 | 头部副题 |
| order | 120 | 已按业务序预分配，直接用；升序即菜单序 |

- 页面零鉴权：无任何权限判断；菜单按页面授权渲染在 shell，数据范围（一线销售仅本人负责零件）由后端闸门执法，401 由 api.js 自动跳登录。
- 本应用契约**无 update / delete / import_batch** → 无编辑入口、无删除按钮；单据变更仅经状态机动作（create / add_record / attribute / calculate）。
- `conv_rate` / `dev_qty` 由系统自动计算，前端仅展示、不进表单。
- 契约中 `attribute` 服务合并归因认定与考核结论（attribution + result 同一次调用完成），前端归因表单包含两项。

## 2. 区块构成

### 2.1 列表区（查）—— 三段式：过滤条 / 表格 / 分页条

**用途**：考核记录台账，按零件/期间/考核结论筛选，承载行内归因认定动作。

**过滤控件（与 `forecast_assessment.list(part_no, period, result)` 可过滤参数一一对应；契约无 keyword/status 参数 → 不设关键字搜索框与状态过滤，禁止前端假过滤）**：

| 控件 | 对应参数 | 选项 |
|---|---|---|
| 零件号输入 | `part_no` | input，模糊匹配 |
| 期间输入 | `period` | input，格式 YYYY-MM |
| 考核结论下拉 | `result` | 全部 / 计入考核 / 免责剔除 / 归因流程·策略（value 为后端真实值，源码 `attribute` 方法校验枚举，原样传参） |
| 分页 | `page` / `page_size` | `pageable()` 分页条（契约签名 string 型，照传即可） |

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集；字段序与详情/表单一致）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 考核单号 | `fa_no` | `.b-link`，点击开详情模态 |
| 零件号 | `part_no` | 单行正文 |
| 客户·车型 | `veh_model` | 正文，通用件显示「多客户」/空值 `dash()` |
| 期间 | `period` | YYYY-MM |
| 预测值 | `fcst_qty` | `fmt(0)` 数字 |
| 实际转单 | `actual_qty` | `fmt(0)` 数字 |
| 转单率 | `conv_rate` | `fmt(2)`，< 0.9 红色预警，> 1.1 橙色提示 |
| 偏差量 | `dev_qty` | `fmt(0)`，正值绿色、负值红色 |
| 归因 | `attribution` | `.cell-ellipsis` 省略，空值 `dash()` |
| 考核结论 | `result` | `hue()` 徽章（计入考核=红 / 免责剔除=绿 / 归因流程·策略=蓝） |
| 考核期 | `cycle` | 正文 |
| 考核人 | `assessor` | 正文，空值 `dash()` |
| 创建时间 | `created_at` | `fmtTime()` |
| 操作 | — | 按 `result` 的行内动作，`x-show`（见 §5.1） |

- 列表区默认按 `dev_qty` 降序排列（偏差最大的在前），方便重点审查。

**交互**：任一过滤变化 → 重置回第 1 页重载；状态动作成功后刷新当前页；空结果显示空态文案（不喷 toast）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 状态徽章 / KV 分组体 / 状态操作页脚

**用途**：点 `fa_no` 弹出，展示 `forecast_assessment.get` 返回的**全部**业务字段。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `fa_no` + `result` 徽章 | 墨青头带，徽章 `hue()` |
| 基本信息 | `fa_no` / `part_no` / `veh_model` / `period` / `cycle` | `.kv`；`fa_no` 注明「系统生成 · 全局唯一」；`veh_model` 专用件必填、通用件总量行可为空 |
| 预测 vs 实际 | `fcst_qty` / `actual_qty` / `conv_rate` / `dev_qty` | `.kv`，高亮展示；`fcst_qty` 注明「快照自 D09 R 版发布量」；`conv_rate` 注明「系统计算 = actual_qty / fcst_qty（发运口径）」；`dev_qty` 注明「系统计算 = actual_qty - fcst_qty」；`conv_rate` 与 `dev_qty` 加粗高亮（BR-04 双口径各评各的） |
| 结算与基线（FVA数据） | `settle_qty` / `base_qty` / `adj_qty` | `.kv`；`settle_qty` 注明「消耗口径，来源 IF-A1」；`base_qty` 注明「快照自 D04 基线」；`adj_qty` 注明「快照自 D04 修正」 |
| 归因与结论 | `attribution` / `result` | `.kv`；`attribution` 注明「归因类别（四分类）+ 证据文本」（BR-06）；`result` 注明「计入考核 / 免责剔除 / 归因流程·策略」（BR-02 可控性原则） |
| 考核信息 | `assessor` / `cycle` | `.kv`；`assessor` 注明「归因认定时自动记录当前操作人」 |
| 时间信息 | `created_at` / `updated_at` | `fmtTime()`；`updated_at` 注明「归因/结论/申诉时刷新」 |
| 原始数据 | get 返回全量 JSON | 底部折叠 |

- 详情模态中可选择展示 **FVA 视图**（通过 `get_fva_view` 调用）：基线误差 vs 核定误差 vs FVA（正=增值 / 负=拉低），以独立 `.sec` 分组追加在结算与基线分组之后。

**交互**：页脚 `.modal-ft` 按当前状态放状态机按钮（逻辑同 §5.1，与行内动作共用一处 `x-show` 判定）；动作成功后用返回对象原地刷新模态字段 + 列表行。

### 2.3 创建考核期表单（create）—— 模态表单

**用途**：覆盖 `forecast_assessment.create` 接受的参数（period）。系统从 D09 取 R 版发布快照、从 D04 取基线/修正快照，自动计算指标。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `period` | input，placeholder=YYYY-MM | ★ 必填 | BR-09-02（不能为未来期间） |

- **不进表单**：`fa_no` / `fcst_qty` / `actual_qty` / `conv_rate` / `dev_qty` / `settle_qty` / `base_qty` / `adj_qty` / `attribution` / `result` / `cycle` / `assessor`（系统生成/计算/快照固化）、`created_at` / `updated_at`（系统写入）。
- 提交成功：toast 带出考核期批次号 → 关闭模态 → 重置过滤重载列表。`create` 仅创建批次占位（各数量字段初始为 0），后续须逐零件调用 `add_record` 填充实际考核数据。
- 注明：当前版本 `create` 不自动跨应用取快照（返回 note 提示"请逐个零件调用 add_record 填充考核记录"），`add_record` 的 `base_qty`/`adj_qty`/`fcst_qty`/`actual_qty`/`settle_qty` 均需前端手动传入。

### 2.4 添加考核记录表单（add_record）—— 模态子表单

**用途**：覆盖 `forecast_assessment.add_record` 接受的参数，向考核期批次逐零件添加考核记录并自动计算指标。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `fa_no` | 隐藏域（从当前考核批次取） | ★ 必填 | — |
| `part_no` | input | ★ 必填 | BR-09-13（引用物料主数据） |
| `veh_model` | input | ★ 必填 | BR-09-14（专用件必填；通用件总量行填「TOTAL」或留空） |
| `period` | input，placeholder=YYYY-MM | ★ 必填 | BR-09-02（不能为未来期间） |
| `fcst_qty` | input[type=number]，min=0 | ★ 必填 | BR-09-03（必须 > 0） |
| `actual_qty` | input[type=number]，min=0 | ★ 必填 | BR-09-05（必须 >= 0） |
| `settle_qty` | input[type=number]，min=0 | ★ 必填 | BR-09-04（必须 >= 0） |
| `base_qty` | input[type=number]，min=0 | ★ 必填 | 应取自 D04 基线快照（当前版本需手动填入；`add_record` 签名中 `base_qty*` 为必填参数，后端不自动获取） |
| `adj_qty` | input[type=number]，min=0 | ★ 必填 | 应取自 D04 修正快照（当前版本需手动填入；`add_record` 签名中 `adj_qty*` 为必填参数，后端不自动获取） |

- `conv_rate` / `dev_qty` 由系统自动计算（BR-09-07/BR-09-08），前端不传。
- 校验：必填红星 + toast 警告；`fcst_qty` > 0。
- 提交成功：toast「考核记录已添加」→ 关闭子表单 → 刷新列表。
- 同一零件×期间已存在考核记录时后端拒绝（幂等），提示由 api.js 统一呈现。

### 2.5 归因认定表单（attribute）—— 模态子表单

**用途**：覆盖 `forecast_assessment.attribute` 接受的参数。契约中 `attribute` 合并归因认定（attribution）与考核结论（result）为同一次调用，前端在一个表单中完成两者。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `fa_no` | 隐藏域（从当前行取） | ★ 必填 | — |
| `part_no` | 隐藏域（从当前行取） | ★ 必填 | — |
| `period` | 隐藏域（从当前行取） | ★ 必填 | — |
| `attribution` | select + textarea 组合 | ★ 必填 | BR-06 / BR-09-09（四分类归因 + 证据文本非空；value 为后端真实值） |
| `result` | select：计入考核 / 免责剔除 / 归因流程·策略（value 为后端真实值） | ★ 必填 | BR-09-10（结论枚举，源码 `attribute` 方法校验） |
| `evidence` | textarea | 可选，默认空字符串 | BR-06（举证材料描述；虽契约默认空串，但业务上归因必须附证据——前端提示「建议填写举证材料」） |

**归因类别（attribution 的 select 部分，四选一）**：
- 销售多报
- OEM 需求塌方
- 事件影响
- 基线方法失准

**attribution 控件组合**：上方 select 单选归因类别 → 下方 textarea 填写归因详细说明（含证据）；提交时拼接为 `"{类别}: {说明}"` 格式传给 `attribution` 参数，`evidence` 参数独立传递举证材料。

**归因→结论映射提示**（前端辅助提示，不做硬校验——后端负责业务规则）：
- 销售多报 → 一般归为「计入考核」
- OEM 需求塌方 → 一般归为「免责剔除」
- 事件影响 → 一般归为「归因流程·策略」
- 基线方法失准 → 一般归为「归因流程·策略」

- 校验：attribution 类别必选 + 说明文字非空；result 必选。
- 提交成功：toast「归因认定完成 · FA…」→ 关闭子表单 → 刷新列表+已开模态（`result` 字段由后端写库，归因后不再可编辑）。

### 2.6 批量计算（calculate）—— 列表区操作

**用途**：调用 `forecast_assessment.calculate` 对指定考核期批量重新计算指标。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `period` | input，placeholder=YYYY-MM | ★ 必填 | 考核期 |

- 触发方式：列表区工具栏按钮【批量计算】，弹出小型确认模态填 period → 提交。
- 提交成功：toast「批量计算完成 · N 条记录已更新」→ 刷新列表。

### 2.7 FVA 视图（get_fva_view）—— 详情模态内嵌面板

**用途**：在详情模态中按需加载 `forecast_assessment.get_fva_view` 返回的 FVA 分析数据。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `part_no` | 隐藏域（从当前记录取） | ★ 必填 | — |
| `period` | 隐藏域（从当前记录取） | ★ 必填 | — |

- 展示为详情模态中的独立 `.sec` 面板，以 KV + 条形图呈现：
  - 结算实际 / 基线值 / 基线误差 / 核定值 / 核定误差 / FVA（正=增值绿色 / 负=拉低红色）
  - 销售修正 FVA（一线贡献）/ 总部校准 FVA（总部校准贡献）
- 加载方式：详情模态打开后异步 quiet 加载 FVA 数据，失败不阻断模态展示。

> 注意：契约无 `appeal`（申诉）服务——当前版本申诉功能待后端补充服务接口后前端再接入。`get_trust_discount` 为跨应用内部调用（供 D04 使用），不在本页面 UI 中直接调用，不列入前端 svc 清单。

## 4. 数据来源与下拉

**本页无跨应用下拉**：列表过滤中 `result` 为固定枚举（计入考核 / 免责剔除 / 归因流程·策略），归因表单中 `attribution` 类别为固定枚举（四分类），不需从其他应用拉取主数据。

**契约 payload → 区块字段映射**：

| 来源 | payload 字段 | 去向 |
|---|---|---|
| `forecast_assessment.list` 项 | fa_no, part_no, veh_model, period, fcst_qty, actual_qty, conv_rate, dev_qty, settle_qty, base_qty, adj_qty, attribution, result, cycle, assessor, created_at, updated_at | 列表区表格列（1:1） |
| `forecast_assessment.get` | 同上（全量） | 详情模态全部 KV 分组 + 原始数据折叠 |
| `forecast_assessment.get_fva_view` | FVA 分析数据（结算实际/基线值/基线误差/核定值/核定误差/FVA/销售修正FVA/总部校准FVA） | 详情模态 FVA 面板（独立 .sec） |
| `forecast_assessment.create` 返回 | 考核期批次对象（含 fa_no 列表，各记录 result 为空） | toast 展示考核期 → 列表重载 |
| `forecast_assessment.add_record` 返回 | 考核记录对象（含 fa_no，conv_rate/dev_qty 已计算） | toast 展示 fa_no → 列表重载 |
| `forecast_assessment.attribute` 返回 | 考核记录对象（attribution/result 已写入，状态已流转） | 原地更新已开模态 + 列表行 |
| `forecast_assessment.calculate` 返回 | 批量计算结果（更新记录数） | toast → 列表重载 |

**快照字段标注**：`fcst_qty` 注明「快照自 D09 R 版」（BR-01 快照不可变原则）；`base_qty` / `adj_qty` 注明「应取自 D04 基线/修正快照，当前版本需手动填入 `add_record` 接口（后端不做自动获取）」；`settle_qty` 注明「消耗口径，来源 IF-A1」。

## 5. 交互要点

1. **按状态的行内动作（状态机，行操作列与模态页脚共用判定）**：
   - `result` 为空 → 【归因认定】（弹出 attribute 子表单，含归因类别+结论+证据）；
   - `result` 已赋值（计入考核/免责剔除/归因流程·策略） → 终态，无任何按钮（归因完成后不可直接修改）。
   - 动作成功：toast（如「归因认定完成 · FA…」）+ 刷新列表；非法流转由后端 FdeError 经 api.js 统一 toast，页面不硬编状态机校验。
2. **归因表单设计**：`attribute` 合并归因认定+考核结论为一次调用。表单分两区：上方归因区（类别 select + 说明 textarea）+ 下方结论区（result select + evidence textarea）。归因→结论映射在前端以辅助提示形式展示，不做硬校验（后端负责 BR-02/BR-03 业务规则）。
3. **FVA 视图**：详情模态中异步 quiet 加载 `get_fva_view`，渲染在独立 `.sec` 面板中。失败不阻断模态、不喷 toast，面板显示「FVA 数据暂不可用」占位。FVA 值正=增值绿色、负=拉低红色，配合条形图展示基线误差 vs 核定误差。
4. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 结果徽章；`conv_rate` 与 `dev_qty` 高亮展示（转单率低于 0.9 红色预警、偏差负值红色）。
5. **折叠「更多字段 ▾」**：add_record 表单所有字段均为必填，无可折叠字段；attribute 表单中 `evidence` 可收入「更多字段 ▾」折叠区。
6. **展示工具**：`hue()`（result 徽章）、`dash()`（空值）、`fmtTime()`（时间字段）、`fmt()`（数量字段）；`attribution` 字段为文本非 JSON，无需 `tryParse()`；FVA 数据为结构化对象直接渲染。
7. **toast**：创建成功 / 记录添加成功 / 归因认定完成 / 批量计算完成 / 必填未填警告；其余错误一律由 api.js 统一呈现。
8. **列表默认排序**：按 `dev_qty` 降序（偏差最大的在前），方便总部计划优先审查异常记录。

## 6. 验收关注点（供第⑧步前端测试用例）

1. **路由渲染**：`#/forecast_assessment` 挂载出列表三段式（过滤条 + 表格 + 分页条），**页面无 `.kpi`**（防看板挂载粘滞假过）；菜单「📝 预测考核」按 order=120 定位。
2. **造数后列表有数据**：经 `forecast_assessment.create` 创建考核期 → 列表行数正确，fa_no / part_no / period / fcst_qty / actual_qty / conv_rate / dev_qty / result 列非空。
3. **过滤一一对应**：part_no 输入筛选；period 输入筛选；result=计入考核 下拉仅该结论行；多条件组合；无匹配显示空态且不抛错。
4. **模态全字段**：点 fa_no 开模态，断言全部字段可见（含 fcst_qty / actual_qty / conv_rate / dev_qty / settle_qty / base_qty / adj_qty / attribution / result / cycle / assessor）+ 「原始数据」可展开；已归因（result 非空）记录的模态页脚无动作按钮。

6. **创建考核期落库**：create 表单填 period → 提交 → 列表出现新考核记录且 result 为空（US-01-AC1）；快照字段（fcst_qty/base_qty/adj_qty）来源于 D09/D04，数值非空。
