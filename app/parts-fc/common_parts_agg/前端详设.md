> 来源：app/parts-fc/_contracts.md（冻结契约）+ app/parts-fc/common_parts_agg/应用详设.md；产出供第⑦步前端编码 / 第⑧步前端测试用例
> 落位：`app/parts-fc/common_parts_agg/view.js` + `app/parts-fc/common_parts_agg/view.html`（与 `common_parts_agg.py` 同文件夹，落盘即进启动清单与授权清单，零接线）；import 一律绝对路径 `/view/lib/*`；模板经 `new URL("view.html", import.meta.url)` 抓取；工厂 `export default function pageCommonPartsAgg()`（保留专名）

## 1. 页面元数据 PAGE_META

| 字段 | 值 | 说明 |
|---|---|---|
| key | `common_parts_agg` | = 应用文件夹名，page_id 为 `parts-fc:common_parts_agg` |
| name | 通用件汇总 | 侧栏菜单名 |
| ic | 📊 | 菜单图标字 |
| title | 通用件汇总修正 | 主区页面头 |
| crumb | 汇总修正 · 跨销售去重 · 对抗公地悲剧 | 头部副题 |
| order | 90 | 已按业务序预分配，直接用；升序即菜单序 |

- 页面零鉴权：无任何权限判断；菜单按页面授权渲染在 shell，数据范围由后端闸门执法，401 由 api.js 自动跳登录。
- 本应用契约**无 update / set_* / import_batch / delete** → 无编辑入口、无删除按钮；单据变更仅经状态机动作（add_detail / set_dedup / set_split / confirm）。
- sum_qty / dedup_pct 由系统自动计算，界面不可编辑（详情展示注明即可）。

## 2. 区块构成

### 2.1 列表区（查）—— 三段式：过滤条 / 表格 / 分页条

**用途**：通用件汇总单台账，按零件号、期间、状态筛选，承载行内操作入口。

**过滤控件（与 `svc("common_parts_agg","list")` 可过滤参数 part_no, period, status 一一对应；契约无 keyword 参数 → 不设关键字搜索框，禁止前端假过滤）**：

| 控件 | 对应参数 | 选项 |
|---|---|---|
| 零件号输入 | `part_no` | 文本输入框，精确匹配 |
| 期间输入 | `period` | YYYY-MM 格式输入框 |
| 状态下拉 | `status` | 全部 / 待汇总 / 待修正 / 已修正 / 已确认（BRD 枚举，原值传参） |
| 分页 | `page` / `page_size` | `pageable()` 分页条 |

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集；字段序与详情/表单一致）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 汇总单号 | `agg_no` | `.b-link`，点击开详情模态 |
| 零件号 | `part_no` | 正文 |
| 期间 | `period` | YYYY-MM |
| 汇总合计 | `sum_qty` | `fmt()` 数字 |
| 锚参照 | `anchor_ref` | `.cell-ellipsis` 省略或「已填充」徽章 |
| 修正总量 | `dedup_qty` | `fmt()` 数字，空值 `dash()` |
| 修正率 | `dedup_pct` | `fmt()` 百分比（负值红色），空值 `dash()` |
| 修正说明 | `dedup_reason` | `.cell-ellipsis` 省略，空值 `dash()` |
| 拆回分配 | `split_qty` | 空值 `dash()` 或「已分配」徽章 |
| 状态 | `status` | `hue()` 徽章（四色：待汇总/待修正/已修正/已确认） |
| 修正人 | `reviser` | 正文，空值 `dash()` |
| 修正时间 | `revise_time` | `fmtTime()`，空值 `dash()` |
| 操作 | — | 按 `status` 的行内动作，`x-show`（见 §5.1） |

**交互**：任一过滤变化 → 重置回第 1 页重载；操作成功后刷新当前页；空结果显示空态文案（不喷 toast）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 状态徽章 / KV 分组体 + 客户份额明细子表 / 状态操作页脚

**用途**：点 `agg_no` 弹出，展示 `svc("common_parts_agg","get")` 返回的**全部**业务字段（含客户份额明细 + 锚参照详情）。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `agg_no` + `status` 徽章 | 墨青头带，徽章 `hue()` |
| 基本信息 | `agg_no` / `part_no` / `period` | `.kv`；`agg_no` 注明「系统生成 · 全局唯一」 |
| 汇总数据 | `sum_qty` | `.kv`，`fmt()` 数字，注明「Σ 各客户 D04 核定值 · 系统自动计算」 |
| 锚参照 | `anchor_ref` | `.kv`，`tryParse()` 结构化展示：历史实际 / 池化预测 / 因果合计，空值 `dash()` |
| 修正数据 | `dedup_qty` / `dedup_pct` / `dedup_reason` | `.kv`；`fmt()` 数字 + 百分比；`dedup_pct` 注明「(修正值 − 合计) / 合计 × 100」；未修正时 `dash()` |
| 拆回分配 | `split_qty` | `.kv`，`tryParse()` 结构化展示各客户拆回量，空值 `dash()` |
| 修正信息 | `reviser` / `revise_time` | `.kv`；`fmtTime()`，未修正时 `dash()` |
| 审计时间 | `created_at` / `updated_at` | `fmtTime()` |
| 客户份额明细（子表） | 见下方明细表 | 内嵌表格 `.tbl.tight` |
| 原始数据 | get 返回全量 JSON | 底部折叠 |

**客户份额明细子表（`.tbl.tight` + `.scroll-x`）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 客户 | `oem_code` | 正文 |
| 责任销售 | `owner_sales` | 正文 |
| D04 核定值 | `approved_qty` | `fmt()` 数字 |
| 有证据加码量 | `evidence_qty` | `fmt()` 数字，注明「函件/促销/上市等有据加码」 |
| 口头加码量 | `verbal_qty` | `fmt()` 数字，注明「无书面证据加码 · 纳入折减范围」 |

**交互**：页脚 `.modal-ft` 按当前状态放状态机按钮（逻辑同 §5.1）；动作成功后用返回对象原地刷新模态字段 + 列表行。

### 2.3 表单（增 + 修正操作）—— 模态表单

#### 2.3.1 创建汇总单（覆盖 `svc("common_parts_agg","create")` 接受的参数）

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `part_no` | input | ★ 必填 | 须为通用件（D01/D02 标记）；系统自动校验 |
| `period` | input，YYYY-MM | ★ 必填 | 汇总粒度：零件 × 期间 |

- **不进表单**：`agg_no`（系统生成）、`sum_qty`（系统自动汇总 D04 核定值）、`anchor_ref`（系统自动填充三类锚参照）、`status`（初始"待汇总"后自动流转"待修正"）、明细行 / `dedup_qty` / `dedup_pct` / `reviser` / `revise_time` / `created_at` / `updated_at`（系统写入）。
- 布局：必填先行、底部右对齐提交按钮；校验 = 必填红星 + toast 警告。
- 提交成功：toast 带出新 `agg_no` → 关闭模态 → 重置过滤重载列表。

#### 2.3.2 去重修正（set_dedup，在详情模态页脚触发，弹出子表单）

**用途**：覆盖 `svc("common_parts_agg","set_dedup")` 接受的参数。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `agg_no` | 隐藏（当前汇总单） | ★ 必填 | 从当前详情模态继承 |
| `dedup_qty` | input number | ★ 必填 | 修正后总量，Decimal > 0，≥ 承诺量合计（BR-04） |
| `dedup_reason` | textarea，minlength=50 | ★ 必填 | 折减逻辑 + 数据依据（BR-03） |
| `anchor_ref` | 系统当前锚参照（可覆盖） | 可选 | 默认当前值，可调整；Json 对象 |

- 提交成功：toast → 原地刷新模态字段（dedup_qty / dedup_pct / dedup_reason / reviser / revise_time）→ 列表行刷新。

#### 2.3.3 拆回分配（set_split，在详情模态页脚触发，弹出子表单）

**用途**：覆盖 `svc("common_parts_agg","set_split")` 接受的参数。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `agg_no` | 隐藏（当前汇总单） | ★ 必填 | 从当前详情模态继承 |
| `split_detail` | textarea 或动态行编辑器（输入各客户拆回量） | ★ 必填 | Json 格式 `[{oem_code, qty, basis}]`，总量 = Σqty |

- 提交成功：toast → 原地刷新模态 split_qty → 列表行刷新。

#### 2.3.4 添加客户份额明细（add_detail，在详情模态页脚触发，弹出子表单）

**用途**：覆盖 `svc("common_parts_agg","add_detail")` 接受的参数。通常创建时系统自动拉取，本表单用于人工补录。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `agg_no` | 隐藏（当前汇总单） | ★ 必填 | 从当前详情模态继承 |
| `oem_code` | input | ★ 必填 | 客户编码 |
| `owner_sales` | input | ★ 必填 | 责任销售编号 |
| `approved_qty` | input number | ★ 必填 | D04 核定值 |
| `evidence_qty` | input number | 可选 | 默认 0；有证据加码量 |
| `verbal_qty` | input number | 可选 | 默认 0；口头加码量 |

- 提交成功：toast → 客户份额明细子表追加新行 → 列表行刷新。

| 区块 | 调用（应用.服务） | 参数 | quiet | 说明 |

## 4. 数据来源与下拉

**本页无可跨应用下拉数据源**（状态为契约固定枚举，非动态从其他应用拉取）。

**契约 payload → 区块字段映射**：

| 来源 | payload 字段 | 去向 |
|---|---|---|
| `svc("common_parts_agg","list")` 项 | agg_no, part_no, period, sum_qty, anchor_ref, dedup_qty, dedup_pct, dedup_reason, split_qty, status, reviser, revise_time, created_at, updated_at | 列表区表格列（1:1） |
| `svc("common_parts_agg","get")` | 同上全量 + 客户份额明细列表（oem_code, owner_sales, approved_qty, evidence_qty, verbal_qty） | 详情模态全部 KV 分组 + 客户份额明细子表 + 原始数据折叠 |
| `svc("common_parts_agg","create")` 返回 | 汇总单对象（含 agg_no, sum_qty, anchor_ref, 明细行, status=待汇总→待修正） | toast 展示 agg_no → 列表重载 |
| `svc("common_parts_agg","add_detail")` 返回 | 新增明细行 | 客户份额明细子表追加 → 列表行刷新 |
| `svc("common_parts_agg","set_dedup")` 返回 | 汇总单对象（dedup_qty, dedup_pct, dedup_reason, reviser, revise_time, status=已修正） | 原地更新已开模态修正字段 + 列表行 |
| `svc("common_parts_agg","set_split")` 返回 | 汇总单对象（split_qty） | 原地更新已开模态拆回分配字段 + 列表行 |
| `svc("common_parts_agg","confirm")` 返回 | 汇总单对象（status=已确认） | 原地更新已开模态 + 列表行 |

## 5. 交互要点

1. **按状态的行内动作（状态机，行操作列与模态页脚共用判定）**：
   - `status=待汇总` / `status=待修正` → 模态页脚【添加明细】【去重修正】；
   - `status=已修正` → 【去重修正】（可覆盖修正）【拆回分配】【确认】；
   - `status=已确认` → 终态，无任何按钮（已转 D08）。
   - 动作成功：toast + 刷新列表；非法流转由后端 FdeError 经 api.js 统一 toast。
2. **去重修正弹窗**：set_dedup 弹出子表单收集 dedup_qty / dedup_reason；dedup_reason 最小长度 50 字符（BR-03 依据必须完整）；提交前前端校验 dedup_reason 非空且长度达标。
3. **拆回分配弹窗**：set_split 弹出子表单，可提供动态行编辑器输入各客户拆回量（oem_code / qty / basis），也可接受原始 Json 输入。
4. **sum_qty 系统计算标注**：详情模态 sum_qty 旁注明「系统自动汇总 · 不可编辑」；dedup_pct 注明「(修正值 − 合计) / 合计 × 100 · 系统计算」。
5. **anchor_ref 结构化展示**：`tryParse()` 解析 anchor_ref Json，按三锚分组展示（历史实际 / 池化预测 / 因果合计）；创建时系统自动填充。
6. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 状态徽章。
7. **展示工具**：`hue()`（status 四色徽章）、`dash()`（空值字段）、`fmtTime()`（revise_time / created_at / updated_at）、`fmt()`（sum_qty / dedup_qty / approved_qty / evidence_qty / verbal_qty 数字）、`tryParse()`（anchor_ref / split_qty Json 字段）。
8. **toast**：创建成功 / 添加明细成功 / 去重修正成功 / 拆回分配成功 / 确认成功 / dedup_reason 长度不足警告；其余错误一律由 api.js 统一呈现。

## 6. 验收关注点（供第⑧步前端测试用例）

1. **路由渲染**：`#/common_parts_agg` 挂载出列表三段式（过滤条 + 表格 + 分页条），**页面无 `.kpi`**（防看板挂载粘滞假过）；菜单「📊 通用件汇总」按 order=90 定位。
2. **造数后列表有数据**：经 `svc("common_parts_agg","create")` 造多条汇总单（覆盖 待汇总/待修正/已修正/已确认 状态）→ 列表行数正确，agg_no / part_no / period / sum_qty / status 列非空。
3. **过滤一一对应**：status=待修正 下拉仅待修正行；part_no 输入框精确匹配；period=2026-09 输入框仅该期间行；无匹配显示空态且不抛错。
4. **模态全字段**：点 agg_no 开模态，断言 agg_no / part_no / period / sum_qty / anchor_ref（tryParse 三锚展开）/ dedup_qty / dedup_pct / dedup_reason / split_qty / status / reviser / revise_time / created_at / updated_at 全部可见 + 客户份额明细子表 + 「原始数据」可展开；已确认汇总单的模态页脚无动作按钮。
5. **客户份额明细子表**：明细子表含 oem_code / owner_sales / approved_qty / evidence_qty / verbal_qty 列全部渲染正确。
6. **表单落库——创建**：创建表单填 part_no / period（★）→ 提交 → 列表出现新汇总单且 status=待汇总/待修正；必填为空 toast 警告且不发请求。
7. **去重修正**：在待修正汇总单详情模态点击【去重修正】，填 dedup_qty / dedup_reason（>=50 字符）→ 提交 → dedup_qty / dedup_pct / dedup_reason / reviser / revise_time 原地刷新且 status→"已修正"；dedup_reason 不足 50 字符 toast 警告。
8. **拆回分配**：在已修正汇总单详情模态点击【拆回分配】，填 split_detail → 提交 → split_qty 原地刷新。
9. **确认流转**：已修正汇总单点击【确认】→ status→"已确认"。
10. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP>=400（受限会话 403 属预期执法单独豁免）。
