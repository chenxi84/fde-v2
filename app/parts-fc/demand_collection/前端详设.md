## 2. 区块构成

### 2.1 列表区（查）—— 三段式：过滤条 / 表格 / 分页条

**用途**：收集单台账，按客户、预测版本、状态筛选，承载行内状态流转动作与版本管理操作。

**过滤控件（与 `demand_collection.list(oem_code, fcst_version, status)` 可过滤参数一一对应；契约无 keyword 参数 → 不设关键字搜索框，禁止前端假过滤）**：

| 控件 | 对应参数 | 选项 |
|---|---|---|
| 客户下拉 | `oem_code` | 来自 oem 主数据（见 §4）；选项 value=oem_code，label=客户名称 |
| 预测版本下拉 | `fcst_version` | 来自已有数据去重动态生成；默认「全部」 |
| 状态 chips | `status` | 全部 / 草稿 / 已拆解 / 已锁定 / 已替代 / 已作废（原值传参） |
| 分页 | `page` / `page_size` | `pageable()` 分页条 |

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集；字段序与详情/表单一致）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 收集单号 | `collect_no` | `.b-link`，点击开详情模态 |
| 客户 | `oem_code` | 编号正文 + oemMap 命中时附名称小字 |
| 工厂 | `plant_code` | 文本 |
| 预测版本 | `fcst_version` | 文本 |
| 锚定期间 | `base_period` | 文本，YYYY-MM |
| 需求口径 | `demand_type` | 文本（月度滚动预测 / 年度需求） |
| 来源渠道 | `source_channel` | 文本，空值 `dash()` |
| 接收日期 | `recv_date` | `fmtDate()` |
| 收集人 | `collector` | 用户编号 |
| 状态 | `status` | `hue()` 徽章（草稿=灰 / 已拆解=蓝 / 已锁定=绿 / 已替代=橙 / 已作废=红） |
| 上一版本 | `prev_version` | `.b-link`（存在时可点击跳转），空值 `dash()` |
| 备注 | `remark` | `.cell-ellipsis` 省略，空值 `dash()` |
| 创建时间 | `created_at` | `fmtTime()` |
| 操作 | — | 按 `status` 的行内动作，`x-show`（见 §5） |

**交互**：任一过滤变化 → 重置回第 1 页重载；状态动作成功后刷新当前页；空结果显示空态文案（不喷 toast）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 状态徽章 / KV 分组体 + 子表 / 状态操作页脚

**用途**：点 `collect_no` 弹出，调用 `demand_collection.get(collect_no)` 展示**全部**业务字段——单头信息 + 明细行子表（D03-D）+ 拆解快照子表（D03-S）。

**分组（`.sec`）**：

| 分组 | 字段 | 渲染 |
|---|---|---|
| 头带 | `collect_no` + `status` 徽章 | 墨青头带，徽章 `hue()` |
| 基本信息 | `collect_no` / `oem_code` / `plant_code` / `fcst_version` / `base_period` | `.kv`；`collect_no` 注明「系统生成 · 格式 COL-YYYYMM-NNN」 |
| 口径信息 | `demand_type` / `source_channel` / `recv_date` | `.kv`；`recv_date` `fmtDate()` |
| 人员信息 | `collector` / `created_by` / `updated_by` | `.kv`；注明「收集人负责及时性」 |
| 版本信息 | `prev_version` / `status` | `.kv`；`prev_version` 为空时 `dash()` 并注明「首版」 |
| 备注 | `remark` | 多行文本，空值 `dash()` |
| 时间信息 | `created_at` / `updated_at` | `fmtTime()` |
| 明细行子表 | D03-D 字段：`line_no` / `part_no` / `project_no` / `veh_model` / `proj_stage` / `period` / `orig_qty` / `uom` / `data_flag` | `.tbl.compact` 纵表子表格；`data_flag` 为「OEM未提供」时整行色调标灰；`orig_qty` 使用 `fmt()` 格式化为千分位小数 |
| 拆解快照子表 | D03-S 字段：`line_no` / `period` / `noise_adj` / `pulse_qty` / `true_qty` / `has_pulse` / `event_no` / `method` / `basis` / `decomposer` / `decompose_date` | `.tbl.compact` 子表格；`true_qty` = orig_qty − pulse_qty − noise_adj（系统强制恒等式）；`has_pulse` 布尔用 ✓/— 图标；`event_no` 存在时 `.b-link` 可跳转 D06；`noise_adj` / `pulse_qty` / `true_qty` 使用 `fmt()` |
| 原始数据 | get 返回全量 JSON | 底部折叠 |

**交互**：页脚 `.modal-ft` 按当前 `status` 放状态机按钮（逻辑同 §5，与行内动作共用一处 `x-show` 判定）；动作成功后用返回对象原地刷新模态字段 + 列表行。

### 2.3 创建表单（增）—— 模态表单

**用途**：覆盖 `demand_collection.create` 接受的**全部**可写业务参数（oem_code / plant_code / fcst_version / base_period / demand_type / source_channel / recv_date / remark）。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `oem_code` | select（客户下拉，见 §4） | ★ 必填 | BR-01 客户+工厂+版本唯一性 |
| `plant_code` | select（工厂下拉，见 §4） | ★ 必填 | BR-01 |
| `fcst_version` | input，maxlength=20，placeholder="V2026-08" | ★ 必填 | 格式 V+YYYYMM(.x)，BR-01 |
| `base_period` | input type=month 或 placeholder="YYYY-MM" | ★ 必填 | M0 锚定会计期间 |
| `demand_type` | select：月度滚动预测 / 年度需求，默认「月度滚动预测」 | ★ 必填 | 枚举 |
| `source_channel` | select：EDL/EDI / OEM门户 / 邮件Excel / 销售转录 | 可选 | 枚举，可留空 |
| `recv_date` | input type=date，默认当天 | 可选 | 可手动修改 |
| `remark` | textarea，maxlength=500 | 可选，收进「更多字段 ▾」折叠区 | BRD 备注字段 |

- **不进表单**：`collect_no`（系统自动生成，格式 COL-YYYYMM-NNN）、`status`（系统初始=草稿）、`prev_version`（系统自动带出）、`collector` / `created_at` / `updated_at` / `created_by` / `updated_by`（系统写入）。
- **不进表单**：明细行（`add_lines` 入口独立子表单，见 §5 交互要点）。
- 布局：必填先行、frow 语义分组、底部右对齐提交按钮；校验 = 必填红星 + toast 警告。
- 提交成功：toast 带出新 `collect_no` → 关闭模态 → 重置过滤重载列表（新收集单恒「草稿」）。

### 2.4 明细录入子表单（add_lines）—— 模态子表单

**用途**：对草稿收集单调用 `add_lines(collect_no, lines)` 批量录入明细行。lines 数组中每项含：`part_no`、`project_no`、`veh_model`、`period`、`orig_qty`、`uom`、`data_flag`、`proj_stage` 等。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `part_no` | input（零件号） | ★ 必填 | 须存在于物料主数据 |
| `project_no` | input（项目号） | ★ 必填 | FK → D01 project_ledger |
| `veh_model` | input（车型） | ★ 必填 | FK → D02 vehicle_part_map |
| `period` | input，placeholder="YYYY-MM" | ★ 必填 | 期间，按 base_period 折算 |
| `orig_qty` | input type=number，step=0.0001 | 条件必填 | data_flag="正常"时必填；录入后不可直接修改（BR-02） |
| `uom` | select：件 / 套，默认「件」 | 可选 | 须与 D02 量纲一致 |
| `data_flag` | select：正常 / OEM未提供，默认「正常」 | 可选 | OEM未提供时 orig_qty 可留空（BR-05） |
| `proj_stage` | 自动从 D01 读取，只读展示 | — | 非进行中触发警告（BR-06），不硬阻断 |

- 支持逐行添加（动态行列表 + 添加按钮），一次性提交。
- 提交后关闭子表单，刷新模态中的明细子表。

### 2.5 拆解子表单（decompose）—— 模态子表单

**用途**：对明细行逐行执行拆解，调用 `decompose(collect_no, line_no, period, noise_adj, pulse_qty, method, basis)`。系统展示预计算建议值，总部计划审查确认或人工调整。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `line_no` | 锁定（来自选中明细行） | ★ 必填 | 关联明细行 |
| `period` | 锁定（来自选中明细行） | ★ 必填 | 关联期间 |
| `noise_adj` | input type=number，step=0.0001 | ★ 必填 | 带符号；窗口内 Σnoise_adj ≈ 0（BR-04） |
| `pulse_qty` | input type=number，step=0.0001 | ★ 必填 | 带符号；为正表示剥离脉冲 |
| `method` | select/input：移动平均 / 指数平滑 / 阶跃检测 / 发运−结算倒推 / 免拆解 | ★ 必填 | 拆解方法（系统预填建议） |
| `basis` | textarea | ★ 必填 | 拆解依据文本（系统预填建议） |

- `true_qty` = orig_qty − pulse_qty − noise_adj 系统自动计算并展示（只读）。
- 提交后刷新模态中的拆解快照子表。

## 3. svc 字面量清单（授权派生依据——必须字面量 svc("应用","服务")）

| 区块 | 调用（应用.服务） | 参数 | 说明 |
|---|---|---|---|
| 列表区 | `svc("demand_collection","list")` | `{oem_code, fcst_version, status, page, page_size}` | 过滤查询；空条件传 undefined 不带 |
| 列表区 | `svc("demand_collection","list")` | `{page:1, page_size:200}` | 从已有收集单去重 oem_code 生成客户下拉；收集人从 ctx.userno 取当前用户 |
| 详情模态 | `svc("demand_collection","get")` | `{collect_no}` | 全字段详情（单头+明细+拆解快照） |
| 创建表单 | `svc("demand_collection","create")` | `{oem_code, plant_code, fcst_version, base_period, demand_type, source_channel, recv_date, remark}` | 创建收集单头；返回含 collect_no |
| 明细录入 | `svc("demand_collection","add_lines")` | `{collect_no, lines}` | 批量录入明细；lines=[{part_no, project_no, veh_model, period, orig_qty, ...}] |
| 行内 / 子表单 | `svc("demand_collection","decompose")` | `{collect_no, line_no, period, noise_adj, pulse_qty, method, basis}` | 逐行拆解 |
| 行内 / 模态页脚 | `svc("demand_collection","confirm_decompose")` | `{collect_no}` | 拆解确认 → 版本冻结，状态→已拆解 |
| 行内 / 模态页脚 | `svc("demand_collection","cancel")` | `{collect_no, reason}` | 作废收集单（草稿→已作废）；reason 必填 |
| 行内 / 模态页脚 | `svc("demand_collection","lock")` | `{collect_no}` | 锁定版本（D09 联动触发） |
| 行内 / 模态页脚 | `svc("demand_collection","supersede")` | `{collect_no, new_collect_no}` | 版本替代（→已替代） |
| 行内 / 模态页脚 | `svc("demand_collection","version_diff")` | `{collect_no}` | 版本比对 V_n vs V_{n-1}；以模态或侧面板展示差异对照表 |

> 以上 11 处必须在 view.js 中以字面量逐项书写（可包在闭包里），**勿用变量拼名**——这是页面授权隐式放行派生扫描的唯一来源。

## 4. 数据来源与下拉

**客户下拉（过滤条、创建表单共用一份 oemList / oemMap）**：
- oem_code 来源于外部客户主数据（MDM），页面初始化一次性加载；若无专用 oem 服务，则从 `demand_collection.list` 已有数据去重 `oem_code` 动态生成下拉选项。
- 若有 member/org 模块可提供客户列表，则 quiet 探测加载 `svc("member","list")` 或等价服务。

**工厂下拉（创建表单）**：
- plant_code 来源于外部客户主数据；同 oem_code 逻辑——从已有数据去重或外部服务获取。

**契约 payload → 区块字段映射**：

| 来源 | payload 字段 | 去向 |
|---|---|---|
| `demand_collection.list` 项 | collect_no, oem_code, plant_code, fcst_version, base_period, demand_type, source_channel, recv_date, collector, status, prev_version, remark, created_at, updated_at, created_by, updated_by | 列表区表格列（1:1） |
| `demand_collection.get` | 单头（同上全量）+ 明细列表[D03-D 字段] + 拆解快照列表[D03-S 字段] | 详情模态 KV 分组 + 两个子表 + 原始数据折叠 |
| `demand_collection.create` 返回 | 收集单对象（含 collect_no，status=草稿） | toast 展示 collect_no → 列表重载 |
| `demand_collection.add_lines` 返回 | 写入结果确认 | toast → 刷新模态明细子表 |
| `demand_collection.decompose` 返回 | 拆解快照行 | toast → 刷新模态拆解快照子表 |
| `demand_collection.confirm_decompose / cancel / lock / supersede` 返回 | 更新后的收集单对象（新 status） | 原地更新已开模态 + 列表行 |
| `demand_collection.version_diff` 返回 | 版本差异对照表 | 模态/侧面板渲染差异 |

## 5. 交互要点

1. **按状态的行内动作（状态机，行操作列与模态页脚共用判定）**：
   - `status=草稿` → 【录入明细】【逐行拆解】【拆解确认】【作废】；
     - 【录入明细】→ 打开明细录入子表单（add_lines）；
     - 【逐行拆解】→ 选中明细行后打开拆解子表单（decompose），可逐行操作；
     - 【拆解确认】→ 调用 confirm_decompose，恒等式+守恒校验通过后冻结；
     - 【作废】→ 弹出作废原因输入框（reason 必填），确认后调用 cancel。
   - `status=已拆解` → 【版本比对】【锁定】（系统/D09联动）；
     - 【版本比对】→ 调用 version_diff，弹出差异对照模态。
   - `status=已锁定` → 【版本比对】（只读）；终态，无编辑按钮。
   - `status=已替代` → 只读（查看 + 版本比对）；终态。
   - `status=已作废` → 只读；终态，无任何按钮。
   - 动作成功：toast + 刷新列表；非法流转由后端 FdeError 经 api.js 统一 toast，页面不硬编状态机校验。

2. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 状态徽章；明细子表与拆解快照子表可分别折叠。

3. **子表单交互**：
   - 明细录入子表单支持多行动态添加（添加行 / 删除行），批量提交。
   - 拆解子表单从明细子表中选择目标行，携带 orig_qty 展示，自动计算 true_qty 预览。
   - 子表单提交成功后关闭子表单，原地刷新父模态中的对应子表。

4. **折叠「更多字段 ▾」**：创建表单中仅 `remark` 一个可选字段。

5. **quiet 探测性加载**：客户/工厂下拉 quiet + 零值兜底，失败不喷 toast；列表本身正常加载，错误走 api.js 统一通道。

6. **展示工具**：`hue()`（状态徽章，草稿=灰 / 已拆解=蓝 / 已锁定=绿 / 已替代=橙 / 已作废=红）、`dash()`（空值字段）、`fmtTime()`（created_at / updated_at）、`fmtDate()`（recv_date）、`fmt()`（orig_qty / noise_adj / pulse_qty / true_qty 等数值）。

7. **toast**：创建成功 / 明细录入成功 / 拆解成功 / 拆解确认成功 / 作废成功 / 必填未填警告；其余错误一律由 api.js 统一呈现。

8. **版本比对模态**：version_diff 返回值渲染为逐期对照表（期间 / V_{n-1} 值 / V_n 值 / 差异量 / 系统判定），脉冲行高亮，无对比基线时展示「首版，无对比基线」提示。

## 6. 验收关注点（供第⑧步前端测试用例）

1. **路由渲染**：`#/demand_collection` 挂载出列表三段式（过滤条 + 表格 + 分页条），**页面无 `.kpi`**（防看板挂载粘滞假过）；菜单「📥 需求收集」按 order=40 定位。

2. **造数后列表有数据**：通过 `demand_collection.create` 造多条收集单（覆盖草稿/已拆解/已锁定/已替代/已作废）→ 列表行数正确，collect_no / oem_code / fcst_version / status 列非空。

3. **过滤一一对应**：oem_code 下拉仅该客户行；fcst_version 筛选正确；status=草稿 chips 仅草稿行；多条件组合；无匹配显示空态且不抛错。

4. **模态全字段 + 子表**：点 collect_no 开模态，断言单头全部字段可见 + 明细子表（line_no/part_no/period/orig_qty/data_flag）+ 拆解快照子表（noise_adj/pulse_qty/true_qty/method/basis）+ 「原始数据」可展开；已作废/已锁定收集单的模态页脚无编辑操作按钮。

5. **创建表单落库**：创建表单填 oem_code / plant_code / fcst_version / base_period（★）+「更多字段」remark → 提交 → 列表出现新收集单且 status=草稿；空必填字段提交 → toast 警告且不发请求。

6. **明细录入落库**：草稿收集单 → 打开明细录入子表单 → 填写 part_no / project_no / veh_model / period / orig_qty → 批量提交 → 模态中明细子表刷新显示新行。

7. **拆解子表单**：选中明细行 → 打开拆解子表单 → 系统预填 noise_adj / pulse_qty / method / basis 建议值 → 人工调整后提交 → 快照子表更新；true_qty 自动计算展示。
