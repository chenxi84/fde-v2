## 1. 需求概览

### 1.1 基本信息

| 项目 | 内容 |
|---|---|
| 应用名 / 类名 | `baseline_borrowing` / `BaselineBorrowing` |
| 业务定义 | 历史不足零件的基线例外登记（五种借法），保证"借来的基线"可复核、可回溯 |
| 标识（主键） | `jy_no`（JY-YYYYMM-NNN） |
| 流程位置 | 步骤2 · 统计基线预测——历史不足时的例外登记 |
| 类别 | 过程单据（旁路支撑） |
| 主责角色 | 总部计划 |

### 1.2 需求背景

#### 1.2.1 为什么需要这个需求？

在毛需求加工链的步骤2（统计基线预测）中，零件的基线通常由历史结算量经策略仿真拟合（D10）回测选定的方法外推产生。但以下场景中，该零件可用历史数据不足，无法依赖自身历史序列产生可靠的基线：

- 未上市新车型（SOP 前，零历史）
- 短生命周期车型（清洗历史 < 12 个月或无完整季节周期）
- 断点新件（新件零历史，旧件曲线不可直接复用）
- 单车型史短但平台稳定
- 通用件需做分层预测

如果因历史不足而跳过基线生成，D04 加工表将缺少客观"锚"——销售修正失去参照基准、FVA 无法衡量、核对无据可依。因此需要一套"借用"机制，在自身历史不足时从外部引入客观锚。

#### 1.2.2 期望达到什么目标？

1. **保证任何零件在任何场景下都有可用的客观基线锚**——自身历史不足时，锚从外部借来（类比 / 模板 / 先导指标 / 上移 / 池化）。
2. **借来的基线同样可复核、可回溯**——借用方法、来源、参数、校准过程全程留痕，支撑 FVA 考核与事后复盘。
3. **借用的生命周期与退出机制**——自身历史积累充足后自动提示切换 D10 自产策略，防止"永久借用"脱离数据闭环。
4. **沉淀知识库**——类比结论与模板拟合结果反哺类比库/模板库，先验越用越准。

### 1.3 需求范围

#### 1.3.1 包含哪些功能？

1. **借用登记**（FUNC-01）：登记借用单，选择借法、确定来源与参数，生成推导基线。
2. **借用详情查看**（FUNC-02）：查看借用单完整信息（含来源参数、校准记录、推导基线）。
3. **借用列表查询**（FUNC-03）：按零件号、状态等条件筛选借用单列表。
4. **借用审核**（FUNC-04）：总部计划审核借用单，通过后生效（基线生效），驳回后重新登记。
5. **早期校准**（FUNC-05）：有自身早期数据时，用实际数据校准借用参数（峰值、衰减率等）。
6. **推导基线取数**（FUNC-06）：供 D04 步骤2 调用，获取借用基线各期值。
7. **借用关闭**（FUNC-07）：历史转自产或不再需要时关闭借用单。

#### 1.3.2 不包含哪些功能？

- 策略仿真拟合（归属 `strategy_fitting` 应用，D10）
- 统计基线自动生成（归属 `demand_processing` 应用，D04）
- 销售修正与核对（归属 D04）
- 通用件汇总去重（归属 `common_parts_agg` 应用，D07）
- 类比库/模板库/信任折扣库的管理与维护（归属系统级配置与知识沉淀）

### 1.4 涉及角色

| 角色 | 职责 |
|---|---|
| 总部计划 | 选借法、定参数、执行校准、审核借用单（借用单的责任人） |
| 系统 | 历史不足判定、相似车型候选匹配、模板库检索、转充足提示 |
| 一线销售 | 提供类比线索（竞品/同平台车型信息）、客户预测可信度情报 |

## 3. 业务场景

### 3.1 业务流程描述

#### 场景一：新车型类比法借用基线（完整主流程）

**参与者**：系统、总部计划

**前置条件**：D04 步骤2 判定零件 8210003（车型C新车型）hist_months=2 < 12，历史不足。

**流程步骤**：

1. D04 步骤2 判定历史不足，触发借用登记流程。
2. **系统**判定可用借法优先级：无 OEM 滚动预测（跳过先导指标）→ 有相似车型 → 推荐类比法。
3. **系统**调 `vehicle_part_map.get_active_mapping(8210003)` 获取生命周期形态与车型信息，匹配相似车型候选（车型A，同细分/价格带）。
4. **总部计划**选择类比法，确定借用来源为"相似车型A"，设定来源参数（峰值 450、衰减 −4%/月）。
5. **总部计划**提交登记。系统校验 hist_months 不足、借法非空、来源非空，通过后生成 jy_no（JY-YYYYMM-NNN）、计算 derived_qty，状态="待审核"。
6. **总部计划**（核对人角色）审核借用单：
   - 检查借法选择合理性
   - 检查校准是否充分（有 2 个月自身数据 → 需校准）
   - 总部计划执行 calibrate：用首 2 月实际数据校准峰值和衰减率
   - 审核通过，状态="生效"，记录 reviewer 和 review_date
7. D04 步骤2 调用 `baseline_borrowing.get_derived_qty(JY-202608-001)` 获取推导基线各期值，写入 D04-B.base_qty。
8. 每月随基线批次评估：
   - 系统判定 hist_months 是否达标
   - 达标时系统提示"历史转充足，建议切换 D10 自产策略"
   - 总部计划确认切换，调用 close("历史转充足，已切换到 D10 自产策略")，状态="已转自产"

**后置条件**：借用单状态="已转自产"，D10 自产策略接管基线生成。

---

#### 场景二：未上市车型先导指标法借用基线

**参与者**：系统、总部计划

**前置条件**：零件 8320001（车型D未上市）hist_months=0，OEM 已提供滚动预测。

**流程步骤**：

1. D04 步骤2 判定历史不足（hist_months=0），触发借用登记。
2. **系统**判定有 OEM 滚动预测 → 推荐先导指标法（最强替代）。
3. **系统**调 `demand_collection.get_true_qty(collect_no, part_no)` 取 OEM 滚动预测拆解后的真实消耗（true_qty），作为推导基线的入参数据。
4. **总部计划**选择先导指标法、填入来源（OEM 预测版本 V2026-08）、交叉验证预订量 850，提交登记。
5. 系统校验 true_qty 已取得（非 orig_qty），通过后生成 jy_no 和 derived_qty。
6. 总部计划审核通过，状态="生效"，gen_qty 供 D04 取数。
7. SOP 后逐月数据进入，执行校准。

**后置条件**：借用单状态="生效"，D04 可获取推导基线。

#### 场景三：借用单关闭——历史转充足

**参与者**：系统、总部计划

**前置条件**：借用单 JY-202608-001 已生效 6 个月，零件自身历史数据累计至 13 个月且覆盖完整季节周期。

**流程步骤**：

1. **系统**按月判定：hist_months >= 12 且覆盖 ≥ 1 个完整季节周期 → 判定"历史转充足"。
2. **系统**向总部计划发送提示："零件 8210003 历史已转充足（13 个月），建议切换 D10 自产策略，关闭借用单 JY-202608-001"。
3. **总部计划**在 D10 中确认策略选定后，确认切换。
4. **总部计划**调用 close("历史转充足，已切换到 D10 自产策略")。
5. 系统将借用单状态变更为"已转自产"，此后 D04 不再从此借用单取基线。

**后置条件**：借用单状态="已转自产"，D10 自产策略接管。

#### 场景四：借用单驳回与重审

**参与者**：系统、总部计划

**前置条件**：借用单 JY-202608-003（断点新件，模板拟合法）已提交，状态="待审核"。

**流程步骤**：

1. **总部计划**审核 JY-202608-003：
   - 借法=模板拟合（合理，断点新件）
   - source_params="峰值/衰减待定"（参数不明确）
   - calibration 为空（有待校准标记但未校准）
2. 审核不通过，填写驳回理由："新件以旧件曲线做先验，峰值/衰减待定，尚无可校准值，待断点启动后有首期数据再校准后重审。"
3. 借用单状态保持"待审核"（驳回意见记录）。
4. D06 断点事件 EVT-202608-005（+400）生效后，总部计划取到启动量 400 作为首期实际数据。
5. 总部计划更新 source_params 和 calibration，重新提交审核。
6. 审核通过，状态="生效"。

**后置条件**：借用单状态="生效"。

#### 关键不变量

| 编号 | 规则 | 来源 |

| BR-07 | FVA 覆盖借用基线：借用基线与实际结算的偏差同样纳入 FVA 考核，评估借法质量，反哺类比库/模板库（先验越用越准）。 | BRD §2.5.6 规则5 |

#### 业务约束规则

| 编号 | 规则 |
|---|---|
| BR-30 | 同一零件 × 车型在同一 proc_batch 内只能有一张生效的借用单 |
| BR-31 | 借用方法优先级（系统建议，人工可覆盖）：有 OEM 滚动预测 → 先导指标；无预测有相似车 → 类比；有早期数据 → 模板拟合/池化校准；仅有平台层历史 → 上移 |
| BR-32 | 先导指标法必须交叉验证：如预订量 / 在手订单 / 细分大盘趋势与预测值比对，偏差超过阈值须人工确认 |

### 4.3 功能详细说明

#### FUNC-01：借用单登记 (create)

**功能描述**：总部计划为历史不足零件登记借用单。系统校验历史不足判定、借法非空、来源非空，通过后生成借用单号、计算 derived_qty，状态初始为"待审核"。

**用户主流程**：

1. D04 步骤2 触发借用登记（或总部计划手动发起），携带 part_no、veh_model、hist_months、proc_batch。
2. 系统校验 hist_months < 12 或无完整季节周期（BR-01），不通过则拒绝。
3. 系统调 `vehicle_part_map.get_active_mapping(part_no)` 获取生命周期形态与车型信息，推荐借法优先级和相似车型候选。
4. 若选先导指标法，系统调 `demand_collection.get_true_qty(collect_no, part_no)` 取拆解后真实消耗作为 derived_qty 计算输入。
5. 总部计划选择 borrow_method、填写 borrow_source 和 source_params。
6. 系统校验 borrow_method 非空（BR-14）、borrow_source 非空（BR-15）、source_params 非空（BR-16）。
7. 系统根据借法和参数自动计算 derived_qty。
8. 系统生成 jy_no（JY-YYYYMM-NNN），状态="待审核"，保存记录。
9. 返回 jy_no 供 D04 source_ref 引用。

**输入数据**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| part_no | Ref | ✔ | 零件号 |
| veh_model | Ref | ✔ | 适用车型 |
| hist_months | Int | ✔ | 可用清洗历史月数（系统计算填入） |
| borrow_method | Enum | ✔ | 先导指标 / 类比 / 模板拟合 / 上移 / 池化 |
| borrow_source | Text | ✔ | 借用来源描述 |
| source_params | Text | ✔ | 来源参数（峰值/衰减率/曲线层级/分摊权重） |
| proc_batch | Ref | ✔ | 关联 D04 加工批次 |

**输出数据**：

| 字段 | 类型 | 说明 |
|---|---|---|
| jy_no | String | 系统生成的借用单号（JY-YYYYMM-NNN） |
| derived_qty | Json | 系统计算的推导基线 M0~M+N 各期值 |
| status | Enum | 初始值="待审核" |

**业务规则**：BR-01、BR-03、BR-11~BR-16、BR-18~BR-19、BR-30~BR-32

**特殊处理**：

- **跨应用调用**：create 调 `vehicle_part_map.get_active_mapping(part_no)` 获取生命周期形态、相似车型候选；create 调 `demand_collection.get_true_qty(collect_no, part_no)`（先导指标法）取拆解后真实消耗。
- **借法推荐**：系统根据数据可得性自动推荐借法优先级（有 OEM 预测→先导指标，有相似车→类比，有早期数据→模板拟合/池化，仅有平台层历史→上移），但人工可覆盖（BR-31）。
- **derived_qty 生成**：不同借法的生成逻辑不同——先导指标法：直接使用 true_qty 各期值；类比法：从相似车型曲线映射，经峰值/衰减率标定；模板拟合法：按模板形状参数生成；上移法：平台层预测按份额分摊；池化法：先验均值经收缩系数修正。具体算法待确认。
- **同一批次唯一性**：同一 part_no + veh_model + proc_batch 不允许存在多张生效借用单（BR-30）。
- **hist_months 来源**：系统根据该零件的清洗历史结算数据自动计算，不可手动篡改。

**业务实体**：

借用单（BaselineBorrowing），单表设计（无子表）。

**字段表**：

| 字段名 | 代码 | 类型 | 必填 | 默认值 | 业务逻辑 |
|---|---|---|---|---|---|
| 借用单号 | jy_no | String | ✔ | 系统生成 | 编码规则 `JY-YYYYMM-NNN`，全局唯一 PK |
| 零件号 | part_no | Ref | ✔ | — | 引用物料主数据；必须存在有效零件号 |
| 适用车型 | veh_model | Ref | ✔ | — | 引用车型主数据；必须在 vehicle_part_map 中存在生效映射行 |
| 可用历史月数 | hist_months | Int | ✔ | 系统计算 | 不足判定依据，系统自动计算填入，不可手动修改；BR-01 校验 |
| 借用方法 | borrow_method | Enum | ✔ | — | 先导指标 / 类比 / 模板拟合 / 上移 / 池化 |
| 借用来源 | borrow_source | Text | ✔ | — | 相似车型名称 / 模板编号 / OEM 预测版本 / 平台层级 |
| 来源参数 | source_params | Text | ✔ | — | 峰值 / 衰减率 / 曲线层级 / 分摊权重 |
| 早期校准 | calibration | Text | — | null | 自身早期数据→参数调整记录；有早期数据时必填（BR-02、BR-17） |
| 推导基线 | derived_qty | Json | ✔ | 系统计算 | M0~M+N 各期值，系统根据借法和参数自动计算，不可手动修改 |
| 关联批次 | proc_batch | Ref | ✔ | — | 关联的 D04 加工批次编号 |
| 状态 | status | Enum | ✔ | 待审核 | 待审核 / 生效 / 已转自产 / 已关闭 |
| 审核人 | reviewer | Ref(User) | — | null | 审核通过时必填 |

#### FUNC-04：借用单审核 (review)

**功能描述**：总部计划（核对人）审核待审核的借用单。通过后状态变更为"生效"；驳回后状态保持"待审核"并记录驳回理由。

**用户主流程**：

2. 检查借法选择合理性、来源可信度。
3. 检查校准是否充分：有自身早期数据时 calibration 非空（BR-02）。
4. 检查先导指标法是否取 true_qty（BR-03）。
5. 若通过：调用 review(jy_no, approved=true)，状态→"生效"，记录 reviewer 和 review_date。
6. 若驳回：调用 review(jy_no, approved=false, reason)，状态保持"待审核"，记录驳回理由。
7. 驳回后总部计划可修改借用单内容，重新提交审核。

**输入数据**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| jy_no | String | ✔ | 借用单号 |
| approved | Bool | ✔ | true=通过 / false=驳回 |
| reason | Text | 驳回时必填 | 驳回理由（哪个视角不通过+需要什么修改） |

**输出数据**：

| 字段 | 类型 | 说明 |
|---|---|---|
| status | Enum | 通过→"生效"；驳回→保持"待审核" |
| reviewer | Ref(User) | 审核人 |
| review_date | Date | 审核日期 |

**业务规则**：BR-02、BR-03、BR-21

**特殊处理**：
- 驳回时必须记录理由，供修改后重审参考。
- 驳回后借用单可被修改并重新提交审核，不限驳回次数，但每次驳回留痕。

#### FUNC-05：早期校准 (calibrate)

**功能描述**：用自身早期实际数据校准借用参数，更新 source_params 并重新计算 derived_qty。

**用户主流程**：

1. 总部计划查看借用单详情，确认该零件有新的自身实际数据。
2. 对比实际数据与当前 derived_qty 偏差。
3. 总部计划输入校准说明（如"首2月实际 440/430 → 校准峰值 450、衰减 −4%/月"）和更新后的 source_params（如有变化）。
4. 系统保存 calibration，更新 source_params，重新计算 derived_qty。
5. 校准记录追加到 calibration 字段（保留历史校准记录）。

**输入数据**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| jy_no | String | ✔ | 借用单号 |
| calibration_text | Text | ✔ | 校准说明（如实际数据与参数调整记录） |
| new_params | Text | — | 更新后的 source_params（有变化时填入） |

**输出数据**：

| 字段 | 类型 | 说明 |
|---|---|---|
| calibration | Text | 更新后的校准记录（追加） |
| source_params | Text | 如有变化则更新 |
| derived_qty | Json | 重新计算的推导基线各期值 |

**业务规则**：BR-02、BR-33

**特殊处理**：
- calibration 字段应保留完整的校准历史记录（追加而非覆盖），支持回溯每次校准的时间、依据和调整内容。
- 根据 BR-02，有自身早期数据时必须校准，否则审核不予通过。但无早期数据时可跳过校准（如未上市车型）。
- 已关闭/已转自产状态的借用单不可校准（US-03-AC04）。

---

#### FUNC-06：推导基线取数 (get_derived_qty)

**功能描述**：供 D04 步骤2 调用，返回生效借用单的推导基线各期值。这是 `baseline_borrowing` 被其他应用调用的核心接口。

**用户主流程**（调用方 = D04 demand_processing）：

1. D04 调用 `baseline_borrowing.get_derived_qty(jy_no)`。
2. 系统校验借用单状态="生效"，不通过则返回错误。
3. 系统返回 derived_qty（Json，M0~M+N 各期值）。
4. D04 将各期值写入 D04-B.base_qty，base_path="借用"，source_ref=jy_no。

**输入数据**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| jy_no | String | ✔ | 借用单号 |

**输出数据**：

| 字段 | 类型 | 说明 |
|---|---|---|
| derived_qty | Json | M0~M+N 各期基线值，格式如 `[{"period":"2026-09","qty":430},{"period":"2026-10","qty":413},...]` |

**业务规则**：BR-03（先导指标法时 derived_qty 已基于 true_qty）

**特殊处理**：
- **被调用方**：本方法被 `demand_processing.generate_baseline` 调用。
- 只有"生效"状态的借用单才返回 derived_qty，"待审核"/"已关闭"/"已转自产"状态均拒绝。

---

#### FUNC-07：借用单关闭 (close)

**功能描述**：关闭借用单——历史转充足后切换到 D10 自产策略（→已转自产），或零件 EOP/项目终止等不再需要（→已关闭）。

**用户主流程**：

1. 系统按月判定 hist_months >= 12 且覆盖完整季节周期 → 提示总部计划"历史转充足"。
2. 总部计划在 D10 确认策略选定后，调用 close(jy_no, reason)。
3. 系统将借用单状态变更：历史转充足 → "已转自产"；不再需要 → "已关闭"。
4. 此后 D04 不再从此借用单取基线。

**输入数据**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| jy_no | String | ✔ | 借用单号 |
| reason | Text | ✔ | 关闭原因（如"历史转充足，已切换 D10"或"项目 EOP"） |

**输出数据**：

| 字段 | 类型 | 说明 |
|---|---|---|
| status | Enum | "已转自产"或"已关闭" |

**业务规则**：BR-04、BR-34

**特殊处理**：
- 仅"生效"状态的借用单可关闭。
- 历史转充足判定由系统自动执行（BR-34），但切换动作需人工确认。
- 关闭后 derived_qty 不可再被 D04 获取（FUNC-06 拒绝非生效状态）。

## 8. 五种借法算法规格（§8 Borrowing Method Algorithm Specifications）

> 本章给出 baseline_borrowing 五种借法的数学定义与计算流程，消除 §7.4 备注中"各借法的具体算法细节待确认"的缺口。
> 符号约定同 strategy_fitting §8.0。

### 8.1 借法一：先导指标替代

**原理**：以 OEM 滚动预测（拆解后真实消耗 true_qty）替代自身历史基线。

**适用场景**：历史 = 0（未上市新车型）、OEM 有发布滚动预测

**算法**：

$$\text{derived\_qty}[h] = \text{true\_qty}_{OEM}[h] \quad (h = 0, 1, \dots, N)$$

即逐期直接取 demand_collection.get_true_qty 返回的各期真实消耗量。

**信任折扣校准**（可选，当有 forecast_assessment 的信任折扣数据时）：

$$\text{derived\_qty}[h] = \text{true\_qty}_{OEM}[h] \times (1 - \text{discount\_factor})$$

其中 $\text{discount\_factor} \in [-0.2, 0.3]$ 来自 forecast_assessment.get_trust_discount：
- 正值 = OEM 一贯高报，向下打折（如 0.15 → 预测取 OEM 报量的 85%）
- 负值 = OEM 一贯低报，向上补足（如 -0.10 → 预测取 OEM 报量的 110%）
- 0 = 无系统性偏差，直接采用

**交叉验证**：若路径B（车型产量×单车用量×份额）可用：

$$\text{deviation}[h] = \left| \frac{\text{derived\_qty}[h] - \text{causal\_qty}[h]}{\text{derived\_qty}[h]} \right|$$

deviation > θ_baseline(15%) 时标记"需人工确认"。

---

### 8.2 借法二：类比法

**原理**：按定位/价格带/细分/动力形式找相似车型，用其真实需求曲线做模板映射。

**适用场景**：历史 < 12 期但有相似车型、短生命周期

**算法**：

**Step 1 — 相似车型选择**：

从沉淀库（类比库）或 vehicle_part_map 中选取相似车型 $M_{ref}$：

匹配维度（优先级递减）：
1. 同一 platform（平台）
2. 同一 细分（segment，如紧凑SUV）
3. 价格带接近（±20%）
4. 动力形式相同（纯电/混动/燃油）

选择 top-K（K=3）作为候选参照。

**Step 2 — 曲线映射**：

取 $M_{ref}$ 的清洗后需求序列 $\{y_t^{ref}\}$，时间平移对齐：

$$\tilde{t} = t - (SOP_{new} - SOP_{ref})$$

**Step 3 — 峰值缩放**：

$$\hat{y}_{\tilde{t}}^{new} = \frac{P_{new}}{P_{ref}} \cdot y_{\tilde{t}}^{ref}$$

其中：
- $P_{ref}$ = 相似车型的峰值（历史最大月需求量）
- $P_{new}$ = 新车型的估计峰值：
  - 有新车型早期数据 → 用已观测峰值初估
  - 无早期数据 → 用相似车型峰值 × 份额比：$P_{new} = P_{ref} \times \frac{share_{new}}{share_{ref}}$

**Step 4 — 早期校准（贝叶斯混合）**：

当新车型有 $k$ 期自身数据后：

$$\text{derived\_qty}[t] = w_t \cdot \hat{y}_t^{new} + (1 - w_t) \cdot y_t^{actual}$$

混合权重：

$$w_t = \frac{\sigma_{ref}^2}{\sigma_{ref}^2 + \sigma_{new, observed}^2}$$

其中 $\sigma_{ref}^2$ 为相似车型历史需求的方差，$\sigma_{new, observed}^2$ 为新车型已观测期的方差。
- k=0（零数据）：$w_t = 1$（完全靠类比）
- k 增大：$w_t \to 0$（越来越靠自身数据）
- 通常 SOP 后 3 个月即可显著降低 $w_t$

**Step 5 — 多参照融合**（K > 1 时）：

$$\hat{y}_t^{new} = \sum_{i=1}^{K} v_i \cdot \hat{y}_t^{new, i}$$

权重 $v_i$ 按相似度分配（platform 匹配 = 3 分、segment 匹配 = 2 分、价格带匹配 = 1 分、动力形式匹配 = 1 分），$v_i = \text{score}_i / \sum \text{score}$。

### 8.3 借法三：生命周期模板拟合

**原理**：用 Gompertz 模板先验约束参数，早期数据只标定少数参数。

**适用场景**：历史 < 12 期但有明确生命周期阶段、无合适相似车型

**算法**：

模板先验（来自沉淀库 template_lib，由 strategy_fitting 回测沉淀）：

$$\begin{aligned}
P &\sim \mathcal{N}(\mu_P, \sigma_P^2) \quad \text{（峰值先验）} \\
r &\sim \mathcal{N}(\mu_r, \sigma_r^2) \quad \text{（爬坡速率先验）} \\
\tau &\sim \mathcal{N}(\mu_\tau, \sigma_\tau^2) \quad \text{（拐点时刻先验）}
\end{aligned}$$

参数估计（最大后验 MAP，等价于带正则化的最小二乘）：

$$\min_{P, r, \tau} \left[ \sum_{t} (y_t - \hat{y}_t)^2 + \lambda_P \frac{(P - \mu_P)^2}{\sigma_P^2} + \lambda_r \frac{(r - \mu_r)^2}{\sigma_r^2} + \lambda_\tau \frac{(\tau - \mu_\tau)^2}{\sigma_\tau^2} \right]$$

其中 $\lambda_P = \lambda_r = \lambda_\tau = \frac{1}{k}$（$k$ = 自身数据月数，数据越少先验越强）。

k=0 时：$\lambda \to \infty$，参数退化为先验均值 → 纯模板曲线
k 增大时：$\lambda \to 0$，参数趋近最大似然估计 → 等同 §8.4 自由 Gompertz 拟合

前向外推公式同 strategy_fitting §8.4。

**与 strategy_fitting §8.4 的关系**：该方法与 D10 的 §8.4 使用相同的 Gompertz 模型，区别在于：
- D10 §8.4：自由拟合（无先验约束），用于历史充足场景
- 本方法：**带模板先验的 MAP 估计**，用于历史不足场景

### 8.4 借法四：上移预测

**原理**：在平台/细分层预测（更稳定、有历史），再按份额向下分摊到车型/零件。

**适用场景**：单车型史短但平台/细分层有完整历史

**算法**：

**Step 1 — 聚合**：

将属于同一上移层级（如 platform="P1" 或 segment="紧凑SUV"）的全部车型历史需求加总：

$$Y_t^{agg} = \sum_{j \in \text{group}} y_{t, j}$$

**Step 2 — 上层预测**：

在聚合层对 $\{Y_t^{agg}\}$ 执行 D10 策略拟合选定的方法（如 Holt-Winters），产出上层预测 $\hat{Y}^{agg}_{T+h}$。

**Step 3 — 份额分摊**：

$$\text{derived\_qty}_{new}[h] = \hat{Y}^{agg}_{T+h} \times \text{share}_{new}$$

其中 $\text{share}_{new}$ 为新车型在当前聚合层中的份额，来源优先级：
1. vehicle_part_map 中的供应份额（有合同依据）
2. 历史份额均值（同平台各车型历史份额的平均）
3. $1 / N_{active}$（等分，当无任何份额信息时）

**Step 4 — 约束**：

$$\sum_{j \in \text{group}} \text{share}_j = 1.0 \quad \text{（系统强制）}$$

若新车型加入导致份额和 > 1.0，等比例压缩全部份额至和为 1.0。

### 8.5 借法五：池化/分层估计

**原理**：从全体车型统计学习"典型生命周期形状"先验，新车型用早期数据更新，向相似车均值收缩（James-Stein 型收缩估计）。

**适用场景**：通用件分层预测、历史极少但有大量同层参照

**算法**：

**Step 1 — 层级均值计算**：

取同一池化层（如"全部车型"或"同 segment"或"同 platform"）的历史需求序列，逐月计算层均值与层方差：

$$\bar{y}_t = \frac{1}{M}\sum_{j=1}^{M} y_{t, j}$$

$$s_t^2 = \frac{1}{M-1}\sum_{j=1}^{M} (y_{t, j} - \bar{y}_t)^2$$

**Step 2 — 收缩估计**：

$$\text{derived\_qty}_{new}[t] = \bar{y}_t + c_t \cdot (y_t^{new} - \bar{y}_t)$$

收缩系数 $c_t$（James-Stein 型）：

$$c_t = \max\left(0, \; 1 - \frac{(M-3) \cdot s_t^2}{\sum_{j=1}^{M} (y_{t,j} - \bar{y}_t)^2}\right)$$

- $c_t \approx 1$：新车型数据与层均值差异大 → 保留自身信号
- $c_t \approx 0$：新车型数据噪音大 → 向层均值收缩
- $M$ 越大（参照车型越多），收缩越可靠

**Step 3 — 前向外推**：

对池化层均值 $\{\bar{y}_t\}$ 用 D10 策略方法外推 $\hat{\bar{y}}_{T+h}$，再对新车型做同期收缩：

$$\text{derived\_qty}_{new}[h] = \hat{\bar{y}}_{T+h} + c \cdot (y_{T}^{new} - \bar{y}_T)$$

即未来趋势跟层走，个体偏移量（最后一期的个体偏离）按收缩系数保留。

**Step 4 — 早期数据更新**：

随自身数据积累（k 增大），收缩系数自然增大（$c_t \to 1$）。系统在每月初重算 $c_t$，当 $c_t > 0.8$ 且 k >= 12 时，触发"建议切换 D10 自产策略"通知。

### 8.6 借法选择决策树

系统在 D04 判定"历史不足"后，按以下逻辑推荐借法（人工可覆盖）：

```
历史不足判定
    │
    ├── 有 OEM 滚动预测（demand_collection 中该零件有 V 版本且已拆解）？
    │   └── 是 → 推荐"先导指标替代"（可信度最高）
    │
    ├── 有相似车型（类比库中有生效条目）？
    │   ├── 是，且新车型有早期数据 → 推荐"类比法 + 早期校准"
    │   └── 是，且新车型零数据 → 推荐"类比法（纯模板映射）"
    │
    ├── 有生命周期模板（模板库中有匹配形态的模板）？
    │   └── 是 → 推荐"生命周期模板拟合"
    │
    ├── 平台/细分层有充分历史（同层 >= 3 车型、层历史 >= 24 期）？
    │   └── 是 → 推荐"上移预测"
    │
    └── 以上皆不满足 → 推荐"池化/分层估计"（最通用，需要同层参照数量 >= 5）
        └── 同层参照 < 5 → 降级为"人工指定基线值"（计划手动录入 derived_qty）
```
