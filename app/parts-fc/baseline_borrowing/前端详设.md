# baseline_borrowing（基线借用）前端详设
> 来源：app/parts-fc/_contracts.md（冻结契约）+ app/parts-fc/baseline_borrowing/应用详设.md；产出供第⑦步前端编码 / 第⑧步前端测试用例
> 落位：`app/parts-fc/baseline_borrowing/view.js` + `app/parts-fc/baseline_borrowing/view.html`（与 `baseline_borrowing.py` 同文件夹，落盘即进启动清单与授权清单，零接线）；import 一律绝对路径 `/view/lib/*`；模板经 `new URL("view.html", import.meta.url)` 抓取；工厂 `export default function pageBaselineBorrowing()`（保留专名）

## 1. 页面元数据 PAGE_META

| 字段 | 值 | 说明 |
|---|---|---|
| key | `baseline_borrowing` | = 应用文件夹名，page_id 为 `parts-fc:baseline_borrowing` |
| name | 基线借用 | 侧栏菜单名 |
| ic | 📎 | 菜单图标字 |
| title | 基线借用 | 主区页面头 |
| crumb | 例外登记 · 历史不足零件 · 五种借法 | 头部副题 |

- 页面零鉴权：无任何权限判断；菜单按页面授权渲染在 shell，数据范围由后端闸门执法，401 由 api.js 自动跳登录。
- 本应用为旁路支撑型页面——历史不足零件的基线例外登记；单表设计（无子表），核心单据变更经状态机动作（审核 / 校准 / 关闭）。

## 2. 区块构成

### 2.1 列表区（查）—— 三段式：过滤条 / 表格 / 分页条

**用途**：借用单台账，按零件号、借用方法、状态筛选，承载行内状态流转动作。

**过滤控件（与 `baseline_borrowing.list(part_no, status, borrow_method)` 可过滤参数一一对应；契约无 keyword 参数 → 不设关键字搜索框，禁止前端假过滤）**：

| 控件 | 对应参数 | 选项 |
|---|---|---|
| 零件号输入 | `part_no` | input，模糊/精确匹配（依后端实现） |
| 状态 chips | `status` | 全部 / 待审核 / 生效 / 已转自产 / 已关闭（原值传参） |
| 借用方法下拉 | `borrow_method` | 全部 / 先导指标 / 类比 / 模板拟合 / 上移 / 池化 |
| 分页 | `page` / `page_size` | `pageable()` 分页条 |

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集；字段序与详情/表单一致）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 借用单号 | `jy_no` | `.b-link`，点击开详情模态 |
| 零件号 | `part_no` | 文本 |
| 车型 | `veh_model` | 文本 |
| 历史月数 | `hist_months` | 数字，hist_months < 12 时标橙（不足） |
| 借用方法 | `borrow_method` | `hue()` 徽章（先导指标=蓝 / 类比=绿 / 模板拟合=紫 / 上移=橙 / 池化=青） |
| 借用来源 | `borrow_source` | `.cell-ellipsis` 省略 |
| 推导基线 | `derived_qty` | `tryParse()` 解析 JSON 后截取首期预览（如 "M0=440"），点击可展开查看全局期值 |
| 关联批次 | `proc_batch` | 文本 |
| 状态 | `status` | `hue()` 徽章（待审核=黄 / 生效=绿 / 已转自产=蓝 / 已关闭=灰） |
| 审核人 | `reviewer` | 文本，空值 `dash()` |
| 审核日期 | `review_date` | `fmtDate()`，空值 `dash()` |
| 创建时间 | `created_at` | `fmtTime()` |
| 操作 | — | 按 `status` 的行内动作，`x-show`（见 §5） |

**交互**：任一过滤变化 → 重置回第 1 页重载；状态动作成功后刷新当前页；空结果显示空态文案（不喷 toast）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 状态徽章 / KV 分组体 / 状态操作页脚

**用途**：点 `jy_no` 弹出，调用 `baseline_borrowing.get(jy_no)` 展示**全部**业务字段。单表设计，所有字段在模态中呈现；`source_params` 和 `derived_qty` 为 JSON 文本字段，使用 `tryParse()` 结构化展示。

**分组（`.sec`）**：

| 分组 | 字段 | 渲染 |
|---|---|---|
| 头带 | `jy_no` + `status` 徽章 | 墨青头带，徽章 `hue()` |
| 基本信息 | `jy_no` / `part_no` / `veh_model` / `hist_months` | `.kv`；`jy_no` 注明「系统生成 · 格式 JY-YYYYMM-NNN」；`hist_months` < 12 时标橙「历史不足」 |
| 借用信息 | `borrow_method` / `borrow_source` | `.kv`；`borrow_method` `hue()` 徽章；`borrow_source` 注明来源详情 |
| 来源参数 | `source_params` | 结构化展示：`tryParse()` 解析 JSON → 渲染为 `.kv` 键值对（如峰值=450 / 衰减率=-4%/月）；解析失败则原文展示 |
| 早期校准 | `calibration` | 多行文本，空值 `dash()` 并注明「无早期数据可校准」；非空时保留完整校准历史记录 |
| 推导基线 | `derived_qty` | `tryParse()` 解析 JSON → 渲染为 `.tbl.compact` 期值表（期间 / 基线值）；每期 `fmt()` 格式化；解析失败则折叠展示原文 |
| 关联信息 | `proc_batch` / `reviewer` / `review_date` | `.kv`；`proc_batch` 注明「关联 D04 加工批次」；`reviewer` / `review_date` 空值 `dash()` |
| 时间信息 | `created_at` / `updated_at` | `fmtTime()` |
| 人员信息 | `created_by` / `updated_by` | `.kv` |
| 原始数据 | get 返回全量 JSON | 底部折叠 |

**交互**：页脚 `.modal-ft` 按当前 `status` 放状态机按钮（逻辑同 §5，与行内动作共用一处 `x-show` 判定）；动作成功后用返回对象原地刷新模态字段 + 列表行。

### 2.3 创建表单（增）—— 模态表单

**用途**：覆盖 `baseline_borrowing.create` 接受的**全部**可写业务参数（part_no / veh_model / hist_months / borrow_method / borrow_source / source_params / derived_qty / proc_batch / calibration）。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `part_no` | input | ★ 必填 | 零件号，须存在于物料主数据（BR-11） |
| `veh_model` | input | ★ 必填 | 车型，须在 vehicle_part_map 中存在生效映射行（BR-12） |
| `hist_months` | input type=number，min=0，step=1 | ★ 必填 | 可用清洗历史月数；系统建议自动填入，不可手动篡改（BR-13）；hist_months >= 12 时前端提示「历史充足，建议走 D10 策略仿真拟合」（BR-01） |
| `borrow_method` | select：先导指标 / 类比 / 模板拟合 / 上移 / 池化 | ★ 必填 | 五种借法（BR-14）；每项附带简要说明 |
| `borrow_source` | input / textarea | ★ 必填 | 借用来源——相似车型名称 / 模板编号 / OEM 预测版本 / 平台层级（BR-15） |
| `source_params` | textarea，placeholder="JSON 或键值对文本" | ★ 必填 | 来源参数——峰值 / 衰减率 / 曲线层级 / 分摊权重（BR-16） |
| `derived_qty` | textarea，placeholder='{"2026-09":430,"2026-10":413,...}' | ★ 必填 | 推导基线 JSON（BR-18）；系统可根据借法和参数自动计算预填，人工可覆盖 |
| `proc_batch` | input | ★ 必填 | 关联 D04 加工批次编号（BR-19） |
| `calibration` | textarea，maxlength=2000 | 条件必填 | 早期校准记录；hist_months > 0 时必填（BR-02 / BR-17）；hist_months = 0 时可选 |

- **不进表单**：`jy_no`（系统自动生成，格式 JY-YYYYMM-NNN）、`status`（系统初始=待审核）、`reviewer` / `review_date`（审核时填入）、`created_at` / `updated_at` / `created_by` / `updated_by`（系统写入）。
- 布局：必填先行、frow 语义分组、底部右对齐提交按钮；校验 = 必填红星 + toast 警告。
- 提交成功：toast 带出新 `jy_no` → 关闭模态 → 重置过滤重载列表（新借用单恒「待审核」）。

### 2.4 审核子表单（review）—— 模态子表单

**用途**：对借用单进行审核，调用 `review(jy_no, approved, comment)`。通过后状态→生效，驳回后状态保持待审核。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `jy_no` | 锁定（来自选中借用单） | ★ 必填 | — |
| `approved` | radio / toggle：通过 / 驳回 | ★ 必填 | true=通过，false=驳回 |
| `comment` | textarea，maxlength=2000 | ★ 必填 | 审核意见；驳回时须包含驳回理由（哪个视角不通过 + 需要什么修改） |

- 提交成功后关闭子表单，刷新模态字段 + 列表行。
- 驳回后借用单可被修改并重新提交审核。

### 2.5 校准子表单（calibrate）—— 模态子表单

**用途**：用自身早期实际数据校准借用参数，调用 `calibrate(jy_no, calibration_data)`。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `jy_no` | 锁定（来自选中借用单） | ★ 必填 | — |
| `calibration_data` | textarea，maxlength=3000 | ★ 必填 | 校准记录文本（如"首2月实际 440/430 → 校准峰值 450、衰减 −4%/月"）；含实际数据 + 参数调整 |

- 提交成功后关闭子表单，刷新模态中的 calibration 字段和 derived_qty。

### 2.6 关闭子表单（close）—— 模态子表单

**用途**：关闭借用单，调用 `close(jy_no, reason)`。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `jy_no` | 锁定（来自选中借用单） | ★ 必填 | — |
| `reason` | textarea，maxlength=1000 | ★ 必填 | 关闭原因（如"历史转充足，已切换 D10 自产策略"或"项目 EOP"） |

- 提交成功后关闭子表单，刷新模态字段 + 列表行。系统自动判定 hist_months >= 12 且覆盖完整季节周期 → 提示「建议切换 D10 自产策略」。

## 3. svc 字面量清单（授权派生依据——必须字面量 svc("应用","服务")）

| 区块 | 调用（应用.服务） | 参数 | 说明 |

| 创建表单 | `svc("baseline_borrowing","create")` | `{part_no, veh_model, hist_months, borrow_method, borrow_source, source_params, derived_qty, proc_batch, calibration}` | 新建借用单；返回含 jy_no |

## 4. 数据来源与下拉

**零件号下拉 / 输入建议**：
- part_no 可选从 `vehicle_part_map.list` quiet 探测加载历史不足零件的生效映射列表作为输入建议；失败不喷 toast。
- 若无外部服务，则使用自由文本输入。

**借用方法下拉选项**（静态枚举）：
- 先导指标 —— 以 OEM 滚动预测拆解后真实消耗替代基线；适用 hist_months=0 且有 OEM 预测
- 类比 —— 按定位/价格带找相似车型，用其需求曲线做模板映射；适用有相似车型
- 模板拟合 —— 用生命周期模板先验约束参数拟合；适用有明确生命周期阶段
- 上移 —— 在平台/细分层预测后按份额向下分摊；适用单车型史短但平台层有历史
- 池化 —— 从全体车型统计学习典型形状先验，向相似车均值收缩；适用通用件分层预测

**契约 payload → 区块字段映射**：

| 来源 | payload 字段 | 去向 |
|---|---|---|
| `baseline_borrowing.list` 项 | jy_no, part_no, veh_model, hist_months, borrow_method, borrow_source, source_params, calibration, derived_qty, proc_batch, status, reviewer, review_date, created_at, updated_at, created_by, updated_by | 列表区表格列（1:1，derived_qty 截取首期预览） |
| `baseline_borrowing.get` | 同上（全量） | 详情模态全部 KV 分组 + derived_qty 结构期值表 + 原始数据折叠 |
| `baseline_borrowing.get_derived_baseline` | 各期基线值 | 详情模态「推导基线」区期值表刷新 |
| `baseline_borrowing.create` 返回 | 借用单对象（含 jy_no，status=待审核） | toast 展示 jy_no → 列表重载 |
| `baseline_borrowing.review` 返回 | 更新后的借用单对象（新 status / reviewer / review_date） | 原地更新已开模态 + 列表行 |
| `baseline_borrowing.calibrate` 返回 | 更新后的借用单对象（新 calibration / source_params / derived_qty） | 原地更新已开模态 + 列表行 |
| `baseline_borrowing.close` 返回 | 更新后的借用单对象（新 status） | 原地更新已开模态 + 列表行 |

## 5. 交互要点

1. **按状态的行内动作（状态机，行操作列与模态页脚共用判定）**：
   - `status=待审核` → 【审核】【校准】【编辑】（修改借用单内容后重审）；
     - 【审核】→ 打开审核子表单（review），通过/驳回；
     - 【校准】→ 打开校准子表单（calibrate），仅在有自身数据时可用；
     - 【编辑】→ 打开编辑表单（复用创建表单，预填当前值），提交后覆盖。
   - `status=生效` → 【校准】【关闭】【取推导基线】；
     - 【校准】→ 用新到达的自身数据校准参数；
     - 【关闭】→ 打开关闭子表单（close），须填原因；
     - 【取推导基线】→ 调用 get_derived_baseline，刷新模态期值表。
   - `status=已转自产` → 只读；终态，无任何按钮。注明「已切换 D10 自产策略」。
   - `status=已关闭` → 只读；终态，无任何按钮。注明关闭原因。
   - 动作成功：toast + 刷新列表；非法流转由后端 FdeError 经 api.js 统一 toast，页面不硬编状态机校验。

2. **创建表单 hist_months 联动提示**：
   - hist_months = 0：calibration 可选，提示「无早期数据可校准」。
   - hist_months > 0 且 < 12：calibration 必填，提示「有自身早期数据，必须校准参数（BR-02）」。
   - hist_months >= 12：前端警告提示「历史充足，建议走 D10 策略仿真拟合而非借用登记」（不硬阻断）。

3. **derived_qty 结构化展示**：
   - 列表区：`tryParse()` 解析 JSON，截取首期预览（如 `{"2026-09":430,...}` → "M0=430"）。
   - 详情模态：`tryParse()` 解析 JSON → 渲染为期值表（`.tbl.compact`），每行显示期间与基线值。
   - source_params 同理：`tryParse()` 解析 JSON → 渲染为键值对 `.kv`；解析失败则原文展示。

4. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 状态徽章。

5. **hist_months 不足状态标记**：列表和模态中 hist_months < 12 时，数值用橙色标记 + 小字「不足」提示。

6. **折叠「更多字段 ▾」**：创建表单中 `calibration`（hist_months=0 时）和 `derived_qty`（系统自动计算时可折叠）为可选折叠区。

7. **quiet 探测性加载**：零件号建议下拉 quiet + 零值兜底，失败不喷 toast；列表本身正常加载，错误走 api.js 统一通道。

8. **展示工具**：`hue()`（状态徽章，待审核=黄 / 生效=绿 / 已转自产=蓝 / 已关闭=灰；借法徽章，先导指标=蓝 / 类比=绿 / 模板拟合=紫 / 上移=橙 / 池化=青）、`dash()`（空值字段）、`fmtTime()`（时间字段）、`fmtDate()`（review_date）、`fmt()`（derived_qty 各期数值）、`tryParse()`（source_params / derived_qty JSON 结构化）。

9. **toast**：创建成功 / 审核完成 / 校准成功 / 关闭成功 / 必填未填警告；其余错误一律由 api.js 统一呈现。

## 6. 验收关注点（供第⑧步前端测试用例）

1. **路由渲染**：`#/baseline_borrowing` 挂载出列表三段式（过滤条 + 表格 + 分页条），**页面无 `.kpi`**（防看板挂载粘滞假过）；菜单「📎 基线借用」按 order=60 定位。

2. **造数后列表有数据**：通过 `baseline_borrowing.create` 造多条借用单（覆盖待审核/生效/已转自产/已关闭 + 五种借法）→ 列表行数正确，jy_no / part_no / borrow_method / status 列非空；hist_months < 12 的行橙色标记。

3. **过滤一一对应**：part_no 输入筛选正确；borrow_method 下拉仅匹配行；status=待审核 chips 仅待审核行；多条件组合；无匹配显示空态且不抛错。

4. **模态全字段 + derived_qty 结构化**：点 jy_no 开模态，断言全部字段可见——基本信息 / 借用信息 / source_params（`tryParse()` 结构化键值对）/ calibration / derived_qty（`tryParse()` 结构化期值表）/ 关联信息 / 时间信息 + 「原始数据」可展开；已关闭/已转自产借用单的模态页脚无编辑操作按钮。

5. **创建表单落库**：创建表单填 part_no / veh_model / hist_months / borrow_method / borrow_source / source_params / derived_qty / proc_batch / calibration（★）→ 提交 → 列表出现新借用单且 status=待审核；hist_months > 0 不填 calibration → toast 拦截（BR-02）。hist_months >= 12 时显示提示但不阻断。

6. **审核通过 / 驳回**：待审核行 → 打开审核子表单 → approved=true → 提交 → 状态=生效，reviewer/review_date 回填；待审核行 → approved=false + comment 驳回理由 → 提交 → 状态保持待审核。
