# independent_event（独立事件登记）前端详设
> 来源：app/parts-fc/_contracts.md（冻结契约）+ app/parts-fc/independent_event/应用详设.md；产出供第⑦步前端编码 / 第⑧步前端测试用例
> 落位：`app/parts-fc/independent_event/view.js` + `app/parts-fc/independent_event/view.html`（与 `independent_event.py` 同文件夹，落盘即进启动清单与授权清单，零接线）；import 一律绝对路径 `/view/lib/*`；模板经 `new URL("view.html", import.meta.url)` 抓取；工厂 `export default function pageIndependentEvent()`（保留专名）

## 1. 页面元数据 PAGE_META

| 字段 | 值 | 说明 |
|---|---|---|
| key | `independent_event` | = 应用文件夹名，page_id 为 `parts-fc:independent_event` |
| name | 独立事件 | 侧栏菜单名 |
| ic | ⚡ | 菜单图标字 |
| title | 独立事件登记 | 主区页面头 |
| crumb | 事件台账 · 水位脉冲/断点/其他 · 趋势归趋势、事件归事件 | 头部副题 |

- 页面零鉴权：无任何权限判断；菜单按页面授权渲染在 shell，数据范围由后端闸门执法，401 由 api.js 自动跳登录。
- 本应用契约**无 update / set_* / import_batch / delete** → 无编辑入口、无删除按钮；单据变更仅经状态机动作（confirm / mark_sustained / mark_subsided / close / cancel）。
- 事件量 in_demand 恒 true、in_trend 恒 false 为系统常量，界面不可更改，详情展示注明即可。

## 2. 区块构成

### 2.1 列表区（查）—— 三段式：过滤条 / 表格 / 分页条

**用途**：事件台账，按事件类型、状态、零件号、期间筛选，承载行内状态流转动作。

**过滤控件（与 `svc("independent_event","list")` 可过滤参数 part_no, event_type, status, period 一一对应；契约无 keyword 参数 → 不设关键字搜索框，禁止前端假过滤）**：

| 控件 | 对应参数 | 选项 |
|---|---|---|
| 零件号输入 | `part_no` | 文本输入框，精确匹配 |
| 事件类型下拉 | `event_type` | 全部 / 水位脉冲 / 断点·旧件截断 / 断点·新件启动 / 其他（value 为后端真实值，源码枚举 `_validate_event_type`，原样传参） |
| 状态 chips | `status` | 全部 / 待确认 / 生效 / 持续中 / 已回落 / 已关闭 / 已取消（value 为后端真实值，原样传参） |
| 期间输入 | `period` | YYYY-MM 格式输入框 |
| 分页 | `page` / `page_size` | `pageable()` 分页条 |

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集；字段序与详情/表单一致）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 事件编号 | `event_no` | `.b-link`，点击开详情模态 |
| 事件类型 | `event_type` | `hue()` 徽章（四色：水位脉冲/断点旧件/断点新件/其他） |
| 零件号 | `part_no` | 正文 |
| 客户 | `oem_code` | 正文 |
| 车型 | `veh_model` | 正文 |
| 归属期间 | `period` | YYYY-MM |
| 事件量 | `event_qty` | `fmt()` 数字，正值绿色/负值红色 |
| 来源依据 | `source_basis` | 正文，单行省略 |
| 关联单据 | `source_ref` | `.b-link`（如有），空值 `dash()` |
| 断点批次 | `bp_batch` | 正文（非断点类 `dash()`） |
| 断点时点 | `bp_date` | `fmtTime()`（非断点类 `dash()`） |
| 状态 | `status` | `hue()` 徽章（六色） |
| 登记人 | `creator` | 正文 |
| 登记日期 | `create_date` | `fmtTime()` |
| 关闭依据 | `close_basis` | `.cell-ellipsis` 省略，空值 `dash()` |
| 操作 | — | 按 `status` + `event_type` 的行内动作，`x-show`（见 §5.1） |

**交互**：任一过滤变化 → 重置回第 1 页重载；状态动作成功后刷新当前页；空结果显示空态文案（不喷 toast）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 状态徽章 / KV 分组体 / 状态操作页脚

**用途**：点 `event_no` 弹出，展示 `svc("independent_event","get")` 返回的**全部**业务字段。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `event_no` + `status` 徽章 + `event_type` 徽章 | 墨青头带，徽章 `hue()` |
| 基本信息 | `event_no` / `event_type` / `part_no` / `oem_code` / `veh_model` / `period` | `.kv`；`event_no` 注明「系统生成 · 全局唯一」 |
| 事件量 | `event_qty` | `.kv`，`fmt()` 数字，注明「带符号：正值=上调/新件启动、负值=下调/旧件截断」 |
| 系统常量 | `in_demand` / `in_trend` | `.kv`；`in_demand` 注明「恒 true · 计入当期毛需求」；`in_trend` 注明「恒 false · 不进趋势外推」 |
| 来源信息 | `source_basis` / `source_ref` | `.kv`；`source_ref` 注明「关联单据号」 |
| 断点信息（断点类可见） | `bp_batch` / `bp_date` | `.kv`，`x-show="event_type含断点"`；`bp_batch` 注明「成对关联号」 |
| 登记信息 | `creator` / `create_date` | `.kv`；`fmtTime()` |
| 关闭/回落信息 | `close_basis` | `.kv`，空值 `dash()` |
| 审计时间 | `created_at` / `updated_at` | `fmtTime()` |
| 原始数据 | get 返回全量 JSON | 底部折叠 |

**交互**：页脚 `.modal-ft` 按当前状态 + 事件类型放状态机按钮（逻辑同 §5.1，与行内动作共用一处 `x-show` 判定）；动作成功后用返回对象原地刷新模态字段 + 列表行。

### 2.3 创建表单（增）—— 模态表单

#### 2.3.1 单条事件创建（覆盖 `svc("independent_event","create")` 接受的全部可写业务参数）

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `event_type` | select：水位脉冲 / 断点·旧件截断 / 断点·新件启动 / 其他（value 为后端真实值，原样传参） | ★ 必填 | BRD 枚举 |
| `part_no` | input | ★ 必填 | FK → 物料主数据 |
| `period` | input，YYYY-MM 格式 | ★ 必填 | 归属期间，一次性不滚动 |
| `event_qty` | input number | ★ 必填 | 带符号 Decimal；正值上调/新件启动、负值下调/旧件截断 |
| `source_basis` | select：阶跃检测 / 发运−结算倒推 / 设变通知 / 人工登记+说明（value 为后端真实值，原样传参） | ★ 必填 | BR-04：人工登记+说明时必须附说明文字 |
| `oem_code` | input | ★ 必填 | 客户编码（源码强制非空校验） |
| `veh_model` | input | ★ 必填 | 车型编码（源码强制非空校验） |
| `source_ref` | input | 可选 | 关联单据号，断点类建议填设变通知号 |
| `bp_batch` | input，`x-show="event_type含断点"` | 条件必填（断点类） | 格式 `BP-YYYYMM-NN`，单条断点登记时手动填写 |
| `bp_date` | input date，`x-show="event_type含断点"` | 条件必填（断点类） | 切换生效日 |

- **不进表单**：`event_no`（系统生成）、`status`（系统判定——系统生成→待确认 / 人工登记+举证→生效）、`in_demand` / `in_trend`（系统常量）、`creator` / `create_date` / `close_basis` / `created_at` / `updated_at`（系统写入）。
- 布局：必填先行、frow 语义分组、底部右对齐提交按钮；校验 = 必填红星 + toast 警告（必填为空不发请求）。
- 提交成功：toast 带出新 `event_no` → 关闭模态 → 重置过滤重载列表。

#### 2.3.2 成对断点登记（独立表单入口，覆盖 `svc("independent_event","create_bp_pair")` 接受的全部参数）

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `old_part_no` | input | ★ 必填 | 旧零件号 |
| `new_part_no` | input | ★ 必填 | 新零件号 |
| `bp_date` | input date | ★ 必填 | 断点时点 |
| `old_qty` | input number | ★ 必填 | 旧件事件量（负值，剩余期基线冲销量） |
| `new_qty` | input number | ★ 必填 | 新件事件量（正值，启动量） |
| `oem_code` | input | ★ 必填 | 客户 |
| `veh_model` | input | ★ 必填 | 车型 |
| `period` | input，YYYY-MM | ★ 必填 | 归属期间 |
| `source_basis` | 系统常量 `设变通知` | — | 自动填入，不可改 |
| `source_ref` | input | 可选 | 设变通知号，建议填写 |

- 提交成功：toast 带出两条 `event_no` + `bp_batch` → 关闭模态 → 重置过滤重载列表。

**注意**：单条断点登记时建议走成对登记入口。若走单条入口登记断点，需手动填写 `bp_batch` 确保成对关联（BR-02）。

**本页无可跨应用下拉数据源**（事件类型、来源依据、状态均为契约固定枚举，非动态从其他应用拉取）。

## 5. 交互要点

1. **按状态+类型的行内动作（状态机，行操作列与模态页脚共用判定）**：
   - `status=待确认` → 【确认】【取消】（cancel 弹出 close_basis 输入框）；
   - `status=生效` 且 `event_type=水位脉冲` → 【标记持续中】【标记已回落】【关闭】（mark_subsided / close 弹出 close_basis 输入框）；
   - `status=生效` 且 `event_type=断点·旧件截断` 或 `断点·新件启动` → 【关闭】（弹出 close_basis 输入框）；
   - `status=生效` 且 `event_type=其他` → 【关闭】（弹出 close_basis 输入框）；
   - `status=持续中` → 【标记已回落】（弹出 close_basis 输入框）；
   - `status=已回落` → 【关闭】（弹出 close_basis 输入框）；
   - `status=已关闭` / `status=已取消` → 终态，无任何按钮。
   - 动作成功：toast（如「已确认 · EVT-…」）+ 刷新列表；非法流转由后端 FdeError 经 api.js 统一 toast，页面不硬编状态机校验。
2. **close_basis 必填弹窗**：cancel / mark_subsided / close 操作须弹出输入框收集 close_basis（textarea），确认后才发请求；空值 toast 警告并阻止提交（BR-09）。
3. **创建表单双入口**：【单条事件登记】和【成对断点登记】两个按钮分别打开不同模态表单；系统常量（source_basis 设变通知 / in_demand=true / in_trend=false）在表单中注明但不可编辑。
4. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 状态徽章 + 事件类型徽章。
5. **展示工具**：`hue()`（event_type 四色、status 六色徽章）、`dash()`（空值字段）、`fmtTime()`（create_date / created_at / updated_at / bp_date）、`fmt()`（event_qty 数字，正绿色/负红色）；本页无 `*_json` 快照字段，无需 `tryParse()`。
6. **toast**：创建成功 / 成对登记成功 / 状态流转成功 / close_basis 未填警告；其余错误一律由 api.js 统一呈现。

## 6. 验收关注点（供第⑧步前端测试用例）

1. **路由渲染**：`#/independent_event` 挂载出列表三段式（过滤条 + 表格 + 分页条），**页面无 `.kpi`**（防看板挂载粘滞假过）；菜单「⚡ 独立事件」按 order=70 定位。
2. **造数后列表有数据**：经 `svc("independent_event","create")` 造多条事件（覆盖 水位脉冲/断点旧件/断点新件/其他 与 待确认/生效/持续中/已回落/已关闭/已取消）→ 列表行数正确，event_no / event_type / part_no / event_qty / status 列非空。
3. **过滤一一对应**：event_type=水位脉冲 下拉仅脉冲行；status=生效 chips 仅生效行；period=2026-09 输入框仅该期间行；多条件组合；无匹配显示空态且不抛错。
4. **模态全字段**：点 event_no 开模态，断言 event_no / event_type / part_no / oem_code / veh_model / period / event_qty / in_demand / in_trend / source_basis / source_ref / bp_batch / bp_date / status / creator / create_date / close_basis / created_at / updated_at 全部可见 + 「原始数据」可展开；已关闭/已取消事件的模态页脚无动作按钮。
5. **表单落库——单条创建**：创建表单填 event_type / part_no / period / event_qty / source_basis（★）→ 提交 → 列表出现新事件；必填为空 toast 警告且不发请求。
6. **表单落库——成对断点**：成对断点表单填 old_part_no / new_part_no / bp_date / old_qty / new_qty / oem_code / veh_model / period（★）→ 提交 → 列表出现两条事件，bp_batch 相同。
7. **写操作真实回显**：待确认行【确认】→ 行与模态 status=生效；生效脉冲行【标记持续中】→ status=持续中；持续中行【标记已回落】（输入 close_basis）→ status=已回落；已回落行【关闭】（输入 close_basis）→ status=已关闭；待确认行【取消】（输入 close_basis）→ status=已取消。
8. **close_basis 必填拦截**：cancel / mark_subsided / close 操作时 close_basis 为空 → toast 警告且不发请求。
9. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP>=400（受限会话 403 属预期执法单独豁免）。
