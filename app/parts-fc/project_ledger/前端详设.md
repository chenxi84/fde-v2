## 2. 区块构成

### 2.1 列表区（查）—— 三段式：过滤条 / 表格 / 分页条

**用途**：项目台账总览，按阶段/客户/责任人维度筛选，承载行内阶段迁移与编辑入口。

**过滤控件（与 `project_ledger.list(stage, oem_code, owner_sales, page, page_size)` 可过滤参数一一对应；契约无 keyword 参数 → 不设关键字搜索框，禁止前端假过滤）**：

| 控件 | 对应参数 | 选项 |
|---|---|---|
| 阶段下拉 | `stage` | 全部 / 待定点 / 定点中 / 进行中 / EOP关闭（BR-7 枚举，原值传参） |
| 客户下拉 | `oem_code` | 来自外部客户主数据引用（见 §4）；选项 value=oem_code，label=客户名称 |
| 责任销售下拉 | `owner_sales` | 来自外部用户主数据引用（见 §4）；选项 value=user_id，label=用户名 |
| 分页 | `page` / `page_size` | `pageable()` 分页条（契约签名 string 型，照传即可） |

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集；字段序与详情/表单一致）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 项目号 | `project_no` | `.b-link`，点击开详情模态 |
| 零件号 | `part_no` | 正文 |
| 阶段 | `stage` | `hue()` 徽章（待定点→灰 / 定点中→蓝 / 进行中→绿 / EOP关闭→红） |
| 定点概率 | `award_prob` | 百分比 `fmt()`，空值 `dash()` |
| 客户 | `oem_code` | 正文 |
| 工厂 | `plant_code` | 正文 |
| 车型 | `veh_model` | 正文 |
| 平台 | `platform` | 正文，空值 `dash()` |
| 专用/通用 | `part_kind` | `hue()` 徽章（专用→蓝 / 通用→橙） |
| 单车用量 | `usage` | 数字 `fmt()` |
| 份额 | `share` | 百分比 `fmt()` |
| SOP | `sop` | `fmtTime()` 日期 |
| EOP | `eop` | `fmtTime()` 日期，空值 `dash()` |
| 生命周期形态 | `lc_shape` | 正文，空值 `dash()` |
| 责任销售 | `owner_sales` | 编号正文 + ownerMap 命中时附姓名小字 |
| 创建时间 | `created_at` | `fmtTime()` |
| 更新时间 | `updated_at` | `fmtTime()` |
| 操作 | — | 行内动作按钮，见 §5.1 |

**交互**：任一过滤变化 → 重置回第 1 页重载；阶段迁移或编辑成功后刷新当前页；空结果显示空态文案（不喷 toast）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 状态徽章 / KV 分组体 / 页脚操作

**用途**：点 `project_no` 弹出，展示 `project_ledger.get` 返回的**全部**业务字段 + 变更日志子表。

**头带**：`project_no` + `part_no` + `stage` 徽章（`hue()`）。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 基本信息 | `project_no` / `part_no` / `stage` / `award_prob` / `part_kind` / `lc_shape` | `.kv`；`project_no` + `part_no` 注明「联合业务键 · 全局唯一」（BR-1） |
| 客户/产品 | `oem_code` / `plant_code` / `veh_model` / `platform` | `.kv`；注明「引用外部主数据」 |
| 量纲（引用展示） | `usage` / `share` | `.kv`；注明「权威源在 vehicle_part_map，本表引用展示」（BR-12） |
| 生命周期 | `sop` / `eop` | `.kv`；`fmtTime()` |
| 责任信息 | `owner_sales` | `.kv`；ownerMap 命中附姓名 |
| 时间信息 | `created_at` / `updated_at` | `fmtTime()`；注明 `created_by` / `updated_by` |
| 变更日志 | `change_log` 子表 | `.tbl.inside` 表格，列：`field_name` / `old_value` / `new_value` / `reason` / `change_date` |
| 原始数据 | get 返回全量 JSON | 底部折叠 |

**页脚操作**：按当前 `stage` 提供阶段迁移按钮（`.modal-ft`），见 §5.1。

**交互**：页脚阶段迁移按钮按当前状态 `x-show`；迁移成功后用返回对象原地刷新模态字段 + 列表行。

| `plant_code` | input | ★ 必填 | BR-9 |
| `veh_model` | input | ★ 必填 | BR-10（后端校验车型主数据存在性） |
| `platform` | input | 可选 | BR-10 |
| `part_kind` | select：专用 / 通用，默认专用 | ★ 必填 | BR-11（选"通用"时后端告警 BR-3） |
| `sop` | date input | ★ 必填 | BR-13（须 < eop） |

## 3. svc 字面量清单（授权派生依据——必须字面量 svc("应用","服务")）

| 区块 | 调用（应用.服务） | 参数 | 说明 |
|---|---|---|---|
| 列表区 | `svc("project_ledger","list")` | `{stage, oem_code, owner_sales, page, page_size}` | 过滤查询；空条件传 undefined 不带 |
| 详情模态 | `svc("project_ledger","get")` | `{project_no, part_no}` | 全字段详情 + change_log |
| 详情模态·变更日志 | `svc("project_ledger","get_change_log")` | `{project_no, part_no}` | 变更日志列表 |
| 创建表单 | `svc("project_ledger","create")` | `{project_no, part_no, oem_code, plant_code, veh_model, platform, part_kind, sop, eop, owner_sales, award_prob, lc_shape, usage, share}` | 创建新台账行；返回含 stage=待定点的完整记录 |
| 编辑表单 | `svc("project_ledger","update")` | `{project_no, part_no, kwargs}` | 更新属性；kwargs 仅含变更字段 |
| 阶段迁移弹窗 | `svc("project_ledger","set_stage")` | `{project_no, part_no, new_stage, reason}` | 阶段迁移；返回更新后记录 + change_log |

> 以上 6 处必须在 view.js 中以字面量逐项书写（可包在闭包里），**勿用变量拼名**——这是页面授权隐式放行派生扫描的唯一来源。

## 4. 数据来源与下拉

**客户下拉（过滤条用）**：
- 客户下拉来源为外部主数据引用，本页通过 `svc("project_ledger","list")` 返回项中聚合去重 `oem_code` 构建下拉选项。
- 若外部客户主数据有独立 list 接口（非本组，如 `svc("mdm","customer_list")`），则 quiet 探测加载；若不存在，以本应用已有数据去重兜底。
- 零值兜底 → 下拉仅「全部」选项。

**责任销售下拉（过滤条用）**：
- 类似客户下拉，以 list 返回的 `owner_sales` 去重构建选项。
- ownerMap = `{owner_sales: name}`（若外部有用户接口则补全姓名；否则仅展示 owner_sales 编号）。

**契约 payload → 区块字段映射**：

| 来源 | payload 字段 | 去向 |
|---|---|---|
| `project_ledger.list` 项 | project_no, part_no, stage, award_prob, oem_code, plant_code, veh_model, platform, part_kind, usage, share, sop, eop, lc_shape, owner_sales, created_at, updated_at, created_by, updated_by | 列表区表格列（1:1） |
| `project_ledger.get` | 同上（全量）+ change_log 子表 | 详情模态全部 KV 分组 + 变更日志表格 + 原始数据折叠 |
| `project_ledger.get_change_log` | field_name, old_value, new_value, reason, change_date | 详情模态变更日志子表 |
| `project_ledger.create` 返回 | 完整记录（含 stage=待定点） | toast 展示 project_no+part_no → 列表重载 |
| `project_ledger.update` 返回 | 更新后完整记录 + change_log 新增记录 | 原地更新已开模态 + 列表行 |
| `project_ledger.set_stage` 返回 | 更新后完整记录（新 stage）+ change_log | toast → 原地更新模态 + 列表行 |

## 5. 交互要点

1. **按阶段的行内动作 + 模态页脚共用判定**：
   - 所有阶段均显示【阶段迁移】按钮（set_stage 入口）。
   - 所有阶段均显示【编辑】按钮（update 入口）。
   - 无终态锁定：任何阶段都可迁移（商务变化直接迁移，BR-2），无"不可操作"的终态。
   - 动作成功：toast + 刷新列表；非法操作由后端 FdeError 经 api.js 统一 toast，页面不硬编状态机校验。

2. **编辑表单与阶段迁移的分工**：
   - 编辑表单（update）：更新六维属性字段，自动比对变更字段生成 change_log。
   - 阶段迁移弹窗（set_stage）：仅变更 stage 字段，强制登记 reason，自动生成 change_log。
   - update 接口**不可修改 stage**（走专用 set_stage）；set_stage 接口**不可修改其他属性**（走 update）。

3. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 状态徽章。

4. **折叠「更多字段 ▾」**：仅创建表单中的 `award_prob` / `lc_shape` / `usage` / `share` 收进折叠区。

5. **quieter 主数据下拉**：客户和销售下拉以本应用 list 数据去重兜底；若引入外部主数据接口则 quiet 探测 + 零值兜底，失败不喷 toast。

6. **展示工具**：`hue()`（stage / part_kind 徽章）、`dash()`（空值字段）、`fmtTime()`（sop/eop/created_at/updated_at）、`fmt()`（usage/share/award_prob 数字千分位/百分比）。

7. **toast**：创建成功 / 编辑成功 / 阶段迁移成功 / 必填未填警告；其余错误一律由 api.js 统一呈现。

8. **变更日志子表**：在详情模态中以内嵌表格展示，无分页（通常不超过 20 条）；按 `change_date` 倒序。

## 6. 验收关注点（供第⑧步前端测试用例）

1. **路由渲染**：`#/project_ledger` 挂载出列表三段式（过滤条 + 表格 + 分页条），**页面无 `.kpi`**（防看板挂载粘滞假过）；菜单「📋 项目信息台账」按 order=20 定位。

2. **造数后列表有数据**：经 `project_ledger.create` 造多条台账记录（覆盖 待定点/定点中/进行中/EOP关闭 四种阶段）→ 列表行数正确，project_no / part_no / stage / oem_code / veh_model / owner_sales 列非空。

3. **过滤一一对应**：stage=待定点下拉仅待定点行；oem_code=OEM-A 下拉仅对应客户行；多条件组合；无匹配显示空态且不抛错。

4. **模态全字段**：点 project_no 开模态，断言 project_no / part_no / stage / award_prob / oem_code / plant_code / veh_model / platform / part_kind / usage / share / sop / eop / lc_shape / owner_sales / created_at / updated_at 全部可见 + 「变更日志」子表有数据 + 「原始数据」可展开。

5. **创建表单落库**：创建表单填 project_no / part_no / oem_code / plant_code / veh_model / platform / part_kind / sop / owner_sales → 提交 → 列表出现新记录且 stage=待定点（US-1-AC1）；空 project_no 提交 → toast 警告且不发请求。

6. **编辑表单落库**：列表行点击【编辑】→ 修改 sop 字段 → 提交 → toast 成功 → 详情模态变更日志子表新增一条记录（field_name=sop/old_value/新值/reason）。

7. **阶段迁移真实回显**：待定点行【阶段迁移】→ 选择定点中 + 填写 reason → toast → 行与模态 stage=定点中（US-5-AC1）；不填 reason 提交 → 后端 FdeError toast（US-5-AC5）。

8. **编辑与阶段变更独立**：编辑表单中无 stage 字段；阶段迁移弹窗中仅有 new_stage + reason 两个字段；各自独立提交，互不干扰。

9. **变更日志可审计**：执行 update 修改 2 个字段 → 变更日志子表新增 2 条记录；执行 set_stage → 新增 1 条 stage 变更记录。

10. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP≥400（受限会话 403 属预期执法单独豁免）。
