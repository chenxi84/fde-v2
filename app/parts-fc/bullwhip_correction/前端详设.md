| 字段 | 值 | 说明 |
|---|---|---|

| name | 牛鞭修正 | 侧栏菜单名 |

- 页面零鉴权：无任何权限判断；菜单按页面授权渲染在 shell，数据范围由后端闸门执法，401 由 api.js 自动跳登录。
- 本应用契约**无 update / delete / import_batch** → 无编辑入口、无删除按钮；单据变更仅经状态机动作（maintain / set_correction / confirm）。
- `create` 内部系统自动计算 `amp_factor` 与判定 `amp_verdict`，前端仅传业务参数——`amp_factor` / `amp_verdict` 仅展示、不进表单。

## 2. 区块构成

### 2.1 列表区（查）—— 三段式：过滤条 / 表格 / 分页条

**用途**：牛鞭处理单台账，按零件/期间/层级/状态筛选，承载行内状态流转动作（维持/修正/确认）。

**过滤控件（与 `bullwhip_correction.list(part_no, period, tier, status)` 可过滤参数一一对应；契约无 keyword 参数 → 不设关键字搜索框，禁止前端假过滤）**：

| 控件 | 对应参数 | 选项 |
|---|---|---|
| 零件号输入 | `part_no` | input，模糊匹配 |
| 期间输入 | `period` | input，格式 YYYY-MM |
| 层级下拉 | `tier` | 全部 / Tier1直供 / Tier2 / Tier3（value 为后端真实值，无空格；label 可显示为"Tier 1 直供"等） |
| 状态 chips | `status` | 全部 / 待处理 / 维持 / 已修正 / 已确认（value 为后端真实值；label 可附加业务语义如"已确认(转发布)"） |
| 分页 | `page` / `page_size` | `pageable()` 分页条（契约签名 string 型，照传即可） |

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集；字段序与详情/表单一致）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 处理单号 | `bw_no` | `.b-link`，点击开详情模态 |
| 零件号 | `part_no` | 单行正文 |
| 期间 | `period` | YYYY-MM |
| 层级 | `tier` | `hue()` 徽章（Tier 1 直供 / Tier 2 / Tier 3 三色） |
| 派生需求 | `derived_qty` | `fmt(0)` 数字 |
| 终端需求 | `end_qty` | `fmt(0)` 数字 |
| 放大系数 | `amp_factor` | `fmt(4)`，超阈（>θ_amp）时红色高亮 |
| 判定 | `amp_verdict` | `hue()` 徽章（容忍内·维持=绿 / 超阈·修正=红） |
| 最终预测 | `final_qty` | `fmt(0)` 数字，空值 `dash()` |
| 状态 | `status` | `hue()` 徽章（待处理/维持/已修正/已确认） |
| 核对人 | `checker` | 正文，空值 `dash()` |
| 核对日期 | `chk_date` | `fmtTime()`，空值 `dash()` |
| 创建时间 | `created_at` | `fmtTime()` |
| 操作 | — | 按 `status` + `amp_verdict` 的行内动作，`x-show`（见 §5.1） |

**交互**：任一过滤变化 → 重置回第 1 页重载；状态动作成功后刷新当前页；空结果显示空态文案（不喷 toast）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 状态徽章 / KV 分组体 / 状态操作页脚

**用途**：点 `bw_no` 弹出，展示 `bullwhip_correction.get` 返回的**全部**业务字段。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `bw_no` + `status` 徽章 | 墨青头带，徽章 `hue()` |
| 基本信息 | `bw_no` / `part_no` / `period` / `tier` | `.kv`；`bw_no` 注明「系统生成 · 全局唯一」（BR-07） |
| 需求对比 | `derived_qty` / `end_qty` / `end_source` | `.kv`；`end_source` 注明「按优先级自动取值（结算>OEM消耗>外部映射>排产）」（BR-02）；`derived_qty` 注明「专用件取 D04 核定链值 / 通用件取 D07 修正总量」 |
| 放大分析 | `amp_factor` / `amp_verdict` | `.kv`，高亮展示；`amp_factor` 注明「系统计算 = derived_qty / end_qty，不可手动编辑」（BR-03）；`amp_verdict` 注明「amp_factor ≤ θ_amp → 容忍内·维持；超阈 → 修正」 |
| 修正信息 | `corr_action` / `final_qty` | `.kv`；`corr_action` 注明「六机制菜单 + 说明文字，超阈修正时必填」（BR-04）；`final_qty` 注明「终端口径预测值，维持时=derived_qty」 |
| 核对信息 | `checker` / `chk_date` | `.kv`；`checker` 注明「核对人须为总部计划角色」 |
| 时间信息 | `created_at` / `updated_at` | `fmtTime()`；`updated_at` 注明「状态变更时刷新」 |
| 原始数据 | get 返回全量 JSON | 底部折叠 |

**交互**：页脚 `.modal-ft` 按当前状态放状态机按钮（逻辑同 §5.1，与行内动作共用一处 `x-show` 判定）；动作成功后用返回对象原地刷新模态字段 + 列表行；初始 `status` 恒「待处理」只展示、不进表单。

### 2.3 创建表单（增）—— 模态表单

**用途**：覆盖 `bullwhip_correction.create` 接受的**全部**可写业务参数（part_no / period / tier / derived_qty / end_qty / end_source）。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `part_no` | input | ★ 必填 | BR-07 / BR-08（零件号×期间唯一；引用物料主数据） |
| `period` | input，placeholder=YYYY-MM | ★ 必填 | BR-07 / BR-08（同零件+期间不可重复） |
| `tier` | select：Tier1直供 / Tier2 / Tier3（value 为后端真实值，无空格；label 可显示为"Tier 1 直供"等） | ★ 必填 | BR-01（全覆盖、分轨处理） |
| `derived_qty` | input[type=number]，min=0 | 可选，收进「更多字段 ▾」折叠区 | BR-08（Decimal > 0；通用件场景取 D07 修正总量） |
| `end_qty` | input[type=number]，min=0 | 可选，收进「更多字段 ▾」折叠区 | BR-08（Decimal > 0；按来源优先级自动取数） |
| `end_source` | select：结算 / OEM消耗 / 外部映射 / 排产，默认结算（value 为后端真实值，原样传参） | 可选，收进「更多字段 ▾」折叠区 | BR-02（终端来源优先级不可跳级） |

- **不进表单**：`bw_no` / `amp_factor` / `amp_verdict` / `corr_action` / `final_qty` / `checker` / `chk_date` / `status`（系统生成/计算，仅详情展示并注明）、`created_at` / `updated_at`（系统写入）。
- 布局：必填先行、frow 语义分组、底部右对齐提交按钮；校验 = 必填红星 + toast 警告（零件号/期间/层级为空不发请求）。
- 提交成功：toast 带出新 `bw_no` → 关闭模态 → 重置过滤重载列表（新处理单恒「待处理」）。

### 2.4 修正子表单（set_correction）—— 模态子表单

**用途**：覆盖 `bullwhip_correction.set_correction` 接受的参数（bw_no / corr_action / final_qty），用于超阈场景从六机制菜单选择修正动作。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `bw_no` | 隐藏域（从当前行/模态取） | ★ 必填 | — |
| `corr_action` | 多选 checkbox-group + textarea | ★ 必填 | BR-04（六机制菜单 + 说明文字；禁止无机制纯减数） |
| `final_qty` | input[type=number]，min=0 | ★ 必填 | BR-08（Decimal > 0；终端口径预测值，通常锚定 end_qty） |

**六机制菜单**（checkbox-group，支持多选组合）：
- 终端需求可见（治本）
- 信息共享上传
- 按预测准确率分配
- 减小批量·平准化
- 安全库存协同
- 缩短提前期

- `corr_action` 控件组合：上方 checkbox-group 多选机制 → 下方 textarea 填写说明文字（detail）；提交时拼接为 `{"mechanisms": [...], "detail": "..."}` 格式。
- 校验：corr_action 非空且至少选一个机制 + 说明文字非空；final_qty > 0。
- 提交成功：toast「已修正 · BW…」→ 关闭子表单 → 刷新列表+已开模态。

## 3. svc 字面量清单（授权派生依据——必须字面量 svc("应用","服务")）

| 区块 | 调用（应用.服务） | 参数 | 说明 |
|---|---|---|---|
| 列表区 | `svc("bullwhip_correction","list")` | `{part_no, period, tier, status, page, page_size}` | 过滤查询；空条件传 undefined 不带 |
| 详情模态 | `svc("bullwhip_correction","get")` | `{bw_no}` | 全字段详情 |
| 创建表单 | `svc("bullwhip_correction","create")` | `{part_no, period, tier, derived_qty, end_qty, end_source}` | 创建处理单；返回含 bw_no 的处理单对象，系统自动计算 amp_factor / amp_verdict |
| 行内 / 模态页脚 | `svc("bullwhip_correction","maintain")` | `{bw_no}` | 容忍内维持：待处理 → 维持（BR-01 分轨，amp_factor ≤ θ_amp） |
| 修正子表单 | `svc("bullwhip_correction","set_correction")` | `{bw_no, corr_action, final_qty}` | 超阈修正：待处理 → 已修正（BR-04 留痕三要素） |
| 行内 / 模态页脚 | `svc("bullwhip_correction","confirm")` | `{bw_no}` | 确认：维持/已修正 → 已确认（转发布）（BR-06） |

> 以上 6 处必须在 view.js 中以字面量逐项书写（可包在闭包里），**勿用变量拼名**——这是页面授权隐式放行派生扫描的唯一来源。

## 4. 数据来源与下拉

**本页无跨应用下拉**：列表过滤中 `tier` / `status` / `end_source` 均为固定枚举，不需从其他应用拉取主数据。

**契约 payload → 区块字段映射**：

| 来源 | payload 字段 | 去向 |
|---|---|---|
| `bullwhip_correction.list` 项 | bw_no, part_no, period, tier, derived_qty, end_qty, end_source, amp_factor, amp_verdict, corr_action, final_qty, checker, chk_date, status, created_at, updated_at | 列表区表格列（1:1） |
| `bullwhip_correction.get` | 同上（全量） | 详情模态全部 KV 分组 + 原始数据折叠 |
| `bullwhip_correction.create` 返回 | 处理单对象（含 bw_no，status=待处理，amp_factor/amp_verdict 已计算） | toast 展示 bw_no → 列表重载 |
| `bullwhip_correction.maintain` 返回 | 处理单对象（新 status=维持，刷新 checker/chk_date/updated_at） | 原地更新已开模态 + 列表行 |
| `bullwhip_correction.set_correction` 返回 | 处理单对象（新 status=已修正，corr_action/final_qty 已写入） | 原地更新已开模态 + 列表行 |
| `bullwhip_correction.confirm` 返回 | 处理单对象（新 status=已确认（转发布）） | 原地更新已开模态 + 列表行 |

## 5. 交互要点

1. **按状态 + 判定的行内动作（状态机，行操作列与模态页脚共用判定）**：
   - `status=待处理` + `amp_verdict=容忍内·维持` → 【维持】；
   - `status=待处理` + `amp_verdict=超阈·修正` → 【修正】（弹出 set_correction 子表单，含六机制菜单 + final_qty）；
   - `status=维持` → 【确认】；
   - `status=已修正` → 【确认】；
   - `status=已确认（转发布）` → 终态，无任何按钮。
   - 动作成功：toast（如「已维持 · BW…」/「已修正 · BW…」/「已确认 · BW…」）+ 刷新列表；非法流转（如对已确认点维持）由后端 FdeError 经 api.js 统一 toast，页面不硬编状态机校验。
2. **修正子表单**：六机制 checkbox-group 多选 + textarea 说明，组合拼接为 corr_action；若仅填 final_qty 不选机制 → 前端 toast 警告「修正必须登记所落机制与依据，禁止无机制纯减数」（BR-04），不发请求；后端同样校验拒绝。
3. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 状态徽章；amp_factor 与 amp_verdict 高亮展示（超阈红色警告）。
4. **折叠「更多字段 ▾」**：创建表单中 `derived_qty` / `end_qty` / `end_source` 三个可选字段收入折叠区。
5. **展示工具**：`hue()`（状态/层级/判定徽章）、`dash()`（空值字段）、`fmtTime()`（时间字段）、`fmt()`（数量字段）；本页无 `*_json` 快照字段，无需 `tryParse()`。
6. **toast**：创建成功 / 维持成功 / 修正成功 / 确认成功 / 必填未填警告 / 无机制纯减数警告；其余错误一律由 api.js 统一呈现。
7. **系统自动计算字段**：`amp_factor` 与 `amp_verdict` 由后端 create 时自动计算，前端仅展示——列表列与详情模态中注明「系统计算」提示。

## 6. 验收关注点（供第⑧步前端测试用例）

1. **路由渲染**：`#/bullwhip_correction` 挂载出列表三段式（过滤条 + 表格 + 分页条），**页面无 `.kpi`**（防看板挂载粘滞假过）；菜单「📈 牛鞭修正」按 order=100 定位。
2. **造数后列表有数据**：经 `bullwhip_correction.create` 造多条处理单（覆盖 Tier 1/Tier 2/Tier 3 + 待处理/维持/已修正/已确认）→ 列表行数正确，bw_no / part_no / period / tier / derived_qty / end_qty / amp_factor / amp_verdict / status 列非空。
3. **过滤一一对应**：part_no 输入筛选；period 输入筛选；tier=Tier 2 chips 仅 Tier 2 行；status=待处理 chips 仅待处理行；多条件组合；无匹配显示空态且不抛错。
4. **模态全字段**：点 bw_no 开模态，断言全部字段可见（含派生需求、终端需求及来源、放大系数、判定结果、修正动作、最终预测）+ 「原始数据」可展开；已确认处理单的模态页脚无动作按钮。
5. **创建表单落库**：创建表单填 part_no / period / tier（★）→ 提交 → 列表出现新处理单且 status=待处理、amp_factor 与 amp_verdict 已自动计算（US-01-AC1）；展开「更多字段」填 derived_qty / end_qty / end_source → 提交成功；空必填提交 → toast 警告且不发请求。
6. **维持操作回显**：待处理+容忍内行【维持】→ 行与模态 status=维持（US-04-AC1）。
7. **修正操作回显**：待处理+超阈行【修正】→ 弹出子表单选六机制+填 final_qty → 提交 → 行与模态 status=已修正，corr_action 含机制+说明，final_qty 已更新（US-05-AC1）；仅填 final_qty 不选机制 → toast 警告不发请求（US-05-AC2）。
8. **确认操作回显**：维持行【确认】→ status=已确认（转发布）（US-06-AC1）；已修正行【确认】→ status=已确认（转发布）（US-06-AC2）。
9. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP≥400（受限会话 403 属预期执法单独豁免）。
