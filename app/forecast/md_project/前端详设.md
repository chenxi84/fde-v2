## 2. 区块构成

### 2.1 列表区（查）—— 三段式：工具栏 / 表格 / 分页条

**用途**：项目台账全量浏览 + 条件检索 + 新建入口。本页为非看板页，不设 KPI 指标带（验收断言无 `.kpi`）。

**过滤控件（与 `md_project.list(project_no, stage, oem_code, plant_code, page, page_size)` 可过滤参数一一对应）**：

| 控件 | 对应参数 | 形态 |
|---|---|---|
| 项目号输入框 | `project_no` | placeholder「项目号」，Enter 或「查询」按钮触发（后端 LIKE 模糊匹配） |
| 客户编码输入框 | `oem_code` | placeholder「客户编码」，Enter 或「查询」按钮触发（后端 LIKE 模糊匹配） |
| 工厂编码输入框 | `plant_code` | placeholder「工厂编码」，Enter 或「查询」按钮触发（后端 LIKE 模糊匹配） |
| 阶段 chips | `stage` | 全部 / 待定点 / 定点中 / 进行中 / EOP关闭，单选互斥，点击即查（精确匹配） |
| 分页条 | `page` / `page_size` | `pageable()`，integer 传参 |

**工具栏**：「查询」「+ 新建项目」（打开 2.3 创建模态）。

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 项目号 | `project_no` | `.b-link`，点击打开详情模态 |
| 项目名称 | `project_name` | 单行省略 |
| 阶段 | `stage` | `hue()` 徽章（待定点=灰 / 定点中=黄 / 进行中=绿 / EOP关闭=红） |
| 客户 | `oem_code`+`plant_code` | 双行小字 |
| 车型 | `veh_model` | 文本，空值 `dash()` |
| SOP | `sop` | 文本，空值 `dash()` |
| EOP | `eop` | 文本，空值 `dash()` |
| 责任销售 | `owner` | 文本，空值 `dash()` |
| 操作 | — | 【编辑】（开编辑表单） |

**交互**：任一过滤变化 → 重置回第 1 页重载；编辑保存成功后刷新当前页；空结果显示空态文案。

### 2.2 详情模态（查全）—— 三段式：墨青头带 / KV 分组体 / 操作页脚

**用途**：点 `project_no` 弹出，展示 `md_project.get` 返回的全部字段。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `project_no` + `stage` 徽章 | 墨青头带，徽章 `hue()` |
| 基本信息 | `project_no` / `project_name` / `stage` | `.kv`；project_no 注明「全局唯一主键 · 创建后不可变更」 |
| 客户归属 | `oem_code` / `plant_code` | `.kv`，注明「引用 md_customer · 创建/变更时校验客户存在」 |
| 项目属性 | `veh_model` / `platform` | `.kv`，空值 `dash()` |
| 生命周期 | `sop` / `eop` | `.kv`，空值 `dash()` |
| 责任人 | `owner` | `.kv`，空值 `dash()` |
| 原始数据 | get 返回全量 JSON | 底部折叠（默认收起） |

**页脚 `.modal-ft`**：按当前 `stage` 的【编辑】按钮 + 【关闭】；EOP关闭为终态，编辑按钮仍可用（允许修改非 stage 字段，但 stage 不可回退由后端校验拦截）。

### 2.3 创建 / 编辑表单（增/改）—— 模态表单

**用途**：覆盖 `md_project.create` / `md_project.update` 接受的业务参数。

| 字段 | 控件 | 必填 | create 可见 | update 可见 | 约束来源 |
|---|---|---|---|---|---|
| `project_no` | input，maxlength=50 | ★ 必填 | 是 | 否（只读展示） | BR-01 主键，创建后不可变 |
| `project_name` | input，maxlength=100 | ★ 必填 | 是 | 是 | BR-02 |
| `stage` | select：待定点 / 定点中 / 进行中 / EOP关闭 | ★ 必填 | 是 | 是 | BR-03 状态机；create 为必填但初始建议「待定点」 |
| `oem_code` | 客户 autocomplete（见 §4） | ★ 必填 | 是 | 是 | BR-04；来源 md_customer.list quiet；后端 cross-app 校验 |
| `plant_code` | 客户 autocomplete 联动 | ★ 必填 | 是 | 是 | BR-04；与 oem_code 联动选择 |
| `veh_model` | input，maxlength=50 | 选填 | 是 | 是 | — |
| `platform` | input，maxlength=50 | 选填 | 是 | 是 | — |
| `sop` | date input | 选填 | 是 | 是 | — |
| `eop` | date input | 选填 | 是 | 是 | — |
| `owner` | input，maxlength=50 | 选填 | 是 | 是 | — |

- create 模式：全部字段可见，必填 5 项（project_no, project_name, stage, oem_code, plant_code）；stage 建议默认「待定点」。
- update 模式：`project_no` 回填展示但不可修改（主键）；其余字段均可修改。stage 变更由后端校验状态机规则（正向流转，EOP关闭不可回退），前端不硬编规则仅依赖后端 `FdeError` toast。
- 布局：必填先行——第一行（project_no + project_name）、第二行（oem_code + plant_code）autocomplete、第三行（stage）、折叠区「更多字段 ▾」：veh_model / platform / sop / eop / owner；底部右对齐「取消」「保存」。
- 前端仅做必填校验（空值 → toast 警告、不提交）；stage 枚举值、状态机规则、客户引用校验由后端执行，`FdeError` 经 api.js 以错误 toast 呈现。
- cross-app 校验：创建/更新时后端调用 `self.fde.call("md_customer","get", oem_code, plant_code)` 校验客户存在；前端 autocomplete 已从 md_customer.list 限定选项，降低无效输入概率。
- 提交成功：toast 成功消息 → 关闭模态 → 重置过滤重载列表（create）/ 刷新当前页（update）。

## 3. svc 字面量清单（授权派生依据——必须字面量 svc("应用","服务")）

| 区块 | 调用（应用.服务） | 参数 | quiet | 说明 |
|---|---|---|---|---|
| 列表区 | `svc("md_project","list")` | `{project_no, stage, oem_code, plant_code, page, page_size}` | — | 分页查询 |
| 客户下拉 | `svc("md_customer","list")` | `{page:1, page_size:200}` | true | quiet 探测，失败不喷 toast；零值兜底 |
| 详情模态 | `svc("md_project","get")` | `{project_no}` | — | 全字段详情 |
| 创建表单 | `svc("md_project","create")` | `{project_no, project_name, stage, oem_code, plant_code, veh_model, platform, sop, eop, owner}` | — | 跨应用：后端调 md_customer.get 校验 |
| 编辑表单 | `svc("md_project","update")` | `{project_no, project_name, stage, veh_model, platform, sop, eop, owner}` | — | 更新（仅传有变更字段） |

> 以上 5 处必须在 view.js 中以字面量逐项书写，**勿用变量拼名**。

## 4. 数据来源与下拉

**客户下拉（创建/编辑表单 autocomplete）**：
- 页面初始化一次性 `svc("md_customer","list")` `{page:1, page_size:200}`，`quiet:true` 探测：失败不喷 toast；零值兜底 → 下拉仅显示「暂无可选客户」禁用项。
- 由返回项构建 `custOptions` 扁平数组（格式 `{oem_code, plant_code, oem_name, plant_name}`），autocomplete 显示「oem_code - oem_name / plant_code - plant_name」，选中后分别回填 oem_code 和 plant_code。
- oem_code 和 plant_code 联动：选择客户后同时回填两个字段。

**阶段下拉**：静态枚举（待定点 / 定点中 / 进行中 / EOP关闭），来源：应用详设 BR-03 / 建表 CHECK。

**契约 payload → 区块字段映射**：

| 契约 | 载荷字段 | 映射区块 |
|---|---|---|
| `md_project.list` 返回项 | `project_no, project_name, stage, oem_code, plant_code, veh_model, platform, sop, eop, owner` | 2.1 列表列 |
| `md_project.get` 返回 | 同上（全量） | 2.2 详情模态 kv + 原始数据 |
| `md_project.create` 入参 | `project_no, project_name, stage, oem_code, plant_code, veh_model, platform, sop, eop, owner` | 2.3 创建表单 |
| `md_project.update` 入参 | `project_no, project_name, stage, veh_model, platform, sop, eop, owner` | 2.3 编辑表单（project_no 只读） |
| `md_customer.list` 项 | `oem_code, plant_code, oem_name, plant_name` | 客户 autocomplete 选项 |

## 5. 交互要点

1. **加载**：首载正常拉取 list（非看板页，失败走 api.js 统一通道）+ quiet 拉取 md_customer.list 构建客户下拉。
2. **过滤**：阶段 chips 点击即查并重置 `page=1`；project_no / oem_code / plant_code 输入后 Enter 或「查询」触发；翻页仅改 `page/page_size`，不清过滤条件。
3. **客户 autocomplete**：点击输入框弹出匹配列表（@click.stop 展开 / @click.away 关闭 / @input 实时过滤），同时匹配 oem_code + plant_code + oem_name；列表项双行显示「编码 - 名称」，选中后分别回填 oem_code 和 plant_code。
4. **状态机**：stage select 选项始终为全部 4 个枚举值（让用户可选），非法流转由后端 `FdeError` toast 提示（如「EOP关闭项目不可回退」），前端不硬编码状态转换规则。EOP关闭行在详情页脚和列表操作列仍显示编辑按钮，但 stage 选择后提交时后端会拦截非法值。
5. **微交互**：表格行 hover 高亮；project_no `.b-link` hover 下划线；stage 徽章 `hue()` 着色；「保存」按钮提交期 loading 防重复点击。
6. **成功流**：create 成功 → 关闭模态并清空表单 → toast「项目台账创建成功」→ 列表回第 1 页重载；update 成功 → 关闭模态 → toast「项目台账更新成功」→ 刷新当前页。
7. **错误流**：重复 project_no / 客户不存在 / 非法状态转换等后端 `FdeError` → toast 错误信息，模态保持打开。
8. **空态**：无任何项目时「暂无项目 —— 点『新建项目』创建」；过滤无命中时「无符合条件的项目」。
9. **折叠「更多字段 ▾」**：veh_model / platform / sop / eop / owner 共 5 个选填字段。
10. **展示工具**：`hue()`（stage 徽章）、`dash()`（空值字段）、无时间格式化（sop/eop 为日期文本）、无金额字段无需 `fmt()`、无 `*_json` 字段无需 `tryParse()`。

## 6. 验收关注点（供第⑧步）

1. **路由渲染**：`#/md_project` 挂载出列表三段式（工具栏 + 表格 + 分页条），**断言无 `.kpi`**（非看板页防挂载粘滞假过）。
2. **造数后列表有数据**：先造 customer（OEM001/PLANT01）→ 创建项目 PRJ-001 待定点 → 列表 1 行，project_no / project_name / stage 徽章齐全。
3. **过滤一一对应**：stage=进行中 chips 仅进行中行；project_no=PRJ 模糊匹配；oem_code=OEM 模糊匹配；组合条件；无匹配显示空态且不抛错。
4. **模态全字段**：点 project_no 开模态，断言全部 10 字段可见 + 「原始数据」可展开。
5. **表单落库**：create 表单填必填 5 项 + 「更多字段」选填 → 提交 → 列表出现新记录且 stage=待定点；空必填字段提交 → toast 警告且不发请求。
6. **状态机校验**：更新 stage 从 EOP关闭 → 进行中 → 后端 FdeError toast「EOP关闭项目不可回退」；待定点→进行中（跳跃）→ 合法更新成功。
7. **客户 autocomplete**：点击 oem_code 输入框 → 下拉出现已创建的客户选项；选中后 oem_code + plant_code 同时回填正确。
8. **跨应用校验**：创建项目时 oem_code 选不存在的客户 → 后端 cross-app 校验失败 toast「客户不存在」。
9. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP>=400（受限会话 403 属预期执法单独豁免）。
