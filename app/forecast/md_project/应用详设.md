## 1. 需求概览

### 1.1 基本信息
- **需求名称**: 项目台账管理
- **需求编号**: REQ-FCST-MDP-001
- **所属模块**: 销售预测-主数据层
- **需求来源**: 业务方（销售/计划）
- **创建日期**: 2026-08-12
- **优先级**: P0

### 1.2 需求背景
#### 1.2.1 为什么需要这个需求？
进行中项目定义了"活跃行集"（active row set），是预测快照 opening 时自动生成 N+1/N+2/N+3 三行的零件范围依据。项目阶段/SOP/EOP 提供生命周期感知，断点/EOP 调整按映射 per-project 定量。

#### 1.2.2 期望达到什么目标？
建立项目台账（项目号/阶段/客户·工厂/车型/平台/SOP/EOP/责任销售），为活跃行集定义、生命周期管理、归属追溯提供权威数据。

### 1.3 需求范围
#### 1.3.1 包含哪些功能？
项目台账的创建、列表查询（含按阶段筛选）、更新、活跃项目查询（list_active）。

#### 1.3.2 不包含哪些功能？
- 不做项目合同/预算/里程碑管理（不在预测域范围）
- 不做项目变更审批流（V1 手动修改阶段）

> **数据来源类型**: 独立创建 —— 数据由用户在本应用内独立录入，前端保留"新建"按钮。

### 1.4 涉及角色
**谁会使用这个功能？**

- **一线销售**: 新建/维护项目信息（项目是预测归属载体）
- **总部计划**: 查看项目列表、管理项目阶段（待定点→定点中→进行中→EOP关闭）

## 2. 用户故事

### 2.1 核心用户故事

#### 2.1.1 `US-01` 用户故事 — 创建项目台账（优先级：P1）

- **故事描述**: 作为一线销售，我想要创建项目台账记录，以便于定义活跃行集、追溯预测归属
- **为何赋予此优先级**：项目台账是活跃行集的来源，无项目则快照 opening 无法确定生成范围
- **独立测试**：可通过进入项目台账页面，点击"新建"，填写必填字段后保存并验证来独立测试
- **前置条件**: 用户已登录；引用的 oem_code+plant_code 已存在于 md_customer 中
- **后置条件**: 系统生成一条新的项目台账记录，project_no 全局唯一

**验收场景**：

1. `US-01-AC1` **场景**: 合法参数创建成功
   - **Given** 系统中不存在 project_no=PRJ-001，客户 OEM001/PLANT01 已存在，**When** 填写 project_no=PRJ-001, project_name=某项目, stage=待定点, oem_code=OEM001, plant_code=PLANT01, owner=张三 后保存，**Then** 记录创建成功，可通过 get(PRJ-001) 查询

2. `US-01-AC2` **场景**: 重复项目号被拒绝
   - **Given** 系统中已存在 project_no=PRJ-001，**When** 再次创建 project_no=PRJ-001，**Then** 系统拒绝保存并提示"该项目号已存在"

3. `US-01-AC3` **场景**: 引用不存在的客户被拒绝
   - **Given** 系统中不存在 OEM=NOTEXIST + PLANT=NOTEXIST，**When** 创建项目引用该客户工厂组合，**Then** 系统通过 self.fde.call 校验客户存在性失败，拒绝保存并提示"客户/工厂不存在"

## 3. 业务场景

### 3.1 业务流程描述

#### 3.1.1 场景1: 项目全生命周期管理
1. 一线销售获知新项目线索 → 创建项目（stage=待定点）
2. 项目推进中 → 更新 stage=定点中
3. 项目定点量产 → 更新 stage=进行中（此时项目进入活跃行集）
4. 项目结束 → 更新 stage=EOP关闭（退出活跃行集）
5. 在整个生命周期内可随时维护 SOP/EOP 日期、车型、平台信息

#### 3.1.2 场景2: 快照 opening 使用活跃项目列表
1. 系统触发 open_version(fcst_version)
2. 调用 self.fde.call('md_project.list_active') 获取进行中项目列表
3. 结合 md_project_part.list_active() 获取活跃零件集
4. 为每个活跃零件自动生成 N+1/N+2/N+3 三行快照记录

### 3.2 业务规则

#### 3.2.1 `BR-01` 项目号全局唯一
- **规则描述**: project_no 全局唯一，为单字段主键
- **适用场景**: 创建
- **示例**: PRJ-001 已存在，不可再建 PRJ-001

#### 3.2.2 `BR-02` 必填字段校验
- **规则描述**: project_no, project_name, stage, oem_code, plant_code 为必填；veh_model, platform, sop, eop, owner 为选填
- **适用场景**: 创建、更新
- **示例**: 创建时 project_name 为空 → 拒绝保存，提示"项目名称不能为空"

#### 3.2.3 `BR-03` 项目阶段枚举与状态机约束
- **规则描述**: stage 取值仅限"待定点/定点中/进行中/EOP关闭"；状态只允许正向流转（待定点→定点中→进行中→EOP关闭），禁止回退（EOP关闭不可回退到进行中）
- **适用场景**: 创建、更新
- **示例**: stage=已取消 → 拒绝保存；EOP关闭 → 进行中 → 拒绝，提示"EOP关闭项目不可回退"

#### 3.2.4 `BR-04` 客户引用校验
- **规则描述**: oem_code + plant_code 必须已存在于 md_customer 中，创建/更新时通过 self.fde.call('md_customer.get', oem_code, plant_code) 校验
- **适用场景**: 创建、更新
- **示例**: 引用不存在的客户 → 拒绝保存，提示"客户/工厂不存在"

#### 3.2.5 `BR-05` 活跃项目定义
- **规则描述**: 活跃项目 = stage=进行中；list_active() 仅返回进行中项目
- **适用场景**: 快照 opening 确定生成范围
- **示例**: 3个进行中 + 2个待定点 → list_active 返回3条

### 3.3 业务数据

#### 3.3.1 数据1: 项目号 project_no
- **数据描述**: 项目的唯一编号，全局主键
- **数据类型**: 文本
- **数据来源**: 用户录入
- **示例值**: PRJ-001

#### 3.3.2 数据2: 项目名称 project_name
- **数据描述**: 项目的中文名称
- **数据类型**: 文本

- **示例值**: 某车型项目

#### 3.3.3 数据3: 项目阶段 stage
- **数据描述**: 项目生命周期阶段；"进行中"定义活跃行集
- **数据类型**: 枚举值
- **数据来源**: 用户选择
- **示例值**: 待定点 / 定点中 / 进行中 / EOP关闭

#### 3.3.4 数据4: 客户编码/工厂 oem_code / plant_code
- **数据描述**: 关联的客户/OEM工厂
- **数据类型**: 文本
- **数据来源**: 引用 md_customer，通过 self.fde.call 校验
- **示例值**: OEM001 / PLANT01

#### 3.3.5 数据5: 车型/平台 veh_model / platform
- **数据描述**: 关联的车型和平台信息，选填参考

#### 3.3.7 数据7: 责任销售 owner
- **数据描述**: 项目归属的责任销售
- **数据类型**: 文本
- **数据来源**: 用户录入
- **示例值**: 张三

### 3.4 状态机

项目阶段状态流转：

```
待定点 ──→ 定点中 ──→ 进行中 ──→ EOP关闭
  │                                           ↑
  └───────────────────────────────（不可回退）─┘
```

**状态转换规则矩阵：**

| 当前状态 | 目标状态 | 触发动作 | 前置条件 |
|---|---|---|---|
| (新建) | 待定点 | 创建项目 | 客户引用校验通过 |
| 待定点 | 定点中 | 更新项目 | 无 |
| 待定点 | 进行中 | 更新项目 | 无（可跳跃） |
| 定点中 | 进行中 | 更新项目 | 无 |
| 进行中 | EOP关闭 | 更新项目 | 无 |
| EOP关闭 | 任何 | 禁止 | EOP关闭为终态，不可回退 |

### 4.3 功能详细说明

#### 4.3.1 F01-03 项目台账

##### 4.3.1.1 FUNC-01 创建项目台账

**功能描述**:
提供项目台账的创建表单，用户录入项目号/名称/阶段/客户工厂/车型/平台/SOP/EOP/责任销售后保存。此功能为独立创建——前端保留"新建"按钮。

**用户操作流程**:
1. 用户进入"项目台账"列表页，点击"新建"按钮
2. 系统展示创建表单
3. 用户填写必填字段：project_no, project_name, stage, oem_code, plant_code
   - oem_code/plant_code：来源 md_customer.list 下拉选择
4. 用户选填：veh_model, platform, sop, eop, owner
5. 用户点击"保存"
6. 系统执行校验：
   a. project_no 唯一性
   b. oem_code+plant_code 客户存在性（self.fde.call → md_customer.get）
7. 校验通过 → 记录入库

**输入数据**:
- project_no: 项目号 - 必填，最大50字符，PK - 示例：PRJ-001
- project_name: 项目名称 - 必填，最大100字符 - 示例：某车型项目
- stage: 项目阶段 - 必填，枚举（待定点\|定点中\|进行中\|EOP关闭）- 示例：待定点
- oem_code: 客户编码 - 必填，来源 md_customer.list 下拉选择 - 示例：OEM001
- plant_code: 工厂编码 - 必填，来源 md_customer.list 下拉选择 - 示例：PLANT01
- veh_model: 车型 - 选填，最大50字符 - 示例：车型A
- platform: 平台 - 选填，最大50字符 - 示例：平台X
- sop: SOP日期 - 选填，日期 - 示例：2026-01-01
- eop: EOP日期 - 选填，日期 - 示例：2030-12-31
- owner: 责任销售 - 选填，最大50字符 - 示例：张三

**输出数据**:
- 成功消息: "项目台账创建成功"
- 错误消息: "该项目号已存在" / "客户/工厂不存在" / "项目阶段值不合法" / "XX字段不能为空"

**业务规则**:
- BR-01: project_no 全局唯一
- BR-02: project_no, project_name, stage, oem_code, plant_code 必填
- BR-03: stage 仅限"待定点/定点中/进行中/EOP关闭"
- BR-04: oem_code+plant_code 须经 md_customer.get 校验

**特殊处理**:
- oem_code/plant_code 下拉选择来源于 md_customer.list（主数据引用铁律：禁止手工录入）
- 创建时 stage 默认为"待定点"（初始状态）

**业务实体**:
- **MdProject**: 项目台账，标识为 project_no，含生命周期阶段/客户/SOP/EOP/责任销售

**MdProject 字段**

##### 4.3.1.2 FUNC-02 项目台账列表查询

**功能描述**:
提供项目台账的分页列表，支持按项目号、项目阶段、客户编码、工厂编码等条件筛选。

**用户操作流程**:
1. 用户进入"项目台账"列表页
2. 用户可选填写筛选条件
3. 用户点击"查询"
4. 系统返回符合条件的项目列表（分页）

**输入数据**:
- project_no: 项目号 - 选填，模糊匹配 - 示例：PRJ
- stage: 项目阶段 - 选填，精确匹配 - 示例：进行中
- oem_code: 客户编码 - 选填，模糊匹配 - 示例：OEM
- plant_code: 工厂编码 - 选填，模糊匹配 - 示例：PLANT
- page: 页码 - 默认1
- size: 每页条数 - 默认20

**输出数据**:
- 列表字段: project_no, project_name, stage, oem_code, plant_code, veh_model, sop, eop, owner
- 分页信息: total, page, size

**业务规则**:
- 筛选条件均为可选，条件之间 AND 关系
- project_no / oem_code / plant_code 支持模糊匹配

**特殊处理**:
- 默认按 project_no 升序排列
- 列表页直观展示 stage 状态（可用颜色标签区分）

**业务实体**:
- **MdProject**: 同上 FUNC-01

**MdProject 列表展示字段**

| 展示字段 | 字段来源 | 可筛选 | 说明 |
|---|---|---|---|
| 项目号 | project_no | 是（模糊） | PK |
| 项目名称 | project_name | 否 | 显示用 |
| 项目阶段 | stage | 是（精确） | 待定点/定点中/进行中/EOP关闭 |
| 客户编码 | oem_code | 是（模糊） | 引用 M1 |
| 工厂编码 | plant_code | 是（模糊） | 引用 M1 |
| 车型 | veh_model | 否 | 显示用 |
| SOP | sop | 否 | 显示用 |
| EOP | eop | 否 | 显示用 |
| 责任销售 | owner | 否 | 显示用 |

##### 4.3.1.3 FUNC-03 更新项目台账

**功能描述**:
对已有项目台账记录修改项目阶段、SOP/EOP、责任销售等信息。project_no 作为主键不允许修改。阶段变更须遵循状态机规则。

**用户操作流程**:
1. 用户在列表页点击目标行 → 进入编辑模式
2. 系统回填当前值到表单
3. 用户修改可编辑字段
4. 用户点击"保存"
5. 系统校验：状态机规则、客户引用、枚举值
6. 校验通过 → 更新入库

**输入数据**:
- project_no: 项目号 - 不可修改
- project_name: 项目名称 - 可修改
- stage: 项目阶段 - 可修改（须遵循状态机）
- oem_code / plant_code: 客户/工厂 - 可修改（须重新校验客户存在）
- veh_model / platform / sop / eop / owner: 可修改

**输出数据**:
- 成功消息: "项目台账更新成功"
- 错误消息: "EOP关闭项目不可回退" / "客户/工厂不存在" / "项目阶段值不合法"

**业务规则**:
- BR-01: project_no 不可修改（主键不可变）
- BR-03: 状态机正向流转，EOP关闭不可回退
- BR-04: 变更 oem_code/plant_code 须重新校验客户存在

**特殊处理**:
- 状态机校验逻辑：
  - 待定点 → 定点中 / 进行中：合法
  - 定点中 → 进行中：合法
  - 进行中 → EOP关闭：合法
  - EOP关闭 → 任何其他状态：拒绝
  - 任何状态 → 同状态：允许（仅更新其他字段）

---

##### 4.3.1.4 FUNC-04 活跃项目查询

**功能描述**:
提供 list_active() 公共方法，返回所有 stage=进行中的项目列表。供 forecast_snapshot 的 open_version 方法调用，确定活跃零件生成范围。

**用户操作流程**:
（系统内部调用，非前端功能）：
1. forecast_snapshot.open_version 调用 self.fde.call('md_project.list_active')
2. 本应用查询 stage=进行中的全部项目
3. 返回项目列表

**输入数据**:
- 无参数

**输出数据**:
- 项目列表: [{ project_no, project_name, oem_code, plant_code, ... }]

**业务规则**:
- BR-05: 仅返回 stage=进行中的项目

**特殊处理**:
- 此方法为公共接口（public method），供跨应用调用（self.fde.call）
- 不分页，返回全部活跃项目（通常数量有限）

## 6. 验收标准

### 6.1 功能验收标准

#### 6.1.1 标准1: 项目台账 CRUD + 状态机完整闭环
- **关联用户故事**: US-01, US-02, US-03
- **关联业务规则**: BR-01, BR-02, BR-03, BR-04
- **验证方式**: 创建项目→查询→推进阶段到进行中→查询→推进到EOP关闭→尝试回退
- **测试数据**: project_no=PRJ-TEST, oem_code/plant_code=已有客户
- **预期结果**: 
  - 创建成功
  - 待定点→定点中→进行中→EOP关闭均成功
  - EOP关闭→进行中被拒绝，提示"EOP关闭项目不可回退"

#### 6.1.2 标准2: 客户引用校验
- **关联用户故事**: US-01, US-03
- **关联业务规则**: BR-04
- **验证方式**: 创建项目时引用不存在的客户
- **测试数据**: oem_code=NOTEXIST, plant_code=NOTEXIST
- **预期结果**: self.fde.call 返回客户不存在，拒绝创建

#### 6.1.3 标准3: list_active 仅返回进行中项目
- **关联用户故事**: US-04
- **关联业务规则**: BR-05
- **验证方式**: 准备3个进行中+2个待定点+1个EOP关闭项目，调用 list_active
- **预期结果**: 仅返回3个进行中项目

#### 6.1.4 标准4: 必填字段校验
- **关联用户故事**: US-01
- **关联业务规则**: BR-02
- **验证方式**: 创建项目时依次缺失 project_no, project_name, stage, oem_code, plant_code
- **预期结果**: 每种缺失均被拒绝并提示具体字段

### 6.2 非功能验收标准
**性能要求**: 列表查询（500条以内）页面加载时间<2秒
**安全性要求**: 状态机规则在服务端强制执行，不依赖前端校验
**兼容性要求**: 支持 Chrome、Edge 浏览器

### 6.3 已知问题或限制
- 项目删除功能暂不提供（V1 只增不改删）
- 状态机仅支持正向流转，不支持的路径（如从EOP关闭回退）需业务流程上通过新建项目处理
- V1 无项目预警（SOP临近提醒等），后续增强
