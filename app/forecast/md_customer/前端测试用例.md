# md_customer 前端测试用例

> 页面：forecast:md_customer

## §0 测试数据字典（本页自足）

| 标识 | 造数服务 | 参数 |
|------|---------|------|
| C1 | md_customer.create | oem_code=OEM-A, plant_code=PLT-A1, oem_name=主机厂A, plant_name=一工厂, settle_mode=寄售 |
| C2 | md_customer.create | oem_code=OEM-B, plant_code=PLT-B1, oem_name=主机厂B, plant_name=二工厂, settle_mode=非寄售 |

## §1 渲染

- **VT-RENDER-01 路由渲染有内容**
  - 页面：forecast:md_customer
  - 操作：admin 进入 `#/md_customer`
  - 断言：`.card` > 0；列表三段式（过滤条 + 表格 + 分页区域）可见；**无 `.kpi`**（防粘滞）
  - 选择器注意：`:visible` 限定

## §2 造数后列表有数据

- **VT-LIST-01 造数后列表有数据**
  - 前置造数：经 REST 调用 `md_customer.create` 创建 C1、C2
  - 操作：刷新页面 `#/md_customer`
  - 断言：`table.tbl tr.data` 行数 >= 2；含 oem_code=OEM-A 且 settle_mode 徽章显示「寄售」
  - 选择器注意：精确 `has_text("OEM-A")` 定位行

- **VT-LIST-02 过滤生效**
  - 前置造数：同 VT-LIST-01
  - 操作：settle_mode chips 选「寄售」
  - 断言：仅显示寄售行（OEM-A）；OEM-B 不可见
  - 选择器注意：chips 点击后等待列表刷新

- **VT-LIST-03 模糊搜索生效**
  - 操作：oem_code 输入框填入「OEM」→ 点击「查询」
  - 断言：C1 和 C2 均可见（模糊匹配命中）

## §3 模态全字段

- **VT-MODAL-01 详情模态全字段**
  - 前置造数：同 VT-LIST-01
  - 操作：点击 oem_code=OEM-A 的 `.b-link` → `wait_modal()` 等 `.loadbox` 消失
  - 断言：模态含字段 oem_code / oem_name / plant_code / plant_name / settle_mode；头带含 settle_mode 徽章；原始数据可展开
  - 选择器注意：多 `.modal-bd` 用 `.first`；`:visible` 限定

## §4 表单落库回显

- **VT-FORM-01 创建落库**
  - 操作：点击「+ 新建客户」→ 填写 oem_code=OEM-C, plant_code=PLT-C1, oem_name=主机厂C, plant_name=三工厂, settle_mode=寄售 → 提交
  - 断言：toast 含『客户主数据创建成功』；列表刷新后含 OEM-C 行
  - 选择器注意：`:visible` 限定表单控件

- **VT-FORM-02 空必填字段被拒**
  - 操作：点击「+ 新建客户」→ oem_code 留空 → 提交
  - 断言：toast 警告『必填』且不发请求；模态保持打开
  - 选择器注意：toast 选择器

- **VT-FORM-03 编辑回显**
  - 前置造数：C1 存在
  - 操作：点击 C1 行【编辑】→ 断言 oem_code / plant_code 只读不可改 → 修改 oem_name=主机厂A-改 → 提交
  - 断言：toast 含『客户主数据更新成功』；列表刷新后 oem_name=主机厂A-改
  - 选择器注意：edit 表单中 oem_code/plant_code input 为 readonly

- **VT-FORM-04 批量导入**
  - 操作：点击「批量导入」→ 上传含有效行的 Excel → 确认
  - 断言：toast 含摘要（成功 N 条 / 失败 M 条）；列表刷新含新行

## §6 0 报错

- **VT-ERR-01 本会话 0 报错**
  - 操作：完成上述全部测试步骤
  - 断言：本脚本会话全程 0 console error / 0 pageerror / 0 HTTP>=400（favicon 除外）
