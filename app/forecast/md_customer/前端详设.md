## 2. 区块构成

### 2.1 列表区（查）—— 三段式：工具栏 / 表格 / 分页条

**用途**：客户主数据全量浏览 + 条件检索 + 新建/批量导入入口。本页为非看板页，不设 KPI 指标带（验收断言无 `.kpi`）。

**过滤控件（与 `md_customer.list(oem_code, plant_code, settle_mode, page, page_size)` 可过滤参数一一对应）**：

| 控件 | 对应参数 | 形态 |
|---|---|---|
| 客户编码输入框 | `oem_code` | placeholder「客户编码」，Enter 或「查询」按钮触发（后端 LIKE 模糊匹配） |
| 工厂编码输入框 | `plant_code` | placeholder「工厂编码」，Enter 或「查询」按钮触发（后端 LIKE 模糊匹配） |
| 结算模式 chips | `settle_mode` | 全部 / 寄售 / 非寄售，单选互斥，点击即查（精确匹配） |
| 分页条 | `page` / `page_size` | `pageable()`，integer 传参 |

**工具栏**：「查询」「+ 新建客户」（打开 2.3 创建模态）「批量导入」（打开文件选择模态）。

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 客户编码 | `oem_code` | `.b-link`，点击打开详情模态 |
| 客户名称 | `oem_name` | 文本 |
| 工厂编码 | `plant_code` | 文本 |
| 工厂名称 | `plant_name` | 文本 |
| 结算模式 | `settle_mode` | `hue()` 徽章（寄售=绿 / 非寄售=蓝） |
| 操作 | — | 【编辑】按钮（开编辑表单） |

**交互**：任一过滤变化 → 重置回第 1 页重载；编辑保存成功后刷新当前页；空结果显示空态文案。

### 2.2 详情模态（查全）—— 三段式：墨青头带 / KV 分组体 / 操作页脚

**用途**：点 `oem_code` 弹出，展示 `md_customer.get` 返回的全部字段。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `oem_code` + `plant_code` + `settle_mode` 徽章 | 墨青头带，徽章 `hue()` |
| 基本信息 | `oem_code` / `oem_name` / `plant_code` / `plant_name` | `.kv`；oem_code 注明「联合主键 · 创建后不可变更」 |
| 结算信息 | `settle_mode` | `.kv`，注明「寄售→取H1结算量；非寄售→取H2出货台账」 |
| 原始数据 | get 返回全量 JSON | 底部折叠（默认收起） |

**页脚 `.modal-ft`**：【编辑】（打开编辑表单）【关闭】。

### 2.3 创建 / 编辑表单（增/改）—— 模态表单

**用途**：覆盖 `md_customer.create` / `md_customer.update` 接受的业务参数。

| 字段 | 控件 | 必填 | create 可见 | update 可见 | 约束来源 |
|---|---|---|---|---|---|
| `oem_code` | input，maxlength=50 | ★ 必填 | 是 | 否（只读展示） | BR-01 联合主键，创建后不可变 |
| `plant_code` | input，maxlength=50 | ★ 必填 | 是 | 否（只读展示） | BR-01 联合主键，创建后不可变 |
| `oem_name` | input，maxlength=100 | ★ 必填 | 是 | 是 | BR-02 |
| `plant_name` | input，maxlength=100 | ★ 必填 | 是 | 是 | BR-02 |
| `settle_mode` | select：寄售 / 非寄售 | ★ 必填 | 是 | 是 | BR-03 枚举约束 |

- create 模式：全部 5 字段可填写。
- update 模式：`oem_code` + `plant_code` 回填展示但不可修改（主键）；`oem_name` / `plant_name` / `settle_mode` 可修改。
- 布局：必填先行、frow 语义分组——第一行（oem_code + plant_code）、第二行（oem_name + plant_name）、第三行（settle_mode）；底部右对齐「取消」「保存」。
- 前端仅做必填校验（空值 → toast 警告、不提交）；枚举值合法性、主键唯一性由后端校验，`FdeError` 经 api.js 以错误 toast 呈现。
- 更新时 oem_code / plant_code 不可修改（主键不可变），update 仅接受 oem_name / plant_name / settle_mode。
- 提交成功：toast 成功消息 → 关闭模态 → 重置过滤重载列表。

### 2.4 批量导入

**用途**：点击「批量导入」按钮，弹出文件上传模态，调 `md_customer.import_batch`。

- 提供模板下载链接（表头：oem_code, oem_name, plant_code, plant_name, settle_mode）。
- 上传 Excel → 后端逐行校验 + upsert（已存在主键 → 更新，新增 → 创建）。
- 返回摘要：成功数 / 失败数 / 错误明细列表。
- 导入完成后刷新列表。

## 3. svc 字面量清单（授权派生依据——必须字面量 svc("应用","服务")）

| 区块 | 调用（应用.服务） | 参数 | quiet | 说明 |
|---|---|---|---|---|
| 列表区 | `svc("md_customer","list")` | `{oem_code, plant_code, settle_mode, page, page_size}` | — | 分页查询；空条件传 undefined 不带 |
| 详情模态 | `svc("md_customer","get")` | `{oem_code, plant_code}` | — | 全字段详情 |
| 创建表单 | `svc("md_customer","create")` | `{oem_code, oem_name, plant_code, plant_name, settle_mode}` | — | 新建客户主数据 |
| 编辑表单 | `svc("md_customer","update")` | `{oem_code, plant_code, oem_name, plant_name, settle_mode}` | — | 更新（仅传有变更字段） |
| 批量导入 | `svc("md_customer","import_batch")` | `{rows: [...]}` | — | Excel 逐行校验 + upsert |

> 以上 5 处必须在 view.js 中以字面量逐项书写，**勿用变量拼名**。

## 4. 数据来源与下拉

- **无跨应用主数据下拉**：`md_customer` 不主动外调，结算模式为静态枚举（寄售 / 非寄售），来源：应用详设 BR-03 / 建表 CHECK。
- **契约 payload → 区块字段映射**：

| 契约 | 载荷字段 | 映射区块 |
|---|---|---|
| `md_customer.list` 返回项 | `oem_code, oem_name, plant_code, plant_name, settle_mode` | 2.1 列表列 |
| `md_customer.get` 返回 | `oem_code, oem_name, plant_code, plant_name, settle_mode` | 2.2 详情模态 kv + 原始数据 |
| `md_customer.create` 入参 | `oem_code, oem_name, plant_code, plant_name, settle_mode` | 2.3 创建表单 |
| `md_customer.update` 入参 | `oem_code, plant_code, oem_name, plant_name, settle_mode` | 2.3 编辑表单（oem_code/plant_code 只读） |
| `md_customer.import_batch` 入参 | `rows: [{oem_code, oem_name, plant_code, plant_name, settle_mode}]` | 2.4 批量导入 |

## 5. 交互要点

1. **加载**：首载正常拉取 list（非看板页，失败走 api.js 统一通道）；列表重载期间显示加载态。
2. **过滤**：结算模式 chips 点击即查并重置 `page=1`；oem_code / plant_code 输入后 Enter 或「查询」触发；翻页仅改 `page/page_size`，不清过滤条件。
3. **微交互**：表格行 hover 高亮；oem_code `.b-link` hover 下划线；settle_mode 徽章 `hue()` 着色；「保存」按钮提交期 loading 防重复点击。
4. **成功流**：create 成功 → 关闭模态并清空表单 → toast「客户主数据创建成功」→ 列表回第 1 页重载；update 成功 → 关闭模态 → toast「客户主数据更新成功」→ 刷新当前页。
5. **错误流**：重复主键 / 枚举非法等后端 `FdeError` → toast 错误信息，模态保持打开便于修改后重试。
6. **空态**：无任何客户时「暂无客户 —— 点『新建客户』创建」；过滤无命中时「无符合条件的客户」。
7. **批量导入**：文件选择后上传 → 导入过程 loading → 完成弹摘要（成功 N 条，失败 M 条，错误明细列表）→ 关闭后刷新列表。
8. **原始数据**折叠默认收起。
9. **展示工具**：`hue()`（settle_mode 徽章）、无金额字段无需 `fmt()`、无时间字段无需 `fmtTime()`、无 `*_json` 字段无需 `tryParse()`。

## 6. 验收关注点（供第⑧步）

1. **路由渲染**：`#/md_customer` 挂载出列表三段式（工具栏 + 表格 + 分页条），**断言无 `.kpi`**（非看板页防挂载粘滞假过）。
2. **造数后列表有数据**：REST 创建 OEM001/PLANT01 寄售 → 列表 1 行，oem_code / oem_name / plant_code / plant_name / settle_mode 徽章齐全。
3. **过滤一一对应**：settle_mode=寄售 chips 仅寄售行；oem_code=OEM 模糊匹配；组合条件；无匹配显示空态且不抛错。
4. **模态全字段**：点 oem_code 开模态，断言 oem_code / oem_name / plant_code / plant_name / settle_mode 全部可见 + 「原始数据」可展开。
5. **表单落库**：create 表单填全部 5 项必填 → 提交 → 列表出现新记录；空字段提交 → toast 警告且不发请求；重复主键创建 → 后端 FdeError toast。
6. **update 回显**：编辑模态 oem_code/plant_code 只读不可改；修改 settle_mode 保存后列表和详情均反映新值。
7. **批量导入**：上传合法 Excel → 列表新增行；含冲突行 → 摘要正确展示成功/失败数。
8. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP>=400（受限会话 403 属预期执法单独豁免）。
