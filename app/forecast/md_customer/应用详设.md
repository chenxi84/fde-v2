## 1. 需求概览

### 1.1 基本信息
- **需求名称**: 客户主数据管理
- **需求编号**: REQ-FCST-MDC-001
- **所属模块**: 销售预测-主数据层
- **需求来源**: 业务方（销售/计划）
- **创建日期**: 2026-08-12
- **优先级**: P0

### 1.2 需求背景
#### 1.2.1 为什么需要这个需求？
预测快照的录入键依赖客户/OEM工厂信息，历史数据取数口径（寄售结算H1 vs 出货台账H2）由结算模式决定，因此必须有一条统一的客户主数据作为权威来源。

#### 1.2.2 期望达到什么目标？
建立客户/OEM工厂的基础信息台账，为预测快照、基线生成、加工表等业务链提供客户键校验与结算模式查询能力。

### 1.3 需求范围
#### 1.3.1 包含哪些功能？
客户主数据的创建、列表查询、更新、批量导入/更新。

#### 1.3.2 不包含哪些功能？
- 不做客户信用/等级/价格体系管理（不在预测域范围内）
- 不做客户 MDM 同步接口（V1 以 Excel 导入起步）

> **数据来源类型**: 独立创建 —— 数据由用户在本应用内独立录入，前端保留"新建"按钮。

### 1.4 涉及角色
**谁会使用这个功能？**

- **一线销售**: 新建/维护客户基础信息、批量导入客户主数据
- **总部计划**: 查看客户列表、维护结算模式（寄售/非寄售决定历史取数口径）

## 2. 用户故事

### 2.1 核心用户故事

#### 2.1.1 `US-01` 用户故事 — 创建客户主数据（优先级：P1）

- **故事描述**: 作为一线销售/总部计划，我想要创建客户主数据记录，以便于后续预测快照录入时选择客户与工厂
- **为何赋予此优先级**：客户主数据是预测快照的录入键来源，无客户则无快照入口
- **独立测试**：可通过进入客户主数据页面，点击"新建"按钮，填写必填字段后保存并验证记录已入库来独立测试
- **前置条件**: 用户已登录，拥有客户主数据创建权限
- **后置条件**: 系统生成一条新的客户主数据记录，oem_code+plant_code 组合唯一

**验收场景**：

1. `US-01-AC1` **场景**: 合法参数创建成功
   - **Given** 系统中不存在 OEM=OEM001 + Plant=PLANT01 的记录，**When** 填写 oem_code=OEM001, oem_name=某主机厂, plant_code=PLANT01, plant_name=某工厂, settle_mode=寄售 后点击保存，**Then** 记录创建成功，可通过 get(OEM001, PLANT01) 查询到完整记录

2. `US-01-AC2` **场景**: 重复主键被拒绝
   - **Given** 系统中已存在 OEM=OEM001 + Plant=PLANT01 的记录，**When** 再次创建相同 oem_code+plant_code，**Then** 系统拒绝保存并提示"该客户+工厂组合已存在"

3. `US-01-AC3` **场景**: 必填字段为空被拒绝
   - **Given** 用户在新建表单中，**When** oem_code 或 oem_name 或 plant_code 或 plant_name 或 settle_mode 任一为空提交，**Then** 系统拒绝保存并提示具体缺失字段

---

#### 2.1.2 `US-02` 用户故事 — 查看客户主数据列表（优先级：P1）

- **故事描述**: 作为一线销售/总部计划，我想要按条件筛选查看客户主数据列表，以便于快速定位目标客户
- **为何赋予此优先级**：列表查询是最基础的数据浏览入口，是更新/维护的前置操作
- **独立测试**：可通过进入客户列表页，使用不同筛选条件查询并验证结果来独立测试
- **前置条件**: 系统中已有客户主数据记录
- **后置条件**: 返回符合条件的客户列表，支持分页

**验收场景**：

1. `US-02-AC1` **场景**: 按客户编码模糊查询
   - **Given** 系统中存在多条客户记录，**When** 输入 oem_code=OEM 后查询，**Then** 列表展示所有 oem_code 包含"OEM"的客户

2. `US-02-AC2` **场景**: 按结算模式筛选
   - **Given** 系统中存在寄售和非寄售客户，**When** 筛选 settle_mode=寄售 后查询，**Then** 列表仅展示结算模式为寄售的客户

3. `US-02-AC3` **场景**: 空列表
   - **Given** 查询条件不匹配任何记录，**When** 执行查询，**Then** 返回空列表并提示"无匹配记录"

---

#### 2.1.3 `US-03` 用户故事 — 更新客户主数据（优先级：P2）

- **故事描述**: 作为总部计划，我想要修改客户主数据的名称、结算模式等信息，以便于保持主数据与业务实际一致
- **为何赋予此优先级**：主数据变更频率低，但结算模式（寄售/非寄售）变更直接影响基线取数口径，确保可维护
- **独立测试**：可通过查询一条已有记录，修改其 settle_mode 后保存并验证生效来独立测试
- **前置条件**: 目标记录已存在
- **后置条件**: 记录更新成功，后续引用该客户的应用读取到最新数据

**验收场景**：

1. `US-03-AC1` **场景**: 更新结算模式成功
   - **Given** 存在客户 OEM001/PLANT01 settle_mode=寄售，**When** 修改 settle_mode 为"非寄售"后保存，**Then** 更新成功，重新查询 settle_mode 为"非寄售"

2. `US-03-AC2` **场景**: 更新不存在的记录被拒绝
   - **Given** 系统中不存在 OEM=NOTEXIST + PLANT=NOTEXIST，**When** 尝试更新该组合，**Then** 系统拒绝并提示"客户记录不存在"

---

#### 2.1.4 `US-04` 用户故事 — 批量导入客户主数据（优先级：P2）

- **故事描述**: 作为一线销售，我想要通过 Excel 批量导入客户主数据，以便于系统初始化或新客户集中上线时高效建账
- **为何赋予此优先级**：V1 主数据以 Excel 导入起步，批量导入是初始化阶段的核心入口
- **独立测试**：可通过准备合法的 Excel 文件，执行导入并验证所有行均已入库来独立测试
- **前置条件**: 导入文件格式符合规范（列：oem_code, oem_name, plant_code, plant_name, settle_mode）
- **后置条件**: 导入成功的行入库，失败的行返回错误明细

**验收场景**：

1. `US-04-AC1` **场景**: 全部合法行导入成功
   - **Given** 导入文件含3条合法客户记录且无主键冲突，**When** 执行导入，**Then** 3条均入库，返回成功计数

2. `US-04-AC2` **场景**: 部分行冲突—冲突行跳过
   - **Given** 导入文件含5条，其中2条 oem_code+plant_code 与已有记录冲突，**When** 执行导入，**Then** 3条新记录入库，2条冲突行记录错误明细（冲突原因=主键重复）

3. `US-04-AC3` **场景**: 单元格必填缺失—该行失败
   - **Given** 导入文件某行 oem_code 为空，**When** 执行导入，**Then** 该行导入失败，错误明细提示"客户编码不能为空"，其他合法行正常导入

## 3. 业务场景

### 3.1 业务流程描述

#### 3.1.1 场景1: 新建客户主数据
1. 用户进入"客户主数据"页面，点击"新建"
2. 系统展示客户主数据表单（oem_code, oem_name, plant_code, plant_name, settle_mode）
3. 用户填写所有必填字段
4. 用户点击"保存"
5. 系统校验 oem_code+plant_code 唯一性
6. 校验通过，记录入库；校验不通过，提示冲突

#### 3.1.2 场景2: 批量导入客户主数据
1. 用户进入"客户主数据"页面，点击"批量导入"
2. 系统弹出文件上传对话框
3. 用户选择符合模板格式的 Excel 文件并上传
4. 系统逐行校验唯一性与必填字段
5. 校验通过的行入库，冲突/缺失的行记录错误明细
6. 系统返回导入结果摘要（成功数、失败数、错误明细）

### 3.2 业务规则

#### 3.2.1 `BR-01` 客户+工厂唯一性
- **规则描述**: 同一客户编码+工厂编码组合全局唯一（oem_code + plant_code 为联合主键）
- **适用场景**: 创建、导入、更新（禁止修改 oem_code/plant_code 导致冲突）
- **示例**: OEM001 + PLANT01 已存在，则不可再建 OEM001 + PLANT01；但 OEM001 + PLANT02 合法（不同工厂）

#### 3.2.2 `BR-02` 必填字段校验
- **规则描述**: oem_code, oem_name, plant_code, plant_name, settle_mode 均为必填，不可为空字符串
- **适用场景**: 创建、导入、更新
- **示例**: 创建时 plant_name 为空 → 拒绝保存，提示"工厂名称不能为空"

#### 3.2.3 `BR-03` 结算模式枚举约束
- **规则描述**: settle_mode 取值仅限"寄售"或"非寄售"，不接受其他值
- **适用场景**: 创建、导入、更新
- **示例**: settle_mode=月结 → 拒绝保存，提示"结算模式仅支持寄售/非寄售"

#### 3.2.4 `BR-04` 结算模式决定历史取数口径
- **规则描述**: settle_mode=寄售 → 基线生成取 H1（寄售仓月度结算）；settle_mode=非寄售 → 取 H2（出货台账）
- **适用场景**: 基线生成（forecast_baseline 通过 self.fde.call 读取本应用 settle_mode）
- **示例**: 客户A settle_mode=寄售 → 基线生成时调用 _load_settlement_history；客户B settle_mode=非寄售 → 调用 _load_shipment_history

### 3.3 业务数据

#### 3.3.1 数据1: 客户编码 oem_code
- **数据描述**: 客户/OEM 的唯一编码，与 plant_code 组成联合主键
- **数据类型**: 文本
- **数据来源**: 用户录入 / Excel 导入
- **示例值**: OEM001

#### 3.3.2 数据2: 客户名称 oem_name
- **数据描述**: 客户/OEM 的中文全称
- **数据类型**: 文本
- **数据来源**: 用户录入 / Excel 导入
- **示例值**: 某主机厂

#### 3.3.3 数据3: 工厂编码 plant_code
- **数据描述**: OEM 工厂编码，同一主机厂多工厂分行
- **数据类型**: 文本
- **数据来源**: 用户录入 / Excel 导入
- **示例值**: PLANT01

#### 3.3.4 数据4: 工厂名称 plant_name
- **数据描述**: OEM 工厂的中文名称
- **数据类型**: 文本
- **数据来源**: 用户录入 / Excel 导入
- **示例值**: 某工厂

#### 3.3.5 数据5: 结算模式 settle_mode
- **数据描述**: 结算方式，决定历史数据取寄售结算(H1)还是出货台账(H2)
- **数据类型**: 枚举值
- **数据来源**: 用户录入 / Excel 导入
- **示例值**: 寄售 / 非寄售

### 3.4 状态机
无状态机。客户主数据为静态基础数据，无生命周期状态流转。

### 4.3 功能详细说明

#### 4.3.1 F01-01 客户主数据

##### 4.3.1.1 FUNC-01 创建客户主数据

**功能描述**:
提供客户主数据的创建表单，用户录入客户/OEM工厂基础信息与结算模式后保存。此功能为独立创建——前端保留"新建"按钮。

**用户操作流程**:
1. 用户进入"客户主数据"列表页，点击"新建"按钮
2. 系统展示创建表单（oem_code, oem_name, plant_code, plant_name, settle_mode）
3. 用户填写所有必填字段
4. 用户点击"保存"
5. 系统校验 oem_code+plant_code 唯一性
6. 校验通过 → 记录入库，提示保存成功；校验不通过 → 提示"该客户+工厂组合已存在"

**输入数据**:
- oem_code: 客户编码 - 必填，最大50字符 - 示例：OEM001
- oem_name: 客户名称 - 必填，最大100字符 - 示例：某主机厂
- plant_code: 工厂编码 - 必填，最大50字符 - 示例：PLANT01
- plant_name: 工厂名称 - 必填，最大100字符 - 示例：某工厂
- settle_mode: 结算模式 - 必填，枚举（寄售\|非寄售） - 示例：寄售

**输出数据**:
- 成功消息: "客户主数据创建成功"
- 错误消息: "该客户+工厂组合已存在" / "XX字段不能为空" / "结算模式仅支持寄售/非寄售"

**业务规则**:
- BR-01: oem_code + plant_code 全局唯一
- BR-02: 所有5个字段必填
- BR-03: settle_mode 仅限"寄售"或"非寄售"

**特殊处理**:
- 无

**业务实体**:
- **MdCustomer**: 客户/OEM工厂基础信息，含结算模式，标识为 oem_code+plant_code

**MdCustomer 字段**

| 字段名称 | 字段类型 | 是否必填 | 默认值 | 业务逻辑 |
|---|---|---|---|---|
| oem_code | 文本 | 是 | - | 客户编码，PK之一，最大50字符 |
| oem_name | 文本 | 是 | - | 客户名称，最大100字符 |
| plant_code | 文本 | 是 | - | OEM工厂编码，PK之一，同一主机厂多工厂分行，最大50字符 |
| plant_name | 文本 | 是 | - | 工厂名称，最大100字符 |
| settle_mode | 枚举值 | 是 | - | 寄售\|非寄售；决定历史取H1(寄售结算)还是H2(出货台账)，来源：用户选择 |

##### 4.3.1.2 FUNC-02 客户主数据列表查询

**功能描述**:
提供客户主数据的分页列表，支持按客户编码、工厂编码、结算模式等条件筛选，支持分页浏览。

**用户操作流程**:
1. 用户进入"客户主数据"列表页
2. 用户可选填写筛选条件：oem_code（模糊匹配）、plant_code（模糊匹配）、settle_mode（精确匹配）
3. 用户点击"查询"
4. 系统返回符合条件的客户列表（分页）

**输入数据**:
- oem_code: 客户编码 - 选填，模糊匹配 - 示例：OEM
- plant_code: 工厂编码 - 选填，模糊匹配 - 示例：PLANT
- settle_mode: 结算模式 - 选填，精确匹配 - 示例：寄售
- page: 页码 - 默认1
- size: 每页条数 - 默认20

**输出数据**:
- 列表字段: oem_code, oem_name, plant_code, plant_name, settle_mode
- 分页信息: total, page, size

**业务规则**:
- 筛选条件均为可选，条件之间 AND 关系
- oem_code / plant_code 支持模糊匹配（LIKE %value%）

**特殊处理**:
- 默认按 oem_code, plant_code 升序排列

**业务实体**:
- **MdCustomer**: 同上 FUNC-01

**MdCustomer 列表展示字段**

| 展示字段 | 字段来源 | 可筛选 | 说明 |
|---|---|---|---|
| 客户编码 | oem_code | 是（模糊） | PK之一 |
| 客户名称 | oem_name | 否 | 显示用 |
| 工厂编码 | plant_code | 是（模糊） | PK之一 |
| 工厂名称 | plant_name | 否 | 显示用 |
| 结算模式 | settle_mode | 是（精确） | 寄售/非寄售 |

##### 4.3.1.3 FUNC-03 更新客户主数据

**功能描述**:
对已有客户主数据记录修改 oem_name, plant_name, settle_mode。oem_code 和 plant_code 作为主键不允许修改。

**用户操作流程**:
1. 用户在列表页点击目标行 → 进入编辑模式（或详情页"编辑"按钮）
2. 系统回填当前值到表单
3. 用户修改 oem_name / plant_name / settle_mode
4. 用户点击"保存"
5. 系统校验 settle_mode 枚举值
6. 校验通过 → 更新入库；校验不通过 → 提示错误

**输入数据**:
- oem_code: 客户编码 - 不可修改，仅作为定位键
- plant_code: 工厂编码 - 不可修改，仅作为定位键
- oem_name: 客户名称 - 可修改，最大100字符
- plant_name: 工厂名称 - 可修改，最大100字符
- settle_mode: 结算模式 - 可修改，枚举（寄售\|非寄售）

**输出数据**:
- 成功消息: "客户主数据更新成功"
- 错误消息: "客户记录不存在" / "结算模式仅支持寄售/非寄售"

**业务规则**:
- BR-01: oem_code + plant_code 不可修改（主键不可变）
- BR-02: oem_name, plant_name, settle_mode 不能更新为空
- BR-03: settle_mode 仅限"寄售"或"非寄售"

**特殊处理**:
- 更新 settle_mode 后，下游基线生成的下次取数将自动切换 H1/H2 口径

---

##### 4.3.1.4 FUNC-04 批量导入客户主数据

**功能描述**:
通过上传 Excel 文件（列：oem_code, oem_name, plant_code, plant_name, settle_mode），系统逐行校验入库。已存在的主键行执行更新，不存在的新增。

**用户操作流程**:
1. 用户点击"批量导入"按钮
2. 系统弹出文件上传对话框，附带模板下载链接
3. 用户选择符合格式的 Excel 文件上传
4. 系统逐行校验（必填、枚举值、主键冲突判断）
5. 导入完成 → 系统返回摘要（成功数、失败数、错误明细列表）

**输入数据**:
- Excel 文件，列：oem_code, oem_name, plant_code, plant_name, settle_mode

**输出数据**:
- 导入摘要: { total: N, success: N, fail: N, errors: [{ row, field, message }] }

**业务规则**:
- BR-01: 主键已存在行 → 更新（upsert），非冲突拒绝
- BR-02: 必填字段为空行 → 失败，记录错误明细
- BR-03: settle_mode 值不在枚举范围内 → 失败，记录错误明细

**特殊处理**:
- Upsert 策略：已存在主键 → 更新 oem_name, plant_name, settle_mode
- 提供模板下载：含表头行（oem_code, oem_name, plant_code, plant_name, settle_mode）的空白 Excel

## 6. 验收标准

### 6.1 功能验收标准

#### 6.1.1 标准1: 客户主数据 CRUD 完整闭环
- **关联用户故事**: US-01, US-02, US-03
- **关联业务规则**: BR-01, BR-02, BR-03
- **验证方式**: 依次执行创建→查询→更新→再查询
- **测试数据**: oem_code=OEM001, plant_code=PLANT01, settle_mode=寄售
- **预期结果**: 创建成功并通过 list/get 可查询；更新 settle_mode 为非寄售后再次查询值已变更

#### 6.1.2 标准2: 主键唯一性校验
- **关联用户故事**: US-01
- **关联业务规则**: BR-01
- **验证方式**: 创建两条 oem_code+plant_code 完全相同的记录
- **测试数据**: 重复创建 OEM001+PLANT01
- **预期结果**: 第二条创建被拒绝，提示"该客户+工厂组合已存在"

#### 6.1.3 标准3: 批量导入正常+异常混合场景
- **关联用户故事**: US-04
- **关联业务规则**: BR-01, BR-02, BR-03
- **验证方式**: 导入含5行数据（3行合法、1行重复主键、1行缺必填字段）
- **测试数据**: 合法行3条 + 重复行1条 + 缺 oem_code 行1条
- **预期结果**: 3条成功入库，2条失败并返回错误明细

#### 6.1.4 标准4: 结算模式枚举约束
- **关联用户故事**: US-01, US-03
- **关联业务规则**: BR-03
- **验证方式**: 创建/更新时 settle_mode 传入非法值（如"月结"）
- **测试数据**: settle_mode=月结
- **预期结果**: 保存被拒绝，提示"结算模式仅支持寄售/非寄售"
