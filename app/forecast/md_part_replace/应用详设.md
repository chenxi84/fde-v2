## 1. 需求概览

### 1.1 基本信息
- **需求名称**: 零件替换关系管理
- **需求编号**: REQ-FCST-MDPR-001
- **所属模块**: 销售预测-主数据层
- **需求来源**: 业务方（工程/计划）
- **创建日期**: 2026-08-12
- **优先级**: P0

### 1.2 需求背景
#### 1.2.1 为什么需要这个需求？
零件间的替换/替代关系是零件级处理中"替换件合并"与"断点处理"的核心输入。没有替换关系数据，系统无法：合并可替代零件需求防分别下单超储、执行断点新旧件成对调整。

#### 1.2.2 期望达到什么目标？
建立零件间替换/替代关系的权威台账（关系类型/旧件/新件/切换时点/ECN依据/生效状态），支撑替换件合并与断点处理逻辑。

### 1.3 需求范围
#### 1.3.1 包含哪些功能？
替换关系的创建、列表查询、更新、设为失效（disable）。

#### 1.3.2 不包含哪些功能？
- 不做 ECN 变更审批流（V1 手动维护替换关系）
- 不做替换关系自动发现（如从 BOM 变更中识别）

> **数据来源类型**: 独立创建 —— 数据由用户在本应用内独立录入，前端保留"新建"按钮。

### 1.4 涉及角色
**谁会使用这个功能？**

- **总部计划**: 维护替换/替代关系（依据 ECN 变更通知），管理关系生命周期（生效→失效）
- **一线销售**: 查看替换关系（了解零件变更影响）

## 2. 用户故事

### 2.1 核心用户故事

#### 2.1.1 `US-01` 用户故事 — 创建替换关系（优先级：P1）

- **故事描述**: 作为总部计划，我想要创建零件间的替换/替代关系记录，以便于零件级处理中合并需求和断点调整
- **为何赋予此优先级**：替换关系是替换件合并与断点处理的唯一输入数据，无此数据则两个核心功能无法运行
- **独立测试**：可通过进入替换关系页面，点击"新建"，选择关系类型和旧/新零件号后保存并验证来独立测试
- **前置条件**: 引用的 old_part 和 new_part 已存在于 md_material 中
- **后置条件**: 系统生成一条新的替换关系记录，rel_no 全局唯一

**验收场景**：

1. `US-01-AC1` **场景**: 替换关系创建成功
   - **Given** 零件 8210001-A 和 8210001-B 均存在，rel_no 未使用，**When** 填写 rel_no=REL-001, rel_type=替换, old_part=8210001-A, new_part=8210001-B, switch_date=2026-10-01, ecn_no=ECN-A-118 后保存，**Then** 记录创建成功

2. `US-01-AC2` **场景**: 替代关系创建成功
   - **Given** 零件 8210001 和 8210002 均存在，**When** 填写 rel_no=REL-002, rel_type=替代, old_part=8210001, new_part=8210002 后保存，**Then** 记录创建成功

3. `US-01-AC3` **场景**: 重复关系号被拒绝
   - **Given** 已存在 rel_no=REL-001，**When** 再次创建 rel_no=REL-001，**Then** 系统拒绝并提示"该关系号已存在"

4. `US-01-AC4` **场景**: 引用不存在的旧件被拒绝
   - **Given** 系统中不存在 old_part=NOTEXIST，**When** 创建替换关系引用该旧件，**Then** self.fde.call('md_material.get') 返回不存在，拒绝保存并提示"旧件号不存在"

5. `US-01-AC5` **场景**: 引用不存在的新件被拒绝
   - **Given** 系统中不存在 new_part=NOTEXIST，**When** 创建替换关系引用该新件，**Then** self.fde.call('md_material.get') 返回不存在，拒绝保存并提示"新件号不存在"

6. `US-01-AC6` **场景**: 替换类型旧件等于新件被拒绝
   - **Given** 零件 8210001 存在，**When** 创建 rel_type=替换, old_part=8210001, new_part=8210001，**Then** 系统拒绝并提示"替换关系新旧件不能相同"

#### 2.1.4 `US-04` 用户故事 — 设为失效（优先级：P2）

- **故事描述**: 作为总部计划，我想要将不再有效的替换关系设为失效，以便于零件级处理中排除过期关系
- **为何赋予此优先级**：替换关系有生命周期，过期关系须标记失效以排除出计算
- **独立测试**：可通过查询一条生效中的替换关系，执行 disable 后验证 status 变为"失效"来独立测试
- **前置条件**: 目标替换关系 status=生效

**验收场景**：

1. `US-04-AC1` **场景**: 设为失效成功
   - **Given** 存在替换关系 REL-001 status=生效，**When** 调用 disable(REL-001)，**Then** status 变为"失效"，零件级处理引用此关系时被排除

2. `US-04-AC2` **场景**: 对已失效记录再设失效
   - **Given** 替换关系 REL-001 status=失效，**When** 再次调用 disable(REL-001)，**Then** 操作成功（幂等），status 保持"失效"

## 3. 业务场景

### 3.1 业务流程描述

#### 3.1.1 场景1: 建立替换关系
1. 总部计划收到工程变更通知（ECN），确认旧件将被新件替换
2. 进入"替换关系"页面，点击"新建"
3. 选择关系类型（替换/替代）
4. 选择旧件号（来源：md_material.list 下拉选择）
5. 选择新件号（来源：md_material.list 下拉选择）
6. 填写切换时点、ECN 号
7. 系统校验：旧件/新件存在性（self.fde.call）、替换类型新旧件不相等
8. 保存成功，status 默认为"生效"

#### 3.1.2 场景2: 零件级处理使用替换关系
1. part_level_adj.create_replace_merge 被触发
2. 调用 self.fde.call('md_part_replace.get', rel_no) 获取替换关系详情
3. 使用 old_part/new_part 信息执行替换件合并计算
4. part_level_adj.create_breakpoint_adj 被触发
5. 调用 self.fde.call('md_part_replace.get', rel_no) 获取断点关系详情
6. 按旧件截断/新件启动成对生成调整量

#### 3.1.3 场景3: 替换关系生命周期
1. 替换关系初始创建 → status=生效
2. 新件替代完成、旧件彻底退出后 → disable(rel_no) → status=失效
3. 失效的记录在零件级处理中被排除

### 3.2 业务规则

#### 3.2.1 `BR-01` 关系号全局唯一
- **规则描述**: rel_no 全局唯一，为单字段主键
- **适用场景**: 创建
- **示例**: REL-001 已存在，不可再建 REL-001

#### 3.2.2 `BR-02` 必填字段校验
- **规则描述**: rel_no, rel_type, old_part, new_part, status 为必填；switch_date, ecn_no 为选填
- **适用场景**: 创建、更新
- **示例**: 创建时 old_part 为空 → 拒绝保存

#### 3.2.3 `BR-03` 关系类型枚举约束
- **规则描述**: rel_type 取值仅限"替换"或"替代"
- **适用场景**: 创建、更新
- **示例**: rel_type=互换 → 拒绝保存，提示"关系类型仅支持替换/替代"

#### 3.2.4 `BR-04` 替换类型新旧件不相同
- **规则描述**: rel_type=替换时，old_part 必须不等于 new_part（替换意味着新旧不同；替代允许自引用但无业务意义，不强制拦截）
- **适用场景**: 创建、更新
- **示例**: rel_type=替换, old_part=8210001, new_part=8210001 → 拒绝保存

#### 3.2.5 `BR-05` 旧件引用校验
- **规则描述**: old_part 必须已存在于 md_material 中，通过 self.fde.call('md_material.get', old_part) 校验
- **适用场景**: 创建、更新
- **示例**: old_part=NOTEXIST → 拒绝保存，提示"旧件号不存在"

#### 3.2.6 `BR-06` 新件引用校验
- **规则描述**: new_part 必须已存在于 md_material 中，通过 self.fde.call('md_material.get', new_part) 校验
- **适用场景**: 创建、更新
- **示例**: new_part=NOTEXIST → 拒绝保存，提示"新件号不存在"

#### 3.2.7 `BR-07` 状态枚举约束
- **规则描述**: status 取值仅限"生效"或"失效"
- **适用场景**: 创建、更新、disable
- **示例**: status=待审批 → 拒绝保存

### 3.3 业务数据

#### 3.3.1 数据1: 关系号 rel_no
- **数据描述**: 替换/替代关系的唯一编号，全局主键
- **数据类型**: 文本
- **数据来源**: 用户录入
- **示例值**: REL-001

#### 3.3.2 数据2: 关系类型 rel_type
- **数据描述**: 替换（旧→新，不共存）或替代（可并存、功能等效）
- **数据类型**: 枚举值
- **数据来源**: 用户选择
- **示例值**: 替换 / 替代

#### 3.3.3 数据3: 旧件号 old_part
- **数据描述**: 被替换/被替代的旧零件号
- **数据类型**: 文本
- **数据来源**: 引用 md_material，通过 self.fde.call 校验；前端从 md_material.list 下拉选择
- **示例值**: 8210001-A

#### 3.3.4 数据4: 新件号 new_part
- **数据描述**: 替换后/替代的新零件号
- **数据类型**: 文本
- **数据来源**: 引用 md_material，通过 self.fde.call 校验；前端从 md_material.list 下拉选择
- **示例值**: 8210001-B

#### 3.3.5 数据5: 切换时点 switch_date
- **数据描述**: 旧件切换到新件的日期，断点依据
- **数据类型**: 日期
- **数据来源**: 用户录入（依据 ECN）
- **示例值**: 2026-10-01

#### 3.3.6 数据6: ECN 号 ecn_no
- **数据描述**: 工程变更通知编号，变更依据
- **数据类型**: 文本
- **数据来源**: 用户录入
- **示例值**: ECN-A-118

#### 3.3.7 数据7: 状态 status
- **数据描述**: 关系是否生效；失效的关系在零件级处理中被排除
- **数据类型**: 枚举值
- **数据来源**: 系统默认"生效"，用户可设为"失效"
- **示例值**: 生效 / 失效

### 3.4 状态机

替换关系状态流转：

```
(新建) ──→ 生效 ──→ 失效
```

**状态转换规则矩阵：**

| 当前状态 | 目标状态 | 触发动作 | 前置条件 |
|---|---|---|---|
| (新建) | 生效 | 创建替换关系 | 旧件/新件引用校验通过，替换类型新旧件不同 |
| 生效 | 失效 | disable(rel_no) | 无 |
| 失效 | 生效 | 需重新创建（V1 不支持反向激活，实际通过新建关系实现） | — |

### 4.3 功能详细说明

#### 4.3.1 F01-05 替换关系

##### 4.3.1.1 FUNC-01 创建替换关系

**功能描述**:
提供替换关系的创建表单，用户选择关系类型和旧/新零件号，填写切换时点/ECN号后保存。此功能为独立创建——前端保留"新建"按钮。

**用户操作流程**:
1. 用户进入"替换关系"列表页，点击"新建"按钮
2. 系统展示创建表单
3. 用户选择 rel_type（替换/替代）
4. 用户选择 old_part（来源：md_material.list 下拉选择）
5. 用户选择 new_part（来源：md_material.list 下拉选择）
6. 用户填写选填字段：switch_date, ecn_no
7. 用户点击"保存"
8. 系统执行校验：
   a. rel_no 唯一性
   b. old_part 存在性（self.fde.call → md_material.get）
   c. new_part 存在性（self.fde.call → md_material.get）
   d. rel_type=替换 → old_part != new_part
   e. rel_type 和 status 枚举值
9. 校验通过 → 记录入库，status 默认"生效"

**输入数据**:
- rel_no: 关系号 - 必填，最大50字符，PK - 示例：REL-001
- rel_type: 关系类型 - 必填，枚举（替换\|替代） - 示例：替换
- old_part: 旧件号 - 必填，来源 md_material.list 下拉选择 - 示例：8210001-A
- new_part: 新件号 - 必填，来源 md_material.list 下拉选择 - 示例：8210001-B
- switch_date: 切换时点 - 选填，日期 - 示例：2026-10-01
- ecn_no: ECN号 - 选填，最大50字符 - 示例：ECN-A-118
- status: 状态 - 系统默认"生效"，枚举（生效\|失效）

**输出数据**:
- 成功消息: "替换关系创建成功"
- 错误消息: "该关系号已存在" / "旧件号不存在" / "新件号不存在" / "替换关系新旧件不能相同" / "关系类型仅支持替换/替代"

**业务规则**:
- BR-01: rel_no 全局唯一
- BR-02: rel_no, rel_type, old_part, new_part 必填
- BR-03: rel_type 仅限"替换"或"替代"
- BR-04: rel_type=替换 → old_part != new_part
- BR-05: old_part 须经 md_material.get 校验
- BR-06: new_part 须经 md_material.get 校验
- BR-07: status 仅限"生效"或"失效"

**特殊处理**:
- old_part 和 new_part 的前端下拉选择均来源于 md_material.list（主数据引用铁律：禁止手工录入）
- 创建时后端做两次 self.fde.call 校验引用完整性
- status 默认"生效"，无需用户选择

**业务实体**:
- **MdPartReplace**: 零件间替换/替代关系与ECN依据，含关系类型/旧件/新件/切换时点/状态

**MdPartReplace 字段**

| 字段名称 | 字段类型 | 是否必填 | 默认值 | 业务逻辑 |
|---|---|---|---|---|
| rel_no | 文本 | 是 | - | 关系号，PK，全局唯一，最大50字符 |
| rel_type | 枚举值 | 是 | - | 替换（旧→新）\|替代；替换类型新旧件不能相同 |
| old_part | 文本 | 是 | - | 旧件号，来源：md_material.list 下拉选择；后端 self.fde.call('md_material.get', old_part) 校验 |
| new_part | 文本 | 是 | - | 新件号，来源：md_material.list 下拉选择；后端 self.fde.call('md_material.get', new_part) 校验 |
| switch_date | 日期 | 否 | - | 切换时点，断点调整的依据 |
| ecn_no | 文本 | 否 | - | ECN号，变更依据，最大50字符 |
| status | 枚举值 | 是 | 生效 | 生效\|失效；失效关系在零件级处理中被排除 |

##### 4.3.1.2 FUNC-02 替换关系列表查询

**功能描述**:
提供替换关系的分页列表，支持按关系类型、旧件号、新件号、状态等条件筛选。

**用户操作流程**:
1. 用户进入"替换关系"列表页
2. 用户可选填写筛选条件
3. 用户点击"查询"
4. 系统返回符合条件的替换关系列表（分页）

**输入数据**:

- old_part: 旧件号 - 选填，模糊匹配 - 示例：8210001
- new_part: 新件号 - 选填，模糊匹配 - 示例：8210001
- status: 状态 - 选填，精确匹配 - 示例：生效
- page: 页码 - 默认1
- size: 每页条数 - 默认20

**输出数据**:
- 列表字段: rel_no, rel_type, old_part, new_part, switch_date, ecn_no, status
- 分页信息: total, page, size

**业务规则**:
- 筛选条件均为可选，条件之间 AND 关系
- old_part / new_part 支持模糊匹配

**特殊处理**:
- 默认按 rel_no 升序排列
- 列表以 status 标签颜色直观区分生效（绿）/失效（灰）

| 关系类型 | rel_type | 是（精确） | 替换/替代 |
| 旧件号 | old_part | 是（模糊） | 被替换/替代件 |
| 新件号 | new_part | 是（模糊） | 替换/替代件 |
| 切换时点 | switch_date | 否 | 显示用 |
| ECN号 | ecn_no | 否 | 变更依据 |
| 状态 | status | 是（精确） | 生效/失效 |

##### 4.3.1.3 FUNC-03 更新替换关系

**功能描述**:
对已有替换关系记录修改切换时点/ECN号/关系类型等信息。rel_no 作为主键不允许修改。变更零件引用须重新校验。

**用户操作流程**:
1. 用户在列表页点击目标行 → 进入编辑模式
2. 系统回填当前值到表单
3. 用户修改可编辑字段
4. 用户点击"保存"
5. 系统校验：枚举值、新旧件相同检查、零件引用校验
6. 校验通过 → 更新入库

**输入数据**:
- rel_no: 关系号 - 不可修改
- rel_type: 关系类型 - 可修改
- old_part: 旧件号 - 可修改（须重新校验）
- new_part: 新件号 - 可修改（须重新校验）
- switch_date / ecn_no: 可修改

**输出数据**:
- 成功消息: "替换关系更新成功"
- 错误消息: "替换关系新旧件不能相同" / "旧件号不存在" / "新件号不存在" / "关系类型仅支持替换/替代"

**业务规则**:
- BR-01: rel_no 不可修改（主键不可变）
- BR-03: rel_type 仅限"替换"或"替代"
- BR-04: rel_type=替换 → old_part != new_part
- BR-05/BR-06: 变更零件引用须重新校验

**特殊处理**:
- 若需同时将 status 设为失效，应使用 disable 方法而非 update

---

##### 4.3.1.4 FUNC-04 设为失效

**功能描述**:
提供 disable(rel_no) 方法将替换关系 status 设为"失效"。也可从前端通过列表操作按钮触发。失效的关系在零件级处理中被排除。

**用户操作流程**:
1. 用户在列表页找到目标替换关系
2. 点击"设为失效"操作按钮
3. 系统弹出确认提示
4. 用户确认后，status 更新为"失效"
5. 后续 part_level_adj 调用 get(rel_no) 时检查 status，失效则排除

**输入数据**:
- rel_no: 关系号 - 必填

**输出数据**:
- 成功消息: "替换关系已设为失效"
- 错误消息: "替换关系不存在"

**业务规则**:
- BR-07: status 更新为"失效"
- 幂等性: 已失效的记录再调用 disable 无副作用

**特殊处理**:
- disable 为幂等操作：已是"失效"状态时直接返回成功
- 失效是单向操作，V1 不支持反向激活（如需恢复生效，重新创建新记录）
- 此方法为公共接口，也可供外部系统通过 self.fde.call 调用

### 6.1 功能验收标准

#### 6.1.1 标准1: 替换关系 CRUD + 生命周期完整闭环

- **预期结果**: 全流程操作成功

#### 6.1.2 标准2: 引用完整性双校验
- **关联用户故事**: US-01
- **关联业务规则**: BR-05, BR-06
- **验证方式**: 创建时分别引用不存在的旧件号 / 新件号
- **测试数据**: old_part=NOTEXIST / new_part=NOTEXIST
- **预期结果**: 两次 self.fde.call 均返回不存在，拒绝创建并提示具体不存在实体

#### 6.1.3 标准3: 替换类型新旧件相同拦截
- **关联用户故事**: US-01, US-03
- **关联业务规则**: BR-04
- **验证方式**: 创建/更新替换类型时 old_part=new_part
- **测试数据**: old_part=8210001, new_part=8210001, rel_type=替换
- **预期结果**: 拒绝保存，提示"替换关系新旧件不能相同"

#### 6.1.4 标准4: 失效记录在零件级处理中被排除
- **关联用户故事**: US-04
- **关联业务规则**: BR-07
- **验证方式**: 创建替换关系→disable→part_level_adj.create_replace_merge 调用 get(rel_no)
- **预期结果**: get 返回 status=失效，调用方据此跳过该关系

#### 6.1.5 标准5: 枚举值校验
- **关联用户故事**: US-01, US-03
- **关联业务规则**: BR-03, BR-07
- **验证方式**: 创建/更新时分别传入 rel_type=互换, status=作废

### 6.2 非功能验收标准
**性能要求**: 列表查询（500条以内）页面加载时间<2秒
**安全性要求**: 引用校验在服务端通过 self.fde.call 强制实施
**兼容性要求**: 支持 Chrome、Edge 浏览器

### 6.3 已知问题或限制
- 替换关系删除功能暂不提供（有效期管理通过 disable 实现）
- V1 不支持失效关系的反向激活，如需恢复生效须重新创建新记录
- 替换关系的生效历史不做自动版本管理，由 switch_date + ecn_no 人工追溯
- ECN 通知不做系统对接，V1 手动录入

### 7.3 外部依赖
- **md_material.get(old_part)**: 创建/更新时校验旧件存在（self.fde.call）
- **md_material.get(new_part)**: 创建/更新时校验新件存在（self.fde.call）
- **被调用方**: part_level_adj.create_replace_merge → get(rel_no)；part_level_adj.create_breakpoint_adj → get(rel_no)

### 7.4 备注
- 本应用属主数据层，数据来源类型为"独立创建"，前端保留"新建"按钮
- rel_type=替换（旧→新，不共存）与 rel_type=替代（可并存、功能等效）在业务上有区别：
  - 替换：断点成对调整（旧件截断 + 新件启动），本应用提供 switch_date 作为切换时点
  - 替代：替换件合并（需求合并计算 + 可用库存统一扣减），本应用提供关系依据
- disable 方法为公共接口，供系统内部调用和前端操作触发
