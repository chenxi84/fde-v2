# 销售预测 · 详细设计

> 本文档是销售预测域的单独详设，即《产销协同简化详设》§1 的展开版。上游接客户需求信息与历史数据，下游交出**已发布毛需求**，作为净需求运算的唯一需求输入。不做净需求运算、库存策略设定、生产排程与调拨执行（归《产销协同简化详设》§2~§4）。

---

## 0. 域边界与节奏

| 项 | 内容 |
|---|---|
| 输入 | 客户 N+1~N+3 滚动预测；历史需求（干净口径）；外生变量（可选增强）；事件线索 |
| 输出 | 已发布毛需求（物料 × 期间：当期仅含一次性调整量 + N+1~N+3 预测） |
| 不做 | 净需求运算、库存水位设定、生产排程、调拨/发运执行 |
| 节奏 | 月度滚动发布；周度只执行、不改预测参数——参数只在月度闭环中调整 |

---

## 1. 数据准备

### 1.1 客户滚动预测收集

- 期间口径 **N+1~N+3**（N = 当前自然月），不含当前月；当期基础需求由未发订单承接（简化详设 §3）；
- **模式约定：仅支持 N+3 月度滚动**。版本 = 自然月（V+YYYYMM），无子版本；每月收集 opening 时按**进行中项目的零件**自动生成 N+1/N+2/N+3 三行，收集填量或标"未提供"（完整性结构化保证）；
- 客户月中修订不在预测层追：近端由执行层吸收（未发订单/缺货订单进需求池），远端下月版本体现；一次性事件可随时附加登记（§3.3），不受月度冻结限制；
- 客户未提供的期间显式标记"未提供"，**禁止隐性补 0**（区分"没需求"与"没给数"）；客户完全不提供预测的物料，走基线直达路径（§2.3 规则 4）。

### 1.2 历史需求（干净口径）

- **采纳口径：需求历史 = 寄售仓月度结算量**。结算是客户实际领用，天然不含水位脉冲与补货波动，无需分离；基线生成、参数回校直接取用。基线由此固定为**消耗口径**；发运/补库口径由基线 + 一次性调整（§3.3）构成，各管一段；
- 结算侧自身的大一次性尖峰（如客户一次性集中领用）按重大性排除（> 20% 期量）；断点期历史按截断处理（§2.3 规则 3）；
- **非寄售客户无结算**：用出货台账，干净量取得顺序：① ERP 订单按原因拆分；② 扣加工表（§3.3）登记且已履约的一次性量；③ 漏登大事件用当期实际对比当期基线水平估算；阈值以下容忍不分离（平均稀释、脉冲与回落对冲，影响小）。

### 1.3 外生变量（可选增强）

- 整车销量/上险数/OEM 排产，用于趋势交叉验证（§3.2）；
- 外部数据须登记来源/口径/时滞，**未登记不使用**；滞后数据不得当期数据用。

## 2. 统计基线

### 2.1 定位

基线是客观锚与修正起点，不直接等于预测结论；客户预测缺失时，基线经 §3.2/§3.3 调整后作为独立需求底。

### 2.2 方法库

| 方法 | 适用形态 | 参数 / 来源 | 档位 |
|---|---|---|---|
| 移动平均 | 稳定 | 窗口期数 | 必选 |
| 指数平滑 | 近期权重高的趋势 | α | 必选 |
| 阶跃外推 | SOP/产能切换等阶跃变化 | 阶跃点识别 | 必选 |
| 生命周期衰减模型 | 上市高后下滑、短生命周期 | 峰值、衰减率：自身早期数据校准优先，不足时从模板库/类比借 | 必选（"禁峰值外推"规则的执行方法） |
| 借用：先导指标/类比/模板 | 零历史（SOP 新件、断点新件） | 先导指标（客户滚动预测/预订量通知）、相似车型或模板库；有自身早期数据必须校准 | 必选 |

- 模板库/类比库是**先验来源通道**，不与外推方法并列：其输出是相应方法的参数或曲线（衰减模型的峰值/衰减率、类比车型的基线曲线）；
- 先分类形态再选方法；**方法切换须登记依据**，不自动跳（参数按月回校，方法不按月跳）；
- 参数初始按经验设，按基线准确率/偏差由月度闭环回校（简化详设 §5）；
- **禁峰值外推**："上市高后下滑"形态必须用衰减模型，禁止按上市峰值线性外推。

### 2.3 生成规则

1. 粒度：物料 × 客户·车型 × 期间；月度滚动重生成，留版本痕迹；
2. 输入用干净需求（小一次性容忍、被平均稀释）；"大一次性"量不进基线（§3.3）；
3. 断点联动：旧件基线在断点期截断，新件按正调整启动（§3.3）；
4. 客户预测缺失 → 基线直接作为加工底；
5. 零历史（SOP 新件、断点新件）→ 走借用（先导指标/类比/模板），借用来源与参数登记入基线表；自身早期数据到达后校准参数。

### 2.4 基线表最小字段

物料 / 客户·车型 / 期间 / 基线值 / 方法+参数（含借用来源） / 生成批次·版本

## 3. 基线加工 → 独立需求

### 3.1 客户置信度调整

- 基线对比客户预测值，参考置信度调整；
- 置信度 = 客户历史达成率（闭环产出，§8）：一贯多报打折、一贯少报补足、达成率高直接采用；
- 客户预测缺失 → 本步跳过。

### 3.2 整车销售趋势调整

- 用外生变量（§1.3）交叉验证；偏离超阈 → 调整或登记原因；
- 整车库存系数偏高 → 远端减产预警，提示下调远端。

### 3.3 一次性调整（特殊事件）

事件（促销、客户加库存、断点、其他一次性、独立需求）不单设台账，作为**调整最终预测数字的来源之一**：在预测行上记调整量 + 原因，如"+180，原因：客户促销/客户加库存"。纪律：

- **一次性标签与重大性**：调整标一次性、记归属期，只作用于归属期、不外推；历史算基线时排除超重大性阈值（一次性量 > 20% 期量；断点/大事件恒排除）的量，阈值以下容忍（§1.2、§2.3）；
- **不顺延**：一次性调整只加在归属期行上，不自动带入后续各期；事件完成后需求回落是预期表现，不作新的负调整登记；
- **订单冲抵**：调整并入该期毛需求后，对应要货（调拨单）到达时由订单冲抵该期毛需求——与净需求运算、库存推移表共用（简化详设 §3.1 规则 3），不双算的唯一关口；订单数据由协调层供给（净需求公式的未发订单项），预测域不读订单台账；
- **断点成对调整**：旧件截断（负量）与新件启动（正量）在各自物料行上成对调整，原因挂同一设变号；旧件残余量与库存+在途比对，超出转呆滞预警。

### 3.4 独立需求与加工表

独立需求 = 基线 + 置信度/趋势/一次性调整（客户·工厂行粒度）；按物料汇总成初步毛需求（§8.4），再经零件级处理（§4、§8.5）得最终毛需求。

加工表最小字段：物料 / 期间 / 基线 / 客户预测 / 置信度调整 / 趋势调整 / 一次性调整（量+原因+标签） / 独立需求 / 加工人

表样（承接 8210001 剧情）：

| 物料 | 期间 | 基线 | 客户预测 | 置信度调整 | 一次性调整 | 独立需求 | 说明 |
|---|---|---|---|---|---|---|---|
| 8210001 | 2026-09 | 960 | 1150 | 970（达成率 97.5%，近直采） | +180 一次性（原因：客户加库存） | 1150 | 一次性量不进基线、不顺延（§3.3） |
| 8210001 | 2026-10 | 1100 | 1100 | 1100 | 0 | 1100 | 无阶跃，直采 |

## 4. 合并加工（零件级处理功能）

> 三个功能独立运行，在初步毛需求表（§8.4，物料级）生成后执行，结果以零件级调整量作用回初步表得最终毛需求（§8.6）；不混入客户行加工（§8.3）。

### 4.1 通用件合并

- 跨客户汇总去重，总量由计划把控；
- 有证据加码（函件/促销）保留，口头加码按历史折减系数折减；折减系数由历史"加码 vs 实际用量"回测。

### 4.2 替换件合并

- 可替代/替换关系零件的需求合并计算，可用库存（含被替换件库存）统一扣减，防分别下单造成超储。

### 4.3 变更断点调整

- 旧件需求断崖与新件启动按 §3.3 成对调整落入对应期间；
- 旧件尾量与现有库存+在途比对，超出部分转呆滞预警。

## 5. 毛需求发布

### 5.1 构成

已发布毛需求(物料×期间) = 初步毛需求（物料汇总）+ Σ 零件级处理量（通用/替换/断点）；一次性调整已含在独立需求/初步内，随原因列示——列示不重复加。

当期列仅含一次性调整量；当期基础需求由未发订单承接，与预测互斥（§1.1）。

### 5.2 冻结与版本

- R 版 = 自然月，与 V 版/加工批次 1:1；三个预测行发布后冻结；**一次性调整可月中附加登记**并入池；
- 考核/复盘只引用版本快照（V/R），不引用当前值。

### 5.3 下游交接

- 已发布毛需求是净需求运算的**唯一输入**（简化详设 §3）；未发布口径不得外流；
- 构成列示：一次性调整量随原因列示，下游可区分性质（趋势量可随版本演化，一次性量必须履约）。

### 5.4 发布表最小字段

物料 / 期间 / 发布量 / 主要依据（含重要一次性调整的原因） / 发布版本

## 6. 角色与分工（轻量）

| 角色 | 职责 |
|---|---|
| 一线销售 | 预测收集（及时性）、客户侧信息（改款/促销/口头增减）、事件线索 |
| 总部计划 | 基线生成与确认、置信度/趋势/一次性调整确认、合并总量把控、发布决策 |

- 销售提供"信息"，计划把控"口径"；修正须附依据（函件优于口头）；
- 争议不在域内僵持：升级月度产销平衡会。

## 7. 闭环接口（预测域侧）

> 闭环会体在协调层（简化详设 §5 月度闭环）；本域负责指标供给、归因执行与参数接收。本节为操作层设计。

### 7.1 指标与计算口径

| 指标 | 口径 | 粒度 | 用途 |
|---|---|---|---|
| 客户预测达成率 | 结算实际 / V 版快照原始量；一次性量两侧剔除 | 客户 × 期间，**分 horizon（M+1/M+2/M+3 各算）** | H3 置信度（P2） |
| 基线偏差率 / 方向 | (基线 − 结算) / 结算；符号即方向 | 零件 × 期间 × horizon | 方法/参数回校（P1） |
| 发布偏差率 | (发布量 − 结算) / 结算 | 零件 × 期间 | 总体复盘、归因 |

规则：

1. 一次性调整量单独核销，不混入准确率计算；
2. **分 horizon 计算是核心**：同一目标月被预测三次，分 horizon 准确率反映信息衰减，供置信度与模式假设复盘；
3. H1 月度关账后系统自动生成，不人工算。

### 7.2 月度复盘流程（入站回校）

1. 关账后指标与 H3 自动生成；
2. 计划复核越阈行（达成率 <90% 或 |基线偏差| >15%，可配置）：逐行归因（§7.3）；
3. 回校动作写 §10 配置：conf_factor 按 P2 自动；基线方法/参数按 P1 调整并登记；一次性纪律强化反哺登记；
4. 复盘结论与动作入月度复盘表（协调层，简化详设 §5）；预测域留归因结论留痕。

### 7.3 归因（轻量规则）

偏差归因区分"我方多报/加工失误"与"客户需求塌方"，塌方须举证（外部减产/销量骤降/客户函件），不凭自述免责；归因结论入月度复盘。

归因登记三要素：归因类别 / 证据 / 结论；误判的一次性调整反哺登记纪律（§3.3）。

## 8. 表单详设

> 单据链为"快照 → 基线 → 加工 → 初步毛需求 → 零件级处理 → 发布"；各表最小字段见 §1.1/§2.4/§3.4/§5.4，本节为字段与规则的正式规格。调整列均为**带符号调整量（delta）**，独立需求/发布量由系统强制加和。
> 录入键 = 客户/工厂 + 物料 + 月度版本（期间自动展开 N+1/N+2/N+3 三行）；录入只填这几项 + 量。**项目、车型为多值参考属性**：从项目台账自动带出，不参与键、不拆行（零件跨车型/跨项目 = 一行多标签）；供生命周期/EOP 感知、断点与 EOP 调整按映射 per-project 定量、归属参考（多值时按需按份额分摊）。活跃行集 = 出现在至少一个进行中项目的零件。

### 8.1 预测快照表（平铺·物料明细）

定位：客户预测唯一入口；无单头，按物料明细平铺；版本号即快照键；达成率/置信度的计算基准。

| 字段 | 代码 | 必填 | 规则 |
|---|---|---|---|
| 客户 / OEM 工厂 | oem_code / plant_code | ✔ | 录入键；同一主机厂多工厂分行 |
| 物料号 | part_no | ✔ | 录入键 |
| 项目号（多值） | project_no | — | 自动带出、仅参考：项目台账关联的全部项目；不拆行 |
| 客户车型（多值） | veh_model | — | 自动带出、仅参考 |
| 期间 / 偏移 | period / offset | ✔ | M+1~M+3 折算会计期间；**不含当前月** |
| 原始需求量 | orig_qty | ✔ | **录入后永不修改**；变更 = 新版本新行 |
| 数据标记 | data_flag | ✔ | 正常 / OEM 未提供（显式缺报 ≠ 0） |
| 预测版本 | fcst_version | ✔ | V+YYYYMM(.x)；PK = 客户+版本+物料+期间 |
| 来源渠道 | source_channel | ✔ | EDL/EDI · OEM 门户 · 邮件 Excel · 销售转录；按版本自动盖章 |
| 接收日期 / 收集人 | recv_date / collector | ✔ | 系统自动盖章；收集人 = 一线销售（及时性责任人） |

规则：

1. **单一模式**：仅 N+3 月度滚动；版本 = 自然月（V+YYYYMM），无子版本；收集 opening 时系统按"出现在至少一个进行中项目的零件"自动生成 N+1/N+2/N+3 三行，完整性结构化保证（不存在半套；未提供显式标记、禁止补 0）；
2. **行不可变**：旧月版本行永不覆盖、永久保留、不参与下游取数；
3. **状态推导、不维护**：无状态列——最新月版本即活跃；更旧版本自动"已替代"；随当期 R 版发布联动锁定；
4. **月中不追修订**：近端变化由执行层吸收（未发订单/缺货订单），远端下月版本体现；一次性事件可随时附加登记（§3.3），不受此限；
5. 达成率 = 结算实际 / 本版本行原始量（§7.1）；同一目标月在连续三个版本中被预测（作 N+3/N+2/N+1），并排即预测成熟度视图，供分置信度分析；
6. **跨版本比对**：按物料过滤、版本列并排即差异视图（阶跃识别入口）。

### 8.2 基线表

定位：客观锚；系统生成 + 计划确认；销售只读。

| 字段 | 代码 | 必填 | 规则 |
|---|---|---|---|
| 基线批次 | base_batch | ✔ | B+YYYYMM；与同月快照 V 版 1:1 |
| 客户 / OEM 工厂 | oem_code / plant_code | ✔ | 键，与快照表同维度 |
| 物料 / 期间 | part_no / period | ✔ | 键，与快照表同构 |
| 预测版本 | fcst_version | ✔ | 同月 V+YYYYMM，供 lineage |
| 项目号 / 车型（多值） | project_no / veh_model | — | 自动带出、仅参考 |
| 统计基线值 | base_qty | ✔ | 方法输出 |
| 基线路径 | base_path | ✔ | 时序外推 / 借用 |
| 方法+参数 | base_method | ✔ | 如"指数平滑 α=0.3"；借用记方法+来源（相似车型/模板/预测版本） |
| 交叉验证 | cross_chk | — | 外生变量（车型销量/排产）偏离，超阈记原因 |
| 生成人·时间 / 状态 | generator / status | ✔ | 系统预计算 / 计划确认 |

规则：

1. **与快照表一一对应**：B+YYYYMM 与 V+YYYYMM 按同一"零件（出现在在产项目）× N+1/N+2/N+3"行集逐行展开；客户未提供预测的行基线照生成（取结算历史）；仅"既无历史又无预测"的新件空窗标"待补"，走借用/人工（§2.3 规则 5）；
2. 外推原料 = 寄售结算量（干净）；大一次性排除、断点截断（§1.2、§2.3）；
3. 零历史必须借用：记方法+来源+参数，有早期数据必须校准（§2.3 规则 5）；
4. 方法切换登记依据；参数按月闭环回校；
5. 销售只读；基线不因"不认可"调整，意见走加工表调整层；
6. 历史批次保留不覆盖。

### 8.3 预测加工表

定位：加工总账；基线 → 各调整 → 独立需求；计划与销售的制衡载体。

单头：加工批次 PRC-YYYYMM-NNN，绑定基线批次 + V 版；状态：进行中 / 全部核定 / 已锁定。

**明细**

| 字段 | 代码 | 必填 | 规则 |
|---|---|---|---|
| 客户/工厂+批次+物料+期间 | — | ✔ | 键与快照表同构；项目/车型为多值参考列 |
| 基线值 | base_qty | ✔ | §8.2 快照 |
| 客户预测 | cust_qty | — | = 快照 orig_qty；未提供即空 |
| 置信度调整 | conf_adj | — | delta；信任系数自动带出（闭环），人工覆写须理由 |
| 趋势调整 | trend_adj | — | delta；外生交叉验证，超阈须理由 |
| 一次性调整 | onetime_adj | — | delta + 原因 + 一次性标签；超重大性（>20% 期量）或断点/大事件标"大一次性" |

1. 独立需求系统强制加和，禁止手工改总量；

5. 全部行核定 → 喂初步毛需求汇总（§8.4）；随 R 版发布同步锁定；
6. **当期一次性行**：加工/发布表可有当期行（基线值空、仅一次性调整有值），V/B 表无对应行——1:1 行集指 N+1~N+3，一次性行附加于加工/发布侧（趋势按月冻结、事件随时登记）；

### 8.5 零件级处理功能（通用/替换/断点）

定位：三个独立功能，在初步表生成后顺序运行；输出为物料×期间的调整量（delta + 原因/依据），作用回初步表得最终毛需求。

| 功能 | 输入 | 调整逻辑 | 输出 |
|---|---|---|---|
| 通用件合并 | 通用标记（M4 派生 ≥2 客户）的初步行 | 汇总去重折减：有证据保留、口头按历史系数折减（§4.1） | delta（常 ≤0）+ 折减依据 |
| 替换件合并 | M5 替换关系 | 替代关系需求合并、可用库存（含被替换件）统一扣减（§4.2） | delta + 原因 |
| 断点处理 | M5 / ECN | 旧件截断负、新件启动正，成对（§4.3） | 成对 delta + ECN 依据 |

规则：

1. 功能只写 delta，不改初步表与客户行加工表；最终毛需求 = 初步 + Σ delta；
2. 每条 delta 登记原因/依据，可追溯；
3. 执行顺序：通用 → 替换 → 断点（断点最后，基于最新量）。

**输出记录字段（零件级处理表）**

| 字段 | 代码 | 必填 | 规则 |
|---|---|---|---|
| 处理单号 | adj_no | ✔ | PK，PAD-YYYYMM-NNN |
| 功能类型 | func_type | ✔ | 通用件合并 / 替换件合并 / 断点处理 |

| 调整量 | adj_qty | ✔ | delta，带符号 |
| 原因 / 依据 | basis | ✔ | 函件 / ECN / 历史折减系数 / 替换关系等 |
| 配对号 | pair_no | 条件 | 断点必填：关联旧/新件正负行 |
| 处理人·时间 | owner / time | ✔ | 总部计划 |

> 通用件不做客户拆回：发运侧按实际调拨单执行（执行层），预测侧只给物料级总量。
