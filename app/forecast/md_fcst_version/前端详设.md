## 2. 区块构成

### 2.1 列表区（查）—— 三段式：工具栏 / 表格 / 分页条

**用途**：月度版本全量浏览 + 新建入口。本页为非看板页，不设 KPI 指标带（验收断言无 `.kpi`）。

**过滤控件（与 `md_fcst_version.list(page, page_size)` 参数对应；list 仅支持分页，无业务过滤参数）**：

| 控件 | 对应参数 | 形态 |
|---|---|---|
| 分页条 | `page` / `page_size` | `pageable()`，integer 传参 |

> 注：`md_fcst_version.list` 仅接受 `page` / `page_size`，无 oem_code/stage 等业务过滤参数。列表按 fcst_version 降序（最新版本在前），前端不额外设过滤控件。

**工具栏**：「+ 新建版本」（打开 2.3 创建模态）。

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 版本号 | `fcst_version` | `.b-link`，点击打开详情模态 |
| 锚定期间 | `base_period` | 文本 |
| 对应预测期间 | `periods` | `tryParse()` 后展示为「M+1 ~ M+3」三个月份标签 |
| Opening日 | `opening_date` | 文本，空值 `dash()` |
| 状态 | `status` | `hue()` 徽章（活跃=绿 / 锁定=灰） |
| 关联批次 | `linked_batch` | 文本，空值 `dash()`；活跃版本为空白 |
| 操作 | — | 活跃行 → 【锁定】（调 set_linked）；锁定行 → 无操作 |

**交互**：翻页仅改 `page/page_size`；锁定操作成功后刷新当前页；空结果显示空态文案。

### 2.2 详情模态（查全）—— 三段式：墨青头带 / KV 分组体 / 操作页脚

**用途**：点 `fcst_version` 弹出，展示 `md_fcst_version.get` 返回的全部字段。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `fcst_version` + `status` 徽章 | 墨青头带，徽章 `hue()` |
| 基本信息 | `fcst_version` / `base_period` / `opening_date` | `.kv`；fcst_version 注明「YYYYMM 格式 · 全局唯一 · 创建后不可变更」 |
| 预测期间 | `periods` | `tryParse()` 后按「M+1: YYYY-MM / M+2: YYYY-MM / M+3: YYYY-MM」结构化展示 |
| 状态信息 | `status` / `linked_batch` | `.kv`；linked_batch 空值 `dash()`，注明「R版发布联动写入」 |
| 原始数据 | get 返回全量 JSON | 底部折叠（默认收起） |

**页脚 `.modal-ft`**：按 `status` 的【锁定】按钮（x-show="status==='活跃'"）+ 【关闭】。

### 2.3 创建表单（增）—— 模态表单

**用途**：覆盖 `md_fcst_version.create` 接受的业务参数。**本应用无 update 服务，创建后除 set_linked 外不可修改字段。**

| 字段 | 控件 | 必填 | create 可见 | 约束来源 |
|---|---|---|---|---|
| `fcst_version` | input，maxlength=6，placeholder「如 202608」 | ★ 必填 | 是 | BR-06 6位数字 YYYYMM；BR-01 全局唯一 |
| `base_period` | input，placeholder「如 2026-08」 | ★ 必填 | 是 | BR-03 periods 以此为锚计算 |
| `periods` | 只读展示（自动推算） | ★ 必填 | 是（自动） | BR-03；系统根据 base_period 自动推算 M+1~M+3 |
| `opening_date` | date input | 选填 | 是 | BR-05 |

- create 模式：`fcst_version` + `base_period` 用户填写；`periods` 由前端根据 base_period 自动推算三个连续月份并展示为只读标签（M+1~M+3），用户确认无误后提交。后端再次校验 periods 合法性。
- 布局：第一行（fcst_version）、第二行（base_period）、第三行（periods 自动推算展示 + 说明文字「系统根据锚定期间自动推算 M+1~M+3」）、第四行（opening_date）；底部右对齐「取消」「创建」。
- 前端仅做必填校验（空值 → toast 警告、不提交）；fcst_version 格式、唯一性、活跃版本冲突、periods 合法性由后端校验，`FdeError` 经 api.js 以错误 toast 呈现。
- 提交成功：toast「月度版本创建成功」→ 关闭模态 → 重置列表回第 1 页重载。
- **无编辑入口**：本应用无 update 服务，创建后不可修改字段；状态变更仅通过 set_linked 锁定操作。

### 2.4 锁定操作（set_linked）

**用途**：活跃版本行显示【锁定】按钮，调 `md_fcst_version.set_linked`。

- 行内操作列 + 详情模态页脚：`x-show="status==='活跃'"` 时显示【锁定】。
- 点击 → 弹出输入框填写关联 R 版发布单号（`rel_no`），可选填写。
- 确认后调用 `svc("md_fcst_version","set_linked")` `{fcst_version, rel_no}`。
- 成功后 toast「版本已锁定」→ 刷新列表 + 若模态打开则原地更新 status/linked_batch。
- 已锁定版本再锁定 → 后端返回「版本已锁定」，前端 toast 呈现。

## 3. svc 字面量清单（授权派生依据——必须字面量 svc("应用","服务")）

| 区块 | 调用（应用.服务） | 参数 | quiet | 说明 |
|---|---|---|---|---|
| 列表区 | `svc("md_fcst_version","list")` | `{page, page_size}` | — | 分页查询，按 fcst_version 降序 |
| 详情模态 | `svc("md_fcst_version","get")` | `{fcst_version}` | — | 全字段详情；periods 为 JSON 数组 |
| 创建表单 | `svc("md_fcst_version","create")` | `{fcst_version, base_period, periods, opening_date}` | — | periods 为前端自动推算的数组 |
| 锁定操作 | `svc("md_fcst_version","set_linked")` | `{fcst_version, rel_no}` | — | 活跃→锁定，关联 R 版单号 |

> 以上 4 处必须在 view.js 中以字面量逐项书写，**勿用变量拼名**。

## 4. 数据来源与下拉

- **无跨应用主数据下拉**：`md_fcst_version` 不主动外调其他应用；版本号、锚定期间均为用户手工录入；periods 由前端根据 base_period 自动推算；状态为静态枚举（活跃 / 锁定）。
- **契约 payload → 区块字段映射**：

| 契约 | 载荷字段 | 映射区块 |
|---|---|---|
| `md_fcst_version.list` 返回项 | `fcst_version, base_period, periods, opening_date, status, linked_batch` | 2.1 列表列 |
| `md_fcst_version.get` 返回 | 同上（全量） | 2.2 详情模态 kv + 原始数据 |
| `md_fcst_version.create` 入参 | `fcst_version, base_period, periods, opening_date` | 2.3 创建表单 |
| `md_fcst_version.set_linked` 入参 | `fcst_version, rel_no` | 2.4 锁定操作 |

- `periods` 为 JSON 数组字符串（如 `["2026-09","2026-10","2026-11"]`），get 返回已由后端反序列化；列表展示和详情模态均需 `tryParse()` 处理。

## 5. 交互要点

1. **加载**：首载正常拉取 list（非看板页，失败走 api.js 统一通道）。
2. **periods 自动推算**：用户输入 base_period（如 2026-08）→ 前端实时计算并展示 M+1~M+3（2026-09 / 2026-10 / 2026-11）为只读标签，用户确认无误后随表单提交 periods 数组 `["2026-09","2026-10","2026-11"]`。
3. **状态机（活跃→锁定）**：仅 status=活跃 的行显示【锁定】按钮；锁定为终态，锁定后不再显示任何操作按钮。创建表单无 status 选择器，状态由系统自动管理。
4. **微交互**：表格行 hover 高亮；fcst_version `.b-link` hover 下划线；status 徽章 `hue()` 着色；「创建」按钮提交期 loading 防重复点击。
5. **成功流**：create 成功 → 关闭模态并清空表单 → toast「月度版本创建成功」→ 列表回第 1 页重载；set_linked 成功 → toast「版本已锁定」→ 刷新当前页。
6. **错误流**：重复 fcst_version / 活跃版本冲突 / periods 不合法 / 重复锁定等后端 `FdeError` → toast 错误信息；创建模态保持打开便于修改后重试。
7. **空态**：无任何版本时「暂无版本 —— 点『新建版本』创建」。
8. **展示工具**：`tryParse()`（periods JSON 数组）、`hue()`（status 徽章）、`dash()`（空 opening_date / linked_batch）、无金额字段无需 `fmt()`、无时间字段无需 `fmtTime()`。

## 6. 验收关注点（供第⑧步）

1. **路由渲染**：`#/md_fcst_version` 挂载出列表三段式（工具栏 + 表格 + 分页条），**断言无 `.kpi`**（非看板页防挂载粘滞假过）。
2. **造数后列表有数据**：创建版本 202608 → 列表 1 行，fcst_version / base_period / periods（M+1~M+3 三标签）/ opening_date / status=活跃 齐全；按 fcst_version 降序排列。
3. **无业务过滤控件**：列表区仅分页条，无 oem_code/stage 等过滤控件（list 签名仅 page/page_size）。
4. **模态全字段**：点 fcst_version 开模态，断言全部 6 字段可见 + periods 结构化展示 + 「原始数据」可展开。
5. **periods 自动推算**：base_period 填 2026-08 → periods 展示 2026-09/2026-10/2026-11；提交后 get 返回 periods 数组正确。
6. **表单落库**：create 填 fcst_version + base_period（★）→ 提交 → 列表出现新记录且 status=活跃；空必填字段提交 → toast 警告且不发请求。
7. **活跃版本冲突**：已有活跃版本 202608 → 创建 202609 → 后端 toast「当前已有活跃版本 202608」。
8. **锁定操作**：活跃行点【锁定】→ 输入 R 版单号 → 确认后 status 变为 锁定 + linked_batch 正确记录 → 行内不再显示【锁定】按钮；已锁定版本再锁定 → 后端 toast「版本已锁定」。
9. **无编辑入口**：列表面和详情模态均无编辑按钮（本应用无 update 服务）。
10. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP>=400（受限会话 403 属预期执法单独豁免）。
