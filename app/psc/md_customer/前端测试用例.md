## §2 造数后列表有数据

- **VT-LIST-01 列表含所造单号**
  - 页面: `psc:md_customer`
  - 前置造数: fetch 造数 §0 C001 + C1001（两条）
  - 操作: 进入 `#/md_customer`（或 `pg.reload()`）
  - 断言: 列表含 C001 单号（`has_text="C001"` 精确定位，不假设顺序，#17）；该行六列值齐 = [C001 / 客户A / 91110000710931000M / 现售 / 3 / 2]；「共 2 条」；表头含「统一社会信用代码」列；悬停线边库存天数表头「?」徽标 → 释义条出现且含「最低库存 A」
  - 选择器注意: 多单号时 `.first` 可能命中 C1001（列表按 customer_no 升序），一律用精确单号 `has_text` 定位（#17）

- **VT-LIST-02 搜索抽样（customer_no 模糊）**

## §4 表单落库回显

- **VT-FORM-01 创建**
  - 页面: `psc:md_customer`
  - 前置造数: 无（表单自造 NEW-01）
  - 操作: 点「+ 新建客户」→ 填 customer_no=NEW01 / customer_name=新客户 / credit_code=91350100M000100C4G / settle_mode 下拉选 寄售 / line_stock_days=2 / transfer_lead_days=4 → 点「创建」
  - 断言: toast「客户主数据创建成功」；模态关闭；列表回显 NEW01 单号（`has_text`）；重开 NEW01 详情六字段值回显正确（新客户 / 91350100M000100C4G / 寄售 / 2 / 4）
  - 选择器注意: 提交期按钮文案切「保存中…」防重复点击；`line_stock_days` 留空入库默认 0（US-01-AC4）可另补专案，见 §7

- **VT-FORM-02 创建必填校验（前端拦，不发请求）**
  - 页面: `psc:md_customer`
  - 前置造数: 无
  - 操作: 点「+ 新建客户」→ customer_no / customer_name 留空 → 点「创建」
  - 断言: toast 警告「客户编码与客户名称必填」；模态保持打开；**不发出** `/api/apps/md_customer/call/create` 新请求（网络请求断言无该 POST）
  - 选择器注意: 必填仅前端校验（customer_no/customer_name）；唯一性与非负整数校验归后端（`FdeError` → 错误 toast）

- **VT-FORM-03 编辑态（键字段锁定 + 变更回显）**
  - 页面: `psc:md_customer`
  - 前置造数: §0 C001（fetch 造数）
  - 操作: 点 C001 行【编辑】→ 编辑表单打开
  - 断言: `customer_no` 输入框带 `disabled` 属性（`has_attribute`，主键只读不可改）；标题含「编辑客户 · C001」；改 line_stock_days=7 → 点「保存修改」→ toast「客户主数据更新成功」→ 列表 C001 行 line_stock_days 列 = 7 → 重开 C001 详情回显 7
  - 选择器注意: customer_no 只读用 `:disabled` 绑定，断言 `input[placeholder="如 C1001"]:disabled`；保存后刷新当前页（`list.load(page)`）

- **VT-FORM-04 批量导入（import_batch upsert）**
  - 页面: `psc:md_customer`
  - 前置造数: 无（导入模态自造 IMP-01）
  - 操作: 点「批量导入」→ textarea 粘贴 `IMP01,导入客户,91350100M000100C4G,现售,1,2` → 点「批量导入」
  - 断言: 摘要区显示「成功 1 条」「失败 0 条」「共 1 条」；toast「导入完成 · 成功 1 条 / 失败 0 条」；关闭后列表回显 IMP01（`has_text`）
  - 选择器注意: 导入支持 CSV/TSV/JSON 逐行（首行表头自动跳过）；`rows` 经 UI 粘贴提交（非 fetch 造数），返回 `{total, success, fail, errors}`；导入完成 `list.load(1)` 刷新
