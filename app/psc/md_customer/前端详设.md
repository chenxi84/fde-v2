# 客户主数据 前端详设
> 来源：app/psc/_contracts.md（冻结契约）+ app/psc/md_customer/应用详设.md；产出供第⑦步前端编码 / 第⑧步前端测试用例。
> 落位：`app/psc/md_customer/view.js` + `view.html`（与 `md_customer.py` 同文件夹，落盘即进启动清单与授权清单，零接线）；import 一律绝对路径 `/view/lib/*`；模板经 `new URL("view.html", import.meta.url)` 抓取；工厂 `export default function pageMdCustomer()`（保留专名）。

## 1. 页面元数据 PAGE_META

| 字段 | 值 | 说明 |
|---|---|---|
| key | `md_customer` | = 应用文件夹名，page_id 为 `psc:md_customer` |
| name | 客户主数据 | 侧栏菜单名 |
| ic | 🏢 | 菜单图标字 |
| title | 客户主数据 | 主区页面头标题 |
| crumb | 主数据 · 客户/结算模式/线边缓冲参数 | 头部副题 |
| order | 20 | 升序即菜单序 |

- 页面零鉴权：无任何权限判断；菜单按页面授权渲染在 shell，数据范围（一线销售/总部计划均可全量操作，仅「批量导入」对一线销售收敛）由后端闸门执法，401 由 api.js 自动跳登录。
- 数据来源类型：**独立创建**——前端保留「新建」按钮 + 编辑入口 + 批量导入（ERP 冗余同步）；本应用是主数据源，无上游主数据依赖，被 sales_forecast / inventory_strategy / attainment 下游弱引用。

## 2. 区块构成

### 2.1 列表区（查）—— 三段式：过滤条 / 表格 / 分页条

**用途**：客户主数据全量浏览 + 条件检索 + 新建/编辑/批量导入入口。本页为非看板页，不设 KPI 指标带（验收断言无 `.kpi`）。

**过滤控件（与 `md_customer.list(customer_no, customer_name, credit_code, page, size)` 可过滤参数一一对应；契约无 settle_mode 过滤参数 → 不设结算模式过滤控件，禁止前端假过滤）**：

| 控件 | 对应参数 | 形态 |
|---|---|---|
| 客户编码输入框 | `customer_no` | placeholder「客户编码」，Enter 或「查询」按钮触发（后端 LIKE 模糊匹配） |
| 客户名称输入框 | `customer_name` | placeholder「客户名称」，Enter 或「查询」按钮触发（后端 LIKE 模糊匹配） |
| 统一社会信用代码输入框 | `credit_code` | placeholder「统一社会信用代码」，Enter 或「查询」按钮触发（后端 LIKE 模糊匹配，自动大写化） |
| 分页条 | `page` / `size` | `pageable()`，integer 传参 |

**工具栏**：「查询」「+ 新建客户」（打开 2.3 创建表单）「批量导入」（打开 2.4 文件选择模态）。

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集，字段序与详情/表单一致：单号→名称→结算模式→缓冲参数）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 客户编码 | `customer_no` | `.b-link`，点击打开详情模态 |
| 客户名称 | `customer_name` | 文本 |
| 统一社会信用代码 | `credit_code` | `.mono`，空值 `dash()`（18 位，BR-06） |
| 结算模式 | `settle_mode` | 文本，空值 `dash()`（字典值：现售 / 寄售，见 BR-05） |
| 线边库存天数 | `line_stock_days` | 整数正文（默认 0）；表头带「?」徽标：悬停/点击展开字段释义条（客户线边缓冲天数 · 最低库存 A = 日需求 × max(0, 生产+物流 − 线边天数)，BR-03） |
| 调拨提前期 | `transfer_lead_days` | 整数正文，空值 `dash()`；表头带「?」徽标：悬停/点击展开字段释义条（调拨到客户仓所需天数 · 不设安全库存硬条件，BR-04） |
| 操作 | — | 【编辑】按钮（打开 2.3 编辑表单，锁定键字段） |

**交互**：任一过滤变化 → 重置回第 1 页重载；编辑保存成功后刷新当前页；空结果显示空态文案（不喷 toast）。表头「?」徽标：悬停即在列表上方显示字段释义条（`tip.show`），点击钉住（`tip.pin`，出现「✕ 收起」）；释义条出现会把表格下推，故隐藏时机取「鼠标移出整张卡片」（卡片 `@mouseleave` → `tipHide()`，钉住时不隐藏），避免悬停抖动。

### 2.2 详情模态（查全）—— 三段式：墨青头带 / KV 分组体 / 操作页脚

**用途**：点 `customer_no` 弹出，展示 `md_customer.get` 返回的**全部**业务字段（无状态机 → 头带无状态徽章）。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `customer_no` | 墨青头带（无状态字段，不设徽章） |
| 基本信息 | `customer_no` / `customer_name` / `credit_code` / `settle_mode` | `.kv`；`customer_no` 注明「单字段主键 · 全局唯一」（BR-01）；`credit_code` 空值 `dash()`、注明「18 位 · GB 32100-2015（含校验位）」（BR-06）；`settle_mode` 空值 `dash()`、注明「字典值：现售 / 寄售」（BR-05） |
| 线边缓冲参数 | `line_stock_days` / `transfer_lead_days` | `.kv`；`line_stock_days` 注明「客户线边已放置的缓冲库存天数（可用缓冲，缺省 0）· 最低库存 A = 日需求 × max(0, 生产+物流 − 线边天数)」（BR-03）；`transfer_lead_days` 注明「从我方仓调拨到客户仓/线边所需天数 · 不设安全库存硬条件：生产+物流 ≤ 线边+调拨提前期 → 高价值件速度对冲」（BR-04） |
| 原始数据 | get 返回全量 JSON | 底部折叠（默认收起） |

**页脚 `.modal-ft`**：【编辑】（打开 2.3 编辑表单）【关闭】。

### 2.3 创建 / 编辑表单（增/改）—— 模态表单

**用途**：覆盖 `md_customer.create` / `md_customer.update` 接受的**全部**业务参数（customer_no / customer_name / settle_mode / line_stock_days / transfer_lead_days）。

| 字段 | 控件 | 必填 | create 可见 | update 可见 | 约束来源 |
|---|---|---|---|---|---|
| `customer_no` | input，maxlength=50 | ★ 必填 | 是 | 否（只读展示） | BR-01 主键，创建后不可改 |
| `customer_name` | input，maxlength=100 | ★ 必填 | 是 | 是 | BR-02 |
| `settle_mode` | select（字典下拉：（未设置）/ 现售 / 寄售） | 选填 | 是 | 是 | BR-05 字典值：现售 / 寄售 |
| `credit_code` | input，maxlength=18，placeholder「18位统一社会信用代码」 | 选填 | 是 | 是 | BR-06 18 位 GB 32100-2015（后端校验长度/字符集/校验位） |
| `line_stock_days` | input number，非负整数；下方提示业务含义（客户线边缓冲天数，可抵减需我方兜底的最低库存） | 选填（默认 0） | 是 | 是 | BR-03 |
| `transfer_lead_days` | input number，非负整数；下方提示业务含义（从我方仓调拨到客户仓/线边所需天数，与线边天数共同决定高价值件可否速度对冲） | 选填 | 是 | 是 | BR-04 |

- create 模式：全部 5 字段可填写；`line_stock_days` 留空即后端取默认 0（BR-03 / US-01-AC4）。
- update 模式：`customer_no` 回填展示但只读不可修改（主键不可变）；`customer_name` / `credit_code` / `settle_mode` / `line_stock_days` / `transfer_lead_days` 可修改。
- 布局：必填先行、frow 语义分组——第一行（customer_no）、第二行（customer_name）、第三行（credit_code）、第四行（settle_mode）、第五行（line_stock_days + transfer_lead_days）；底部右对齐「取消」「保存」。
- 前端仅做必填校验（customer_no / customer_name 空值 → toast 警告、不提交）；主键唯一性、长度上限、非负整数校验由后端负责，`FdeError` 经 api.js 以错误 toast 呈现。
- `settle_mode` 字典已确认（现售 / 寄售，BR-05）：UI 用 `select` 下拉（空选项=未设置），后端 `_settle_mode` 校验非空值必须命中字典，DDL 带 CHECK 兜底；批量导入非法值按行报错。
- 提交成功：toast 成功消息（「客户主数据创建成功 / 更新成功」）→ 关闭模态 → 重置过滤重载列表。

### 2.4 批量导入（ERP 冗余同步）

**用途**：点击「批量导入」按钮，弹出文件上传模态，调 `md_customer.import_batch`。

- 提供模板下载链接（表头：customer_no, customer_name, credit_code, settle_mode, line_stock_days, transfer_lead_days）。
- 上传 Excel → 后端逐行校验 + upsert（已存在 customer_no → 更新，新行 → 新增）。
- 返回摘要：`{total, success, fail, errors: [{row, field, message}]}`；前端弹摘要（成功 N 条 / 失败 M 条 + 错误明细列表）。
- 导入完成后刷新列表。

## 3. svc 字面量清单（授权派生依据——必须字面量 svc("应用","服务")）

| 区块 | 调用（应用.服务） | 参数 | quiet | 说明 |
|---|---|---|---|---|
| 列表区 | `svc("md_customer","list")` | `{customer_no, customer_name, credit_code, page, size}` | — | 分页查询；空条件传 undefined 不带 |
| 详情模态 | `svc("md_customer","get")` | `{customer_no}` | — | 全字段详情 |
| 创建表单 | `svc("md_customer","create")` | `{customer_no, customer_name, credit_code, settle_mode, line_stock_days, transfer_lead_days}` | — | 新建客户主数据 |
| 编辑表单 | `svc("md_customer","update")` | `{customer_no, customer_name, credit_code, settle_mode, line_stock_days, transfer_lead_days}` | — | 更新（customer_no 只读，仅传有变更字段） |
| 批量导入 | `svc("md_customer","import_batch")` | `{rows: [...]}` | — | Excel 逐行校验 + upsert |

> 以上 5 处必须在 view.js 中以字面量逐项书写（可包在闭包里），**勿用变量拼名**——这是页面授权隐式放行派生扫描的唯一来源。

## 4. 数据来源与下拉

- **无跨应用主数据下拉**：`md_customer` 不主动外调任何应用；本应用是主数据源，被 sales_forecast / inventory_strategy / attainment 下游引用（弱引用，不在本页呈现）。
- `settle_mode` 字典下拉（现售 / 寄售）：后端 `_settle_mode` 枚举校验 + DDL CHECK 兜底；表单 select 空选项表示未设置（BR-05）。
- **契约 payload → 区块字段映射**：

| 契约 | 载荷字段 | 映射区块 |
|---|---|---|
| `md_customer.list` 返回项 | `customer_no, customer_name, credit_code, settle_mode, line_stock_days, transfer_lead_days` | 2.1 列表列（1:1） |
| `md_customer.get` 返回 | `customer_no, customer_name, credit_code, settle_mode, line_stock_days, transfer_lead_days` | 2.2 详情模态 KV 分组 + 原始数据折叠 |
| `md_customer.create` 入参 | `customer_no, customer_name, credit_code, settle_mode, line_stock_days, transfer_lead_days` | 2.3 创建表单 |
| `md_customer.update` 入参 | `customer_no, customer_name, credit_code, settle_mode, line_stock_days, transfer_lead_days` | 2.3 编辑表单（customer_no 只读） |
| `md_customer.import_batch` 入参 | `rows: [{customer_no, customer_name, credit_code, settle_mode, line_stock_days, transfer_lead_days}]` | 2.4 批量导入 |

## 5. 交互要点

1. **加载**：首载正常拉取 list（非看板页，失败走 api.js 统一通道）；列表重载期间显示加载态。
2. **过滤**：customer_no / customer_name / credit_code 输入后 Enter 或「查询」触发并重置 `page=1`；翻页仅改 `page/size`，不清过滤条件。credit_code 过滤由后端自动大写化后 LIKE 模糊匹配。
3. **微交互**：表格行 hover 高亮；customer_no `.b-link` hover 下划线；「保存」按钮提交期 loading 防重复点击。
4. **成功流**：create 成功 → 关闭模态并清空表单 → toast「客户主数据创建成功」→ 列表回第 1 页重载；update 成功 → 关闭模态 → toast「客户主数据更新成功」→ 刷新当前页。
5. **错误流**：重复主键 / 非负整数非法等后端 `FdeError` → toast 错误信息（如「该客户编码已存在」「线边库存天数必须为非负整数」），模态保持打开便于修改后重试。
6. **空态**：无任何客户时「暂无客户 —— 点『新建客户』创建」；过滤无命中时「无符合条件的客户」。
7. **批量导入**：文件选择后上传 → 导入过程 loading → 完成弹摘要（成功 N 条 / 失败 M 条 + 错误明细列表）→ 关闭后刷新列表。
8. **原始数据**折叠默认收起。
9. **展示工具**：`dash()`（credit_code / settle_mode / transfer_lead_days 空值）、无状态字段无需 `hue()`、无金额字段无需 `fmt()`、返回无时间字段无需 `fmtTime()`、无 `*_json` 字段无需 `tryParse()`。

## 6. 验收关注点（供第⑧步）

1. **路由渲染**：`#/md_customer` 挂载出列表三段式（过滤条 + 表格 + 分页条），**断言无 `.kpi`**（非看板页防挂载粘滞假过）；菜单「🏢 客户主数据」按 order=20 定位。
2. **造数后列表有数据**：REST 创建 C1001（现结 / line_stock_days=3 / transfer_lead_days=2）→ 列表 1 行，customer_no / customer_name / settle_mode / line_stock_days / transfer_lead_days 列齐全。
3. **过滤一一对应**：customer_no=C10 模糊匹配；customer_name=汽车 模糊匹配；组合条件；无匹配显示空态且不抛错（US-03-AC3）。
4. **模态全字段**：点 customer_no 开模态，断言 customer_no / customer_name / settle_mode / line_stock_days / transfer_lead_days 全部可见 + 「原始数据」可展开。
5. **表单落库**：create 表单填 customer_no / customer_name（★）+ 缓冲参数 → 提交 → 列表出现新记录；空 customer_no / customer_name 提交 → toast 警告且不发请求（US-01-AC3）；重复主键创建 → 后端 FdeError toast（US-01-AC2）；line_stock_days 留空 → 入库为 0（US-01-AC4）。
6. **update 回显**：编辑模态 customer_no 只读不可改；修改 line_stock_days 保存后列表和详情均反映新值（US-04-AC1）；transfer_lead_days 填 -1 → 后端 FdeError toast（US-04-AC3）。
7. **批量导入**：上传合法 Excel → 列表新增行；含冲突行 / 缺必填行 → 摘要正确展示成功/失败数与错误明细（US-05-AC2 / US-05-AC3）。
8. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP≥400（受限会话 403 属预期执法单独豁免）。
