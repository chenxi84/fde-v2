## §2 主业务链（happy path）

- **TC-MC-01 开启月度版本**
  - 步骤: `sales_forecast.open_version(version_no=V202608)`
  - 期望: 返回处理表行信息；`sales_forecast.list(version_no=V202608)` 返回 `total >= 1`（正常物料 × 历史采购客户 → 拆 N+1/N+2/N+3）
  - 调用链验证: open_version → `md_material.list(status=正常)` + `md_monthly_version.get` + `_load_sales_history`

- **TC-MC-02 填客户预测（N+1/N+2/N+3）**
  - 数据: C001 × M1 三个滚动月度
  - 步骤:
    1. `sales_forecast.fill_customer(version_no=V202608, material_no=M1, customer_no=C001, rolling_month=N+1, orig_qty=1000)`
    2. 同 N+2、N+3 各 orig_qty=1000
  - 期望: `sales_forecast.get(version_no=V202608, material_no=M1, customer_no=C001, rolling_month=N+1)` 返回 `orig_qty=1000`、`adj_qty=950`（= 1000 × (1−0.05)）
  - 调用链验证: fill_customer → `md_material.get` + `md_customer.get` 校验存在

- **TC-MC-03 基线计算（含断点追溯前置）**
  - 步骤: `sales_forecast.calc_baseline(version_no=V202608, material_no=M1, customer_no=C001, rolling_month=N+1)`
  - 期望: 返回处理表行，`base_method=移动平均`、`base_qty=None`（stub 历史为空）
  - 调用链验证: calc_baseline → `md_breakpoint.trace` + `md_material.get` + `_load_sales_history`

- **TC-MC-04 异常决策（基线未计算 → 取客户调整后值）**
  - 步骤: `sales_forecast.decide(version_no=V202608, material_no=M1, customer_no=C001, rolling_month=N+1)`
  - 期望: 返回 `abnormal_flag=false`、`final_qty=950`（base_event_qty=None → 取 adj_qty）；
    且 `bias` 与 `mape` **一并落库**（两者同源于 `attainment.get`，不得一有一无）
  - 调用链验证: decide → `attainment.get(customer_no=C001, material_no=M1)` 取 MAPE

- **TC-MC-05 物料预测汇总**
  - 步骤: `sales_forecast.summarize(version_no=V202608)`
  - 期望: 返回 `summary_rows >= 1`；`sales_forecast.get_summary(version_no=V202608, material_no=M1)` 返回 3 行（N+1/N+2/N+3），每行 `final_qty_sum=950`（汇总按物料×滚动月度逐行，非合计值）

- **TC-PRED-06 人工定稿优先（decide 不覆盖已定稿行）**
  - 步骤: `fill_customer(orig=800)` → `decide`（偏离 25% → `abnormal_flag=1`、`final_qty=None`） → `set_final(950)` → `decide_batch`
  - 期望: `decide_batch` 返回 `settled_skipped=1` 且 `settled_rows` 含该行；该行 `final_qty` 仍为 **950**（不被重算成 None）
  - 收尾: 复原 `fill_customer(orig=1000)`，后续用例按 final=950 断言

- **TC-MC-06 计算库存策略（三层水位）**
  - 步骤: `inventory_strategy.calc(version_no=V202608, material_no=M1, customer_no=C001)`
  - 期望: `inventory_strategy.get(version_no=V202608, material_no=M1)` 返回 `hedge_tool`、`min_level`、`safety_level`、`batch_level` 字段（stub 历史空 → 日需求=0 → 三层水位=0）
  - 调用链验证: calc → `md_material.get` + `md_customer.get` + `_load_sales_history`

- **TC-MC-07 取三层水位（供毛需求）**
  - 步骤: `inventory_strategy.get_water_level(version_no=V202608, material_no=M1)`
  - 期望: 返回含 `min_level`/`safety_level`/`batch_level` 字段

- **TC-MC-08 合成毛需求**
  - 前置: `inventory_strategy.calc_batch(V202608)`（水位取不到即报错，见 BR-02）；M2/M3/M4 建料时须给 `service_level/prod_days/logistics_days`，否则算不出水位
  - 步骤: `demand.build_gross(version_no=V202608)`
  - 期望: 返回 `material_count >= 1`；`demand.get(version_no=V202608, material_no=M1, rolling_month=N+1)` 返回 `gross_qty = 950 + 该物料水位`（`inventory_qty` 也等于该水位）
  - 调用链验证: build_gross → `sales_forecast.get_summary` + `inventory_strategy.get_water_level` + `md_part_replace.list` + `md_breakpoint.list`

- **TC-MC-09 发布毛需求（冻结）**
  - 步骤: `demand.publish(version_no=V202608)`
  - 期望: 返回 `message` 含"发布成功"；`md_monthly_version.get(version_no=V202608)` 返回 `lock_status=发布（锁定）`
  - 调用链验证: publish → `md_monthly_version.publish`

- **TC-MC-10 净需求运算（冻结版本）**
  - 步骤: `demand.calc_net(version_no=V202608)`
  - 期望: 返回 `row_count >= 1`；`demand.get(...)` 返回 `net_qty=950`（gross 950 + 未发 0 − 库存 0 − 在途 0）；`md_monthly_version.get(...)` 返回 `lock_status=冻结`
  - 调用链验证: calc_net → `md_monthly_version.freeze` + `_load_open_order`/`_load_inventory`/`_load_in_transit`

- **TC-MC-11 导入主计划（线下产能平衡结果导回）**
  - 步骤: `master_plan.import_plan(version_no=V202608, rows=[{material_no:M1, rolling_month:N+1, plan_qty:950, latest_inbound_date:2026-09-30}])`
  - 期望: 返回 `plan_version=1`、`success=1`；`master_plan.get_latest(version_no=V202608, material_no=M1)` 返回 `plan_qty=950`
  - 调用链验证: import_plan → `demand.export_net` 导出净需求

- **TC-MC-12 库存推移表逐日推演**
  - 前置: 该物料在「biz_date 推出的版本」下须已有水位策略——`refresh` 是 fail-closed 的（见 BR-12 / TC-ERR-40）
  - 步骤: `inventory_projection.refresh(material_no=M1, biz_date=2026-08-15, opening_stock=0)`
  - 期望: 返回推演结果；`inventory_projection.get(material_no=M1, biz_date=2026-08-15)` 返回 `balance` 字段
  - 调用链验证: refresh → `master_plan.get_latest` + `demand_pool.list` + `outbound_plan.list` + `inventory_strategy.get_water_level` + `_load_inventory`（起始库存适配器）
    （⚠ 2026-09-17 订正：原写 `_load_in_transit`/`_load_transfer_order` —— 前者已于 B-02 删除、后者全仓从未存在，见 §5 末）

- **TC-MC-13 预警扫描（对照水位线）**
  - 步骤: `inventory_projection.scan_alert(material_no=M1, version_no=V202608)`
  - 期望: 返回 alert 结果；`inventory_projection.list(material_no=M1)` 各日 `alert_type` 已回填。注：缺货判定为 `balance < 0`（stub 下 balance=0、水位 A=0，不击穿不触发补库；三类补库的确定性覆盖由 §TC-ERR-20~22 直接调 `demand_pool.create` 承担）
  - 调用链验证: scan_alert → `inventory_strategy.get_water_level`（`demand_pool.create` 触发依赖 balance<0，见 §6 Q2）

- **TC-MC-14 补库单下达生产（ERP 出向）**
  - 前置: 取 §TC-MC-13 或 §TC-ERR-24 生成的补库单号 `RP001`（缺货补库）
  - 步骤: `demand_pool.release(replenish_no=RP001, promised_inbound=2026-08-20)`
  - 期望: `demand_pool.get(replenish_no=RP001)` 返回 `status=已下达`
  - 回执模拟点: 出向 `_dispatch_to_erp` 走 stub，无需模拟

- **TC-MC-15 ERP 回传工单开工（异步回执模拟）**
  - 步骤: `demand_pool.on_workorder_started(replenish_no=RP001)`
  - 回执模拟: 主动调用 `on_workorder_started` 模拟 ERP 开工回执（成功路）
  - 期望: `demand_pool.get(replenish_no=RP001)` 返回 `status=生产中`

- **TC-MC-16 ERP 回传入库（异步回执模拟，终态）**
  - 步骤: `demand_pool.on_inbound(replenish_no=RP001)`
  - 回执模拟: 主动调用 `on_inbound` 模拟 ERP 入库回执（成功路）
  - 期望: `demand_pool.get(replenish_no=RP001)` 返回 `status=已完成`

- **TC-MC-17 策略拟合（预测拟合 + 库存拟合）**
  - 步骤: `strategy_fitting.run(material_no=M1, fit_version=FIT-202608)`
  - 期望: 返回拟合结果；`strategy_fitting.get(fit_version=FIT-202608, material_no=M1)` 返回 `status=待复核`
  - 调用链验证: run → `md_material.get` + `_load_sales_history`

- **TC-MC-18 拟合复核通过（回填物料主数据）**
  - 步骤: `strategy_fitting.approve(fit_version=FIT-202608, material_no=M1)`
  - 期望: 返回 `status=已生效`；`md_material.get(material_no=M1)` 的**预测侧**参数已回填（`base_method`/`base_params` 按拟合结果更新，带 `fit_version`）——
    ⚠ **`batch_window`/`service_level` 不被回填**（它们是主数据人工维护的，2026-09-17 口径）：断言复核前后二者不变，
    且 `strategy_fitting` 记录里的 `batch_window`/`fulfill_rate` == 主数据当前值（**镜像**）
  - 调用链验证: approve → `md_material.set_fit_params`

## §3 分支 / 异常用例

  - 期望: 抛 `FdeError` 含『原』『新』或『相同』

> 已统一为「派生量 / 中间量 二者皆认」，并把这条写进两个脚本的文件头。

> **`disabled` 那条值得单记**：它是「规则写对了、但没人验过」的活例 ——
> 停用标记不参与追溯，是断点台账唯一的软删除语义；此前一条断言都没有。
