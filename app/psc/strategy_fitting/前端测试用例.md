# 应用组 `psc` · 策略拟合 前端测试用例（滚动回测拟合最优方法参数）

> 产出技能：前端测试用例生成（第⑧步，规格 design-plus/前端测试.md）。
> 页面：`psc:strategy_fitting`（本文件全部用例针对本页，条目内「页面」要素省写）。输入：本应用前端详设（app/psc/strategy_fitting/前端详设.md）+ app/psc/_contracts.md。
> 执行：第⑨步翻译成 app/psc/tests/verify_view_psc_strategy_fitting.py（自包含：dbguard 隔离 → 起平台 → 登录 → 造数 → 断言 → 0 报错）。
> 数据来源类型：手工参考创建（run / run_batch 发起拟合 + approve / reject / rollback 状态机）；契约无 update / set_* / import_batch / delete → 无编辑入口、无删除按钮。

## §1 本页渲染（防粘滞）

- **VT-ROUTE-01 路由渲染 + 三段式挂载**
  - 前置造数：无（渲染断言先于造数）。
  - 操作：登录 admin → `location.hash = '#/strategy_fitting'`（或 GET /view/psc/ 后进路由），必要时 `pg.reload()`（注册表 mtime 缓存，#6）。
  - 断言：`main .card` 数 > 0；**非看板页 `.kpi` 数 == 0**（防看板挂载粘滞，pitfalls #2）；列表三段式存在——过滤条（状态 chips「全部/待复核/已生效/已否决」+ 物料号输入框 + 版本输入框 + 异常标记下拉 +「＋ 发起拟合」「批量拟合」按钮）+ 表格 `.tbl.tight` + 分页条（含「共 N 条」）。
  - 选择器注意：`.kpi` 计数用页面全局 `pg.locator(".kpi")`，不做 scope 限定。

## §2 造数后列表有数据

- **VT-LIST-01 列表含所造单号（三态全显）**
  - 前置造数：§0 全部（M1/M2 + SF1…SF7）。
  - 操作：进入 `#/strategy_fitting`（或 `pg.reload()` 重载列表）。
  - 断言：列表行数 == 7（分页条「共 7 条」）；SF1 行含 `material_no=M1`、`fit_version=202608`、`pred_method`=Auto*（真实方法，含「Auto」）、`status=待复核`（hue 徽章）；SF2 行含 `M1`+`202607`+`已生效`；SF3 行含 `M1`+`202606`+`已否决`；pred_method / status 徽章文本取可见元素（`:visible`）。
  - 选择器注意：精确单号定位用 `has_text`（不假设顺序，pitfalls #17）；徽章读文本而非类名。

- **VT-LIST-02 状态下拉（chips）筛选收敛**
  - 前置造数：§0（沿用 SF1/SF2/SF3）。
  - 操作：点状态 chip「待复核」→ 断言结果仅待复核行（含 SF1 M1@202608，不含已生效/已否决行）；再点「已生效」→ 含 SF2 M1@202607；再点「已否决」→ 含 SF3 M1@202606。
  - 断言：每次 chip 点击后可见数据行集合只含对应 status 徽章文本，无其他状态行混入。
  - 选择器注意：chips 用 `:visible` 点击；行状态徽章读 `.tbl.tight tr.data` 内文本。

- **VT-LIST-03 物料号模糊 + 版本精确 + 异常标记 AND + 空态**
  - 前置造数：§0（沿用）。
  - 操作：物料号输入框填 `M1`（模糊 LIKE）→ 断言仅 M1 行（不含 M2 行）；叠加版本输入框填 `202608`（精确）→ 断言仅 SF1 行；异常标记下拉选「正常」→ 仍含 SF1；清空版本改填 `209999` → 断言空态文案「无匹配数据」且不抛错。
  - 断言：模糊/精确/布尔 AND 组合结果收敛；空结果显示空态文案、无 console error。
  - 选择器注意：异常标记为 `<select>`（非 chips），用 `select_option`；输入框触发用回车或点「搜索」按钮。

## §3 模态全字段

- **VT-MODAL-01 详情模态全字段 + 待复核页脚按钮**
  - 前置造数：§0（SF1 待复核为目标）。
  - 操作：点 SF1 行 `material_no`（`.b-link mono`）→ `wait_modal()`（轮询 `.modal-mask:visible .loadbox` 消失，pitfalls #16）。
  - 断言：`.modal-bd").first` 含字段标签全集——物料号 / 拟合版本 / 物料名称 / 预测方法 / 预测误差（sMAPE）/ 预测参数（pred_params）/ 服务系数 / 安全水位 / 组批窗口 / 满足率 / 库存天数 / 切线次数 / 异常标记 / 状态；且值逐一命中：`M1`、`202608`、`移动平均物料A`、pred_method=Auto*（含「Auto」）、pred_params tryParse 结构化展开含 `season_length`→`12`、`1.65`、`28`、`95%`、`正常`（异常标记徽章）、`待复核`（状态徽章）；「原始数据」`details` 可展开；页脚 `.modal-ft` 含「复核通过」「否决」、不含「回滚」（待复核态）。
  - 选择器注意：多 `.modal-bd` 用 `.first`（pitfalls #15）；pred_params 结构化表格在 `.modal-bd.first` 内定位 key/value 行。

- **VT-MODAL-02 已否决模态页脚无动作按钮（终态 x-show）**
  - 前置造数：§0（SF3 已否决为目标）。
  - 操作：点 SF3 行 `material_no` → `wait_modal()`。
  - 断言：`.modal-bd.first` 含 `M1`+`202606`；状态徽章文本 == 已否决；页脚 `.modal-ft` 含「已否决 · 终态，无可用操作」文案，且无可见的「复核通过/否决/回滚」按钮。
  - 选择器注意：按钮可见性用 `:visible` 限定（x-show 隐藏 ≠ 不存在，pitfalls #14）。

- **VT-MODAL-03 拟合过程候选排名表 + 逐月曲线（detail_json）**
  - 前置造数：§0（SF1 = M1@202609，≥12 期历史，run 后含 detail_json）。
  - 操作：点 SF1 行 `material_no` → `wait_modal()` → 滚动到「下月预测」/「拟合过程」区块。
  - 断言：「下月预测」区块含 `pred_qty`（点预测）；「拟合过程」候选排名表有 ≥1 行（AutoTheta/AutoARIMA/AutoETS 或 Croston/TSB），首行含「★ 推荐」；每行含 method 徽章 + MASE + sMAPE 两列；`#fitChart` 容器存在且 echarts 曲线渲染（0 console error）；点非首行候选 → 选中行高亮、曲线切换。
  - 选择器注意：`#fitChart` 在模态内 `.modal-bd.first`；echarts 渲染需 `window.echarts` 就绪（shell 已加载）；旧记录（无 detail_json）显示「无拟合过程数据」空态。

## §4 表单落库回显 + 状态机操作（按 status x-show）

- **VT-FORM-01 发起拟合（run）表单落库回显**
  - 前置造数：§0（M1 供 autocomplete）。
  - 操作：点「＋ 发起拟合」→ 表单模态内物料号内联 autocomplete 输入 `M1` → 选中选项 `M1 / 移动平均物料A` → 填 fit_version `202609` → 点「发起拟合」提交。
  - 断言：toast 含「已发起拟合 · M1 · 202609」；模态关闭；列表回显新行 M1@202609 且 status=待复核（`has_text` 精确定位）。
  - 选择器注意：主数据选择为内联 autocomplete（非 `<select>`，主数据引用铁律），`:visible` 限定展开面板；选中后表单存代号 M1。

- **VT-FORM-02 发起拟合必填/非法版本校验（不发请求）**
  - 前置造数：§0。
  - 操作：点「＋ 发起拟合」→ 不选物料直接提交 → 断言 toast「请选择物料号」（不发请求）；选 M1 后填非 6 位版本 `2026` → 断言 toast「拟合版本格式必须为 YYYYMM」（前端 warn）；填 6 位但非法月份 `202613` → 断言后端 FdeError toast「拟合版本格式必须为 YYYYMM」（api.js 统一呈现），列表不新增该记录。
  - 断言：三类非法输入各触发对应 toast，且均不产生新记录（列表仍为原记录集）。
  - 选择器注意：toast 断言读 `.toast` 可见文本；`202613` 走后端校验（前端正则只查 6 位数字）。

- **VT-FORM-03 批量拟合（run_batch）摘要 toast + 落表**
  - 前置造数：§0（M1、M2 两个「正常」状态物料）。
  - 操作：点「批量拟合」→ 填 fit_version `202610` → 提交。
  - 断言：toast 含「批量拟合完成 · 共 2 · 成功 2 · 失败 0」；模态关闭；列表重载出现 M1@202610 与 M2@202610 且 status=待复核。
  - 选择器注意：摘要数字来自 run_batch 返回 `{total, success, failed}`，断言 toast 文案前缀「批量拟合完成」。

- **VT-ACT-01 待复核 → approve 已生效（行内复核通过）**
  - 前置造数：§0（SF4 = M2@202608 待复核）。
  - 操作：定位 SF4 行（`has_text` M2 + 202608）→ 点行内「复核通过」（`:visible`）。
  - 断言：toast 含「已复核通过 · M2 · 202608」；该行 status 徽章变「已生效」；行内按钮切换为「回滚」（x-show 切换，待复核的「复核通过/否决」消失）。
  - 选择器注意：行内按钮限定在该行的 `.rowact` 内、`:visible` 限定（x-show 隐藏按钮仍在 DOM，#14）。

- **VT-ACT-02 待复核 → reject 已否决（行内否决）**
  - 前置造数：§0（SF5 = M2@202607 待复核）。
  - 操作：定位 SF5 行 → 点行内「否决」。
  - 断言：toast 含「已否决 · M2 · 202607」；该行 status 徽章变「已否决」；行内无可见操作按钮（终态）。
  - 选择器注意：同上，行内 scope + `:visible`。

- **VT-ACT-03 已生效 → rollback 已否决（回滚，回填上一版参数）**
  - 前置造数：§0（SF6 = M2@202606 已生效；SF7 = M2@202605 已生效为上一版，保证 rollback 有上一版可回填）。
  - 操作：定位 SF6 行 → 点行内「回滚」。
  - 断言：toast 含「已回滚 · M2 · 202606」；该行 status 徽章变「已否决」；行内无可见操作按钮；回填上一版参数为后端 `md_material.set_fit_params` 跨应用调用（前端不直接断言）。
  - 选择器注意：rollback 要求存在更低 fit_version 的「已生效」记录（后端「无上一版参数可回滚」FdeError），§0 已铺 SF7 满足前置。

- **VT-ACT-04 已否决终态无按钮（行内 x-show 收敛）**
  - 前置造数：§0（SF3 = M1@202606 已否决）。
  - 操作：定位 SF3 行（M1 + 202606）。
  - 断言：该行操作列无任何可见的「复核通过/否决/回滚」按钮；status 徽章 == 已否决。
  - 选择器注意：`:visible` 限定（隐藏按钮 ≠ 不存在，#14）。
