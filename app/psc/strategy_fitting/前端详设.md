# 策略拟合 前端详设
> 来源：app/psc/_contracts.md（冻结契约）+ app/psc/strategy_fitting/应用详设.md；产出供第⑦步前端编码 / 第⑧步前端测试用例
> 落位：`app/psc/strategy_fitting/view.js` + `app/psc/strategy_fitting/view.html`（与 `strategy_fitting.py` 同文件夹，落盘即进启动清单与授权清单，零接线）；import 一律绝对路径 `/view/lib/*`；模板经 `new URL("view.html", import.meta.url)` 抓取；工厂 `export default function pageStrategyFitting()`（保留专名）

## 1. 页面元数据 PAGE_META

| 字段 | 值 | 说明 |
|---|---|---|
| key | `strategy_fitting` | = 应用文件夹名，page_id 为 `psc:strategy_fitting` |
| name | 策略拟合 | 侧栏菜单名 |
| ic | 🎯 | 菜单图标字 |
| title | 策略拟合 | 主区页面头 |
| crumb | 滚动回测拟合最优方法参数 · 待复核→已生效/已否决 | 头部副题 |
| order | 90 | 已按业务序预分配，直接用；升序即菜单序（策略拟合置于销售预测前） |

- 页面零鉴权：无任何权限判断；菜单按页面授权渲染在 shell，数据范围由后端闸门执法，401 由 api.js 自动跳登录。
- **数据来源类型 = 手工参考创建**：数据引用上游结果（历史干净需求来自 ERP `_load_sales_history`、参数来自 `md_material`），但由用户**手工决定**何时基于哪些上游数据创建——前端保留「发起拟合 run」/「批量拟合 run_batch」入口，并明确标注上游数据来源（历史干净需求 ERP / 物料当前参数 md_material）。
- 本应用契约**无 update / set_* / import_batch / delete** → 无编辑入口、无删除按钮；单据变更仅经状态机动作（approve / reject / rollback）与创建（run / run_batch）。

## 2. 区块构成

### 2.1 列表区（查）—— 三段式：过滤条 / 表格 / 分页条

**用途**：拟合结果台账，按物料号 / 拟合版本 / 状态 / 异常标记筛选，承载行内状态流转动作。

**过滤控件（与 `strategy_fitting.list(material_no, fit_version, status, abnormal_flag, page, size)` 可过滤参数一一对应；契约无 keyword 参数 → 不设关键字搜索框，禁止前端假过滤）**：

| 控件 | 对应参数 | 选项 |
|---|---|---|
| 物料号输入框 | `material_no` | 文本输入框，**模糊匹配（LIKE）**——契约签名标注「按物料号（模糊）筛选」，属关键字搜索而非主数据选择，故用自由文本输入（主数据 autocomplete 仅在发起拟合表单用，见 §2.3.1 / §4） |
| 拟合版本输入框 | `fit_version` | 文本输入框，精确匹配，格式 YYYYMM（6 位数字） |
| 状态下拉 | `status` | 全部 / 待复核 / 已生效 / 已否决（后端 `VALID_STATUSES` 枚举，原值传参） |
| 异常标记下拉 | `abnormal_flag` | 全部（不传）/ 异常（true）/ 正常（false）；布尔参数 |
| 分页 | `page` / `size` | `pageable()` 分页条（契约签名 string 型，照传即可） |

> **跳转预填**：销售预测页「查看策略拟合」经 `sessionStorage["fde.fit.material"]` 跳入本页，`init()` 读取（读取即清）预填 `fMaterial` 过滤——落地定位到该物料、列表按 `fit_version DESC` 最新一版在最上，点开即现有详情模态。纯前端、无后端服务。

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集；字段序与详情一致）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 物料号 | `material_no` | `.b-link`，点击开详情模态；matMap 命中时附物料名小字 |
| 拟合版本 | `fit_version` | 正文 |
| 预测方法 | `pred_method` | `hue()` 徽章（statsforecast 方法：AutoTheta/AutoARIMA/AutoETS/SeasonalNaive/CrostonOptimized/TSB），空值 `dash()` |
| 预测误差 | `smape` | `fmt()` 百分比（0.152 → 15.2%），空值 `dash()` |
| 服务系数 | `service_factor` | 正文，空值 `dash()` |
| 安全水位 | `safety_level` | 正文，空值 `dash()` |
| 组批窗口 | `batch_window` | 正文（天存储，28 = 4 周），空值 `dash()` |
| 满足率 | `fulfill_rate` | `fmt()` 百分比（0.95 → 95%），空值 `dash()` |
| 库存天数 | `inv_days` | 正文，空值 `dash()` |
| 切线次数 | `changeover_cnt` | 正文（整数），空值 `dash()` |
| 异常标记 | `abnormal_flag` | `hue()` 徽章（true=⚠ 异常 / false=正常）；空/无 `dash()` |
| 状态 | `status` | `hue()` 徽章（三色：待复核=橙 / 已生效=绿 / 已否决=灰） |
| 操作 | — | 按 `status` 的行内动作，`x-show`（见 §5.1） |

**交互**：任一过滤变化 → 重置回第 1 页重载；状态动作成功后刷新当前页；空结果显示空态文案（不喷 toast）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 状态徽章 / KV 分组体 / 状态操作页脚

**用途**：点 `material_no` 弹出，展示 `strategy_fitting.get(fit_version, material_no)` 返回的**全部**业务字段。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `material_no` + `fit_version` + `status` 徽章 | 墨青头带，徽章 `hue()`；异常记录附 ⚠ 徽章 |
| 标识信息 | `material_no` / `fit_version` | `.kv`；注明「复合主键 · 拟合版本+物料号全局唯一」（BR-01）；`material_no` 注明「弱引用物料主数据，来源 md_material」（BR-17） |
| 预测拟合结果 | `pred_method` / `pred_params` / `smape` | `.kv`；`pred_method` `hue()` 徽章（statsforecast 方法）；`pred_params` **`tryParse()` 结构化展示**（JSON 如 `{"season_length":12}` 展开为可读键值）；`smape` `fmt()` 百分比（参考） |
| 库存拟合结果 | `service_factor` / `safety_level` / `batch_window` | `.kv`；注明「约束优化选成本最小」（BR-11）；`batch_window` 天存储（28 = 4 周） |
| 回测指标 | `fulfill_rate` / `inv_days` / `changeover_cnt` | `.kv`；`fulfill_rate` `fmt()` 百分比，注明「满足率 = 1 − 缺货量/总需求」（BR-10）；`inv_days` 库存天数；`changeover_cnt` 切线次数 |
| 下月预测 | `pred_qty` / `pred_lo` / `pred_hi` / `mase` | `.kv`；`pred_qty` 点预测、`pred_lo ~ pred_hi` 80% 区间、`mase` 选型误差（越小越准，>1 不可预测） |
| 拟合过程 | `detail_json` | 解析 `candidates` 列表 → 候选排名表（method / mase / smape，按 mase 升序，行首标 ★ 推荐，mase>1 标「不可预测」）+ echarts 逐月曲线（选中候选，实线=实际 / 虚线=预测）；`detail_json` 为空（旧记录）显示「无拟合过程数据」 |
| 复核状态 | `abnormal_flag` / `status` | `.kv`；`abnormal_flag=true` 时红字提示「数据不足或 MASE ≥ 1（不可预测），复核通过须二次确认」（BR-14）；`status` `hue()` 徽章 |
| 原始数据 | get 返回全量 JSON | 底部折叠 |

**交互**：页脚 `.modal-ft` 按当前状态放状态机按钮（逻辑同 §5.1，与行内动作共用一处 `x-show` 判定）；动作成功后用返回对象原地刷新模态字段 + 列表行。本应用无审计时间字段（表无 created_at/updated_at），详情以「原始数据」折叠兜底。

### 2.3 创建 / 编辑表单（增）—— 两个发起拟合入口，均无编辑入口

**用途**：本应用数据来源类型为「手工参考创建」，保留两个创建入口；**无 update / set_* 服务 → 无编辑入口**。写服务仅 `run` / `run_batch`（发起拟合），二者接受的参数即全部可写业务参数；其余字段（pred_method/pred_params/smape/service_factor/safety_level/batch_window/fulfill_rate/inv_days/changeover_cnt/abnormal_flag/status）均为后端拟合计算落表，**不进表单**。

#### 2.3.1 发起拟合（单物料 run）—— 模态表单

**用途**：覆盖 `strategy_fitting.run(material_no, fit_version)` 接受的**全部**可写业务参数。表单顶部标注上游数据来源：「历史干净需求（ERP `_load_sales_history`，断点前后拼接、剔除一次性脉冲）/ 物料当前参数（`md_material`）」。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `material_no` | 内联 autocomplete（物料下拉，见 §4） | ★ 必填 | BR-17 主数据引用铁律：来源 md_material，禁止手工录入；后端经 `md_material.get` 校验存在，不存在由后端 FdeError toast（US-01-AC3） |
| `fit_version` | input，格式 `YYYYMM`（6 位数字） | ★ 必填 | BR-01；后端 `_clean_fit_version` 正则 `\d{6}` + 月份 1~12 校验，非法由后端 FdeError toast |

- **不进表单**：`pred_method` / `pred_params` / `smape` / `service_factor` / `safety_level` / `batch_window` / `fulfill_rate` / `inv_days` / `changeover_cnt`（拟合自动计算）、`abnormal_flag`（系统标记）、`status`（初始恒「待复核」）——全部只在详情展示。
- 布局：必填先行、frow 语义分组、底部右对齐提交按钮；校验 = 必填红星 + toast 警告（material_no / fit_version 为空不发请求）。
- 提交成功：toast 带出 `material_no` + `fit_version` → 关闭模态 → 重置过滤重载列表（新记录恒「待复核」）。

#### 2.3.2 批量拟合（整批 run_batch）—— 模态表单

**用途**：覆盖 `strategy_fitting.run_batch(fit_version)` 接受的**全部**可写业务参数（对全部正常状态物料逐物料拟合，幂等——同版本已有结果物料跳过/覆盖）。同样标注上游数据来源。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `fit_version` | input，格式 `YYYYMM`（6 位数字） | ★ 必填 | BR-01；后端同 run 的 `_clean_fit_version` 校验 |

- **不进表单**：无 `material_no`（run_batch 对 `md_material.list(status="正常")` 全量物料拟合，非单物料选择）。
- 提交成功：toast 展示返回摘要（`total` / `success` / `failed` / `errors`）→ 关闭模态 → 重载列表（拟合结果陆续落表，均为「待复核」）。

## 3. svc 字面量清单（授权派生依据——必须字面量 svc("应用","服务")）

| 区块 | 调用（应用.服务） | 参数 | quiet | 说明 |
|---|---|---|---|---|
| 列表区 | `svc("strategy_fitting","list")` | `{material_no, fit_version, status, abnormal_flag, page, size}` | — | 过滤查询；AND 关系；空条件传 undefined 不带 |
| 详情模态 | `svc("strategy_fitting","get")` | `{fit_version, material_no}` | — | 全字段详情 |
| 发起拟合表单 | `svc("strategy_fitting","run")` | `{material_no, fit_version}` | — | 单物料拟合；返回含全字段结果对象（含 detail_json/mase/pred_qty/pred_lo/pred_hi） |
| 批量拟合表单 | `svc("strategy_fitting","run_batch")` | `{fit_version}` | — | 整批拟合；返回 `{fit_version,total,success,failed,errors}` 摘要 |
| 行内 / 模态页脚 | `svc("strategy_fitting","approve")` | `{fit_version, material_no, confirm}` | — | 待复核 → 已生效；异常记录 `confirm:true` 二次确认 |
| 行内 / 模态页脚 | `svc("strategy_fitting","reject")` | `{fit_version, material_no}` | — | 待复核 → 已否决 |
| 行内 / 模态页脚 | `svc("strategy_fitting","rollback")` | `{fit_version, material_no}` | — | 已生效 → 已否决（回填上一版参数） |
| 发起拟合表单 | `svc("md_material","list")` | `{page:1, page_size:200}` | true | 物料 autocomplete 数据源，quiet 探测；**跨应用调用，字面量产生 psc:strategy_fitting → md_material.list 派生边** |

> 以上 8 处必须在 view.js 中以字面量逐项书写（可包在闭包里），**勿用变量拼名**——这是页面授权隐式放行派生扫描的唯一来源。`md_material.get` / `md_material.set_fit_params` 由后端 run/approve/rollback 内部跨应用调用，**前端不调用，不进 svc 清单**。

## 4. 数据来源与下拉

**物料 autocomplete（发起拟合表单用，构建 matOptions / matMap）**：
- 页面初始化一次性 `svc("md_material","list")` `{page:1, page_size:200}`，`quiet:true` 探测：失败不喷 toast；零值兜底 → 发起拟合表单物料下拉显示「暂无可选物料」禁用项（提交时再 toast 提示）。
- 由返回项构建 `matMap = {material_no: material_name}`，供列表「物料号」列与详情模态名称回显；未命中则原样展示 material_no。
- md_material 列表项字段以 md_material 契约为准，本页仅用 `material_no` / `material_name`（status / unit_value 等不展示）。
- **主数据选择控件实现要点（主数据引用铁律）**：发起拟合表单的 `material_no` 必须用内联 autocomplete（点击输入框弹出匹配列表、输入关键字过滤、选中回填代号），**禁止**普通 `<select>`；为每个主数据源单独声明扁平数组 `matOptions`（禁止嵌套对象 `autoOptions[field]`）；`@click.stop` 展开 + `@input` 实时过滤（同时匹配代号和名称）+ `@click.away` 关闭；列表项双行「代号 + 名称」，选中后表单存代号。
- 列表过滤条的 `material_no` 为**模糊关键字搜索**（契约 LIKE），用自由文本输入框，非主数据选择——二者不可混用。

**契约 payload → 区块字段映射**：

| 来源 | payload 字段 | 去向 |
|---|---|---|
| `strategy_fitting.list` 项 | material_no, fit_version, pred_method, pred_params, smape, service_factor, safety_level, batch_window, fulfill_rate, inv_days, changeover_cnt, abnormal_flag, status | 列表区表格列（1:1，pred_params 不在列表展示） |
| `strategy_fitting.get` | 同上（全量） | 详情模态全部 KV 分组 + 原始数据折叠 |
| `strategy_fitting.run` 返回 | 结果对象（status=待复核，全字段已填） | toast 展示 material_no+fit_version → 列表重载 |
| `strategy_fitting.run_batch` 返回 | `{fit_version, total, success, failed, errors}` | toast 展示摘要 → 列表重载 |
| `strategy_fitting.approve / reject / rollback` 返回 | 结果对象（新 status） | 原地更新已开模态 + 列表行 |
| `md_material.list` 项 | material_no, material_name | 物料 autocomplete 选项 + matMap |

- `pred_params` 为 JSON 字符串快照字段，详情模态 `tryParse()` 结构化展示；列表不展示（列字段子集约束）。
- `smape` / `fulfill_rate` 为小数（0.152 / 0.95），前端 `fmt()` 格式化为百分比；空值 `dash()`。
- `batch_window` 天存储（28 = 4 周），展示天数即可；`changeover_cnt` 整数。
- 本应用**无审计时间字段**（表无 created_at/updated_at），无需 `fmtTime()`；无金额字段，无需 `fmt()` 货币。

## 5. 交互要点

1. **按状态的行内动作（状态机，行操作列与模态页脚共用判定）**：
   - `status=待复核` → 【复核通过 approve】【否决 reject】；
   - `status=已生效` → 【回滚 rollback】；
   - `status=已否决` → 终态，无任何按钮（BR-16）。
   - 动作成功：toast + 刷新列表；非法流转（如对已生效再 approve、对已否决再 approve）由后端 FdeError 经 api.js 统一 toast，页面不硬编状态机校验。
2. **异常记录二次确认（BR-14）**：`abnormal_flag=true` 且点击【复核通过】时，先弹出二次确认（「该物料拟合异常（数据不足或 MASE≥1 不可预测），确认仍生效？」），确认后才以 `confirm:true` 调 `approve`；未确认不发请求。`abnormal_flag=false` 时 `confirm:false` 直接通过。
3. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 状态徽章 + 异常 ⚠ 徽章。
4. **`pred_params` JSON 结构化**：详情模态 `tryParse()` 展开为可读键值（如 alpha=0.3 / trend=false）；解析失败原样展示字符串。
5. **quiet 探测性加载**：`md_material.list` 下拉 quiet + 零值兜底，失败不喷 toast；拟合结果列表本身正常加载，错误走 api.js 统一通道。
6. **两个发起入口**：工具栏【发起拟合】（run，选物料+版本）/【批量拟合】（run_batch，仅版本）；均在表单内标注上游数据来源（ERP 历史干净需求 / md_material 参数）。
7. **展示工具**：`hue()`（pred_method statsforecast 方法 / status 三色 / abnormal_flag 徽章）、`dash()`（空值字段）、`fmt()`（mase / smape / fulfill_rate 百分比）、`tryParse()`（pred_params JSON）；本页无时间字段（无需 `fmtTime()`）、无金额字段。
8. **toast**：run / run_batch 成功 / 状态流转成功 / 必填未填警告；其余错误一律由 api.js 统一呈现。

## 6. 验收关注点（供第⑧步前端测试用例）

1. **路由渲染**：`#/strategy_fitting` 挂载出列表三段式（过滤条 + 表格 + 分页条），**页面无 `.kpi`**（防看板挂载粘滞假过）；菜单「🎯 策略拟合」按 order=90 定位。
2. **造数后列表有数据**：先造 md_material（M001 正常状态）→ 经 `run` 造多条拟合结果（覆盖 待复核/已生效/已否决 三态，含异常记录）→ 列表行数正确，material_no / fit_version / pred_method / status 列非空。
3. **过滤一一对应**：status=待复核 下拉仅待复核行；material_no 输入框模糊匹配（如输入「M00」命中含 M00 的行）；fit_version 精确匹配；abnormal_flag=异常 仅异常行；多条件 AND 组合；无匹配显示空态且不抛错。
4. **模态全字段**：点 material_no 开模态，断言 material_no / fit_version / pred_method / pred_params（tryParse 结构化）/ smape / service_factor / safety_level / batch_window / fulfill_rate / inv_days / changeover_cnt / abnormal_flag / status 全部可见 + 「原始数据」可展开；已否决记录的模态页脚无动作按钮。
5. **表单落库**：发起拟合表单选 material_no（autocomplete）+ 填 fit_version（YYYYMM）→ 提交 → 列表出现新记录且 status=待复核；空 material_no / 非法 fit_version（如 202613）→ 前端必填警告 / 后端 FdeError toast（不发请求）。
6. **批量拟合**：批量拟合表单填 fit_version → 提交 → toast 展示 total/success/failed 摘要 → 列表重载（多物料「待复核」记录落表）。
