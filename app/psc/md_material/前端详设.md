# 物料主数据 前端详设
> 来源：app/psc/_contracts.md（冻结契约）+ app/psc/md_material/应用详设.md；产出供第⑦步前端编码 / 第⑧步前端测试用例
> 落位：`app/psc/md_material/view.js` + `view.html`（与 `md_material.py` 同文件夹，落盘即进启动清单与授权清单，零接线）；import 一律绝对路径 `/view/lib/*`；模板经 `new URL("view.html", import.meta.url)` 抓取；工厂 `export default function pageMdMaterial()`

## 1. 页面元数据 PAGE_META

| 字段 | 值 | 说明 |
|---|---|---|
| key | `md_material` | = 应用文件夹名，page_id 为 `psc:md_material` |
| name | 物料主数据 | 侧栏菜单名 |
| ic | ⚙ | 菜单图标字 |
| title | 物料主数据 | 主区页面头 |
| crumb | 主数据 · 物料属性/预测方法/库存参数 | 头部副题 |
| order | 30 | 已按业务序预分配，直接用；升序即菜单序 |

- 页面零鉴权：无任何权限判断；菜单按页面授权渲染在 shell，数据范围（PERM 主数据管理员可增改导、计划员只读）由后端闸门执法，401 由 api.js 自动跳登录。
- 本应用契约**无 delete** → 无删除按钮；物料主数据被全链 11 个聚合引用，V1 只增改不删（应用详设 §1.3.2）。
- 本应用**提供 `set_fit_params` 服务但前端不调用**——被 `strategy_fitting.approve` 跨应用回填拟合参数（出向被调），不进本页 svc 字面量清单。

## 2. 区块构成

### 2.1 列表区（查）—— 三段式：工具栏 / 表格 / 分页条

**用途**：物料主数据台账，承载新建 / 编辑 / 批量导入入口，按物料号/名称/状态筛选。本页为非看板页，不设 KPI 指标带（验收断言无 `.kpi`）。

**过滤控件（与 `md_material.list(material_no, material_name, status, page, size)` 可过滤参数一一对应；契约无 keyword 参数 → 不设关键字搜索框，禁止前端假过滤）**：

| 控件 | 对应参数 | 形态 |
|---|---|---|
| 物料号输入框 | `material_no` | placeholder「物料号」，Enter 或「查询」触发（后端 LIKE 模糊匹配，US-03-AC1） |
| 物料名称输入框 | `material_name` | placeholder「物料名称」，Enter 或「查询」触发（后端 LIKE 模糊匹配，US-03-AC3） |
| 状态 chips | `status` | 全部 / 正常 / EOP / 停用，单选互斥，点击即查（精确匹配，BR-04 枚举，原值传参；US-03-AC2） |
| 分页条 | `page` / `size` | `pageable()`，integer 传参（契约签名 integer 型，照传） |

**工具栏**：「查询」「+ 新建物料」（打开 2.3 创建模态）「批量导入」（打开 2.4 导入模态）。

**表格列（`.tbl.tight` + `.scroll-x`；全部为 `list` 返回项字段，且为详情字段子集；字段序与详情一致）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 物料号 | `material_no` | `.b-link`，点击打开详情模态 |
| 物料名称 | `material_name` | 文本，单行省略 |
| 状态 | `status` | `hue()` 徽章（正常=绿 / EOP=橙 / 停用=灰） |
| 价值分类 | `value_class` | `hue()` 徽章（高/低 双色），空值 `dash()` |
| 变更风险 | `change_risk` | `hue()` 徽章（高/低 双色），空值 `dash()` |
| 基线方法 | `base_method` | 文本，空值 `dash()` |
| 操作 | — | 【编辑】按钮（开编辑表单，主数据管理员可见） |

**交互**：任一过滤变化 → 重置回第 1 页重载；编辑/导入成功后刷新当前页；空结果显示空态文案（不喷 toast）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 状态徽章 / KV 分组体 / 操作页脚

**用途**：点 `material_no` 弹出，展示 `md_material.get` 返回的**全部**业务字段（15 项，含 fit_version / fit_effective_at 快照）。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `material_no` + `status` 徽章 | 墨青头带，徽章 `hue()` |
| 基本信息 | `material_no` / `material_name` / `status` | `.kv`；`material_no` 注明「全局唯一主键 · 创建后不可变更」（BR-19）；`status` 注明「外部维护 · 本系统只读」（BR-04） |
| 库存策略参数 | `unit_value` / `value_class` / `change_cost` / `prod_days` / `logistics_days` / `change_risk` / `service_level` / `batch_window` | `.kv`；`unit_value`（元/件）、`change_cost`（元/次）用 `fmt()`；`service_level` 以小数展示（0.95，注明口径 0~1）；`batch_window` 天展示并附「≈ N 周」换算提示（BR-12 天存储/周展示）；空值 `dash()` |
| 预测方法参数 | `base_method` / `base_params` | `.kv`；`base_params`（`*_json`）用 `tryParse()` 结构化展示（键值逐行），空值 `dash()`；解析失败回退原文 |
| 拟合版本快照 | `fit_version` / `fit_effective_at` | `.kv`；注明「set_fit_params 回填 · 最近拟合版本」（BR-20），空值 `dash()`；`fit_effective_at` 用 `fmtTime()` |
| 所属项目 | `md_project_part.list_by_material` + `md_project.list` 名称 | 跨应用子表（项目号/项目名称/车型/单车用量/供应份额%）；无映射显示「该物料暂无项目映射」 |
| 原始数据 | get 返回全量 JSON | 底部折叠（默认收起） |

**页脚 `.modal-ft`**：【编辑】（打开编辑表单，`x-show` 主数据管理员可用）【关闭】。本应用无状态机动作（状态由外部维护，仅只读展示），页脚不按状态放流转按钮。

### 2.3 创建 / 编辑表单（增/改）—— 模态表单

**用途**：覆盖 `md_material.create` / `md_material.update` 接受的业务参数（status 不进表单，见下）。`set_fit_params` 为内部回填服务，不进表单。

| 字段 | 控件 | 必填 | create 可见 | update 可见 | 约束来源 |
|---|---|---|---|---|---|
| `material_no` | input，maxlength=64 | ★ 必填 | 是 | 否（只读展示） | BR-01/BR-02/BR-19 主键，创建后不可变 |
| `material_name` | input，maxlength=100 | ★ 必填 | 是 | 是 | BR-03 |
| `status` | —（不进表单） | — | 否 | 否 | BR-04 外部维护只读；create 后端默认「正常」 |
| `unit_value` | number，step=0.01 | 选填 | 是 | 是 | BR-05 ≥0（元/件） |
| `value_class` | select：空 / 高 / 低 | 选填 | 是 | 是 | BR-06 枚举 |
| `change_cost` | number，step=0.01 | 选填 | 是 | 是 | BR-07 ≥0（元/次） |
| `prod_days` | number | 选填 | 是 | 是 | BR-08 ≥0（天） |
| `logistics_days` | number | 选填 | 是 | 是 | BR-09 ≥0（天） |
| `change_risk` | select：空 / 高 / 低 | 选填 | 是 | 是 | BR-10 枚举 |
| `service_level` | number，step=0.01 | 选填 | 是 | 是 | BR-11 0~1 |
| `batch_window` | number | 选填 | 是 | 是 | BR-12 >0（天存储/周展示） |
| `base_method` | select：空 / 移动平均 / 指数平滑 / 阶跃检测 / 借用参考 | 选填 | 是 | 是 | BR-13 枚举 |
| `base_params` | textarea（JSON 字符串） | 选填 | 是 | 是 | BR-14~18 与方法匹配 |

- **不进表单**：`status`（外部维护只读，create 后端默认「正常」、update 不接受修改）、`fit_version` / `fit_effective_at`（set_fit_params 回填快照，仅详情展示）。
- **create 模式**：`material_no` / `material_name` 必填，其余参数选填；`status` 不进表单（默认「正常」）。
- **update 模式**：`material_no` 回填展示但只读（主键不可改，BR-19）；`material_name` 与其余参数字段可改；`status` 不进表单（快照只展示）。
- **布局**：必填先行、frow 语义分组——① 基本信息（material_no / material_name）→ ② 库存策略参数（unit_value / value_class / change_cost / prod_days / logistics_days / change_risk / service_level / batch_window）→ ③ 预测方法参数（base_method / base_params）；底部右对齐「取消」「保存」。
- **base_params 输入**：`base_method` 为空时 `base_params` 禁用（后端「基线参数与基线方法不匹配」）；选择方法后 placeholder 给出该方法的合法 JSON 模板（BR-15~18）：
  - 移动平均 `{"window":6}`（window 3~12 整数，默认 6）
  - 指数平滑 `{"alpha":0.3,"trend":false}`
  - 阶跃检测 `{"threshold":0.3,"confirm_periods":2,"lookback":6}`
  - 借用参考 `{"ref_material":"M12345","scale":1.0,"mode":"trend"}`
  - 留空 = 后端按该方法的默认参数落库。
- **校验**：前端仅做必填校验（material_no / material_name 空 → toast 警告、不发请求）；枚举值合法性、数值非负/取值范围、base_params 合法性与方法匹配、主键唯一性均由后端校验，`FdeError` 经 api.js 统一 toast 呈现，模态保持打开便于修改后重试。
- **提交成功**：toast 成功消息 → 关闭模态 → create 重置过滤回第 1 页重载 / update 刷新当前页。

### 2.4 批量导入（增/改）—— 文件上传模态

**用途**：点击「批量导入」按钮，弹出文件上传模态，调 `md_material.import_batch`（ERP/PLM 冗余同步 + 本地批量建账，upsert）。

- 提供模板下载链接，表头含：material_no, material_name, status, unit_value, value_class, change_cost, prod_days, logistics_days, change_risk, service_level, batch_window, base_method, base_params。
- 上传文件 → 后端逐行校验 + upsert（已存在主键 → 更新参数含 status 随同步更新，新行 → 新增）。
- 返回摘要：`{total, success, fail, errors:[{row, field, message}]}` → 弹摘要（成功 N 条 / 失败 M 条 / 错误明细列表）。
- 导入完成后关闭并刷新列表。
- 注意：导入是 status 唯一随外部冗余同步更新的入口（非本地手工改，BR-04），前端只传 rows、不做二次校验。

> **`set_fit_params` 不进本清单**：本应用提供该服务、被 `strategy_fitting.approve` 跨应用调用（出向被调），本页前端不主动调用。

## 4. 数据来源与下拉

- **无跨应用主数据下拉**：`md_material` 不主动外调其他应用（应用详设 §7.3「本应用跨应用调用（出向）：无」）。
- **枚举为静态字典**（本应用内建，来源应用详设 BR-04/06/10/13）：
  - `status`：正常 / EOP / 停用（只读展示，列表 chips + 详情徽章）
  - `value_class`：高 / 低（表单 select）
  - `change_risk`：高 / 低（表单 select）
  - `base_method`：移动平均 / 指数平滑 / 阶跃检测 / 借用参考（表单 select）
- **借用参考 ref_material**：嵌在 `base_params` JSON 内、非顶层字段，前端以 JSON textarea 录入，存在性由后端 `_normalize_base_params` 校验（`_exists(ref_material)`），不设独立主数据 autocomplete。
- **契约 payload → 区块字段映射**：

| 契约 | 载荷字段 | 映射区块 |
|---|---|---|
| `md_material.list` 返回项 | `material_no, material_name, status, value_class, change_risk, base_method` | 2.1 列表列（1:1） |
| `md_material.get` 返回 | `material_no, material_name, status, unit_value, value_class, change_cost, prod_days, logistics_days, change_risk, service_level, batch_window, base_method, base_params, fit_version, fit_effective_at` | 2.2 详情模态全部 KV 分组 + 原始数据折叠 |
| `md_material.create` 入参 | `material_no, material_name, unit_value, value_class, change_cost, prod_days, logistics_days, change_risk, service_level, batch_window, base_method, base_params` | 2.3 创建表单（status 不传） |
| `md_material.update` 入参 | `material_no, material_name, unit_value, value_class, change_cost, prod_days, logistics_days, change_risk, service_level, batch_window, base_method, base_params` | 2.3 编辑表单（material_no 只读、status 不传） |
| `md_material.import_batch` 入参 | `rows: [{material_no, material_name, status, unit_value, value_class, change_cost, prod_days, logistics_days, change_risk, service_level, batch_window, base_method, base_params}]` | 2.4 批量导入（含 status 随冗余同步） |
| `set_fit_params`（本应用提供） | `material_no, base_method, base_params, batch_window, service_level, fit_version` | 非前端调用；`fit_version` / `fit_effective_at` 经 get 快照回显到 2.2 详情 |

## 5. 交互要点

1. **加载**：首载正常拉取 list（非看板页，失败走 api.js 统一通道）；列表重载期间显示加载态。
2. **过滤**：status chips 点击即查并重置 `page=1`；material_no / material_name 输入后 Enter 或「查询」触发；翻页仅改 `page/size`，不清过滤条件。
3. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 状态徽章。
4. **折叠「原始数据」**默认收起；`base_params` 结构化经 `tryParse()` 逐键展示，解析失败回退原文（不抛错）。
5. **表单折叠**：必填字段（material_no / material_name）先行；库存策略参数与预测方法参数分 `.sec` 组，可选字段集中排布（字段多，不逐项折叠）。
6. **成功流**：create 成功 → 关闭模态并清空表单 → toast「物料主数据创建成功」→ 列表回第 1 页重载；update 成功 → 关闭模态 → toast「物料主数据更新成功」→ 刷新当前页；import_batch 成功 → 弹摘要后刷新列表。
7. **错误流**：重复 material_no / 枚举非法 / 数值越界 / base_params 非法等后端 `FdeError` → toast 错误信息，模态保持打开便于修改后重试。
8. **空态**：无任何物料时「暂无物料 —— 点『新建物料』创建」；过滤无命中时「无符合条件的物料」。
9. **展示工具**：`hue()`（status / value_class / change_risk 徽章）、`dash()`（空枚举/空参数/空快照）、`fmt()`（unit_value / change_cost 金额）、`fmtTime()`（fit_effective_at）、`tryParse()`（base_params JSON 结构化）；`batch_window` 展示附周数换算（天 ÷ 7）。
10. **只读语义**：status 仅列表/详情展示、不进表单；fit_version / fit_effective_at 仅详情快照展示，注明「set_fit_params 回填」。

## 6. 验收关注点（供第⑧步前端测试用例）

1. **路由渲染**：`#/md_material` 挂载出列表三段式（工具栏 + 表格 + 分页条），**断言无 `.kpi`**（非看板页防挂载粘滞假过）；菜单「⚙ 物料主数据」按 order=30 定位。
2. **造数后列表有数据**：REST 经 `md_material.create` 造多条（覆盖 正常/EOP/停用 与 高/低 价值分类、四种 base_method）→ 列表行数正确，material_no / material_name / status / value_class / change_risk / base_method 列非空（空枚举列 `dash()`）。
3. **过滤一一对应**：material_no=M-10 模糊匹配（US-03-AC1）；status=正常 chips 仅正常行（US-03-AC2）；material_name=螺栓 模糊匹配（US-03-AC3）；三条件组合；无匹配显示空态且不抛错。
4. **模态全字段**：点 material_no 开模态，断言 material_no / material_name / status / unit_value / value_class / change_cost / prod_days / logistics_days / change_risk / service_level / batch_window / base_method / base_params / fit_version / fit_effective_at 全部可见 + `base_params` 结构化 + 「原始数据」可展开。
5. **表单落库**：create 表单填 material_no + material_name（★）+ 库存策略参数 + 预测方法参数 → 提交 → 列表出现新记录（status 默认「正常」）；空必填字段提交 → toast 警告且不发请求（US-01-AC3）；重复 material_no 创建 → 后端 FdeError toast「该物料号已存在」（US-01-AC2）。
6. **update 回显**：编辑模态 material_no 只读不可改（US-04-AC2）、status 不进表单（US-04-AC3）；修改 material_name 保存后列表和详情均反映新值（US-04-AC1）。
7. **枚举/参数校验**：value_class=中 → 后端 FdeError；base_method=借用参考 缺 ref_material → 后端 FdeError；base_params 非法 JSON → 后端 FdeError（US-01-AC4）。
8. **批量导入**：上传合法文件 → 列表新增行；含冲突行 → 摘要正确展示成功/失败数（US-05-AC2）；缺必填行 → 错误明细提示「物料号不能为空」（US-05-AC3）。
9. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP≥400（受限会话 403 属预期执法单独豁免；计划员角色下仅可读列表/详情、无「新建/编辑/批量导入」入口，页面不做任何判断）。
