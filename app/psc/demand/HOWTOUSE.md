# demand 使用要点

**管什么**：月度版本的毛需求与净需求合成——毛需求 = 预测 + 库存水位，净需求再叠加未发、扣库存与在途。

## 标准工作流（按此顺序）

1. `build_gross` — 合成毛需求：合并替换件/断点，期末 N+3 叠加库存策略水位；幂等重算
2. `publish` — 核对无误后发布冻结毛需求，**联动月度版本 草稿 → 发布（锁定）**
3. `calc_net` — 运算净需求（叠加未发、扣库存与在途，各层非负），**联动月度版本 发布 → 冻结**
4. `export_net` — 导出净需求清单，交线下产能平衡

核对用：`list`（按版本/物料筛）→ `get`（看单行分层拆解）。

## 前置条件与禁忌

- **版本状态是硬闸**：`build_gross` 只认草稿；`publish` 要求已合成；`calc_net` 只认发布（锁定）态；`export_net` 只认冻结态。**每一步都会推进月度版本状态且不可逆**——用户没确认就别往下走。
- **一步不成，后续不推进**：报「毛需求未合成」= 没 `build_gross`；报「毛需求未发布冻结」= 没 `publish`。别跳步重试。
- **水位必须先算好（硬前置）**：毛需求 = 预测 + 库存水位，所以该版本的 `inventory_strategy.calc_batch` 要先跑；**取不到水位会直接报错**（报「未找到版本 X 的库存水位策略（物料 Y），无法合成毛需求」），不会静默按 0 算。跑流程时保证「库存策略节点」在「毛需求节点」之前。
- **发布后毛需求行禁止修改**。要重做只能换新版本，不要试图在原版本上改。
- 前置数据须先就绪：销售预测已 `summarize`、库存策略已 `calc`，否则报「销售预测汇总取数失败」。
- `rolling_month` 只能是 `N+1` / `N+2` / `N+3`；`version_no` 为 `YYYYMM`。
- `material_no` 来自 `md_material`，不要凭空写。
