# 毛需求与净需求 前端详设
> 来源：app/psc/_contracts.md（冻结契约）+ app/psc/demand/应用详设.md；产出供第⑦步前端编码 / 第⑧步前端测试用例。
> 落位：`app/psc/demand/view.js` + `app/psc/demand/view.html`（与 `demand.py` 同文件夹，落盘即进启动清单与授权清单，零接线）。

## 1. 页面元数据 PAGE_META

key=demand / name=毛需求与净需求 / ic=🧮 / title=毛需求与净需求 / crumb=毛需求合成发布 · 净需求运算(毛需求+未发−库存−在途) / order=120

| 字段 | 值 | 说明 |
|---|---|---|
| key | `demand` | = 应用文件夹名，page_id 为 `psc:demand` |
| name | 毛需求与净需求 | 侧栏菜单名 |
| ic | 🧮 | 菜单图标字 |
| title | 毛需求与净需求 | 主区页面头 |
| crumb | 毛需求合成发布 · 净需求运算(毛需求+未发−库存−在途) | 头部副题 |
| order | 120 | 已按业务序预分配，直接用；升序即菜单序 |

- 页面零鉴权：无任何权限判断；菜单按页面授权渲染在 shell，数据范围由后端闸门执法，401 由 api.js 自动跳登录。
- **数据来源类型：手工参考创建**——本应用契约**无 create / update / set_* / import_batch / delete**，单据变更仅经版本级操作入口（build_gross / publish / calc_net / export_net），**无创建/编辑表单**（详见 §2.3 操作区）。

## 2. 区块构成

### 2.1 列表区（查）—— 三段式：操作区 / 过滤条 / 表格 / 分页条

**用途**：毛需求/净需求台账，按版本/物料/滚动月度筛选，承载版本级操作入口（合成/发布/运算/导出）。

**过滤控件（与 `demand.list(version_no, material_no, rolling_month, page, size)` 可过滤参数一一对应；契约无 keyword 参数 → 不设关键字搜索框，禁止前端假过滤）**：

| 控件 | 对应参数 | 选项 |
|---|---|---|
| 版本下拉 | `version_no` | 来自 `md_monthly_version.list` quiet 加载（见 §4）；选项 value=version_no，label=version_no + lock_status 徽章 |
| 物料 autocomplete | `material_no` | 内联 autocomplete（主数据，见 §4）；value=material_no，label=material_no + material_name |
| 滚动月度 chips | `rolling_month` | 全部 / N+1 / N+2 / N+3（BR-03 枚举，原值传参） |
| 分页 | `page` / `size` | `pageable()` 分页条（契约签名 string 型，照传即可） |

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集；字段序与详情/操作区一致）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 版本 | `version_no` | 正文 |
| 物料 | `material_no` | `.b-link`，点击开详情模态（携带 version_no + material_no + rolling_month） |
| 滚动月度 | `rolling_month` | 正文（N+1/N+2/N+3） |
| 预测 | `forecast_qty` | `fmt()` |
| 库存策略 | `inventory_qty` | `fmt()` |
| **毛需求** | `gross_qty` | `fmt()` 加粗（BR-01 系统计算） |
| 未发 | `open_order_qty` | `fmt()` |
| 库存 | `onhand_qty` | `fmt()` |
| 在途 | `in_transit_qty` | `fmt()` |
| **净需求** | `net_qty` | `fmt()` 加粗（BR-04 系统计算） |

**交互**：任一过滤变化 → 重置回第 1 页重载；版本操作成功后刷新当前页；空结果显示空态文案（不喷 toast）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 状态徽章 / KV 分组体 / 操作页脚

**用途**：点 `material_no` 弹出，展示 `demand.get` 返回的**全部**业务字段（毛需求/净需求分层拆解）。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `version_no` + `material_no` + `rolling_month` + 版本状态徽章 | 墨青头带，状态徽章 `hue()`（版本 lock_status 由 §4 版本下拉携带） |
| 基本标识 | `version_no` / `material_no` / `rolling_month` | `.kv`；注明「标识 = version_no + material_no + rolling_month 唯一」（BR-11） |
| 毛需求拆解 | `forecast_qty` / `inventory_qty` / `gross_qty` | `.kv`，小节标题「毛需求 = 预测 + 库存策略」；`gross_qty` 注明「系统计算 · 禁止手工改」（BR-01）；`inventory_qty` 注明「只加期末 N+3，不逐期分摊」（BR-02） |
| 净需求拆解 | `gross_qty` / `open_order_qty` / `onhand_qty` / `in_transit_qty` / `net_qty` | `.kv`，小节标题「净需求 = 毛需求 + 未发 − 库存 − 在途」；`net_qty` 注明「系统计算 · 各层非负」（BR-04 / BR-08）；`onhand_qty` 注明「自有仓 + 寄售仓」（BR-06） |
| 原始数据 | get 返回全量 JSON | 底部折叠 |

**交互**：页脚 `.modal-ft` 按当前版本状态放版本级动作按钮（逻辑同 §2.3，与操作区共用一处 `x-show` 判定）；动作成功后用返回对象原地刷新 + 刷新列表；各数量字段均 `fmt()`，无 `*_json` 快照字段（无需 `tryParse()`）。

### 2.3 操作区（手工参考创建 · 无 create/update 表单）

**用途**：本应用**无 create/update 写服务**，创建/变更入口为版本级操作按钮（手工参考创建，基于预测汇总 + 水位），故以「操作区」替代创建表单。

- **版本选择**：下拉选月度版本（`md_monthly_version.list` quiet），选中后列表按该版本过滤、操作区按钮按该版本 `lock_status` 显示。
- **上游数据摘要（折叠「上游数据摘要 ▾」）**：quiet 调 `sales_forecast.get_summary(version_no)` 展示最终预测量汇总（material_no × rolling_month × final_qty_sum），标注「来源：sales_forecast」；三层水位（`inventory_strategy.get_water_level`）逐物料、已在 build_gross 内合并进 `inventory_qty`，前端不单独调（可选项：选择物料时 quiet 预览，标注「来源：inventory_strategy」）。

**操作按钮（按版本 `lock_status` x-show）**：

| 按钮 | 服务 | x-show 条件 | 说明 |
|---|---|---|---|
| 【合成毛需求】 | `build_gross` | `lock_status === '草稿'` | 幂等重算；成功后 toast「毛需求合成成功，共 N 个物料」 |
| 【发布】 | `publish` | `lock_status === '草稿'` | 冻结毛需求并联动版本发布；发布确认对话框提示「发布后毛需求冻结不可改，联动锁定月度版本」 |
| 【运算净需求】 | `calc_net` | `lock_status === '发布（锁定）'` | 叠加未发/扣减库存与在途，联动版本冻结 |
| 【导出净需求】 | `export_net` | `lock_status === '冻结'` | 返回净需求清单数组 → 前端拼 CSV 触发下载，供线下产能平衡 |
| （只读） | — | `lock_status === '冻结'` | 冻结态除【导出净需求】外无其他按钮 |

> 版本状态枚举值以后端 `md_monthly_version.VALID_LOCK_STATUSES` 为准：`草稿` / `发布（锁定）` / `冻结`（注意「发布（锁定）」为全角括号，x-show 判定须逐字一致）。

## 3. svc 字面量清单（授权派生依据——必须字面量 svc("应用","服务")）

| 区块 | 调用（应用.服务） | 参数 | quiet | 说明 |
|---|---|---|---|---|
| 列表区 | `svc("demand","list")` | `{version_no, material_no, rolling_month, page, size}` | 否 | 分页查询；空条件传 undefined 不带 |
| 版本下拉 | `svc("md_monthly_version","list")` | `{page:1, size:200}` | 是 | version_no 下拉数据源（含 lock_status 驱动操作区按钮）；**跨应用调用，字面量产生 psc:demand → md_monthly_version.list 派生边** |
| 物料下拉 | `svc("md_material","list")` | `{page:1, size:200}` | 是 | material_no 内联 autocomplete 数据源；**跨应用调用，字面量产生 psc:demand → md_material.list 派生边** |
| 操作区·上游摘要 | `svc("sales_forecast","get_summary")` | `{version_no}` | 是 | 合成前展示最终预测量汇总（手工参考创建确认）；**跨应用调用，字面量产生 psc:demand → sales_forecast.get_summary 派生边** |
| 详情模态 | `svc("demand","get")` | `{version_no, material_no, rolling_month}` | 否 | 单行全字段（分层拆解） |
| 操作区/模态页脚 | `svc("demand","build_gross")` | `{version_no}` | 否 | 草稿 → 合成毛需求（BR-01/02/03/09/11） |
| 操作区/模态页脚 | `svc("demand","publish")` | `{version_no}` | 否 | 草稿（已合成）→ 发布冻结（BR-10） |
| 操作区/模态页脚 | `svc("demand","calc_net")` | `{version_no}` | 否 | 发布（锁定）→ 运算净需求（BR-04/06/07/08） |
| 操作区/模态页脚 | `svc("demand","export_net")` | `{version_no}` | 否 | 冻结 → 导出净需求清单（US-06） |

> 以上 9 处必须在 view.js 中以字面量逐项书写（可包在闭包里），**勿用变量拼名**——这是页面授权隐式放行派生扫描的唯一来源。

## 4. 数据来源与下拉

**版本下拉（version_no）**：
- 页面初始化一次性 `svc("md_monthly_version","list")` `{page:1, size:200}`，`quiet:true` 探测：失败不喷 toast；零值兜底 → 下拉仅「全部」、操作区按钮禁用并提示「暂无月度版本」。
- 由返回项构建 `versionMap = {version_no: lock_status}`，供操作区按钮 x-show 判定；选中项存 `version_no`，`lock_status` 用于 §2.3 状态机按钮。
- 选项 value=version_no，label=`version_no`（附 lock_status 徽章 `hue()`）。

**物料下拉（material_no，主数据引用铁律）**：
- 页面初始化一次性 `svc("md_material","list")` `{page:1, size:200}`，`quiet:true` 探测；零值兜底 → 空数组。
- 用**扁平数组** `materialOptions` 存（禁止嵌套 `autoOptions[field]`）；`@click.stop` 展开 + `@input` 过滤（同时匹配 material_no 与 material_name）+ `@click.away` 关闭；列表项「material_no + material_name」双行，选中后存 material_no。
- 列表按 material_no 精确匹配（后端 `= ?` 精确），非模糊。

**上游摘要（手工参考创建确认）**：
- `sales_forecast.get_summary(version_no)` quiet：展示最终预测量汇总（material_no / rolling_month / final_qty_sum），标注「来源：sales_forecast」；失败静默折叠为空。
- 三层水位来自 `inventory_strategy.get_water_level(version_no, material_no)`（逐物料），已在 build_gross 内合并进 `inventory_qty`，前端不单独调用（可选项：选择物料时 quiet 预览，标注「来源：inventory_strategy」）。

**契约 payload → 区块字段映射**：

| 来源 | payload 字段 | 去向 |
|---|---|---|
| `demand.list` 项 | version_no, material_no, rolling_month, forecast_qty, inventory_qty, gross_qty, open_order_qty, onhand_qty, in_transit_qty, net_qty | 列表区表格列（1:1） |
| `demand.get` | 同上（全量） | 详情模态全部 KV 分组 + 原始数据折叠 |
| `demand.build_gross` 返回 | {version_no, material_count, message} | toast「毛需求合成成功，共 N 个物料」→ 刷新列表 |
| `demand.publish` 返回 | {version_no, message} | toast「毛需求发布成功」→ 刷新版本下拉 + 列表 |
| `demand.calc_net` 返回 | {version_no, row_count, message} | toast「净需求运算成功」→ 刷新版本下拉 + 列表 |
| `demand.export_net` 返回 | [{version_no, material_no, rolling_month, net_qty}] | 前端拼 CSV 触发下载 + toast「已导出 N 行净需求」 |
| `md_monthly_version.list` 项 | version_no, anchor_period, opening_date, lock_status | 版本下拉选项 + versionMap（lock_status 驱动按钮） |
| `md_material.list` 项 | material_no, material_name | 物料 autocomplete 选项（materialOptions） |
| `sales_forecast.get_summary` 项 | version_no, material_no, rolling_month, final_qty_sum | 操作区「上游数据摘要」折叠区 |

## 5. 交互要点

1. **按版本状态的操作按钮（状态机，操作区与模态页脚共用判定）**：
   - `lock_status='草稿'` → 【合成毛需求】【发布】；
   - `lock_status='发布（锁定）'` → 【运算净需求】；
   - `lock_status='冻结'` → 只读，仅【导出净需求】。
   - 动作成功：toast + 刷新版本下拉（重载 `md_monthly_version.list` quiet，更新 lock_status）+ 刷新列表；非法流转（如冻结后再合成、未合成即发布、未发布即运算、未运算即导出）由后端 `FdeError` 经 api.js 统一 toast，页面不硬编状态机校验。
2. **发布确认对话框**：【发布】弹确认，提示「发布后毛需求冻结不可改，联动锁定月度版本」（US-02/BR-10）。
3. **导出**：【导出净需求】调 `export_net` 得净需求清单数组 → 前端拼 CSV（物料号/滚动月度/net_qty）触发浏览器下载，供线下产能平衡（US-06）；未运算版本由后端 FdeError 呈现。
4. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 版本状态徽章。
5. **折叠「上游数据摘要 ▾」**：操作区默认折叠，展开展示最终预测量汇总（quiet 加载）。
6. **quiet 探测性加载**：版本/物料/上游摘要下拉均 quiet + 零值兜底，失败不喷 toast；需求列表本身正常加载，错误走 api.js 统一通道。
7. **展示工具**：`fmt()`（全部数量字段，保留小数）、`dash()`（空值）、`hue()`（版本 lock_status 徽章）；本页无 `*_json` 快照字段，无需 `tryParse()`；无时间字段，无需 `fmtTime()`。
8. **toast**：合成/发布/运算/导出成功 + 必填未选版本警告；其余错误一律由 api.js 统一呈现。

## 6. 验收关注点（供第⑧步前端测试用例）

1. **路由渲染**：`#/demand` 挂载出操作区 + 列表三段式（过滤条 + 表格 + 分页条），**页面无 `.kpi`**（防看板挂载粘滞假过）；菜单「🧮 毛需求与净需求」按 order=120 定位。
2. **造数后列表有数据**：先造 md_monthly_version（草稿）+ md_material（M1）→ 走 sales_forecast 出汇总 → 经 `build_gross` 合成 → 列表出现 M1 三行（N+1/N+2/N+3），version_no / material_no / rolling_month / forecast_qty / gross_qty 列非空（US-01-AC1）。
3. **过滤一一对应**：version_no=202608 仅该版本行；material_no=M1；rolling_month=N+3 chips；三条件组合（US-04）；无匹配显示空态且不抛错。
4. **模态全字段**：点 material_no 开模态，断言 version_no / material_no / rolling_month / forecast_qty / inventory_qty / gross_qty / open_order_qty / onhand_qty / in_transit_qty / net_qty 全部可见 + 「原始数据」可展开；冻结版本模态页脚仅【导出净需求】。
5. **操作入口真实回显**：草稿版本【合成毛需求】→ 列表出现毛需求行 + toast；【发布】→ 版本 lock_status 变「发布（锁定）」、操作区按钮切换为【运算净需求】（US-02）；【运算净需求】→ lock_status 变「冻结」、net_qty 落库（US-03）；【导出净需求】→ 触发 CSV 下载 + toast 行数（US-06）。
6. **状态机收敛**：冻结版本操作区无【合成】【发布】【运算】按钮（只读）；草稿版本无【运算净需求】【导出净需求】按钮（US-02-AC2/AC3、US-03-AC3）。
7. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP≥400（受限会话 403 属预期执法单独豁免；计划角色全量可见，页面不做任何判断）。
