# 月度版本 前端详设
> 来源：app/psc/_contracts.md（冻结契约）+ app/psc/md_monthly_version/应用详设.md
> 落位：`app/psc/md_monthly_version/view.js` + `view.html`（与 `md_monthly_version.py` 同文件夹）

## 1. 页面元数据 PAGE_META

| 字段 | 值 | 说明 |
|---|---|---|
| key | `md_monthly_version` | = 应用文件夹名，page_id 为 `psc:md_monthly_version` |
| name | 月度版本 | 侧栏菜单名 |
| ic | 📅 | 菜单图标字 |
| title | 月度版本 | 主区页面头标题 |
| crumb | 主数据 · 计划周期版本(草稿→发布→冻结→回退) | 副题·要点 |
| order | 80 | 升序即菜单序 |

- 页面零鉴权：无任何权限判断；菜单按页面授权渲染在 shell，数据范围由后端闸门执法，401 由 api.js 自动跳登录。
- **数据来源类型 = 独立创建**（本系统定义版本，无上游依赖）→ 前端保留「+ 新建」按钮。
- 本应用契约**无 update / set_* / import_batch / delete** → 无编辑入口、无删除按钮；单据变更仅经状态机动作（publish / freeze / unfreeze）。
- 本应用**无出向跨应用调用**（§7.3），无主数据下拉；`get_active` 为后端接口（供下游应用经 `self.fde.call` 取版本锚点），**本页不调用**。

## 2. 区块构成

### 2.1 列表区（查）—— 三段式：过滤条 / 表格 / 分页条

**用途**：月度版本台账，按版本号与锁定状态筛选，承载行内状态流转动作（发布 / 冻结 / 回退）。本页为非看板页，不设 KPI 指标带（验收断言无 `.kpi`）。

**过滤控件（与 `md_monthly_version.list(version_no, lock_status, page, size)` 可过滤参数一一对应；契约无 keyword 参数 → 不设关键字搜索框，禁止前端假过滤）**：

| 控件 | 对应参数 | 选项 |
|---|---|---|
| 版本号输入框 | `version_no` | 文本输入，**精确匹配**（后端 `WHERE version_no = ?`）；空值不传 |
| 锁定状态 chips | `lock_status` | 全部 / 草稿 / 发布（锁定）/ 冻结（BR-05 三态枚举，原值传参） |
| 分页 | `page` / `size` | `pageable()` 分页条（integer 型，照传即可） |

**工具栏**：「+ 新建版本」（打开 2.3 创建模态）。

**表格列（`.tbl.tight`；全部为详情字段子集；字段序与详情/表单一致：单号→状态→归属→时间）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 版本号 | `version_no` | `.b-link`，点击打开详情模态 |
| 锁定状态 | `lock_status` | `hue()` 徽章（草稿 / 发布（锁定）/ 冻结 三色） |
| 锚定期间 | `anchor_period` | 文本，空值 `dash()` |
| opening 日 | `opening_date` | 文本，空值 `dash()` |
| 操作 | — | 按 `lock_status` 的行内动作，`x-show`（见 §5.1） |

**交互**：任一过滤变化 → 重置回第 1 页重载；状态动作成功后刷新当前页；空结果显示空态文案（不喷 toast）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 状态徽章 / KV 分组体 / 状态操作页脚

**用途**：点 `version_no` 弹出，展示 `md_monthly_version.get` 返回的**全部**业务字段。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `version_no` + `lock_status` 徽章 | 墨青头带，徽章 `hue()` |
| 基本信息 | `version_no` / `anchor_period` / `opening_date` | `.kv`；`version_no` 注明「YYYYMM 格式 · 全局唯一 · 主键」（BR-01/BR-02） |
| 状态信息 | `lock_status` | `.kv`；注明「草稿 --publish--> 发布（锁定） --freeze--> 冻结 --unfreeze--> 草稿（可回退）」（BR-07/BR-08/BR-09） |
| 原始数据 | get 返回全量 JSON | 底部折叠（默认收起） |

**页脚 `.modal-ft`**：按当前状态放状态机按钮（逻辑同 §5.1，与行内动作共用一处 `x-show` 判定）；动作成功后用返回对象原地刷新模态字段 + 列表行。

### 2.3 创建表单（增）—— 模态表单

**用途**：覆盖 `md_monthly_version.create` 接受的**全部**可写业务参数（version_no / anchor_period / opening_date）。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `version_no` | input，maxlength=6，placeholder「如 202608」 | ★ 必填 | BR-01（全局唯一）/ BR-02（6 位数字 YYYYMM，月 01~12）/ BR-06（同一时刻仅一个活跃版本） |
| `anchor_period` | input，placeholder「锚定期间」 | ★ 必填 | BR-03（非空）；具体格式/口径待确认（BRD 未展开，后端仅非空校验） |
| `opening_date` | date input | ★ 必填 | BR-04（合法日期，后端 `%Y-%m-%d` 校验） |

- **不进表单**：`lock_status`（系统默认「草稿」，随状态机流转，仅详情展示并注明）。
- 布局：必填先行、frow 语义分组、底部右对齐提交按钮；校验 = 必填红星 + toast 警告（任一必填为空不发请求）。
- 前端仅做必填校验；version_no 格式、唯一性、活跃版本冲突（BR-06）由后端 `FdeError` 经 api.js 以错误 toast 呈现。
- 提交成功：toast「月度版本创建成功」→ 关闭模态 → 重置过滤重载列表（新版本恒「草稿」）。
- **无编辑入口**：本应用无 update 服务，创建后字段不可修改；变更仅经状态机动作。

## 3. svc 字面量清单（授权派生依据——必须字面量 svc("应用","服务")）

| 区块 | 调用（应用.服务） | 参数 | quiet | 说明 |
|---|---|---|---|---|
| 列表区 | `svc("md_monthly_version","list")` | `{version_no, lock_status, page, size}` | — | 过滤查询；空条件传 undefined 不带 |
| 详情模态 | `svc("md_monthly_version","get")` | `{version_no}` | — | 全字段详情 |
| 创建表单 | `svc("md_monthly_version","create")` | `{version_no, anchor_period, opening_date}` | — | 创建；lock_status 由后端默认「草稿」 |
| 行内 / 模态页脚 | `svc("md_monthly_version","publish")` | `{version_no}` | — | 草稿 → 发布（锁定）（BR-07） |
| 行内 / 模态页脚 | `svc("md_monthly_version","freeze")` | `{version_no}` | — | 发布（锁定）→ 冻结（BR-08） |
| 行内 / 模态页脚 | `svc("md_monthly_version","unfreeze")` | `{version_no}` | — | 冻结 → 草稿（回退，BR-09） |

> 以上 6 处必须在 view.js 中以字面量逐项书写（可包在闭包里），**勿用变量拼名**——这是页面授权隐式放行派生扫描的唯一来源。
> `md_monthly_version.get_active` 为后端接口（FUNC-05，供下游应用经 `self.fde.call` 取版本锚点），**本页不调用、不列入 svc 清单**；活跃版本由列表 `lock_status` 列直接辨识（草稿/发布（锁定）即未冻结）。

## 4. 数据来源与下拉

- **无跨应用主数据下拉**：本应用无出向跨应用调用（§7.3），version_no / anchor_period / opening_date 均为用户手工录入；lock_status 为静态三态枚举（草稿 / 发布（锁定）/ 冻结），用 chips 过滤、`hue()` 徽章展示。
- **契约 payload → 区块字段映射**：

| 来源 | payload 字段 | 去向 |
|---|---|---|
| `md_monthly_version.list` 项 | version_no, anchor_period, opening_date, lock_status | 列表区表格列（1:1） |
| `md_monthly_version.get` | 同上（全量） | 详情模态全部 KV 分组 + 原始数据折叠 |
| `md_monthly_version.create` 入参 | version_no, anchor_period, opening_date | 创建表单 |
| `md_monthly_version.create / publish / freeze` 返回 | 版本对象（含 lock_status） | create 后列表重载；publish/freeze 后原地更新已开模态 + 列表行 |

- 本页无 `*_json` 快照字段，无需 `tryParse()`；无金额字段，无需 `fmt()`；无 `created_at/updated_at` 展示字段，无需 `fmtTime()`。

## 5. 交互要点

1. **按状态的行内动作（状态机，行操作列与模态页脚共用判定）**：
   - `lock_status=草稿` → 【发布】（调 publish，BR-07）；
   - `lock_status=发布（锁定）` → 【冻结】（调 freeze，BR-08）；
   - `lock_status=冻结` → 【回退】（调 unfreeze，BR-09，回退到草稿）。
   - 动作成功：toast（如「版本发布成功，预测已锁定」/「版本冻结成功」/「版本已回退到草稿」）+ 刷新列表；非法流转（如对冻结版本点发布、对草稿点冻结、非冻结版本点回退）由后端 `FdeError` 经 api.js 统一 toast，页面不硬编状态机校验。
2. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 状态徽章。
3. **quiet 探测性加载**：本页无跨应用 quiet 探测；列表本身正常加载，错误走 api.js 统一通道。
4. **展示工具**：`hue()`（lock_status 三态徽章）、`dash()`（空 anchor_period / opening_date）；无金额/时间/`*_json` 字段，无需 `fmt()`/`fmtTime()`/`tryParse()`。
5. **toast**：创建成功 / 发布成功 / 冻结成功 / 回退成功 / 必填未填警告；其余错误（版本号已存在、格式非法、已存在活跃版本、非法流转）一律由 api.js 统一呈现。

## 6. 验收关注点（供第⑧步）

1. **路由渲染**：`#/md_monthly_version` 挂载出列表三段式（过滤条 + 表格 + 分页条），**断言无 `.kpi`**（非看板页防挂载粘滞假过）；菜单「📅 月度版本」按 order=80 定位。
2. **造数后列表有数据**：经 `create` 造版本 202608 → 列表 1 行，version_no / lock_status=草稿 / anchor_period / opening_date 四列非空；按 version_no 降序。
3. **过滤一一对应**：version_no=202608 精确匹配仅该行；lock_status=冻结 chips 仅冻结行；两条件组合（AND）；无匹配显示空态且不抛错。
4. **模态全字段**：点 version_no 开模态，断言 version_no / anchor_period / opening_date / lock_status 全部可见 + 「原始数据」可展开；冻结版本的模态页脚含【回退到草稿】按钮。
5. **表单落库**：创建表单填 version_no / anchor_period / opening_date（★）→ 提交 → 列表出现新记录且 lock_status=草稿（US-01-AC1）；空必填提交 → toast 警告且不发请求；重复 version_no → 后端 toast「该版本号已存在」（US-01-AC2）；非法格式 → 「版本号格式必须为 YYYYMM」（US-01-AC3）；已有活跃版本再建 → 「已存在活跃版本」（US-01-AC4）。
6. **写操作真实回显**：草稿行【发布】→ 行与模态 lock_status=发布（锁定）（US-03）；发布（锁定）行【冻结】→ lock_status=冻结（US-04）；冻结行【回退】→ lock_status=草稿（US-06）。
7. **无编辑入口**：列表面与详情模态均无编辑按钮（本应用无 update 服务）。
8. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP≥400（受限会话 403 属预期执法单独豁免）。
