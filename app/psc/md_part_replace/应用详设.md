# 替换关系 · 应用详设

> 应用名：`md_part_replace` | 类名：`MdPartReplace` | 聚合根：替换关系

## 1. 需求概览

### 1.1 基本信息
- **需求名称**: 零件替换关系管理
- **需求编号**: REQ-PSC-MDPR-001
- **所属模块**: 产销协同-主数据层
- **需求来源**: 业务方（工程/计划）
- **创建日期**: 2026-08-14
- **优先级**: P0

### 1.2 需求背景
#### 1.2.1 为什么需要这个需求？
零件间的替换关系（原件→替换件）是毛需求发布「替换件合并」处理的输入。没有替换关系数据，系统无法在毛需求合成时合并可替代零件的需求、防止对同一需求量分别下单导致超储。

#### 1.2.2 期望达到什么目标？
建立零件间替换关系的权威台账（原物料号/替换物料号/ECN 依据/生效状态），支撑毛需求发布的替换件合并处理。

### 1.3 需求范围
#### 1.3.1 包含哪些功能？
替换关系的创建、详情查看、列表查询、更新、设为失效（disable）。

#### 1.3.2 不包含哪些功能？
- 不做 ECN 变更审批流（替换关系按 ECN 依据维护，不承载审批）
- 不做替换关系自动发现（如从 BOM 变更中识别）
- 不做断点切换关系（新旧件断点切换由 `md_breakpoint` 承载）

> **数据来源类型**: 独立创建 —— 数据由 PLM 冗余同步（变更增量同步，§8.5.2），上游 PLM 无此数据时本地录入；前端保留"新建"按钮。

### 1.4 涉及角色
**谁会使用这个功能？**

- **计划员**: 维护替换关系（依据 ECN 通知创建/更新/设为失效），管理关系生命周期（生效→失效）
- **责任销售**: 查看替换关系（了解零件变更对预测/需求的影响）

## 2. 用户故事

### 2.1 核心用户故事

#### 2.1.1 `US-01` 用户故事 — 创建替换关系（优先级：P1）

- **故事描述**: 作为计划员，我想要创建零件间的替换关系记录，以便于毛需求发布时做替换件合并
- **为何赋予此优先级**：替换关系是毛需求「替换件合并」的唯一输入，无此数据则合并处理无法运行
- **独立测试**：可通过进入替换关系页面，点击"新建"，选择原物料号/替换物料号并保存后验证来独立测试
- **前置条件**: 引用的 old_material_no 和 new_material_no 已存在于 md_material 中
- **后置条件**: 系统生成一条新的替换关系记录，rel_no 系统自动生成，status 默认为"生效"

**验收场景**：

1. `US-01-AC1` **场景**: 合法参数创建成功
   - **Given** 物料 M10001 和 M10002 均存在，且系统中不存在该原+替换组合，**When** 填写 old_material_no=M10001, new_material_no=M10002, ecn_no=ECN-A-118 后保存，**Then** 记录创建成功，rel_no 系统自动生成，status=生效，可通过 get(rel_no) 查询到完整记录

2. `US-01-AC2` **场景**: 重复原+替换组合被拒绝
   - **Given** 系统中已存在 old_material_no=M10001, new_material_no=M10002 的替换关系，**When** 再次创建相同原+替换组合，**Then** 系统拒绝保存并提示"该原物料+替换物料组合已存在"

3. `US-01-AC3` **场景**: 原物料等于替换物料被拒绝
   - **Given** 物料 M10001 存在，**When** 创建 old_material_no=M10001, new_material_no=M10001，**Then** 系统拒绝保存并提示"原物料号与替换物料号不能相同"

4. `US-01-AC4` **场景**: 引用不存在的原物料被拒绝
   - **Given** 系统中不存在 old_material_no=NOTEXIST，**When** 创建替换关系引用该原物料，**Then** self.fde.call('md_material.get') 返回不存在，拒绝保存并提示"原物料号不存在"

5. `US-01-AC5` **场景**: 引用不存在的替换物料被拒绝
   - **Given** 系统中不存在 new_material_no=NOTEXIST，**When** 创建替换关系引用该替换物料，**Then** self.fde.call('md_material.get') 返回不存在，拒绝保存并提示"替换物料号不存在"

6. `US-01-AC6` **场景**: 必填字段为空被拒绝
   - **Given** 用户在新建表单中，**When** old_material_no 或 new_material_no 为空提交，**Then** 系统拒绝保存并提示具体缺失字段

#### 2.1.5 `US-05` 用户故事 — 设为失效（优先级：P2）

- **故事描述**: 作为计划员，我想要将不再有效的替换关系设为失效，以便于毛需求替换件合并中排除过期关系
- **为何赋予此优先级**：替换关系有生命周期，过期关系须标记失效以排除出合并计算
- **独立测试**：可通过查询一条生效中的替换关系，执行 disable 后验证 status 变为"失效"来独立测试
- **前置条件**: 目标替换关系 status=生效
- **后置条件**: status 更新为"失效"，后续毛需求替换件合并中排除此关系

**验收场景**：

1. `US-05-AC1` **场景**: 设为失效成功
   - **Given** 存在替换关系 rel_no=R1 status=生效，**When** 调用 disable(rel_no)，**Then** status 变为"失效"，毛需求替换件合并引用此关系时被排除

2. `US-05-AC2` **场景**: 对已失效记录再设失效（幂等）
   - **Given** 替换关系 rel_no=R1 status=失效，**When** 再次调用 disable(rel_no)，**Then** 操作无副作用，status 保持"失效"

## 3. 业务场景

### 3.1 业务流程描述

#### 3.1.1 场景1: 建立替换关系
1. 计划员收到工程变更通知（ECN），确认原件将被替换件替换
2. 进入"替换关系"页面，点击"新建"
3. 选择原物料号（来源：md_material.list 下拉选择）
4. 选择替换物料号（来源：md_material.list 下拉选择）
5. 填写 ECN 依据（ecn_no）
6. 系统校验：原/替换物料存在性（self.fde.call → md_material.get）、原≠替换、原+替换组合唯一
7. 校验通过 → 记录入库，rel_no 系统自动生成，status 默认"生效"

#### 3.1.2 场景2: 毛需求替换件合并使用替换关系
1. demand.build_gross(version_no) 被触发（毛需求合成）
2. 调用 self.fde.call('md_part_replace.list', status=生效) 获取生效替换关系
3. 对存在替换关系的物料，将替换件需求合并到原物料（替换件合并处理，§5.2）
4. 失效的替换关系在合并处理中被排除

#### 3.1.3 场景3: 替换关系生命周期
1. 替换关系初始创建 → status=生效
2. 替换件替代完成、原物料彻底退出后 → disable(rel_no) → status=失效
3. 失效的记录在毛需求替换件合并中被排除

### 3.2 业务规则

#### 3.2.1 `BR-01` 原物料+替换物料组合唯一
- **规则描述**: 同一原物料+替换物料组合唯一（业务唯一：old_material_no + new_material_no），一对新旧件只能有一条替换关系
- **适用场景**: 创建、更新
- **示例**: 已存在 old_material_no=M10001 + new_material_no=M10002，则不可再建相同组合

#### 3.2.2 `BR-02` 原物料号不等于替换物料号
- **规则描述**: old_material_no 必须不等于 new_material_no（替换意味着新旧不同，禁止自替换）
- **适用场景**: 创建、更新
- **示例**: old_material_no=M10001, new_material_no=M10001 → 拒绝保存

#### 3.2.3 `BR-03` 必填字段校验
- **规则描述**: old_material_no, new_material_no 为必填，不可为空字符串；ecn_no 为选填
- **适用场景**: 创建、更新
- **示例**: 创建时 new_material_no 为空 → 拒绝保存，提示"替换物料号不能为空"

#### 3.2.4 `BR-04` 原物料引用校验
- **规则描述**: old_material_no 必须已存在于 md_material 中，通过 self.fde.call('md_material.get', old_material_no) 校验
- **适用场景**: 创建、更新
- **示例**: old_material_no=NOTEXIST → 拒绝保存，提示"原物料号不存在"

#### 3.2.5 `BR-05` 替换物料引用校验
- **规则描述**: new_material_no 必须已存在于 md_material 中，通过 self.fde.call('md_material.get', new_material_no) 校验
- **适用场景**: 创建、更新
- **示例**: new_material_no=NOTEXIST → 拒绝保存，提示"替换物料号不存在"

#### 3.2.6 `BR-06` 状态枚举约束
- **规则描述**: status 取值仅限"生效"或"失效"
- **适用场景**: 创建、更新、disable
- **示例**: status=待审批 → 拒绝保存，提示"状态仅支持生效/失效"

### 3.3 业务数据

#### 3.3.1 数据1: 关系号 rel_no
- **数据描述**: 替换关系的唯一编号，单字段主键，系统自动生成
- **数据类型**: 文本
- **数据来源**: 系统自动生成
- **示例值**: R1

#### 3.3.2 数据2: 原物料号 old_material_no
- **数据描述**: 被替换的原物料号
- **数据类型**: 文本
- **数据来源**: 引用 md_material，通过 self.fde.call 校验；前端从 md_material.list 下拉选择
- **示例值**: M10001

#### 3.3.3 数据3: 替换物料号 new_material_no
- **数据描述**: 替换后的替换物料号
- **数据类型**: 文本
- **数据来源**: 引用 md_material，通过 self.fde.call 校验；前端从 md_material.list 下拉选择
- **示例值**: M10002

#### 3.3.4 数据4: ECN 依据 ecn_no
- **数据描述**: 工程变更通知编号，替换关系的变更依据
- **数据类型**: 文本
- **数据来源**: 用户录入（依据 ECN 通知）
- **示例值**: ECN-A-118

#### 3.3.5 数据5: 状态 status
- **数据描述**: 关系是否生效；失效的关系在毛需求替换件合并中被排除
- **数据类型**: 枚举值
- **数据来源**: 系统默认"生效"，用户可设为"失效"
- **示例值**: 生效 / 失效

### 3.4 状态机

替换关系状态流转：

```
(新建) ──→ 生效 ──→ 失效
```

**状态转换规则矩阵：**

| 当前状态 | 目标状态 | 触发动作 | 前置条件 |
|----------|----------|----------|----------|
| (新建) | 生效 | 创建替换关系（create） | 原/替换物料引用校验通过、原≠替换、原+替换组合唯一 |
| 生效 | 失效 | disable(rel_no) | 当前状态=生效 |
| 失效 | 生效 | 需重新创建（V1 不支持反向激活，实际通过新建关系实现） | — |

### 4.3 功能详细说明

#### 4.3.1 F01-06 替换关系

##### 4.3.1.1 FUNC-01 创建替换关系

**功能描述**:
提供替换关系的创建表单，用户选择原物料号和替换物料号，填写 ECN 依据后保存。此功能为独立创建——前端保留"新建"按钮。

**用户操作流程**:
1. 用户进入"替换关系"列表页，点击"新建"按钮
2. 系统展示创建表单
3. 用户选择 old_material_no（来源：md_material.list 下拉选择）
4. 用户选择 new_material_no（来源：md_material.list 下拉选择）
5. 用户填写选填字段：ecn_no
6. 用户点击"保存"
7. 系统执行校验：
   a. old_material_no 存在性（self.fde.call → md_material.get）
   b. new_material_no 存在性（self.fde.call → md_material.get）
   c. old_material_no != new_material_no
   d. old+new 组合唯一性
   e. status 枚举值
8. 校验通过 → 记录入库，rel_no 系统自动生成，status 默认"生效"

**输入数据**:
- old_material_no: 原物料号 - 必填，来源 md_material.list 下拉选择 - 示例：M10001
- new_material_no: 替换物料号 - 必填，来源 md_material.list 下拉选择 - 示例：M10002
- ecn_no: ECN 依据 - 选填，最大50字符 - 示例：ECN-A-118

**输出数据**:
- 成功消息: "替换关系创建成功"
- 错误消息: "该原物料+替换物料组合已存在" / "原物料号不存在" / "替换物料号不存在" / "原物料号与替换物料号不能相同"

**业务规则**:
- BR-01: old_material_no + new_material_no 组合唯一
- BR-02: old_material_no != new_material_no
- BR-03: old_material_no, new_material_no 必填
- BR-04: old_material_no 须经 md_material.get 校验
- BR-05: new_material_no 须经 md_material.get 校验
- BR-06: status 仅限"生效"或"失效"

**特殊处理**:
- old_material_no 和 new_material_no 的前端下拉选择均来源于 md_material.list（主数据引用铁律：禁止手工录入）
- 创建时后端做两次 self.fde.call 校验引用完整性
- rel_no 由系统自动生成（具体编码规则待确认），status 默认"生效"，无需用户选择

**业务实体**:
- **MdPartReplace**: 零件间替换关系（原物料→替换物料）与 ECN 依据、生效状态，标识为 rel_no

**MdPartReplace 字段**

| 字段名称 | 字段类型 | 是否必填 | 默认值 | 业务逻辑 |
|---|---|---|---|---|
| rel_no | 文本 | 否（系统生成） | - | 关系号，PK，系统自动生成，全局唯一 |
| old_material_no | 文本 | 是 | - | 原物料号，来源：md_material.list 下拉选择；后端 self.fde.call('md_material.get', old_material_no) 校验；与 new_material_no 组合唯一 |
| new_material_no | 文本 | 是 | - | 替换物料号，来源：md_material.list 下拉选择；后端 self.fde.call('md_material.get', new_material_no) 校验；须 ≠ old_material_no |
| ecn_no | 文本 | 否 | - | ECN 依据，变更来源，最大50字符 |
| status | 枚举值 | 是 | 生效 | 生效\|失效；失效关系在毛需求替换件合并中被排除 |

##### 4.3.1.2 FUNC-02 替换关系列表查询

**功能描述**:
提供替换关系的分页列表，支持按原物料号、替换物料号、状态等条件筛选。

**用户操作流程**:
1. 用户进入"替换关系"列表页
2. 用户可选填写筛选条件
3. 用户点击"查询"
4. 系统返回符合条件的替换关系列表（分页）

**输入数据**:
- old_material_no: 原物料号 - 选填，模糊匹配 - 示例：M10001
- new_material_no: 替换物料号 - 选填，模糊匹配 - 示例：M10002
- status: 状态 - 选填，精确匹配 - 示例：生效
- page: 页码 - 默认1
- size: 每页条数 - 默认20

**输出数据**:
- 列表字段: rel_no, old_material_no, new_material_no, ecn_no, status
- 分页信息: total, page, size

**业务规则**:
- 筛选条件均为可选，条件之间 AND 关系
- old_material_no / new_material_no 支持模糊匹配（LIKE %value%）

**特殊处理**:
- 默认按 rel_no 升序排列
- 列表以 status 标签颜色直观区分生效（绿）/失效（灰）
- 供下游 demand.build_gross 调用 list(status=生效) 做替换件合并

**业务实体**:
- **MdPartReplace**: 同上 FUNC-01

**MdPartReplace 列表展示字段**

| 展示字段 | 字段来源 | 可筛选 | 说明 |
|---|---|---|---|
| 关系号 | rel_no | 否 | PK |
| 原物料号 | old_material_no | 是（模糊） | 被替换的原物料 |
| 替换物料号 | new_material_no | 是（模糊） | 替换后的物料 |
| ECN 依据 | ecn_no | 否 | 变更来源 |
| 状态 | status | 是（精确） | 生效/失效 |

##### 4.3.1.3 FUNC-03 替换关系详情

**功能描述**:
提供单条替换关系的详情查看，展示原物料号/替换物料号/ECN 依据/状态等完整字段。

3. 用户核对原/替换物料与 ECN 依据

**输入数据**:

**输出数据**:
- 详情字段: rel_no, old_material_no, new_material_no, ecn_no, status

**业务规则**:
- 无额外校验（只读展示）

**特殊处理**:
- 详情页提供"编辑"与"设为失效"操作入口

##### 4.3.1.4 FUNC-04 更新替换关系

**功能描述**:
对已有替换关系记录修改 ecn_no（ECN 依据）；原/替换物料号可修改，但须重新校验物料存在性、原≠替换与组合唯一性。rel_no 作为主键不允许修改。

**用户操作流程**:
1. 用户在列表页点击目标行 → 进入编辑模式
2. 系统回填当前值到表单
3. 用户修改可编辑字段（ecn_no；old_material_no / new_material_no 可改）
4. 用户点击"保存"
5. 系统校验：物料存在性、原≠替换、组合唯一性、枚举值
6. 校验通过 → 更新入库

**输入数据**:
- rel_no: 关系号 - 不可修改，仅作为定位键
- old_material_no: 原物料号 - 可修改（须重新校验）
- new_material_no: 替换物料号 - 可修改（须重新校验）
- ecn_no: ECN 依据 - 可修改，最大50字符

**输出数据**:
- 成功消息: "替换关系更新成功"
- 错误消息: "替换关系不存在" / "原物料号不存在" / "替换物料号不存在" / "原物料号与替换物料号不能相同" / "该原物料+替换物料组合已存在"

**业务规则**:
- BR-01: 变更原/替换物料号须重新校验组合唯一性
- BR-02: old_material_no != new_material_no
- BR-03: old_material_no, new_material_no 不能更新为空
- BR-04/BR-05: 变更物料引用须重新校验物料存在

**特殊处理**:
- 若需同时将 status 设为失效，应使用 disable 方法而非 update

---

##### 4.3.1.5 FUNC-05 设为失效

**功能描述**:
提供 disable(rel_no) 方法将替换关系 status 设为"失效"。也可从前端通过列表操作按钮触发。失效的关系在毛需求替换件合并中被排除。

**用户操作流程**:
1. 用户在列表页找到目标替换关系
2. 点击"设为失效"操作按钮
3. 系统弹出确认提示
4. 用户确认后，status 更新为"失效"
5. 后续 demand.build_gross 调用 list(status=生效) 时失效关系被排除

**输入数据**:
- rel_no: 关系号 - 必填

**输出数据**:
- 成功消息: "替换关系已设为失效"
- 错误消息: "替换关系不存在"

**业务规则**:
- BR-06: status 更新为"失效"
- 幂等性: 已失效的记录再调用 disable 无副作用

**特殊处理**:
- disable 为幂等操作：已是"失效"状态时直接返回成功
- 失效是单向操作，V1 不支持反向激活（如需恢复生效，重新创建新记录）
- 此方法为公共接口，也可供外部系统通过 self.fde.call 调用

- 替换关系删除功能暂不提供（有效期管理通过 disable 实现）
