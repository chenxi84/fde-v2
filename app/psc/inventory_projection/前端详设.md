# 库存推移表 前端详设
> 来源：app/psc/_contracts.md（冻结契约）+ app/psc/inventory_projection/应用详设.md；产出供第⑦步前端编码 / 第⑧步前端测试用例。
> 落位：`app/psc/inventory_projection/view.js` + `view.html`（与 `inventory_projection.py` 同文件夹，落盘即进启动清单与授权清单，零接线）；import 一律绝对路径 `/view/lib/*`；模板经 `new URL("view.html", import.meta.url)` 抓取；工厂 `export default function pageInventoryProjection()`（保留专名）。

## 1. 页面元数据 PAGE_META

| 字段 | 值 | 说明 |
|---|---|---|
| key | `inventory_projection` | = 应用文件夹名，page_id 为 `psc:inventory_projection` |
| name | 库存推移表 | 侧栏菜单名 |
| ic | 🌊 | 菜单图标字 |
| title | 库存推移表 | 主区页面头标题 |
| crumb | 逐日推演库存水位 · 缺货/击穿/呆滞/超储预警 | 头部副题 |
| order | 140 | 升序即菜单序 |

- 页面零鉴权：无任何权限判断；菜单按页面授权渲染在 shell，数据范围（计划员可查看全量推移表，无物料级隔离）由后端闸门执法，401 由 api.js 自动跳登录。
- 数据来源类型：**自动参考创建**——每日 0 点系统自动 refresh_batch 推演生成，**无手工新建 / 编辑 / 删除入口**（无 create / update / delete 服务 → 无业务单据表单）。前端只提供「刷新 refresh / 批量刷新 refresh_batch」两个计算触发按钮 + 列表 + 详情；预警扫描 scan_alert **不设前端入口**，由批量刷新内部联动（计划员仅需触发刷新/批量刷新）。
- 本应用**无状态机**（BR-11 逐日快照）→ 无按状态的行内流转动作；刷新统一在列表工具栏触发。

## 2. 区块构成

### 2.1 列表区（查）—— 三段式：过滤条 / 表格 / 分页条

**用途**：库存推移表逐日台账浏览，按物料 / 日期 / 预警类型筛选，承载「刷新 / 批量刷新」两个计算触发入口。本页为非看板页，不设 KPI 指标带（验收断言无 `.kpi`）。

**过滤控件（与 `inventory_projection.list(material_no, biz_date, alert_type, page, size)` 可过滤参数一一对应；契约无 keyword 参数 → 不设关键字搜索框，禁止前端假过滤）**：

| 控件 | 对应参数 | 形态 |
|---|---|---|
| 物料下拉 | `material_no` | 主数据引用铁律：内联 autocomplete 下拉，来源 `md_material.list` quiet 加载（见 §4）；选项 value=material_no，双行展示「代号 + 名称」；精确匹配 |
| 日期输入框 | `biz_date` | placeholder「YYYY-MM-DD」，Enter 或「查询」按钮触发（后端精确匹配） |
| 预警类型 chips | `alert_type` | 全部 / 无 / 缺货 / 击穿最低 / 击穿安全 / 呆滞 / 超储（六态原值传参，BR-09 枚举） |
| 分页条 | `page` / `size` | `pageable()`，integer 传参 |

**工具栏**：「查询」「🌊 刷新」（单物料 refresh，见 2.3.1）「🌊 批量刷新」（整批 refresh_batch，见 2.3.2）。无「扫描预警」按钮。

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集，字段序与详情一致：物料号→日期→入库→出库→余额→预警）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 物料号 | `material_no` | `.b-link`，点击以 `material_no` + `biz_date` 复合主键打开详情模态；matMap 命中时附物料名称小字 |
| 日期 | `biz_date` | 正文（YYYY-MM-DD） |
| 预计入库量 | `inbound_qty` | `fmt()` 数字 |
| 预计出库量 | `outbound_qty` | `fmt()` 数字 |
| 库存余额 | `balance` | `fmt()` 数字；负值红色高亮 |
| 预警类型 | `alert_type` | `hue()` 徽章（六态：缺货/击穿最低/击穿安全=红，呆滞/超储=橙，无=中性） |
| 操作 | — | 无状态机 → 无行内流转动作列；命中预警行整行高亮（`alert_type !== '无'`） |

**交互**：任一过滤变化 → 重置回第 1 页重载；刷新 / 扫描成功后刷新当前页；空结果显示空态文案（不喷 toast）；`biz_date < 今日` 的历史已结束快照由后端 list 隐藏（未选日期时仅返回当日及以后，升序；选定具体历史日期可回看；BR-11，数据仍在库、不删除）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 预警徽章 / KV 分组体 / 操作页脚

**用途**：点物料号弹出，按 `material_no` + `biz_date` 调 `get`，展示**全部**业务字段（6 字段，无审计列）。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `material_no` + `biz_date` + `alert_type` 徽章 | 墨青头带，徽章 `hue()` |
| 基本信息 | `material_no` / `biz_date` | `.kv`；注明「物料号 + 日期复合主键 · 全局唯一」（BR-01）；`material_no` 注明「引用 md_material 主数据」；`biz_date` 注明「未来 3 个月自然日自动初始化，已结束日隐藏不删除」（BR-07 / BR-11） |
| 数量信息 | `inbound_qty` / `outbound_qty` / `balance` | `.kv`；`fmt()`；`inbound_qty` 注明「主计划月度需求（集中最迟入库日）+ 需求池已下达/生产中补库单」（BR-04）；`outbound_qty` 注明「当日待出库出库计划合计（outbound_plan）」（BR-05）；`balance` 注明「逐日递推 = 上日余额 + 入库 − 出库，起始锚定 ERP 自有仓库存」（BR-02 / BR-03 / BR-06） |
| 预警信息 | `alert_type` | `hue()` 徽章 + 注明「scan_alert 对照水位线回填，缺货 > 击穿最低 > 击穿安全取最严重」（BR-08 / BR-09） |
| 原始数据 | get 返回全量 JSON | 底部折叠（默认收起） |

**页脚 `.modal-ft`**：【关闭】。

### 2.3 操作区（刷新 / 批量刷新）—— 表单豁免

> **表单豁免说明**：本应用数据来源类型为「自动参考创建」，契约无 `create` / `update` / `set_*` / `import_batch` → **无创建 / 编辑业务表单**。本节为两个计算触发动作的操作弹窗（收集入参 + 展示结果摘要），非业务单据表单；`material_no` / `biz_date` / `inbound_qty` / `outbound_qty` / `balance` / `alert_type` 全为系统推演生成，**只读展示、不进任何表单**。

#### 2.3.1 刷新（单物料 refresh）

**用途**：以 ERP 库存为锚点，对单物料逐日推演未来 3 个月水位并落盘。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `material_no` | autocomplete 下拉（`md_material`，见 §4） | ★ 必填 | BR-10 主数据引用铁律，须存在 md_material |
| `biz_date` | date input，默认今日 | ★ 必填 | 推演起始日期，格式 YYYY-MM-DD |
| `opening_stock` | number input | 选填 | 留空则后端经 ERP `_load_inventory` 取自有仓成品库存（BR-03） |

- 提交成功：返回 `{material_no, biz_date, version_no, opening_stock, generated, rows}` → toast「已推演 N 日」→ 关闭弹窗 → 刷新当前列表。
- 错误：物料不存在 / 日期非法 / 无策略记录等由后端 `FdeError` 经 api.js 统一 toast，弹窗保持打开便于改后重试。

#### 2.3.2 批量刷新（整批 refresh_batch）

**用途**：对全量物料整批执行 refresh，完成后联动 scan_alert 预警扫描（击穿水位**自动创建**需求池补库单，无需人工确认）。

**免输入弹窗**：无表单字段——自动以**当天**为推演起始日期、**全量「正常」状态物料**为范围（后端 `biz_date` / `material_nos` 均缺省），弹窗仅展示口径说明 + 【批量刷新】按钮。

- 提交成功：返回 `{total, success, fail, success_materials, errors, replenishments}` → 弹摘要并保持打开：
  - 计数：物料总数 / 成功 / 失败 / 自动补库单张数；
  - **成功物料**（success_materials chips 列出）；
  - **失败物料**（errors 明细：物料号 + 原因）；
  - **触发补库的物料**（replenishments 按物料聚合，chips 显示「物料 × N 张」）。
- 批量过程逐物料独立，单物料失败不阻断整批，前端按摘要展示。

#### 2.3.3 扫描预警（scan_alert）—— 无前端入口

`scan_alert` 服务仍保留（对照三层水位回填 `alert_type`，击穿时 `demand_pool.create` 自动补库），但**前端不提供单独按钮/弹窗**：它由 `refresh_batch` 对每个刷新成功的物料内部联动调用。详情模态页脚仅保留【关闭】。

### 2.4 日历视图（单物料月历）—— 列表/日历 segmented 切换（默认日历）

**用途**：在列表上方以 segmented「列表 / 日历」切换，**默认进入日历视图**；日历视图针对**单个物料**，以月历方式直观查看库存随日期的波动。数据仍复用 `list(material_no, page/size 不传)`（返回该物料全序列，默认 `biz_date` 升序、从今天起，历史隐藏）。

- **物料选择**：单物料 autocomplete（复用 `matOptions/matMap`，`acShow='cal'`）；选定后 `loadCal` 拉全序列。
- **月份导航**：`◀ 上月 / 下月 ▶ / 回到本月`；月历游标 `cal.month`（YYYY-MM，默认当月）。
- **月历网格**：7 列（周一~周日）× 6 周（`buildMonthGrid` 生成 42 格，本月外 padding 置灰）。
- **单元格内容**：三行带中文标签——**预计库存量 / 预计入库量 / 预计出库量**（预计库存量为负标红加粗）；底色按 `alert_type`（缺货/击穿=红、击穿安全/超储=橙、无=白），今日格蓝框高亮。
- **三层水位**：选料后自动显示「最低 / 安全 / 组批上限」水位行（`inventory_strategy.get_water_level(version_no=当月YYYYMM, material_no)` quiet 取数）；无库存策略时显示「暂无库存策略水位」且不阻断日历主体。
- **交互**：点有数据的日 → 复用详情模态 `viewX(get)`；未选物料/无记录/载入中分别显示空态提示。
- **边界**：严格从今天起（BR-11），不显示历史；默认月 = 当月。

| 区块 | 调用（应用.服务） | 参数 | quiet | 说明 |
|---|---|---|---|---|
| 列表区 | `svc("inventory_projection","list")` | `{material_no, biz_date, alert_type, page, size}` | — | 过滤查询；空条件传 undefined 不带 |
| 详情模态 | `svc("inventory_projection","get")` | `{material_no, biz_date}` | — | 单日推移明细（6 字段） |
| 列表区 / 操作弹窗 | `svc("md_material","list")` | `{page:1, size:200}` | true | 物料下拉数据源，quiet 探测；**跨应用调用，字面量产生 psc:inventory_projection → md_material.list 派生边** |
| 操作弹窗 · 刷新 | `svc("inventory_projection","refresh")` | `{material_no, biz_date, opening_stock}` | — | 单物料逐日推演 90 天并落盘 |
| 操作弹窗 · 批量刷新 | `svc("inventory_projection","refresh_batch")` | `{}`（后端自动当天+全量物料） | — | 整批刷新 + 联动扫描（击穿触发补库） |
| 日历视图 | `svc("inventory_projection","list")` | `{material_no}`（不传 page/size → 全序列） | — | 单物料月历取数，`biz_date` 升序、从今天起 |
| 日历视图 · 水位 | `svc("inventory_strategy","get_water_level")` | `{version_no, material_no}` | true | 三层水位（最低/安全/组批上限）；**跨应用调用，字面量产生 psc:inventory_projection → inventory_strategy.get_water_level 派生边** |

> 以上 6 处必须在 view.js 中以字面量逐项书写（可包在闭包里），**勿用变量拼名**——这是页面授权隐式放行派生扫描的唯一来源。`scan_alert` 无前端入口（由 refresh_batch 内部联动），不产生前端 svc 调用。

## 4. 数据来源与下拉

**物料下拉（过滤条 / 操作弹窗 / 日历视图共用一份 matOptions / matMap）**：
- 页面初始化一次性 `svc("md_material","list")` `{page:1, size:200}`，`quiet:true` 探测：失败不喷 toast；零值兜底 → 过滤下拉仅「全部」、操作弹窗下拉显示「暂无可选物料」禁用项（提交时再 toast 提示）。
- 由返回项构建 `matMap = {material_no: material_name}`，供列表「物料号」列与详情模态名称回显；未命中则原样展示 material_no。
- 内联 autocomplete 实现要点：单独声明扁平数组 `matOptions`（禁止嵌套对象存储）、`@click.stop` 切换 + `@input` 实时过滤（同时匹配代号和名称）+ `@click.away` 关闭、选项双行「代号 + 名称」、选中回填 material_no（主数据引用铁律）。

**契约 payload → 区块字段映射**：

| 来源 | payload 字段 | 去向 |
|---|---|---|
| `inventory_projection.list` 项 | material_no, biz_date, inbound_qty, outbound_qty, balance, alert_type | 2.1 列表列（1:1） |
| `inventory_projection.get` | 同上（全量 6 字段） | 2.2 详情模态 KV 分组 + 原始数据折叠 |
| `inventory_projection.refresh` 返回 | material_no, biz_date, version_no, opening_stock, generated, rows | toast 展示 generated → 列表重载 |
| `inventory_projection.refresh_batch` 返回 | total, success, fail, errors, replenishments | 摘要弹窗 → 列表重载 |
| `inventory_projection.scan_alert` 返回 | material_no, version_no, scanned, breach_count, replenishments | toast 展示结果 → 列表重载（预警徽章回填） |
| `md_material.list` 项 | material_no, material_name | 物料下拉选项 + matMap |

- **快照/推导字段标注**：`inbound_qty` / `outbound_qty` / `balance` / `alert_type` 均为系统推演/扫描生成，任何写服务都不接受 → **只展示、不进表单**；本页无 `*_json` 快照字段，无需 `tryParse()`。

## 5. 交互要点

1. **计算触发按钮 loading**：刷新 / 批量刷新 / 扫描预警为后端计算动作（批量可能耗时），点击后按钮置 loading 防重复点击，完成后再刷新列表；中途错误由 api.js 统一 toast。
2. **主数据下拉 autocomplete**：material_no 一律走内联 autocomplete（主数据引用铁律），quiet 加载 + 零值兜底，失败不喷 toast；禁止普通 `<select>` 与手工录入。
3. **预警徽章配色（`hue()` 六态）**：缺货 / 击穿最低 / 击穿安全 = 红色（击穿警示），呆滞 / 超储 = 橙色（降储治理），无 = 中性；列表命中预警（`alert_type !== '无'`）的行整行高亮。
4. **逐日快照、已结束日隐藏**：`biz_date < 今日` 的历史行前端视觉隐藏（BR-11），仅作展示过滤、不删除数据；默认按 biz_date 升序展示未来 3 个月窗口。
5. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 预警徽章；原始数据折叠默认收起。
6. **展示工具**：`hue()`（alert_type 六态徽章）、`fmt()`（inbound_qty / outbound_qty / balance 数字，balance 负值红显）、无时间审计字段无需 `fmtTime()`、无 `*_json` 字段无需 `tryParse()`。
7. **toast**：刷新成功（已推演 N 日）/ 批量刷新摘要 / 扫描结果（扫描 N 日 · 击穿 M 日 · 补库 K 张）；其余错误一律由 api.js 统一呈现。

## 6. 验收关注点（供第⑧步）

1. **路由渲染**：`#/inventory_projection` 挂载出列表三段式（过滤条 + 表格 + 分页条），**断言无 `.kpi`**（非看板页防挂载粘滞假过）；菜单「🌊 库存推移表」按 order=140 定位。
2. **造数后列表有数据**：先造 md_material（正常状态物料）→ 点「刷新」对某物料 biz_date=今日 推演 → 列表出现该物料 90 天记录（material_no / biz_date / inbound_qty / outbound_qty / balance / alert_type 列齐全）。
3. **过滤一一对应**：material_no 下拉精确匹配；biz_date 输入精确匹配；alert_type=缺货 chips 仅缺货行（US-02-AC2）；组合条件；无匹配显示空态且不抛错。
4. **模态全字段**：点物料号开模态，断言 material_no / biz_date / inbound_qty / outbound_qty / balance / alert_type 全部可见 + 「原始数据」可展开；页脚【扫描预警】可用。
5. **刷新落库回显**：填 material_no + biz_date（★）→ 提交 → toast「已推演 90 日」→ 列表出现该物料未来 3 个月逐日记录（US-01-AC1）；物料不存在 → 后端 FdeError toast（BR-10）。
6. **扫描预警真实回显**：对已推演物料执行 scan_alert → alert_type 回填（缺货/击穿最低/击穿安全/超储按水位判定，US-03-AC1~AC3）→ 列表预警徽章更新、命中行高亮；击穿水位联动生成 demand_pool 补库单。
7. **无创建入口**：页面不存在「新建 / 编辑 / 删除」按钮或表单（自动参考创建，无 create/update/delete 服务），仅刷新 / 批量刷新 / 扫描预警三个操作按钮。
8. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP≥400（受限会话 403 属预期执法单独豁免）。
