## 1. 需求概览

### 1.1 基本信息
- **需求名称**: 库存推移表（预警引擎）
- **需求编号**: REQ-PSC-IP-001
- **所属模块**: 产销协同-需求池管理
- **需求来源**: 业务方（计划）
- **创建日期**: 2026-08-14
- **优先级**: P0

### 1.2 需求背景
#### 1.2.1 为什么需要这个需求？
主计划（净需求经产能平衡后的结果）是「总量」口径的静态规划，无法覆盖期间内的时点缺货。在产能紧平衡、库存结构尚未建立的阶段，会出现频繁的缺货或紧急补货，主计划驱动的生产计划并不能完全指导生产。需要一个按日推演库存水位的预警引擎，回答「何时缺货、何时击穿水位」的问题——总量靠净需求，时点靠推移表。

#### 1.2.2 期望达到什么目标？
以每日 0 点从 ERP 取的最新库存总额为锚点，逐日滚动推演未来 3 个月的库存水位，产出缺货 / 击穿水位 / 呆滞 / 超储预警，向下驱动需求池补库、向上支撑降储治理。

### 1.3 需求范围
#### 1.3.1 包含哪些功能？
库存推移表逐日推演（单物料 refresh + 整批 refresh_batch）、推移表明细/列表查看（get / list）、对照水位线扫描预警（scan_alert）。

#### 1.3.2 不包含哪些功能？
- 不做库存推移表的手工新建 / 编辑 / 删除（数据由系统逐日刷新推演，前端只读查看）
- 不做需求池补库单的管理（补库单生成后的状态流转属 `demand_pool` 聚合）
- 不做库存 / 在途 / 调拨单的源数据维护（来自 ERP 冗余同步，只读引用）

> **数据来源类型**: 自动参考创建 —— 每日 0 点系统自动刷新推演生成，用户无需手工触发；**前端禁止提供创建入口，只提供查看**。US/FUNC 清单不含 `create` 用户故事。

### 1.4 涉及角色
**谁会使用这个功能？**

- **计划（计划员）**: 查看库存推移表与预警结果，跟进需求池补库与超储降储治理。

## 2. 用户故事

### 2.1 核心用户故事

#### 2.1.1 `US-01` 用户故事 — 每日自动刷新库存推移表（优先级：P1）

- **故事描述**: 作为计划员，我想要系统每日 0 点自动刷新库存推移表，以便于始终基于 ERP 最新库存滚动推演未来 3 个月水位
- **为何赋予此优先级**：库存推移表是全体系预警引擎，逐日刷新保证起点与 ERP 实际库存一致、不累积误差，是所有查看与预警的基础
- **独立测试**：可通过触发 refresh（单物料）或 refresh_batch（整批），验证推演结果逐日递推正确且起始库存等于 ERP 库存来独立测试
- **前置条件**: 存在物料主数据（md_material）、主计划（master_plan）、库存策略（inventory_strategy）、需求池在途补库单、出库计划（outbound_plan）及 ERP 同步数据（库存）
- **后置条件**: 系统生成该物料未来 3 个月逐日库存推移记录，balance 满足递推公式，起始库存锚定 ERP 库存

**验收场景**：

1. `US-01-AC1` **场景**: 逐日递推一致
   - **Given** 物料 M 起始库存 100，未来某日入库 20、出库 30，**When** 执行 refresh，**Then** 该日 balance = 前一日 balance + 20 − 30，逐日递推链完整无断档

2. `US-01-AC2` **场景**: 起始库存锚定 ERP
   - **Given** ERP 当日 0 点自有仓成品库存总额为 100，**When** 执行 refresh_batch，**Then** 推演窗口首日 balance = 100，与 ERP 库存一致

3. `US-01-AC3` **场景**: 已结束日期隐藏不删除
   - **Given** 存在历史已结束日期的推移记录，**When** 查看列表/刷新，**Then** 已结束日期记录不删除，仅在前端隐藏显示

---

#### 2.1.2 `US-02` 用户故事 — 查看库存推移表（优先级：P1）

- **故事描述**: 作为计划员，我想要按物料/日期/预警类型筛选查看库存推移表列表与明细，以便于了解各物料未来水位走势与预警时点
- **为何赋予此优先级**：查看是预警引擎的消费入口，是计划员跟进补库与降储的日常基础操作
- **独立测试**：可通过进入库存推移表页面，使用物料号/日期/预警类型筛选并查看单日明细来独立测试
- **前置条件**: 系统已生成库存推移表记录
- **后置条件**: 返回符合条件的推移表列表，支持分页；可查看单物料单日明细

**验收场景**：

1. `US-02-AC1` **场景**: 按物料+日期查询明细
   - **Given** 存在物料 M 在日期 D 的推移记录，**When** 按 material_no=M、biz_date=D 查询，**Then** 返回该记录的入库/出库/余额/预警类型完整字段

2. `US-02-AC2` **场景**: 按预警类型筛选
   - **Given** 存在多条不同 alert_type 的推移记录，**When** 筛选 alert_type=缺货 后查询，**Then** 列表仅展示预警类型为「缺货」的记录

3. `US-02-AC3` **场景**: 按物料分页列表
   - **Given** 物料 M 存在 90 天推移记录，**When** 按 material_no=M 分页查询，**Then** 按日期升序分页返回，总数 = 90

---

#### 2.1.3 `US-03` 用户故事 — 扫描库存推移预警（优先级：P1）

- **故事描述**: 作为计划员，我想要系统对照水位线扫描库存推移表预警，以便于及时发现缺货/击穿水位并触发需求池补库、跟进超储降储
- **为何赋予此优先级**：预警扫描是推移表价值的落点——向下产出补库单、向上产出降储预警，缺它推移表只是展示无行动闭环
- **独立测试**：可通过对某物料执行 scan_alert，验证缺货/击穿最低/击穿安全/超储判定正确，并触发对应需求池补库来独立测试
- **前置条件**: 物料已有库存推移表记录，且存在 inventory_strategy 水位（A/C/B）
- **后置条件**: 推移表 alert_type 被回填；击穿水位（缺货/最低/安全）触发 demand_pool.create 生成补库单，超储/呆滞标记降储预警

**验收场景**：

1. `US-03-AC1` **场景**: 缺货判定
   - **Given** 某日 balance < 0，**When** 执行 scan_alert，**Then** 该日 alert_type=缺货，并触发 demand_pool.create（缺货补库）

2. `US-03-AC2` **场景**: 击穿最低/安全判定
   - **Given** 某日 balance 介于 A 与 A+C 之间（击穿安全），**When** 执行 scan_alert，**Then** 该日 alert_type=击穿安全，并触发 demand_pool.create（安全库存补库）

3. `US-03-AC3` **场景**: 超储判定
   - **Given** 某日 balance > B，**When** 执行 scan_alert，**Then** 该日 alert_type=超储，标记降储预警（不触发补库单）

## 3. 业务场景

### 3.1 业务流程描述

#### 3.1.1 场景1: 每日整批刷新推移表
1. 系统每日 0 点触发 refresh_batch
2. 系统调用 `_load_inventory` 适配器从 ERP 取当日最新库存总额（自有仓成品）
3. 系统遍历需推演的物料，为每个物料调用 refresh：以 ERP 库存为起始锚点，逐日推演未来 3 个月
4. 系统调用 `master_plan.get_latest` 取主计划月度需求量与最迟入库日期 → 生成预计入库量
5. 系统调用 `demand_pool.list` 取「待下达 / 已下达 / 生产中」补库单（在途）→ 并入预计入库量
6. 系统调用 `outbound_plan.list` 取「待出库」出库计划 → 生成预计出库量
7. 系统逐日计算 balance(t) = balance(t−1) + 入库(t) − 出库(t)，落盘
8. 系统调用 `scan_alert` 对照 `inventory_strategy.get_water_level` 水位扫描预警并回填 alert_type

#### 3.1.2 场景2: 计划员查看预警
1. 计划员进入「库存推移表」页面
2. 选择筛选条件：物料号、日期、预警类型（可选）
3. 点击查询
4. 系统返回符合条件的推移表列表（分页），命中预警的行高亮展示
5. 计划员点击目标行查看单日明细（入库/出库/余额/预警类型）
6. 对缺货/击穿行，计划员跟进需求池补库单；对超储/呆滞行，跟进降储治理

### 3.2 业务规则

#### 3.2.1 `BR-01` 推移表行唯一性
- **规则描述**: 库存推移表行以「物料号 + 日期」为复合主键，全局唯一
- **适用场景**: refresh / refresh_batch 落盘
- **示例**: 同一物料号在同一日期仅允许一条推移记录

#### 3.2.2 `BR-02` 库存余额逐日递推
- **规则描述**: 库存余额逐日递推，balance(t) = balance(t−1) + 预计入库量(t) − 预计出库量(t)
- **适用场景**: refresh / refresh_batch 逐日推演
- **计算方式**: 第 0 日（推演窗口首日）balance = 起始库存（ERP 最新库存总额）；其后每一自然日的 balance = 上一日 balance + 当日入库 − 当日出库
- **示例**: 起始库存 100，第 1 日入库 20、出库 30，则第 1 日 balance = 100 + 20 − 30 = 90；第 2 日入库 0、出库 50，则第 2 日 balance = 90 + 0 − 50 = 40

#### 3.2.3 `BR-03` 起始库存口径
- **规则描述**: 起始库存 = 每日 0 点从 ERP 取的最新库存总额（自有仓成品库存）
- **适用场景**: refresh / refresh_batch 起始锚点
- **示例**: ERP 当日 0 点返回自有仓成品库存 500 件，则推演首日 balance = 500

#### 3.2.4 `BR-04` 预计入库量口径
- **规则描述**: 预计入库量 = 主计划月度需求量（集中记在最迟入库日期当天）+ 需求池「待下达 / 已下达 / 生产中」补库单（在途）
- **适用场景**: refresh 计算每日 inbound_qty
- **计算方式**: 主计划月度需求量经 `master_plan.get_latest` 获取，将其集中记在该月「最迟入库日期」当天（不逐日分摊）；在途补库单经 `demand_pool.list(status=待下达/已下达/生产中)` 获取，按承诺入库日（无承诺则要求入库日）记入对应自然日
- **示例**: 物料 M 主计划某月需求 1000、最迟入库日期为 2026-09-30，则 2026-09-30 当天入库 +1000；另有生产中补库单 200 承诺 2026-09-15 入库，则 2026-09-15 入库 +200

#### 3.2.5 `BR-05` 预计出库量口径
- **规则描述**: 预计出库量 = 当日「待出库」出库计划合计（来源：outbound_plan 出库计划表，业务人员手工登记）
- **适用场景**: refresh 计算每日 outbound_qty
- **计算方式**: 经 `outbound_plan.list(material_no, status=待出库)` 获取，按计划出库日期记入对应自然日；已关闭计划不计入，关闭后经编辑延期恢复待出库会重新进入推演
- **示例**: 2026-09-20 有 2 张待出库出库计划，数量合计 300，则该日出库 = 300

#### 3.2.6 `BR-06` 库存余额口径（自有仓）
- **规则描述**: 库存余额口径 = 除调拨到客户仓之外，我方所有仓库的成品库存总和（即自有仓）；寄售仓的后续消耗由客户下一张调拨单体现，不在此单节点推演
- **适用场景**: 起始库存取数与逐日推演
- **示例**: 寄售仓现有库存不计入推移表余额；客户从寄售仓领用后，以新的调拨单（出库）形式体现在对应日期

#### 3.2.7 `BR-07` 推演窗口
- **规则描述**: 推移表自动初始化未来 3 个月所有自然日；每日 0 点整批刷新，保证起点与 ERP 实际库存一致、不累积误差
- **适用场景**: refresh / refresh_batch
- **示例**: 以 2026-08-14 为刷新日，推演窗口覆盖 2026-08-14 起未来 3 个月（约 90 个自然日）

#### 3.2.8 `BR-08` 预警水位线判定
- **规则描述**: 对照 inventory_strategy 水位线（最低 A / 安全 C / 组批 B）扫描预警：balance < 0 → 缺货；0 ≤ balance < A → 击穿最低；A ≤ balance < A+C → 击穿安全；balance > B → 超储；其余 → 无。水位来自 `inventory_strategy.get_water_level`
- **适用场景**: scan_alert
- **示例**: 水位 A=100、C=50、B=300：balance=-10 → 缺货；balance=60 → 击穿最低；balance=120 → 击穿安全；balance=400 → 超储

#### 3.2.9 `BR-09` 预警级别与取值
- **规则描述**: alert_type 枚举 = 无 / 缺货 / 击穿最低 / 击穿安全 / 呆滞 / 超储；同一日期同时命中多个水位时取最严重级别（优先级：缺货 > 击穿最低 > 击穿安全，与 BRD §6.2 一致）；缺货/击穿最低/击穿安全触发需求池补库，超储/呆滞标记降储预警
- **适用场景**: scan_alert 回填 alert_type
- **示例**: balance < 0 时同时满足「<A」「<A+C」，取「缺货」；「呆滞」的触发阈值 BRD 未明确定义，待确认（见 §6.3 / §7.4）

#### 3.2.10 `BR-10` 物料号主数据引用
- **规则描述**: material_no 必须引用物料主数据 `md_material`（主数据引用铁律），禁止手工录入
- **适用场景**: refresh / scan_alert 前的物料范围确定与校验
- **示例**: 推演物料范围取自 md_material.list 的正常状态物料；material_no 在 md_material 中不存在则拒绝推演

#### 3.2.11 `BR-11` 逐日快照，已结束日隐藏不删除
- **规则描述**: 推移表为逐日快照，无状态机；已结束的日期（biz_date < 今日）隐藏显示但不删除。隐藏由后端 list 承担：未选日期时仅返回 `biz_date >= 今日` 的行（默认从当天开始、按日期升序）；选定具体日期（含历史日期）时精确回看该日
- **适用场景**: 全部操作
- **示例**: 昨日（已结束）的推移记录仍保留在库，默认列表不显示；日期过滤选昨日可回看

### 3.3 业务数据

#### 3.3.1 数据1: 物料号 material_no
- **数据描述**: 被推演物料的唯一编码，与日期组成复合主键
- **数据类型**: 文本
- **数据来源**: 引用 `md_material`（主数据，来源：md_material.list 下拉选择）
- **示例值**: 8210001

#### 3.3.2 数据2: 日期 biz_date
- **数据描述**: 推移表日期（未来 3 个月自然日，自动初始化）
- **数据类型**: 日期
- **数据来源**: 系统自动初始化
- **示例值**: 2026-09-30

#### 3.3.3 数据3: 预计入库量 inbound_qty
- **数据描述**: 当日该品种所有入库合计（主计划月度需求集中记最迟入库日 + 需求池待下达/已下达/生产中补库单）
- **数据类型**: 数字
- **数据来源**: master_plan.get_latest + demand_pool.list（待下达/已下达/生产中）
- **示例值**: 1200

#### 3.3.4 数据4: 预计出库量 outbound_qty
- **数据描述**: 当日该品种所有「待出库」出库计划合计
- **数据类型**: 数字
- **数据来源**: outbound_plan.list（status=待出库，按计划出库日期）
- **示例值**: 300

#### 3.3.5 数据5: 库存余额 balance
- **数据描述**: 逐日推演的自有仓库存余额
- **数据类型**: 数字
- **数据来源**: 系统计算（起始=ERP 库存，其后逐日递推）
- **示例值**: 90

#### 3.3.6 数据6: 预警类型 alert_type
- **数据描述**: 对照水位线的预警结果
- **数据类型**: 枚举值
- **数据来源**: 系统扫描计算（scan_alert）
- **示例值**: 无 / 缺货 / 击穿最低 / 击穿安全 / 呆滞 / 超储

### 3.4 状态机
无状态机。库存推移表为逐日快照，无生命周期状态流转；已结束的日期隐藏显示但不删除（BR-11）。

### 4.3 功能详细说明

#### 4.3.1 F01-01 库存推移表

##### 4.3.1.1 FUNC-01 单物料刷新推演（refresh）

**功能描述**:
以 ERP 库存为锚点，对单个物料逐日推演未来 3 个月库存水位。此功能为自动参考创建——由系统触发，前端不提供手工入口。

**用户操作流程**:
1. 系统（或 refresh_batch 内部）以 material_no、biz_date 调用 refresh
2. 系统调用 `_load_inventory` 取 ERP 当日最新库存总额作为起始库存（opening_stock 亦可由调用方显式传入）
3. 系统调用 `master_plan.get_latest` 取主计划月度需求量与最迟入库日期
4. 系统调用 `demand_pool.list` 取「待下达 / 已下达 / 生产中」补库单（在途），按承诺/要求入库日期并入预计入库量
5. 系统调用 `outbound_plan.list` 取「待出库」出库计划，生成每日预计出库量
6. 系统逐日计算 balance(t) = balance(t−1) + 入库(t) − 出库(t)
7. 系统落盘逐日推移记录（material_no + biz_date 唯一）

**输入数据**:
- material_no: 物料号 - 必填，引用 md_material - 示例：8210001
- biz_date: 推演起始日期 - 必填 - 示例：2026-08-14
- opening_stock: 起始库存 - 来自 ERP `_load_inventory`（自有仓成品库存） - 示例：500

**输出数据**:
- 未来 3 个月逐日推移记录: material_no, biz_date, inbound_qty, outbound_qty, balance

**业务规则**:
- BR-01: 物料号+日期唯一
- BR-02: 逐日递推 balance(t) = balance(t−1) + 入库(t) − 出库(t)
- BR-03: 起始库存 = ERP 自有仓成品库存总额
- BR-04: 入库 = 主计划月度需求（集中最迟入库日）+ 在途工单
- BR-05: 出库 = 当日「待出库」出库计划合计（outbound_plan）
- BR-06: 库存余额口径 = 自有仓
- BR-07: 推演窗口 = 未来 3 个月自然日
- BR-10: material_no 引用 md_material

**特殊处理**:
- 主计划月度需求量集中记在最迟入库日期当天，不逐日分摊
- 需跨应用调用 master_plan.get_latest、demand_pool.list、outbound_plan.list、inventory_strategy.get_water_level（见 §7.3）
- 需 ERP 适配器 _load_inventory（起始库存锚点，见 §7.3）

**业务实体**:
- **InventoryProjection（库存推移表行）**: 物料×日期维度的逐日库存水位快照，含预计入库/出库/余额/预警类型，标识为 material_no + biz_date

**InventoryProjection 字段**

| 字段名称 | 字段类型 | 是否必填 | 默认值 | 业务逻辑 |
|---|---|---|---|---|
| material_no | 文本 | 是 | - | 物料号，复合主键（与 biz_date），来源：md_material.list 下拉选择（主数据引用铁律） |
| biz_date | 日期 | 是 | - | 日期，复合主键，未来 3 个月自然日自动初始化；已结束日隐藏不删除 |
| inbound_qty | 数字 | 是 | 0 | 预计入库量 = 主计划月度需求（集中最迟入库日）+ 需求池待下达/已下达/生产中补库单 |
| outbound_qty | 数字 | 是 | 0 | 预计出库量 = 当日「待出库」出库计划合计（outbound_plan） |
| balance | 数字 | 是 | - | 库存余额；起始 = ERP 自有仓成品库存，其后 = 上日余额 + 入库 − 出库 |
| alert_type | 枚举值 | 是 | 无 | 无 / 缺货 / 击穿最低 / 击穿安全 / 呆滞 / 超储；scan_alert 扫描后回填 |

##### 4.3.1.2 FUNC-02 整批刷新推演（refresh_batch）

**功能描述**:
每日 0 点定时任务，对全量需推演物料整批执行 refresh，保证推移表起点与 ERP 实际库存一致。

**用户操作流程**:
1. 系统每日 0 点触发 refresh_batch(biz_date)
2. 系统确定推演物料范围（md_material.list 正常状态物料）
3. 系统遍历物料，逐个调用 refresh(material_no, biz_date, opening_stock)
4. 系统在整批刷新完成后，对命中预警的物料执行 scan_alert
5. 系统记录刷新结果摘要（成功数/失败数/错误明细）

**输入数据**:
- biz_date: 推演起始日期 - 必填 - 示例：2026-08-14

**输出数据**:
- 刷新摘要: { total: N, success: N, fail: N, errors: [{ material_no, message }] }

**业务规则**:
- BR-02 ~ BR-07: 同 FUNC-01
- BR-10: 推演物料范围取自 md_material（正常状态物料）
- BR-11: 已结束日期隐藏不删除

**特殊处理**:
- 批量刷新逐物料独立事务，单物料失败不阻断其他物料（待确认，见 §6.3）
- 整批刷新后联动 scan_alert（预警扫描）

**业务实体**:
- **InventoryProjection**: 同 FUNC-01

**输入数据**:

**输出数据**:
- 明细字段: material_no, biz_date, inbound_qty, outbound_qty, balance, alert_type

**业务规则**:
- BR-01: 按复合主键（物料号+日期）定位

**特殊处理**:
- 无

**业务实体**:
- **InventoryProjection**: 同 FUNC-01

##### 4.3.1.4 FUNC-04 库存推移表列表查询（list）

**功能描述**:
按物料号、日期、预警类型等条件分页查看库存推移表列表。

**用户操作流程**:

**输出数据**:

**业务规则**:

**特殊处理**:

##### 4.3.1.5 FUNC-05 预警扫描（scan_alert）

**功能描述**:
对照 inventory_strategy 水位线（最低 A / 安全 C / 组批 B）扫描物料推移表，回填 alert_type；击穿水位（缺货/最低/安全）触发 demand_pool.create 生成补库单，超储/呆滞标记降储预警。

**用户操作流程**:
1. 系统（refresh 后或定时）以 material_no 调用 scan_alert
2. 系统调用 `inventory_strategy.get_water_level(version_no, material_no)` 取水位 A / C / B
3. 系统逐日比对 balance 与水位线，判定 alert_type
4. 系统回填 alert_type 到推移表
5. 命中缺货/击穿最低/击穿安全时，系统调用 demand_pool.create 生成补库单

**输入数据**:
- material_no: 物料号 - 必填 - 示例：8210001

**输出数据**:
- 该物料各日 alert_type 回填结果
- 补库单生成结果（缺货/最低/安全三类，交由 demand_pool）

**业务规则**:
- BR-08: 水位线判定（<0 缺货 / <A 击穿最低 / <A+C 击穿安全 / >B 超储）
- BR-09: 预警级别与取值（缺货 > 击穿最低 > 击穿安全）

**特殊处理**:
- 跨应用调用 inventory_strategy.get_water_level（取水位）与 demand_pool.create（生成补库单，见 §7.3）
- 补库量按产能松紧分档的规则属 demand_pool 聚合，本应用仅触发 create

**业务实体**:
- **InventoryProjection**: 同 FUNC-01（alert_type 回填）

## 6. 验收标准

### 6.1 功能验收标准

#### 6.1.1 标准1: 逐日递推一致性
- **关联用户故事**: US-01
- **关联业务规则**: BR-02, BR-03, BR-04, BR-05
- **验证方式**: 对单物料执行 refresh，逐日核对 balance 是否满足 balance(t) = balance(t−1) + 入库(t) − 出库(t)
- **测试数据**: 起始库存 100；第 1 日入库 20、出库 30；第 2 日入库 0、出库 50
- **预期结果**: 第 1 日 balance = 90，第 2 日 balance = 40，逐日递推链完整无断档

#### 6.1.2 标准2: 起始库存锚定 ERP
- **关联用户故事**: US-01
- **关联业务规则**: BR-03, BR-06
- **验证方式**: 执行 refresh_batch 后核对推演首日 balance 与 ERP 自有仓成品库存一致
- **测试数据**: ERP 当日 0 点自有仓成品库存 = 500
- **预期结果**: 推演首日 balance = 500

#### 6.1.3 标准3: 入库/出库口径
- **关联用户故事**: US-01
- **关联业务规则**: BR-04, BR-05
- **验证方式**: 核对主计划月度需求是否集中记在最迟入库日、需求池在途补库单是否按承诺/要求入库日记入、出库计划是否按日合计
- **测试数据**: 主计划需求 1000（最迟入库日 09-30）+ 生产中补库单 200（承诺 09-15 入库）；09-20 待出库出库计划合计 300
- **预期结果**: 09-15 入库 200、09-30 入库 1000、09-20 出库 300，其余日入库/出库为 0

#### 6.1.4 标准4: 预警水位线判定
- **关联用户故事**: US-03
- **关联业务规则**: BR-08, BR-09
- **验证方式**: 构造不同 balance 区间，执行 scan_alert 核对 alert_type
- **测试数据**: 水位 A=100、C=50、B=300；balance 分别取 -10 / 60 / 120 / 400
- **预期结果**: 依次判定为 缺货 / 击穿最低 / 击穿安全 / 超储；缺货行触发 demand_pool.create

#### 6.1.5 标准5: 已结束日期隐藏不删除
- **关联用户故事**: US-01, US-02
- **关联业务规则**: BR-11
- **验证方式**: 存在历史已结束日期记录时查看列表
- **测试数据**: 存在昨日（已结束）推移记录
- **预期结果**: 记录不删除；未选日期时列表仅显示当日及以后（升序），选定昨日日期可回看

### 6.2 非功能验收标准
**性能要求**: 整批 refresh_batch（全量物料）在可接受时间内完成（建议异步分批，见 §6.3）；单物料 list 查询（90 条以内）响应时间 < 2 秒
**安全性要求**: 无敏感数据加密需求；material_no 引用主数据，不可手工录入
**兼容性要求**: 支持 Chrome、Edge 浏览器

### 6.3 已知问题或限制
- 「呆滞」预警的触发阈值 BRD（§2.7）仅描述为「产出呆滞/超储预警驱动降储」，未给出具体判定公式，待业务方确认（暂标记待确认）
- 超储判定：BRD §4.2.3 描述「超过组批库存即超储」、§4.3 描述「上限 = 最低+安全+组批」，两者口径存在差异；本设计按 architecture.md 的「>B（组批水位）」执行，若以 A+C+B 为超储上限需业务方确认
- refresh_batch 单物料失败是否阻断整批（逐物料独立事务 vs 全批次回滚）待实施设计确认
- 整批刷新与策略拟合均为计算密集操作，异步任务队列与调度方式待实施设计确认（architecture.md Q5）
