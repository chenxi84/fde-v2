# 主计划 前端详设
> 来源：app/psc/_contracts.md（冻结契约）+ app/psc/master_plan/应用详设.md；产出供第⑦步前端编码 / 第⑧步前端测试用例。
> 落位：`app/psc/master_plan/view.js` + `app/psc/master_plan/view.html`（与 `master_plan.py` 同文件夹，落盘即进启动清单与授权清单，零接线）；import 一律绝对路径 `/view/lib/*`；模板经 `new URL("view.html", import.meta.url)` 抓取；工厂 `export default function pageMasterPlan()`（保留专名）。

## 1. 页面元数据 PAGE_META

key=master_plan / name=主计划 / ic=🗓 / title=主计划 / crumb=线下产能平衡结果导回 · 计划版本号版本化 / order=130

| 字段 | 值 | 说明 |
|---|---|---|
| key | `master_plan` | = 应用文件夹名，page_id 为 `psc:master_plan` |
| name | 主计划 | 侧栏菜单名 |
| ic | 🗓 | 菜单图标字 |
| title | 主计划 | 主区页面头 |
| crumb | 线下产能平衡结果导回 · 计划版本号版本化 | 头部副题 |
| order | 130 | 已按业务序预分配，直接用；升序即菜单序 |

- 页面零鉴权：无任何权限判断；菜单按页面授权渲染在 shell，数据闸门在后端，401 由 api.js 自动跳登录。受限角色「计划」可访问导入/列表/详情；页面不做角色判断（菜单收敛由 shell 负责）。
- 本应用契约**无 update / set_* / delete / create**，且数据来源类型为「手工参考创建」→ **无「新建」按钮、无编辑入口、无删除按钮**；唯一写入口为「导入」按钮（`import_plan` 批量行录入，版本 `plan_version` 由后端 +1 自动生成，不进表单）。
- 本应用**无显式状态机**（以 `plan_version` 表达版本演进）→ 列表行内动作与模态页脚**无任何状态流转按钮**。
- `get_latest` 为跨应用服务（供库存推移表 `inventory_projection` 取「预计入库量」），**前端不主动调、不设计入口**。

## 2. 区块构成

### 2.1 列表区（查）—— 三段式：过滤条 / 表格 / 分页条

**用途**：主计划台账，按月度版本、物料筛选查看各版本主计划行，默认最新版本在前。

**过滤控件（与 `master_plan.list(version_no, material_no, page, size)` 可过滤参数一一对应；契约无 keyword 参数 → 不设关键字搜索框，禁止前端假过滤）**：

| 控件 | 对应参数 | 选项 |
|---|---|---|
| 月度版本下拉 | `version_no` | 来自 `md_monthly_version.list` quiet 加载（见 §4）；选项 value=version_no，label=version_no（+ lock_status 小字）；精确匹配 |
| 物料号 autocomplete | `material_no` | 来自 `md_material.list` quiet 加载（见 §4）；内联 autocomplete 下拉（主数据引用铁律），选中回填 material_no；精确匹配 |
| 分页 | `page` / `size` | `pageable()` 分页条（契约签名 integer 型，照传即可） |

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集；字段序与详情/表单一致：单号→版本→归属→数量→时间）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 计划版本号 | `plan_version` | `.b-link`，点击开详情模态；正文「v{plan_version}」 |
| 物料号 | `material_no` | 编号正文 + materialMap 命中时附物料名称小字 |
| 月度版本 | `version_no` | 正文 |
| 滚动月度 | `rolling_month` | `hue()` 徽章（N+1/N+2/N+3 三色，或正文） |
| 需求量 | `plan_qty` | `fmt()` 数字 |
| 最迟入库日期 | `latest_inbound_date` | 正文（YYYY-MM-DD） |

**交互**：任一过滤变化 → 重置回第 1 页重载；导入成功后重置过滤重载列表；空结果显示空态文案（不喷 toast）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 版本徽章 / KV 分组体 / 只读页脚

**用途**：点列表行 `plan_version` 弹出，按主键 `get(plan_version, material_no, rolling_month)` 展示**全部**业务字段。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `material_no` + `plan_version` 徽章 | 墨青头带，徽章 `hue()`/正文「v{plan_version}」 |
| 主键信息 | `plan_version` / `material_no` / `rolling_month` | `.kv`；`material_no` 注明「引用 md_material 主数据」（BR-07） |
| 版本信息 | `version_no` | `.kv`，注明「导入时指定，承接净需求导出的月度版本」 |
| 数量信息 | `plan_qty` | `.kv`，`fmt()`；注明「计划生产量，≥0」（BR-06） |
| 时间信息 | `latest_inbound_date` | `.kv`，正文；注明「该批计划最迟完工入库时间，推移表据此记预计入库量」 |
| 原始数据 | get 返回全量 JSON | 底部折叠 |

**交互**：页脚 `.modal-ft` 无操作按钮（无状态机、无更新/删除）；本应用不展示审计字段（无 created_at 等，主计划仅 6 个业务字段）。

### 2.3 导入表单（增，唯一数据入口）—— 模态表单（批量行录入）

**用途**：覆盖 `import_plan(version_no, rows)` 接受的**全部**可写业务参数——顶部指定 `version_no`，主体为**批量行录入表格**，每行 = `material_no / rolling_month / plan_qty / latest_inbound_date`。表单顶部注明上游数据来源「净需求」（线下产能平衡结果导回）。

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `version_no`（表单头部） | 下拉（月度版本，来自 `md_monthly_version.list` quiet，见 §4） | ★ 必填 | BR-04；后端校验「月度版本不能为空」 |
| 行 · `material_no` | 内联 autocomplete（物料下拉，见 §4） | ★ 必填 | BR-04 / BR-07（后端经 md_material 校验存在，物料不存在时该行返回「物料不存在」错误明细） |
| 行 · `rolling_month` | select：N+1 / N+2 / N+3 | ★ 必填 | BR-05（枚举值与后端 `VALID_ROLLING_MONTHS` 完全一致） |
| 行 · `plan_qty` | number input，min=0 | ★ 必填 | BR-06（后端校验「需求量不能为空 / 必须为数字 / 不能为负」） |
| 行 · `latest_inbound_date` | date input（YYYY-MM-DD） | ★ 必填 | BR-04（后端校验「最迟入库日期不能为空 / 格式应为 YYYY-MM-DD」） |

- **不进表单**：`plan_version`（系统自动生成，导入时按「物料 × 滚动月度」取当前最大 +1，BR-02）、`version_no` 仅顶部一次指定（不逐行）。
- 批量行交互：行可**增删**（「+ 添加行」「删除行」），至少保留 1 行；提交时组装 `rows = [{material_no, rolling_month, plan_qty, latest_inbound_date}, ...]`。
- 布局：版本下拉先行 → 批量行表格 → 底部右对齐「导入」按钮；校验 = 必填红星 + toast 警告（版本为空或任一行必填为空不发请求，前端预校验仅覆盖「明显为空」，枚举/负值/日期格式/物料存在交由后端逐行校验返回错误明细）。
- 提交成功：toast 带出新版本号（`导入摘要` 返回 `{version_no, plan_version, success, fail, errors}`）→ 关闭模态 → 重置过滤重载列表（新版本 plan_version 更大，排在最新）；`fail > 0` 时 toast 展示「成功 {success} 行 / 失败 {fail} 行」，失败明细（`errors[]`）在模态内列表回显，不关闭模态。

## 3. svc 字面量清单（授权派生依据——必须字面量 svc("应用","服务")）

| 区块 | 调用（应用.服务） | 参数 | quiet | 说明 |
|---|---|---|---|---|
| 列表区 | `svc("master_plan","list")` | `{version_no, material_no, page, size}` | 否 | 过滤查询；空条件传 undefined 不带 |
| 列表区 / 导入表单 | `svc("md_monthly_version","list")` | `{page:1, page_size:200}` | 是 | 月度版本下拉数据源，quiet 探测；**跨应用调用，字面量产生 psc:master_plan → md_monthly_version.list 派生边** |
| 列表区 / 导入表单 | `svc("md_material","list")` | `{page:1, page_size:200}` | 是 | 物料 autocomplete 下拉数据源，quiet 探测；**跨应用调用，字面量产生 psc:master_plan → md_material.list 派生边** |
| 详情模态 | `svc("master_plan","get")` | `{plan_version, material_no, rolling_month}` | 否 | 全字段详情 |
| 导入表单 | `svc("master_plan","import_plan")` | `{version_no, rows}` | 否 | 导回线下产能平衡结果；返回 `{version_no, plan_version, success, fail, errors}` |

> 以上 5 处必须在 view.js 中以字面量逐项书写（可包在闭包里），**勿用变量拼名**——这是页面授权隐式放行派生扫描的唯一来源。
> `demand.export_net`（净需求导出）在 `import_plan` 服务**内部**由后端自动调用（失败不阻断导入），前端**不主动调、不列入清单**，仅在导入表单顶部文字标注上游来源「净需求」。
> `get_latest` 为跨应用服务（供库存推移表），前端不调用、不列入本页清单。

## 4. 数据来源与下拉

**月度版本下拉（过滤条与导入表单共用一份 versionOptions / versionMap）**：
- 页面初始化一次性 `svc("md_monthly_version","list")` `{page:1, page_size:200}`，`quiet:true` 探测：失败不喷 toast；零值兜底 → 过滤下拉仅「全部」、导入表单版本下拉显示「暂无可用月度版本」禁用项（提交时再 toast 提示）。
- 由返回项构建 `versionMap = {version_no: lock_status}`，选项 value=version_no、label=version_no（+ lock_status 小字）；仅用 `version_no` / `lock_status`（anchor_period / opening_date 不展示）。

**物料号 autocomplete 下拉（过滤条与导入表单共用一份 materialOptions / materialMap）**：
- 页面初始化一次性 `svc("md_material","list")` `{page:1, page_size:200}`，`quiet:true` 探测：失败不喷 toast；零值兜底 → 过滤下拉仅「全部」、导入表单物料下拉显示「暂无可用物料」禁用项（提交时再 toast 提示）。
- 实现要点（主数据引用铁律）：① 声明扁平数组 `materialOptions`（**禁止**嵌套对象 `autoOptions[field]`）；② `@click.stop` 展开/收起 + `@input` 实时过滤 + `@click.away` 关闭；③ 过滤同时匹配 `material_no` 与 `material_name`；④ 列表项显示「代号 + 名称」双行，选中后表单存 `material_no`；⑤ 选项 value=material_no、label=material_name。
- 由返回项构建 `materialMap = {material_no: material_name}`，供列表「物料号」列与详情模态名称回显；未命中则原样展示 material_no。

**契约 payload → 区块字段映射**：

| 来源 | payload 字段 | 去向 |
|---|---|---|
| `master_plan.list` 项 | material_no, version_no, rolling_month, plan_version, plan_qty, latest_inbound_date | 列表区表格列（1:1，全部 6 字段） |
| `master_plan.get` | 同上（全量 6 字段） | 详情模态全部 KV 分组 + 原始数据折叠 |
| `master_plan.import_plan` 返回 | version_no, plan_version, success, fail, errors | toast 展示新 plan_version + 成功/失败数；errors 明细在模态内回显 |
| `md_monthly_version.list` 项 | version_no, lock_status | 版本下拉选项 + versionMap |
| `md_material.list` 项 | material_no, material_name | 物料 autocomplete 选项 + materialMap |

- **快照/系统生成字段**：`plan_version`（系统自动生成，仅展示）——详情展示并注明「系统生成 · 版本演进 +1」，不进导入表单。
- **无 `*_json` 字段** → 本页无需 `tryParse()`；`plan_qty` 为金额/数量类字段 → 用 `fmt()`。

## 5. 交互要点

1. **导入即唯一写入口（数据来源铁律）**：列表顶部仅「导入」按钮，**无「新建」按钮**（BR-03）；导入表单顶部标注「数据来源：净需求（线下产能平衡结果导回）」。
2. **批量行录入**：导入表单内行为「增删行」的批量录入表格；提交前本地预校验「版本非空 + 每行 material_no/rolling_month/plan_qty/latest_inbound_date 非空」，其余（枚举非法、负数、日期格式、物料不存在）交由后端 `import_plan` 逐行校验，`errors` 回显为行级错误提示（`{row, field, message}`）。
3. **版本化感知**：导入成功后 toast 带出「已导入 · 新版本 v{plan_version}」；列表默认 `plan_version` 降序，新版本自然置顶。
4. **quiet 探测性加载**：version_no / material_no 两个下拉 quiet + 零值兜底，失败不喷 toast；主计划列表本身正常加载，错误走 api.js 统一通道。
5. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `plan_version` 徽章；页脚无操作按钮（无状态机、无更新/删除）。
6. **展示工具**：`hue()`（rolling_month 徽章）、`fmt()`（plan_qty）、`dash()`（无空字段，备用）；无 `*_json` 字段，无需 `tryParse()`；无 `fmtTime()` 字段（latest_inbound_date 为日期文本，原样展示）。
7. **toast**：导入成功 / 必填未填警告；其余错误（如「主计划记录不存在」「月度版本不能为空」）一律由 api.js 统一呈现。

## 6. 验收关注点（供第⑧步前端测试用例）

1. **路由渲染**：`#/master_plan` 挂载出列表三段式（过滤条 + 表格 + 分页条），**页面无 `.kpi`**（防看板挂载粘滞假过）；菜单「🗓 主计划」按 order=130 定位；列表顶部有「导入」按钮、**无「新建」按钮**。
2. **造数后列表有数据**：先造 md_material（物料）与 md_monthly_version（版本）→ 经 `import_plan` 导入主计划 → 列表行数正确，plan_version / material_no / version_no / rolling_month / plan_qty / latest_inbound_date 六列非空；默认按 plan_version 降序（最新版本在前）。
3. **过滤一一对应**：version_no=202608 下拉仅该版本行（US-02-AC1）；material_no 下拉选中某物料仅该物料行（US-02-AC2）；两条件 AND 组合；无匹配显示空态且不抛错。
4. **模态全字段**：点 `plan_version` 开模态，断言 material_no / version_no / rolling_month / plan_version / plan_qty / latest_inbound_date 全部可见 + 「原始数据」可展开；模态页脚无动作按钮（无状态机）。
5. **导入表单落库回显**：导入表单选 version_no + 批量行（material_no/rolling_month/plan_qty/latest_inbound_date，★）→ 提交 → 列表出现新版本且 plan_version 较旧版 +1（US-01-AC1）；首次导入 plan_version=1（US-01-AC2）；空版本/空行提交 → toast 警告且不发请求。
6. **逐行校验回显**：导入含非法行（物料不存在 / rolling_month=N+5 / plan_qty 为负 / 缺必填）→ 合法行入库、非法行错误明细按行回显、`success`/`fail` 计数正确（US-01-AC3 / AC4）。
7. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP≥400（受限会话 403 属预期执法单独豁免；页面不做任何鉴权判断）。
