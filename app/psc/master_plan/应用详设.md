## 1. 需求概览

### 1.1 基本信息
- **需求名称**: 主计划维护
- **需求编号**: REQ-PSC-MP-001
- **所属模块**: 产销协同-主计划维护
- **需求来源**: 业务方（计划）
- **创建日期**: 2026-08-14
- **优先级**: P0

### 1.2 需求背景
#### 1.2.1 为什么需要这个需求？

净需求还不是最终的生产指令，需经产能平衡（产能约束、优先级排序、产线排程）调整后才形成主计划。产能平衡在系统外线下完成，平衡后的结果需要导回系统，作为库存推移表「预计入库量」的输入来源。

#### 1.2.2 期望达到什么目标？

将线下产能平衡结果导回系统，按计划版本号版本化（每次变更 +1），使主计划可追溯、可回滚，并供库存推移表取预计入库量。

### 1.3 需求范围
#### 1.3.1 包含哪些功能？

主计划导入（导回线下产能平衡结果）、主计划列表查询、主计划单行详情查询、取最新计划版本。

#### 1.3.2 不包含哪些功能？

- 不做产能平衡（产能约束、优先级排序、产线排程均在系统外线下完成，本系统不自行生成主计划）
- 不做生产计划下达 ERP（由需求池 + 主计划共同驱动的生产计划下发属其他环节）

> **数据来源类型**: 手工参考创建 —— 主计划引用上游净需求结果（demand.export_net 导出供线下平衡），由用户手工决定何时导入线下产能平衡结果；前端保留「导入」入口，并标注上游数据来源（净需求）。

### 1.4 涉及角色
**谁会使用这个功能？**

- **计划**: 执行净需求导出、线下产能平衡后导回主计划、查看主计划列表与详情

## 2. 用户故事

### 2.1 核心用户故事

#### 2.1.1 `US-01` 用户故事 — 导入主计划（优先级：P1）

- **故事描述**: 作为计划，我想要将线下产能平衡结果导入系统形成主计划，以便于为库存推移表提供预计入库量
- **为何赋予此优先级**：主计划的唯一数据入口，无导入则主计划为空、下游库存推移表无预计入库来源
- **独立测试**：可通过执行一次合法导入，验证新版本生成且计划版本号 +1 来独立测试
- **前置条件**: 该月度版本已完成净需求导出（demand.export_net），且线下产能平衡已完成
- **后置条件**: 系统生成新版本主计划行，plan_version 在上一版本基础上 +1，旧版本保留可追溯

**验收场景**：

1. `US-01-AC1` **场景**: 合法导入成功，版本号递增
   - **Given** 当前 version_no=202608 已存在 plan_version=1 的主计划，**When** 计划导入同一月度版本的平衡结果（rows 含 material_no/rolling_month/plan_qty/latest_inbound_date），**Then** 系统生成 plan_version=2 的新版本，旧版本 v1 保留不覆盖

2. `US-01-AC2` **场景**: 首次导入版本号从 1 开始
   - **Given** version_no=202608 尚无任何主计划记录，**When** 执行导入，**Then** 新版本 plan_version=1，全部行入库

3. `US-01-AC3` **场景**: 导入行物料不存在被拒绝
   - **Given** 导入行 material_no=NOTEXIST 不存在于 md_material，**When** 执行导入，**Then** 该行导入失败并提示"物料不存在"，其余合法行正常入库

4. `US-01-AC4` **场景**: 非法滚动月度/缺失必填被拒绝
   - **Given** 导入行 rolling_month 为非法值或 plan_qty 缺失，**When** 执行导入，**Then** 该行导入失败并返回错误明细，其余合法行正常入库

**验收场景**：

1. `US-02-AC1` **场景**: 按月度版本筛选

2. `US-02-AC2` **场景**: 按物料号筛选

3. `US-02-AC3` **场景**: 分页查询
   - **Given** 主计划记录超过一页，**When** 查询指定 page/size，**Then** 返回对应页数据及 total 总数

#### 2.1.3 `US-03` 用户故事 — 查看主计划单行详情（优先级：P2）

- **故事描述**: 作为计划，我想要按计划版本号+物料+滚动月度查询单行主计划，以便于核对某条计划的精确数量与最迟入库日期
- **为何赋予此优先级**：详情查询是精确核对单条计划的辅助操作，依赖列表入口定位
- **独立测试**：可通过 get 查询一条已知主键的主计划行并验证返回字段来独立测试
- **前置条件**: 目标主计划行已存在
- **后置条件**: 返回该行的完整字段（plan_version/material_no/rolling_month/plan_qty/latest_inbound_date）

**验收场景**：

1. `US-03-AC1` **场景**: 按主键查询成功
   - **Given** 存在主计划行（plan_version=2, material_no=8210001, rolling_month=N+1），**When** 调用 get 查询，**Then** 返回该行完整字段

2. `US-03-AC2` **场景**: 查询不存在的行
   - **Given** 系统中不存在主键（plan_version=99, material_no=8210001, rolling_month=N+1），**When** 调用 get 查询，**Then** 返回空/提示"主计划记录不存在"

#### 2.1.4 `US-04` 用户故事 — 取最新计划版本（优先级：P2）

- **故事描述**: 作为计划（及下游库存推移表），我想要取某物料在指定月度版本的最新计划版本，以便于获取当前生效的预计入库量
- **为何赋予此优先级**：get_latest 是库存推移表 refresh 取「预计入库量」的跨应用入口，是本聚合对外供给的核心接口
- **独立测试**：可通过在存在多版本的物料上调用 get_latest，验证返回最大 plan_version 的行来独立测试
- **前置条件**: 该月度版本下该物料已存在至少一条主计划
- **后置条件**: 返回该物料最新 plan_version 的全部滚动月度行（N+1/N+2/N+3）

**验收场景**：

1. `US-04-AC1` **场景**: 返回最大版本号的行
   - **Given** version_no=202608、material_no=8210001 存在 plan_version=1 与 plan_version=2 两版，**When** 调用 get_latest，**Then** 返回 plan_version=2 的行，不返回 v1

2. `US-04-AC2` **场景**: 无主计划记录
   - **Given** version_no=202608、material_no=8210001 无任何主计划，**When** 调用 get_latest，**Then** 返回空列表

## 3. 业务场景

### 3.1 业务流程描述

#### 3.1.1 场景1: 导回主计划（净需求 → 线下产能平衡 → 主计划）

1. 净需求运算完成后，计划触发「导出净需求」（调用 demand.export_net(version_no)），取得净需求供线下产能平衡
2. 计划在系统外线下完成产能平衡（产能约束、优先级排序、产线排程，不在本系统）
3. 计划进入「主计划」页面，点击「导入」
4. 系统提示选择月度版本 version_no，并标注上游来源为「净需求」
5. 计划上传/填写平衡结果行（material_no, rolling_month, plan_qty, latest_inbound_date）
6. 系统逐行校验（物料存在、rolling_month 枚举、plan_qty 非负、必填）
7. 校验通过 → 生成新版本：plan_version 在上一版本基础上 +1，全部行落新版本，旧版本保留

#### 3.1.2 场景2: 库存推移表取预计入库量

1. 库存推移表每日 refresh 时，对每个物料调用 master_plan.get_latest(version_no, material_no)
2. 系统返回该物料最新 plan_version 的各滚动月度 plan_qty 与 latest_inbound_date
3. 库存推移表据此记「预计入库量」（主计划月度需求量集中记在最迟入库日期当天）

### 3.2 业务规则

#### 3.2.1 `BR-01` 主计划行唯一性
- **规则描述**: 主计划行由（plan_version + material_no + rolling_month）联合唯一，作为单行主键
- **适用场景**: 导入、查询
- **示例**: 同一 plan_version 下，material_no=8210001 在 N+1 月只能有一条主计划行

#### 3.2.2 `BR-02` 计划版本号单调递增
- **规则描述**: 每次导入（变更）生成新版本，plan_version 在上一版本基础上 +1，单调递增，不覆盖旧版本，保证版本可追溯、可回滚
- **适用场景**: 导入
- **示例**: 版本 v1 → 变更导入 → v2 → 再变更 → v3；旧版本 v1/v2 始终保留

#### 3.2.3 `BR-03` 主计划由线下产能平衡结果导回
- **规则描述**: 主计划数据来源为线下产能平衡结果，本系统不自行生成主计划（不提供"新建"按钮，仅提供"导入"入口）
- **适用场景**: 导入（数据来源铁律）
- **示例**: 主计划行只能由 import_plan 导回，不存在独立新建功能

#### 3.2.4 `BR-04` 必填字段校验
- **规则描述**: material_no、version_no、rolling_month、plan_qty、latest_inbound_date 为必填，不可为空
- **适用场景**: 导入
- **示例**: 导入行 plan_qty 为空 → 该行失败，提示"需求量不能为空"

#### 3.2.5 `BR-05` 滚动月度枚举约束
- **规则描述**: rolling_month 仅限 N+1 / N+2 / N+3
- **适用场景**: 导入
- **示例**: rolling_month=N+5 → 该行失败，提示"滚动月度仅支持 N+1/N+2/N+3"

#### 3.2.6 `BR-06` 需求量非负
- **规则描述**: plan_qty（计划生产量）必须 ≥ 0
- **适用场景**: 导入
- **示例**: plan_qty=-100 → 该行失败，提示"需求量不能为负"

#### 3.2.7 `BR-07` 物料主数据引用
- **规则描述**: material_no 必须引用 md_material 中已存在的物料（主数据引用铁律，禁止手工录入不存在的物料号）
- **适用场景**: 导入
- **示例**: material_no=NOTEXIST 不存在于 md_material → 该行失败，提示"物料不存在"

### 3.3 业务数据

#### 3.3.1 数据1: 物料号 material_no
- **数据描述**: 物料维度，主计划行的主键组成之一，引用物料主数据
- **数据类型**: 文本
- **数据来源**: md_material（主数据引用，导入行校验物料存在）
- **示例值**: 8210001

#### 3.3.2 数据2: 月度版本 version_no
- **数据描述**: 自然月版本，标识主计划所属计划周期
- **数据类型**: 文本
- **数据来源**: 导入时由计划指定（承接净需求导出的月度版本）
- **示例值**: 202608

#### 3.3.3 数据3: 滚动月度 rolling_month
- **数据描述**: 滚动计划期，N+1 / N+2 / N+3
- **数据类型**: 枚举值
- **数据来源**: 导入行指定
- **示例值**: N+1 / N+2 / N+3

#### 3.3.4 数据4: 计划版本号 plan_version
- **数据描述**: 计划版本号，每次变更 +1，表达版本演进（可追溯、可回滚）
- **数据类型**: 整数
- **数据来源**: 系统自动生成（导入时在上一版本基础上 +1）
- **示例值**: 1 / 2 / 3

#### 3.3.5 数据5: 需求量 plan_qty
- **数据描述**: 计划生产量，是库存推移表「预计入库量」的数量来源
- **数据类型**: 数字
- **数据来源**: 线下产能平衡结果
- **示例值**: 5000

#### 3.3.6 数据6: 最迟入库日期 latest_inbound_date
- **数据描述**: 该批计划的最迟完工入库时间，库存推移表据此记「预计入库量」
- **数据类型**: 日期
- **数据来源**: 线下产能平衡结果
- **示例值**: 2026-09-15

### 3.4 状态机
无显式状态机。主计划以「计划版本号（plan_version）」表达版本演进（每次变更 +1），无生命周期状态流转。

### 4.3 功能详细说明

#### 4.3.1 F01-01 主计划

##### 4.3.1.1 FUNC-01 导入主计划

**功能描述**:
提供主计划导入入口，用户将线下产能平衡结果导回系统。此功能为手工参考创建——前端保留「导入」入口，不提供「新建」按钮，并在导入表单标注上游数据来源（净需求）。

**用户操作流程**:
1. 用户进入「主计划」页面，点击「导入」按钮
2. 系统调用 demand.export_net(version_no) 导出净需求供线下产能平衡（标注上游来源）
3. 用户在线下完成产能平衡后，选择月度版本 version_no
4. 系统展示导入表单/上传入口，逐行录入 material_no, rolling_month, plan_qty, latest_inbound_date
5. 用户点击「导入」
6. 系统逐行校验：物料存在（BR-07）、必填（BR-04）、rolling_month 枚举（BR-05）、plan_qty 非负（BR-06）
7. 校验通过 → 系统生成新版本：plan_version = 上一版本 +1（BR-02），全部行落新版本；旧版本保留
8. 导入完成 → 系统返回结果摘要（成功数、失败数、错误明细、新版本号）

**输入数据**:
- version_no: 月度版本 - 必填 - 示例：202608
- rows[]: 平衡结果行列表，每行含 material_no, rolling_month, plan_qty, latest_inbound_date

**输出数据**:
- 新版本号: plan_version - 示例：2
- 导入摘要: { version_no, plan_version, success, fail, errors: [{ row, field, message }] }

**业务规则**:
- BR-01: 主计划行（plan_version + material_no + rolling_month）唯一
- BR-02: plan_version 单调递增（每次变更 +1，旧版本保留）
- BR-03: 主计划仅由线下产能平衡结果导回，本系统不自行生成
- BR-04: 必填字段校验
- BR-05: rolling_month 枚举约束（N+1/N+2/N+3）
- BR-06: plan_qty ≥ 0
- BR-07: material_no 引用 md_material 已存在物料

**特殊处理**:
- 导入前置：调用 `demand.export_net(version_no)` 导出净需求供线下产能平衡（跨应用调用，见 §7.3）
- 产能平衡在线下完成，本系统只接收平衡结果，不做产能约束/优先级排序/排程计算
- 版本化策略：每次导入生成新版本而非覆盖旧版本，实现版本可追溯、可回滚

**业务实体**:
- **MasterPlan**: 主计划行，标识为（plan_version + material_no + rolling_month），记录月度版本、需求量与最迟入库日期

**MasterPlan 字段**

| 字段名称 | 字段类型 | 是否必填 | 默认值 | 业务逻辑 |
|---|---|---|---|---|
| material_no | 文本 | 是 | - | 物料号，PK 之一；来源：md_material.list 下拉选择（导入行校验物料存在） |
| version_no | 文本 | 是 | - | 月度版本 YYYYMM，导入时指定 |
| rolling_month | 枚举值 | 是 | - | N+1 / N+2 / N+3，PK 之一 |
| plan_version | 整数 | 否（系统生成） | 1 | 计划版本号，每次导入变更 +1，单调递增，PK 之一 |
| plan_qty | 数字 | 是 | - | 需求量（计划生产量），≥ 0 |
| latest_inbound_date | 日期 | 是 | - | 最迟入库日期（该批计划最迟完工入库时间） |

##### 4.3.1.2 FUNC-02 主计划列表查询

**功能描述**:
提供主计划的分页列表，支持按月度版本、物料号筛选。

**用户操作流程**:
1. 用户进入「主计划」列表页
2. 用户可选填写筛选条件：version_no（精确匹配）、material_no（精确匹配）
3. 用户点击「查询」
4. 系统返回符合条件的主计划列表（分页）

**输入数据**:
- version_no: 月度版本 - 选填，精确匹配 - 示例：202608
- material_no: 物料号 - 选填，精确匹配 - 示例：8210001
- page: 页码 - 默认1
- size: 每页条数 - 默认20

**输出数据**:
- 列表字段: plan_version, material_no, rolling_month, plan_qty, latest_inbound_date
- 分页信息: total, page, size

**业务规则**:
- 筛选条件均为可选，条件之间 AND 关系

**特殊处理**:
- 默认按 plan_version 降序排列（最新版本在前）

**业务实体**:
- **MasterPlan**: 同上 FUNC-01

**MasterPlan 列表展示字段**

| 展示字段 | 字段来源 | 可筛选 | 说明 |
|---|---|---|---|
| 计划版本号 | plan_version | 否 | 版本演进标识 |
| 物料号 | material_no | 是（精确） | PK |
| 滚动月度 | rolling_month | 否 | N+1/N+2/N+3 |
| 需求量 | plan_qty | 否 | 计划生产量 |
| 最迟入库日期 | latest_inbound_date | 否 | 显示用 |

##### 4.3.1.3 FUNC-03 主计划详情查询

**功能描述**:
按主键（plan_version + material_no + rolling_month）查询单行主计划详情。

**用户操作流程**:
1. 用户在列表页点击目标行 → 进入详情
2. 系统按主键 get(plan_version, material_no, rolling_month) 返回完整字段
3. 用户查看该行 plan_qty、latest_inbound_date 等明细

**输入数据**:
- plan_version: 计划版本号 - 必填
- material_no: 物料号 - 必填
- rolling_month: 滚动月度 - 必填

**输出数据**:
- 完整字段: plan_version, material_no, version_no, rolling_month, plan_qty, latest_inbound_date

**业务规则**:
- BR-01: 主键唯一，按主键精确定位

**特殊处理**:
- 主键不存在时返回空/提示"主计划记录不存在"

---

##### 4.3.1.4 FUNC-04 取最新计划版本

**功能描述**:
按（version_no + material_no）取该物料在指定月度版本的最新 plan_version 的全部滚动月度行，供库存推移表取「预计入库量」。

**用户操作流程**:
1. 库存推移表 refresh 时，对物料调用 get_latest(version_no, material_no)
2. 系统定位该物料最大 plan_version，返回该版本下全部 rolling_month 行

**输入数据**:
- version_no: 月度版本 - 必填
- material_no: 物料号 - 必填

**输出数据**:
- 最新版本行列表: [{ plan_version, material_no, rolling_month, plan_qty, latest_inbound_date }]

**业务规则**:
- BR-01: 取最大 plan_version 的行（同一物料可能有多个滚动月度行）
- 无记录时返回空列表

**特殊处理**:
- 被库存推移表（inventory_projection）refresh 跨应用调用，取预计入库量（见 §7.2）

## 6. 验收标准

### 6.1 功能验收标准

#### 6.1.1 标准1: 主计划导入与版本递增
- **关联用户故事**: US-01
- **关联业务规则**: BR-01, BR-02, BR-03, BR-04, BR-05, BR-06, BR-07
- **验证方式**: 对同一 version_no 连续导入两次平衡结果
- **测试数据**: version_no=202608，material_no=8210001，rolling_month=N+1，plan_qty=5000，latest_inbound_date=2026-09-15
- **预期结果**: 首次导入生成 plan_version=1；第二次导入生成 plan_version=2，旧版本 v1 保留

#### 6.1.2 标准2: 导入行校验（物料不存在/非法枚举/负数量）
- **关联用户故事**: US-01
- **关联业务规则**: BR-04, BR-05, BR-06, BR-07
- **验证方式**: 导入含非法行的混合数据（物料不存在、rolling_month 非法、plan_qty 为负、缺必填）
- **测试数据**: 3 行合法 + 4 行非法（各一类）
- **预期结果**: 合法行入库，非法行失败并返回对应错误明细

#### 6.1.3 标准3: 列表与详情查询
- **关联用户故事**: US-02, US-03
- **关联业务规则**: BR-01
- **验证方式**: 按 version_no/material_no 筛选列表，按主键查详情
- **测试数据**: version_no=202608，material_no=8210001
- **预期结果**: 列表返回匹配行，详情返回完整字段；不存在的行返回空/提示不存在

#### 6.1.4 标准4: 取最新计划版本
- **关联用户故事**: US-04
- **关联业务规则**: BR-01
- **验证方式**: 对存在多版本的物料调用 get_latest
- **测试数据**: version_no=202608，material_no=8210001 存在 v1、v2
- **预期结果**: 返回 v2 的行，不返回 v1；无记录物料返回空列表

### 6.2 非功能验收标准
**性能要求**: 列表查询页面加载时间<2秒；get_latest 单物料查询响应时间<1秒（供推移表批量调用）
**安全性要求**: 主计划数据不可由前端直接新建，仅允许「导入」入口导回；版本历史不可删除
**兼容性要求**: 支持 Chrome、Edge 浏览器

### 6.3 已知问题或限制
- 产能平衡（产能约束、优先级排序、产线排程）不在本系统，线下完成后导回，本系统只做版本化与只读引用
- 计划版本号粒度（按物料还是按整版本递增）待业务方确认（architecture.md Q6，当前按物料×滚动月度）
- 主计划历史版本不提供删除/物理覆盖，仅保留版本链（可追溯、可回滚）
