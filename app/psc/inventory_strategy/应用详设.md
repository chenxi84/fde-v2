## 1. 需求概览

### 1.1 基本信息
- **需求名称**: 库存策略（三层水位计算与品种分层）
- **需求编号**: REQ-PSC-IS-001
- **所属模块**: 产销协同-库存策略
- **需求来源**: 业务方（计划/财务）
- **创建日期**: 2026-08-14
- **优先级**: P0

### 1.2 需求背景
#### 1.2.1 为什么需要这个需求？
销售预测天然不可能准确。库存策略用合理的水位设置去弥补预测的不准确性，在不显著抬高成本的前提下守住客户服务水平——为每个物料回答「存多少、什么时候补」。三层库存（最低 A / 安全 C / 组批 B）各自对应一个独立的不确定源（响应缺口 / 需求波动 / 切线成本），必须分列计算与诊断，不能混为一谈。

#### 1.2.2 期望达到什么目标？
按物料×月度版本自动计算三层水位，判定品种分层（库存对冲 vs 速度对冲），产出月度库存策略表，供毛需求叠加与库存推移表对照水位线。

### 1.3 需求范围
#### 1.3.1 包含哪些功能？
单物料库存策略计算、整版本批量计算、库存策略详情查看、库存策略列表查询、取三层水位（供下游应用调用）。

#### 1.3.2 不包含哪些功能？
- 不做手工录入/编辑水位值的「新建」「编辑」表单（水位为系统计算派生值）
- 不做组批窗口/水位的回测拟合（由 `strategy_fitting` 应用负责，拟合结果回填物料主数据）
- 不做库存逐日推演与补库单（由 `inventory_projection` / `demand_pool` 应用负责）

> **数据来源类型**: 自动参考创建 —— 系统按物料参数（md_material）+ 客户缓冲参数（md_customer）+ 历史干净需求（_load_sales_history）自动计算水位，前端不提供手工录入水位的"新建"表单，只提供**查看 + 计算/重算**。

### 1.4 涉及角色
**谁会使用这个功能？**

- **计划**: 触发单物料/整版本水位计算与重算，查看库存策略列表与详情，据此判断补货与组批节奏
- **财务**: 只读查看库存策略（水位带、超储上限），用于评估库存持有成本与降储治理

## 3. 业务场景

### 3.1 业务流程描述

#### 3.1.1 场景1: 计算单物料库存策略
1. 计划进入"库存策略"列表页，筛选目标物料
2. 计划选择物料+版本，点击"计算/重算"
3. 系统调用 md_material.get 取物料参数（生产/物流时间、满足率目标、组批窗口、价值/变更风险等）
4. 系统调用 md_customer.get 取客户线边库存天数/调拨提前期（可用缓冲，默认0）
5. 系统调用 _load_sales_history 取近 N 期（默认12个月）干净需求
6. 系统按公式计算日需求、响应窗口波动 σ_L、服务系数、三层水位 A/C/B
7. 系统判定品种分层（对冲工具：库存/速度），生成设定依据
8. 系统同事务落库（version_no + material_no），返回结果

#### 3.1.2 场景2: 整版本批量计算库存策略
1. 计划进入"库存策略"页，选择月度版本，点击"整版本计算"
2. 系统确定该版本物料范围（md_material 正常状态物料）
3. 系统逐物料执行与场景1相同的取数+计算
4. 成功的物料落库，失败的物料记录错误明细（物料号+原因）
5. 系统返回摘要（成功数、失败数、错误明细）

#### 3.1.3 场景3: 查看库存策略
1. 计划/财务进入"库存策略"列表页
2. 填写筛选条件（版本、物料、对冲工具），点击"查询"
3. 系统返回策略列表（物料、对冲工具、三层水位、水位带）
4. 用户点击某行进入详情，查看完整参数与设定依据

### 3.2 业务规则

#### 3.2.1 `BR-01` 库存策略行唯一性
- **规则描述**: version_no + material_no 复合主键唯一；同一物料同一月度版本仅一条库存策略记录，重复 calc 覆盖更新（重算），不新增行
- **适用场景**: calc / calc_batch 落表
- **示例**: 版本202608物料8210001已有记录，再次 calc 同版本同物料 → 覆盖该行

#### 3.2.2 `BR-02` 日需求计算
- **规则描述**: 日需求 = 近 N 期（默认 12 个月）月均干净需求 ÷ 30（自然日）；月均取简单算术平均；干净需求=剔除一次性脉冲事件后的需求
- **适用场景**: 计算 A、B 时
- **计算方式**: 日需求 = (Σ 近 N 期干净需求 / N) ÷ 30
- **示例**: 近12月干净需求合计36000件 → 月均3000 → 日需求 = 100 件/日

#### 3.2.3 `BR-03` 最低库存 A 公式
- **规则描述**: 最低库存 A = 日需求 × max(0, 生产时间 + 物流时间 − 可用缓冲天数)
- **适用场景**: 所有物料的最低库存计算
- **计算方式**: 见公式；生产时间、物流时间取自物料主数据（md_material.prod_days / logistics_days）
- **示例**: 日需求100，生产5天+物流3天=8天，可用缓冲0 → A = 100 × 8 = 800

#### 3.2.4 `BR-04` 可用缓冲天数取值
- **规则描述**: 可用缓冲天数默认 0；来源客户线边库存天数（md_customer.line_stock_days），仅在与客户有明确稳定缓冲协议时扣减；寄售仓已计入当前库存，不重复计入缓冲
- **适用场景**: 最低库存 A 计算
- **示例**: 客户线边库存天数=2，生产+物流=8天 → A = 日需求 × max(0, 8−2) = 日需求 × 6

#### 3.2.5 `BR-05` 响应窗口 L 折算为月
- **规则描述**: 响应窗口 L = 生产时间 + 物流时间，折算为与历史需求一致的月期数：L(月) = (生产时间 + 物流时间) ÷ 30（自然日）
- **适用场景**: 响应窗口需求波动 σ_L 计算
- **示例**: 生产5天+物流3天=8天 → L ≈ 0.27 月

#### 3.2.6 `BR-06` 响应窗口需求波动 σ_L（滚动累计标准差，方法二推荐）
- **规则描述**: 响应窗口内需求波动 σ_L 采用滚动累计法（方法二，推荐）：构造连续 L 期的累计需求序列 S_i = D_i + … + D_{i+L-1}，σ_L = std(S)；不依赖"各期独立"假设，可正确捕捉需求自相关。单期 σ 采用近 N 期干净需求样本标准差 σ = √( Σ(x_i − x̄)² / (n−1) )（方法一 σ_L = σ×√L 仅作参考，趋势/季节下易失真）
- **适用场景**: 安全库存 C 计算
- **示例**: 近12月干净需求构造滚动 L 期累计序列，std(S)=50 → σ_L = 50

#### 3.2.7 `BR-07` 服务系数映射（满足率目标→标准正态分位数）
- **规则描述**: 服务系数由满足率目标查标准正态分位数表：90%→1.28，95%→1.65，98%→2.05，99%→2.33
- **适用场景**: 安全库存 C 计算
- **示例**: 满足率目标95% → 服务系数 = 1.65

#### 3.2.8 `BR-08` 安全库存 C 公式
- **规则描述**: 安全库存 C = 服务系数 × 响应窗口需求波动（σ_L）
- **适用场景**: 所有物料的安全库存计算
- **计算方式**: 见公式
- **示例**: 服务系数1.65 × σ_L=50 → C = 82.5

#### 3.2.9 `BR-09` 组批库存 B 公式
- **规则描述**: 组批库存 B = 日需求 × 组批窗口（天）；组批窗口来源物料主数据（经验值），经济批量模型 T=√(2S/(h·d)) 仅作窗口上限参考；B 是水位上限而非要补到的目标量，超过即超储
- **适用场景**: 组批库存计算
- **计算方式**: 见公式
- **示例**: 日需求100 × 组批窗口30天 → B = 3000

#### 3.2.10 `BR-10` 水位带
- **规则描述**: 下限（补货触发线）= A + C；上限（组批封顶线）= A + C + B；库存低于下限触发补货（最低/安全补库），高于上限即超储、不再组批并触发降储预警
- **适用场景**: 供毛需求叠加与库存推移表对照
- **示例**: A=800, C=82.5, B=3000 → 下限=882.5，上限=3882.5

#### 3.2.11 `BR-11` 品种分层对冲工具判定
- **规则描述**: 低价值+低变更风险→库存对冲（设齐 A/B/C 三层，B 为大头）；高价值+生产周期短→速度对冲（可只设 A(+C)，B=0 不组批）；近 EOP/高变更风险→组批窗口强制收缩、清尾防减值
- **适用场景**: calc / calc_batch 时判定 hedge_tool
- **示例**: 价值分类=低、变更风险=低 → hedge_tool=库存；价值分类=高、生产时间短 → hedge_tool=速度

#### 3.2.12 `BR-12` 不设安全库存硬条件
- **规则描述**: 当 生产时间 + 物流时间 ≤ 客户线边库存天数 + 调拨提前期 时，可不设安全库存（C 可为 0），以速度对冲；需按品种量化核对，价值高不自动豁免
- **适用场景**: 速度对冲物料的 C 判定
- **示例**: 生产2天+物流1天=3天 ≤ 线边2天+调拨2天=4天 → 可不设安全库存（C=0）

#### 3.2.13 `BR-13` 三层水位同事务一致性
- **规则描述**: 同一物料×版本的最低 A / 安全 C / 组批 B 三层同源于同一批参数与历史，须同一次事务算出并落库，保证三层一致，不得分层独立编辑
- **适用场景**: calc / calc_batch

#### 3.2.14 `BR-14` 对冲工具枚举约束
- **规则描述**: hedge_tool 仅限"库存" / "速度"
- **适用场景**: calc / calc_batch 落表
- **示例**: hedge_tool=其他 → 拒绝

#### 3.2.15 `BR-15` 计算参数合法性校验
- **规则描述**: 生产时间、物流时间、组批窗口 ≥ 0；满足率目标须为支持值（90%/95%/98%/99%）；日需求、服务系数、σ_L 计算结果 ≥ 0；组批窗口为 0 时 B=0（不组批）
- **适用场景**: calc / calc_batch 前置校验
- **示例**: 生产时间为负 → 拒绝计算并提示"生产时间不能为负"

#### 3.2.16 `BR-16` 版本有效性校验
- **规则描述**: version_no 须为有效月度版本（引用 md_monthly_version），计算前校验版本存在
- **适用场景**: calc / calc_batch 前置校验
- **示例**: version_no=209999 不存在 → 拒绝计算并提示"月度版本不存在"

### 3.3 业务数据

#### 3.3.1 数据1: 三层水位（A/C/B）
- **数据描述**: 最低库存 A、安全库存 C、组批库存 B 三档水位，共同构成库存水位带
- **数据类型**: 数量（件）
- **数据来源**: 系统按公式自动计算（BR-03/BR-08/BR-09）
- **示例值**: A=800, C=82.5, B=3000

#### 3.3.2 数据2: 对冲工具 hedge_tool
- **数据描述**: 品种分层判定的对冲工具（库存/速度），决定是否设齐三层
- **数据类型**: 枚举值
- **数据来源**: 系统按物料价值/变更风险/生产周期判定（BR-11）
- **示例值**: 库存 / 速度

#### 3.3.3 数据3: 服务系数 service_factor
- **数据描述**: 由满足率目标查标准正态表得到的系数
- **数据类型**: 数字
- **数据来源**: 满足率目标（md_material.service_level）→ 查表（BR-07）
- **示例值**: 1.65（满足率95%）

#### 3.3.4 数据4: 响应窗口需求波动 resp_volatility
- **数据描述**: 响应窗口 L 期内需求的滚动累计标准差 σ_L
- **数据类型**: 数字
- **数据来源**: 历史干净需求派生（BR-06）
- **示例值**: 50

#### 3.3.5 数据5: 日需求（派生）
- **数据描述**: 近 N 期月均干净需求 ÷ 30，为 A/B 计算的公共基数
- **数据类型**: 数字（件/日）
- **数据来源**: 物料销售历史派生（BR-02）
- **示例值**: 100 件/日

#### 3.3.6 数据6: 组批窗口 batch_window
- **数据描述**: 组批生产的窗口天数，决定 B 的上限
- **数据类型**: 数字（天）
- **数据来源**: 物料主数据（md_material.batch_window，经验值；经济批量模型作上限参考）
- **示例值**: 30 天

### 3.4 状态机

无状态机。库存策略为月度计算、版本化记录，无生命周期状态流转；同一物料×版本重复 calc 即重算覆盖。

### 4.3 功能详细说明

#### 4.3.1 F01-01 水位计算

##### 4.3.1.1 FUNC-01 计算单物料库存策略

**功能描述**:
对指定物料+月度版本计算三层水位（最低 A / 安全 C / 组批 B）与品种分层对冲工具判定。此功能为自动参考创建——前端不提供手工录入水位的"新建"表单，只提供"计算/重算"按钮触发。

**用户操作流程**:
1. 计划进入"库存策略"列表页，选择物料+版本，点击"计算/重算"
2. 系统调用 md_monthly_version.get 校验版本有效
3. 系统调用 md_material.get(material_no) 取物料参数（生产/物流时间、满足率目标、组批窗口、价值分类、变更风险、单位货值、切线成本）
4. 系统调用 md_customer.get(customer_no) 取客户线边库存天数/调拨提前期（可用缓冲，默认0）
5. 系统调用 _load_sales_history(material_no, 近N期) 取历史干净需求
6. 系统按公式计算日需求、响应窗口波动 σ_L、服务系数、三层水位 A/C/B
7. 系统按品种分层判定 hedge_tool（库存/速度），生成设定依据 basis
8. 系统同事务落库（version_no + material_no），返回结果

**输入数据**:
- version_no: 月度版本 - 必填，来源 md_monthly_version - 示例：202608
- material_no: 物料号 - 必填，来源 md_material - 示例：8210001
- 物料参数（md_material.get）: prod_days 生产时间(天)、logistics_days 物流时间(天)、service_level 满足率目标、batch_window 组批窗口(天)、value_class 价值分类、change_risk 变更风险、unit_value 单位货值、change_cost 切线成本
- 客户参数（md_customer.get）: line_stock_days 线边库存天数(可用缓冲，默认0)、transfer_lead_days 调拨提前期(天)
- 历史干净需求（_load_sales_history）: 近 N 期（默认12个月）月度干净需求序列

**输出数据**:
- min_level: 最低库存 A - 示例：800
- safety_level: 安全库存 C - 示例：82.5
- batch_level: 组批库存 B - 示例：3000
- service_factor: 服务系数 - 示例：1.65
- resp_volatility: 响应窗口波动 σ_L - 示例：50
- hedge_tool: 对冲工具 - 示例：库存
- 水位带: 下限 A+C / 上限 A+C+B（派生） - 示例：882.5 / 3882.5
- basis: 设定依据（参数来源与依据备注）

**业务规则**:
- BR-01: 版本+物料唯一，重复 calc 覆盖更新
- BR-02~BR-12: 日需求/A/C/B/水位带/分层/硬条件等全部计算公式
- BR-13: 三层同事务一致落库
- BR-14~BR-16: 枚举/参数合法性/版本有效性校验

**特殊处理**:
- 速度对冲物料（BR-11/BR-12）: C 可为 0、B=0 不组批，hedge_tool=速度
- 可用缓冲天数默认 0，仅客户有明确缓冲协议时按 line_stock_days 扣减（BR-04）
- 计算参数与历史通过跨应用调用/适配器获取，不手工录入

**业务实体**:
- **InventoryStrategy**: 物料×月度版本的三层水位与对冲工具判定结果，标识 version_no + material_no

**InventoryStrategy 字段**

| 字段名称 | 字段类型 | 是否必填 | 默认值 | 业务逻辑 |
|---|---|---|---|---|
| version_no | 文本 | 是 | - | 月度版本 YYYYMM，来源 md_monthly_version；与 material_no 组成复合主键 |
| material_no | 文本 | 是 | - | 物料号，来源 md_material.get/list 选择；与 version_no 组成复合主键 |
| hedge_tool | 枚举值 | 是 | 库存 | 库存\|速度，系统按品种分层判定（BR-11），禁止手工录入 |
| min_level | 数字 | 是 | 0 | 最低库存 A = 日需求 × max(0, 生产+物流−缓冲)（BR-03） |
| service_factor | 数字 | 是 | 1.65 | 服务系数，满足率目标查标准正态表（BR-07） |
| resp_volatility | 数字 | 是 | 0 | 响应窗口需求波动 σ_L，滚动 L 期累计标准差（BR-06） |
| safety_level | 数字 | 是 | 0 | 安全库存 C = 服务系数 × σ_L（BR-08） |
| batch_window | 数字 | 是 | 0 | 组批窗口（天），来源 md_material.batch_window |
| batch_level | 数字 | 是 | 0 | 组批库存 B = 日需求 × 组批窗口（BR-09） |
| basis | 文本 | 否 | - | 设定依据，参数来源与依据备注（如"生产5天+物流3天，满足率95%，组批窗口30天"） |

> **主数据引用铁律**：material_no 关联参数（生产时间 prod_days、物流时间 logistics_days、满足率目标 service_level、组批窗口 batch_window、单位货值 unit_value、切线成本 change_cost、价值分类 value_class、变更风险 change_risk）均来源 md_material；可用缓冲天数与"不设安全硬条件"所需的线边库存天数 line_stock_days / 调拨提前期 transfer_lead_days 来源 md_customer。以上均禁止手工录入，只能引用主数据。

##### 4.3.1.2 FUNC-02 整版本批量计算

**功能描述**:
对指定月度版本下所有物料批量计算库存策略，月度滚动时一次性生成整张策略表。

**用户操作流程**:
1. 计划进入"库存策略"页，选择月度版本，点击"整版本计算"
2. 系统调用 md_monthly_version.get 校验版本有效
3. 系统确定物料范围（md_material 正常状态物料）
4. 系统逐物料执行 FUNC-01 的取数+计算逻辑
5. 成功物料落库，失败物料记录错误明细（物料号+原因）
6. 系统返回摘要（成功数、失败数、错误明细）

**输入数据**:
- version_no: 月度版本 - 必填
- 物料范围: 由 md_material.list(status=正常) 确定

**输出数据**:
- 计算摘要: { total: N, success: N, fail: N, errors: [{ material_no, message }] }

**业务规则**:
- BR-01~BR-16: 逐物料同 FUNC-01 的规则
- 单个物料失败不影响其余物料（失败物料记录错误，可重算）

**特殊处理**:
- 计算量大，触发方式（定时/手动）与任务队列实现待实施设计确认（对应 architecture 待确认 Q5）
- 月度版本已发布/冻结时是否允许重算，随 md_monthly_version 锁定状态约束（待确认）

**业务实体**:
- **InventoryStrategy**: 同上 FUNC-01

##### 4.3.2.2 FUNC-04 库存策略列表查询

## 6. 验收标准

### 6.1 功能验收标准

#### 6.1.1 标准1: 三层水位计算正确
- **关联用户故事**: US-01
- **关联业务规则**: BR-02, BR-03, BR-06, BR-07, BR-08, BR-09
- **验证方式**: 用固定参数执行 calc，核对三层水位
- **测试数据**: 生产5天+物流3天、满足率95%、组批窗口30天、近12月月均干净需求3000件、σ_L=50
- **预期结果**: 日需求=100、A=800、服务系数=1.65、C=82.5、B=3000

#### 6.1.2 标准2: 品种分层判定正确
- **关联用户故事**: US-01
- **关联业务规则**: BR-11, BR-12
- **验证方式**: 分别对低价值低风险物料与高价值短周期物料执行 calc
- **测试数据**: 物料A（价值低/风险低/生产5+物流3），物料B（价值高/生产2+物流1、线边2+调拨2）
- **预期结果**: 物料A hedge_tool=库存、三层齐全；物料B hedge_tool=速度、B=0、C=0

#### 6.1.3 标准3: 批量计算成功+失败混合场景
- **关联用户故事**: US-02
- **关联业务规则**: BR-15, BR-16
- **验证方式**: 对含5物料（4正常+1缺历史）的版本执行 calc_batch
- **测试数据**: 版本202608，4个物料参数齐全，1个物料历史数据缺失
- **预期结果**: 4个成功落库，1个失败并返回错误明细（物料号+原因）

#### 6.1.4 标准4: 取三层水位接口
- **关联用户故事**: US-05
- **关联业务规则**: BR-01
- **验证方式**: 下游调用 get_water_level(202608, 8210001)
- **测试数据**: 已存在 A=800/C=82.5/B=3000 记录
- **预期结果**: 返回 {min_level:800, safety_level:82.5, batch_level:3000} 及水位带上下限

### 6.2 非功能验收标准
**性能要求**: 单物料 calc 响应时间<5秒；整版本 calc_batch 支持异步/任务队列执行
**安全性要求**: 水位为系统计算派生值，前端不可手工录入/篡改；仅计划可触发计算
**兼容性要求**: 支持 Chrome、Edge 浏览器

### 6.3 已知问题或限制
- **多客户物料的客户缓冲取值待确认**：库存策略为物料级（version_no + material_no），而可用缓冲/不设安全硬条件参数来自客户（md_customer.line_stock_days / transfer_lead_days）；一个物料可能服务多个客户时取哪个客户的缓冲参数，需业务方确认（默认按 0 处理）
- **N 历史窗口期数、年持有费率属策略配置参数**：本期取值默认 N=12、缓冲默认0，参数配置化管理待业务方确认（对应 architecture 待确认 Q3）
- **calc_batch 调度与任务队列**：计算量大需异步，触发方式（定时/手动）与实现待实施设计确认（对应 architecture 待确认 Q5）

- `_load_sales_history` 适配器 - ERP 历史干净需求：取近 N 期月度干净需求（计算日需求、σ、响应窗口波动）

### 7.4 备注
- 本应用数据来源类型为"自动参考创建"，US/FUNC 不含 create 用户故事，前端无手工录入水位的"新建"表单，只提供查看 + 计算/重算
- 状态机：无（月度计算，版本化记录，重复 calc 即重算覆盖）
- 主数据引用铁律：material_no 相关参数标注 md_material 来源；customer_no 相关参数（线边/调拨提前期）标注 md_customer 来源；历史需求经 _load_sales_history 适配器访问（非聚合、非跨应用调用）
