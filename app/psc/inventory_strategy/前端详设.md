# 库存策略 前端详设
> 来源：app/psc/_contracts.md（冻结契约）+ app/psc/inventory_strategy/应用详设.md；产出供第⑦步前端编码 / 第⑧步前端测试用例。
> 落位：`app/psc/inventory_strategy/view.js` + `view.html`（与 `inventory_strategy.py` 同文件夹，落盘即进启动清单与授权清单，零接线）。

## 1. 页面元数据 PAGE_META
key=inventory_strategy / name=库存策略 / ic=🎚 / title=库存策略 / crumb=三层水位(最低/安全/组批) · 品种分层(库存/速度对冲) / order=110

- 页面零鉴权：无任何权限判断；菜单按页面授权渲染在 shell，数据闸门与「计划可计算 / 财务只读」的权限差异由后端闸门执法（详设 §5，`psc:inventory_strategy:calc` / `calc_batch` / `query`），401 由 api.js 自动跳登录。
- 数据来源类型「自动参考创建」→ 本应用契约**无 create / update / set_* / import_batch / delete** → 无「新建/编辑」表单；水位为系统计算派生值、禁止手工录入（详设 §1.3.2、BR-13），前端只提供「计算 / 批量计算」按钮 + 列表 + 详情。
- 无状态机（详设 §3.4）：月度版本化记录，同一物料×版本重复 `calc` 即重算覆盖，行内无状态流转动作。

## 2. 区块构成

### 2.1 列表区（查）—— 三段式：计算入口条 / 过滤条 / 表格 / 分页条

**用途**：库存策略台账，按版本 / 物料 / 对冲工具筛选浏览各物料三层水位与水位带，承载单物料计算/重算入口。

**计算入口条（列表顶部，替代创建表单；见 §2.3）**：版本下拉 + 物料 autocomplete +【计算】+【批量计算】按钮。

**过滤控件（与 `inventory_strategy.list(version_no, material_no, hedge_tool, page, size)` 可过滤参数一一对应；契约无 keyword 参数 → 不设独立关键字搜索框）**：

| 控件 | 对应参数 | 选项 |
|---|---|---|
| 版本下拉 | `version_no` | 来自 `md_monthly_version.list` quiet 加载（见 §4）；精确匹配 |
| 物料 autocomplete | `material_no` | 来自 `md_material.list` quiet 加载（见 §4）；选中回填完整物料号（后端 LIKE 模糊匹配） |
| 对冲工具 chips | `hedge_tool` | 全部 / 库存 / 速度（BR-14 枚举，原值传参） |
| 分页 | `page` / `size` | `pageable()` 分页条 |

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集；字段序：版本→物料→分层→水位→参数→操作）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 版本 | `version_no` | `.mono` 正文 |
| 物料 | `material_no` | `.b-link`，点击开详情模态（带 version_no + material_no） |
| 对冲工具 | `hedge_tool` | `hue()` 徽章（库存 / 速度双色） |
| 最低水位 A | `min_level` | `fmt()` |
| 安全水位 C | `safety_level` | `fmt()` |
| 组批水位 B | `batch_level` | `fmt()` |
| 下限 A+C | `lower` | `fmt()`（派生值，注明「补货触发线」） |
| 上限 A+C+B | `upper` | `fmt()`（派生值，注明「组批封顶线」） |
| 服务系数 | `service_factor` | 正文 |
| 响应波动 σ_L | `resp_volatility` | `fmt()` |
| 组批窗口 | `batch_window` | 正文 + 「天」单位 |
| 操作 | — | 行内【重算】按钮（对该行 version+material 触发 `calc`，见 §5） |

- `basis`（设定依据）为长文本，不进列表列，仅详情展示（列表列 ⊆ 详情字段集仍成立）。

**交互**：任一过滤变化 → 重置回第 1 页重载；计算/重算成功后刷新当前页；空结果显示空态文案（不喷 toast）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 分层徽章 / KV 分组体 / 页脚

**用途**：点 `material_no` 弹出，展示 `inventory_strategy.get` 返回的**全部**业务字段（含派生水位带）。

**头带**：`material_no` + `version_no`（`docno`）+ `hedge_tool` 徽章（`hue()`）。

**KV 分组（`.kv` + `.sec`，get 全字段）**：

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 版本与物料 | `version_no` / `material_no` | `.kv`；均注明「主数据引用：md_monthly_version / md_material」 |
| 品种分层 | `hedge_tool` | 徽章 `hue()`，注明「系统判定，禁止手工录入」（BR-11/BR-14） |
| 三层水位 | `min_level`(最低A) / `safety_level`(安全C) / `batch_level`(组批B) | `.kv`，`fmt()`；速度对冲物料 B=0（BR-12） |
| 水位带（派生） | `lower`(下限 A+C) / `upper`(上限 A+C+B) | `.kv`，`fmt()`，注明「派生值，不单独存储（BR-10）；下限=补货触发线、上限=组批封顶线」 |
| 计算参数 | `service_factor`(服务系数) / `resp_volatility`(响应窗口波动 σ_L) / `batch_window`(组批窗口·天) | `.kv` |
| 设定依据 | `basis` | 多行文本，空值 `dash()` |
| 原始数据 | get 返回全量 JSON | 底部折叠 |

**页脚**：无状态机 → 无状态操作按钮；放置【重算】按钮（对该记录 version_no + material_no 触发 `calc`，成功后用返回对象原地刷新模态 + 列表行）。

### 2.3 计算入口（替代创建/编辑表单 —— 自动参考创建豁免）

**表单区豁免理由**：数据来源类型为「自动参考创建」，三层水位/对冲工具均为系统计算派生值，禁止手工录入（详设 §1.3.2、§4.3.1、BR-13）；契约无任何写服务接受业务参数（`calc` 仅接受计算定位键 version_no + material_no，不接受水位值）→ 无「新建/编辑」表单，改以「计算入口条」承载计算动作。

**计算入口控件**：

| 字段 | 控件 | 必填 | 约束来源 |
|---|---|---|---|
| `version_no` | 版本下拉（md_monthly_version，见 §4） | ★ 必填 | BR-16 版本有效性（YYYYMM，后端校验） |
| `material_no` | 物料 autocomplete（md_material，见 §4） | ★ 必填（仅单物料计算时） | 主数据引用铁律；后端 `md_material.get` 校验存在性 |

**动作**：
- 【计算】：校验 version_no + material_no 非空（空则 toast 警告、不发请求）→ 调 `calc(version_no, material_no)`；不传 `customer_no`（可选，前端不收集 —— 可用缓冲默认 0，多客户缓冲取值「待确认」见详设 §6.3）。
- 【批量计算】：仅需 version_no（material_no 留空即批量语义）→ 调 `calc_batch(version_no)`；成功后 toast 摘要「成功 N / 失败 M」，失败明细（物料号+原因）以 toast 或可展开列表呈现（详设 US-02-AC2）。

**不进入口**：`hedge_tool` / `min_level` / `service_factor` / `resp_volatility` / `safety_level` / `batch_window` / `batch_level` / `basis` / `lower` / `upper` —— 全部系统派生，仅详情展示。

## 3. svc 字面量清单（授权派生依据——必须字面量 svc("应用","服务")）

| 区块 | 调用（应用.服务） | 参数 | quiet | 说明 |
|---|---|---|---|---|
| 列表区 | `svc("inventory_strategy","list")` | `{version_no, material_no, hedge_tool, page, size}` | — | 过滤查询；空条件传 undefined 不带 |
| 版本下拉（过滤条 + 计算入口） | `svc("md_monthly_version","list")` | `{page:1, page_size:200}` | true | 版本选项源；**跨应用调用，字面量产生 psc:inventory_strategy → md_monthly_version.list 派生边** |
| 物料 autocomplete（过滤条 + 计算入口） | `svc("md_material","list")` | `{page:1, page_size:200}` | true | 物料选项源；**跨应用调用，字面量产生 psc:inventory_strategy → md_material.list 派生边** |
| 详情模态 | `svc("inventory_strategy","get")` | `{version_no, material_no}` | — | 全字段详情（含 lower/upper 派生值） |
| 计算入口 / 行内重算 / 模态页脚 | `svc("inventory_strategy","calc")` | `{version_no, material_no}` | — | 单物料计算/重算（BR-01 覆盖更新） |
| 计算入口（批量计算） | `svc("inventory_strategy","calc_batch")` | `{version_no}` | — | 整版本批量计算，返回 {total, success, fail, errors} |

> 以上 6 处必须在 view.js 中以字面量逐项书写（可包在闭包里），**勿用变量拼名**——这是页面授权隐式放行派生扫描的唯一来源。
> `get_water_level` 为跨应用服务（供 demand.build_gross / inventory_projection.refresh 对照水位线），**前端不主动调**，不进 svc 字面量清单。

## 4. 数据来源与下拉

**版本下拉（过滤条与计算入口共用一份 versionOptions）**：
- 页面初始化一次性 `svc("md_monthly_version","list")` `{page:1, page_size:200}`，`quiet:true` 探测：失败不喷 toast；零值兜底 → 下拉仅「全部」/禁用项（计算时再 toast 提示无版本）。
- 选项 value=version_no，label=version_no（可附 lock_status 小字，本页仅用 `version_no`）。

**物料 autocomplete（过滤条与计算入口共用一份 materialOptions）**：
- 页面初始化一次性 `svc("md_material","list")` `{page:1, page_size:200}`，`quiet:true` 探测，失败静默降级为空数组。
- 主数据选择铁律：内联 autocomplete 下拉（点击输入框弹出匹配列表、输入关键字过滤、选中回填），**禁止**普通 `<select>`；独立扁平数组 `materialOptions`，**禁止**嵌套对象存储；`@click.stop` 切换 + `@input` 过滤 + `@click.away` 关闭；过滤同时匹配 `material_no` 与 `material_name`；列表项显示「物料号 + 物料名」双行，选中后表单存 `material_no`。
- 过滤条场景：选中回填完整 `material_no` 提交（后端 LIKE 命中）；也可直接输入关键字回车按模糊提交（后端 LIKE）。

**契约 payload → 区块字段映射**：

| 来源 | payload 字段 | 去向 |
|---|---|---|
| `inventory_strategy.list` 项 | version_no, material_no, hedge_tool, min_level, service_factor, resp_volatility, safety_level, batch_window, batch_level, basis, lower, upper | 列表区表格列（basis 除外）+ 详情模态入参 |
| `inventory_strategy.get` | 同上（全量，含 lower/upper） | 详情模态全部 KV 分组 + 原始数据折叠 |
| `inventory_strategy.calc` 返回 | 策略记录（新水位 + hedge_tool + basis + lower/upper） | toast 展示 → 刷新列表 / 原地更新已开模态 |
| `inventory_strategy.calc_batch` 返回 | {total, success, fail, errors[]} | toast 摘要 + 失败明细提示 → 刷新列表 |
| `md_monthly_version.list` 项 | version_no | 版本下拉选项 |
| `md_material.list` 项 | material_no, material_name | 物料 autocomplete 选项 |

## 5. 交互要点

1. **计算/重算动作（无状态机，恒可用）**：
   - 计算入口条【计算】：version_no + material_no 必填校验（空则 toast 警告、不发请求）→ `calc` → 成功 toast「已计算 · {material_no}」+ 刷新列表；
   - 列表行内【重算】与模态页脚【重算】：取该行 `version_no + material_no` 触发 `calc`（重复计算覆盖更新，BR-01）→ 成功刷新列表 / 原地更新模态字段；
   - 计算参数非法（生产时间负 / 满足率不支持 / 版本不存在）由后端 FdeError 经 api.js 统一 toast（BR-15/BR-16），页面不硬编码校验逻辑。
2. **批量计算**：仅 version_no 必填 → `calc_batch` → 成功 toast「批量计算完成：成功 N / 失败 M」；M>0 时以 toast 或可展开列表列出 `errors[]`（物料号+原因），单个失败不中断其余（US-02-AC2）。
3. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 分层徽章。
4. **quiet 探测性加载**：版本下拉 / 物料 autocomplete 均 `quiet:true` + 零值兜底，失败不喷 toast；策略列表本身正常加载，错误走 api.js 统一通道。
5. **展示工具**：`hue()`（对冲工具徽章）、`fmt()`（三层水位与水位带数值）、`dash()`（空 basis）；本页无 `*_json` 快照字段、无时间字段、无状态字段，无需 `tryParse()` / `fmtTime()`。
6. **toast**：计算成功 / 批量计算摘要 / 必填未填警告；其余错误一律由 api.js 统一呈现。

## 6. 验收关注点（供第⑧步前端测试用例）

1. **路由渲染**：`#/inventory_strategy` 挂载出列表三段式（计算入口条 + 过滤条 + 表格 + 分页条），**页面无 `.kpi`**（防看板挂载粘滞假过）；菜单「🎚 库存策略」按 order=110 定位。
2. **造数后列表有数据**：先造 md_material（M1，生产5+物流3、满足率95%、组批窗口30）+ md_monthly_version（202608）→ 经 `calc` 计算 → 列表出现该行，version_no / material_no / hedge_tool / min_level / safety_level / batch_level 列非空。
3. **过滤一一对应**：version_no=202608 仅该版本行；material_no 选中某物料仅该物料行；hedge_tool=库存 chips 仅库存对冲行（US-04-AC1/AC2）；无匹配显示空态且不抛错。
4. **模态全字段**：点 material_no 开模态，断言 version_no / material_no / hedge_tool / min_level / safety_level / batch_level / lower / upper / service_factor / resp_volatility / batch_window / basis 全部可见 + 「原始数据」可展开；lower=A+C、upper=A+C+B（US-03-AC1）。
5. **计算落库回显**：计算入口选版本+物料点【计算】→ 列表出现/更新该行、toast 出现（US-01-AC1）；空版本或空物料提交 → toast 警告且不发请求；对不存在的物料计算 → 后端 FdeError toast（BR-15）。
6. **批量计算**：选版本点【批量计算】→ toast 摘要「成功 N / 失败 M」→ 列表该版本物料策略记录均已生成（US-02-AC1）。
7. **重算覆盖**：对已有记录行点【重算】→ 行数与主键（version_no+material_no）不变、水位刷新（BR-01）。
8. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP≥400（受限会话 403 属预期执法单独豁免；财务角色页面仅展示、计算按钮由后端闸门执法，页面不做任何判断）。
