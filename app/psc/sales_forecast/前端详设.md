# 销售预测 前端详设
> 来源：app/psc/_contracts.md（冻结契约）+ app/psc/sales_forecast/应用详设.md；产出供第⑦步前端编码 / 第⑧步前端测试用例。
> 落位：`app/psc/sales_forecast/view.js` + `app/psc/sales_forecast/view.html`（与 `sales_forecast.py` 同文件夹，落盘即进启动清单与授权清单，零接线）；import 一律绝对路径 `/view/lib/*`；模板经 `new URL("view.html", import.meta.url)` 抓取；工厂 `export default function pageSalesForecast()`（保留专名）。

## 1. 页面元数据 PAGE_META

| 字段 | 值 | 说明 |
|---|---|---|
| key | `sales_forecast` | = 应用文件夹名，page_id 为 `psc:sales_forecast` |
| name | 销售预测 | 侧栏菜单名 |
| ic | 📈 | 菜单图标字 |
| title | 销售预测 | 主区页面头 |
| crumb | 预测清单→处理→汇总 · 四种方法/异常决策/断点追溯 | 头部副题 |
| order | 100 | 已按业务序预分配，直接用；升序即菜单序 |

- 页面零鉴权：无任何权限判断；菜单按页面授权渲染在 shell，数据范围（客户仅本客户、一线销售仅代填负责客户、总部计划全量）由后端闸门执法，401 由 api.js 自动跳登录。
- **无独立 `create` / `update` / `delete` / `import_batch`**：本应用是「手工参考创建」型（数据来源类型），"创建"入口即 `open_version`（开启月度版本），行级变更仅经加工动作（fill_customer / calc_baseline / adjust_event / decide / set_final）+ 版本级 `summarize`。
- **无独立状态列**：行是否可编辑随 `md_monthly_version.lock_status`（草稿才可写，发布（锁定）/冻结只读），前端经 versionMap 判定，不硬编码状态机校验（非法写操作由后端 FdeError 统一 toast）。

## 2. 区块构成

### 2.1 列表区（处理表）—— 三段式：工具栏 + 过滤条 / 表格 / 分页条

**用途**：处理表台账（复合键 version_no+material_no+customer_no+rolling_month），承载逐行加工动作与版本级汇总入口。

**工具栏（列表顶部）**：
- 【开启版本】→ 打开「开启版本」模态（§2.3.1）
- 【新建组合】→ 打开「新建组合」模态（§2.3.2，手工补充 物料×客户 组合，客户可空）
- 【批量导入客户原始预测】→ 粘贴/上传 CSV 导入 orig_qty
- 【批量算基线】/【批量决策】→ 对当前版本全量行执行 `calc_baseline_batch` / `decide_batch`
- 【汇总】→ 打开「版本汇总」模态，选版本（草稿）执行 `summarize`，toast 显示 `summary_rows`
- 【查看汇总】→ 打开「汇总查询」模态，选版本（可再选物料）执行 `get_summary`，表格展示汇总行

**过滤控件（与 `sales_forecast.list(version_no, material_no, customer_no, rolling_month, abnormal_flag, page, size)` 可过滤参数一一对应；契约无 keyword 参数 → 不设关键字搜索框，禁止前端假过滤）**：

| 控件 | 对应参数 | 选项 |
|---|---|---|
| 版本下拉 | `version_no` | 来自 `md_monthly_version.list` quiet 加载（见 §4）；label=「version_no · lock_status」 |
| 物料下拉 | `material_no` | **autocomplete**（内联下拉，见 §4）；来源 `md_material.list`，value=material_no，label=「代号 + 名称」双行 |
| 客户下拉 | `customer_no` | **autocomplete**；来源 `md_customer.list`，value=customer_no，label=「代号 + 名称」双行 |
| 滚动月度下拉 | `rolling_month` | 全部 / N+1 / N+2 / N+3（BR-05 枚举，原值传参） |
| 异常标记 chips | `abnormal_flag` | 全部 / 异常（true）/ 正常（false） |
| 分页 | `page` / `size` | `pageable()` 分页条 |

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集；字段序与详情一致）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 版本 | `version_no` | 正文 |
| 物料 | `material_no` | 正文 + materialMap 命中附名称小字 |
| 客户 | `customer_no` | 正文 + custMap 命中附名称小字 |
| 滚动月度 | `rolling_month` | 正文（N+1 / N+2 / N+3） |
| 原始预测 | `orig_qty` | `fmt()`，空值 `dash()` |
| 调整后需求 | `adj_qty` | `fmt()`，空值 `dash()` |
| 基线方法 | `base_method` | 正文（空值 `dash()`） |
| 基线数量 | `base_qty` | `fmt()`，空值 `dash()` |
| 基线和事件合计 | `base_event_qty` | `fmt()`，空值 `dash()` |
| 异常标记 | `abnormal_flag` | `hue()` 徽章（异常=红 / 正常=灰，`abnormal_flag` 为 0/1 整数，映射后展示） |
| 最终预测 | `final_qty` | `fmt()` **加粗**，空值 `dash()`（异常行未填时显示「待人工填」小标签） |
| 操作 | — | 按 versionMap 状态 + abnormal_flag 的行内动作，`x-show`（见 §5.1） |

**交互**：任一过滤变化 → 重置回第 1 页重载；加工动作成功后刷新当前页；空结果显示空态文案（不喷 toast）。
**默认版本过滤**：列表默认只显示当前「草稿」版本；无草稿版本时暂不显示任何数据（`hideAll`），用户手动选版本后解除。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 状态徽章 / KV 分组体 / 状态操作页脚

**用途**：点列表行（版本/物料/客户/滚动月度任一主键列 `.b-link`）弹出，展示 `sales_forecast.get` 返回的**全部**业务字段。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | 复合键 `version_no · material_no · customer_no · rolling_month` + `abnormal_flag` 徽章 | 墨青头带，异常徽章 `hue()` |
| 定位信息 | `version_no` / `material_no` / `customer_no` / `rolling_month` | `.kv`；`material_no` 注「弱引用 md_material 主数据」、`customer_no` 注「弱引用 md_customer 主数据」、`version_no` 注「弱引用 md_monthly_version」 |
| 客户预测（双源之一） | `orig_qty` / `mape` / `bias` / `adj_qty` | `.kv`；`mape`/`bias` 注「attainment 派生（只读快照）」，空值 `dash()`；`adj_qty` 注「= orig_qty × (1 − bias)，系统修正人工可调」（BR-11） |
| 基线（双源之二） | `base_method` / `base_params` / `base_qty` / `bp_material_no` / `switch_time` | `.kv`；`base_params` 为 JSON 字符串 → `tryParse()` 结构化展示（四种方法参数，BR-18~21）；`bp_material_no` 注「断点追溯原物料（md_breakpoint.trace）」，非空才显示；`switch_time` `fmtTime()` 非空才显示 |
| 事件调整 | `event_analysis` / `event_adj` / `base_event_qty` | `.kv`；`base_event_qty` 注「= base_qty + event_adj」（BR-23）；`event_adj` 带符号 `fmt()` |
| 决策结果 | `abnormal_flag` / `final_qty` | `.kv`；`abnormal_flag` 注「双源分歧需人工介入」；`final_qty` 空值注「异常行未人工填写」（BR-26） |
| 时间信息 | `created_at` / `updated_at` | `fmtTime()` |
| 原始数据 | get 返回全量 JSON | 底部折叠 |

**交互**：页脚 `.modal-ft` 按版本状态 + 异常标记放加工动作按钮（逻辑同 §5.1，与行内动作共用一处判定）；动作成功后用返回对象原地刷新模态字段 + 列表行。

### 2.3 表单（增/改）—— 开启版本 + 行级加工

#### 2.3.1 开启版本（open_version，批量生成入口，数据来源类型 = 手工参考创建）

**用途**：总部计划对草稿版本执行 `open_version`，系统按「正常状态物料 × 历史采购客户」生成清单并拆 N+1/N+2/N+3 进处理表。

| 字段 | 控件 | 必填 | 说明 |
|---|---|---|---|
| `version_no` | select（版本下拉，仅 `lock_status=草稿` 项，见 §4） | ★ 必填 | 版本来源 `md_monthly_version`；发布（锁定）/冻结版本不显示（open_version 拒绝对锁定版本开启） |
| 上游数据摘要（只读） | 说明卡 | — | 「预测范围 = 正常状态物料 × 该物料的历史采购客户」；物料数来自 `md_material.list(status=正常)` quiet 计数；某物料无历史时客户为空、仅一行；未覆盖组合可用「新建组合」补充 |

- **不进表单**：清单行 / 处理表行 / `list_rows` / `line_rows`（系统生成，仅提交后 toast 反馈）。
- 提交成功：toast 带出「清单 X 行 · 处理表 Y 行」→ 关闭模态 → 重置过滤重载列表。
- 失败：版本不存在 / 已锁定 / 已开启 → 后端 FdeError 经 api.js 统一 toast（US-01-AC2/AC3）。

#### 2.3.2 新建组合（create，手工补充 物料×客户，客户可空）

**用途**：覆盖「开启版本」未生成的组合——业务人员手工新建一个「物料×客户」组合（客户允许为空），系统拆 N+1/N+2/N+3 三行进处理表。

| 字段 | 控件 | 必填 | 说明 |
|---|---|---|---|
| `version_no` | select（仅草稿版本，默认当前过滤版本） | ★ 必填 | 版本来源 `md_monthly_version` |
| `material_no` | autocomplete（md_material） | ★ 必填 | 主数据引用铁律，物料必须存在 |
| `customer_no` | autocomplete（md_customer） | 可选 | 留空 = 空客户组合（无具体客户） |

- 提交成功：toast「已新建组合 · 物料 × 客户（空则显示（空客户））」→ 关闭模态 → 刷新列表。
- 失败：组合已存在 / 物料或客户不存在 / 版本非草稿 → 后端 FdeError 经 api.js 统一 toast。

#### 2.3.3 行级加工入口（草稿版本可执行）

| 动作 | 服务 | 可写字段 | 控件 | 必填 | 说明 |
|---|---|---|---|---|---|
| 填预测 | `fill_customer` | `orig_qty` | input number | 可选 | 留空即客户不填报（BR-09）；提交后系统回显 `adj_qty`（= orig_qty × (1 − bias)，人工可调） |
| | | `adj_qty` | input number（收进「更多字段 ▾」） | 可选 | 人工覆盖调整后需求（缺省自动算，BR-11） |
| 算基线 | `calc_baseline` | — | 直接动作（确认后执行） | — | 无额外参数；断点追溯 + 基线计算由后端完成，返回含 `base_qty`/`base_event_qty`/`bp_material_no`/`switch_time` |
| 事件调整 | `adjust_event` | `event_analysis` | input text | 可选 | 促销/SOP/断点 分析 |
| | | `event_adj` | input number，默认 0 | 可选 | 只作用归属期，不外推（BR-22）；提交后 `base_event_qty` = base_qty + event_adj 重算 |
| 决策 | `decide` | — | 直接动作（确认后执行） | — | 无额外参数；按 MAPE 与偏离率自动标记异常并给出 final_qty（异常行不自动填，BR-14/BR-15） |
| 人工填最终预测 | `set_final` | `final_qty` | input number | ★ 必填 | **仅异常行（abnormal_flag=true）显示**；非异常行后端拒绝（US-06-AC2） |

- 布局：填预测 / 事件调整 / 填最终 复用一个小模态表单（头带显示复合键定位信息 + 只读回显当前值）；算基线 / 决策为按钮直发（无表单）。
- 校验：`set_final` 的 final_qty 为空不发请求（必填红星 + toast 警告）；其余错误一律后端 FdeError 经 api.js 统一 toast。
- **编辑入口形态**：行内操作列按钮 + 详情模态页脚按钮共用同一套动作，两处一致。

### 2.4 汇总区（版本级）

| 模态 | 服务 | 交互 |
|---|---|---|
| 版本汇总 | `summarize` | 选版本（草稿）→ 执行 → toast「已汇总 N 行」；汇总表是处理表派生合计，禁止独立编辑（BR-03） |
| 汇总查询 | `get_summary` | 选版本（可再选物料，不选=整版本）→ 表格展示 `version_no`/`material_no`/`rolling_month`/`final_qty_sum`（`.tbl.tight`，`final_qty_sum` 用 `fmt()` 加粗） |

> 汇总查询是销售预测最终输出、供 demand 合成毛需求；本页仅展示，`material_no` 筛选在汇总查询模态内用 autocomplete（同 §4）。

## 4. 数据来源与下拉

**主数据下拉（三份，`init()` 中一次性 `{quiet:true}` 加载，失败静默降级为空数组）**：
- **物料 autocomplete（materialOptions / materialMap）**：`svc("md_material","list")` `{page:1, page_size:200}` quiet；由返回项构建 `materialMap = {material_no: material_name}`；列表「物料」列与详情姓名回显；开启版本上游摘要复用同源另加 `status:"正常"` 计数。
- **客户 autocomplete（custOptions / custMap）**：`svc("md_customer","list")` `{page:1, page_size:200}` quiet；构建 `custMap = {customer_no: customer_name}`。
- **版本下拉（versionOptions / versionMap）**：`svc("md_monthly_version","list")` `{page:1, page_size:200}` quiet；构建 `versionMap = {version_no: {lock_status, anchor_period, opening_date}}`；过滤条版本下拉用全量，开启版本模态仅取 `lock_status === "草稿"` 项，行编辑态判定取 `versionMap[row.version_no].lock_status === "草稿"`。
- autocomplete 实现要点（铁律）：① 每个主数据源独立扁平数组，**禁止**嵌套对象存储；② `@click.stop` 展开/收起 + `@input` 实时过滤 + `@click.away` 关闭；③ 过滤同时匹配代号和名称；④ 列表项「代号 + 名称」双行，选中后表单存代号。

**契约 payload → 区块字段映射**：

| 来源 | payload 字段 | 去向 |
|---|---|---|
| `sales_forecast.list` 项 | version_no, material_no, customer_no, rolling_month, orig_qty, mape, bias, adj_qty, base_method, base_params, base_qty, event_analysis, event_adj, base_event_qty, bp_material_no, switch_time, abnormal_flag, final_qty, created_at, updated_at, created_by, updated_by | 列表区表格列（1:1 子集）+ 详情模态全部 KV 分组 + 原始数据折叠 |
| `sales_forecast.get` | 同上（全量） | 详情模态全部字段 |
| `sales_forecast.open_version` 返回 | `{version_no, list_rows, line_rows}` | toast「清单 X 行 · 处理表 Y 行」→ 列表重载 |
| `fill_customer / calc_baseline / adjust_event / decide / set_final` 返回 | 处理表行对象（更新后全字段） | 原地更新已开模态 + 列表行 |
| `summarize` 返回 | `{version_no, summary_rows}` | toast「已汇总 N 行」 |
| `get_summary` 返回 | version_no, material_no, rolling_month, final_qty_sum | 汇总查询模态表格 |
| `md_material.list` 项 | material_no, material_name, status | 物料 autocomplete 选项 + materialMap + 开启版本摘要计数 |
| `md_customer.list` 项 | customer_no, customer_name | 客户 autocomplete 选项 + custMap |
| `md_monthly_version.list` 项 | version_no, anchor_period, opening_date, lock_status | 版本下拉选项 + versionMap |

**快照字段标注**（只读展示、不进任何写表单）：
- `mape` / `bias`：attainment 派生快照（只读引用），fill_customer 时由后端从 attainment 取回写回显；
- `base_method` / `base_params`：md_material 主数据快照，calc_baseline 时后端取回写；
- `bp_material_no` / `switch_time`：md_breakpoint.trace 追溯结果，calc_baseline 时后端写；
- `abnormal_flag` / `final_qty`：decide 系统计算（异常行 final_qty 由 set_final 人工填）；
- `created_at` / `updated_at` / `created_by` / `updated_by`：审计字段，平台写。

## 5. 交互要点

1. **按版本状态 + 异常标记的行内动作（行操作列与详情页脚共用判定）**：
   - 仅 `versionMap[row.version_no].lock_status === "草稿"` 时显示动作；发布（锁定）/冻结 → 无任何按钮（BR-06，只读）。
   - 草稿下：全部行显示【填预测】【算基线】【事件调整】【决策】；`abnormal_flag=true` 的行**额外**显示【填最终】（set_final，非异常行后端拒绝）。
   - 动作成功：toast（如「已算基线 · base_qty=110」「已决策 · 异常」）+ 刷新列表/原地更新模态；非法流转（锁定版本写操作、非异常行填最终）由后端 FdeError 经 api.js 统一 toast，页面不硬编状态机校验。
2. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 异常徽章。
3. **base_params JSON 结构化**：详情模态用 `tryParse()` 将 `base_params`（如 `{"window":6}` / `{"alpha":0.3,"trend":false}`）结构化展示，解析失败回退原文。
4. **断点追溯展示**：`bp_material_no` / `switch_time` 非空才显示（无断点行不展示空字段）。
5. **quiet 探测性加载**：三份主数据下拉 quiet + 零值兜底（失败不喷 toast，下拉仅「全部」或空禁用项）；处理表列表本身正常加载，错误走 api.js 统一通道。
6. **展示工具**：`hue()`（abnormal_flag 徽章）、`dash()`（空数量/空方法/空分析）、`fmt()`（orig_qty/adj_qty/base_qty/base_event_qty/final_qty/final_qty_sum，`event_adj` 带符号）、`fmtTime()`（created_at/updated_at/switch_time）、`tryParse()`（base_params）。
7. **toast**：开启版本成功（清单/处理表行数）、加工动作成功、汇总成功、必填未填警告；其余错误一律由 api.js 统一呈现。
