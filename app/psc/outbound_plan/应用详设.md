# 出库计划 · 应用详设

> 应用名：`outbound_plan` | 类名：`OutboundPlan` | 聚合根：出库计划
> 数据来源类型：手工参考创建

---

## 1. 需求概览

### 1.1 基本信息
- **需求名称**: 出库计划
- **需求编号**: REQ-PSC-OP-001
- **所属模块**: 产销协同-库存推移
- **需求来源**: 业务方（销售/计划）
- **创建日期**: 2026-08-20
- **优先级**: P0

### 1.2 需求背景
#### 1.2.1 为什么需要这个需求？
库存推移表的预计出库量此前依赖 ERP 调拨单适配器（stub），没有业务人员可维护的落地载体。实际业务中，对客户的出库由业务人员按客户+物料+数量+日期排布，需要一张可手工登记、到期自动关闭、可延期恢复的出库计划表，并作为推移表预计出库量的唯一来源。

#### 1.2.2 期望达到什么目标？
业务人员可手工建立出库计划（客户、物料、数量、日期、对应实际出库单号）；计划到期后自动关闭；关闭后仍可手工编辑延期；库存推移表预计出库量从本表取（仅「待出库」）。

### 1.3 需求范围
#### 1.3.1 包含哪些功能？
出库计划手工新建（create）、编辑/延期（update）、删除（delete，仅待出库）、到期自动关闭（惰性 close_expired）、查看（get / list）。

#### 1.3.2 不包含哪些功能？
- 不做实际出库单的生成与执行（实际出库单号仅回填登记，执行在 ERP/WMS）。
- 不做与调拨单的自动对账。

> **数据来源类型**: 手工参考创建 —— 业务人员手工登记，前端提供新建 / 编辑 / 删除入口。

### 1.4 涉及角色
- **业务人员（销售）**: 登记与维护对客户的出库计划。
- **计划员**: 消费——库存推移表预计出库量来源于本表。

## 2. 用户故事

### 2.1 核心用户故事

#### 2.1.1 `US-01` 手工新建出库计划（优先级：P0）
- **故事描述**: 作为业务人员，我想要按客户+物料+数量+日期登记出库计划，以便于指导后续出库执行并进入库存推演
- **前置条件**: 存在客户主数据（md_customer）与物料主数据（md_material）
- **后置条件**: 生成出库计划，计划号自动生成，状态按计划出库日期判定（今日及以后=待出库，早于今日=已关闭）

**验收场景**：
1. `US-01-AC1` **Given** 合法客户/物料/数量/未来日期，**When** create，**Then** 生成待出库计划并返回全字段
2. `US-01-AC2` **Given** 客户或物料不在主数据，**When** create，**Then** 报「客户记录不存在 / 物料记录不存在」
3. `US-01-AC3` **Given** 数量 ≤0 或日期非法，**When** create，**Then** 报相应校验错误

#### 2.1.2 `US-02` 到期自动关闭（优先级：P0）
- **故事描述**: 作为业务人员，我希望到期未执行的计划自动关闭，以便于列表聚焦未执行计划
- **后置条件**: 待出库且计划出库日期早于今日的计划置为已关闭（惰性结算：list / get 读取时执行 close_expired）

**验收场景**：
1. `US-02-AC1` **Given** 待出库计划日期已过，**When** 读取 list/get，**Then** 该计划状态为已关闭
2. `US-02-AC2` **Given** 已关闭计划，**When** 再次 close_expired，**Then** 幂等不重复处理

#### 2.1.3 `US-03` 关闭后编辑延期恢复（优先级：P0）
- **故事描述**: 作为业务人员，我想要把已关闭的计划延期到后面某天，以便于恢复执行并重新进入库存推演
- **后置条件**: update 后状态按最终日期重算：今日及以后=待出库，早于今日=已关闭

**验收场景**：
1. `US-03-AC1` **Given** 已关闭计划，**When** update 延期到未来日期，**Then** 状态恢复待出库
2. `US-03-AC2` **Given** 待出库计划，**When** update 回填实际出库单号，**Then** 其余字段不变、状态保持待出库

#### 2.1.4 `US-04` 删除出库计划（优先级：P2）
- **验收场景**: 待出库可删除；已关闭删除报「已关闭的出库计划不可删除，如需继续执行请编辑延期」。

#### 2.1.5 `US-05` 查看与筛选（优先级：P1）
- **故事描述**: 按物料/客户/状态筛选出库计划列表并查看单条详情
- **验收场景**: 过滤 AND 组合生效；分页返回 {items, total}；get 返回全字段。

## 3. 业务场景

### 3.1 业务流程描述

#### 3.1.1 场景1: 登记并执行
1. 业务人员进入「出库计划」页面，点「新建出库计划」
2. 选择客户、物料，填数量、计划出库日期（可预填实际出库单号）
3. 系统校验主数据引用后生成计划（状态按日期判定）
4. 实际出库发生后，编辑回填实际出库单号

#### 3.1.2 场景2: 到期关闭与延期
1. 计划出库日期过期后，任何一次读取（list/get）系统自动将其置为已关闭
2. 业务人员对已关闭计划点「编辑」，把日期延后到未来某天并保存
3. 系统恢复其为待出库；库存推移表下一次 refresh 时重新计入预计出库量

#### 3.1.3 场景3: 推移表消费
1. `inventory_projection.refresh` 调 `outbound_plan.list(material_no, status=待出库)`
2. 按计划出库日期合计为逐日预计出库量（BR-05 口径）

### 3.2 业务规则

#### 3.2.1 `BR-01` 计划号全局唯一
- 系统自动生成 `OB` + 日期 + 4 位流水（如 `OB202608200001`），创建后不可变更。

#### 3.2.2 `BR-02` 状态枚举约束
- 状态仅 `待出库 / 已关闭`；由系统按计划出库日期自动判定，不接受手工指定。

#### 3.2.3 `BR-03` 到期自动关闭（惰性）
- `待出库` 且 `out_date < 今日` → `已关闭`；在 list / get / close_expired 时结算，幂等。

#### 3.2.4 `BR-04` 延期恢复
- 已关闭计划可 update；最终 `out_date ≥ 今日` → 恢复 `待出库`，重新进入推移表预计出库量。

#### 3.2.5 `BR-05` 主数据引用铁律
- `customer_no` 必须存在于 md_customer；`material_no` 必须存在于 md_material；创建/编辑均校验。

#### 3.2.6 `BR-06` 数量与日期校验
- `qty` 必须为大于 0 的数字；`out_date` 必须为合法日期（YYYY-MM-DD，兼容 YYYYMMDD）。

#### 3.2.7 `BR-07` 删除约束
- 仅 `待出库` 可删除；已关闭为历史留痕，后端拦截删除。

### 3.3 业务数据

#### 3.3.1 数据1: 计划号 plan_no — 文本，系统生成，主键
#### 3.3.2 数据2: 客户编码 customer_no — 文本，必填，弱引用 md_customer
#### 3.3.3 数据3: 物料号 material_no — 文本，必填，弱引用 md_material
#### 3.3.4 数据4: 数量 qty — 数字，必填，>0
#### 3.3.5 数据5: 计划出库日期 out_date — 日期，必填，到期关闭判定与推移表出库归集的依据
#### 3.3.6 数据6: 实际出库单号 actual_out_no — 文本，可选，执行后回填
#### 3.3.7 数据7: 状态 status — 枚举（待出库/已关闭），系统判定

## 4. 功能设计

### 4.1 FUNC-01 新建出库计划（create）
**用户操作流程**: 业务人员传 customer_no / material_no / qty / out_date（可选 actual_out_no）→ 校验主数据与数量日期 → 生成计划号 → 按日期判定状态落盘。

**输入数据**: customer_no（必填，引用 md_customer）、material_no（必填，引用 md_material）、qty（必填 >0）、out_date（必填）、actual_out_no（可选）。

**关联规则**: BR-01 / BR-02 / BR-05 / BR-06。

### 4.2 FUNC-02 编辑 / 延期（update）
传入字段覆盖，未传字段保留；状态按最终 out_date 重算。已关闭可编辑（延期恢复 BR-04）。

### 4.3 FUNC-03 删除（delete）
仅待出库可删（BR-07），物理删除。

### 4.4 FUNC-04 到期自动关闭（close_expired）
批量 UPDATE：`status='待出库' AND out_date < 今日 → 已关闭`；幂等，返回关闭数。

### 4.5 FUNC-05 查看（get / list）
读取前先 close_expired 结算；list 支持 material_no / customer_no / status AND 过滤 + 分页，按 out_date 降序。

## 5. 实体设计

**业务实体**: OutboundPlan（出库计划）—— 客户×物料×日期维度的出库安排，标识为 plan_no。

| 字段名称 | 字段类型 | 是否必填 | 默认值 | 业务逻辑 |
|---|---|---|---|---|
| plan_no | 文本 | 是 | 系统生成 | 主键，OB+日期+流水 |
| customer_no | 文本 | 是 | - | 弱引用 md_customer |
| material_no | 文本 | 是 | - | 弱引用 md_material |
| qty | 数字 | 是 | - | 出库数量，>0 |
| out_date | 日期 | 是 | - | 计划出库日期；到期关闭判定依据 |
| actual_out_no | 文本 | 否 | 空 | 实际出库单号（执行后回填） |
| status | 枚举值 | 是 | 待出库 | 待出库 / 已关闭；系统按日期判定 |
