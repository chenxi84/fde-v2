# 项目台账 前端详设
> 来源：app/psc/_contracts.md（冻结契约）+ app/psc/md_project/应用详设.md
> 落位：`app/psc/md_project/view.js` + `view.html`

## 1. 页面元数据 PAGE_META

| 字段 | 值 | 说明 |
|---|---|---|
| key | `md_project` | = 应用文件夹名，page_id 为 `psc:md_project` |
| name | 项目台账 | 侧栏菜单名 |
| ic | 📁 | 图标字 |
| title | 项目台账 | 主区页面头标题 |
| crumb | 主数据 · 项目生命周期(阶段/SOP/EOP) | 副题·要点 |
| order | 40 | 升序即菜单序 |

页面零鉴权：无任何权限判断；菜单按页面授权渲染在 shell，数据范围由后端闸门执法，401 由 api.js 自动跳登录。
数据来源类型：**独立创建** —— 前端保留「新建」按钮（本地录入）+ 「批量导入」（承接 PLM 冗余同步）。

## 2. 区块构成

### 2.1 列表区（查）—— 三段式：工具栏 / 表格 / 分页条

**用途**：项目台账全量浏览 + 条件检索 + 新建/批量导入入口 + 行内阶段推进动作。本页为非看板页，不设 KPI 指标带（验收断言无 `.kpi`）。

**过滤控件（与 `md_project.list(project_no, project_name, stage, page, size)` 可过滤参数一一对应；契约无 keyword / owner 参数 → 不设关键字框、不设责任销售过滤，禁止前端假过滤）**：

| 控件 | 对应参数 | 形态 |
|---|---|---|
| 项目号输入框 | `project_no` | placeholder「项目号」，Enter 或「查询」按钮触发（后端 LIKE 模糊匹配） |
| 项目名称输入框 | `project_name` | placeholder「项目名称」，Enter 或「查询」按钮触发（后端 LIKE 模糊匹配） |
| 阶段 chips | `stage` | 全部 / 进行中 / SOP / EOP，单选互斥，点击即查（精确匹配） |
| 分页条 | `page` / `size` | `pageable()`，integer 传参 |

**工具栏**：「查询」「+ 新建项目」（打开 2.3 创建模态）「批量导入」（打开 2.4 文件上传模态）。

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集；字段序与详情/表单一致）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 项目号 | `project_no` | `.b-link`，点击打开详情模态 |
| 项目名称 | `project_name` | 单行省略 |
| 阶段 | `stage` | `hue()` 徽章（进行中=绿 / SOP=黄 / EOP=红） |
| SOP 时间 | `sop_date` | 文本，空值 `dash()` |
| EOP 时间 | `eop_date` | 文本，空值 `dash()` |
| 责任销售 | `owner` | 文本，空值 `dash()` |
| 操作 | — | 按 `stage` 的行内动作，`x-show`（见 §5.1） |

**交互**：任一过滤变化 → 重置回第 1 页重载；创建/更新/导入成功后刷新当前页；空结果显示空态文案（不喷 toast）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 / KV 分组体 / 操作页脚

**用途**：点 `project_no` 弹出，展示 `md_project.get` 返回的**全部**业务字段（6 字段：project_no / project_name / stage / sop_date / eop_date / owner）。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `project_no` + `stage` 徽章 | 墨青头带，徽章 `hue()` |
| 基本信息 | `project_no` / `project_name` / `stage` | `.kv`；`project_no` 注明「全局唯一主键 · 创建后不可变更」 |
| 生命周期 | `sop_date` / `eop_date` | `.kv`，空值 `dash()`；`eop_date` 注明「须晚于 sop_date（BR-05）」 |
| 责任人 | `owner` | `.kv`，注明「责任销售姓名/工号 · 文本字段（用户主数据来源待确认）」 |
| 原始数据 | get 返回全量 JSON | 底部折叠（默认收起） |

**页脚 `.modal-ft`**：按当前 `stage` 的【阶段推进】按钮 + 【编辑】 + 【关闭】（逻辑同 §5.1，与行内动作共用一处 `x-show` 判定）；动作成功后用返回对象原地刷新模态字段 + 列表行。

### 2.3 创建 / 编辑表单（增/改）—— 模态表单

**用途**：覆盖 `md_project.create` / `md_project.update` 接受的业务参数。

| 字段 | 控件 | 必填 | create 可见 | update 可见 | 约束来源 |
|---|---|---|---|---|---|
| `project_no` | input，maxlength=50 | ★ 必填 | 是 | 否（只读展示） | BR-01 主键，创建后不可变 |
| `project_name` | input，maxlength=100 | ★ 必填 | 是 | 是 | BR-02 |
| `owner` | input，maxlength=50 | ★ 必填 | 是 | 是 | BR-02；责任销售姓名/工号（纯文本，无用户主数据下拉） |
| `stage` | 只读「进行中」（create）/ select（update） | — | 是（只读） | 是 | BR-03 / BR-06 状态机（见下） |
| `sop_date` | date input（YYYY-MM-DD） | 选填 | 是 | 是 | BR-04 |
| `eop_date` | date input（YYYY-MM-DD） | 选填 | 是 | 是 | BR-04 / BR-05 |

- **create 模式**：`stage` 恒为「进行中」只读展示（后端 `_validate_transition(None, stage)` 仅允许初始为进行中，新建传 SOP/EOP 会被拒）；必填 3 项（project_no / project_name / owner）；sop_date / eop_date 收进「更多字段 ▾」折叠区。
- **update 模式**：`project_no` 回填展示但不可修改（主键）；`stage` 为 select，选项仅提供「当前阶段 + 下一阶段」（进行中→进行中/SOP、SOP→SOP/EOP、EOP→仅 EOP），不提供回退/跳级选项；其余字段均可修改。stage 变更由后端校验状态机（BR-06 单向流转），前端不硬编规则、依赖后端 `FdeError` toast 兜底。
- **阶段推进模式（「推进至 SOP / EOP」动作复用本表单）**：`stage` 只读锁定为目标阶段（SOP 或 EOP），目标阶段对应的日期标必填——推进至 SOP 须填 `sop_date`、推进至 EOP 须填 `eop_date`（后端 BR-06 亦校验：推进到 SOP 须已填 SOP 时间、推进到 EOP 须已填 EOP 时间）。
- 布局：必填先行、frow 语义分组——第一行（project_no + project_name）、第二行（owner + stage）、折叠区「更多字段 ▾」：sop_date / eop_date；底部右对齐「取消」「保存」。
- 前端仅做必填校验（空值 → toast 警告、不提交）；stage 枚举值、状态机单向流转、日期格式、eop_date 晚于 sop_date 由后端校验，`FdeError` 经 api.js 以错误 toast 呈现。
- 提交成功：toast 成功消息 → 关闭模态 → 重置过滤重载列表（create）/ 刷新当前页（update / 推进）。

### 2.4 批量导入

**用途**：点击「批量导入」按钮，弹出文件上传模态，调 `md_project.import_batch`。

- 提供模板下载链接（表头：project_no, project_name, stage, sop_date, eop_date, owner）。
- 上传 Excel → 前端解析为 `rows: [{project_no, project_name, stage, sop_date, eop_date, owner}]` 数组 → 调 `svc("md_project","import_batch", {rows})`；后端逐行校验 + upsert（已存在主键 → 更新，新行 → 新增）。
- 返回摘要：`{total, success, fail, created, updated, errors:[{row, message}]}`；页面弹出导入结果摘要（成功 N 条 / 失败 M 条 / 错误明细列表）。
- 导入完成后刷新列表。

## 3. svc 字面量清单（授权派生依据——必须字面量 svc("应用","服务")）

| 区块 | 调用（应用.服务） | 参数 | quiet | 说明 |
|---|---|---|---|---|
| 列表区 | `svc("md_project","list")` | `{project_no, project_name, stage, page, size}` | — | 分页查询；空条件传 undefined 不带 |
| 详情模态 | `svc("md_project","get")` | `{project_no}` | — | 全字段详情 |
| 创建表单 | `svc("md_project","create")` | `{project_no, project_name, owner, stage, sop_date, eop_date}` | — | 新建项目台账（stage 恒「进行中」） |
| 编辑表单 / 阶段推进 | `svc("md_project","update")` | `{project_no, project_name, owner, stage, sop_date, eop_date}` | — | 更新（仅传有变更字段）；阶段推进复用 |
| 批量导入 | `svc("md_project","import_batch")` | `{rows: [...]}` | — | Excel 逐行校验 + upsert |

> 以上 5 处必须在 view.js 中以字面量逐项书写，**勿用变量拼名**。本页**无跨应用 svc 调用**（owner 为纯文本字段，无用户主数据下拉）。

## 4. 数据来源与下拉

- **无跨应用主数据下拉**：`md_project` 不主动外调其他应用。`owner` 为纯文本输入（责任销售姓名/工号，用户主数据来源待确认，聚合清单未建模 md_user）；`stage` 为静态枚举（进行中 / SOP / EOP），来源：应用详设 BR-03 / 建表 CHECK。
- **契约 payload → 区块字段映射**：

| 契约 | 载荷字段 | 映射区块 |
|---|---|---|
| `md_project.list` 返回项 | `project_no, project_name, stage, sop_date, eop_date, owner` | 2.1 列表列 |
| `md_project.get` 返回 | 同上（全量 6 字段） | 2.2 详情模态 kv + 原始数据 |
| `md_project.create` 入参 | `project_no, project_name, owner, stage, sop_date, eop_date` | 2.3 创建表单（stage 只读=进行中） |
| `md_project.update` 入参 | `project_no, project_name, owner, stage, sop_date, eop_date` | 2.3 编辑表单（project_no 只读） |
| `md_project.import_batch` 入参 | `rows: [{project_no, project_name, stage, sop_date, eop_date, owner}]` | 2.4 批量导入 |

- 快照/系统字段：无。本应用无 `*_json` 快照字段、无审计列（created_at 等，建表未含审计列），详情即 6 个业务字段。

## 5. 交互要点

1. **按状态的行内动作（状态机，行操作列与详情页脚共用判定）**：
   - `stage=进行中` → 【推进至 SOP】（打开阶段推进模态，stage 锁定 SOP，sop_date 必填） + 【编辑】；
   - `stage=SOP` → 【推进至 EOP】（打开阶段推进模态，stage 锁定 EOP，eop_date 必填） + 【编辑】；
   - `stage=EOP` → 终态，无推进按钮，仅【编辑】（允许修改 project_name / owner / 日期，但 stage 不可回退由后端拦截）。
   - 动作成功：toast（如「已推进至 SOP · PRJ-1」）+ 刷新列表；非法流转（跳级/回退）由后端 FdeError 经 api.js 统一 toast，页面不硬编状态机校验。
2. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 状态徽章。
3. **过滤**：阶段 chips 点击即查并重置 `page=1`；project_no / project_name 输入后 Enter 或「查询」触发；翻页仅改 `page/size`，不清过滤条件。
4. **阶段推进模式**：复用编辑表单，stage 只读锁定目标阶段，对应日期必填（推进 SOP 需 sop_date、推进 EOP 需 eop_date）；提交调 update，成功关闭模态刷新列表。
5. **折叠「更多字段 ▾」**：create 为 sop_date / eop_date 两个选填字段。
6. **批量导入**：文件选择后上传 → 前端解析 Excel 为 rows → 导入过程 loading → 完成弹摘要（成功/失败数 + 错误明细）→ 关闭后刷新列表。
7. **成功流**：create 成功 → 关闭模态并清空表单 → toast「项目台账创建成功」→ 列表回第 1 页重载；update / 阶段推进成功 → 关闭模态 → toast「项目台账更新成功」→ 刷新当前页。
8. **错误流**：重复 project_no / 非法阶段 / 非法流转 / 日期格式非法 / eop_date 早于 sop_date 等后端 `FdeError` → toast 错误信息，模态保持打开便于修改后重试。
9. **空态**：无任何项目时「暂无项目 —— 点『新建项目』创建」；过滤无命中时「无符合条件的项目」。
10. **展示工具**：`hue()`（stage 徽章）、`dash()`（空值 sop_date/eop_date/owner）；无金额字段无需 `fmt()`、无时间戳字段无需 `fmtTime()`、无 `*_json` 字段无需 `tryParse()`。

## 6. 验收关注点（供第⑧步）

1. **路由渲染**：`#/md_project` 挂载出列表三段式（工具栏 + 表格 + 分页条），**断言无 `.kpi`**（非看板页防挂载粘滞假过）。
2. **造数后列表有数据**：经 `md_project.create` 造项目 PRJ-001 → 列表 1 行，project_no / project_name / stage 徽章 / owner 列非空。
3. **过滤一一对应**：stage=SOP chips 仅 SOP 行；project_no=PRJ 模糊匹配；project_name=项目 模糊匹配；三条件组合；无匹配显示空态且不抛错。
4. **模态全字段**：点 project_no 开模态，断言 project_no / project_name / stage / sop_date / eop_date / owner 全部可见 + 「原始数据」可展开；EOP 行模态页脚无推进按钮。
5. **表单落库**：create 表单填 project_no / project_name / owner（★）→ 提交 → 列表出现新记录且 stage=进行中；空必填字段提交 → toast 警告且不发请求；重复 project_no 创建 → 后端 FdeError toast（BR-01）。
6. **阶段推进真实回显**：进行中行【推进至 SOP】填 sop_date → stage=SOP（US-03-AC1）；SOP 行【推进至 EOP】填 eop_date → stage=EOP；EOP 行无推进按钮；非法回退（编辑表单选回进行中）由后端拦截 toast「阶段仅可单向推进」。
7. **日期校验**：sop_date 填 `2026/09/30`（非 YYYY-MM-DD）→ 后端 FdeError toast；sop_date=2026-09-30 + eop_date=2026-08-31 → toast「EOP 时间须晚于 SOP 时间」。
8. **批量导入**：上传合法 Excel → 列表新增行；含冲突行（已有主键）→ 摘要正确展示 success/fail/错误明细。
9. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP≥400（受限会话 403 属预期执法单独豁免）。
