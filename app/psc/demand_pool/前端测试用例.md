# 应用组 `psc` · 需求池 前端测试用例（需求池）

> 产出技能：前端测试用例生成（第⑧步，规格 design-plus/前端测试.md）。
> 页面：`psc:demand_pool`（本文件全部用例针对本页；页面 key = `demand_pool`，路由 `#/demand_pool`）。输入：本应用前端详设 `app/psc/demand_pool/前端详设.md` + `app/psc/_contracts.md`。
> 执行：第⑨步翻译成 `app/psc/tests/verify_view_psc_demand_pool.py`（自包含：隔离→起平台→登录→造数→断言→0 报错）。
> 数据来源类型：**自动参考创建**——本页无创建/编辑表单（`demand_pool.create` 由库存推移表击穿水位线跨应用触发，非手工新建）；唯一的用户写入口是两个状态机动作 `release`（下达）/ `cancel`（取消）。§4 表单落库**豁免**，改以「状态机操作 + 无创建入口」断言覆盖。

## §0 测试数据字典（冻结 · 本脚本自足）

造数全部走真实 REST（浏览器内 `fetch /api/apps/<应用>/call/<服务>`，带会话 Cookie，pitfalls #18），不直连 DB。`replenish_no` 为系统生成（格式 `RP+yyyyMMdd+4位流水`），脚本在造数返回值中捕获并记为下表别名。

| 别名 | 类型 | 造数服务（链） | 关键参数 / 结果状态 |
|---|---|---|---|
| M1 | 物料（跨应用前置） | `md_material.create` | `material_no=M1, material_name=物料A` |
| RP1 | 补库单（缺货补库 · 待下达） | `demand_pool.create` | `material_no=M1, replenish_type=缺货补库, replenish_qty=100, required_inbound=2026-08-20` → 捕获返回 `replenish_no`，`status=待下达` |
| RP2 | 补库单（最低库存补库 · 待下达） | `demand_pool.create` | `material_no=M1, replenish_type=最低库存补库, replenish_qty=200, required_inbound=2026-08-21` → `status=待下达` |
| RP3 | 补库单（安全库存补库 · 待下达） | `demand_pool.create` | `material_no=M1, replenish_type=安全库存补库, replenish_qty=300, required_inbound=2026-08-22` → `status=待下达` |
| RP4 | 补库单（缺货补库 · 已下达） | `demand_pool.create` → `demand_pool.release` | create `replenish_qty=110, required_inbound=2026-08-23`；`release(replenish_no=RP4, promised_inbound=2026-08-20)` → `status=已下达`，`promised_inbound=2026-08-20` |
| RP5 | 补库单（缺货补库 · 生产中） | `demand_pool.create` → `release` → `on_workorder_started` | `on_workorder_started(replenish_no=RP5)` → `status=生产中` |
| RP6 | 补库单（缺货补库 · 已完成） | `demand_pool.create` → `release` → `on_workorder_started` → `on_inbound` | `on_inbound(replenish_no=RP6)` → `status=已完成` |
| RP7 | 补库单（安全库存补库 · 已取消） | `demand_pool.create` → `cancel` | `cancel(replenish_no=RP7)` → `status=已取消` |

> 覆盖设计：RP1/RP2/RP3 覆盖 `replenish_type` 三态（缺货/最低/安全）徽章；RP1–RP7 覆盖 `status` 五态（待下达/已下达/生产中/已完成/已取消）徽章；RP4 提供 `promised_inbound=2026-08-20` 供模态全字段断言（其余补库单该字段为空 → `dash()` 显示「—」）。

## §1 本页渲染（防粘滞）

- **VT-ROUTE-01 路由渲染**
  - 页面: `psc:demand_pool`
  - 前置造数: 无（仅登录即可）
  - 操作: 登录 admin → `page.evaluate("location.hash = '#/demand_pool'")` → 等待 `main .card` 出现

  - 操作: 造数后进入（或 `page.reload()`）`#/demand_pool`，等待 `table.tbody tr.data` 出现
  - 断言: 列表含 RP1 单号（`has_text=RP1` 精确定位，不假设顺序，pitfalls #17）；`table` 表头含 7 列标签：`补库单号 / 补库类型 / 状态 / 物料号 / 补库数量 / 要求入库时间 / 承诺入库时间`；该行含 `replenish_no / replenish_type(缺货补库) / replenish_qty(100) / status(待下达)`
  - 选择器注意: 用精确单号 `has_text` 定位而非 `.first`（列表按 required_inbound 升序，新到未必在前，#17）

- **VT-LIST-02 物料号过滤**

  - 选择器注意: 内联 autocomplete 选中后回填 `fMaterial`，`:visible` 限定下拉项（x-show 隐藏 ≠ 不存在，pitfalls #14）

- **VT-LIST-03 补库类型过滤（replenish_type=缺货补库）**
  - 前置造数: §0
  - 操作: 点补库类型 chips「缺货补库」

- **VT-LIST-04 状态过滤（status=待下达）**

- **VT-LIST-05 组合过滤 + 无匹配空态**

  - 选择器注意: 空态 `td.empty` 含「无匹配数据」，不计入 `tr.data` 行

## §4 状态机操作（表单豁免 + 无创建入口）

> 豁免说明：本应用为**自动参考创建**（BRD §1.3.2 / 详设 §4.3.1.1），无「新建」按钮、无创建/编辑表单；`demand_pool.create` 是系统触发服务，`promised_inbound` 仅在 `release` 环节可选回填。故 §4 的「创建表单落库回显」豁免，改以「状态机操作回显 + 无创建入口」覆盖。状态机动作用户触发两类：`release`（待下达→已下达，可选回填 promised_inbound）、`cancel`（待下达/已下达→已取消）。

- **VT-STATE-01 下达（待下达 → 已下达，toast 回显）**
  - 前置造数: §0（RP1 待下达）
  - 操作: RP1 行点【下达】→ 确认对话框（标题「下达生产」）→ （可选）填承诺入库时间 `2026-08-20` → 点【确认下达】
  - 断言: toast 文案含「已下达 · RP1」；RP1 行 `status` 徽章变 `已下达`；重新点开 RP1 模态 `status=已下达`、`promised_inbound=2026-08-20`（用返回对象原地刷新，pitfalls 无，但列表需刷新后定位）
  - 选择器注意: 确认对话框 `.modal:visible` 内定位 `input[type=date]`；确认按钮 `button:visible:has-text("确认下达")`

- **VT-STATE-02 取消（待下达 → 已取消，toast 回显）**
  - 前置造数: §0（RP3 安全库存补库 · 待下达）
  - 操作: RP3 行点【取消】→ 确认对话框（标题「取消补库单」）→ 点【确认取消】
  - 断言: toast 文案含「已取消 · RP3」；RP3 行 `status` 徽章变 `已取消`
  - 选择器注意: 确认按钮 `button:visible:has-text("确认取消")`

- **VT-STATE-03 已下达行按钮集（无下达，仅取消）**
  - 前置造数: §0（RP4 已下达）
  - 操作: 定位 RP4 行操作列
  - 断言: 可见操作按钮仅「取消」，**无**「下达」（`x-show` 按 status 判定，pitfalls #14 用 `:visible`）

- **VT-STATE-04 终态行无操作按钮（生产中/已完成/已取消）**
  - 前置造数: §0（RP5 生产中 / RP6 已完成 / RP7 已取消）
  - 操作: 分别定位 RP5、RP6、RP7 行操作列
  - 断言: `button:visible` 数 == 0（无任何「下达」「取消」按钮）；非法流转由后端 `FdeError` 兜底，页面不硬编

- **VT-STATE-05 无创建入口（自动参考创建铁律）**
  - 前置造数: 无
  - 操作: 进入 `#/demand_pool`，扫描主区 `button/a` 可见文本
  - 断言: 页面**不存在**「新建 / 创建 / 批量导入 / 添加」按钮或表单控件（`input`/`select` 仅过滤条物料 autocomplete 与 date 输入，无 CRUD 表单）；无「新建」入口
