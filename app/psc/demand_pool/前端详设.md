# 需求池 前端详设
> 来源：app/psc/_contracts.md（冻结契约）+ app/psc/demand_pool/应用详设.md；产出供第⑦步前端编码 / 第⑧步前端测试用例。
> 落位：`app/psc/demand_pool/view.js` + `view.html`（与 `demand_pool.py` 同文件夹，落盘即进启动清单与授权清单，零接线）；import 一律绝对路径 `/view/lib/*`；模板经 `new URL("view.html", import.meta.url)` 抓取；工厂 `export default function pageDemandPool()`（保留专名）。

## 1. 页面元数据 PAGE_META

| 字段 | 值 | 说明 |
|---|---|---|
| key | `demand_pool` | = 应用文件夹名，page_id 为 `psc:demand_pool` |
| name | 需求池 | 侧栏菜单名 |
| ic | 🛠 | 菜单图标字 |
| title | 需求池 | 主区页面头标题 |
| crumb | 三类补库单 · 待下达→已下达→生产中→已完成/已取消 | 头部副题 |
| order | 150 | 升序即菜单序 |

- 页面零鉴权：无任何权限判断；菜单按页面授权渲染在 shell，数据范围（总部计划可全量查看/操作所有补库单，无物料级隔离）由后端闸门执法，401 由 api.js 自动跳登录。
- 数据来源类型：**自动参考创建**——补库单由上游库存推移表（`inventory_projection.scan_alert`）击穿水位线时跨应用调用 `demand_pool.create(...)` 自动生成，前端**不提供「新建」按钮、无创建表单**；`create` 为系统触发，非用户手工新建（BRD §1.3.2 / 详设 §4.3.1.1）。
- 状态机为「单向下发 + ERP 回传闭环」：`release`（待下达→已下达）由用户手工触发；`on_workorder_started`（已下达→生产中）与 `on_inbound`（生产中→已完成）由 ERP 回传驱动，前端**不主动调用、仅展示**；`cancel`（待下达/已下达→已取消）由用户手工触发。
- 本应用契约**无 update / set_* / import_batch / delete** → 无编辑入口、无删除按钮、无批量导入；单据变更仅经状态机动作（release / cancel）。

## 2. 区块构成

### 2.1 列表区（查）—— 三段式：过滤条 / 表格 / 分页条

**用途**：补库单台账，按物料 / 补库类型 / 状态筛选，承载行内状态流转动作（下达 / 取消）。本页为非看板页，不设 KPI 指标带（验收断言无 `.kpi`）。

**过滤控件（与 `demand_pool.list(material_no, replenish_type, status, page, size)` 可过滤参数一一对应；契约无 keyword 参数 → 不设关键字搜索框，禁止前端假过滤）**：

| 控件 | 对应参数 | 形态 |
|---|---|---|
| 物料号下拉 | `material_no` | 内联 autocomplete 下拉（主数据引用铁律），来源 `md_material.list` quiet 加载（见 §4）；选中回填 material_no，精确匹配 |
| 补库类型 chips | `replenish_type` | 全部 / 缺货补库 / 最低库存补库 / 安全库存补库（BR-02 枚举，原值传参） |
| 状态 chips | `status` | 全部 / 待下达 / 已下达 / 生产中 / 已完成 / 已取消（BR-03 枚举，原值传参） |
| 分页条 | `page` / `size` | `pageable()`，契约签名 string 型，照传即可 |

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集，字段序与详情一致：单号→状态→物料→数量→时间）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 补库单号 | `replenish_no` | `.b-link`，点击打开详情模态 |
| 补库类型 | `replenish_type` | `hue()` 徽章（缺货补库=红 / 最低库存补库=琥珀 / 安全库存补库=蓝） |
| 状态 | `status` | `hue()` 徽章（待下达=灰 / 已下达=青 / 生产中=琥珀 / 已完成=绿 / 已取消=灰） |
| 物料号 | `material_no` | 编号正文 + materialMap 命中时附物料名称小字 |
| 补库数量 | `replenish_qty` | `fmt()`（REAL 数值） |
| 要求入库时间 | `required_inbound` | 日期文本（BR-10 击穿时点） |
| 承诺入库时间 | `promised_inbound` | 日期文本，空值 `dash()` |
| 操作 | — | 按 `status` 的行内动作，`x-show`（见 §5.1） |

**交互**：任一过滤变化 → 重置回第 1 页重载；状态动作成功后刷新当前页；空结果显示空态文案（不喷 toast）。默认列表按要求入库时间升序（缺货/击穿时点更早的优先，后端已排好序）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 + 状态徽章 / KV 分组体 / 状态操作页脚

**用途**：点 `replenish_no` 弹出，展示 `demand_pool.get` 返回的**全部**业务字段，供下达、取消操作前核对。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `replenish_no` + `status` 徽章 | 墨青头带，徽章 `hue()` |
| 基本信息 | `replenish_no` / `status` / `replenish_type` / `material_no` | `.kv`；`replenish_no` 注明「系统生成 · 全局唯一」（BR-01，格式 `RP+yyyyMMdd+4位流水`）；`material_no` 注明「主数据引用 md_material · 禁止手工录入」（BR-08），materialMap 命中附物料名称；`replenish_type` 用 `hue()` 徽章 |
| 数量与时间 | `replenish_qty` / `required_inbound` / `promised_inbound` | `.kv`；`replenish_qty` 用 `fmt()`，注明「按产能松紧分档确定」（BR-06）；`required_inbound` 注明「击穿时点 · 须在此之前入库」（BR-10）；`promised_inbound` 空值 `dash()`，注明「产能平衡后承诺 · 回填时点待确认」 |
| 原始数据 | get 返回全量 JSON | 底部折叠（默认收起） |

**页脚 `.modal-ft`**：按当前状态放状态机按钮（逻辑同 §5.1，与行内动作共用一处 `x-show` 判定）+ 【关闭】。动作成功后用返回对象原地刷新模态字段 + 列表行。

### 2.3 创建 / 编辑表单（豁免——本应用无表单区）

- **豁免理由**：数据来源类型为**自动参考创建**（BRD §1.3.2 / 详设 §4.3.1.1）——补库单由库存推移表击穿水位线时**系统跨应用调用 `demand_pool.create(...)` 自动生成**，`create` 是系统触发服务，前端**不提供「新建」按钮、无创建表单、无编辑表单**。
- `create` 的入参（`material_no / replenish_type / replenish_qty / required_inbound / stock_on_hand / min_level_a / safety_level_c / batch_level_b / capacity_tight`）全部由上游 `inventory_projection.scan_alert` 按 BR-04/BR-05/BR-06/BR-07/BR-10 规则计算传入，**不进任何前端表单**。
- 本页唯一的「写」入口是两个状态机动作：`release`（下达，可带可选 `promised_inbound`）与 `cancel`（取消），以确认对话框 / 行内按钮形态承载（见 §5.1），不属于 CRUD 表单。
- 全部字段均只读展示：`replenish_no` / `status` / `replenish_type` / `material_no` / `replenish_qty` / `required_inbound` 系统生成；`promised_inbound` 仅 release 环节可选回填。

## 3. svc 字面量清单（授权派生依据——必须字面量 svc("应用","服务")）

| 区块 | 调用（应用.服务） | 参数 | quiet | 说明 |
|---|---|---|---|---|
| 列表区 | `svc("demand_pool","list")` | `{material_no, replenish_type, status, page, size}` | — | 过滤查询；空条件传 undefined 不带 |
| 列表区 / 物料下拉 | `svc("md_material","list")` | `{page:1, page_size:200}` | ✅ | material_no 下拉数据源；**跨应用调用，字面量产生 psc:demand_pool → md_material.list 派生边**；失败静默降级为空数组 |
| 详情模态 | `svc("demand_pool","get")` | `{replenish_no}` | — | 全字段详情 |
| 行内 / 模态页脚 | `svc("demand_pool","release")` | `{replenish_no, promised_inbound?}` | — | 待下达 → 已下达（US-02 / BR-11），`promised_inbound` 可选，留空传 undefined |
| 行内 / 模态页脚 | `svc("demand_pool","cancel")` | `{replenish_no}` | — | 待下达 / 已下达 → 已取消（US-05 / BR-13） |

> 以上 5 处必须在 view.js 中以字面量逐项书写（可包在闭包里），**勿用变量拼名**——这是页面授权隐式放行派生扫描的唯一来源。
> **不调用（系统/ERP 触发，仅展示其产生的状态流转）**：`demand_pool.create`（库存推移表击穿自动生成）、`demand_pool.on_workorder_started`（ERP 回传开工）、`demand_pool.on_inbound`（ERP 回传入库）——三者均无前端触发入口，不进 svc 清单。

## 4. 数据来源与下拉

**物料号下拉（过滤条内联 autocomplete，主数据引用铁律 BR-08）**：
- 页面初始化一次性 `svc("md_material","list")` `{page:1, page_size:200}`，`quiet:true` 探测：失败不喷 toast；零值兜底 → 过滤下拉仅「全部」，选中项缺失时原样展示 material_no。
- 由返回项构建 `materialOptions = [{material_no, material_name}]` 与 `materialMap = {material_no: material_name}`，供列表「物料号」列与详情模态物料名称回显；未命中则原样展示 material_no。
- 内联 autocomplete 实现要点（铁律）：单独声明扁平数组 `materialOptions`（**禁止**嵌套对象 `autoOptions[field]`）；`@click.stop` 切换展开/收起 + `@input` 实时过滤 + `@click.away` 关闭；过滤同时匹配 `material_no` 与 `material_name`；列表项「代号 + 名称」双行，选中后表单存 material_no。
- md_material 列表项字段以 md_material 契约为准，本页仅用 `material_no` / `material_name`（status / value_class 等不展示）。

**契约 payload → 区块字段映射**：

| 契约 | 载荷字段 | 映射区块 |
|---|---|---|
| `demand_pool.list` 返回项 | `replenish_no, material_no, replenish_type, replenish_qty, required_inbound, promised_inbound, status` | 2.1 列表列（1:1，7 字段全上） |
| `demand_pool.get` 返回 | 同上（全量 7 字段） | 2.2 详情模态全部 KV 分组 + 原始数据折叠 |
| `demand_pool.release` 入参 | `replenish_no`（必）、`promised_inbound`（可选） | 2.2 页脚 / 行内下达确认对话框 |
| `demand_pool.cancel` 入参 | `replenish_no` | 2.2 页脚 / 行内取消确认 |
| `md_material.list` 返回项 | `material_no, material_name` | 过滤下拉选项 + materialMap |

**快照 / 系统生成字段标注**：`replenish_no`（系统生成，BR-01）、`status`（系统按状态机维护，BR-03/BR-11）、`replenish_type`（触发条件判定，BR-04/BR-05）、`replenish_qty`（分档计算，BR-06）、`required_inbound`（击穿时点，BR-10）——均**只读展示，不进表单**；`promised_inbound` 仅 release 环节可选回填（回填时点待确认）。

## 5. 交互要点

1. **按状态的行内动作（状态机，行操作列与模态页脚共用判定）**：
   - `status=待下达` → 【下达】【取消】；
   - `status=已下达` → 【取消】；
   - `status=生产中` / `已完成` / `已取消` → 终态/回传态，无任何按钮。
   - 【下达】：弹确认对话框（标题「下达生产」），展示补库单号，可选填「承诺入库时间」（`promised_inbound`，选填，留空传 undefined）→ 调 `release`。
   - 【取消】：弹确认对话框（标题「取消补库单」）→ 调 `cancel`。
   - 动作成功：toast（如「已下达 · RP…」/「已取消 · RP…」）+ 用返回对象原地刷新已开模态 + 刷新当前列表页。
   - 非法流转（如对已下达点下达、对生产中/已完成点取消）由后端 `FdeError` 经 api.js 统一 toast（「当前状态不可下达」「当前状态不可取消」等），页面**不硬编状态机校验**。
2. **ERP 回传流转的展示**：`已下达 → 生产中 → 已完成` 由 ERP 回传（`on_workorder_started` / `on_inbound`）驱动，前端无对应按钮；用户刷新列表/详情即可看到最新状态（状态徽章随之变化）。`生产中`/`已完成` 行无操作按钮。
3. **模态**：统一三段式；加载态等待消失后再断言内容；头带墨青 + `hue()` 状态徽章。
4. **quiet 探测性加载**：material 下拉 quiet + 零值兜底，失败不喷 toast；补库单列表本身正常加载，错误走 api.js 统一通道。
5. **展示工具**：`hue()`（补库类型三色、状态五色徽章）、`dash()`（promised_inbound 空值）、`fmt()`（replenish_qty 数值）；日期字段 `required_inbound` / `promised_inbound` 为纯日期文本（后端存储 `YYYY-MM-DD`，非时间戳，无需 `fmtTime()`）；无 `*_json` 快照字段，无需 `tryParse()`。
6. **toast**：下达成功 / 取消成功 / 必填确认；其余错误（补库单不存在、状态非法等）一律由 api.js 统一呈现。

## 6. 验收关注点（供第⑧步前端测试用例）

1. **路由渲染**：`#/demand_pool` 挂载出列表三段式（过滤条 + 表格 + 分页条），**断言无 `.kpi`**（非看板页防挂载粘滞假过）；菜单「🛠 需求池」按 order=150 定位。
2. **造数后列表有数据**：先经 `md_material.create` 造物料（M1）→ 经 `demand_pool.create` 造多条补库单（覆盖 待下达/已下达/生产中/已完成/已取消 与 缺货/最低/安全 三类型）→ 列表行数正确，replenish_no / material_no / replenish_type / replenish_qty / required_inbound / promised_inbound / status 列齐全（7 字段全上）。
3. **过滤一一对应**：物料号下拉选 M1 → 仅 M1 行（US-07-AC1）；replenish_type=缺货补库 chips → 仅缺货补库行（US-07-AC2）；status=待下达 → 仅待下达行（US-07-AC3）；三条件组合；无匹配显示空态且不抛错。
4. **模态全字段**：点 replenish_no 开模态，断言 replenish_no / material_no / replenish_type / replenish_qty / required_inbound / promised_inbound / status 全部可见 + 「原始数据」可展开；终态行（已完成/已取消/生产中）模态页脚无动作按钮。
5. **状态机动作回显**：待下达行【下达】→ 确认 → 行与模态 status=已下达（US-02-AC1）；待下达/已下达行【取消】→ status=已取消（US-05-AC1/AC2）；已下达行无【下达】按钮（仅【取消】）；生产中/已完成行无任何操作按钮（US-05-AC3 由后端执法）。
6. **无创建入口**：页面**不存在**「新建 / 创建 / 批量导入」按钮或表单（自动参考创建铁律）；断言无创建表单控件。
7. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP≥400（受限会话 403 属预期执法单独豁免）。
