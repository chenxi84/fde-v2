# 项目零件映射 前端详设
> 来源：app/psc/_contracts.md（冻结契约）+ app/psc/md_project_part/应用详设.md；产出供第⑦步前端编码 / 第⑧步前端测试用例
> 落位：`app/psc/md_project_part/view.js` + `app/psc/md_project_part/view.html`（与 `md_project_part.py` 同文件夹，落盘即进启动清单与授权清单，零接线）；import 一律绝对路径 `/view/lib/*`；模板经 `new URL("view.html", import.meta.url)` 抓取；工厂 `export default function pageMdProjectPart()`（保留专名）
> 页面定位：**主数据映射页（独立创建）**——数据来源类型为「独立创建（PLM 冗余同步 + 本地录入）」，后端开放 create / get / list / update / import_batch（另含跨应用接口 list_by_material，前端不直接调用）；无状态机（量纲随项目阶段隐式演进），故详情模态头带无状态徽章、行内无状态流转动作。

## 2. 区块构成

### 2.1 列表区（查）—— 三段式：工具栏 / 表格 / 分页条

**用途**：项目零件映射台账，按项目号 / 物料号两个模糊维度筛选，承载新建、编辑、批量导入入口。本页为非看板页，**不设 KPI 指标带**（验收断言无 `.kpi`）。

> **数据治理变更（2026-08）**：车型 / 供应份额为项目级信息，只在 `md_project` 维护，映射表不存储；列表 / 详情经 `project_no` 关联项目显示（`projVeh()/projShare()`），表单不再提供车型 / 份额输入，过滤条不再设车型搜索。下文仍按旧口径（车型入映射表/可筛选/表单必填）的描述以本变更为准。

**过滤控件（与 `md_project_part.list(project_no, material_no, veh_model, page, size)` 可过滤参数一一对应；契约无 keyword 参数 → 不设关键字搜索框，禁止前端假过滤）**：

| 控件 | 对应参数 | 形态 |
|---|---|---|
| 项目号输入框 | `project_no` | placeholder「项目号」，Enter 或「查询」按钮触发（后端 LIKE 模糊匹配） |
| 物料号输入框 | `material_no` | placeholder「物料号」，Enter 或「查询」按钮触发（后端 LIKE 模糊匹配） |
| 车型输入框 | `veh_model` | placeholder「车型」，Enter 或「查询」按钮触发（后端 LIKE 模糊匹配） |
| 分页条 | `page` / `size` | `pageable()`，integer 传参（契约参数名为 `size`，非 `page_size`） |

**工具栏**：「查询」「+ 新建映射」（打开 2.3 创建模态）「批量导入」（打开 2.4 导入模态）。

**表格列（`.tbl.tight` + `.scroll-x`；全部为详情字段子集；字段序与详情/表单一致）**：

| 列 | 字段 | 渲染 |
|---|---|---|
| 项目号 | `project_no` | `.b-link`，点击打开详情模态；projectMap 命中时附项目名小字 |
| 物料号 | `material_no` | 文本；materialMap 命中时附物料名小字 |
| 车型 | `veh_model` | 文本 |
| 单车用量 | `usage` | 正整数，`fmt()` 右对齐 |
| 供应份额 | `share` | 百分比 `fmt()`（如 0.8 → 80%），范围 [0,1] |
| 操作 | — | 【编辑】（开编辑表单，`project_no`+`material_no` 锁定） |

**交互**：任一过滤变化 → 重置回第 1 页重载；编辑/导入成功后刷新当前页；空结果显示空态文案（不喷 toast）。

### 2.2 详情模态（查全）—— 三段式：墨青头带 / KV 分组体 / 操作页脚

**用途**：点 `project_no` 弹出，展示 `md_project_part.get(project_no, material_no)` 返回的**全部**字段（共 5 个业务字段，无审计字段、无 `*_json` 快照字段）。

| 分组（`.sec`） | 字段 | 渲染 |
|---|---|---|
| 头带 | `project_no` + `material_no` | 墨青头带，展示「项目×物料」复合主键（本应用无状态机，无状态徽章） |
| 基本信息 | `project_no` / `material_no` | `.kv`；注明「复合主键 · project_no+material_no 创建后不可直接变更（BR-01）」；projectMap/materialMap 命中时附名称 |
| 量纲信息 | `usage`（+ 关联项目的车型/份额） | `.kv`；`usage` 注明「正整数」（BR-05）；车型/份额注明「关联项目 · 不在映射表存储」 |
| 原始数据 | get 返回全量 JSON | 底部折叠（默认收起） |

**页脚 `.modal-ft`**：【编辑】（打开编辑表单）【关闭】。

### 2.3 创建 / 编辑表单（增/改）—— 模态表单

**用途**：覆盖 `md_project_part.create`（5 参数全必填）与 `md_project_part.update`（project_no+material_no 定位键 + veh_model/usage/share 可改）接受的业务参数。

| 字段 | 控件 | 必填 | create 可见 | update 可见 | 约束来源 |
|---|---|---|---|---|---|
| `project_no` | 项目 autocomplete（见 §4，来源 `md_project.list`） | ★ 必填 | 是 | 否（只读展示） | BR-01/BR-03；后端 cross-app 调 `md_project.get` 校验存在 |
| `material_no` | 物料 autocomplete（见 §4，来源 `md_material.list`） | ★ 必填 | 是 | 否（只读展示） | BR-01/BR-04；后端 cross-app 调 `md_material.get` 校验存在 |
| `veh_model` | input，maxlength=50 | ★ 必填 | 是 | 是 | BR-02；量纲三要素之一 |
| `usage` | input number，min=1，step=1 | ★ 必填 | 是 | 是 | BR-05；单车用量须为正整数 |
| `share` | input number，min=0，max=1，step=0.01 | ★ 必填 | 是 | 是 | BR-06；供应份额 [0,1] |

- create 模式：全部 5 字段必填（BR-02 全必填 → **不设「更多字段 ▾」折叠区**）；`share` 无默认值、须用户输入。
- update 模式：`project_no` + `material_no` 回填展示但不可修改（复合主键，BR-01）；`veh_model` / `usage` / `share` 可修改。如需变更项目或物料，应删除旧映射后新建（本应用 V1 无 delete，需新建替代组合）。
- 布局：必填先行、frow 语义分组——第一行（project_no autocomplete + material_no autocomplete）、第二行（veh_model）、第三行（usage + share）；底部右对齐「取消」「保存」。
- 前端做必填与单车用量整数/正数前置校验（不满足 → toast 警告、不提交）；usage 整数、project_no+material_no 唯一性、引用存在性最终由后端校验，`FdeError` 经 api.js 以错误 toast 呈现。
- cross-app 校验：创建/更新时后端调 `self.fde.call("md_project","get", project_no)` + `self.fde.call("md_material","get", material_no)`；前端 autocomplete 已限定选项以降低无效输入。
- 提交成功：toast 成功消息 → 关闭模态 → 重置过滤重载列表（create）/ 刷新当前页（update）。

### 2.4 批量导入（增/改 upsert）

**用途**：点击「批量导入」按钮，弹出导入模态，调 `md_project_part.import_batch`（列：project_no, material_no, veh_model, usage, share）。

- 提供模板下载链接（表头：project_no, material_no, veh_model, usage, share）。
- 上传/粘贴数据 → 后端逐行校验（必填、引用存在、usage>0、share∈[0,1]）+ upsert（已存在主键行 → 更新 veh_model/usage/share，新行 → 新增）。
- 返回摘要 `{total, success, fail, errors: [{row, field, message}]}`，模态内展示成功数 / 失败数 / 错误明细列表。
- 导入完成后关闭模态并刷新当前页。

| 区块 | 调用（应用.服务） | 参数 | quiet | 说明 |
|---|---|---|---|---|
| 列表区 | `svc("md_project_part","list")` | `{project_no, material_no, veh_model, page, size}` | — | 分页查询；空条件传 undefined 不带 |
| 项目下拉 | `svc("md_project","list")` | `{page:1, page_size:200}` | true | quiet 探测；零值兜底（跨应用调用，字面量产生 psc:md_project_part → md_project.list 派生边） |
| 物料下拉 | `svc("md_material","list")` | `{page:1, page_size:500}` | true | quiet 探测；零值兜底（跨应用调用，字面量产生 psc:md_project_part → md_material.list 派生边） |
| 详情模态 | `svc("md_project_part","get")` | `{project_no, material_no}` | — | 复合主键全字段详情 |
| 创建表单 | `svc("md_project_part","create")` | `{project_no, material_no, veh_model, usage, share}` | — | 新建映射；跨应用双校验 |
| 编辑表单 | `svc("md_project_part","update")` | `{project_no, material_no, veh_model, usage, share}` | — | 更新量纲（仅传有变更字段，主键只读） |

> `list_by_material` 为跨应用接口（供量纲折算/预测分摊经 `self.fde.call` 调用，详见详设 FUNC-05），**本页前端不调用、不进 svc 清单**。

## 4. 数据来源与下拉

**项目下拉（创建表单 autocomplete，来源 `svc("md_project","list")`）**：
- 页面初始化一次性 `svc("md_project","list")` `{page:1, page_size:200}`，`quiet:true` 探测：失败不喷 toast；零值兜底 → 下拉显示「暂无可选项目」禁用项。
- 由返回项构建 `projectOptions` **扁平数组**（字段 `project_no, project_name`），autocomplete 显示「project_no - project_name」双行，选中后表单回填 `project_no`。

**物料下拉（创建表单 autocomplete，来源 `svc("md_material","list")`）**：
- 页面初始化一次性 `svc("md_material","list")` `{page:1, page_size:500}`，`quiet:true` 探测：失败不喷 toast；零值兜底 → 下拉显示「暂无可选物料」禁用项。
- 由返回项构建 `materialOptions` **扁平数组**（字段 `material_no, material_name`），autocomplete 显示「material_no - material_name」双行，选中后表单回填 `material_no`。

> 主数据引用铁律：`project_no` / `material_no` 均使用内联 autocomplete 下拉（`@click.stop` 展开 + `@input` 过滤 + `@click.away` 关闭，同时匹配代号与名称），**禁止普通 `<select>`**。两个选项源各用**独立扁平数组**（`projectOptions` / `materialOptions`），**禁止**嵌套对象 `autoOptions[field]`（Alpine reactive 对嵌套属性追踪不稳定）。

**契约 payload → 区块字段映射**：

| 来源 | payload 字段 | 去向 |
|---|---|---|
| `md_project_part.list` 项 | project_no, material_no, veh_model, usage, share | 2.1 列表列（1:1） |
| `md_project_part.get` | project_no, material_no, veh_model, usage, share（全量） | 2.2 详情模态 KV 分组 + 原始数据折叠 |
| `md_project_part.create` 入参 | project_no, material_no, veh_model, usage, share | 2.3 创建表单（全 5 项） |
| `md_project_part.update` 入参 | project_no, material_no, veh_model, usage, share | 2.3 编辑表单（project_no/material_no 只读） |
| `md_project_part.import_batch` 入参 | rows: [{project_no, material_no, veh_model, usage, share}] | 2.4 批量导入 |
| `md_project.list` 项 | project_no, project_name | 项目 autocomplete 选项 + projectMap |
| `md_material.list` 项 | material_no, material_name | 物料 autocomplete 选项 + materialMap |

- 无快照字段、无 `*_json` 字段、无审计字段（`_to_dict` 仅返回 5 业务字段），详情无需 `tryParse()`、列表无需 `dash()` 兜底审计列。

## 5. 交互要点

1. **加载**：首载正常拉取 list（非看板页，失败走 api.js 统一通道）+ quiet 拉取 `md_project.list` + `md_material.list` 构建双下拉；`self.list` 等 reactive 状态须在首个 `await` 前同步建好（pitfalls #37）。
2. **过滤**：project_no / material_no / veh_model 输入后 Enter 或「查询」触发；翻页仅改 `page/size`，不清过滤条件。
3. **双 autocomplete**：project_no 与 material_no 各独立 autocomplete 下拉（`@click.stop` / `@click.away` / `@input` 实时过滤），选项存储为独立扁平数组（`projectOptions` / `materialOptions`），列表项双行显示「编码 - 名称」，选中后回填对应编码。
4. **微交互**：表格行 hover 高亮；project_no `.b-link` hover 下划线；share 百分比格式化显示；「保存」按钮提交期 loading 防重复点击。
5. **成功流**：create 成功 → 关闭模态并清空表单 → toast「项目零件映射创建成功」→ 列表回第 1 页重载；update 成功 → 关闭模态 → toast「映射更新成功」→ 刷新当前页；import_batch 完成 → 弹摘要（成功 N / 失败 M）→ 关闭后刷新当前页。
6. **错误流**：重复映射（「该项目-物料映射已存在」）/ 项目不存在 / 物料不存在 / 单车用量须大于0 / 供应份额须在0~1之间 等后端 `FdeError` → toast 错误信息，模态保持打开便于修改后重试。
7. **空态**：无任何映射时「暂无映射 —— 点『新建映射』创建」；过滤无命中时「无符合条件的映射」。
8. **批量导入**：文件/数据选择后提交 → 导入过程 loading → 完成展示摘要（成功数 / 失败数 / 错误明细列表）→ 关闭刷新。
9. **展示工具**：`fmt()`（share 百分比、usage 数值）、`dash()`（下拉未命中时名称回退）、无状态徽章（本应用无状态机，无需 `hue()`）、无时间字段无需 `fmtTime()`、无 `*_json` 字段无需 `tryParse()`。

## 6. 验收关注点（供第⑧步前端测试用例）

1. **路由渲染**：`#/md_project_part` 挂载出列表三段式（工具栏 + 表格 + 分页条），**断言无 `.kpi`**（非看板页防挂载粘滞假过）；菜单「🔗 项目零件映射」按 order=50 定位。
2. **造数后列表有数据**：先造 project（PRJ-1）+ material（M1）→ 经 `md_project_part.create` 造多条映射（覆盖不同 veh_model/usage/share）→ 列表行数正确，project_no / material_no / veh_model / usage / share 列非空。
3. **过滤一一对应**：project_no=PRJ 模糊匹配；material_no=8210 模糊匹配；veh_model=车型A 模糊匹配；三条件组合（US-02-AC1/2/3）；无匹配显示空态且不抛错。
4. **模态全字段**：点 project_no 开模态，断言 project_no / material_no / veh_model / usage / share 全部可见 + 「原始数据」可展开；头带展示复合主键、无状态徽章。
5. **表单落库**：create 表单选 project_no + material_no（autocomplete）+ 填 veh_model/usage/share（★ 全必填）→ 提交 → 列表出现新记录；空必填字段提交 → toast 警告且不发请求；重复 project_no+material_no → 后端 FdeError toast（BR-01/US-01-AC2）。
6. **双 autocomplete**：project_no 下拉含已创建项目；material_no 下拉含已创建物料；选中后正确回填编码；输入关键字过滤命中代号与名称。
7. **跨应用双校验**：project_no 选不存在项目 → 后端 toast「项目不存在」（US-01-AC3）；material_no 选不存在物料 → 后端 toast「物料不存在」（US-01-AC4）。
8. **范围约束**：usage=0/-1 → 后端 toast「单车用量须大于0」（US-04-AC3）；share=1.5 → 后端 toast「供应份额须在0~1之间」（US-04-AC2）。
9. **update 主键只读**：编辑模态 project_no + material_no 只读不可改；修改 share 保存后列表与详情均反映新值（US-04-AC1）。
10. **批量导入**：上传含「3 合法新行 + 1 已有主键行 + 1 缺物料行」的数据 → 摘要正确展示 3 新增 / 1 更新 / 1 失败及错误明细（US-06-AC2/AC3）。
11. **干净控制台**：全程 0 console error / 0 pageerror / 0 HTTP≥400（受限会话 403 属预期执法单独豁免）。
