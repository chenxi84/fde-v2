## 1. 需求概览

### 1.1 基本信息
- **需求名称**: 项目零件映射管理
- **需求编号**: REQ-PSC-MDPP-001
- **所属模块**: 产销协同-主数据层
- **需求来源**: 业务方（销售/计划）
- **创建日期**: 2026-08-14
- **优先级**: P0

### 1.2 需求背景
#### 1.2.1 为什么需要这个需求？
项目零件映射定义了「项目 × 零件 × 车型」的用量/份额量纲关系（单车用量/供应份额），是借用参考 scale 量纲、预测按份额分摊等量纲折算的潜在依据。若无该映射，预测分摊与量纲折算将缺少权威的用量/份额基准。

#### 1.2.2 期望达到什么目标？
建立项目号 + 物料号的映射台账（单车用量），为量纲折算与预测分摊提供权威数据，并通过引用校验保证项目号、物料号指向真实存在的主数据。

> **数据治理变更（2026-08）**：车型（veh_model）与供应份额（share）为**项目级信息**，只在 `md_project` 维护；映射表**不再存储**这两列（旧库自动迁移丢弃），列表/详情通过 `project_no` 关联项目显示。映射表仅保留零件级「单车用量（usage）」。下文个别 AC 仍按旧口径描述车型/份额入映射表者，以本变更为准。

### 1.3 需求范围
#### 1.3.1 包含哪些功能？
项目零件映射的创建、详情查看、列表查询、更新、按物料查所有项目映射（list_by_material）、批量导入/更新（import_batch）。

#### 1.3.2 不包含哪些功能？
- 不做零件 BOM/工艺定额管理（不在产销协同域范围）
- 不做映射审批流（主数据维护，无需审批）

> **数据来源类型**: 独立创建（PLM 冗余同步 + 本地录入）—— 数据由 PLM 冗余同步或用户在本应用内录入，前端保留"新建"按钮。

### 1.4 涉及角色
**谁会使用这个功能？**

- **总部计划**: 维护项目零件映射关系（新建/更新/批量导入），配置车型/单车用量/供应份额
- **一线销售**: 查看映射关系（作为量纲折算/预测分摊的数据来源）

## 2. 用户故事

### 2.1 核心用户故事

#### 2.1.1 `US-01` 用户故事 — 创建项目零件映射（优先级：P1）

- **故事描述**: 作为总部计划，我想要创建项目与物料的映射关系，以便于定义项目×零件×车型的用量/份额量纲
- **为何赋予此优先级**：映射是量纲折算与预测分摊的基础，无映射则无法折算
- **独立测试**：可通过进入映射页面，点击"新建"，选择已有项目和物料，填写车型/单车用量/供应份额后保存并验证来独立测试
- **前置条件**: 引用的 project_no 已存在于 md_project，引用的 material_no 已存在于 md_material
- **后置条件**: 系统生成一条新的映射记录，project_no+material_no 组合唯一

**验收场景**：

1. `US-01-AC1` **场景**: 合法参数创建成功
   - **Given** 项目 PRJ-001 和物料 8210001 均存在，project_no+material_no 组合未使用，**When** 填写 project_no=PRJ-001, material_no=8210001, veh_model=车型A, usage=2, share=0.8 后保存，**Then** 记录创建成功，可通过 get(PRJ-001, 8210001) 查询到完整记录

2. `US-01-AC2` **场景**: 重复映射被拒绝
   - **Given** 已存在 PRJ-001+8210001 的映射，**When** 再次创建相同组合，**Then** 系统拒绝保存并提示"该项目-物料映射已存在"

3. `US-01-AC3` **场景**: 引用不存在的项目被拒绝
   - **Given** 系统中不存在 project_no=NOTEXIST，**When** 创建映射引用该项目，**Then** self.fde.call('md_project.get') 返回不存在，拒绝保存并提示"项目不存在"

4. `US-01-AC4` **场景**: 引用不存在的物料被拒绝
   - **Given** 系统中不存在 material_no=NOTEXIST，**When** 创建映射引用该物料，**Then** self.fde.call('md_material.get') 返回不存在，拒绝保存并提示"物料不存在"

#### 2.1.4 `US-04` 用户故事 — 更新项目零件映射（优先级：P2）

- **故事描述**: 作为总部计划，我想要更新映射的车型/单车用量/供应份额，以便于跟踪量纲变更
- **为何赋予此优先级**：量纲变更（份额调整/用量调整）是业务常态，需保持映射时效性
- **独立测试**：可通过查询一条已有映射，修改 share 后保存并验证生效来独立测试
- **前置条件**: 目标记录已存在
- **后置条件**: 记录更新成功

**验收场景**：

1. `US-04-AC1` **场景**: 更新供应份额成功
   - **Given** 存在映射 PRJ-001+8210001 share=0.8，**When** 修改 share=1.0 后保存，**Then** 更新成功，重新查询 share=1.0

2. `US-04-AC2` **场景**: 份额超出范围被拒绝
   - **Given** 存在映射 PRJ-001+8210001，**When** 修改 share=1.5，**Then** 系统拒绝保存并提示"供应份额须在0~1之间"

3. `US-04-AC3` **场景**: 单车用量非法被拒绝
   - **Given** 存在映射 PRJ-001+8210001，**When** 修改 usage=0 / -1 / 1.5，**Then** 系统拒绝保存并提示"单车用量须大于0"/"单车用量须为整数"

4. `US-04-AC4` **场景**: 变更引用须重新校验
   - **Given** 存在映射，**When** 修改 material_no 为不存在的物料号，**Then** self.fde.call 校验失败，拒绝保存

#### 2.1.5 `US-05` 用户故事 — 按物料查所有项目映射（优先级：P2）

- **故事描述**: 作为系统（量纲折算/预测分摊的调用方），我想要按物料号查询其所有项目映射，以便于获得该物料在各项目中的单车用量/供应份额
- **为何赋予此优先级**：list_by_material 是量纲折算（借用参考 scale）与预测分摊的潜在前置调用
- **独立测试**：可通过传入一个出现在多个项目映射中的物料号，验证返回全部映射来独立测试
- **前置条件**: 系统中存在该物料的项目映射
- **后置条件**: 返回该物料号的所有项目映射列表（不限项目阶段）

**验收场景**：

1. `US-05-AC1` **场景**: 通用物料返回多条映射
   - **Given** 物料 8210001 同时出现在 PRJ-001 和 PRJ-002 的映射中，**When** 调用 list_by_material(8210001)，**Then** 返回2条映射记录

2. `US-05-AC2` **场景**: 专用物料仅返回一条映射
   - **Given** 物料 8210002 仅出现在一个项目的映射中，**When** 调用 list_by_material(8210002)，**Then** 返回1条映射记录

#### 2.1.6 `US-06` 用户故事 — 批量导入项目零件映射（优先级：P2）

- **故事描述**: 作为总部计划，我想要通过批量导入（Excel/PLM 同步）映射数据，以便于系统初始化或 PLM 冗余同步时高效建账
- **为何赋予此优先级**：映射数据来源含 PLM 冗余同步，批量导入是初始化与同步的核心入口
- **独立测试**：可通过准备合法的导入数据，执行导入并验证所有行均已入库来独立测试
- **前置条件**: 导入文件格式符合规范（列：project_no, material_no, veh_model, usage, share）
- **后置条件**: 导入成功的行入库，失败的行返回错误明细

**验收场景**：

1. `US-06-AC1` **场景**: 全部合法行导入成功
   - **Given** 导入文件含5条合法映射记录且无主键冲突，**When** 执行导入，**Then** 5条均入库，返回成功计数

2. `US-06-AC2` **场景**: 部分行冲突—冲突行更新
   - **Given** 导入文件含5条，其中2条 project_no+material_no 与已有记录冲突，**When** 执行导入，**Then** 3条新增入库，2条已有记录的 veh_model/usage/share 被更新（upsert）

3. `US-06-AC3` **场景**: 引用不存在的项目/物料—该行失败
   - **Given** 导入文件某行 material_no 不存在，**When** 执行导入，**Then** 该行导入失败，错误明细提示"物料不存在"，其他合法行正常导入

## 3. 业务场景

### 3.1 业务流程描述

#### 3.1.1 场景1: 建立项目零件映射
1. 总部计划进入"项目零件映射"页面，点击"新建"
2. 系统展示映射表单（project_no, material_no, veh_model, usage, share）
3. 用户选择 project_no（来源：md_project.list 下拉选择）
4. 用户选择 material_no（来源：md_material.list 下拉选择）
5. 用户填写车型、单车用量、供应份额
6. 系统校验 project_no+material_no 唯一性、引用存在性（self.fde.call）、字段范围
7. 校验通过，记录入库；不通过，提示具体错误

#### 3.1.2 场景2: PLM 冗余同步 / 批量导入
1. 总部计划进入"项目零件映射"页面，点击"批量导入"（或由 PLM 同步触发 import_batch）
2. 系统接收导入行（project_no, material_no, veh_model, usage, share）
3. 系统逐行校验：主键唯一、引用存在（md_project.get / md_material.get）、usage>0、share∈[0,1]
4. 已存在主键行 → 更新（upsert），新行 → 新增
5. 系统返回导入结果摘要（成功数、失败数、错误明细）

### 3.2 业务规则

#### 3.2.1 `BR-01` 项目+物料组合唯一
- **规则描述**: 同一项目+物料组合全局唯一（project_no + material_no 为复合主键）
- **适用场景**: 创建、导入
- **示例**: PRJ-001+8210001 已存在，不可再建相同组合

#### 3.2.2 `BR-02` 必填字段校验
- **规则描述**: project_no, material_no, veh_model, usage, share 均为必填，不可为空
- **适用场景**: 创建、更新、导入
- **示例**: 创建时 material_no 为空 → 拒绝保存，提示"物料号不能为空"

#### 3.2.3 `BR-03` 项目引用校验
- **规则描述**: project_no 必须已存在于 md_project 中，创建/更新时通过 self.fde.call('md_project.get', project_no) 校验
- **适用场景**: 创建、更新、导入
- **示例**: 引用不存在的项目 → 拒绝保存，提示"项目不存在"

#### 3.2.4 `BR-04` 物料引用校验
- **规则描述**: material_no 必须已存在于 md_material 中，创建/更新时通过 self.fde.call('md_material.get', material_no) 校验
- **适用场景**: 创建、更新、导入
- **示例**: 引用不存在的物料 → 拒绝保存，提示"物料不存在"

#### 3.2.5 `BR-05` 单车用量校验
- **规则描述**: usage（单车用量）必须为**正整数**（>0 且为整数）
- **适用场景**: 创建、更新、导入
- **示例**: usage=0 / -1 → 提示"单车用量须大于0"；usage=1.5 → 提示"单车用量须为整数"

#### 3.2.6 `BR-06` 供应份额范围约束
- **规则描述**: share（供应份额）须在 [0, 1] 范围内（含 0 和 1）
- **适用场景**: 创建、更新、导入
- **示例**: share=1.5 → 拒绝保存，提示"供应份额须在0~1之间"

### 3.3 业务数据

#### 3.3.1 数据1: 项目号 project_no
- **数据描述**: 关联的项目编号，复合主键之一
- **数据类型**: 文本
- **数据来源**: 来源：md_project 下拉选择/校验（self.fde.call('md_project.get')）
- **示例值**: PRJ-001

#### 3.3.2 数据2: 物料号 material_no
- **数据描述**: 关联的物料号，复合主键之一
- **数据类型**: 文本
- **数据来源**: 来源：md_material 下拉选择/校验（self.fde.call('md_material.get')）
- **示例值**: 8210001

#### 3.3.3 数据3: 车型 veh_model
- **数据描述**: 客户车型，量纲关系三要素之一（项目×零件×车型）
- **数据类型**: 文本
- **数据来源**: 用户录入 / PLM 同步
- **示例值**: 车型A

#### 3.3.4 数据4: 单车用量 usage
- **数据描述**: 每辆车使用该零件的数量（>0）
- **数据类型**: 数字
- **数据来源**: 用户录入 / PLM 同步
- **示例值**: 2

#### 3.3.5 数据5: 供应份额 share
- **数据描述**: 对该零件的供应份额比例，范围 [0, 1]
- **数据类型**: 数字
- **数据来源**: 用户录入 / PLM 同步
- **示例值**: 0.8

### 3.4 状态机
无状态机。量纲随项目阶段隐式演进，无独立生命周期状态流转。

### 4.3 功能详细说明

#### 4.3.1 F01-04 项目零件映射

##### 4.3.1.1 FUNC-01 创建项目零件映射

**功能描述**:
提供项目零件映射的创建表单，用户选择已有项目和物料并填写量纲信息（车型/单车用量/供应份额）后保存。此功能为独立创建——前端保留"新建"按钮。

**用户操作流程**:
1. 用户进入"项目零件映射"列表页，点击"新建"按钮
2. 系统展示创建表单
3. 用户选择 project_no（来源：md_project.list 下拉选择）
4. 用户选择 material_no（来源：md_material.list 下拉选择）
5. 用户填写 veh_model, usage, share
6. 用户点击"保存"
7. 系统执行校验：
   a. project_no+material_no 唯一性（BR-01）
   b. 必填校验（BR-02）
   c. project_no 存在性（BR-03，self.fde.call → md_project.get）
   d. material_no 存在性（BR-04，self.fde.call → md_material.get）
   e. usage 为正整数（BR-05）
   f. share ∈ [0,1]（BR-06，项目级，仅旧口径）
8. 校验通过 → 记录入库

**输入数据**:
- project_no: 项目号 - 必填，来源 md_project.list 下拉选择 - 示例：PRJ-001
- material_no: 物料号 - 必填，来源 md_material.list 下拉选择 - 示例：8210001
- veh_model: 车型 - 必填，最大50字符 - 示例：车型A
- usage: 单车用量 - 必填，数字 >0 - 示例：2
- share: 供应份额 - 必填，数字 [0,1] - 示例：0.8

**输出数据**:
- 成功消息: "项目零件映射创建成功"
- 错误消息: "该项目-物料映射已存在" / "项目不存在" / "物料不存在" / "单车用量须大于0" / "供应份额须在0~1之间" / "XX字段不能为空"

**业务规则**:
- BR-01: project_no+material_no 组合唯一
- BR-02: project_no, material_no, veh_model, usage, share 必填
- BR-03: project_no 须经 md_project.get 校验
- BR-04: material_no 须经 md_material.get 校验
- BR-05: usage 为正整数
- BR-06: share ∈ [0,1]

**特殊处理**:
- project_no 和 material_no 的前端下拉选择分别来源于 md_project.list 和 md_material.list（主数据引用铁律：禁止手工录入）
- 创建时后端做两次 self.fde.call 校验引用完整性

**业务实体**:
- **MdProjectPart**: 项目×零件×车型的量纲关系，含单车用量/供应份额，标识为 project_no + material_no

**MdProjectPart 字段**

| 字段名称 | 字段类型 | 是否必填 | 默认值 | 业务逻辑 |
|---|---|---|---|---|
| project_no | 文本 | 是 | - | 项目号，PK之一，来源：md_project 下拉选择/校验；后端 self.fde.call('md_project.get') 校验 |

##### 4.3.1.4 FUNC-04 更新映射

##### 4.3.1.6 FUNC-06 批量导入映射

**功能描述**:
通过批量导入（Excel/PLM 同步，列：project_no, material_no, veh_model, usage, share），系统逐行校验入库。已存在的主键行执行更新（upsert），不存在的新增。

**用户操作流程**:
1. 用户点击"批量导入"按钮（或由 PLM 同步触发）
2. 系统接收导入数据（含模板下载入口）
3. 系统逐行校验：必填、引用存在（md_project.get / md_material.get）、usage>0、share∈[0,1]
4. 导入完成 → 系统返回摘要（成功数、失败数、错误明细列表）

**输入数据**:
- 导入数据，列：project_no, material_no, veh_model, usage, share

**输出数据**:
- 导入摘要: { total: N, success: N, fail: N, errors: [{ row, field, message }] }

**业务规则**:
- BR-01: 主键已存在行 → 更新 veh_model/usage/share（upsert），非冲突拒绝
- BR-02: 必填字段为空行 → 失败，记录错误明细
- BR-03/BR-04: 引用不存在的项目/物料 → 失败，记录错误明细
- BR-05: usage<=0 → 失败，记录错误明细
- BR-06: share 超出 [0,1] → 失败，记录错误明细

**特殊处理**:
- Upsert 策略：已存在主键 → 更新 veh_model, usage, share
- 提供模板下载：含表头行（project_no, material_no, veh_model, usage, share）的空白文件

## 6. 验收标准

### 6.1 功能验收标准

#### 6.1.1 标准1: 映射 CRUD 完整闭环
- **关联用户故事**: US-01, US-02, US-03, US-04
- **关联业务规则**: BR-01, BR-02, BR-05, BR-06
- **验证方式**: 创建映射→列表查询→详情查看→更新 share→再查询
- **测试数据**: project_no=已有项目, material_no=已有物料, usage=2, share=0.8
- **预期结果**: 创建成功；更新 share=1.0 后再次查询值已变更

#### 6.1.2 标准2: 引用完整性双校验
- **关联用户故事**: US-01, US-04
- **关联业务规则**: BR-03, BR-04
- **验证方式**: 创建映射时引用不存在的项目 / 不存在的物料
- **测试数据**: project_no=NOTEXIST / material_no=NOTEXIST
- **预期结果**: 两次 self.fde.call 均返回不存在，拒绝创建并提示具体不存在实体

#### 6.1.3 标准3: 单车用量与供应份额范围约束
- **关联用户故事**: US-01, US-04
- **关联业务规则**: BR-05, BR-06
- **验证方式**: 创建/更新时 usage 传入 0/-1，share 传入 1.5/-0.5
- **预期结果**: usage<=0 被拒绝提示"单车用量须大于0"；share 越界被拒绝提示"供应份额须在0~1之间"

#### 6.1.4 标准4: 批量导入正常+异常混合场景
- **关联用户故事**: US-06
- **关联业务规则**: BR-01, BR-03, BR-04, BR-05, BR-06
- **验证方式**: 导入含5行数据（3行合法新记录、1行已有主键、1行物料不存在）
- **测试数据**: 合法新记录3条 + 已有主键1条 + 缺物料行1条
- **预期结果**: 3条新增入库，已有主键行被更新，物料不存在行失败并返回错误明细

### 6.2 非功能验收标准
**性能要求**: 列表查询（1000条以内）页面加载时间<2秒
**安全性要求**: 引用校验在服务端通过 self.fde.call 强制实施
**兼容性要求**: 支持 Chrome、Edge 浏览器

### 6.3 已知问题或限制
- 映射删除功能暂不提供（V1 只增不改删，避免量纲折算/分摊级联问题）
- project_no 或 material_no 变更需通过删除+新建方式实现
- 项目零件映射消费场景（借用参考 scale 量纲 / 预测按份额分摊）待业务方确认，当前可能属冗余主数据（见 architecture.md Q7）
