# 第5章 管理体系详述——毛需求发布和净需求运算

销售预测（第3章）给出了客户需求，库存策略（第4章）给出了库存目标水位。本章把它们合并为毛需求并发布，再叠加执行数据运算出净需求——净需求才是真正驱动生产的数量。

## 5.1 毛需求的构成

**毛需求是每个物料「销售预测 + 库存策略」的总和**，代表该物料在未来各期需要满足的全部需求：

```
毛需求 = 销售预测 + 库存策略
```

| 构成 | 来源 | 含义 |
|---|---|---|
| 销售预测 | 第 3 章产出 | 客户需求：对客户 N+1~N+3 滚动需求量的预测 |
| 库存策略 | 第 4 章产出 | 目标水位：库存要维持的水平（最低 + 安全 + 组批） |

两者相加，构成该物料在对应期间的「总需求」，是净需求运算的需求侧输入。

## 5.2 毛需求的发布

毛需求发布，是把「销售预测」与「库存策略」合并、加工、冻结为正式需求的过程：

1. **合并加工**：销售预测在发布前，完成通用件合并、替换件合并、变更断点等零件级处理；
2. **叠加库存策略**：将库存策略的三层目标水位（最低 + 安全 + 组批）叠加到销售预测上；
3. **发布冻结**：按自然月版本发布，发布后冻结，作为净需求运算的唯一需求输入。月度版本状态流转：`草稿 → 发布（锁定）→ 冻结`——草稿期可编辑预测，发布后锁定不可改，净需求运算后冻结。

毛需求表字段：

| 字段 | 说明 |
|---|---|
| 物料号 | 维度 |
| 月度版本 | 自然月 |
| 滚动月度 | N+1 / N+2 / N+3 |
| 销售预测 | 第 3 章产出的最终预测量（客户需求） |
| 库存策略 | 最低 + 安全 + 组批目标水位 |
| 毛需求 | 销售预测 + 库存策略 |

> 口径说明：库存策略目标水位是「期末目标」，加在总量口径上（期末 N+3），**不逐期分摊**；销售预测按 N+1/N+2/N+3 逐期拆分。净需求运算按总量口径进行，期间内的时点缺货由库存推移表逐期前推捕获。

## 5.3 净需求运算

毛需求代表「要满足的总需求」，但其中有一部分已被现有库存和在途工单覆盖，真正「还需要生产多少」由净需求给出：

```
净需求 = 毛需求 + 未发订单 − 当前库存 − 在途工单
```

展开即：

```
净需求 = （销售预测 + 库存策略）+ 未发订单 − 当前库存 − 在途工单
```

| 项 | 口径 |
|---|---|
| 毛需求 | 销售预测 + 库存策略（§5.1） |
| 未发订单 | 已接收未发运的订单 / 调拨单，承接当前月及近端实际需求 |
| 当前库存 | 自有仓 + 寄售仓（寄售库存仍是我方资产，必须扣减） |
| 在途工单 | 在制 / 在途数量，防重复下单 |

净需求按物料 × 期间输出，经产能平衡后成为主计划（§5.5）。

## 5.4 依赖 ERP 的库存与在途数据

净需求运算中的「当前库存」「在途工单」「未发订单」三项，是**实时变动的执行数据**，本系统不自行生产，必须基于 ERP 提供：

| 数据 | ERP 来源 | 作用 |
|---|---|---|
| 当前库存（自有仓 + 寄售仓） | ERP 库存模块 | 扣减已有库存 |
| 在途工单 | ERP 生产 / 采购模块 | 扣减在制 / 在途，防重复下单 |
| 未发订单 | ERP 销售 / 订单模块 | 承接已下未发的实际需求 |

这些数据从 ERP **冗余（同步副本）到本地**，本系统只读引用。若库存、在途数据缺失或不及时，净需求会系统性算错——**漏扣库存 → 多下单；漏扣在途 → 重复下单**。因此 ERP 数据的及时性与准确性是净需求运算的前提。

## 5.5 主计划：产能平衡的结果

净需求还不是最终的生产指令，需经产能平衡调整后才形成主计划：

```
净需求 → 产能平衡（线下）→ 主计划（导回系统）
```

- 产能平衡（产能约束、优先级排序、产线排程）**不在本项目范围内**，在系统外线下完成；
- 平衡后的结果作为主计划**导回系统**，用于后续的库存推移表（第 6 章），体现「预计入库量」。

主计划字段：

| 字段 | 说明 |
|---|---|
| 物料号 | 维度 |
| 月度版本 | 自然月 |
| 滚动月度 | N+1 / N+2 / N+3 |
| 计划版本号 | 主计划可变更，每次变更版本 +1 |
| 需求量 | 计划生产量 |
| 最迟入库日期 | 该批计划的最迟完工入库时间 |

主计划是库存推移表「预计入库量」的输入来源。
