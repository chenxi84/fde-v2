# 第6章 管理体系详述——需求池管理

主计划（第 5 章净需求经产能平衡后的结果）是「总量」口径，无法覆盖期间内的时点缺货。需求池由库存推移表驱动，按日推演库存水位，把主计划在时点上的缺口重新触发为执行项，是对主计划（进而生产计划）准确性不足的补充。

一句话：**总量靠净需求，时点靠推移表**。

## 6.1 库存推移表

库存推移表是本体系的预警引擎：基于当前库存、已下工单（预计入库）、客户需求（预计出库），逐日推演未来 3 个月的库存水位，从而发现「何时缺货、何时击穿水位」。

推移表的**起始库存**是每天 0 点从 ERP 取的最新库存总额（自有仓成品库存），此后逐日滚动推演未来 3 个月；每天刷新，保证起点与 ERP 实际库存一致、不累积误差。

### 6.1.1 字段

| 字段 | 说明 |
|---|---|
| 物料号 | 主维度（按品种推演） |
| 日期 | 自动初始化未来 3 个月所有自然日；已结束的日隐藏显示但不删除 |
| 预计入库量 | 当日该品种所有工单的合计入库量（基于主计划，含已下工单）；主计划月度需求量**集中记在最迟入库日期当天** |
| 预计出库量 | 当日该品种所有调拨单（调拨到客户仓）的合计出库量（基于当前客户需求） |
| 库存余额 | 当日起点 = 0 点从 ERP 取的最新库存总额；其后逐日 = 上一日余额 + 预计入库量 − 预计出库量 |

### 6.1.2 库存余额口径

库存余额 = 除调拨到客户仓之外，我方所有仓库的成品库存总和（即自有仓）。

> 与第 5 章净需求「当前库存 = 自有仓 + 寄售仓」的分工：净需求按总量扣全部资产（含寄售仓），防重复生产；库存推移表按自有仓单节点推演时点缺货——出库即「调拨到客户仓」，寄售仓的后续消耗由客户下一张调拨单体现。

## 6.2 三类补库需求

推移表逐日对照水位线（来自第 4 章：最低 A、安全 C、组批 B），一旦击穿即生成补库需求：

| 补库类型 | 触发条件 | 优先级 |
|---|---|---|
| 缺货补库 | 库存余额 < 0 | 最高 |
| 最低库存补库 | 库存余额 < 最低水位 A | 其次 |
| 安全库存补库 | 库存余额 < 最低 A + 安全 C | 再次 |

补货量按产能松紧分两档：

| 补库类型 | 产能紧张时补货量 | 产能富余时补货量 |
|---|---|---|
| 缺货补库 | 缺货量（补回 0） | 缺货量 + 组批 B（补到组批水位） |
| 最低库存补库 | 补到最低 A | 补到组批水位 B |
| 安全库存补库 | 补到最低 A + 安全 C | 补到组批水位 B |

核心逻辑：**任何补库触发，产能富余就一次按组批量切线上足（补到组批水位 B），减少未来切线；产能紧张时只补到触发的那条水位线**。

其中「产能富余 / 紧张」由**线下产能平衡时人工标记**（与第 5 章产能平衡在线下完成一致），作为补货量分档的依据。

## 6.3 需求池字段

| 字段 | 说明 |
|---|---|
| 补库单号 | 唯一标识 |
| 物料号 | 关联物料 |
| 补库类型 | 缺货补库 / 最低库存补库 / 安全库存补库 |
| 补库数量 | 按 §6.2 规则确定 |
| 要求入库时间 | 推移表推演出的缺货 / 击穿时点（须在此之前入库） |
| 承诺入库时间 | 产能平衡后承诺的入库时间 |
| 状态 | 待下达 / 已下达 / 生产中（在途）/ 已完成 / 已取消 |

补库单状态流转：

```
待下达 ──产能允许，下达生产──→ 已下达 ──ERP 回传开工──→ 生产中/在途 ──入库──→ 已完成
   │                             │
   └─────需求消失/库存已补───────→ 已取消
```

- 「待下达 → 已下达」由系统下达生产计划给 ERP 触发；
- 「已下达 → 生产中/在途」「生产中/在途 → 已完成」依赖 ERP 回传工单状态与入库（见第 8 章 §8.5）；
- 「已取消」用于需求消失（库存已补、客户取消）时作废。

## 6.4 需求池与生产计划

生产体系最终拿到的需求，由两部分构成：

```
生产需求 = 主计划（第 5 章）+ 需求池补充需求（本章）
```

- **主计划**：净需求经产能平衡后的月度计划；
- **需求池补充需求**：推移表逐日推演出的时点补库需求，对主计划进行动态修正。

两者共同驱动实际调整后的生产计划。
