# 第2章 管理体系概述

本章给出产销协同管理体系的整体框架。后续各章是对其中每一个模块的展开；先建立全局认识，再逐层深入。

## 2.1 体系总览

产销协同管理体系由「一条主链 + 一套补充机制 + 一个治理闭环」构成：

```
销售预测 ─┐
          ├─→ 毛需求 ─→ 净需求 ─→ 产能平衡 ─→ 主计划 ─┐
库存策略 ─┘                                            ├─→ 生产计划
                                       库存推移表 ─→ 需求池 ┘

治理闭环：模型拟合（按物料回填参数）＋ 月度产销平衡会（复盘调参）
```

- **主链**：从销售预测、库存策略到主计划发布的规划链条；
- **补充机制**：需求池，由库存推移表逐日推演驱动，与主计划共同构成生产需求；
- **治理闭环**：模型拟合按物料回填参数，月度产销平衡会复盘调参，保证主链与补充机制持续有效。

## 2.2 需求的主要来源：销售预测

销售预测的核心任务，是预测客户针对每个物料的 N+3 滚动需求量，这是需求的主要来源；当客户不提供预测时，企业需基于历史干净需求自行预测。

销售预测的产出，经加工、合并、调整后发布，构成毛需求的**客户需求部分**。（详见第 3 章）

## 2.3 不确定性的对冲：库存策略

预测天然不可能准确。库存策略用来弥补销售预测的不准确性，按物料分三层设定：

| 层 | 目的 | 应对的问题 |
|---|---|---|
| 最低库存 | 覆盖响应缺口 | 客户需求提前期不足 |
| 安全库存 | 覆盖需求波动 | 客户需求波动性 |
| 组批库存 | 摊薄切换成本 | 频繁切线造成的效率损失 |

三层库存各自对应一个独立的不确定源，设定与诊断时必须分列，不能混为一谈。（详见第 4 章）

## 2.4 从毛需求到净需求

毛需求（= 销售预测 + 库存策略）叠加未发订单，扣减当前库存与在途工单，即运算生成净需求：

```
净需求 = 毛需求 + 未发订单 − 当前库存 − 在途工单
```

其中：毛需求 = 销售预测（客户需求）+ 库存策略（三层目标水位）；未发订单承接当前月及近端实际需求；当前库存含寄售库存；在途工单防止重复下单。净需求经产能平衡后成为主计划（详见第 5 章）。

## 2.5 主计划：产能平衡与最终决策

净需求经产能平衡和最终决策后，发布为主计划。产能平衡时，若产能紧张，优先满足客户需求与最低 / 安全水位补货，组批库存对应的制造任务优先级相对更低——只有富余产能时才执行组批。

## 2.6 主计划的局限与需求池

但不管需求做得再准确，主计划依然面临一个结构性挑战：在产能紧平衡的情况下——尤其在体系上线初期、库存结构尚未建立时——会出现比较频繁的缺货或紧急补货，主计划驱动的生产计划并不能完全指导生产。

原因在于主计划是「计划态」的静态规划，而实际的库存消耗是动态的：**总量靠净需求，时点靠推移表**。

因此需要引入**需求池管理**，作为对主计划（进而生产计划）准确性不足的补充。需求池包含三类补货，按紧急程度从高到低依次为：

1. 缺货导致的补货；
2. 击穿最低库存水位导致的补货；
3. 击穿安全库存水位导致的补货。

这三类补货需求都基于物料的库存推移表逐期推演推导而来，本质上是把主计划在时点上的缺口重新触发为执行项。（详见第 6 章）

## 2.7 库存推移表：体系的预警引擎

库存推移表在本体系中不只是「推导补货」的工具，更是承上启下的预警引擎：

- 对自有仓（单节点）做库存前推推演，寄售仓的消耗由客户调拨单体现；
- 向下产出缺货订单（需求池补货的来源）；
- 同时产出呆滞 / 超储预警，驱动降储，支撑库存周转与减值的治理目标。

## 2.8 治理闭环

在主体框架之上，体系通过「月度产销平衡会 = 策略层、需求池 = 执行层」的分工形成治理闭环：策略层每月复盘并回校参数，执行层按周度/日度节奏执行，异常频次作为治理信号反哺策略层。

在此基础上，还有一项上层建设——**模型拟合**（第 7 章）：通过历史数据运算，为每个物料找到最适合的预测模式与库存策略。它与主链、补充机制一起，构成完整的产销协同管理体系；其落地形态在第 8 章「管理系统设计实现」中展开。
