## 3. 交互规则（逐条对应后端约束）

| # | 规则 | 依据 |
|---|---|---|
| F-1 | **风险等级是推导只读值**：列表列与详情信息条都是徽标文本；**新建表单与编辑表单里都没有等级控件**（连「可能性/后果」在编辑态也是只读的，改等级只能走「评估」） | `BR-01` |
| F-2 | 关闭时**必须先选处置结论**，未选则「确认关闭」按钮 `disabled` | `BR-02` |
| F-3 | 「关闭」的处置结论下拉里，等级为「高」/「严重」时 **「接受」选项 `disabled`**；未登记缓解措施时 **「缓解完成」选项 `disabled`** | `BR-03` / `BR-02` |
| F-4 | **动作入口与服务端同口径**（2026-09-25 补）：未评估等级的行**不显示**「缓解」（服务端「尚未评估等级…」会拒）；非「缓解中」的行**不显示**「关闭」（§3.4 状态机只有 `mitigating → close`）。两处都用 `x-if` 移出 DOM，不用 `x-show` | `BR-02` / §3.4 状态机 |
| F-4 | 详情/编辑里的**风险编号为纯文本**，不可编辑 | `BR-04` |
| F-5 | 风险类别 / 可能性 / 后果 / 处置结论均为**下拉字典**，选项与后端校验值完全一致 | `BR-05` |
| F-6 | 终态（已关闭 / 已接受）行**不再显示任何动作按钮**（只剩「详情」）—— 用 `x-if` 把按钮移出 DOM | `BR-06` |
| F-7 | 「受影响需求」下拉由**跨应用** `requirement.list` 填充（可留空）；失败静默兜底为空列表 | `BR-07` |

## 7. 已知限制

- **责任人为「文本输入 + 候选建议」**（2026-09-25 改）：`owner` 挂 `datalist`，候选来自跨应用
  `stakeholder.list`；**值仍是文本姓名、不落 `sh_no`**（与 `requirement` 同口径）。用例 `VT-SUG-55..VT-SUG-57`。
- **「受影响需求」下拉不做搜索过滤**：需求数量大时应改为可搜索的 autocomplete；
  当前实现是「一次拉全量 + 原生 select」，中小规模够用。
- **关闭无二次确认弹窗**：关闭的"二次确认"由模态内的处置结论选择本身承担
  （必须显式选一个结论 + 可选填说明），比 `confirm()` 更能留下决策信息。
- **列表不展示风险情景 / 缓解措施**：长文本不进列表列，在详情模态里看（列表列是详情字段集的子集）。

## 附：状态/枚举下拉的「回填静默失败」缺陷（2026-09-25 已修）

**现象**：Alpine 的 `x-model` + `x-for` 生成 `<option>` 时，**数据→DOM 的回填会静默停在第一项** ——
`x-model` 的「数据→DOM」effect 跑在 `x-for` 把选项插进 DOM **之前**，`select.value = "<真实值>"`
当时无此选项、静默失败；选项插入后 `selectedIndex` 落到 0，而该 effect 的依赖此后不再变 ⇒ **永不重跑**。

**影响不只是显示**：用户看着错的选项去改别的字段并保存，会把"他看到的那个值"当成事实。

**修法**：本页的枚举下拉**一律改用静态 `<option>`**（元素静态 → 无时序问题）；
**数值型字段用 `:value` 绑定**（`:value="1"`）以保留数字类型，别写成 `value="1"`（会字符串化）。

**同一缺陷曾存在于本组另外两个应用**（`requirement` / `risk` / `configuration_item` 各 2 处），
已于同批统一修复并复跑全部通过。规格侧对应 `design-plus/view-convention/patterns.md` §4。

## 附：终态禁编辑入口（2026-09-25 修）

**缺陷**：服务端 `risk.update` 有 `_check_mutable`（BR-06：终态「已关闭 / 已接受」不得修改），
但**前端对终态行照样显示「编辑」** —— 用户编辑已关闭的风险、点保存**必然被拒**。
属"UI 提供了后端会拒绝的动作"这一类。

**修法**：`view.js` 加 `frozen(d)`（与服务端同口径：`closed` / `accepted`），
`view.html` 的「编辑」入口加 `x-show="!frozen(d)"`。

**测试**：补 `FE-54`（终态 2 行 · 可见「编辑」0 个）与 `FE-54b`（识别态 1 行 · 可见「编辑」1 个）——
**必须是正例断言**：负例挡不住这类缺陷（原 35 项断言全绿却没碰到它）。
⚠ FE-54b 的对照**不能**用"清筛选后的首行"，列表默认序下首行可能就是终态行（实测假红一次）。
