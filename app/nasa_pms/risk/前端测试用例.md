# 前端测试用例：风险（risk）

> 产出技能：第⑧步 前端测试用例（规格 `design-plus/前端测试.md`）
> 来源：`前端详设.md`（F-1..F-8）+ `_contracts.md`（已冻结的服务契约）**同源**
> 执行：第⑨步 `python app/nasa_pms/tests/verify_view_nasa_pms_risk.py`
> 硬件指标：**0 console error · 0 pageerror · 0 HTTP≥400**

---

## §0 自足造数（前置）

| 步骤 | 动作 |
|---|---|
| S-1 | 经 REST 直调 `requirement.create` 造 2 条需求：`REQ-001`（技术需求/测试）、`REQ-002`（接口需求/检验）—— 供 §2 的跨应用下拉 |
| S-2 | 经 REST 直调 `risk.create` 造 4 条风险，覆盖 4 个状态与 4 个等级：<br>① `RSK-001` 技术风险 4×4=16 **严重** → `mitigate` → `close(transferred)` ⇒ 已关闭<br>② `RSK-002` 进度风险 **未评估** ⇒ 识别<br>③ `RSK-003` 成本风险 3×4=12 **高** → `assess` → `mitigate` ⇒ 缓解中（**有缓解措施**，供 §5 用）<br>④ `RSK-004` 安全风险 2×2=4 **低** → `assess` ⇒ 分析中 |

> 造数走 REST 而非 UI：避免用例依赖"新建功能本身是否正确"（那是 §2 的覆盖对象）。

## §1 渲染与入口

| 编号 | 用例 | 预期 |
|---|---|---|
| `VT-ROUTE-01` | 打开 `#/risk` | 页面渲染，标题「风险台账」可见；列表有 4 行 |
| `VT-ROUTE-02` | 表头 | 依次为：风险编号 / 标题 / 风险类别 / 风险值 / 风险等级 / 状态 / 责任人 / 操作 |

| `VT-ROUTE-04` | 首行内容 | `RSK-001` 行：类别「技术风险」、等级「严重」、状态「已关闭」、风险值 16 |
| `VT-ROUTE-05` | **F-6 终态行** | `RSK-001` 行**没有** 编辑 / 评估 / 关闭 按钮（`x-if` 移出 DOM） |
| `VT-ROUTE-05b` | 未评估的风险 | `RSK-002` 行状态「识别」，风险值与等级显示「—」 |

| `VT-ROUTE-05c` | 缓解中行（RSK-003）的动作入口 | **有**「关闭」——只有这一态可关闭（§3.4 状态机） |
