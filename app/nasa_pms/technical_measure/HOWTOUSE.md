# technical_measure 使用要点

**管什么**：一条**量化指标**（TPM / MOP / KPP）的目标值 / 阈值 / 实测值序列——超阈值**同事务**开告警。
查「不确定事件与缓解」用『风险』；查「选哪个方案」用『决策』（其 `measure_no` 指向这里的度量）。

## 标准工作流（按此顺序）

1. `create` — 定义：`name` + `category` + `direction` + `target_value` + `threshold_value` 五项必填，落「定义」态
2. `baseline` — **冻结判定口径**（方向 / 目标值 / 阈值）并开始度量：「定义」→「度量中」；**每个度量只能基线一次**
3. `record` — 按期记实测值：在阈内保持「度量中」；**超阈值 → 「超阈值」并在同一次调用写一条 `open` 告警**
4. `correct` — 纠正措施 → 「已纠正」，并同事务了结未了结的告警
5. `close` — 无未了结告警时关闭（硬终态，记录保留）

口径确需变更：`rebaseline` + 变更请求号（`baseline_ver` 递增 `B1 → B2`）。
核对用：`list` / `get`（主档 + 实测值 `readings` + 告警 `alerts` + 计数）/ `list_alerts`（**跨度量**告警汇总）。

## 前置条件与禁忌

- **顺序闸**：没 `baseline` 不能 `record`（报「尚未基线化（目标值与阈值未冻结）」）；「超阈值」未 `correct` **不能再 `record`、也不能 `close`**（报「还有 N 条告警未了结」）；`correct` 只认「超阈值」态；「已关闭」下记录 / 纠正 / 修改 / 重设基线 / 再关闭**全拒**。
- **判定口径只在「定义」态可改**：基线后 `update` 再传 `direction` / `target_value` / `threshold_value` 直接拒绝（指向 `rebaseline`）。⚠ **不是"基线后一律只读"**——名称 / 类别 / 单位 / 关联需求 / 责任人基线后仍可 `update`。
- **`record` 守卫顺序**：终态 → 未基线 → 超阈值未纠正 → 期次非空 → 期次本度量内唯一 → 实测值是数字。期次重复报「第「X」期已经记过实测值」——要重测请换期次标签。
- 字典：`category` ∈ `tpm` / `mop` / `kpp`（技术绩效指标 / 性能度量 / 关键性能参数）；`direction` ∈ `higher` / `lower`（越大越好 / 越小越好）；判定按方向——`higher` 时**实测值 < 阈值**即超阈值（`lower` 反之）。
- **目标值必须落在阈值的「好」这一侧**：`higher` ⇒ 目标值 ≥ 阈值；`lower` ⇒ 目标值 ≤ 阈值。
- 编号形如 `TPM-001`；一次最多一条未了结告警；改口径**不回溯**历史读数的 `passed`。
- **没有删改实测值的服务**（记错就再记一期并在备注说明）。
