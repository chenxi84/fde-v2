## 1. 页面定位

| 项 | 内容 |
|---|---|
| key / name | `technical_measure` / 技术度量 |
| 一句话 | 技术度量台账：定义、基线化、记实测值（超阈值即出告警）、纠正、重设基线、关闭，按类别/状态/方向/关联需求筛选 |
| 数据来源类型 | **独立创建** —— 因此**保留「新建度量」入口**（与服务契约 `create` 对应） |
| `PAGE_META.order` | `670` —— **组内序不在此复抄**：真值 = 各页 `PAGE_META.order`，组级 view 测试的「菜单序」断言从 `PAGE_META` + `shell.js` 的 `PLATFORM_PAGES` **现算**。本行此前逐页复抄了一遍 —— 复抄必漂：2026-09-25 因 `order` 并列、平台按 key 字母序兜底，「配置项」被渲染到「风险」之前，而复抄的清单还把旧值当成了正确值（见 pitfalls #43）。 |
| 页面构成 | 主列表卡片 + **告警汇总卡片**（跨度量查询视图）+ 四个模态（详情/编辑、记实测值、纠正、新建） |

## 3. 交互规则（逐条对应后端约束）

| # | 规则 | 依据 |
|---|---|---|
| F-1 | 新建表单里**名称 / 类别 / 方向 / 目标值 / 阈值五项必填**，未齐时提交按钮禁用（类别与方向**不给默认值**；目标值 / 阈值还要能转成数字） | `BR-04` + `BR-08` + 非空校验 |
| F-2 | **「定义」态判定口径可改**（优化方向 / 目标值 / 阈值输入可写）；**基线之后只读**并给出指向 `rebaseline` 的提示 | `BR-02`（I-2）—— **本页与同组其它页的语义差**，见 §7 第 1 条 |
| F-3 | 页脚动作**按状态显隐**：`defined`→[基线化]；`measuring`/`corrected`→[记实测值] + [关闭度量]；`exceeded`→[纠正] + [关闭度量]（禁用）；`closed`→无 | 状态机（§3.4 到达服务表） |
| F-4 | 「记实测值」是**独立模态**：期次与实测值必填、实测值须是数字；模态里给出**按当前口径会不会告警**的提示（如"实测值 < 95% 即触发告警"） | `BR-07` / `BR-08` / `BR-01`（前端镜像，后端仍是权威） |
| F-5 | **未了结告警时「关闭度量」可见但禁用**，详情给出「还有 N 条告警未了结（超阈值未纠正）」（不是只藏按钮） | `BR-06`；材料 §6.7.1.2.2 的 corrective action 口径 |
| F-6 | 「纠正」模态要求**纠正措施非空**，提交后告警了结（`0/1`）、「关闭度量」变可点 | `BR-06` + §4.3.4 |
| F-7 | 状态为「已关闭」时**行内「编辑」入口消失**、详情无「保存」、无任何页脚动作，提示「已关闭（终态）」 | `BR-06` 后半（硬终态） |
| F-8 | 两条锁定轴**互不混淆**：`specFrozen`（判定口径，基线后冻结但**可经 rebaseline 解锁**）与 `locked`（整条度量，终态**不可解锁**）分别出提示；已基线但未关闭时**不**出现终态提示 | `BR-02` vs `BR-06` —— 见 §7 第 1 条 |
| F-9 | 告警汇总按状态用 `fchip` 收敛（未了结/已了结/全部）；该卡片是**只读台账**（纵向按 `tpm_no, seq`），不提供行内动作 | `list_alerts` 是查询视图；告警的写入口只有所属度量的「纠正」（§1.3.2 的边界） |
| F-10 | 四个筛选控件变化即刷新（下拉 `@change`、输入 `@keydown.enter`；重置到第 1 页）；列表默认按编号升序 | `US-08` |
| F-11 | 详情里的**实测值序列与告警台账都直接展示**（`get` 一次带回，不做二次请求）；记实测值 / 基线化 / 纠正后若详情开着，**重取一次详情** | `get` 返回 `readings` / `alerts`；子表变了详情不刷新会前后不一致 |

## 4. 字段展示（业务名取自术语表，列名见后端）

| 列 / 字段 | 后端字段 | 展示 |
|---|---|---|
| 度量编号 | `tpm_no` | `mono` 等宽，点击开详情 |
| 名称 | `name` | 截断 220px |
| 度量类别 | `category` | **两行**：上行码（`TPM`）+ 下行中文全名（`技术绩效指标（TPM）`）—— 台账要短码，业务名要全称 |
| 优化方向 | `direction` | 箭头 + 中文（`↑ 越大越好` / `↓ 越小越好`）—— 一眼看"这个量往哪边算好" |
| 计量单位 | `unit` | `mono`；空显示 `—` |
| 目标值 | `target_value` | `mono` |
| 阈值 | `threshold_value` | `mono` —— 与"当前实测值"相邻，一眼比出超没超 |
| 当前实测值 | `current_value` | `mono`；未测过显示 `—` |
| 度量期次 | `current_period` | `mono`；未测过显示 `—` |
| 状态 | `status` | `.st` 彩色徽标（定义/度量中/超阈值/已纠正/已关闭） |
| 告警 未/总 | `alert_open` / `alert_total` | `mono` 的 `未/总`（如 `1/2`）—— 一列看出"还剩几条没处置" |
| 基线版本 | `baseline_ver` | `mono`；未基线显示 `—` |
| 关联需求 | `req_no` | `mono`（**默认隐藏列**） |
| 责任人 | `owner` | 空显示 `—` |
| 关闭说明 | `close_note` | 截断（**默认隐藏列**） |
| 所属项目 | `project_no` | 空显示 `—`（**默认隐藏列**） |
| 实测值序列 | `readings[].seq/period/measured_value/passed/note` | 只在详情模态的子表里（列表无此项）；`passed` 渲染成「在阈内 / 超阈值」徽标 |
| 告警台账 | `alerts[].seq/period/measured_value/deviation/message/status/handle_note` | 详情子表 + 汇总卡片 |

`col_default_hidden`：**"关联需求,关闭说明,所属项目"**（三列）。
本页把 `list` 返回的**全字段都渲染成列**（CONVENTION §7：数据层给全字段，列自选才有东西可选），
非关键的三列默认隐藏，经平台「列设置」按需开启。
⚠ **「计量单位」与「基线版本」刻意不藏** —— 单位决定读数怎么读（`12.5` 是 `12.5%` 还是 `12.5kg`），
基线版本是"当前生效的是哪一版口径"（`BR-02` 的可见证据）；藏了它们，台账上的数字就失去意义。

> ⚠ 「重设基线」(`rebaseline`) **本页没有入口** —— 它是一个需要写理由（变更请求号）的**口径变更动作**，

> 页面只通过提示把用户引到这里（F-8 的文案直接点名 `rebaseline`）。

## 7. 已知限制

- **⚠ 两条锁定轴是刻意的，不是冗余**（本页与同组其它页最容易照抄错的地方）：
  - `specFrozen(d)` = `d.status !== "defined"` —— **判定口径三件**（优化方向 / 目标值 / 阈值）冻结。
    它**只在「定义」态**可改，之后唯一解锁入口是 `rebaseline`（带变更请求号）。
  - `locked(d)` = `d.status === "closed"` —— **整条度量**只读，无解锁入口。
  同组 `review` / `configuration_item` 只有一个 `frozen()`（"已结论即一律冻结、无解锁入口"），
  照抄过来会同时错两处：**定义态改不了目标值**（其实可以改）与**已基线后以为能永久锁死**
  （其实 `rebaseline` 能改）。模板里所有读 `modal.d` 的地方都走
  `isStatus / inStatus / stName / stCls / specFrozen / locked / canClose / showCloseBlock /
  closeBlockText / specFrozenText / lockedText` 这层空安全 helper，**不写裸取值**
  （理由见 `前端测试用例.md` §9 的坑 1）。
- **模态里所有枚举下拉都用静态 `<option>`** —— 本页的「度量类别」「优化方向」两条都要
  **由数据回填**（`openDetail` 后写 `modal.d.category` / `modal.d.direction`）。
  用 `x-for` 生成选项时这个回填会**静默停在第一项**（Alpine 的 effect 跑在选项插入之前、
  此后不再重跑）—— 页面不报错、只是基线/编辑改错值。**筛选区的三个下拉也一并写成静态的**，
  口径统一、少一处例外。
- **告警汇总卡片是只读的** —— 告警的写入口只有**所属度量的「纠正」**（§1.3.2 的边界取舍：
  跨度量批量销告警会越过聚合边界）。所以这张卡片没有行内按钮，只有状态筛选。
- **`rebaseline` 无页面入口**（见 §6）—— 页面只提示"须经变更请求"，实际改口径走 Agent / API。
  若将来要在页面上开这个口，加一个"重设基线"模态（目标值 + 阈值 + 方向 + 变更请求号）即可，
  后端契约已经就绪，**不需要改后端**。
- **「关联需求」筛选是精确匹配** —— 后端 `list(req_no=...)` 是等值过滤（弱引用编号是短串，
  不需要模糊搜索）；输入框回车即筛，不做下拉（选项要 `requirement.list` 的跨应用数据，
  本页不发跨应用调用）。
- **「纠正」从**列表行**打开时看不到触发期次** —— 列表行不带子表（`list` 不做 N+1），
  模态里那行"触发期次"是从详情来的。从详情页脚开「纠正」才有期次；从行内开则期次留空
  （措施本身与期次无关，不影响落库）。
- **组级 `_contracts.md` 尚未冻结本应用** —— 本页的服务名 / 入参**逐字取自 `technical_measure.py`
  的公共方法签名**（`create` / `baseline` / `record` / `correct` / `rebaseline` / `close` /
  `update` / `get` / `list` / `list_alerts`）；契约冻结应由第⑤步出口的统一 dump 完成
  （本任务范围不含改 `_contracts.md`）。
- **实测值不可删改** —— 没有 `delete_reading` / `update_reading`；记错了只能换期次标签再记一期
  并在备注里说明（`应用详设.md` §6.3 同口径）。
