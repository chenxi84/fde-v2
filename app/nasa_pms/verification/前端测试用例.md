> 产出技能：第⑧步 前端测试用例（规格 `design-plus/前端测试.md`）

## §0 自足造数（前置）

| 步骤 | 动作 |
|---|---|
| S-1 | 经 REST 直调 `nasa_pms/requirement.create` 造 3 条需求（**必须用组限定名**，短名会 404「应用不存在」）：<br>① `REQ-001` 系统应支持 1000 并发用户<br>② `REQ-002` 星上存储器容量不小于 2Tb<br>③ `REQ-003` 遥测帧率不低于 1Hz |
| S-2 | `requirement.baseline([REQ-001, REQ-002, REQ-003], "B1")` ⇒ 三条**全部已基线**（矩阵的"分母"= 3） |
| S-3 | 经 REST 直调 `nasa_pms/verification.*` 造 4 条验证项，覆盖状态机的四种中间状态：<br>① `VER-001` REQ-001 / test / system_functional → `start` → `record_result(pass)` → `close` ⇒ **关闭**<br>② `VER-002` REQ-002 / analysis / box_functional → `start` ⇒ **执行中**<br>③ `VER-003` REQ-001 / inspection / end_to_end ⇒ **规划**<br>④ `VER-004` REQ-002 / demonstration / on_orbit → `start` → `record_result(fail, follow_up)` ⇒ **不通过** |

> 造数走 REST 而非 UI：避免用例依赖"规划功能本身是否正确"（那是 §2 的覆盖对象）。
> 四态齐备是刻意的 —— §4 的「动作按钮按状态显隐」（F-7）需要四种状态同屏可比。
> `REQ-003` **故意不挂验证项** —— §1 的覆盖读数（F-10 / I-1）要能看到"缺口 1"。

## §8 本轮踩到并修正的坑（记录）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | `VT-MODAL-21` 断言「验证阶段回显 `end_to_end`」失败，实际读到 **`pre_development`**；而「验证方法」看起来是对的（假象 —— 它恰好是选项里的第一项） | 枚举 select 的选项由 `<template x-for>` 生成时，Alpine 的 `x-model`「数据 → DOM」回填是**一次性 effect**，**跑在 `x-for` 把 option 插进 DOM 之前**：`select.value = "end_to_end"` 当时无此 option、静默失败；插入 option 时 `selectedIndex` 落到 0，且回填 effect 的依赖此后不再变 ⇒ **永不重跑** | 枚举 select 一律改**静态 `<option>`**（`patterns.md` §4 的写法）；断言时用 `input_value()` 读 select 的值 |
| 2 | 断言「方法/阶段」时 `inner_text()` 把 `<select>` 的全部 option 文本都吃进来 | 同上：`<select>` 的 `inner_text` 含未选中项 | 只读信息条与只读单元格加 `data-role`，断言只读它们 |
| 3 | `VT-ACT-31` / `VT-ACT-39` 按钮存在性断言假红 | 动作按钮用 `x-show` 隐藏（`display:none` 但仍在 DOM），`count()` 照样数到 | 选择器加 `:visible` |
| 4 | 「状态文本已变、动作按钮还没变」的中间态假红 | 状态单元格与行内动作按钮是两处独立绑定，重渲染不在同一拍上 | 等待条件与断言对象**同一个**（`wait_text(状态单元格, …)`），**断言用等到的那个快照**，不重新求值 |
