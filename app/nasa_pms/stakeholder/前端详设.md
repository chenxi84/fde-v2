## 1. 页面定位

| 项 | 内容 |
|---|---|
| key / name | `stakeholder` / 利益相关者 |
| 一句话 | 利益相关者台账：从外部主数据同步相关方（机构与人员），并把它的**期望逐条**维护在相关方名下（含类别 / 来源 / MOE 度量口径 / 已获承诺） |
| 数据来源类型 | **外部同步（机构与人员）** —— 因此**没有「新建」入口**，只有一个「**同步相关方**」入口（= `upsert`） |
| `PAGE_META.order` | `710` —— **组内序不在此复抄**：真值 = 各页 `PAGE_META.order`，组级 view 测试的「菜单序」断言从 `PAGE_META` + `shell.js` 的 `PLATFORM_PAGES` **现算**。本行此前逐页复抄了一遍 —— 复抄必漂：2026-09-25 因 `order` 并列、平台按 key 字母序兜底，「配置项」被渲染到「风险」之前，而复抄的清单还把旧值当成了正确值（见 pitfalls #43）。 |
| 页面构成 | 主列表卡片 + 三个模态（详情/维护、同步相关方、期望新增/编辑） |

> ⚠ **本页与同组其它九页的四处语义差**（照抄别的页会同时错，逐条见 §4）：
> ① 没有「新建」按钮（入口叫「同步相关方」）；② 没有删除；③ **没有状态徽标与状态筛选**（卡片 11 无状态机）；
> ④ 期望的「已获承诺」是**可撤回的冻结**（冻结可解锁），不是"已结论后一律只读"那种单向锁。

## 3. svc 字面量清单（授权派生依据 —— 必须字面量 `svc("应用","服务")`）

## 4. 交互规则（逐条对应后端约束）

| # | 规则 | 依据 |
|---|---|---|
| F-1 | 同步表单里**编号 / 名称 / 类型三项必填**，未齐时提交禁用；类型**不给默认值**（静态 `<option>`，首项为「请选择（必选）」） | `upsert` 的三项校验（`BR-01/02/03`） |
| F-2 | 期望表单里**陈述 / 类别 / 来源三项必填**，未齐时提交禁用 | `BR-05` |
| F-3 | 类别选「度量有效性（MOE）」时**度量口径变必填**：提交禁用 + 出现口径提示；换回其它类别提示消失、恢复可选 | `BR-06`（前端镜像，后端仍是权威） |
| F-4 | **已获承诺**的期望：陈述 / 类别 / 来源 / 度量口径四个控件 `disabled`，并给出「要改请先取消勾选」的提示；**备注恒可写** | `BR-07` 前半 + `note` 不受冻结 |
| F-5 | **冻结可解锁**：取消勾选「已获相关方承诺」，四个字段**当场变可写**、提示消失；保存时把 `committed=false` 与改动**一次发出去**（撤回 + 改写同一次调用） | `BR-07` 后半（本页语义差） |
| F-6 | 保存期望时，**已承诺则只发**「承诺 + 备注」两个字段，口径字段**根本不进载荷**（发过去必被 `BR-07` 拒）；取消勾选后 `expFrozen()` 立刻为假，四个字段随即可发 | `BR-07` 的守卫在服务端；前端不制造注定失败的请求 |
| F-7 | 「维护」入口的**编号锁定**（`disabled`）—— 编号由外部来源给定、落库不可变；从行内「维护」进来时表单已回填 | `BR-01` |
| F-8 | 期望是**聚合内子表**：任何期望写操作后，**详情模态与列表派生计数两处一起刷**（`refreshDetail` + `list.load`） | 卡片 I-1 + `expectation_total` / `committed_total` 是两个计数 |
| F-9 | **没有状态驱动的按钮组** —— 本页不写 `x-show="d.status === …"`，因为**没有状态**；页面上唯一的 0/1 标记是期望行的「已承诺 / 未承诺」徽标 | 卡片 11「状态机：无」 |
| F-10 | 三个筛选（类型 / 关键字）变化即刷新（重置到第 1 页）；关键字回车即搜；列表默认按编号升序 | `US-06` |
| F-11 | 模态里所有读 `modal.d` / `em.d` 的绑定都走空安全 helper（`expFrozenRow / expFrozen / expFrozenText / needMoe / expCount / expTitle / dash`），模板里不写裸 `em.d.kind` | 同组 `review` 页实测踩过的 `Cannot read properties of null` |
| F-12 | 三层模态（详情 ← 同步 / 期望）各自带 `data-role`，**不靠 `.modal-mask:last` 猜**；关闭顺序自栈顶向下 | 见 §9 与 `前端测试用例.md` §9 的坑 2 |

| 联系方式 | `contact` | 空显示 `—`（**默认隐藏列**） |
| 所属项目 | `project_no` | 空显示 `—`（**默认隐藏列**） |
| 期望清单 | `expectations[].seq/statement/kind/source/moe/committed/note` | 只在详情模态的子表里（列表无此项 —— 明细只在 `get`） |

`col_default_hidden`：**"职责,联系方式,所属项目"**
—— 本页把 `list` 返回的**全字段都渲染成列**（CONVENTION §7：数据层给全字段，列自选才有东西可选），
非关键的三列默认隐藏，经平台「列设置」按需开启。
⚠ **「所属机构」刻意不藏**：相关方来源是「机构与人员」，一条人员相关方靠它归口到机构，藏了就看不出"这是哪个单位的人"。

**期望子表的两处状态色**（`.st` + `.st-<色>`，**不用** `var(--ok)` / `var(--red)` —— 设计令牌里没有这两个变量）：
`committed=1` → `st-green`「已承诺」；`committed=0` → `st-slate`「未承诺」。

## 9. 已知限制

- **三层模态叠加** —— 本页最多同时开三层（详情 ← 同步 / 期望）。三个模态根都带 `data-role`，
  e2e **按 `data-role` scope**，不按 `.modal-mask:last` 猜（后者在"详情模态还开着"时
  会随 DOM 变化而错位）。这一条是被 `前端测试用例.md` §9 的坑 2 逼出来的。
- **`em.d` / `modal.d` 的空安全 helper 层**：模态里所有条件绑定都走
  `expFrozenRow / expFrozen / expFrozenText / needMoe / expCount / dash` 这层 helper，
  模板里**不写裸 `modal.d.<字段>` 做判断**。原因见 `前端测试用例.md` §9 的坑 1。
- **枚举下拉全用静态 `<option>`** —— 相关方类型在筛选 / 同步表单两处、期望类别在期望表单一处，
  都是**写死的 option 列表**（字典分别 3 项与 5 项且稳定）。刻意**不用** `x-model` + `x-for` 渲染：
  那样**回填会静默停在第一项**（同组实测踩过），而维护态与期望编辑态都必须能正确回填。
- **期望清单没有"跨相关方汇总"页签** —— 与 `review` 的「行动项汇总」（`list_actions`）刻意不同：
  卡片 11 没有「并入说明」类要求，理由见 `应用详设.md` §1.3.2。
  若将来要，先加**服务**（查询视图）再谈页面，别在页面上拼假汇总。
- **组级 `_contracts.md` 尚未冻结本应用** —— 本页的服务名 / 入参**逐字取自 `stakeholder.py` 的公共方法签名**
  （`upsert` / `add_expectation` / `update_expectation` / `get` / `list`）；
  契约冻结应由第⑤步出口的统一 dump 完成（本任务范围不含改 `_contracts.md`）。
- **不做期望的行内删除** —— 与主数据"无 delete"同口径：期望只有"加"与"改"。
  登记错了改掉即可（`update_expectation`），认为整条不该存在的正确做法是**改写成最终结论**
  而不是抹掉痕迹（`应用详设.md` §6.3）。
- **「维护」与「同步」是同一个模态**（同一服务的两个入口）—— 差别只在 `editing`
  （编号是否锁定、按钮文案「保存」/「同步」）。不拆成两个模态：**upsert 的语义就是一个**
  （存在即更新），拆开反而暗示"新增"与"修改"是两件事。
