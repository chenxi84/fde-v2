# 前端测试用例：需求（requirement）

> 产出技能：第⑧步 前端测试用例（规格 `design-plus/前端测试.md`）
> 来源：`前端详设.md`（F-1..F-7）+ `_contracts.md`（已冻结的服务契约）**同源**
> 执行：第⑨步 `python app/nasa_pms/tests/verify_view_nasa_pms_requirement.py`
> 硬件指标：**0 console error · 0 pageerror · 0 HTTP≥400**

## §0 自足造数（前置）

| 步骤 | 动作 |
|---|---|
| S-1 | 经 REST 直调 `requirement.create` 造 3 条：<br>① `REQ-001` 技术需求/测试方法/张三<br>② `REQ-002` 接口需求/检验方法<br>③ `REQ-003` 派生需求（上游 REQ-001）/分析方法 |
| S-2 | 经 REST 调 `requirement.baseline([REQ-001, REQ-002], "B1")` → 两条置基线 |

> 造数走 REST 而非 UI：避免用例依赖"新建功能本身是否正确"（那是 §2 的覆盖对象）。

## §5b 责任人候选（datalist ← `stakeholder.list`）

> 2026-09-25 补：`stakeholder` 应用建成后，**责任人**由纯文本改为「文本输入 + 候选建议」。
> **值仍是文本姓名**（不落 `sh_no`）—— 全组 11 个应用的 `owner` 口径一致，单给本页上外键会造成
> 「同一件事两种口径」；语义上的外键化（`owner_no`）会改服务签名 ⇒ 须重冻契约，本轮不做（见应用详设 §6.3）。
> 控件选 `<datalist>` 而非 `<select>`：`x-model` + `x-for` 的选项回填会**静默停在第一项**（见本文件附）。

| 编号 | 用例 | 预期 |
|---|---|---|
| `VT-SUG-51` | 新建表单：读「责任人」的 `datalist#sh-options-form` 选项 | **≥2 项**（造数 `SH-EX1/SH-EX2`）；**值=姓名**、标签含编号（`候选人甲 · SH-EX1`） |
| `VT-SUG-52` | 该控件类型 | 仍是 `input[list=…]`（**不是** `select`） |
| `VT-SUG-53` | 详情模态：同样读 `datalist#sh-options-modal` | **≥2 项**，且同样是文本输入 |
| `VT-SUG-54` | 新建表单**选类型=派生**后读 `datalist#req-options-form` | 输入框**确实渲染**（防空转）；**≥2 项**（来自本应用 `requirement.list`）；值=`REQ-xxx`、标签含标题 |
