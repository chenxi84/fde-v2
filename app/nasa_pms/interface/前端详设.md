# 前端详设：接口（interface）

> 产出技能：第⑥步 前端设计（规格 `design-plus/前端设计.md`，规范正本 `VIEW_CONVENTION.md`）
> 输入：`应用详设.md`（US/FUNC/PERM/状态机/§6.3）+ `architecture.md`（聚合根卡 9，含 I-1 / I-2）
> 后端契约**以 `interface.py` 源码为准**（组级 `_contracts.md` 尚未收录本应用 —— 见 §7 限制）

> ⚠ 本页说的「接口」是**系统/分系统之间的接口约定（ICD）**，不是代码里的 API 接口 ——
> 页面副题、字段提示都按这个口径写。

## 3. 交互规则（逐条对应后端约束）

| # | 规则 | 依据 |
|---|---|---|
| F-1 | 定义接口表单里**接口名称 / 类型 / 提供方 / 使用方四项必填**，未齐时提交禁用（类型**不给默认值**）；**两端填成同一个系统**时同样禁用并给出原因 | `BR-01`（卡片 I-1）+ `BR-02` |
| F-2 | 两端与约定内容（ICD）**只在「定义中」可写**；已定版后输入框置灰，并在编辑态给出原因「已定版（…）—— 两端与约定内容不可直接改，请用「版本变更」（BR-05）」。⚠ 保存时**只读字段不进写载荷**（`saveEdit` 按 `canEditEnds` 决定发不发这三个参数）—— 后端判的是"传没传"，把置灰的旧值一起发出去会让整次保存被拒 | `BR-05`（后端权威） |
| F-3 | 状态机动作按钮**按当前状态显隐**：定义中→[发布]；已发布→[版本变更][冻结]；变更中→[完成变更]；已冻结→无（只剩「详情」） | 状态机（§3.4 到达服务表） |
| F-4 | 「版本变更」是**独立模态**：新版本号必填且须匹配 `^[A-Z]$`、**严格大于当前版本**；**变更原因必填**；约定内容选填（本次变更的实质内容）；给出「填入下一个版本」便捷按钮 | `BR-03` / `BR-04` |
| F-5 | 详情里**版本变更通知记录直接展示**（`get` 一次带回，不做二次请求），每行带出**端**（提供方 / 使用方）与**通知对象**（端名快照） | `get` 返回 `changes`；卡片 **I-2** 的视图面 |
| F-6 | 「变更通知台账」按端用 `fchip` 收敛（提供方 / 使用方 / 全部），并给出合计「共 N 条通知」 | `list_changes` + `BR-04` |
| F-7 | 状态为「已冻结」时**行内「编辑」入口消失**、详情无「保存」、页脚无任何动作按钮，并提示「已冻结（终态）—— 不能再修改、发布或变更版本」 | `BR-07`（硬终态） |
| F-8 | 四个筛选（类型 / 状态 / 提供方 / 使用方）与后端 `list` 的可过滤参数**一一对应**；下拉变化即刷新（重置到第 1 页），两个文本框回车或失焦刷新；列表默认按编号升序 | `US-07` |
| F-9 | 「关联配置项」是**跨应用取数**的输入（`svc("configuration_item", "list", {}, {quiet:true})` 填 `datalist` 建议），取数失败**静默兜底**为空列表（纯手输仍可用） | `BR-08`（后端校验存在且未归档） |
| F-10 | 列表把 `list` 返回的**全字段都渲染成列**（CONVENTION §7），非关键三列默认隐藏；「变更通知」列显示 `change_total` | `list` 全字段契约 + `col_default_hidden` |
| F-11 | 版本列在未定版时显示「未定版」而不是空白（定义中的接口本就还没有版本）；通知记录行的版本显示为 `A → B`（首次发布显示 `定版 A`） | `version` 可空 + `old_version` 可空 |
| F-12 | 状态文案与徽标色走平台 `.st` + `.st-<色>`：定义中=slate / 已发布=blue / 变更中=amber / 已冻结=green | 设计令牌（**不写不存在的 CSS 变量**） |

## 7. 已知限制

- **关联配置项用「文本输入 + datalist」而不是 `<select>`** —— 本轮实测踩到：`<select>` 的选项由
  `x-for` 生成时，Alpine 在**选项插入之前**就完成了 `x-model` 的赋值，**回填会静默停在第一项**
  （详见 `前端测试用例.md` §9 坑 1）。改成文本输入后值就是文本、回填天然正确，
  `datalist` 仍提供建议列表。**同组 `change_request` 页规避此坑的方式是只读态用纯文本回显**
  （`data-role="scope-ci"`），本页需要可编辑回填，故取 datalist。
- **枚举下拉一律静态 `<option>`** —— 类型 / 状态两个下拉的选项写死在模板里（不用 `x-for`），
  这是同一个坑的另一半：静态选项在 DOM 创建时即存在，回填不会丢。
- **只读字段不进写载荷** —— 已定版接口的两端与约定内容在界面上是置灰的，保存时**不带**这三个参数。
  这不是"顺手优化"：后端按"传了即要改"判定（`BR-05`），把置灰的旧值一起发出去，
  整次保存会被正确拒掉 —— 表现为"改个责任人却存不下来"。本轮实测踩到并修掉，
  对应用例 `VT-MODAL-18`（这条路径**负例挡不住，必须有一条"改得下去"的正例**）。
- **模态里读 `modal.d` 一律走空安全 helper**（`isStatus / inStatus / isFrozen / canEditEnds /
  statusName / versionText / frozenText`），模板不写裸 `modal.d.status` —— 与同组 `review`
  页同一处置（`x-if="modal.d"` 的子绑定可能在 `openDetail` 把 `modal.d` 置 null 的那一拍被再求值一次）。
- **两端不可改之后没有"换端"入口** —— 已定版接口要换端只能新建一条（`BR-05` 的设计取舍，
  不是前端缺口）。
- **变更通知只落"已通知"，不落"已确认"** —— 前端没有"签收"按钮；后端要加
  `ack_change` 服务与两列 `acked_*` 才谈得上（属对外操作扩展，不是前端自造），见 `应用详设.md` §6.3。
- **组级 `_contracts.md` 尚未冻结本应用** —— 本页的服务名/入参**逐字取自 `interface.py` 的公共方法
  签名**（`create` / `update` / `release` / `revise` / `freeze` / `get` / `list` / `list_changes`）；
  契约冻结应由第⑤步出口的统一 dump 完成（本任务范围不含改 `_contracts.md`）。
