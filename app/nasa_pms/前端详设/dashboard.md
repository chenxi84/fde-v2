# 前端详设：系统工程看板（`dashboard` · 组级页 · 默认落地页）

> 产出技能：第⑥步 前端设计（规格 `design-plus/前端设计.md`，规范正本 `VIEW_CONVENTION.md`）
> 输入：`architecture.md`（四个职能域）+ `_roles.py`（四个角色）+ 各应用详设（状态机与状态中文名）
> 落点：`app/nasa_pms/dashboard.js` + `dashboard.html`（**无后端应用的组级聚合页**，key = 文件名）
> 范式参照：`app/psc/dashboard.js`（KPI 数字可点 · 主链管道 · 待办队列）

---

## 1. 页面定位

| 项 | 内容 |
|---|---|
| key / name | `dashboard` / **系统工程看板** |
| `order` | `1`（最小 ⇒ 侧栏首位、且是平台壳的**默认落地页**） |
| 一句话 | 一屏看清 KPI、**四个职能域**最近动态与**待办队列**；任何数字/条目都能点进对应台账 |
| 数据来源类型 | **无后端应用**（组级聚合页）：读数全部来自其它应用的公共读服务 |

> ⚠ **本页是模块级必备产物**（`VIEW_CONVENTION.md` §2 / `pitfalls.md` #36）：壳默认路由写死
> `route: "dashboard"`，缺本页会首帧 `x-html="tpl"` 对 undefined 求值 ⇒ **整片 console error**。

## 2. 页面结构（与 PSC 同构的三块）

```
┌ KPI 指标带（6 张，**数字本身是链接**）───────────────────────────────┐
│ 需求总数 → 需求 | 已基线需求 → 需求 | 待评审需求 → 需求               │
│ 未了结告警 → 技术度量 | 审批中变更 → 变更请求 | 缓解中风险 → 风险      │
├ 四个职能域（最近 3 条，行内编号可点 + 中文状态徽标）─────────────────┤
│ ① 需求与验证  ② 风险与度量  ③ 配置与变更  ④ 计划与评审                │
├ 待办队列（3 列，各带 total 与最近条目）──────────────────────────────┤
│ ① 需求 · 待提交评审  ② 技术度量 · 未了结告警  ③ 评审 · 行动项跟踪中     │
└────────────────────────────────────────────────────────────────────┘
```

## 3. 交互规则

| # | 规则 | 依据 |
|---|---|---|
| D-1 | **KPI 的数字本身可点**（`button.v.b-link` + `gotoPage`），点它进对应台账 | 与 PSC 一致（用户反馈"无法点击"后订正） |
| D-2 | 管道与待办里的**编号是链接**、整页只经 `gotoPage(key)` 跳转（key 字面量） | VIEW_CONVENTION：跳转目标字面量 |
| D-3 | 四个职能域与「流程总览」页**同一套分域**（需求与验证 / 风险与度量 / 配置与变更 / 计划与评审） | `_roles.py` 的四个角色 |
| D-4 | **状态一律中文 + 语义色**：字典逐字取自各应用自己的 `view.js::STATUS`；颜色在本页**本地映射**（`HUE_BY_NAME`：起始 slate / 进行中 amber / 终态-好 green / 终态-坏 red） | 平台基座 `api.js::hue()` 只认 PSC 的状态名，本组状态会回落 slate **且显示英文原文**（基座只 import 不修改） |
| D-5 | 风险行额外显示**等级**徽标（`levelCn`/`levelCls`：低/中/高/严重） | 风险列表里 `risk_level` 是英文码 |
| D-6 | 探测一律 `{quiet: true}` + 失败零值兜底；**不做裸数组兜底**（`list` 契约是 `{items,total}`，形状不对就该红） | 《测试用例.md》TC-28 |

## 4. 字段 / 读数

| 区块 | 数据来源 |
|---|---|
| 需求总数 / 已基线 / 待评审 | `requirement.list`（带 `status` 筛选，取 `total`） |
| 未了结告警 | `technical_measure.list_alerts`（`status=open`） |
| 审批中变更 | `change_request.list`（`status=reviewing`） |
| 缓解中风险 | `risk.list`（`status=mitigating`） |
| 四个职能域的 3 行 | `requirement.list` / `risk.list` / `change_request.list` / `review.list`（各取前 3） |
| 待办三列 | `requirement.list(status=draft)` / `list_alerts(status=open)` / `review.list(status=tracking)` |

## 5. 权限

- 读数走各应用的公共读服务；平台按「页→服务」隐式放行（`X-Fde-Page`）。
- **受限用户**下，未授权应用的服务返回 403 ⇒ 本页 `quiet` 探测兜底为 0（页面照常渲染，不崩）。
  实测：受限会话下 6 张 KPI 卡照常渲染（只有「需求」有数）。

## 6. 已知限制

- **不做跨应用一致性校验**：读数各取各的 `total`，不交叉核对（例如"未覆盖需求数"需要两步查询，本页留白）。
- **字典靠本页维护**：新增应用/状态时，`STATUS` 与 `HUE_BY_NAME` 都要补（`VT-DASH-01` 有一条
  「**主区文本不得出现英文状态原文**」的断言兜住漏补）。
- **域内顺序是阅读方向**，不是硬依赖（同「流程总览」页的说明）。
