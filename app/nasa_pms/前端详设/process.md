# 前端详设：流程总览（`process` · 组级页）

> 产出技能：第⑥步 前端设计（规格 `design-plus/前端设计.md`，规范正本 `VIEW_CONVENTION.md`）
> 输入：`architecture.md`（聚合关系）+ `_roles.py`（四个角色）+ `_flow_*.yaml`（三条流程）+ 各应用详设
> 落点：`app/nasa_pms/process.js` + `process.html`（**无后端应用的组级聚合页**，key = 文件名）
> 范式参照：`app/psc/process.js`（同款"数据驱动 SVG + 事件委托 + 委托右栏 Agent"机制）

---

## 1. 页面定位

| 项 | 内容 |
|---|---|
| key / name | `process` / 流程总览 |
| `order` | `5`（`dashboard`=1 之后、业务页 610+ 之前） |
| 一句话 | 一屏看清**四个职能域**的实时状态与**三条已声明流程**，并可跳台账 / 派活给 AI 管家 |
| 数据来源类型 | **无后端应用**（组级聚合页）：读数全部来自**其它应用的公共读服务**（`svc(...)` 字面量，quiet 探测 + 零值兜底） |

## 3. 交互规则

| # | 规则 | 依据 |
|---|---|---|
| P-1 | **拓扑与 PSC 不同**：四个职能域**并列**（域间不连线）；域内应用是一条**有先后依赖**的小链，用横向箭头体现 | `architecture.md` ③ + `_roles.py` 的四个角色 |
| P-2 | 节点读数**一律来自该应用自己的服务**（`list` / `list_alerts`，`quiet: true` 探测、失败零值兜底），**不硬编码** —— 演示时"点开就看到真数" | VIEW_CONVENTION 主数据选择铁律的反面：**别在页面上编数** |
| P-3 | 节点**灰/绿**的判据 = 该应用的关键闭环**有没有发生过**（如需求的「已基线 > 0」、评审的「已关闭 > 0」、技术度量的「有条目且无未了结告警」） | 各应用的状态机 |
| P-4 | 点击**域名或节点**经事件委托（`data-page`）跳对应台账 | 与 PSC 的 `VT-PROCESS-01` 同款 |
| P-5 | 「✦ Agent 分析下一步」把**图上有什么就发什么**的状态快照交给右栏 Agent（`fde:agent-open` + `fde:agent-prompt`） | 平台右栏协议 |
| P-6 | 「让 AI 管家跑」**不直连 HTTP**：平台没有"运行流程"端点，改为把「请用 `platform_run_flow` 运行流程 X」交给 Agent（它有该工具） | ⑪ 的执行面由 Agent 承担 |

## 4. 字段 / 读数（逐应用）

| 应用 | 节点摘要 | 绿（done）判据 |
|---|---|---|
| `stakeholder` | `N 条 · 期望随方维护` | 有条目 |
| `requirement` | `N 条 · 已基线 x · 待评审 y` | 已基线 > 0 |
| `verification` | `N 行 · 通过 a · 不通过 b · 已关闭 c` | 已判定 > 0 |
| `risk` | `N 条 · 已了结 k` | 已了结 > 0 |
| `technical_measure` | `N 条 · 未了结告警 a` | 有条目**且**无未了结告警 |
| `decision` | `N 条 · 已实施 k` | 已实施 > 0 |
| `configuration_item` | `N 条 · 已发布 r` | 已发布 > 0 |
| `change_request` | `N 条 · 审批中 r` | 有条目**且**无在审 |
| `interface` | `N 条 · 已冻结 f` | 已冻结 > 0 |
| `tech_plan` | `N 份 · 已批准 a · 已修订 r` | 已批准 > 0 |
| `review` | `N 场 · 跟踪中 t · 已关闭 c` | 已关闭 > 0 |

## 5. 权限

- 页面读的都是各应用的**公共读服务**（`list`），平台按「页→服务」隐式放行（`X-Fde-Page`）。
- 组级页在侧栏的可见性同样由平台页面授权决定；受限用户若未获授本页则不显示（→ 组级测试的受限菜单断言）。

## 6. 已知限制

- **只做"声明与渲染"**：三条流程的**执行**不在此页（`agent` 节点需 LLM）；「让 AI 管家跑」把执行交给 Agent，
  执行半的验证见 `pitfalls #47`（真跑一次的记录）。
- **域内顺序是"数据依赖"而非"时间顺序"**：例如变更请求与配置项是**双向**业务关系（提变更要选配置项、
  配置项发版要变更号），图上按"配置项 → 变更请求"排列只是取**主要阅读方向**，不代表后者不能反过来引用前者。
- **节点读数不做"跨应用一致性校验"**：如"未覆盖需求数"这类跨应用的量需要两步查询，本页不聚合（留白比编数好）。
