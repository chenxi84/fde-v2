## §6 元素 ↔ 活动（2026-09-26 增补）

| 编号 | 用例 | 预期 |
|---|---|---|
| `VT-REL-01` | 「活动」列 | 有活动的叶子 `123456.01.01` 显示「**1 条**」；没有活动的叶子（`123456.02` / `123456.03`）显示琥珀色「**加活动**」；**非叶子**（`123456` / `123456.01`）显示「**—**」（活动只能挂最底层，BR-05） |
| `VT-REL-02` | 点「1 条」 | 跳到进度活动台账并**带上「挂靠元素」筛选**（`123456.01.01`），台账只剩该元素下的 **1 条** |
| `VT-REL-03` | 点「加活动」 | 跳到进度活动台账、**新建模态已开且挂靠元素已预选** `123456.02` |

> **为什么要这三条**：材料（WBS 手册 §4）原话是 *"The lowest level of each WBS element should have at
> least one task or activity"* —— 这是**反方向**的判据（`activity` 侧的 `non_leaf` 管"活动挂错了地方"，
> 它管"地方还空着"）。所以台账上要看得见"这个叶子有没有活动"，并且能一步跳过去建。
>
> ⚠ 本页对 `activity` **只读**（只做跳转）：全仓的视图层跨应用调用**一律只读**，
> 第一条"页面写别组聚合"的边不从这里开（见 `architecture.md` 方向表与 `VT-REL-02/03` 的实现）。
> 跳转参数走 `sessionStorage` 而不是 hash 查询串 —— 平台的 route key 是**整段 hash**，
> `#/activity?wbs=x` 会让路由匹配不上（详见 `前端详设.md` W-12）。

## §7 版式（2026-09-26 增补）

| 编号 | 用例 | 预期 |
|---|---|---|
| `VT-LAYOUT-01` | 操作列 | 动作按钮**不换行**（窄画布下也一样 —— 「宁可横滚，不可变形」） |
| `VT-LAYOUT-02` | 默认隐藏列 | 正好是四个字典列：内容描述 / 规范号 / 预算与报告号 / 修订授权 |
| `VT-LAYOUT-03` | 1920 宽（右栏展开） | 列表**不横向溢出**（`scrollWidth ≤ clientWidth + 2`） |

> **为什么补这三条**：页面刚到手的版式是坏的 —— 15 列同时铺开时表格**最小内容宽 1380px**
> 超过卡片宽 **1238px**（1500 宽 · 右栏收起实测），浏览器只能把最后一列「操作」压到 **48px**，
> 四个按钮竖排，**行高从 39px 涨到 223px**。这是"看着才知道"的那类缺陷（同 `activity` 页
> 甘特刻度的 `VT-GANTT-75`），所以固化成判据。
>
> **修法两条**：① 四个字典 / 长文本列进 `col_default_hidden`（平台「列设置」可按需勾回，
> 信息不丢 —— 与同组 `decision` / `interface` / `review` 同口径）；② 操作列 `white-space:nowrap`
> —— 画布不够时让 `.scroll-x` **横滚**，而不是让浏览器把按钮压成竖排。
>
> ⚠ 同组 `interface` / `technical_measure` / `tech_plan` 三页在**同一画布**（1600 宽 · 右栏展开
> ⇒ 卡片 958px）下仍是这个症状（实测行高 191 / 223 / 86px），本页是目前唯一"宁可横滚"的。

## §8 WBS 甘特（2026-09-27 增补 · 同日改为 ECharts 渲染）

造数（§8 内，走 REST 不经 UI）：在 `123456.02` 上建一条**串联**活动（`predecessors = <123456.01.01 的那条>:FS:0`）
+ 一条**里程碑**（挂在同一条活动之后）—— 这样"包络"与"两支先后"都能被**量**出来，而不是只断言"有条"。

| 编号 | 用例 | 预期 |
|---|---|---|
| `VT-WGANTT-01` | 点「甘特视图」 | 图**真的建出来了**、canvas 有尺寸（`>200×>100`）；元素行数 **==** 树视图行数（同一棵树的两种呈现，不重不漏） |
| `VT-WGANTT-02` | **汇总条 = 子树包络** | 根元素 `123456` 的条**包住**两支后代的条（`from ≤ min`、`to ≥ max`）；且串联链下 01 支整条落在 02 支**之前** |
| `VT-WGANTT-03` | 单后代元素 | 汇总条与该后代区间**同起同止**（`123456.01` 的条 == `123456.01.01` 的条） |
| `VT-WGANTT-04` | 无活动的元素 | **不画条**（没有日期区间），只在图上标「无活动」——实测 `123456.03` / `654321` |
| `VT-WGANTT-05` | 活动行与里程碑 | 活动条**缩进挂在元素行下**（`depth ≥ 1`）；里程碑按**菱形**渲染（`is_ms` 行存在） |
| `VT-WGANTT-06` | 窗口变宽 | 图跟着 `resize`（606 → 926）；漏了 resize 监听就会留一张固定宽的图 |
| `VT-WGANTT-07` | 点**左侧名称** | 开该元素详情（`yAxis.triggerEvent` 那条路） |
| `VT-WGANTT-08` | 点**活动条** | 跳活动台账、带「挂靠元素」筛选（`123456.01.01`） |

> **为什么要这八条（而不是只断言"有条"）**：材料 `SP-2010-3403` §5.5 里 IMS 的甘特是**按 WBS 层级**
> 呈现的 —— 元素行的条不是元素自己的日期（`wbs_element` 根本没有日期列），而是**其子树全部活动的包络**。
> 所以要量的是**区间关系**（包住 / 同起同止 / 先后），而不是"有条没条"。
>
> ⚠ **断言面是 `getOption()`，不是 DOM**：图是 canvas 画的，DOM 里没有"条"可量（只有一个容器
> `#wbsGantt`）。行模型随 option 挂在 `series[0].data[*].row` 上（实测 `getOption()` 原样返回），
> 量的是**渲染真正吃进去的那份数据**，不是页面上另存的一份副本。
>
> ⚠ **两条"静默"缺陷是本轮真撞出来的，故都钉成了判据**：
> ① `VT-WGANTT-01` 的"canvas 有尺寸"——容器在 `x-show` 切过来的那一帧可能是 **0 宽**，
>    而 canvas 宽 0 就是**整张图什么都不画且不报错**（平台在 material360 的「逐月拟合」图上踩过）；
> ② `VT-WGANTT-07` 的"点名称开详情"——轴标签事件里的 `p.value` 是**类目名（那串富文本标签）**
>    而不是行号，首版按行号取，静默拿到 `undefined`、点上去毫无反应、控制台也不报错。
>
> ⚠ 另有一条**版式**教训换过两次面孔（正本 pitfalls #51）：那是 Alpine 的 `:style` 字符串会
> **整条替换** inline style —— 手搓 div 版被冲掉的是名称列的 `width/flex`（每行条的起点差 ~13px），
> 改 ECharts 版之后同一个坑落在**图容器**上（`width:100%` 与 `height` 必须写在同一个 `:style` 里）。
