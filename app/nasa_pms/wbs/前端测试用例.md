## §0 自足造数（前置，走 REST 不经 UI）

| 造什么 | 结果 |
|---|---|
| 两条需求 | `REQ-001`（星上存储容量）/ `REQ-002`（单圈观测时长） |
| 一个**已批准**的变更请求 | `CR-001`（配置项 → 影响分析 → 提交审批 → 批准） |
| 一棵树四个元素 | `123456` 遥感卫星系统（**已基线**）· `123456.01` 星务分系统（**已基线**、挂 `REQ-001`）· `123456.01.01` 星务计算机（草稿、**无范围出处**）· `123456.02` 载荷分系统（草稿、有范围出处、挂 `REQ-002`） |

## §2 新建顶层 / 加子元素（W-1）

| 编号 | 用例 | 预期 |
|---|---|---|
| `VT-FORM-11` | 打开新建 | 模态出现，含编号输入框 |
| `VT-FORM-12` | 顶层**缺编号** | 被拒（toast 含「顶层元素必须给出编号」，即 BR-01），**行数不变** |
| `VT-FORM-13` | 顶层编号 `654321` + 名称 | 成功，列表 5 行 |
| `VT-FORM-14` | 对 `123456` 点「加子元素」 | 模态标题点名父元素；提交后出现 **`123456.03`**（子号自动分配），列表 6 行 |
| `VT-FORM-15` | 关掉重开 | 表单已重置（不残留上次输入） |
| `VT-FORM-16` | **BR-04** 非产品词（用**子元素**表单） | 名称「工程部」被拒（toast 含「非产品词」），行数不变 |

> ⚠ `VT-FORM-16` 必须走**子元素**表单：顶层表单缺编号会先被 BR-01 拦下，轮不到 BR-04。

## §3 状态动作（W-2 / W-3 / W-4 / W-5）

| 编号 | 用例 | 预期 |
|---|---|---|
| `VT-ACT-21` | 按钮可见性 | 已基线行**看得到**「发起变更」；草稿行**看不到**「发起变更」与「关闭」，**看得到**「纳入基线」 |
| `VT-ACT-22` | 发起变更模态 | 变更号候选**只列已批准的**（`CR-001`） |
| `VT-ACT-23` | 提交变更 | 该行状态 →「变更中」；按钮变「落实变更」 |
| `VT-ACT-24` | 落实变更 | 回到「已基线」、**版次 `v1`**、修订授权列记 `CR-001` |
| `VT-ACT-25` | **BR-03** | 无范围出处的 `123456.01.01`：「纳入基线」**禁用**（前端镜像）；**绕过界面直接调服务也被拒**（后端硬闸，报错含「范围定义出处」）；状态仍草稿 |
| `VT-ACT-26` | **BR-06** | 对 `123456.01` 关闭 → 被拒，报错**点名**未关闭的子元素 |

> `VT-ACT-25` 是**双断言**：前端禁用只是提示，**判据在后端** —— 所以另用 REST 直调一次，
> 证明不是"界面上点不动而已"。
