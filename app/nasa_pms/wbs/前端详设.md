## 2. 页面结构

```
┌ 工具条：状态筛 · 类型筛 · 关键词 · [列表视图] [树视图] [甘特视图] · [新建顶层元素] ┐
├ 列表视图：16 列 —— 可见 12 列（编号 / 名称 / 类型 / 层级 / 父元素 / 状态 / 版次 / 责任方 /
│            范围定义出处 / 关联需求 / **活动** / 操作），四个字典列默认隐藏（内容描述 / 规范号 /
│            预算与报告号 / 修订授权，见下方 `col_default_hidden`）
├ 树视图：`[data-role="tree"]` 缩进索引（按 depth × 26px 缩进 —— 材料 §3.4.4 图 3-12）
├ 甘特视图：`[data-role="wbs-gantt"]` 里就一个 **ECharts 容器 `#wbsGantt`** —— 图里每行一个
│            元素（**汇总条 = 子树活动的包络**）+ 叶子下面逐条活动（缩进 +1，里程碑是菱形）
└ 四个模态：详情/编辑 · 新建（顶层或子元素）· 发起变更 · 关闭
```

## 3. 交互规则（逐条对应后端约束）

| # | 规则 | 依据 |
|---|---|---|
| W-1 | **子号不给填**：`add_child` 由系统分配（`父号.01/.02…`）；顶层才给编号输入框 | BR-01（编号规则机械可判，不该交给人） |
| W-2 | 「纳入基线」按钮**在前端预禁用**（无范围出处时）—— 前端只做提示，**判据在后端**（后端 BR-03 另有硬闸） | BR-03；本组惯例：前端镜像 ≠ 判据 |
| W-3 | 「发起变更」的变更号候选**只列已批准**（`change_request.list(status=approved)`）；值仍是文本，后端 `change` 会再校验一次 | BR-05（§3.3.6） |
| W-4 | 已基线元素**不给「编辑」入口**（给的是「发起变更」）—— 否则点进去字段全灰，是死胡同 | BR-05；同组 `decision` 页对 frozen 状态同款处理 |
| W-5 | 已关闭是终态：按钮只剩「详情」 | BR-06 |
| W-6 | 动作按钮用 `x-show` 控制（元素仍在 DOM），**e2e 断言存在性必须按可见性判** | pitfalls：`x-show` 不等于不存在 |
| W-7 | 详情模态里的字段用 `data-role` 钩住 | 整卡 `inner_text` 会被 `select` 的全部 `option` 文本污染（本组踩过） |
| W-8 | 列表**可见 11 列**，四个字典列默认隐藏；「操作」列 `white-space:nowrap` —— 画布不够时靠 `.scroll-x` **横滚**，不让浏览器把按钮压成竖排 | 版式：15 列同时铺开时表格最小内容宽 **1380px** > 卡片 **1238px**（1500 宽 · 右栏收起实测），「操作」被压到 48px → 四按钮竖排 → 行高 39px→**223px**；判据 `VT-LAYOUT-01..03` |
| W-9 | 隐藏列由平台「列设置」（`colctl`，per-user 服务端持久化）管理，**信息不丢**、按需勾回 | 平台机制；同组 `decision` / `interface` / `review` 同口径 |
| W-10 | **「活动」列**（跨应用**只读** `activity.list`，一次取全表在内存里归并）：叶子显示 `N 条`（点它 → 跳活动台账并**按本元素筛选**）；叶子且 **0 条**显示琥珀色「**加活动**」（点它 → 跳活动台账、**新建模态已开且本元素已预选**）；**非叶子显示 `—`**（活动只能挂最底层，BR-05） | 材料 WBS 手册 §4："The lowest level of each WBS element should have at least one task or activity" —— 把这条做成看得见的读数与一步可及的入口 |
| W-11 | 跳转**不写 `activity` 的聚合**：跨页参数走 `sessionStorage`（`fde.activity_preset`），写活动仍是 `activity` 页自己发起 | 全仓的视图层跨应用调用**一律只读**（`verify_app_edges.py` 对账；`architecture.md` 方向表） |
| W-12 | 跨页参数为什么不用 hash 查询串：平台的 route key 取的是**整段 hash**（`location.hash.replace(/^#\//,"")`），`#/activity?wbs=x` 会变成页名 `activity?wbs=x` 而匹配不上任何页 —— 直接白屏 | `view/lib/shell.js` 的 `syncRoute`（`view/lib/` 只 import 不修改） |
| W-13 | 三个视图各一个按钮（列表 / 树 / 甘特）；**不写一个 toggle 按钮** —— 两态时 `x-text` 换词勉强可以，三态会绕圈 | 与活动页三视图同款（`台账视图 / 排程视图 / 甘特视图`） |
| W-14 | **WBS 甘特**：元素行的条 = **其子树全部活动的包络**（`min 最早开始 → max 最早完成`），不是元素自己的日期（`wbs_element` 根本没有日期列）；叶子行下面逐条列活动（缩进 +1）；无活动的元素标「**无活动**」且**不画条** | 材料 `SP-2010-3403` §5.5：IMS 的甘特按 **WBS 层级**呈现，汇总条是"看整体"的层级、活动条是"干活"的层级 |
| W-15 | 甘特里的日期全是**派生量**：来自 `activity.schedule_view`（跨应用**只读**），本页只做归并 —— 本应用至今**不存日期**、也不开写边 | `wbs/应用详设.md` §1.3.2「不管理活动与日期（进度侧）」；视图层跨应用调用一律只读 |
| W-16 | 图由 **ECharts** 画（平台已内置 `view/lib/echarts.min.js`，经 `view_shell.html` 全局加载，psc 三页在用 ⇒ **零新增依赖**、观感统一）：`custom` series + `renderItem` 逐行画（汇总条 8px 深色 + 两端小三角 / 活动条 9px，条内深色叠**完成度**、条下 3px 灰线是**基线** / 里程碑**菱形**）；`yAxis` 类目轴承载行标签，富文本两列（定宽等宽编号 + 定宽截断名称） | 手搓 div 条那版实测两个硬伤：180px 日期列装不下「2026-09-28 → 2026-10-23（5 条）」→ 文字溢出压在条上；没有网格线 ⇒ 条悬空、读不出"到哪天" |
| W-17 | 横轴是**「天偏移」的 value 轴**（0 = 最早开始日），**不是 `type:"time"`**：时间轴那条路有三处**静默**坑 —— 轴范围一旦被无日期的行污染成 `NaN` 就把轴缩到 epoch（刻度全「1-1」、一根条都不画）；`interval` 对时间轴**被忽略**；auto 在窄画布排出 2 天步长、标签叠成「9-2910-1」且**不遵守 `hideOverlap`**。改用 value 轴后步长是整数天（按跨度分档 7/14/28/56 天）、标签由 `base + v 天` 反算（`setDate` 推进，躲开时区与夏令时） | 判据 `VT-WGANTT-01`（canvas 必须有尺寸）；刻度步长是**自主决定**的，比活动页甘特更进一步 |
| W-18 | 点击入口两个：**条** → 该行（元素开详情 / 活动跳活动台账并带「挂靠元素」筛选）；**左侧名称** → 元素详情（`yAxis.triggerEvent`）。⚠ 轴标签事件的 `p.value` 是**类目名（那串富文本标签）**、不是行号 —— 按行号取会静默拿到 `undefined`、点了毫无反应且不报错 | `VT-WGANTT-07/08` 把两条入口都钉住了 |
| W-19 | **宽/窄两套布局**（标签列宽 + 右侧 gutter 不同）由容器宽度（`< 820px`）切换；`resize` 时**跨过分界必须重画**、同档只需 `resize()`。另：`x-show` 切过来的那一帧容器可能仍是 0 宽，而 **canvas 宽 0 = 整张图什么都不画且不报错**（platform 在 material360 踩过）⇒ 建图后补一帧 `requestAnimationFrame(resize)` | `VT-WGANTT-06`（窗口变宽图跟着变）；pitfalls #51（`:style` 整条替换 —— 容器上 `width:100%` 与 `height` 必须写在同一个 `:style` 里） |

## 4. 字段展示（业务名取自术语表）

| 列 / 字段 | 业务名 | 备注 |
|---|---|---|
| `wbs_no` | 元素编号 | 等宽字体；**不可变**，界面上没有输入框（BR-07） |
| `title` | 元素名称 | 提示「必须按产品分解」 |
| `level` / `parent_no` | 层级 / 父元素 | 顶层显示「（顶层）」 |
| `kind` | 类型 | 产品 / 使能性工作 / 控制账户 / 工作包 / 规划包 |
| `scope_ref` | 范围定义出处 | 没有它不能基线（BR-03） |
| `req_nos` | 关联需求 | 交叉引用矩阵的 X（§3.3.3），覆盖对账按它求差 |
| `description` | 内容描述 | 截断 200px（**默认隐藏列**） |
| `spec_no` / `spec_title` | 规范号 | `mono`（**默认隐藏列**；规范名只在详情模态） |
| `charge_code` | 预算与报告号 | §3.4.4h（**默认隐藏列**） |
| `rev_no` / `rev_authorization` | 版次 / 修订授权 | 落实变更时 +1 并记变更号（修订授权是**默认隐藏列**，取证走详情模态） |
| `status` | 状态 | 草稿 / 已基线 / 变更中 / 已关闭（语义色） |

`col_default_hidden`：**"内容描述,规范号,预算与报告号,修订授权"** ——
本页把 `list` 返回的**全字段都渲染成列**（CONVENTION §7：数据层给全字段，列自选才有东西可选），
四个**字典 / 长文本**列默认隐藏，经平台「列设置」按需开启（与同组 `decision` / `interface` / `review`
同口径）。**为什么非藏不可**：15 列同时铺开时表格最小内容宽 1380px 超过卡片 1238px，
浏览器只能把最后一列压成 48px，四个按钮竖排、行高涨到 223px（详见 W-8 与 §7）。

| 依赖 | 用途 | 在哪一层 | 失败时 |
|---|---|---|---|
| `stakeholder.list` | 「责任方」候选（**值仍是文本姓名**） | **视图层** `svc(...)` | 静默兜底为空列表（不喷 toast） |

## 7. 已知限制

- **不画图形化的元素树**（材料 §3.4.3 的 tree diagram）：本页给的是**缩进索引**（§3.4.4 的 WBS Index），
  图形化树留白 —— 意义有限而维护成本高
- **不做拖拽调整层级**：改层级 = 改编号 = 换一个元素（BR-07），没有"拖一下"这种入口
- **覆盖对账不在本页展示**：`coverage` 是服务级能力，页面留白（避免与看板的读数重复）
- **甘特只画"最早排程" + 基线条，不画实绩**：条的区间取 `early_start/early_finish`（正推的最早日期），
  活动行**额外叠一条灰色基线条**（`baseline_start/finish`，有基线才画）；**实绩条不画** ——
  `actual_*` 属于进度绩效，活动页台账已有列。这里只回答"哪个元素/活动在什么时候、占多长、跟基线差多少"。
- **甘特不做缩放**：横轴步长按跨度分档定死（7/14/28/56 天）。加 `dataZoom` 会让刻度落到**非整数天**，
  而标签格式器只给整数天出字 ⇒ 一缩放刻度就整片消失。长周期项目由分档兜住。
- **甘特不选日历**：跟随**默认日历**（活动页有 `cal_no` 选择器）；本页的甘特是"层级视图"，
  口径与项目级日历一致才可比 —— 要换口径去活动页换（口径挂在日历上、全表共用一个，见应用详设 §1.3.2）。
- **甘特不按工具条的筛选过滤**：画的是**整棵树**（与树视图同款）。列表筛选只作用于列表视图。
- **画布 ≤ ~1100px 时列表横向滚动**：隐藏四列后表格最小内容宽 1103px（含「操作」列不可换行的
  205px）。1920 宽（右栏展开）正好铺满，1600 宽 + 右栏展开（卡片 958px）会横滚 145px。
  这是**有意的取舍** —— 宁可横滚，也不让浏览器把「操作」列压成竖排（行高 39px → 223px）。
  想在本档画布下也不横滚，就把「层级 / 版次 / 关联需求」也放进 `col_default_hidden`（少三列）。
