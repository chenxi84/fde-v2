# 应用详设：通用件汇总修正表（common_part_aggregation）

> **应用名**：`common_part_aggregation` | **类名**：`CommonPartAggregation`
> **对应聚合根卡**：architecture.md #7 | **对应 BRD**：§2.6 D07

---

## 1. 需求概览

- **需求名称**: 通用件汇总去重修正
- **优先级**: P1（对抗公地悲剧，总部对总量负责）
- **涉及角色**: 总部计划（修正人·总量负责）、一线销售（证据提供）

### 1.2 需求背景
多销售各自加码、汇总必然虚高——逐客户核对（D04）看不见总量。仅通用件经过，需总量层修正：汇总→取锚→判别虚高→差异化折减→登记三件套。

---

## 2. 用户故事

#### `US-01` 汇总去重修正（优先级：P1）
- **故事描述**: 作为总部计划，我想要汇总各客户 D04 核定值并与历史锚对比，差异化折减口头加码部分，以便于产出合理的通用件总量
- **验收场景**：
  1. `US-01-AC1` **正常汇总**: Given STD-M6三家客户核定值32000/28000/25000，When 汇总取锚对比，Then 汇总85000>锚78500约7.5%，触发修正
  2. `US-01-AC2` **差异化折减**: Given 李四有函件加码1200保留，三家口头加码4700按系数折减3000，Then 修正总量82000
  3. `US-01-AC3` **承诺量保护**: Given 某客户有函件承诺量，Then 该部分不参与折减

---

## 3.2 业务规则

| 编号 | 规则 |
|-----|------|
| BR-01 | 仅通用件进入（按 D01/D02 标记自动分流），专用件跳过 |
| BR-02 | 折减必有依据：无锚、无证据清单不得拍脑袋折减 |
| BR-03 | 承诺量保护：函件/承诺部分不参与折减（下限约束） |
| BR-04 | 总量层修正不回退个体：各份额已过 D04 核对，此处只调总量 |
| BR-05 | 差异化折减：有证据加码保留、无证据按历史系数折减 |

### 3.4 状态机

```
待汇总 --去重修正--> 已修正 --确认--> 已确认（转D08）
```
