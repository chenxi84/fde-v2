# common_part_aggregation 前端测试用例

> 逐应用 · 第⑧步产出 | 对应前端详设 PAGE_META.key = common_part_aggregation

## TC-CA-01 本页渲染
- 页面: `/view/sales-forecast/#common_part_aggregation`
- 操作: admin 登录后访问
- 断言:
  1. 列表区 `.card .tbl` 存在（即使无数据也会有空提示行）
  2. **新建按钮存在**: `.tagline` 内可见 `新建` 按钮或 `b-pri` 含"新建"文本
  3. 搜索栏含状态 chips（待汇总/已修正/已确认）和搜索输入框
  4. 非看板页 `.kpi` 数量 == 0（防粘滞——确保不是 dashboard 残留）

## TC-CA-02 新建通用件汇总 —— 落库回显
- 前置: 列表已渲染
- 造数: 浏览器内 fetch POST `/api/apps/sales-forecast/common_part_aggregation/call/create`，传入 part_no=PART-001, period=2026-08
- 操作: 点击 `新建` → 填入必填字段 → 点击提交
- 断言:
  1. toast 提示创建成功 + agg_no
  2. 列表自动刷新，新记录出现在第一条
  3. 列表中显示 agg_no, part_no, period, sum_qty, dedup_qty, dedup_pct, status

## TC-CA-03 详情模态全字段
- 前置: 列表有数据
- 操作: 点击某汇总单的编号 `.b-link`
- 断言:
  1. 模态 `.modal-mask` 出现
  2. 等待 `.loadbox` 消失
  3. 单头 KV 含: agg_no, part_no, period, sum_qty, dedup_qty, dedup_pct, status
  4. 客户明细 table 存在（含表头：客户编码/客户名称/原始需求/去重后需求/备注）

## TC-CA-04 汇总修正
- 前置: 打开一个 status=待汇总 的汇总单详情
- 操作: 在客户明细表中修改某客户的去重后需求 → 点击 "修正" 或 "保存"
- 断言:
  1. toast 提示 "修正成功"
  2. sum_qty / dedup_qty / dedup_pct 数值更新
  3. 状态更新为 "已修正"

## TC-CA-05 汇总确认
- 前置: 打开一个 status=已修正 的汇总单详情
- 操作: 点击 "确认" 按钮 → 确认弹窗中确认
- 断言:
  1. confirm 弹窗出现
  2. 确认后 toast 提示 "汇总已确认"
  3. 状态更新为 "已确认"

## TC-CA-06 状态筛选
- 前置: 列表已渲染
- 操作: 依次点击状态 chips（待汇总 / 已修正 / 已确认）
- 断言:
  1. 点击后 chip 高亮
  2. 列表仅刷新为对应状态的记录
  3. 再次点击已选中 chip 取消筛选
