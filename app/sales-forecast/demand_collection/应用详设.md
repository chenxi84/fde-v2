# 应用详设：主机厂原始需求收集表（demand_collection）

> **应用名**：`demand_collection` | **类名**：`DemandCollection`
> **对应聚合根卡**：architecture.md #3
> **对应 BRD**：§2.1 D03 + §2.2 信号拆解

---

## 1. 需求概览

### 1.1 基本信息
- **需求名称**: 主机厂原始需求收集与信号拆解
- **所属模块**: sales-forecast / 毛需求管理
- **优先级**: P0（加工链入口，无此应用则下游全部无数据输入）

### 1.2 需求背景
OEM 滚动预测是毛需求加工的源头数据。原始要货计划是混杂信号——含真实消耗驱动、MRP 计算噪声、库存水位调整脉冲。直接进基线/趋势外推必然出错（尖峰被外推→虚高；脉冲混入趋势→超储或漏要货）。需要：①版本化收集 OEM 预测；②信号拆解（滤噪声、剥脉冲、留真实消耗）。

### 1.3 需求范围
**包含**：收集单管理（新建/录入明细/提交）、版本快照机制、信号拆解（噪声滤波+脉冲识别剥离+外生变量校验）、拆解快照随版本冻结、版本比对视图
**不包含**：基线预测、销售修正、核对（归 D04）；周度发货指示（属履约层调拨单）

### 1.4 涉及角色
- **一线销售**：录入 OEM 预测明细，提交收集；提供客户侧信息辅助拆解判断
- **总部计划**：执行信号拆解（算法预计算+人工确认），确认并冻结版本
- **系统**：拆解预计算（噪声/脉冲建议）、版本比对自动生成

## 2. 用户故事

### 2.1 核心用户故事

#### 2.1.1 `US-01` 新建收集单并录入明细（优先级：P1）
- **故事描述**: 作为一线销售，我想要新建收集单并逐零件录入 OEM 滚动预测各期原始量，以便于版本化记录 OEM 需求信息
- **前置条件**: 客户/零件/项目/车型在对应主数据中存在
- **后置条件**: 收集单状态为"草稿"，明细已录入
- **验收场景**：
  1. `US-01-AC1` **正常录入**: Given 销售已登录且有负责的零件，When 新建收集单（客户A、V2026-08）并录入 3 个零件各 4 期原始量后保存，Then 收集单创建成功，明细完整
  2. `US-01-AC2` **重复版本拒绝**: Given 已存在客户A+一工厂+V2026-08的收集单，When 再次新建相同客户+工厂+版本的收集单，Then 系统拒绝并提示"该客户工厂版本已存在收集单"
  3. `US-01-AC3` **OEM未提供标记**: Given 某零件 M+2~M+3 期间未提供数据，When 录入时标记"OEM未提供"，Then 系统接受，不强制补0

#### 2.1.2 `US-02` 信号拆解执行（优先级：P1）
- **故事描述**: 作为总部计划，我想要对收集版本执行信号拆解（噪声滤波+脉冲识别+外生校验），以便于产出真实消耗量供基线使用
- **前置条件**: 收集单存在且状态为"草稿"，明细已完整
- **后置条件**: 拆解快照生成，true_qty = orig_qty − pulse_qty − noise_adj
- **验收场景**：
  1. `US-02-AC1` **正常拆解**: Given 收集单 V2026-08 有完整的明细+上一版本 V2026-07 存在，When 执行拆解（系统预计算+计划确认），Then 拆解快照生成，恒等式成立
  2. `US-02-AC2` **首版无基线**: Given 收集单为首个版本（无上一版本），When 执行拆解，Then 阶跃检测不可用，标"首版，无对比基线"，仅靠水位倒推+外生校验
  3. `US-02-AC3` **脉冲识别生成事件**: Given 拆解识别出水位脉冲 +180，When 计划确认脉冲，Then 自动调 independent_event.create 生成事件并回写 event_no

#### 2.1.3 `US-03` 拆解确认与版本冻结（优先级：P1）
- **故事描述**: 作为总部计划，我想要确认拆解结果并冻结版本，以便于下游 D04 可安全引用 true_qty
- **前置条件**: 拆解快照已生成，恒等式校验通过
- **后置条件**: 状态→已拆解，全版冻结
- **验收场景**：
  1. `US-03-AC1` **确认冻结**: Given 拆解完成且恒等式成立，When 点击"拆解确认"，Then 状态→已拆解，所有明细+快照不可编辑
  2. `US-03-AC2` **守恒校验失败**: Given 拆解窗口内 Σnoise_adj ≠ 0，When 点击确认，Then 系统拒绝并提示"噪声调整跨期总额不守恒，拆解不通过"

## 3. 业务场景

### 3.1 业务流程描述

#### 场景1：收集→拆解→基线供给
1. 一线销售收到 OEM 滚动预测 → 新建收集单（选定客户/工厂/版本/锚定期间）
2. 逐零件录入 M0~M+N 各期原始量（"OEM未提供"期间显式标记）
3. 提交收集单
4. 系统触发拆解预计算：Step 0 前置检查 → Step 1 噪声滤波 → Step 2 脉冲识别
5. 总部计划审核拆解建议：逐条确认脉冲、调整噪声、填写依据
6. 系统强制恒等式校验 → 确认冻结（状态→已拆解）
7. D04 取 true_qty 做基线输入；脉冲生成 D06 事件

### 3.2 业务规则

#### 3.2.1 `BR-01` 快照不可变
- **规则描述**: 明细原始量录入后永不修改；任何改动必须产生新版本
- **适用场景**: 任何对已录入明细的修改
- **示例**: V2026-08 录入后发现有误 → 新建 V2026-08.1 子版本

#### 3.2.2 `BR-02` 拆解恒等式强制
- **规则描述**: true_qty = orig_qty − pulse_qty − noise_adj，系统强制校验，不可绕过
- **适用场景**: 拆解确认时
- **示例**: 原始量 1150，脉冲 180，噪声 0 → 真实消耗 = 970

#### 3.2.3 `BR-03` 噪声总额守恒
- **规则描述**: 拆解窗口内 Σnoise_adj = 0（平滑只改形状、不改总量）
- **适用场景**: 拆解确认时

#### 3.2.4 `BR-04` OEM未提供不拆解不补0
- **规则描述**: 标记"OEM未提供"的期间不执行拆解、不自动补0，原样保留

#### 3.2.5 `BR-05` 非寄售件免拆解
- **规则描述**: 非寄售模式零件的收集明细免拆解（true_qty = orig_qty）

#### 3.2.6 `BR-06` 版本唯一性
- **规则描述**: 同一客户+工厂+预测版本唯一，不可重复创建

#### 3.2.7 `BR-07` 脉冲确认后生成事件
- **规则描述**: 拆解确认的脉冲自动生成 D06 事件，event_no 回写拆解快照

### 3.3 业务数据
1. **原始需求量(orig_qty)**: OEM 报数量，录入后永不修改
2. **真实消耗量(true_qty)**: 基线唯一取数口径 = orig_qty − pulse_qty − noise_adj
3. **噪声调整量(noise_adj)**: 批量尖峰抹平调整量，带符号，跨期总额守恒
4. **水位脉冲量(pulse_qty)**: 一次性阶跃量，带符号（上调+/下调−），总额不守恒
5. **预测版本(fcst_version)**: V+YYYYMM(.x) 格式，快照载体

### 3.4 状态机

```
草稿 ──拆解确认──→ 已拆解 ──D09 R版发布(联动锁定)──→ 已锁定
  │                 │
  └─作废(须填原因)   └─新版本替代──→ 已替代
```

| 当前状态 | 目标状态 | 触发动作 | 前置条件 |
|---------|---------|---------|---------|
| 草稿 | 已拆解 | 拆解确认 | 拆解快照完整 + 恒等式校验通过 |
| 草稿 | (作废) | 作废 | 须填原因 |
| 已拆解 | 已锁定 | D09 发布联动 | D09 R版已发布 |
| 已拆解 | 已替代 | 新版本确认 | 新版本已拆解 |

### 4.2 功能详细说明

#### FUNC-01 新建收集单
**功能描述**: 一线销售新建收集单，选定客户/工厂/预测版本/锚定期间等单头信息

**输入数据**:
- oem_code: 客户编码（必填）
- plant_code: OEM工厂（必填）
- fcst_version: 预测版本 V+YYYYMM(.x)（必填）
- base_period: 锚定期间 YYYY-MM（必填）
- demand_type: 需求口径（必填，默认"月度滚动预测"）
- source_channel: 来源渠道（必填）
- recv_date: 接收日期（默认当天）

**业务规则**:
- 客户+工厂+版本唯一（BR-06）
- 上一版本系统自动带出

#### FUNC-02 录入明细
**功能描述**: 逐零件×期间录入原始需求量（纵表存储），支持批量录入

**输入数据**（每条明细）:
- part_no: 零件号（必填，须存在于 md_part）
- project_no: 项目号（必填，须存在于 project_info）
- veh_model: 客户车型（必填，须存在于 vehicle_part_mapping）
- period: 期间 YYYY-MM（必填，由 M0~M+N 按锚定期间折算）
- orig_qty: 原始需求量（必填，录入后永不修改）
- uom: 计量单位（必填，默认"件"）
- data_flag: 数据标记（必填，正常/OEM未提供）

**业务规则**:
- 零件须为进行中项目（非进行中录入触发警告）
- "OEM未提供"期间显式标记，不补0（BR-04）
- 通用件按客户分别收集，不汇总

#### FUNC-03 执行拆解
**功能描述**: 系统对收集版本执行信号拆解预计算，总部计划审核确认

**拆解步骤**:
1. Step 0 前置检查：有无上一版本、有无寄售仓数据、是否寄售件
2. Step 1 噪声滤波：识别批量尖峰，移动平均/指数平滑抹平
3. Step 2 脉冲识别：跨版本阶跃检测 + 水位倒推 + 外生变量交叉验证
4. Step 3 外生趋势校验：偏离>θ_exo 转人工，不自动改数
5. Step 4 对账与落库：恒等式强制校验

**输出**: 拆解快照（D03-S），逐行含 noise_adj / pulse_qty / true_qty / method / basis

**业务规则**:
- 恒等式强制（BR-02）
- 噪声守恒（BR-03）
- 非寄售件免拆解（BR-05）
- 脉冲确认后生成 D06 事件（BR-07）

## 6. 验收标准

### 6.1 功能验收标准

#### 6.1.1 收集单全生命周期
- **关联用户故事**: US-01
- **关联业务规则**: BR-01, BR-06
- **验证方式**: 新建→录入明细→提交→拆解→确认→（发布后）锁定
- **测试数据**: 客户A·一工厂·V2026-08，3个零件各4期
- **预期结果**: 全流程通过，状态正确流转，快照不可变

#### 6.1.2 拆解恒等式
- **关联用户故事**: US-02, US-03
- **关联业务规则**: BR-02, BR-03
- **验证方式**: 执行拆解后逐行校验 true_qty = orig_qty − pulse_qty − noise_adj
- **预期结果**: 全部行通过，Σnoise_adj≈0

#### 6.1.3 脉冲生成事件
- **关联用户故事**: US-02
- **关联业务规则**: BR-07
- **验证方式**: 确认脉冲后检查 independent_event 中是否生成对应事件
- **预期结果**: 事件已生成，event_no 回写 D03-S
