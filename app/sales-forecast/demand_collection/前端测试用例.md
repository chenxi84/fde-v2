# demand_collection 前端测试用例

> 逐应用 · 第⑧步产出 | 对应前端详设 PAGE_META.key = demand_collection

## TC-DC-01 本页渲染
- 页面: `/view/sales-forecast/#demand_collection`
- 操作: admin 登录后访问
- 断言:
  1. 列表区 `.card .tbl` 存在（即使无数据也会有空提示行）
  2. **新建按钮存在**: `.tagline` 内可见 `＋ 新建收集单` 按钮或 `b-pri` 含"新建"文本
  3. 搜索栏含状态 chips（草稿/已拆解/已锁定/已替代）和搜索输入框
  4. 非看板页 `.kpi` 数量 == 0（防粘滞——确保不是 dashboard 残留）

## TC-DC-02 新建收集单 —— 表单展开
- 前置: 列表已渲染
- 操作: 点击 `＋ 新建收集单` 按钮
- 断言:
  1. 折叠表单 `.collapse.open` 出现
  2. 必填字段可见: 客户编码 input、工厂编码 input、预测版本 input、基准期间 input
  3. "更多字段 ▾" 可展开，内含 需求口径 select + 来源渠道 select + 接收日期 + 备注
  4. 底部有 "创建收集单" 提交按钮

## TC-DC-03 新建收集单 —— 落库回显
- 前置: 表单已展开
- 造数: 浏览器内 fetch POST `/api/apps/sales-forecast/demand_collection/call/create` → 或通过页面表单填入 oem_code=OEM-A, plant_code=PLANT-A1, fcst_version=V2026-08-TEST, base_period=2026-08
- 操作: 填写必填字段后点击「创建收集单」
- 断言:
  1. toast 提示创建成功 + collect_no
  2. 列表自动刷新，新记录出现在第一条
  3. 新记录 status = "草稿"

## TC-DC-04 详情模态全字段
- 前置: 列表有数据
- 操作: 点击某收集单的单号 `.b-link`
- 断言:
  1. 模态 `.modal-mask` 出现
  2. 等待 `.loadbox` 消失
  3. 单头 KV 含: collect_no, oem_code, plant_code, fcst_version, base_period, status, collector
  4. 明细 table 存在（含表头：行号/零件号/项目号/车型/期间/原始量）
  5. 拆解快照 table 存在（含表头：噪声调整/脉冲量/真实量/方法/依据）
  6. 原始数据 `<details.raw>` 可展开

## TC-DC-05 草稿状态操作 —— 确认拆解
- 前置: 打开一个 status=草稿 的收集单详情
- 操作: 点击 "确认拆解" 按钮
- 断言:
  1. confirm 弹窗出现
  2. 确认后 toast 提示 "拆解已确认"
  3. 模态内状态更新为 "已拆解"

## TC-DC-06 草稿状态操作 —— 作废
- 前置: 打开一个 status=草稿 的收集单详情
- 操作: 点击 "作废" 按钮 → 弹窗中输入原因 → 确认
- 断言:
  1. 未填原因时 toast 警告 "请填写作废原因"
  2. 填原因后提交，toast 提示 "已作废"
  3. 状态变为 "已作废"
