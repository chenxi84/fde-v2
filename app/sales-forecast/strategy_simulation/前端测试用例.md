# strategy_simulation 前端测试用例

> 逐应用 · 第⑧步产出 | 对应前端详设 PAGE_META.key = strategy_simulation

## TC-SS-01 本页渲染
- 页面: `/view/sales-forecast/#strategy_simulation`
- 操作: admin 登录后访问
- 断言:
  1. 列表区 `.card .tbl` 存在（即使无数据也会有空提示行）
  2. **新建按钮存在**: `.tagline` 内可见 `新建` 按钮或 `b-pri` 含"新建"文本
  3. 搜索栏含状态 chips 和需求形态 demand_shape chips
  4. 非看板页 `.kpi` 数量 == 0（防粘滞——确保不是 dashboard 残留）

## TC-SS-02 新建策略拟合 —— 落库回显
- 前置: 列表已渲染
- 造数: 浏览器内 fetch POST `/api/apps/sales-forecast/strategy_simulation/call/create`，传入 part_no=PART-001, veh_model=Model-X, demand_shape=平稳型
- 操作: 点击 `新建` → 填入必填字段 → 点击提交
- 断言:
  1. toast 提示创建成功 + fit_no
  2. 列表自动刷新，新记录出现在第一条
  3. 列表中显示 fit_no, part_no, veh_model, demand_shape, status, fit_date

## TC-SS-03 详情模态全字段
- 前置: 列表有数据
- 操作: 点击某拟合单的编号 `.b-link`
- 断言:
  1. 模态 `.modal-mask` 出现
  2. 等待 `.loadbox` 消失
  3. 单头 KV 含: fit_no, part_no, veh_model, demand_shape, status, fit_date
  4. 候选策略 table 存在（含表头：策略名称/MAE/MAPE/RMSE/拟合得分/选择状态）
  5. 回测指标可视化展示（若有图表或仪表盘元素）

## TC-SS-04 需求形态筛选
- 前置: 列表已渲染
- 操作: 依次点击需求形态 chips（平稳型 / 趋势型 / 季节型 / 波动型 等）
- 断言:
  1. 点击后 chip 高亮
  2. 列表仅刷新为对应形态的记录
  3. 再次点击已选中 chip 取消筛选

## TC-SS-05 策略选择
- 前置: 打开一个策略拟合详情
- 操作: 在候选策略 table 中选择一条策略（勾选或点击"选用"）
- 断言:
  1. 策略行高亮或标记为 "已选用"
  2. toast 提示 "策略已选用"
  3. 状态更新

## TC-SS-06 状态筛选
- 前置: 列表已渲染
- 操作: 依次点击状态 chips
- 断言:
  1. 点击后 chip 高亮
  2. 列表仅刷新为对应状态的记录
  3. 组合筛选（status + demand_shape）同时生效
