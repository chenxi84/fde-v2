# 应用详设：毛需求加工表（demand_processing）

> **应用名**：`demand_processing` | **类名**：`DemandProcessing`
> **对应聚合根卡**：architecture.md #4
> **对应 BRD**：§2.3 D04（步骤2基线 + 步骤3修正 + 步骤4核对）

---

## 1. 需求概览

### 1.1 基本信息
- **需求名称**: 毛需求加工（基线→修正→核对）
- **所属模块**: sales-forecast / 毛需求管理
- **优先级**: P0（核心加工总账，无此应用则毛需求无法核定）

### 1.2 需求背景
D03 产出真实消耗后，需经三步加工才能形成核定毛需求：①统计基线（客观锚，独立于销售偏置）；②销售修正（注入客户侧信息）；③修正核对（多因素校准+质询）。加工过程承载调整登记三件套（原因类别+数据依据+责任人），支撑 FVA 追溯。

### 1.3 需求范围
**包含**：加工批次管理、双路径基线生成与确认、销售修正提交（三件套强制）、修正核对（七视角校准+退回返工循环）、核定毛需求输出、调整登记日志
**不包含**：通用件汇总去重（归 D07）、牛鞭修正（归 D08）、发布（归 D09）

### 1.4 涉及角色
- **总部计划**：确认基线、执行核对、校准调整（三件套双向约束）
- **一线销售**：提交修正（三件套）、应答质询、补充证据重报
- **系统**：基线预计算、偏差校验、三件套强制、幅度预警、轮次跟踪

## 2. 用户故事

### 2.1 核心用户故事

#### 2.1.1 `US-01` 基线生成与确认（优先级：P1）
- **故事描述**: 作为总部计划，我想要系统自动生成双路径基线（时序外推+因果推演）并交叉验证，以便于获得独立于销售偏置的客观锚
- **前置条件**: D03 拆解已完成（true_qty 可用）；历史充足时 D10 策略已选定
- **后置条件**: 基线明细生成，偏差超阈的有原因记录
- **验收场景**：
  1. `US-01-AC1` **历史充足-时序外推**: Given 零件有≥12月清洗历史+D10策略已选定，When 生成基线，Then 路径A为主基线、路径B交叉验证，偏差≤θ_baseline直接采用
  2. `US-01-AC2` **历史不足-借用**: Given 零件历史<12月且无D10策略，When 生成基线，Then 系统提示历史不足，计划走 D05 借用基线登记
  3. `US-01-AC3` **偏差超阈**: Given 路径A与路径B偏差>15%，When 生成基线，Then 标记超阈+计划人工裁决并记录原因

#### 2.1.2 `US-02` 销售修正提交（优先级：P1）
- **故事描述**: 作为一线销售，我想要在基线之上提交修正值并登记三件套，以便于注入客户侧情报
- **前置条件**: 基线已确认，销售负责该零件
- **后置条件**: 修正值+三件套记录到 D04-A，状态→待核对
- **验收场景**：
  1. `US-02-AC1` **正常修正**: Given 基线960，When 销售提交修正值990（+30）+原因"促销备货（附邮件）"，Then 提交成功，幅度率3.1%
  2. `US-02-AC2` **超阈强制举证**: Given 修正幅度率25%>θ_rev(20%)，When 销售仅填"口头"未附证据，Then 系统拒绝提交，提示"幅度率超20%，必须附数据依据"
  3. `US-02-AC3` **基线直通**: Given 销售认为基线准确无需修正，When 不提交该行修正，Then 该行自动按基线处理（修正幅度=0）

#### 2.1.3 `US-03` 修正核对（优先级：P1）
- **故事描述**: 作为总部计划，我想要沿七视角校准逐一核对销售修正值，以便于制衡放大偏置、产出核定毛需求
- **前置条件**: 销售已提交修正
- **后置条件**: 核对结论（通过→核定毛需求 / 退回→返步骤3）
- **验收场景**：
  1. `US-03-AC1` **核对通过**: Given 修正+30有邮件证据且信任视角达成率97.5%，When 核对通过，Then approved_qty=990
  2. `US-03-AC2` **退回返工**: Given 修正+240与D06脉冲事件EVT-003(+180)重复且无函件证据，When 核对退回（理由："与事件重复，证据不足"），Then 状态→已退回·待重报
  3. `US-03-AC3` **2轮升级**: Given 同零件×期间经2轮退回仍无共识，When 第3次核对，Then 系统提示"已达升级阈值，建议升级产销平衡会"

#### 2.1.4 `US-04` 调整登记（优先级：P2）
- **故事描述**: 作为系统，任何数值调整自动记录三件套到 D04-L，以便于 FVA 追溯与追责
- **验收场景**：
  1. `US-04-AC1` **销售修正记录**: Given 销售提交修正从960→1200，When 提交成功，Then D04-L 自动生成记录（角色=销售，前后值，原因，证据）
  2. `US-04-AC2` **核对校准记录**: Given 核对人直接调数，When 保存校准，Then D04-L 记录（角色=核对人，三件套同样强制）

## 3. 业务场景

### 3.2 业务规则

#### 3.2.1 `BR-01` 基线双路径交叉验证
- **规则描述**: 历史充足→路径A时序外推为主基线，路径B因果推演为验证；偏差=|A−B|/A，>θ_baseline(15%)须人工裁决
- **示例**: 路径A=960，路径B=990，偏差3.1%→直接采用A

#### 3.2.2 `BR-02` 三件套强制登记
- **规则描述**: 任何数值调整（销售修正或核对人校准）必须登记"原因类别+数据依据+责任人"到 D04-L；无三件套不得提交

#### 3.2.3 `BR-03` 过度修正强制举证
- **规则描述**: |修正幅度率| > θ_rev(20%) 视为过度修正，数据依据强制非空且须举证（客户函件/邮件记录/数据截图）

#### 3.2.4 `BR-04` 退回返工循环
- **规则描述**: 退回须书面理由（哪个视角不通过+需要什么证据）；2轮无共识→提示升级产销平衡会

#### 3.2.5 `BR-05` 基线独立于脉冲
- **规则描述**: 基线生成只取 true_qty（拆解已剥离脉冲/断点），脉冲/事件不进基线、不走趋势外推

#### 3.2.6 `BR-06` 逾期未修正按基线上报
- **规则描述**: 规定窗口内未提交修正 → 视为无意见，该行按基线值直通

#### 3.2.7 `BR-07` 七视角校准
- **规则描述**: 核对沿七个视角逐一校准——信任/客户侧情报/外部验证/库存水位/份额量纲/生命周期断点/节奏

#### 3.2.8 `BR-08` 销售仅修本人负责零件
- **规则描述**: 销售只能修正 D01 中 owner_sales 为自己的零件

### 3.3 业务数据
1. **统计基线(base_qty)**: 客观锚，独立于销售偏置
2. **销售修正值(adj_qty)**: 一线销售在基线上的修正值
3. **核定毛需求(approved_qty)**: 核对通过后的定稿值（消耗口径，不含事件）
4. **修正幅度率(adj_pct)**: (adj_qty−base_qty)/base_qty，超 θ_rev 强制举证
5. **调整登记(D04-L)**: 三件套落地载体

### 3.4 状态机

**行级状态**：
```
待生成基线 --基线生成--> 待修正 --销售提交--> 待核对 --核对通过--> 已核定
                        |                    |
                        |                    └─退回--> 已退回·待重报 --重报--> 待核对(轮次+1)
                        |                                |
                        └─逾期未修正--> 按基线上报        └─2轮无共识--> 升级产销平衡会
```

**批次级状态**：
```
进行中 --全部行核定--> 全部核定 --D09 R版发布--> 已锁定
```

### 4.2 功能详细说明

#### FUNC-01 创建加工批次
**功能描述**: D03 拆解确认后，系统自动创建加工批次（绑定收集V版本+客户）
**输入**: fcst_version（D03 V版）, oem_code, plant_code
**输出**: proc_batch（PRC-YYYYMM-NNN），初始状态=进行中

#### FUNC-02 生成基线
**功能描述**: 系统按 D10 选定策略（或 D05 借用基线）生成双路径基线
**处理逻辑**:
1. 取 D03 true_qty 为路径A 原料
2. 查 D10/D05 获取策略方法+参数
3. 计算路径A（时序外推）和路径B（因果推演=产量×用量×份额）
4. 计算交叉偏差，超阈标红
5. 总部计划确认/裁决后落库 D04-B

**特殊处理**:
- 历史充足→调用 `strategy_simulation.get_strategy`
- 历史不足→调用 `baseline_borrowing.get_derived_baseline`
- 生命周期"上市高后下滑"必须用衰减模型
- 受断点影响的期间基线截断

#### FUNC-03 销售修正提交
**功能描述**: 销售在基线上修正，登记三件套
**业务规则**: BR-02, BR-03, BR-08
**输入数据**: proc_batch, part_no, veh_model, period, adj_qty, adj_reason_cat, adj_evidence
**特殊处理**: 通用件各销售只修各自客户份额部分；修正≠定稿（须经核对）

#### FUNC-04 核对执行
**功能描述**: 总部计划沿七视角校准核对，通过/退回
**处理逻辑**:
1. 形式审查：三件套完整性、超阈举证
2. 防重校验：调 independent_event.list 检查与 D06 事件重复
3. 多因素校准：沿七视角逐一核对
4. 结论：通过→核定毛需求 / 退回→附理由返步骤3

**输入数据**: proc_batch, part_no, veh_model, period, chk_result, chk_reason(退回必填), chk_adj_qty(调数时)

## 7. 参考资料

### 7.3 外部依赖
- **demand_collection**: 取 true_qty 做基线输入；fcst_version 绑定

- **system_config**: 取参数阈值（θ_baseline/θ_rev等）
