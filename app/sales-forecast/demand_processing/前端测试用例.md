# demand_processing 前端测试用例

> 逐应用 · 第⑧步产出 | 对应前端详设 PAGE_META.key = demand_processing

## TC-DP-01 本页渲染
- 页面: `/view/sales-forecast/#demand_processing`
- 操作: admin 登录后访问
- 断言:
  1. 列表区 `.card .tbl` 存在（即使无数据也会有空提示行）
  2. **新建按钮存在**: `.tagline` 内可见 `新建` 按钮或 `b-pri` 含"新建"文本
  3. 搜索栏含状态 chips（进行中/全部核定/已锁定）和搜索输入框
  4. 非看板页 `.kpi` 数量 == 0（防粘滞——确保不是 dashboard 残留）

## TC-DP-02 新建加工批次 —— 表单展开
- 前置: 列表已渲染
- 操作: 点击 `新建` 按钮
- 断言:
  1. 折叠表单 `.collapse.open` 出现
  2. 必填字段可见: 预测版本 input、OEM 编码 input、工厂编码 input
  3. 底部有 "创建批次" 提交按钮

## TC-DP-03 新建加工批次 —— 落库回显
- 前置: 表单已展开
- 造数: 通过页面表单填入 fcst_version=V2026-08-TEST, oem_code=OEM-A, plant_code=PLANT-A1
- 操作: 填写必填字段后点击「创建批次」
- 断言:
  1. toast 提示创建成功 + proc_batch 编号
  2. 列表自动刷新，新记录出现在第一条
  3. 新记录 status = "进行中"

## TC-DP-04 详情模态全字段
- 前置: 列表有数据
- 操作: 点击某批次的批次编号 `.b-link`
- 断言:
  1. 模态 `.modal-mask` 出现
  2. 等待 `.loadbox` 消失
  3. 单头 KV 含: proc_batch, oem_code, fcst_version, status, start_time
  4. 基线 table 存在（含表头：零件号/车型/期间/原始量/基准量）
  5. 调整 table 存在（含表头：调整类型/调整量/依据）
  6. 校验 table 存在（含表头：校验项/结果/说明）

## TC-DP-05 筛选芯片
- 前置: 列表已渲染
- 操作: 依次点击状态 chips（进行中 / 全部核定 / 已锁定）
- 断言:
  1. 点击后 chip 高亮（变蓝或加边框）
  2. 列表仅刷新为对应状态的记录
  3. 再次点击已选中 chip 取消筛选，恢复全部数据
