## 0. 设计范围

毛需求管理覆盖需求信息**从输入到发布**的完整加工链，管理标的为：

**零件 × 项目（客户·车型） × 周期（M0~M+N）** 的毛需求量。

```
[输入] OEM 原始需求（年度/月度滚动预测、周度发货指示）
   ↓  步骤1 收集 + 信号拆解（滤噪声 / 剥脉冲 / 留真实消耗）
[加工] 步骤2 统计基线 → 步骤3 销售修正 → 步骤4 修正核对
       → 步骤5 通用件汇总去重 → 牛鞭修正（终端口径）→ 客户对齐
   ↓
[输出] 毛需求发布单（冻结口径）→ 净需求计算 / 产销平衡会（S&OP）
[旁路] 仿真拟合 / 借用基线（喂步骤2）· 转单率考核（事后闭环）
```

### 1.4 逐张说明

#### 主数据类

**D01 项目信息台账**（§1.1.1）
- 用途：毛需求加工的主数据底座；记录项目阶段与客户/产品/车型/量纲/生命周期/责任人六维属性。
- 关键内容：项目号、阶段（待定点/定点中/进行中）、客户·工厂、车型/平台、零件号、专用/通用、单车用量、供应份额、SOP/EOP、责任销售。
- 下游：全部过程单据的项目维度参照；阶段决定需求去向（进行中→近端毛需求；待定点/定点中→长期产能规划输入）。
- 维护节奏：项目生命周期节点变化时更新（定点、SOP、年型、EOP、份额变更）。

**D02 车型—零件映射表**（§1.1.9）
- 用途：把车型级外部数据（市场销量、上险数、生命周期、roadmap）映射到零件级，是使用外部爬取数据的前提。
- 关键内容：零件号、车型、单车用量、份额、生命周期阶段、SOP/EOP。
- 下游：步骤2 基线（车型产量×单车用量×份额）、步骤4 外部验证。
- 与 D01 的关系：D01 以"项目"为中心，D02 以"车型↔零件"映射关系为中心（通用件一行对多车型），二者有重叠但视角不同。

#### 过程单据类（加工链主线）

**D03 主机厂原始需求收集表**（§1.1.2 步骤1）
- 用途：记录主机厂各期滚动预测；**每期保留预测版本快照**，作为追溯与考核（信任折扣、转单率归因）的基础。
- 关键内容：零件号、客户·车型、项目阶段、M0~M+N 各期量、预测版本号、收集人·日期。
- 附加职责：**信号拆解的留痕载体**——每期版本的拆解结果（真实消耗 / 水位脉冲 / 噪声判定）随版本快照保存。
- 下游：真实消耗 → D04 基线输入；识别出的脉冲 → D06 登记。
- 节奏：月度滚动（每期预测一个 V 版本）；主责一线销售。

**D04 毛需求加工表**（§1.1.2 步骤2–4，核心单据）
- 用途：记录统计基线、销售修正、修正核对全过程，是毛需求加工的"总账"。
- 关键内容：零件号、车型、统计基线、基线来源、销售修正值、修正幅度、修正理由、核对结论（通过/退回）、核定毛需求、核对人。
- 内嵌机制：**调整登记三件套**——每次调整必须登记"原因类别 + 数据依据 + 责任人"（可追溯、可归因、可衡量 FVA 的前提）。
- 核对循环：退回→返销售修正→再核对，直至通过。
- 下游：核定值 → D07（通用件）或直接 → D08 → D09。

**D05 基线借用台账**（§1.1.5）
- 用途：历史不足零件的基线例外登记——借用方法（类比/生命周期模板/先导指标/池化）、来源、参数（峰值/衰减）、早期校准依据。
- 定位：D04 "基线来源"栏在历史不足场景的展开与留痕，保证"借来的基线"可复核、可回溯。
- 下游：喂 D04 步骤2 基线。

**D06 独立事件登记表**（⚠️ 补设，框架无对应单据）
- 设立依据：框架确立毛需求是叠加结构——`毛需求(当期) = 消耗驱动预测量 + 一次性水位脉冲 + 其他独立事件(断点等)`；脉冲与断点属"事件驱动"的独立加项，**当期计入、必须履约、不进趋势外推**，且需跟踪回落（水位补足后脉冲消失）。这类事件需要独立承载，否则要么混进趋势（虚高超储）、要么漏登记（断线）。
- 用途：登记水位脉冲、断点（ECN/零件切换）、其他一次性事件，作为发布毛需求中的独立加项管理。
- 关键内容：事件编号、事件类型（水位脉冲/断点/其他）、零件号、归属期间、事件量、来源依据（阶跃检测 / 发运−结算倒推 / 设变通知）、是否计入当期毛需求（恒"是"）、是否进趋势外推（恒"否"）、状态（生效/已回落/已关闭）。
- 下游：D09 发布单的独立加项；库存推移表推演输入（预警胀库/断线）。

**D07 通用件汇总修正表**（§1.1.2 步骤5）
- 用途：应对"公地悲剧"——多个销售各自加码、汇总必然虚高；由总部计划合并去重、对总量负责。
- 关键内容：通用件号、各主机厂需求（对应各销售）、汇总合计、去重修正值、修正说明。
- 位置：仅通用件经过；专用件跳过本单据。

**D08 牛鞭修正处理表**（§1.1.3）
- 用途：记录"下游订单（派生）vs 终端需求（OEM 消耗口径）"对比、放大系数与修正动作，把预测锚定终端需求。
- 关键内容：零件号、所在层级（Tier 1/2/3）、下游订单量、终端需求量、放大系数、修正动作（切换口径/信息共享/减小批量/容忍区间内维持）、修正后预测、核对人。
- 处理过程：收下游订单 → 取终端需求 → 算放大系数识别牛鞭 → 按机制修正 → 输出终端口径预测。

**D09 毛需求发布单**（§1.1.4，加工链终点）
- 用途：与客户对齐后正式定稿下达，是净需求计算与产销平衡会的**唯一输入**。
- 关键内容：零件号、客户·车型、核定毛需求（M0~M+N，含消耗驱动量与独立事件加项的构成）、主要依据、发布版本（R 版）、发布人。
- 发布即**冻结口径**：当期口径不再随意改动；重大变化走版本修订并留痕。

#### 支撑 / 风险 / 闭环类

**D10 策略仿真拟合表**（§1.1.6）
- 用途：在历史数据上滚动回测，为每个物料选出拟合最优的预测策略（方法+参数+配套库存策略），并定期重拟合。
- 关键内容：零件号、需求形态、候选策略、回测区间、MAPE/Bias/服务水平、综合排名、选定标记。
- 与 D05 的分工：历史充足 → 本表选策略；历史不足 → D05 借基线。二者共同决定步骤2 的基线方法与参数。

**D12 预测转单率考核表**（§1.1.10）
- 用途：跟踪预测转为实际订单/调拨单的比例，支撑激励考核；区分可控性（剔除 OEM 需求塌方，只追销售自己多报）。
- 关键内容：零件号、期间、预测值、实际转单值、转单率、偏差量、归因、考核结论。
- 反哺：考核结果 → 信任折扣校准（D04 核对输入）与销售激励。

### 1.5 识别结论与设计要点

1. **一条主线、三个旁路**：主链 D03→D04→D07→D08→D09；旁路为基线供给（D10/D05）、独立事件加项（D06）、闭环考核（D12）。
2. **补设 D06 独立事件登记表**是本次识别的关键增量：叠加结构中的"事件项"在框架中无承载单据，详设必须补齐，否则"趋势归趋势、事件归事件"无法落地。
3. **两级版本体系**需贯穿设计：
   - **V 版（收集版本）**：OEM 每期滚动预测的快照，存于 D03，支撑跨版本阶跃检测与信任折扣考核；
   - **R 版（发布版本）**：毛需求发布单的冻结口径，修订产生新版本并留痕。
4. **信号拆解不单设单据**：拆解是算法过程，结果随 D03 版本快照留存；拆出的脉冲流入 D06，噪声仅留判定说明。
5. **客户对齐是动作不是单据**：对齐结论与调整记入 D09 的"主要依据"。
6. **调整登记三件套**（原因类别+数据依据+责任人）是 D04 的必备字段组，是 FVA 与追责的数据基础。
7. **风险压测不在本域**：压测是库存推移表的情景化应用，归属产销协同层级（框架 §8）；本域仅提供已发布 R 版基准与需求侧情景。

## 2. 单据详设

### 2.1 D03 主机厂原始需求收集表

#### 2.1.1 单据定位

- 毛需求加工链的**流程入口**（步骤1），是 OEM 需求信息进入体系的唯一入口。
- 四项职责：
  1. **如实记录** OEM 各期滚动预测原始值；
  2. **版本快照留痕**——每期预测独立成版、永不覆盖，是阶跃检测、信任折扣、考核追责的数据前提；
  3. **信号拆解**——滤 MRP 噪声、剥水位脉冲、留真实消耗，拆解结果随版本冻结；
  4. **分发**——真实消耗交 D04 基线，水位脉冲交 D06 事件登记。
- 边界：
  - 只管**预测类**需求信息（月度滚动预测为主，年度需求口径为辅）；
  - **周度发货指示不进本表**——属调拨单管理（框架 §1.4），独立于产销协同机制；
  - 本表不做基线、修正、核对、汇总等任何加工动作。

#### 2.1.2 单据结构

三层结构：**收集单头**（客户×版本）→ **收集明细**（零件×期间，纵表）→ **拆解快照**（逐期拆解结果）。

```
D03-H 收集单头        1 ── N   D03-D 收集明细        1 ── 1   D03-S 拆解快照
（客户/版本/渠道/状态）          （零件 × 期间 × 原始量）          （噪声/脉冲/真实消耗）
```

> **为何明细用纵表（零件×期间）而非框架样例的横表（M0~M+3 列）**：各客户滚动期数 N 不一（3/6/12 期），横表列数无法固定；跨版本阶跃检测按"零件×期间"对齐比较，纵表天然支持；横表作为**展示层视图**保留（见 2.1.10）。

#### 2.1.3 字段设计

| 脉冲标记 | has_pulse | Bool | ✔ | 是否识别出一次性脉冲 |
| 事件登记号 | event_no | Ref | — | FK → D06（脉冲确认后生成/关联） |
| 拆解方法 | method | Enum | ✔ | 移动平均 / 指数平滑 / 阶跃检测 / 发运−结算倒推 / 免拆解 |
| 拆解依据 | basis | Text | ✔ | 如"V07→V08 M+1 跳增 200，水位差估算 +180" |
| 拆解人 / 日期 | decomposer / decompose_date | Ref/Date | ✔ | 总部计划 |

#### 2.1.4 版本机制

1. **V 版生成规则**：每收到一期 OEM 滚动预测 = 一个新版本；同月 OEM 中途修订 = 子版本（`V2026-08.1`），修订原因记入备注。
2. **快照不可变**：进入"已拆解"后整版冻结，任何修改只能产生新版本。这是阶跃检测、信任折扣、考核追责的数据前提。
3. **版本比对**：系统自动生成 V_n 对 V_{n−1} 的逐"零件×期间"差异视图，差异是一站式识别水位脉冲的入口。
4. **版本替代**：新版本确认后，旧版本自动置"已替代"；已替代版本**永久保留**、不参与下游取数，仅供历史查询与考核。

#### 2.1.5 信号拆解（接口概要）

拆解是滚动预测收集后的必经预处理，**完整逻辑见 §2.2《信号拆解详设》**。本节仅明确与 D03 的衔接：

- 拆解按收到的每个版本执行；结果存 D03-S 拆解快照，随版本冻结；
- D04 步骤2 基线**只取 `true_qty`，不取 `orig_qty`**；
- 确认的水位脉冲生成 D06 独立事件登记，事件号回写 `D03-S.event_no`；
- 非寄售件免拆解；"OEM 未提供"的期间不拆解、不补 0。

#### 2.1.6 状态机

```
草稿 ──拆解确认──→ 已拆解 ──当期毛需求发布（D09 R版）──→ 已锁定
  │
  └─作废（须填原因；本期收集作废纳入及时性考核）

已拆解/已锁定版本，被新版本确认替代 → 已替代（快照永久保留）
```

| 状态 | 可编辑性 |
|---|---|
| 草稿 | 单头、明细均可编辑 |
| 已拆解 | 全版冻结；拆解结果确需调整时，由授权人操作并留拆解修订记录 |
| 已锁定 | 任何修改禁止 |
| 已替代 | 只读 |

#### 2.1.7 业务规则

1. **完整性**：进行中项目零件全覆盖；OEM 未给的期间必须显式标记"未提供"，禁止隐性补 0。
2. **及时性**：OEM 预测发布后在规定时限内完成收集（纳入销售线考核）。
3. **一致性校验**：零件必须存在于 D01/D02 且为进行中项目（非进行中录入触发警告）；量纲与单车用量口径一致。
4. **合理性提示**：系统给出 零件量 vs（车型量 × 单车用量 × 份额）的偏离参考，超阈值提示人工确认，不硬阻断。
5. **通用件不汇总**：按客户/主机厂分别收集，汇总去重是 D07 的职责。
6. **期间折算**：M0~M+N 按锚定期间折算为会计期间，跨年滚动自然延续。
7. **M0 口径**：期中收集时 M0 = 已执行部分（已知发运）+ 剩余预测，口径在备注中说明并前后一致。

### 2.2 信号拆解详设

> 本节详设步骤1 收集后的预处理逻辑。拆解结果承载于 D03-S 拆解快照（§2.1.3），事件承载于 D06 独立事件登记表。

#### 2.2.1 目的：为什么要拆解

收到的 OEM 要货计划（补库计划）是**混杂信号**，直接进基线/趋势外推必然出错：

| 信号 | 特征 | 不拆解的后果 |
|---|---|---|
| 真实消耗驱动 | 跟随产量趋势，平滑 | ——（这才是要保留的） |
| OEM MRP 计算噪声 | 批量合并、最小起订量、提前期取整，呈周期性尖峰 | 尖峰被外推 → 未来各期虚高 |
| OEM 库存水位调整 | 一次性阶跃 / 脉冲 | **混进趋势 → 未来虚高超储；从当期删除 → 漏要货断线** |

拆解的任务，就是把毛需求的叠加结构还原出来：

```
毛需求(当期) = 消耗驱动预测量（趋势，预测引擎外推）
             + 一次性水位脉冲（独立项，当期计入、不进外推）
             + 其他独立事件（断点等，D06）
```

> **趋势归趋势、事件归事件**：预测引擎只对消耗建模外推；脉冲与断点属"事件驱动"的独立加项——当期计入、必须履约，但不进入趋势外推。

#### 2.2.2 拆解对象与数据角色

| 数据 | 性质 | 与拆解的关系 |
|---|---|---|
| 本期滚动预测（M0~M+N） | 预测 | **被拆解对象** |
| 历史实际消耗（结算量 = 客户领用） | 实测真值 | **无需信号拆解**；只做断点等异常打标，直接供 D04 基线与 D10 仿真拟合 |
| 历史实际数据（寄售仓库存、发运、结算） | 实测 | **拆解的输入与标尺** |
| 外生变量（OEM 排产、车型销量/上险数、整车库存系数） | 外部 | **趋势校验输入** |

> **因果逻辑**：水位脉冲只污染"要货"、不污染"领用"——OEM 上调安全库存使要货跳增，但领用不变。因此拆解只作用于要货预测；结算量天然干净。

历史数据的三个用途：① **检测输入**（跨版本比对、水位倒推）；② **对账标尺**（预测期变实际后与结算对账）；③ **方法回测**（历史要货版本重放拆解，供 D10 校准参数）。

#### 2.2.3 总流程

```
[输入] D03-D 原始量（零件×期间×V_n）· V_{n−1} 同口径原始量
       寄售仓：现时库存 / 目标水位 / 发运到货 / 结算
       外生变量：OEM 排产 / 车型销量·上险数 / 整车库存系数
        │
        ↓
Step 0 数据准备与前置检查
       · 无上一版本 → 阶跃检测不可用，标"首版"
       · 无寄售仓数据 → 脉冲识别降级"疑似未确认"
       · 非寄售件 → 免拆解
        │
        ↓
Step 1 噪声滤波（总额守恒）
       · 识别批量尖峰：|原始−平滑值| > θ_noise 且隔期正负对冲
       · 移动平均/指数平滑抹平，尖峰按周期摊还
       · 输出 noise_adj（带符号，Σ=0）
        │
        ↓
Step 2 水位脉冲识别与剥离（总额不守恒）
       · a 跨版本阶跃检测：单期 |Δ|>θ_step 且后续期 Δ→0 → 阶跃疑似
       · b 水位倒推：补库幅度 ≈ (目标水位−现时水位) × 期消耗当量
       · c 外生变量交叉验证 → 确认幅度
       · 输出 pulse_qty（带符号）→ 生成 D06 事件
        │
        ↓
Step 3 外生变量趋势校验
       · 剩余真实消耗趋势 vs 排产/上险数/库存系数
       · 偏离 > θ_exo → 转人工（D04 步骤4 校准输入），不自动改数
        │
        ↓
Step 4 对账与落库
       · 恒等式强制：true_qty = orig_qty − pulse_qty − noise_adj
       · 结算实际到达 → 对账 → 参数修正
       · 快照存 D03-S，随版本冻结
```

#### 2.2.4 分步逻辑

##### Step 0 · 数据准备与前置检查

输入齐套性决定拆解能力的降级方式：

| 前置条件 | 不满足时的降级 |
|---|---|
| 存在上一版本（V_{n−1}） | 阶跃检测不可用；仅靠水位倒推 + 外生变量；标记"首版，无对比基线" |
| 寄售仓数据可得（库存/水位/发运/结算） | 脉冲识别降级：不贸然剥离，标"脉冲疑似·未确认"转人工 |
| 寄售模式零件 | 非寄售件 → 免拆解（true_qty = orig_qty，噪声滤波可选做） |
| 期间数据存在 | "OEM 未提供"期间不拆解、不补 0，原样保留 |

##### Step 1 · 噪声滤波（总额守恒）

- **识别特征**：|原始量 − 平滑值| > θ_noise，且呈隔期正负对冲（上凸下凹成对出现）、多期均值贴合趋势——即批量合并/最小起订量/提前期取整造成的周期性尖峰。
- **处理**：移动平均（窗口 3 期）或指数平滑（α≈0.3）抹平尖峰；尖峰量按周期重新摊还、还原消耗节奏；**只滤高频，保留趋势与季节性**。
- **输出**：noise_adj，带符号；**拆解窗口内 Σnoise_adj = 0**——平滑只改形状、不改总量。
- **参数来源**：D10 策略仿真拟合表回测选定（方法与参数随物料形态而异），定期重拟合。

##### Step 2 · 水位脉冲识别与剥离（总额不守恒）

三个手段联合判定：

**a) 跨版本阶跃检测**——逐零件×期间计算版本差 Δ = V_n − V_{n−1}，按形态判别：

| Δ 形态 | 判定 | 处理 |
|---|---|---|
| 单期 \|Δ\|>θ_step，后续各期 \|Δ\|→0 | 水位脉冲（一次性） | 剥离，登记 D06 |
| 连续多期同向、渐进变化 | 趋势修订（OEM 排产变化） | 保留，进基线 |
| 全部期间同向同幅平移 | 系统性修订（份额/口径/年型级变化） | 不剥离，先查外生变量证实 |
| 单期跳增、后续同向跟随 | 趋势跳变（新品上量/促销启动） | 人工确认，慎剥离 |
| 隔期正负对冲、均值不变 | 批量噪声 | 归 Step 1 处理 |

**b) 寄售仓水位倒推**——定量估算脉冲幅度：

```
库存序列重建：期末库存 = 期初库存 + 发运到货 − 结算（与客户提供的库存对账）
估算补库幅度 = (目标水位 − 现时水位) × 期消耗当量
```

- 版本跳变量 ≈ 估算幅度（容差内）→ 脉冲坐实，幅度取两者中更可靠者；
- 两者背离大 → 人工裁决（可能是趋势跳变或客户口径变化）；
- 目标水位下调 → 负脉冲（去库）。

**c) 外生变量交叉验证**——消耗端是否支持跳变：车型排产/上险数无对应变化 → 佐证脉冲；消耗确在上行 → 按趋势处理。

**脉冲确认后的动作**：
- 生成/关联 D06 事件登记：量（带符号，水位上调+/下调−）、归属期间、判定依据；事件号回写 D03-S；
- 脉冲进**当期发运计划与当期净需求**（一次性加项），**不进基线/趋势外推**。

**脉冲生命周期与回落跟踪**（防止反馈回路造成重复/漏登记）：

```
生效 ──→ 已回落（水位已补足，事件关闭）
   └──→ 持续中（水位未补足、后续要货仍含该量）
```

- 后续版本比对：脉冲归属期量下降**且寄售仓水位已达标** → 判"脉冲回落"，这是库存反馈回路的预期表现（前期多发 → 本期少要），**不作为新的负向脉冲登记**，关联原事件关闭；
- 水位未达标、要货仍高 → 脉冲持续中，不重复登记；
- 回落判定依据（水位、结算）随事件一并留痕。

##### Step 3 · 外生变量趋势校验

- 对剥离噪声与脉冲后的真实消耗趋势，用 OEM 排产计划、车型销量/上险数、整车库存系数交叉验证；
- 偏离 > θ_exo → **不自动改数**，转 D04 步骤4 修正核对作人工校准输入（外部验证是核对的多因素之一）；
- 整车库存系数偏高 → 预警未来减产，提示下调远端趋势。

##### Step 4 · 对账与落库

- **恒等式（系统强制）**：`true_qty = orig_qty − pulse_qty − noise_adj`；
- **守恒校验**：拆解窗口内 Σnoise_adj ≈ 0，违反则拆解不通过；
- **历史对账**：结算实际到达后，对账两式——
  ```
  真实消耗(实测)   = 期初寄售仓库存 + 本期发运到货 − 期末库存（= 结算量，地面真相）
  真实消耗(拆解法) = 原始补库计划 − 水位脉冲 − 噪声
  ```
  偏差 > 对账警戒线 → 参数修正 + 复盘拆解判定；
- 拆解快照存 D03-S，**随版本冻结**；人工调整任何拆解结果必须登记修订记录（人/时点/原因/前后值）。

| 参数 | 含义 | 初始建议值 | 校准方式 |
|---|---|---|---|
| θ_step | 阶跃判定：单期版本差阈值 | max(10%×期量, 50 件) | 历史版本回测 |
| 阶跃回落 | 后续各期 Δ 回落判定 | \|Δ\| < θ_step×30% | 同上 |

#### 2.3.3 步骤 2：统计基线预测

**a) 定位与三重角色**

1. **客观锚**：独立于销售放大偏置的参考基准；
2. **FVA 标尺**：事后对比"基线 vs 修正值 vs 实际"，衡量销售修正是否带来预测增值（FVA = Forecast Value Added）；
3. **核定毛需求的输入**：修正核对通过的数值以基线为底稿。

> **关键重构（框架 §1.1.5）**：基线的本质是"客观、独立于销售偏置的锚"。历史不足时锚的来源可以换——类比曲线、生命周期模板、甚至直接是主机厂滚动预测——不必执着于"自身历史时间序列基线"。

**b) 输入**

| 输入 | 来源 | 用途 |
|---|---|---|
| 历史真实消耗（结算量，已清洗） | 内部沉淀 | 路径A 时序外推的原料 |
| 车型产量预测 | OEM 滚动预测（拆解后真实消耗趋势）/ 外部排产数据 | 路径B 因果推演 |
| 单车用量、供应份额 | D02 / D01 | 路径B 量纲转换 |
| 外生变量（销量/上险数/库存系数） | 外部爬取 | 趋势交叉验证 |
| 选定策略（方法+参数） | D10 策略仿真拟合表 | 历史充足时的方法与参数 |
| 借用基线登记 | D05 基线借用台账 | 历史不足时的锚来源 |

**c) 双路径生成与交叉验证**

```
路径A 时序外推（数据驱动）：
  历史真实消耗(结算量) ──按 D10 选定方法/参数──→ 未来各期基线
  （移动平均 / 指数平滑 / 季节分解 / 生命周期模板拟合；外生变量校验）

路径B 因果推演（驱动因子）：
  真实消耗(预测) = 车型产量预测 × 单车用量 × 份额

交叉验证：dev = |路径A − 路径B| / 路径A
```

| 情形 | 处理 |
|---|---|
| 历史充足 | **路径A 为主基线**，路径B 作验证；dev ≤ θ_baseline（建议 15%）直接采用 |
| dev 超阈 | 排查：份额/单车用量变化？外部数据时滞？生命周期转折？人工确认后定稿并记录原因 |
| 历史不足 | 路径A 不可用 → **路径B 或借用基线为主**（见 d） |

**d) 策略选择：D10 / D05 联动**

- **历史充足判定**（建议值，试运行后校准）：可用清洗历史 ≥ 12 个月且覆盖至少一个完整季节周期；
- 充足 → 查 **D10 策略仿真拟合表**取该物料的选定方法与参数；策略定期重拟合，形态变化（进入衰退等）时切换；
- 不足 → 走 **D05 基线借用台账**五种借法：先导指标替代（主机厂滚动预测 = 拆解后真实消耗，最强替代）、类比法、生命周期模板拟合、上移到平台/细分层级、池化/分层估计；
- 基线来源（自产方法 or 借用单号）写入加工表"基线来源"栏，保证可复核、可回溯。

**e) 生成规则**

1. **月度滚动**：每期重新生成，基线批次与收集 V 版本、期间绑定；
2. **粒度**：零件 × 客户·车型 × 期间（M0~M+N）；通用件按客户分别生成，**不汇总**（汇总归步骤5 / D07）；
3. **干净输入**：外推原料 = 历史结算量（拆解已剔除脉冲、断点已打标）；脉冲/事件不进基线——趋势归趋势、事件归事件；
4. **生命周期形态**："上市高后下滑"车型必须用衰减模型，**禁止按上市峰值线性外推**；衰退期联动降库存动作（框架 §1.1.9 警示）；
5. **断点联动**：受断点影响的期间不直接外推——旧件基线在断点期截断、新件按 D06 事件启动，衔接期人工确认；
6. **版本留痕**：基线随批次存版本；策略/数据变化触发重新生成，历史版本不覆盖。

**f) 步骤 2 数据项（基线明细，并入 D04 字段设计）**

| 字段 | 代码 | 说明 |
|---|---|---|
| 零件号 / 客户·车型 / 期间 | part_no / veh_model / period | 基线粒度 |
| 统计基线值 | base_qty | 路径A 或主用路径的输出 |

| 来源引用 | source_ref | D10 策略单号 / D05 借用单号 |
| 路径B 参考值 | causal_qty | 车型产量×单车用量×份额 |
| 交叉偏差 | deviation | \|A−B\|/A，超阈须记录原因 |

| 生成人·时间 | generator / gen_time | 系统生成 + 计划确认 |

#### 2.3.4 步骤 3：一线销售初步修正

**a) 定位与目标**

- 由熟悉客户的销售完成，注入统计方法看不到的客户侧信息：改款/促销/关系情报/OEM 口头增减（框架 §1.1.2 步骤3、§1.1.8 比较优势分工——一线有贴近客户的信息优势）。

| 输入 | 来源 | 用途 |
|---|---|---|
| 统计基线值 | 步骤2 输出 | 修正起点与偏离基准 |

| 独立事件提示 | D06 | 知晓脉冲/断点已独立管理，防止重复计入修正 |
| 本人历史修正表现 | FVA / 达成率记录 | 修正时展示提示，自我约束 |

**c) 修正规则**

1. **粒度**：按零件 × 客户·车型 × 期间修正，各期可独立修正；未修正的期间基线直通（修正幅度为 0，无需登记三件套）。
2. **起点**：在基线之上修正，与基线的偏离全程可见、留痕；销售不改基线本身，只产生修正层。
3. **三件套强制登记**：每次修正必须登记"原因类别 + 数据依据 + 责任人"；无三件套不得提交——这是可追溯、可归因、可衡量 FVA 的前提。
4. **分级举证**：|修正幅度率| > θ_rev（建议 20%）视为过度修正，数据依据强制非空且须举证（客户函件/邮件记录/数据截图）；阈值内简述理由即可。
5. **时限**：规定窗口内完成提交（与收集节奏联动，见 §2.1.7 及时性）；逾期系统催办，仍不提交则按基线上报——不修正视为无意见。
6. **边界**：销售不直接改动 D06 独立事件（脉冲/断点项）的量；对事件有信息的，走事件反馈、由计划确认登记。
7. **依据信息**：修正应基于"所知的客户侧信息 + 证据"，而非揣测核对会如何砍数。

**d) 原因类别枚举**（与步骤4 多因素校准框架对齐）

#### 2.3.5 步骤 4：修正核对

**a) 定位与目标**

- 总部计划对销售修正值进行**质询与多因素校准**，是销售放大偏置的制衡场（框架 §1.1.8 制衡逻辑：一线提供信息并做初判，但不对总量拍板；总部提供锚、做核对、把控总量）。
- 核对不只是"通过/退回"，而是**沿多因素校准**——把框架 §1.1.9 的处理信息逐项作为校准视角应用。
- 输出：核对结论（通过 → 核定毛需求 / 退回 → 返步骤3）。

**b) 输入**

| 输入 | 来源 | 用途 |
|---|---|---|
| 销售修正值 + 三件套 | 步骤3 | 核对对象 |
| 统计基线及其来源 | 步骤2 | 对比基准 |
| 信任折扣（客户历史达成率/偏差方向） | D12 / 达成率视图 | 信任校准 |
| 外生变量（销量/上险数/排产/库存系数） | 外部爬取 + D02 映射 | 外部验证 |
| 寄售仓水位与脉冲剥离状态 | D03-S | 水位复核 |
| 份额 / 单车用量 | D01 / D02 | 量纲校准 |
| 生命周期 / 断点 / 节奏日历 | D01 / D06 / 客户协同 | 形态与节奏校准 |
| D06 事件清单 | D06 | 防重复 |

**c) 核对流程（四个子步骤）**

1. **形式审查**：三件套完整性；幅度率超 θ_rev 是否附举证；逾期未提交按基线处理（步骤3 规则5）。
2. **防重校验**：修正量与已登记的 D06 事件（脉冲/断点）交叉检查；重复 → 退回，或剔除重复部分后再核。
3. **多因素校准**：按 d) 视角逐一核对，每个视角记录校准结论（无异常即"视角通过"）。
4. **结论与登记**：通过 → 落定核定毛需求；退回 → 附退回理由（哪个视角 + 需要什么证据）返步骤3。**核对人直接调数时同样必须登记三件套**（原因类别 + 数据依据 + 责任人 = 核对人）——三件套是双向的。

**d) 多因素校准视角**（框架 §1.1.2 步骤4）

| 校准视角 | 校准动作 | 数据来源 |
|---|---|---|
| 信任校准 | 按客户历史达成率/偏差方向打折或补足；达成率高直接采用 | D12 / 达成率视图 |
| 客户侧情报 | 审查销售所附证据是否充分（函件 vs 口头） | 步骤3 三件套 |
| 外部验证 | 市场销量/上险数/排产与修正值背离时调整 | 外部爬取 + D02 映射 |
| 库存水位 | 复核脉冲是否已剥离、目标水位是否变化 | D03-S / 寄售仓 |
| 份额与量纲 | 份额/单车用量变化同步调整 | D01 / D02 |
| 生命周期与断点 | 上市高后下滑、断点切换、年型 | D01 / 断点通知 / D06 |
| 节奏 | 停产/检修、季节性 | 客户协同 |

**e) 退回返工循环**

- 退回必须书面理由：**哪个视角不通过 + 需要什么证据/调整**；
- 销售补充证据或修正数值后重新提交，核对人再核；每轮全程留痕（修正值 / 结论 / 理由 / 人 / 时点）；
- 同一零件×期间 **2 轮仍无共识 → 升级**至产销平衡会或总部仲裁（平衡会是制度化的制衡场，框架 §1.3），防止死循环；
- 退回后销售逾期未重报 → 按基线采纳（保守处理）。

**f) 核定毛需求的落定与去向**

- 核定毛需求 = 零件 × 客户·车型 × 期间的定稿值，**消耗口径**——独立事件（脉冲/断点）不在核对范围内叠加，由 D06 在 D09 发布单上汇合（叠加结构，防重复计入）；
- 通过后流向：通用件 → D07 汇总修正；专用件直入 → D08 牛鞭修正；随后均进入客户对齐 → D09 发布。

### 2.4 D06 独立事件登记表

#### 2.4.1 单据定位

- **独立加项的唯一载体**：毛需求是叠加结构（`毛需求 = 消耗驱动预测量 + 一次性水位脉冲 + 其他独立事件`），"趋势归趋势、事件归事件"要求事件有独立台账——混进趋势则虚高超储，漏登记则漏要货断线（§2.2.1）。
- 承载三类事件：**水位脉冲**（拆解产出）、**断点**（ECN/零件切换，框架 §2.5）、**其他一次性事件**（一次性大批量、政策/展会采购等）。
- 边界：不承载趋势（归基线/修正）；不承载常规需求；不做库存推演，只向库存推移表供给事件输入。

#### 2.4.2 事件分类与来源

| 事件类型 | 来源 | 典型触发 | 数量特征 |
|---|---|---|---|
| 水位脉冲 | D03 拆解（阶跃检测/水位倒推，§2.2.4 Step 2） | OEM 上调/下调安全库存水位 | 带符号：上调 + / 下调 − |
| 断点 | 客户协同（设变通知 ECN） | 零件号切换、改款替代 | **成对**：旧件需求断崖 + 新件需求启动 |
| 其他一次性事件 | 销售/计划登记（须举证） | 一次性大批量、展会/政策采购 | 带符号 |

#### 2.4.4 事件生命周期与状态机

**水位脉冲**（核心是防"反馈回路"造成重复/漏登记，§2.2.4 Step 2）：

```
待确认（拆解"疑似"）──计划确认──→ 生效（计入当期）
                                   ├─水位已补足、后续版本脉冲消失──→ 已回落 ──→ 已关闭
                                   └─水位未补足、要货仍含该量──→ 持续中（不重复登记）
误判（外生/库存证据否定）──→ 已取消（留痕 + 反哺拆解参数）
```

- **回落 ≠ 新负脉冲**：脉冲归属期后水位补足、要货下降，是库存反馈回路的预期表现，关联原事件关闭，**不得登记为新的负向事件**；
- 回落判定依据（寄售仓水位、结算量）写入 close_basis。

**断点**：

```
登记（收到设变通知）──→ 生效（切换在途：旧件截断 + 新件启动）──旧件尾量清零、新件稳定──→ 已关闭
```

- 旧件侧防呆滞：截断后残余需求与库存比对，余量转呆滞预警（物控联动）；
- 新件侧防断货：启动量联动备产/建库。

**其他事件**：生效 → 履约完成 → 已关闭。

#### 2.4.6 业务规则

1. **常量约束**：in_demand 恒"是"、in_trend 恒"否"——系统强制，界面不可改；这是叠加结构在数据层的落锁。
2. **断点量化**：旧件事件量 = 剩余各期基线的冲销量（负值，防呆滞口径）；新件事件量 = 断点时点起的启动量（正值）；两者必须**成对登记**（bp_batch 关联），禁止单边登记——只盯新件会漏掉旧件呆滞，只盯旧件会漏掉新件断货。
3. **一次性**：事件量只计入归属期间（或事件注明的期间），不自动滚动、不进外推。
4. **防重复**：脉冲"持续中"期间，后续版本不得重复登记；回落不得登记为负脉冲（见 2.4.4）。
5. **举证制**：人工登记必须附依据（函件/设变通知/倒推计算）；系统生成的疑似项须计划确认后才生效。
6. **取消留痕**：误判事件置"已取消"，close_basis 记录复盘结论，并反哺拆解参数校准（θ_step 等）。
7. **与基线的关系**：事件不影响基线生成（§2.3.3 e.5 断点联动除外——断点期基线截断，由事件驱动）。

### 2.5 D05 基线借用台账

#### 2.5.1 单据定位

- **基线体系的例外台账**：D04 "基线来源"栏在历史不足场景的展开与留痕——保证"借来的基线"可复核、可回溯（§1.4 D05）。
- 与 D10 的分工：**历史充足 → D10 仿真拟合选策略；历史不足 → D05 借基线**；二者共同决定步骤2 的方法与参数。池化/上移法也用于通用件分层预测（不限于历史不足）。
- 借来的基线同样是"锚"：客观、独立生成、可被 FVA 衡量（框架 §1.1.5 关键重构——锚的来源可以换，锚的属性不变）。

#### 2.5.2 适用场景与触发判定

| 场景 | 特征 | 首选借法 |
|---|---|---|
| 未上市新车型 | 零历史（SOP 前） | 先导指标（OEM 滚动预测/预订量） |
| 短生命周期车型 | 清洗历史 < 12 个月或无完整季节周期（§2.3.3 d） | 类比法 / 生命周期模板 |
| 断点新件 | 新件零历史，旧件有曲线 | 模板拟合（旧件曲线做先验） |
| 单车型史短但平台稳定 | 平台/细分层有历史 | 上移预测 + 份额分摊 |
| 通用件分层预测 | 多车型共用 | 池化/分层估计 |

- 触发：步骤2 生成时判定历史不足 → 必须走借用登记；**未登记不得产生基线**（防黑箱基线）。

#### 2.5.3 五种借法（框架 §1.1.5）

| 方法 | 原理 | 关键参数 | 备注 |
|---|---|---|---|
| 先导指标替代 | 以 OEM 滚动预测（**拆解后真实消耗**）、预订量/在手订单、细分大盘替代自身历史 | 预测版本、信任折扣 | 对零部件企业，OEM 滚动预测是**最强替代** |
| 类比法 | 按定位/价格带/细分/动力形式找相似车型，用其真实需求曲线做模板映射 | 相似车选择依据、峰值、衰减率、时间平移 | 用相似车衰减率做先验，新车型早期数据校准 |
| 生命周期模板拟合 | 拟合"有约束的形状"（上市高后下滑模板）；先验约束形状，早期数据只标定少数参数 | 模板来源、峰值、衰减率 | 参数越少对数据要求越低 |
| 上移预测 | 在平台/细分层预测（更稳定有历史），再按份额向下分摊到车型/零件 | 上移层级、分摊权重 | 单车型史短、平台稳定的场景 |
| 池化/分层估计 | 从全体车型统计学习"典型生命周期形状"先验，新车型用早期数据更新，向相似车均值收缩 | 先验分布、收缩系数 | 避免小样本曲线乱跳 |

**方法优先级**：有 OEM 滚动预测 → 先导指标；无预测、有相似车型 → 类比；有早期数据 → 模板拟合/池化校准；仅有平台层历史 → 上移。可组合（如"类比模板 + 早期数据校准"）。

#### 2.5.4 借用流程

```
步骤2 判定历史不足 ──→ 选借法（按场景/优先级）──→ 定来源与参数 ──→ 早期校准（有自身数据必做）
        ──→ 登记借用单（JY-YYYYMM-NNN）──→ 总部计划审核 ──→ 喂 D04 步骤2（基线路径=借用）
        ──→ 随自身数据积累重校准 ──→ 历史转充足 → 切换 D10 自产策略，借用单关闭
```

- **早期校准**：先验（模板/类比参数）+ 自身早期数据 → 标定峰值、衰减率等少数参数；有早期数据而不校准的，审核不予通过；
- **重校准节奏**：每月随基线批次评估一次；SOP 后逐月数据到达时加密校准；
- **退出机制**：历史转充足（系统按月判定）→ 提示切换 D10 自产基线，人工确认后切换，借用单记"已转自产"。

#### 2.5.6 业务规则

1. **无登记不借用**：历史不足零件未经借用登记不得产生基线；
2. **锚纪律同等适用**：借用基线同样不受脉冲/事件影响、销售不修改（修正走步骤3/4）；
3. **校准优先**：有自身早期数据必须校准参数，纯照搬模板不予通过；
4. **自动退出**：历史转充足后切换自产策略，防止"永久借用"脱离数据闭环；
5. **FVA 覆盖借用基线**：基线 vs 实际同样考核，评估借法质量，反哺类比库/模板库（先验越用越准）；
6. **先导指标须过拆解**：以 OEM 滚动预测做先导时，取拆解后真实消耗（true_qty），不取原始要货量——脉冲不借进基线。

### 2.6 D07 通用件汇总修正表

#### 2.6.1 单据定位

- **步骤5 的承载单据**：通用件跨销售汇总、去重修正，总部计划**对总量负责**（框架 §1.1.2 步骤5、§1.1.8）。
- **对抗"公地悲剧"**：多个销售各自加码、汇总必然虚高；逐个核对（D04）看不见总量，必须有一道总量层的修正。
- 范围：**仅通用件经过**（专用/通用判定见 D01/D02）；专用件从 D04 直入 D08，跳过本单据。

#### 2.6.2 为什么汇总必然虚高（机制认知）

- 每个销售都从自己客户的立场加码（缓冲、筹码、考核），且各自默认"自己的加码不会被折"；
- 个体理性 → 集体虚高：加码相互不独立，简单加总放大偏置；
- 通用件呆滞**难归因到个人**，考核须上移到总量/后端层面（框架 §1.1.10）——因此总量的把关责任也只能放在后端（总部计划）。

#### 2.6.3 单据结构与粒度

- 汇总粒度：**通用件号 × 期间**；一张汇总单 = 一个通用件一个期间，明细行 = 各客户（OEM）份额。
- 输入：D04 核定值（各销售各自客户份额的核定值，已含三件套）；
- 结构：单头（总量与修正结论）+ 明细（各客户份额与证据结构）。

#### 2.6.4 去重修正方法

1. **汇总**：Σ 各客户份额的 D04 核定值 → 汇总合计；
2. **取锚**（总量合理性基准，三者对照）：
   - 历史实际用量（近 N 月结算汇总）；
   - 分层/池化预测（D05 上移/池化产出，通用件天然适合）；
   - 因果合计：Σ(车型产量 × 单车用量 × 份额)。
3. **判别**：汇总合计显著高于锚且加码缺乏需求侧证据 → 判定加码虚高，触发折减；
4. **差异化折减（不一刀切）**：
   - 有证据加码（客户函件/促销/上市，继承 D04 举证）→ 保留相应部分；
   - 口头/无证据加码 → 按历史折减系数折减（系数由历史"加码 vs 实际用量"回测得出）；
   - 下限约束：折减后不得低于已确认承诺量（有承诺/函件的部分必须履约）。
5. **登记**：去重修正值 + 修正说明 + 数据依据（总量层的三件套）；
6. **拆回（可选）**：修正总量需落回客户维度供发运参考时，按证据强度/历史份额比例分摊，分摊依据登记留痕。

### 2.7 D08 牛鞭修正处理表

#### 2.7.1 单据定位

- **发布前的最后一道口径修正**：记录"下游订单（派生）vs 终端需求（OEM 消耗口径）"的对比、放大系数与修正动作，把毛需求**锚定终端需求**（框架 §1.1.3）。
- 主链位置：D04/D07 之后、客户对齐 / D09 之前。
- 与拆解的关系（分层治理）：
  - **Tier 1 直供场景**：OEM 要货中的放大（水位脉冲/MRP 噪声）已在拆解（§2.2）中完成大部分修正，D08 做**简化确认**（放大系数 ≈1 即通过）；
  - **Tier 2/Tier 3 场景**（经 Tier 1 供货）：派生需求层层放大，D08 是**主战场**，须显式取终端口径修正。

#### 2.7.2 牛鞭效应认知（设计背景）

需求波动沿供应链向上游逐层放大，越往后段越明显（幅度为框架示例）：

| 环节 | 需求波动幅度（示意） | 说明 |
|---|---|---|
| OEM 终端消耗 | ±10% | 真实需求 |
| Tier 1 订单波动 | ±20% | 叠加 OEM 水位调整 + Tier 1 预测修正 |
| Tier 2 订单波动 | ±35% | 基于派生需求预测，再放大 |
| Tier 3 订单波动 | ±50% | 层层放大，失真最严重 |

**根源**：上游基于直接下游的订单（派生需求）而非终端需求做预测，订单已含下游的预测修正、安全库存调整与批量下单。四大成因：逐级预测再处理、订单批量、短缺博弈、安全库存叠加。

> **修正核心**（框架 §1.1.3）：治本之道是让每一层**基于终端需求预测，而非派生需求**——越往上游，越要"看穿"到 OEM 终端消耗。

#### 2.7.3 处理流程（五步）

```
① 收下游订单（派生需求）→ ② 取终端需求 → ③ 算放大系数识别牛鞭 → ④ 按机制修正 → ⑤ 输出终端口径预测
```

1. **收下游订单**：直接下游客户的订单/要货（Tier 1 场景 = D04/D07 核定的消耗口径链值）；
2. **取终端需求**，来源优先级：**OEM 结算（寄售领用）> OEM 消耗数据（客户协同）> 外部数据（上险数/整车销量 × D02 映射）> OEM 排产**；
3. **算放大系数**：`放大系数 = 下游订单（派生）/ 终端需求`；
4. **判定**：放大系数 ≤ θ_amp（容忍区间）→ 维持；超阈 → 从修正机制菜单选择动作并登记；
5. **输出**：终端口径预测 → 客户对齐 → D09。

#### 2.7.4 修正机制菜单（框架六机制）

| 机制 | 做法 | 与本体系的关联 |
|---|---|---|
| 终端需求可见（治本） | 基于 OEM 实际消耗、整车销量预测，而非下游订单 | 外部数据爬取 + D02 映射；层级越高越必要 |
| 信息共享上传 | 真实消耗信息向上游逐层共享，用消耗信号替代订单信号 | 寄售结算数据、库存可见（寄售模式天然有利） |
| 按预测准确率分配 | 不按报单量分配，消除短缺博弈 | §1.1.10 激励约束联动 |
| 减小批量 / 平准化 | 小批量高频补货，降低批量放大 | 与主动库存（经济批量）权衡 |
| 安全库存协同 | 避免各层独立叠加，集中或协同设置 | 安全库存策略联动 |
| 缩短提前期 | 降低需用预测覆盖的不确定性 | — |

- 修正动作以**口径切换**为首选（治本），批量/安全库存/提前期措施为配套；
- 禁止"无机制纯减数"——修正必须登记所落机制与依据。

### 2.8 D09 毛需求发布单

#### 2.8.1 单据定位

- **加工链终点**：加工流程（步骤1–5 + 牛鞭修正）与客户对齐完成后，毛需求以发布单形式**正式定稿下达**（框架 §1.1.4）。
- **净需求计算与产销平衡会的唯一输入**——未发布的任何口径不得被下游消费。
- **发布即冻结口径**（R 版）：一经发布，当期口径不再随意改动；重大变化走版本修订并留痕。
- 发布口径是**叠加结构的最终合成**：消耗驱动量（D08 终端口径）+ 独立事件加项（D06），构成列示。

#### 2.8.2 发布口径的构成

```
毛需求发布量(零件×期间) = 消耗驱动量（D08 修正后预测，消耗口径）
                        + Σ D06 生效事件量（归属该期间：脉冲 / 断点 / 其他）
```

- **构成列示**：发布单分行列示"消耗量 / 事件加项（逐条事件号）/ 发布总量"，下游可区分量的性质（趋势量可随版本演化，事件量必须履约）；
- 一次发布覆盖 M0~M+N 整个滚动窗口，与收集 V 版节奏对齐；
- 通用件按件号发布 D07 修正总量，附客户拆回列供调拨/发运参考。

#### 2.8.3 发布前置条件（Release Checklist）

1. D04 核对全部行通过（核定毛需求齐套）；通用件 D07 汇总修正完成；
2. D08 口径修正全部有结论（维持 / 修正）；
3. D06 事件状态齐备：**待确认/疑似事件不得进入发布加项**（只计入生效事件）；
4. **客户对齐完成**（见 2.8.5）：核定结果偏离客户原始意图的已沟通对齐，结论记入主要依据；
5. 与上一 R 版本差异完整（系统差异视图），重大变化均有说明。

#### 2.8.4 版本机制（R 版）

1. **版本编号**：`R+YYYYMM(.x)`，每期一个主版本；期内修订产生子版本（R x.1），修订原因留痕；
2. **冻结纪律**：发布后当期口径不可改，修订只能发新版本；修订人、审批、时点、原因全记录；
3. **版本比对**：系统生成 R_n vs R_n−1 逐零件×期间差异视图（与 V 版比对同机制）；
4. **联动锁定**：R 版发布 → 对应 D04 加工批次锁定 → 对应 D03 V 版本锁定（§2.3.6 c、§2.1.6），三层同时冻结；
5. **版本永久保留**：考核追责、FVA 基准、审计均引用发布快照。

#### 2.8.5 客户对齐（发布前动作）

- 定位：**动作而非单据**，结论记入发布单"主要依据"栏（§1.5 设计要点）；
- 规则（框架 §1.1.2）：
  1. 核定结果偏离客户原始需求/意图 → 与客户沟通、适当调整，**不单方面强加数据结论**；
  2. 数据修正用于"校准"，客户沟通用于"对齐"；
  3. **多路线供应警示**：相对客户需求主动下调时，评估客户转量其他供应商、份额被动降低的风险；决定下调的，对齐记录中说明；
  4. 对齐不成且客户坚持无依据的量 → 升级产销平衡会或上级决策，不带 unresolved 分歧发布。

### 2.9 D12 预测转单率考核表与预测闭环

#### 2.9.1 定位与目标

- 毛需求加工链的**事后闭环**：考核不是终点，反哺才是——它是控制层"不断把缺乏考虑的因素纳入体系"的数据依据（框架 §4）。
- 两个任务（框架 §1.1.10 核心思想）：
  1. **让报数的人有动机报实**（激励闭环：激励约束）；
  2. **让系统每个周期变得更准**（数据闭环：反馈校准）。
- 有手段核验：统计基线 + 评审核对 + 转单率指标，三者与考核共同构成需求处理的完整闭环。

#### 2.9.2 闭环结构

```
数据闭环：实际（结算 / 发运）→ 指标（准确率 / Bias / 达成率 / FVA / 转单率）
             → 反哺：信任折扣（D04）· 策略重拟合（D10）· 拆解参数（§2.2）· 修正规则（D04）
激励闭环：转单率 + 呆滞归因 → 分配优先 / 呆滞考核 → 如实报数
控制层闭环：月度复盘 → 归因发现 → 纳入遗漏因素（新事件类别→D06、新形态→拆解、新阈值）
```

#### 2.9.3 指标体系（双口径）

> **口径设计（关键）**：寄售模式下发货 ≠ 销售。**消耗口径（结算量）考核需求预测能力**——结算是地面真相；**发运口径（调拨/转单）考核履约与报数质量**——预测驱动建库、转单消耗库存。两套口径各评各的，不混用。

| 指标 | 定义 | 口径 | 考核对象 | 用途 |
|---|---|---|---|---|
| OEM 预测达成率 | 结算实际 / OEM 原始预测（V 版快照） | 消耗 | 客户预测可信度 | 信任折扣（D04 信任校准视角） |
| 基线准确率 / Bias | 统计基线 vs 结算实际（MAPE / 偏差方向） | 消耗 | 基线方法与参数 | D10 重拟合、拆解参数校准 |
| FVA（预测增值） | 基线误差 − 核定误差（正 = 修正增值） | 消耗 | 销售修正 / 总部校准的价值 | 修正规则收紧/放松、考核参考 |
| 预测转单率 | 实际转单（调拨/发运）/ 核定毛需求（发布口径，含事件） | 发运 | 销售报数质量 | 分配优先、呆滞考核 |
| 计划达成率 | 生产入库 vs 主计划 | — | 计划执行 | 框架 §4 月度复盘（产销协同层级联动） |

- 事件处理：脉冲/断点事件的实际履约单独核销（对 D06 事件闭环），不混入消耗口径的准确率计算；
- FVA 分层呈现：销售修正 vs 基线（一线贡献）、核定 vs 修正（总部校准贡献），归因到环节。

#### 2.9.4 归因规则（考核的核心）

**归因分类**（枚举）：

| 归因 | 可控性 | 处理 |
|---|---|---|
| 销售多报（加码无证据支撑） | 可控 | 计入考核；转呆滞的按呆滞考核 |
| OEM 需求塌方（车型减产/召回/骤停） | 不可控 | **销售免责，剔除** |
| 事件影响（断点/脉冲漏登或误判） | 流程 | 归因流程，反哺 D06 / 拆解 |
| 基线方法失准 | 策略 | 归因策略，反哺 D10 |

- **可控性原则**：只追可控、剔除不可控；设容忍区间（建议 ±10%，回测校准），区间内不追责；
- **塌方认定须举证**：外部减产信息 / 车型销量骤降 / 结算趋势 / 客户函件——不以销售自述免责；
- **通用件上移**：呆滞难归因到个人，考核上移到总量/后端层面（与 D07 总量责任制对齐）；
- **呆滞联动**：多报预测 + 库存未被消耗 → 呆滞；按归因分摊责任，区分"预测多报"与"执行未消耗"。

### 2.10 D10 策略仿真拟合表

#### 2.10.1 单据定位

- **基线方法的"军火库"**：不同物料的需求形态不同（稳定 / 波动 / 季节 / 短生命周期 / 断续），单一预测方法难以通吃——在历史数据上**滚动回测**，为每个物料选出拟合最优的策略（方法 + 参数 + 配套库存策略），并定期重拟合（框架 §1.1.6）。
- **支撑型单据**：服务于步骤2 基线生成；输出的是"方法 + 参数"，**不直接输出基线数值**（基线值在步骤2 生成，source_ref 指向本表单号）。
- 与 D05 的分工：**历史充足 → D10 选策略；历史不足 → D05 借基线**；拟合结论同时反哺 D05 的模板库 / 类比库。
- 结果登记留痕，供 FVA 与复盘使用。

#### 2.10.2 适用范围与触发

- **适用**：历史充足的物料×客户·车型（判定标准 §2.3.3 d：可用清洗历史 ≥ 12 个月且覆盖完整季节周期）；
- **触发**：
  1. 首次拟合：新物料历史转充足；
  2. 定期重拟合：月度轻量（参数重估）+ 季度全量（完整回测重选）；
  3. 事件触发：需求形态变化（进入衰退/新形态）、D12 闭环的基线准确率持续恶化告警。

#### 2.10.3 拟合流程（五步）

```
① 取历史 → ② 定候选策略 → ③ 滚动回测 → ④ 评估选优 → ⑤ 登记发布（喂步骤2）
```

1. **取历史**：该物料历史真实消耗（结算量，消耗口径）；**清洗**——按拆解（§2.2）与 D06 的标记剔除水位脉冲、断点、异常期，拟合只学干净消耗；
2. **定候选策略**：方法 × 参数 × 配套库存策略（安全库存/补货频率）——
   - 方法库：移动平均（窗口 N）、指数平滑（α）、季节分解（季节指数+趋势）、生命周期模板（峰值/衰减，模板库）、类比；
   - 候选由系统枚举生成，人工可增补；
3. **滚动回测**：训练段拟合 → 验证段出预测 → 滚动推进，模拟真实使用节奏（预测→执行→实际到达）；**严禁未来信息泄漏**——验证段只用当时点可见的数据；
4. **评估选优**：按 2.10.4 指标综合打分、排名、选定；
5. **登记发布**：选定策略登记单号（`D10-YYYYQN-NNN`），供步骤2 引用；全程留痕。

#### 2.10.4 评估指标与综合打分

| 指标 | 定义 | 含义 |
|---|---|---|
| MAPE / MAD / RMSE | 预测误差 | 准确度 |
| Bias | 偏差方向 | 系统性偏高/偏低（低报断线、高报呆滞，方向很重要） |
| 服务水平 / 缺货率 | 配套库存策略下的满足情况 | 服务保障 |
| 库存代价 | 周转 / 呆滞 / 配套安全库存水位 | 成本代价 |

- **综合原则**（框架原文）：不只看误差，要看"误差 + 库存代价"的综合；综合分 = 加权（误差、Bias、服务水平、库存代价），权重可配置；
- **代价不对称**：断线损失 ≫ 呆滞损失，损失函数对 Bias 方向非对称加权（宁可温和偏高，不冒断线）；
- **分段诊断**：回测按形态分段评估（峰期 / 稳期 / 衰减期），防止"平均好、拐点差"——生命周期转折点单独考核。

#### 2.10.6 重拟合与策略切换机制

1. **节奏**：月度轻量重拟合（新数据重估参数，不换方法）+ 季度全量重选（完整回测）；
2. **事件触发**：生命周期转折（进入衰退）、D12 告警（基线误差连续 N 期恶化）→ 即时重拟合；
3. **切换纪律**：换策略须登记依据；新旧策略**影子并行** 1~2 期（旧策略继续影子运行对比），防盲目切换导致恶化；
4. **参数反哺**：回测结论同时校准拆解通用参数（θ_noise、平滑窗口等，§2.2.5）；
5. **沉淀**：生命周期模板与类比结论沉淀为模板库 / 类比库，供 D05 借用。

#### 2.10.7 业务规则

1. **干净输入纪律**：回测数据必须清洗（脉冲/断点/异常已标记剔除），否则方法学到噪声；
2. **防泄漏**：滚动回测严格按时间序，验证段只用当时点可见信息；
3. **不强行选定**：最优候选综合分低于可接受线 → 转借用基线（D05）或人工判断，不硬选；
4. **留痕**：候选全集、得分、选定理由、拟合人全留存，支持复盘与 FVA 归因；
5. **与基线的边界**：D10 出"方法+参数"，步骤2 出基线值；基线偏差的归因在 D12 闭环中区分"方法失准（归 D10）"与"数据污染（归拆解）"。

### 2.13 主数据支撑检查

#### 2.13.1 检查方法

对每张单据枚举"数据输入 → 来源载体"，区分三类：**域内闭环**（本域单据承载）、**跨域依赖**（需外部系统/协同提供）、**缺口**（需补定义）。

#### 2.13.2 支撑矩阵

| 单据 | 关键数据输入 | 来源载体 | 状态 |
|---|---|---|---|
| D03 收集表 | 客户/工厂、零件/项目、车型、上一版本 | 客户主数据（MDM）、D01、D02、自身 V 版 | ✅ 域内闭环 |
| D03-S / 拆解 | 寄售仓库存 + 目标水位、发运到货、结算量 | 执行/协同数据层（ERP + 客户对账） | ⚠ 跨域依赖 |
| D04 加工表 | 基线、修正、七类校准数据（信任/外部/水位/份额/生命周期/节奏/情报） | D10、D05、D12、外部爬取、D03-S、D01/D02、销售三件套 | ✅ 域内闭环 |
| D05 借用台账 | 模板库/类比库、OEM 滚动预测 | 沉淀库（见缺口③）、D03 | ⚠ 沉淀库需载体 |
| D06 事件表 | 设变通知（ECN）、拆解脉冲、客户函件 | 客户协同 → 本单登记；D03-S | ✅ 登记渠道即本单 |
| D07 通用件 | 各客户核定值、历史实际用量、池化预测 | D04、结算量（执行数据层）、D05 | ⚠ 部分跨域 |
| D08 牛鞭 | 终端需求（结算 > OEM 消耗 > 外部映射 > 排产） | 执行数据层 + 客户协同 + D02 | ⚠ 部分跨域 |
| D09 发布单 | 上游全部结果 | 域内 | ✅ 域内闭环 |
| D10 拟合 | 历史清洗消耗、模板库 | 执行数据层 + 拆解标记、沉淀库 | ⚠ 部分跨域 |
| D12 考核 | 结算实际、转单/发运实际 | 执行数据层 | ⚠ 跨域依赖 |
| D01/D02 主数据 | 项目/车型/零件信息、外部生命周期 | 销售/计划维护 + 爬取（需来源登记） | ✅（外部源需登记） |

#### 2.13.3 缺口清单与建议

1. **① 实际执行数据层（最强跨域依赖）**：结算量、发运到货、寄售仓库存、调拨单/订单——拆解对账、D07 锚、D08 终端、D12 考核、D10 回测全部依赖。不属毛需求域单据范畴，需 ERP/履约系统 + 客户协同对账提供。**建议**：在系统集成设计中定义标准实际数接口（零件 × 期间 × 仓维度，含寄售仓节点），列为实施前置条件。
2. **② 外部数据源台账（建议补设）**：爬取数据（销量/上险数/库存系数/生命周期/roadmap）需要登记管理——来源、口径、时滞、更新频率、合规性；否则外部验证与因果路径不可审计。**建议**：作为系统级主数据补设"外部数据源台账"（不属 11 张业务单据）。
3. **③ 沉淀库与参数配置（建议补设）**：生命周期模板库、类比库（D05/D10 沉淀）、信任折扣（D12 计算产出）、阈值参数表（θ 系列、容忍区间、考核权重）。**建议**：定义为系统级"参数与沉淀库配置"，在后续 ER/数据模型章节中落位。
4. **④ 通用主数据（外部依赖）**：客户（OEM/工厂）、物料、车型、组织/用户、停产检修日历——依赖 MDM/ERP，本域只引用不维护；其中**停产检修日历**（步骤4 节奏视角输入）需明确维护责任（客户协同 + 计划录入）。
5. **结论**：11 张单据的业务数据流在域内相互闭环（每张单据的输入都有域内载体或已声明的外部接口），无悬空引用；落地依赖四项外部支撑——执行数据层接口、外部数据源台账、参数沉淀库、通用 MDM——**四项已分别设计，见 §2.14 ~ §2.17**。

| 停产检修子表 | — | 客户·工厂 × 起止日期 × 类型（计划停产/检修）× 来源（客户协同/计划录入）——步骤4"节奏"视角输入 |

#### 2.17.3 本地冗余机制

1. **同步策略**：日增量 + 周全量核对；月度与权威源对账并留快照；
2. **本地只读**：主体字段本地不可编辑；发现错误走权威源变更流程；扩展属性本地可维护；
3. **冲突处理**：主体以权威源覆盖本地；扩展属性以本地为准；
4. **缺失阻断**：零件/客户/车型在本地冗余表不存在 → 阻断相应单据录入（D03/D01/D02 一致性校验依赖此表）；
5. **接口失败降级**：使用本地缓存并显示"同步时点"；超期未同步告警。

              │触发批次

### 4.3 全局不变式（Invariants）

1. **唯一入口**：净需求 / S&OP 只消费已发布 R 版；
2. **锁定链**：R 版 → D04 批次 → D03 V 版同时冻结；锁定后修订只能走新版本；
3. **疑似不发布**：D06 待确认事件不得进入 D09 加项；
4. **构成可加和**：rel_qty = cons_qty + Σ事件量，系统强制；
5. **三件套双向**：任何数值调整（销售修正或核对人校准）必须登记原因类别 + 数据依据 + 责任人；
6. **快照引用**：考核 / 复盘 / FVA 只引用版本快照；
7. **量纲单一权威**：单车用量 / 份额只在 D02 变更。

## 5. 界面与操作设计

### 5.1 工作台（首页）

- **待办清单**（按角色）：
  - 销售：待收集、待修正、逾期未提交、核对质询待应答；
  - 计划：待拆解确认、疑似事件待确认、待核对、待汇总、待牛鞭确认、发布 checklist 待验证；
  - 销售管理：考核归因待认定、申诉待处理。
- **预警区**：θ 超阈（修正幅度/放大系数/对账偏差）、接口数据缺失降级（IF-A）、外部源质量异常（EXT）、事件逾期未回落。

### 5.2 界面清单

| 界面组 | 主要界面 | 对应单据 |
|---|---|---|
| 收集 | 原始需求录入（宽表输入）、版本比对视图、拆解确认页（疑似事件弹窗） | D03 |
| 加工 | 基线视图（双路径+偏差）、修正录入页（三件套表单）、核对工作台（视角清单 + 质询记录 + 退回） | D04 |
| 事件 | 事件台账（状态过滤）、事件详情（依据/加项/关联单据） | D06 |
| 汇总与牛鞭 | 汇总修正页（三锚对照 + 证据结构）、牛鞭处理页（系数清单 + 机制菜单） | D07 / D08 |
| 发布 | 发布草稿（构成列示）、checklist 校验页、版本差异视图 | D09 |
| 策略 | 拟合工作台（候选打分对比、影子并行）、借用台账 | D10 / D05 |
| 闭环 | 考核仪表盘（转单率/FVA/达成率）、归因工作台（举证） | D12 |
| 主数据与配置 | D01/D02 台账维护、参数配置、外部源台账、冗余表浏览 | §2.15~§2.17 |

### 5.3 关键操作流程

1. **收集 → 拆解 → 基线**：宽表录入提交 → 系统拆解预计算 → 计划确认（疑似脉冲弹窗，逐条确认/驳回）→ 自动创建 D04 批次并生成基线；
2. **修正 → 核对循环**：销售修正录入（三件套强制、超 θ_rev 强制举证）→ 核对工作台按七视角清单逐一过 → 通过定稿 / 退回（必填理由+所需证据）→ 重报再核 → 2 轮无共识系统提示升级；
3. **发布**：草稿自动汇总（D04/D06/D07/D08）→ checklist 五项校验 → 构成列示人工复核（消耗/事件分行）→ 发布 → 界面展示联动锁定链；
4. **考核闭环**：仪表盘钻取偏差行 → 归因工作台（四类归因 + 举证）→ 结论 → 反哺动作单跟踪。

### 5.4 通用交互规范

1. **钻取联动**：单号/版本号/事件号全局可钻取（D09 → D04 批次 → D03 V 版 → 拆解 → 事件），支撑审计；
2. **留痕展示**：三件套、变更日志、版本差异在所有发生调整的界面常驻可见；
3. **强制校验**：三件套、举证、发布 checklist 由系统强制，不可绕过；
4. **视图切换**：纵表存储 ↔ 宽表展示透视；期间支持 M 偏移与会计期间双显示；
5. **权限落地**：按 §4.4 矩阵控制；销售仅见本人负责零件；
6. **导出**：单据导出即快照值（含版本号），与界面显示一致。
