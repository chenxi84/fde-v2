# demand_release 前端测试用例

> 逐应用 · 第⑧步产出 | 对应前端详设 PAGE_META.key = demand_release

## TC-DR-01 本页渲染
- 页面: `/view/sales-forecast/#demand_release`
- 操作: admin 登录后访问
- 断言:
  1. 列表区 `.card .tbl` 存在（即使无数据也会有空提示行）
  2. **新建按钮存在**: `.tagline` 内可见 `新建` 按钮或 `b-pri` 含"新建"文本
  3. 搜索栏含状态 chips（草稿/待发布/已发布/已替代）和搜索输入框
  4. 非看板页 `.kpi` 数量 == 0（防粘滞——确保不是 dashboard 残留）

## TC-DR-02 新建发布草稿 —— 落库回显
- 前置: 列表已渲染
- 造数: 浏览器内 fetch POST `/api/apps/sales-forecast/demand_release/call/create_draft`，传入 base_period=2026-08
- 操作: 页面点击 `新建` → 填入 base_period=2026-08 → 点击「创建草稿」
- 断言:
  1. toast 提示创建成功 + rel_no
  2. 列表自动刷新，新记录出现在第一条
  3. 新记录 status = "草稿"

## TC-DR-03 详情模态全字段
- 前置: 列表有数据
- 操作: 点击某发布单的单号 `.b-link`
- 断言:
  1. 模态 `.modal-mask` 出现
  2. 等待 `.loadbox` 消失
  3. 单头 KV 含: rel_no, rel_version, base_period, status, publisher, publish_date
  4. 明细 table 存在（含表头：part_no/cons_qty/event_items/rel_qty/basis）

## TC-DR-04 核对校验
- 前置: 打开一个 status=草稿 的发布单详情
- 操作: 点击 "核对校验" 按钮
- 断言:
  1. 按钮可点击（非 disabled）
  2. 校验完成后 toast 提示 "校验通过" 或显示校验结果
  3. 若校验通过，状态流转为 "待发布"（或保持不变，取决于业务规则）

## TC-DR-05 发布操作
- 前置: 打开一个 status=待发布 的发布单详情
- 操作: 点击 "发布" 按钮 → 确认弹窗中确认
- 断言:
  1. confirm 弹窗出现
  2. 确认后 toast 提示 "发布成功"
  3. 模态内状态更新为 "已发布"
  4. publish_date 字段更新为当前时间戳

## TC-DR-06 筛选芯片
- 前置: 列表已渲染
- 操作: 依次点击状态 chips（草稿 / 待发布 / 已发布 / 已替代）
- 断言:
  1. 点击后 chip 高亮
  2. 列表仅刷新为对应状态的记录
  3. 再次点击已选中 chip 取消筛选
