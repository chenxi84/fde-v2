# 应用详设：毛需求发布单（demand_release）

> **应用名**：`demand_release` | **类名**：`DemandRelease`
> **对应聚合根卡**：architecture.md #9 | **对应 BRD**：§2.8 D09

---

## 1. 需求概览

- **需求名称**: 毛需求发布管理
- **优先级**: P0（加工链终点，净需求/S&OP 唯一入口）
- **涉及角色**: 总部计划（发布人·发布决策）、一线销售（客户对齐执行）

### 1.2 需求背景
加工流程全部完成后，毛需求以发布单形式正式定稿下达。发布即冻结口径 R 版，发布口径 = 消耗驱动量（D08终端口径）+ Σ 生效事件量（D06），构成列示。一经发布，当期口径不再随意改动。

---

## 2. 用户故事

#### `US-01` 发布草稿生成与 checklist 校验（优先级：P1）
- **故事描述**: 作为总部计划，我想要系统自动汇总上游结果生成发布草稿并执行 checklist 校验，以便于确保发布前置条件全部满足
- **验收场景**：
  1. `US-01-AC1` **正常生成**: Given D04全部核定+D08全部有结论+D06事件齐备+客户对齐完成，When 生成发布草稿，Then 消耗量/事件构成列示完整
  2. `US-01-AC2` **checklist不通过**: Given D06有待确认事件，When checklist校验，Then 报告"事件未齐备：疑似事件不得进入发布加项"，阻止发布
  3. `US-01-AC3` **构成可加和强制**: Given 消耗990+事件180，When 发布量手动改为1200（≠1170），Then 系统拒绝并提示"发布量必须=消耗量+Σ事件量"

#### `US-02` 发布与联动锁定（优先级：P1）
- **故事描述**: 作为总部计划，我想要正式发布 R 版，系统自动联动锁定 D04 批次与 D03 V 版
- **验收场景**：
  1. `US-02-AC1` **发布锁定**: Given checklist通过，When 点击发布，Then R版发布→D04批次锁定→D03 V版锁定，三层同时冻结

## 3.2 业务规则

| 编号 | 规则 |
|-----|------|
| BR-01 | 唯一入口：净需求/S&OP 只消费已发布 R 版；草稿口径不得外流 |
| BR-02 | 构成可加和：rel_qty = cons_qty + Σ事件量，系统强制 |
| BR-03 | 疑似不发布：D06 待确认事件不得进入发布加项 |
| BR-04 | 联动锁定：R版发布→D04批次锁定→D03 V版锁定，三层同时冻结 |
| BR-05 | 发布前 checklist 五项全部通过 |
| BR-06 | 偏离客户原始需求未调整的，主要依据中必须说明原因与风险评估 |

### 3.4 状态机

```
草稿 --checklist通过+客户对齐--> 待发布 --发布--> 已发布 --新版本替代--> 已替代
```
