# 应用详设：牛鞭修正处理表（bullwhip_correction）

> **应用名**：`bullwhip_correction` | **类名**：`BullwhipCorrection`
> **对应聚合根卡**：architecture.md #8 | **对应 BRD**：§2.7 D08

---

## 1. 需求概览

- **需求名称**: 牛鞭修正（终端口径锚定）
- **优先级**: P1（发布前最后一道口径修正）
- **涉及角色**: 总部计划（核对人·终端口径负责）

### 1.2 需求背景
下游订单（派生需求）含层层放大——Tier 1 放大约 2×、Tier 2 约 3.5×、Tier 3 可达 5×。修正核心：让每一层基于终端需求（OEM消耗口径）而非派生需求预测。Tier 1 直供且已拆解→简化确认；Tier 2/3→主战场。

---

## 2. 用户故事

#### `US-01` 牛鞭识别与修正（优先级：P1）
- **故事描述**: 作为总部计划，我想要对比派生需求与终端需求计算放大系数，以便于识别牛鞭并执行口径修正
- **验收场景**：
  1. `US-01-AC1` **Tier1容忍内**: Given 8210001·Tier1派生990/终端970，放大系数1.02≤θ_amp(1.10)，Then 维持通过
  2. `US-01-AC2` **Tier2超阈修正**: Given 8220010·Tier2派生1350/终端1000，放大系数1.35>1.10，Then 修正动作=切换终端需求口径+信息共享上传，final_qty=1000
  3. `US-01-AC3` **无机制拒绝**: Given 超阈但未选机制仅填减数值，Then 系统拒绝并提示"修正必须登记所落机制与依据"

---

## 3.2 业务规则

| 编号 | 规则 |
|-----|------|
| BR-01 | 全覆盖分轨：Tier1直供+已拆解→简化确认；Tier2/3→强制修正分析 |
| BR-02 | 终端来源优先级不可跳级：结算>OEM消耗>外部映射>排产 |
| BR-03 | 容忍区间 θ_amp=1.10，可按层级/客户配置 |
| BR-04 | 禁止"无机制纯减数"：修正须登记机制与依据 |
| BR-05 | 修正不改合理修订：调口径锚，不推翻 D04 有据修正 |

### 3.4 状态机

```
待处理 --容忍内--> 维持 --确认--> 已确认（转发布）
待处理 --超阈--> 已修正 --确认--> 已确认
```
