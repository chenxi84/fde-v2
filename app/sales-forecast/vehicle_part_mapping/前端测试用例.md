# vehicle_part_mapping 前端测试用例

> 逐应用 · 第⑧步产出 | 对应前端详设 PAGE_META.key = vehicle_part_mapping

## TC-VM-01 本页渲染
- 页面: `/view/sales-forecast/#vehicle_part_mapping`
- 操作: admin 登录后访问
- 断言:
  1. 列表区 `.card .tbl` 存在（即使无数据也会有空提示行）
  2. **新建按钮存在**: `.tagline` 内可见 `新建` 按钮或 `b-pri` 含"新建"文本
  3. 搜索栏含生命周期阶段 chips（lc_stage）和搜索输入框
  4. 非看板页 `.kpi` 数量 == 0（防粘滞——确保不是 dashboard 残留）

## TC-VM-02 新建车型映射 —— 落库回显
- 前置: 列表已渲染
- 造数: 浏览器内 fetch POST `/api/apps/sales-forecast/vehicle_part_mapping/call/create`，传入 part_no=PART-001, veh_model=Model-X, usage=前保, share=30, lc_stage=SOP, lc_shape=A, sop=2027-01, eop=2032-12, source=客户输入
- 操作: 点击 `新建` → 填入必填字段 → 点击提交
- 断言:
  1. toast 提示创建成功
  2. 列表自动刷新，新记录出现在第一条
  3. 列表行显示 part_no, veh_model, platform, usage, share, lc_stage, lc_shape, status

## TC-VM-03 详情模态全字段
- 前置: 列表有数据
- 操作: 点击某映射记录的零件号 `.b-link`
- 断言:
  1. 模态 `.modal-mask` 出现
  2. 等待 `.loadbox` 消失
  3. 单头 KV 含: part_no, veh_model, platform, usage, share, lc_stage, lc_shape, status
  4. 生命周期字段含: sop, eop
  5. 来源字段含: source
  6. 用量历史子表 usage_history 存在（含表头：期间/用量/来源）

## TC-VM-04 lc_stage 筛选
- 前置: 列表已渲染
- 操作: 依次点击生命周期阶段 chips
- 断言:
  1. 点击后 chip 高亮
  2. 列表仅刷新为对应阶段的记录
  3. 再次点击已选中 chip 取消筛选

## TC-VM-05 用量历史查看
- 前置: 打开一个车型映射详情
- 操作: 查看 usage_history 子表
- 断言:
  1. 子表存在且有表头行
  2. 若该零件有历史用量数据，显示对应行
  3. 无数据时显示空提示
