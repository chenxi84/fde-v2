# project_info 前端测试用例

> 逐应用 · 第⑧步产出 | 对应前端详设 PAGE_META.key = project_info

## TC-PI-01 本页渲染
- 页面: `/view/sales-forecast/#project_info`
- 操作: admin 登录后访问
- 断言:
  1. 列表区 `.card .tbl` 存在（即使无数据也会有空提示行）
  2. **新建按钮存在**: `.tagline` 内可见 `新建` 按钮或 `b-pri` 含"新建"文本
  3. 搜索栏含阶段 chips（待定点/定点中/进行中/EOP关闭）和搜索输入框
  4. 非看板页 `.kpi` 数量 == 0（防粘滞——确保不是 dashboard 残留）

## TC-PI-02 新建项目 —— 落库回显
- 前置: 列表已渲染
- 造数: 浏览器内 fetch POST `/api/apps/sales-forecast/project_info/call/create`，传入 project_no=PRJ-TEST-001, part_no=PART-001, stage=定点中, oem_code=OEM-A, plant_code=PLANT-A1, veh_model=Model-X, part_kind=结构件, sop=2027-01, owner_sales=张三
- 操作: 点击 `新建` → 填入必填字段 → 点击提交
- 断言:
  1. toast 提示创建成功 + project_no
  2. 列表自动刷新，新记录出现在第一条
  3. 新记录 stage = "定点中"

## TC-PI-03 详情模态全字段
- 前置: 列表有数据
- 操作: 点击某项目的项目编号 `.b-link`
- 断言:
  1. 模态 `.modal-mask` 出现
  2. 等待 `.loadbox` 消失
  3. 单头 KV 含: project_no, part_no, stage, oem_code, veh_model, part_kind, owner_sales
  4. 其他字段含: plant_code, sop, eop（若已填）
  5. 变更日志子表 change_log 存在（含表头：变更时间/变更人/变更内容/变更前/变更后）

## TC-PI-04 阶段筛选
- 前置: 列表已渲染
- 操作: 依次点击阶段 chips（待定点 / 定点中 / 进行中 / EOP关闭）
- 断言:
  1. 点击后 chip 高亮
  2. 列表仅刷新为对应阶段的记录
  3. 再次点击已选中 chip 取消筛选，恢复全部数据

## TC-PI-05 阶段流转
- 前置: 打开一个 stage=定点中 的项目详情
- 操作: 点击阶段流转按钮（如 "进入进行中"）
- 断言:
  1. 确认后 toast 提示 "阶段已更新"
  2. 模态内 stage 更新为新阶段
  3. change_log 子表新增一条变更记录

- 断言: 本页整个会话期间浏览器 console 无 error（favicon 除外），HTTP 无 >=400（业务校验抛 FdeError 属正常 200）
