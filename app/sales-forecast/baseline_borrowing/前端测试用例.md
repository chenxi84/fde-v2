# baseline_borrowing 前端测试用例

> 逐应用 · 第⑧步产出 | 对应前端详设 PAGE_META.key = baseline_borrowing

## TC-BB-01 本页渲染
- 页面: `/view/sales-forecast/#baseline_borrowing`
- 操作: admin 登录后访问
- 断言:
  1. 列表区 `.card .tbl` 存在（即使无数据也会有空提示行）
  2. **新建按钮存在**: `.tagline` 内可见 `新建` 按钮或 `b-pri` 含"新建"文本
  3. 搜索栏含状态 chips（待审核/生效/已转自产/已关闭）和搜索输入框
  4. 非看板页 `.kpi` 数量 == 0（防粘滞——确保不是 dashboard 残留）

## TC-BB-02 新建基线借用 —— 落库回显
- 前置: 列表已渲染
- 造数: 浏览器内 fetch POST `/api/apps/sales-forecast/baseline_borrowing/call/create`，传入 part_no=PART-001, veh_model=Model-X, borrow_method=直接借用, borrow_source=Model-Y, hist_months=12
- 操作: 点击 `新建` → 填入必填字段 → 点击提交
- 断言:
  1. toast 提示创建成功 + jy_no
  2. 列表自动刷新，新记录出现在第一条
  3. 列表中显示 part_no, veh_model, borrow_method, hist_months, status

## TC-BB-03 详情模态全字段
- 前置: 列表有数据
- 操作: 点击某借用单的编号 `.b-link`
- 断言:
  1. 模态 `.modal-mask` 出现
  2. 等待 `.loadbox` 消失
  3. 单头 KV 含: jy_no, part_no, veh_model, borrow_method, hist_months, status
  4. 校准字段含: calibration（校准系数/校准说明）
  5. 派生量字段含: derived_qty（借用后派生需求量）

## TC-BB-04 状态流转 —— 审核生效
- 前置: 打开一个 status=待审核 的借用单详情
- 操作: 点击 "审核" 按钮 → 确认
- 断言:
  1. 确认后 toast 提示 "审核通过"
  2. 状态更新为 "生效"
  3. 若已生效，审核按钮消失或 disabled

## TC-BB-05 状态筛选
- 前置: 列表已渲染
- 操作: 依次点击状态 chips（待审核 / 生效 / 已转自产 / 已关闭）
- 断言:
  1. 点击后 chip 高亮
  2. 列表仅刷新为对应状态的记录
  3. 再次点击已选中 chip 取消筛选

## TC-BB-06 关闭借用单
- 前置: 打开一个 status=生效 的借用单详情
- 操作: 点击 "关闭" 按钮 → 确认
- 断言:
  1. confirm 弹窗出现
  2. 确认后 toast 提示 "已关闭"
  3. 状态更新为 "已关闭"
