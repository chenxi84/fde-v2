# 应用详设：独立事件登记表（independent_event）

> **应用名**：`independent_event` | **类名**：`IndependentEvent`
> **对应聚合根卡**：architecture.md #6 | **对应 BRD**：§2.4 D06

---

## 1. 需求概览

- **需求名称**: 独立事件登记管理
- **所属模块**: sales-forecast / 毛需求管理
- **优先级**: P0（叠加结构的独立加项载体，缺此则"趋势归趋势、事件归事件"无法落地）

### 1.2 需求背景
毛需求是叠加结构：`毛需求(当期)=消耗驱动预测量+一次性水位脉冲+其他独立事件`。脉冲与断点属"事件驱动"的独立加项——当期计入、必须履约、不进趋势外推。这类事件需独立承载，否则要么混进趋势（虚高超储）、要么漏登记（断线）。

### 1.3 需求范围
**包含**：事件登记（水位脉冲/断点/其他一次性事件）、事件生命周期管理（确认/生效/持续/回落/关闭/取消）、成对断点管理、防重复机制
**不包含**：趋势预测（归 D04/D10）、常规需求管理

### 1.4 涉及角色
- **系统**：拆解自动生成脉冲疑似项；回落检测建议；断点日期/尾量计算提示
- **总部计划**：疑似项确认、断点登记与关闭、事件取消裁决
- **一线销售**：提供事件线索（客户口头、设变信息）；不直接激活事件

## 2. 用户故事

#### 2.1.1 `US-01` 事件登记（优先级：P1）
- **故事描述**: 作为总部计划，我想要登记独立事件（脉冲/断点/其他），以便于独立加项进入 D09 发布口径
- **验收场景**：
  1. `US-01-AC1` **脉冲自动生成**: Given 拆解确认脉冲+180，When 系统调 independent_event.create，Then 事件生成（event_type=水位脉冲，in_demand=是，in_trend=否）
  2. `US-01-AC2` **成对断点**: Given 断点通知 ECN-A-118，When 调 create_bp_pair(旧件, 新件, bp_date)，Then 两条事件生成，bp_batch 相同关联
  3. `US-01-AC3` **人工登记须举证**: Given 销售登记"其他"事件无依据，Then 系统拒绝并提示"人工登记必须附依据"

#### 2.1.2 `US-02` 事件生命周期管理（优先级：P1）
- **故事描述**: 作为总部计划，我想要管理事件状态流转（确认→生效→回落→关闭），以便于防止重复登记和反馈回路
- **验收场景**：
  1. `US-02-AC1` **脉冲回落**: Given 脉冲事件生效但因水位已达标，When 标记已回落，Then 状态→已回落→已关闭，close_basis 记录水位达标证明
  2. `US-02-AC2` **回落≠新负脉冲**: Given 脉冲回落后后续版本要货下降，Then 系统不将其识别为新脉冲/负向事件
  3. `US-02-AC3` **取消留痕**: Given 脉冲被证实为误判，When 取消事件，Then 状态→已取消，close_basis 记录复盘结论

## 3.2 业务规则

#### `BR-01` 常量约束
- **规则描述**: in_demand 恒"是"、in_trend 恒"否"——系统强制，界面不可改

#### `BR-02` 断点成对登记
- **规则描述**: 旧件截断+新件启动必须成对登记（bp_batch关联），禁止单边

#### `BR-03` 防重复
- **规则描述**: 脉冲"持续中"期间后续版本不得重复登记；回落不得登记为负脉冲

#### `BR-04` 疑似不发布
- **规则描述**: 待确认/疑似事件不得进入 D09 发布加项

#### `BR-05` 举证制
- **规则描述**: 人工登记必须附依据；系统生成的疑似项须计划确认后才生效

### 3.4 状态机

**水位脉冲**：
```
待确认 --计划确认--> 生效 --水位达标--> 已回落 --关闭--> 已关闭
生效 --水位未达标--> 持续中（不重复登记）
待确认 --误判--> 已取消
```

**断点**：
```
登记 --切换在途--> 生效 --旧件清零+新件稳定--> 已关闭
```
