# independent_event 前端测试用例

> 逐应用 · 第⑧步产出 | 对应前端详设 PAGE_META.key = independent_event

## TC-IE-01 本页渲染
- 页面: `/view/sales-forecast/#independent_event`
- 操作: admin 登录后访问
- 断言:
  1. 列表区 `.card .tbl` 存在（即使无数据也会有空提示行）
  2. **新建按钮存在**: `.tagline` 内可见 `新建` 按钮或 `b-pri` 含"新建"文本
  3. 搜索栏含状态 chips 和 event_type 下拉筛选
  4. 非看板页 `.kpi` 数量 == 0（防粘滞——确保不是 dashboard 残留）

## TC-IE-02 新建独立事件 —— 表单展开
- 前置: 列表已渲染
- 操作: 点击 `新建` 按钮
- 断言:
  1. 折叠表单 `.collapse.open` 出现
  2. 信息分组可见: 基本信息（event_type, part_no, period）、量与期间（event_qty）、来源（source_basis）
  3. 底部有提交按钮

## TC-IE-03 新建独立事件 —— 落库回显
- 前置: 表单已展开
- 造数: 通过页面表单填入 event_type=增产, part_no=PART-001, period=2026-08, event_qty=500, source_basis=客户通知
- 操作: 填写必填字段后点击提交
- 断言:
  1. toast 提示创建成功 + event_no
  2. 列表自动刷新，新记录出现在第一条
  3. 新记录 status = "待确认"（或初始状态）

## TC-IE-04 详情模态全字段
- 前置: 列表有数据
- 操作: 点击某事件的编号 `.b-link`
- 断言:
  1. 模态 `.modal-mask` 出现
  2. 等待 `.loadbox` 消失
  3. 基本信息区含: event_no, event_type, part_no, status, creator
  4. 量与期间区含: period, event_qty
  5. 来源区含: source_basis, source_detail
  6. 关闭管理区含: close_reason, closed_at（若已关闭）

## TC-IE-05 事件确认
- 前置: 打开一个未确认的独立事件详情
- 操作: 点击 "确认" 按钮
- 断言:
  1. 确认后 toast 提示 "事件已确认"
  2. 状态更新为 "已确认"
  3. 若事件已确认，按钮变为 disabled 或消失

## TC-IE-06 事件关闭
- 前置: 打开一个已确认的独立事件详情
- 操作: 点击 "关闭" 按钮 → 输入关闭原因 → 确认
- 断言:
  1. 未填原因时 toast 警告
  2. 填原因后提交，toast 提示 "事件已关闭"
  3. 状态变为 "已关闭"，关闭原因字段回显
