## §1 壳与菜单 / 看板 / 流程总览

### VT-SHELL-01 壳启动与菜单序

- **页面**: `e2e:dashboard`（壳启动，覆盖全部页面菜单序）
- **操作**: 登录 admin → `GET /view/e2e/` → 等 `.rail .nav-item` 渲染
- **断言**:
  - 侧栏品牌 `.brand .name` 文本 == `FDE·E2E`
  - 栏首为**平台置顶页**：`AI管家`（`view/lib/shell.js` 的 `PLATFORM_PAGES` 里 `workbench` 带 `top: true`）
  - 其后为**业务页 4 项**，按各页 `PAGE_META.order` 升序：

| 序 | key | order | 菜单中文名（PAGE_META.name） |
|---|---|---|---|
| — | （平台置顶） | — | AI管家 |
| 1 | dashboard | 1 | 首页看板 |
| 2 | member | 10 | 成员管理 |
| 3 | process | 15 | 流程总览 |
| 4 | task | 20 | 任务管理 |

- **选择器注意**: 第⑨步脚本**不手抄**这张表 —— 它扫 `app/e2e/*/view.js` 与组级 `app/e2e/*.js` 的 `PAGE_META`
  加 `view/lib/shell.js` 的 `PLATFORM_PAGES` **现算**期望序列（PSC 那边手抄过一版、漂了三处，**组级脚本因此一直红着**）。
  隐藏平台页（alerts/autopilot/…）不计入。

### VT-DASH-01 首页看板渲染

- **页面**: `e2e:dashboard`（默认落地页）
- **操作**: admin 会话进入 `#/dashboard` → 等 `.loadbox` 消失（`x-show="loading"` 结束）再断言
- **断言**:
  - `.kpi` 数 **== 4**（成员总数 / 任务总数 / 进行中任务 / 已完成任务；与逐应用页「`.kpi` == 0 防粘滞」互为镜像）
  - 「任务状态分布」overline 存在；`.pipe-col` 数 **== 2**（① 任务·按状态 / ② 成员主数据）
  - 状态分布的三行 `.sline` 含 `.st` 徽章 `待办 / 进行中 / 已完成`
  - **造数后**（§0 造了 M001 + T1/T2/T3）：4 张 KPI 依次为 `1 / 3 / 1 / 1`（成员 / 任务 / 进行中 / 已完成），
    两个 `.pipe-col` 右上角 `.right.mono` 依次为 `[任务总数, 成员总数]` = `[3, 1]`（**逐列对账，不比对"某一个数"** ——
    两列都有 `.right.mono`，只写"右上角的数"会分不清是哪一个，这正是本轮 0==0 恒真的成因之一），
    三行状态分布计数 == `[1,1,1]` 且**求和 == 任务总数**，进行中/已完成两行分别等于对应 KPI（**同源对账**）
- **选择器注意**: 先等 loading 结束再断言，避免抢跑；KPI 数字取 `.kpi .v`（`.k` 是中文标签）。

### VT-PROCESS-01 流程总览（数据驱动 SVG）

- **页面**: `e2e:process`
- **操作**: admin 会话内 `location.hash = '#/process'` → 等 `main svg g[data-page]` 渲染
- **断言**: `main svg g[data-page]` 数 **== 8**（3 个阶段胶囊 + 5 个步骤节点 = 2+1+2，皆可点；
  链路在 `process.js` 的 `stages()` 里**硬编码** —— 改链路要同步改这个数）；
  底部图例含「绿」「灰」与「点击节点进入对应页面」
- **选择器注意**: 本页**不发任何 svc**（硬编码链路），故 0 报错只可能来自壳；`.loadbox` 消失后再断言。
