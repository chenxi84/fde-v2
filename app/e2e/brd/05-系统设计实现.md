# 第5章 系统设计实现

前四章定义了业务口径，本章把它落到系统层面：边界、模块、数据流、页面。

## 5.1 系统定位与边界

本系统承载「建成员 → 建任务并指派 → 状态流转 → 全貌查看」的主链路。

| 项 | 处理方式 |
|---|---|
| 登录 / 认证 / 会话 | **由平台承担**，本系统不实现（第 2 章的权限表是"业务要求"，执法在平台） |
| 权限判定与数据范围 | 由平台按「用户 → 角色 → 页面/服务」授权链执行；应用**自身不写鉴权** |
| 审计（谁改的、何时改的） | 由平台在库表上自动补齐审计列 |
| 成员信息维护 | 本期只做新增与查询，**不开放修改/删除**（第 3 章 `R3.12`） |
| 统计报表 / 导出 | 不做；全貌由看板给出（§5.3） |

## 5.2 模块划分

| 模块 | 对应章节 | 职责 | 单据 |
|---|---|---|---|
| 成员主数据 | 第 2、3 章 | 名单的新增与查询；作为任务指派的对象来源 | 成员（`member`） |
| 任务管理 | 第 2、4 章 | 任务创建与指派、状态流转、查询 | 任务（`task`） |

> 两个模块**各自独立**：各有自己的数据与规则，**只有一处跨模块调用**（建任务时校验成员存在）。
> 这样成员名单的改动不会波及任务的历史数据。

## 5.3 页面与视图

| 页面 | 面向 | 内容 |
|---|---|---|
| 首页看板 | 全体（含受限用户） | 四个指标：成员总数 / 任务总数 / 进行中 / 已完成；以及**任务状态分布**（待办 / 进行中 / 已完成 三行计数）。指标口径与任务列表**同源**：状态分布之和 = 任务总数 |
| 成员管理 | 管理员（普通成员按授权） | 成员列表（编号/姓名/邮箱/角色）＋ 成员详情；新建成员 |
| 任务管理 | 管理员（普通成员按授权） | 任务列表（标题/指派/优先级/状态）＋ 筛选（状态、指派成员、优先级）＋ 分页；新建任务；行内状态流转（启动 / 完成 / 退回） |
| 流程总览 | 全体 | 一张图看清主链路（阶段与步骤节点），点节点进对应页面 |

**受限用户的表现**（第 2 章的执行面）：未授权的页面**不在侧栏出现**；直访未授权地址**回落到菜单首项**，
而不是渲染出空白页或报错。

## 5.4 数据流

```
管理员 ──建成员──▶ 成员名单（member）
                      ▲
                      │ 建任务时校验「成员存在吗」（唯一跨模块调用）
                      │
管理员 ──建任务──▶ 任务单（task，初始=待办）
                      │
                      ├─ start ──▶ 进行中 ── complete ──▶ 已完成（终态）
                      │                 │
                      │                 └─ reopen ──▶ 待办
                      │
普通成员 ◀──仅本人的任务（平台按数据范围过滤）
                      │
全体     ◀──看板/流程总览（跨两个模块的只读聚合）
```

## 5.5 运行节奏（本期）

| 事件 | 频率 | 触发方 |
|---|---|---|
| 建成员 | 按需 | 管理员手工 |
| 建任务并指派 | 按需 | 管理员手工 |
| 任务状态流转 | 按需 | 管理员或任务负责人手工 |
| 看板刷新 | 每次进入页面 | 页面自身（实时读两个模块） |

> 本期**没有定时任务、没有外部系统对接**（不像产销协同那样要对接 ERP）——
> 这是 e2e 样板组与真实业务组的最大差别，也是它适合当"最小参考实现"的原因。
