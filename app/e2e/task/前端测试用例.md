# 应用组 `e2e` · 任务管理 前端测试用例（任务管理）

> 产出技能：前端测试用例生成（第⑧步，规格 design-plus/前端测试.md）。
> 页面：`e2e:task`（route `#/task`；本文件全部用例针对本页）。输入：本应用前端详设 + `app/e2e/_contracts.md`。
> 可写应用：**仅 `create`**；契约**无** update / delete / import_batch → 无编辑入口、无删除按钮，
> 单据变更**只经状态机动作** `start` / `complete` / `reopen`（**本页验收重点**：行内按钮随状态收敛）。
> 本页无 `.kpi`（非看板页，§1 防粘滞断言的对象）；跨应用前置：负责人下拉与姓名回显依赖 `member` 主数据
> （§0 字典内含 member 造数，**本脚本自足**）。
> 执行：第⑨步翻译成 `app/e2e/tests/verify_view_e2e_task.py`（自包含：影子库隔离 → 起平台 → 登录 → 造数 → 断言 → 0 报错）。本步只生成、不运行。

## §0 测试数据字典（冻结 · 本脚本自足）

| 别名 | 类型 | 造数服务 | 关键参数 |
|---|---|---|---|
| M001 | 成员（负责人主数据 · 列表姓名回显） | member.create | member_no=M001, name=张管理, email=m001@example.com, role=admin |
| M002 | 成员（第二负责人 · 筛选抽样 + 表单指派） | member.create | member_no=M002, name=李成员, email=m002@example.com, role=member |
| D1 | 任务（**待办** · low · M001；模态/状态机锚点） | task.create | title=待办任务D1, description=D1 描述文本, assignee_member_no=M001, priority=low → status=待办 |
| D2 | 任务（**待办** · high · M002；优先级筛选命中） | task.create | title=待办任务D2, assignee_member_no=M002, priority=high → status=待办 |
| P1 | 任务（**进行中** · low · M001） | task.create + task.start | title=进行中任务P1, assignee_member_no=M001, priority=low → start → status=进行中 |
| F1 | 任务（**已完成** · high · M002；终态无动作按钮） | task.create + task.start + task.complete | title=已完成任务F1, assignee_member_no=M002, priority=high → 启动 → 完成 → status=已完成 |
| N1 | 任务（**表单创建落库回显**） | UI 表单提交 task.create | title=新任务N1, assignee_member_no=M002, priority=high, description=N1 表单创建描述 → status=待办 |

> 造数走**真实 REST**（pitfalls #18）：浏览器内 `fetch("POST /api/apps/e2e/task/call/<服务>")`，body 即参数对象（JSON），带会话 Cookie。
> **`task_no` 系统生成**（`T` + uuid，BR-7），**不可冻结** —— 字典冻结的是**标题 / 状态 / 优先级 / 负责人**四项；
> 脚本从造数返回值**捕获**四个 task_no（+ N1 从创建 toast 文案捕获）作为行/模态定位锚点
> （与后端 `测试用例.md` §0「单据号一律从返回值捕获，禁止硬编码」同口径）。
> `task.list` 返回项 = `{task_no, title, description, assignee_member_no, priority, status, created_at, updated_at}`；
> `get` / `create` / `start` / `complete` / `reopen` 载荷字段同集（全是 `task.get` 的字段子集）。
> **造数有前置序**：`task.create` 内部经 `member.get` 校验负责人存在性（BR-6），故 **member 必须先于 task 造**（§0 表序即造数序）。

## §3 模态全字段

- **VT-MODAL-01 详情模态（待办态 · 全字段 + 页脚「启动」）**
  - 页面: `e2e:task`
  - 前置造数: §0 D1（待办）
  - 操作: 点 D1 行 `.b-link` → `wait_modal()`（轮询 `.modal-mask:visible .loadbox` 消失，#16）
  - 断言: `.modal-bd`（第一个）含分组标题全集 [基本信息 / 指派信息 / 任务描述 / 时间信息]；
    字段标签全集 [任务编号 / 状态 / 标题 / 优先级 / 负责人编号 / 负责人姓名 / 创建时间 / 更新时间]；
    值含 task_no(D1) / 待办任务D1 / 待办 / low / M001 / 张管理 / D1 描述文本；
    头带 `.docno` **文本 == task_no**、副题 `.sub` 含「任务详情 · TASK DETAIL」（⚠ 与 psc 的「客户详情 · C001」写法不同，**按本页实现断言**）；
    `details.raw` 存在且**默认收起**；页脚 `.modal-ft` 可见按钮 = 【启动】（**不含**完成 / 退回）
  - 选择器注意: 本页有**两个** `.modal-mask`（详情 + 创建表单）各含一个 `.modal-bd` → 一律 `.modal-bd").first`（#15）；
    页脚按钮用 `x-show` 收敛，隐藏者在 DOM 中仍存在 → 计数须加 `:visible`（#14）；`.loadbox` 消失后再断言（#16）；
    **分组标题断在 `.sec`、字段标签/值断在 `.kv`**（描述值断在其 `.sec` 的下一兄弟 div）——
    不读整块 `.modal-bd`：底部 `details.raw` 的 JSON 含**全部字段值**，KV 渲染坏了也能"假过"
  - 行状态断言取**状态单元格**（第 3 列）而非整行文本：D1 标题「待办任务D1」含「待办」、P1 标题含「进行中」，
    用整行 `has_text` 判状态**恒真**

  - 页面: `e2e:task`

## §4 表单落库回显与状态机动作

- **VT-FORM-01 创建任务（模态表单 → 落库 → 列表 + 详情双回显）**
  - 页面: `e2e:task`
  - 前置造数: 无（表单自造 N1；依赖 §0 M002 已造作为指派对象）
  - 操作: 点「＋ 新建任务」→ 填 任务标题=`新任务N1` / 负责人下拉选 `M002` / 优先级下拉选 `high`
    → 点「更多字段 ▾」展开 → 填 任务描述=`N1 表单创建描述` → 点「创建任务」
  - 断言: toast 文案含「已创建任务 · T」（**单号从该 toast 文案捕获**，不硬编）；模态关闭；
    列表回显 N1 行 = [捕获的 task_no / 新任务N1 / **待办** / M002 / 李成员 / high / N1 表单创建描述]（新任务恒「待办」，BR-8）；
    重开 N1 详情，`.modal-bd` 含 新任务N1 / 待办 / high / M002 / 李成员 / N1 表单创建描述；「共 5 条」
  - 选择器注意: `description` 收在「更多字段 ▾」折叠区（`.collapse` → `.open`），**先点展再填**；
    提交按钮文案在忙碌期切「处理中…」防重复提交；提交成功会**重置三个过滤控件**（详设 §2.3）→ 新任务必可见；
    填字段用**模态内**选择器（`input[placeholder="必填 · 最多 200 字"]` / `textarea[placeholder="可选 · 最多 2000 字"]`）
    并断言恰 1 个 —— ⚠ **不要用「label + `following::input[1]`」那套定位**：XPath 的 `following::` 轴只受起点约束、
    **不受 scope 约束**，会顺文档序走出模态抓到壳里 Agent 栏的全局输入框（实测「填任务描述」卡 `element is not visible` 超时）

- **VT-FORM-02 创建必填校验（前端拦 · 不发请求）**
  - 页面: `e2e:task`
  - 前置造数: 无
  - 操作: 点「＋ 新建任务」→ 标题留空（其余默认）→ 点「创建任务」
  - 断言: toast 警告「请填写任务标题」；模态**保持打开**；全程**不发出** `POST /api/apps/e2e/task/call/create` 请求
  - 选择器注意: 必填仅前端拦（标题 → 负责人 → 优先级 顺序校验，详设 §2.3）；请求断言用 `page.on("request")` 挂/卸监听；
    关闭用「取消」而非 Esc（模态 `@keydown.escape` 也在，但按钮路径更稳）

- **VT-STATE-01 行内动作按钮随状态收敛（三态矩阵）**
  - 页面: `e2e:task`
  - 前置造数: §0 D1（待办）/ P1（进行中）/ F1（已完成）
  - 操作: 复位全部过滤后，逐行扫操作列（不点任何按钮）
  - 断言: D1 行（待办）**可见**按钮 = 【启动】，【完成】【退回】不可见；
    P1 行（进行中）**可见**按钮 = 【完成】【退回】，【启动】不可见；
    F1 行（已完成）**可见**动作按钮数 == 0（BR-13）
  - 选择器注意: 操作列按钮全部 `x-show` 绑定（详设 §5.1）→ 行内计数一律 `button:visible:has-text("…")`（#14）；
    行定位用精确 task_no 的 `tr.data:has-text(...)`（#17）

- **VT-STATE-02 启动（待办 → 进行中）**
  - 页面: `e2e:task`
  - 前置造数: 依赖 §0 D1 仍为待办（本段须在 §3/§4 之前的状态上跑，或使用未被流转过的任务）
  - 操作: 点 D1 行【启动】
  - 断言: toast「已启动 · <D1 单号>」；D1 行状态徽章变「进行中」；该行可见按钮随之变【完成】【退回】（【启动】消失）；
    「共 5 条」不变（流转不改条数）
  - 选择器注意: 动作成功后页面 `list.load(当前页)` 重载 → 断言用**轮询行文本**（重载是异步的，直接读会读到旧行）

- **VT-STATE-03 完成（进行中 → 已完成 · 终态）**
  - 页面: `e2e:task`
  - 前置造数: 依赖 VT-STATE-02 后的 D1（进行中）
  - 操作: 点 D1 行【完成】
  - 断言: toast「已完成 · <D1 单号>」；D1 行状态变「已完成」；该行**可见动作按钮数 == 0**（终态，BR-13）
  - 选择器注意: 同 VT-STATE-02 的轮询；终态用 `:visible` 计数为 0（#14）

- **VT-STATE-04 退回（进行中 → 待办）**
  - 页面: `e2e:task`
  - 前置造数: §0 P1（进行中 · 未被本会话流转过）
  - 操作: 点 P1 行【退回】
  - 断言: toast「已退回 · <P1 单号>」；P1 行状态变「待办」；该行可见按钮变回【启动】；
    此后 chips「待办」筛选应含 P1（退回后回到待办池，BR-12）
  - 选择器注意: `reopen` 只允许 进行中 → 待办（**不是**已完成 → 待办，已完成是终态 BR-13）；
    筛选断言后复位 chips
  - ⚠ **状态机三态断言的等待纪律**（2026-09-18 补，VT-STATE-01~04 通用）：
    **必须轮询「按钮本身」再断按钮**，不能"等状态文本、断按钮"—— 那是两处独立绑定、不在同一拍上重渲染。
    踩过的表现：单跑必过、**全量套件并跑必红**，且报错自相矛盾（`应变回【启动】，实际 ['启动']`，
    因为断言与拼错误信息各读了一次 DOM）。脚本侧已落成 `wait_buttons(row, expect)`；
    正本记在 `design-plus/view-convention/pitfalls.md` #42

## §6 0 报错红线（本会话）

- **VT-ERR-01 全程 0 报错 + 豁免受检**
  - 断言: 本会话（登录 → 造数 → 渲染 → 筛选 → 模态 → 表单 → 状态机）全程 `console error == 0` · `pageerror == 0` · `HTTP ≥ 400 == 0`（favicon / `.map` 除外）
  - 选择器注意: `ignored` 收集到的豁免项**必须逐条受检**（只认 `/favicon.ico` 与 `.map` 两种理由）——

## §7 待确认（如有）

> ✅ **2026-09-17 已修**：`member`/`task` 的分页形参已统一改名 **`size`**（与平台基座 `pageable()` 及 PSC 全组一致）、`task/view.js` 里显式传的 `page_size: 200` 也一并改掉、契约已重冻。**下面这段保留作历史记录** —— 它示范了「声明了但收不到」这一类：`_coerce` 静默忽略未知键，参数名一错就**没有任何报错**。
>
1. **`pageable` 回传 `size` vs 契约 `page_size`（实现 ↔ 契约漂移，2026-09-17 实测）**：`view.js` 的列表加载器
   `pageable(async (q) => svc("task","list",{…过滤…, ...q}))`，而 `view/lib/shell.js` 的 `pageable.load()` 回传 `{page, size}` ——
   契约声明的是 `page/page_size`。后端 `web.py::_coerce` **对未知键静默忽略**，故 `size` 被丢弃、`page_size` 走服务默认（100）。
   本页 4–5 条数据不受影响（分页条恒 1 页），但**契约声明的 `page_size` 实际从未生效**；前端详设 §2.1「契约签名 string 型，照传即可」
   与实现不符。全平台 `pageable` 页（psc 亦然）同此形态，属平台基座口径而非本页独有 → 本脚本**不断言分页翻页**，此处只登记。
