# 成员主数据应用（member）— 用户需求规格说明书

- **应用名**：`member`
- **聚合根类名**：`Member`
- **实体标识**：`member_no`
- **是否主数据**：是
- **聚合根卡来源**：《架构设计：成员任务管理（e2e）》§2.1 `member` / `Member`
- **一句话职责**：维护成员主数据，提供成员创建、查询与列表能力，作为任务指派对象的基础数据来源。

---

## §1 需求概览

### 1.1 基本信息

| 项目 | 内容 |
|---|---|
| 需求名称 | 成员主数据管理 |
| 所属模块 | 成员任务管理（e2e） |
| 应用 | `member` |
| 聚合根 | `Member` |
| 优先级 | 高 |
| 构建批次 | 批次 1：地基主数据 |

### 1.2 需求背景

在成员任务管理场景中，任务单据必须指派到具体成员。为保证任务创建、查询与流转过程中的指派对象可信、可引用，需要先建立成员主数据应用 `member`，统一管理成员编号、姓名、邮箱与角色信息。

`member` 作为基础主数据应用，不承载任务状态流转，不处理认证登录，不维护组织架构，仅负责成员主数据的创建与只读查询能力。

### 1.3 需求范围

#### 1.3.1 包含范围

本应用包含以下能力：

1. 创建成员主数据。
2. 按成员编号查询单个成员。
3. 按关键字、角色条件查询成员列表。
4. 为任务应用提供成员存在性校验所需的基础查询服务。
5. 维护成员基础属性：成员编号、姓名、邮箱、角色。

#### 1.3.2 不包含范围

本应用不包含以下能力：

1. 不包含成员登录、认证、鉴权令牌发放。
2. 不包含成员密码、账号安全、会话管理。
3. 不包含组织架构、部门、上下级关系管理。
4. 不包含成员修改、停用、删除能力；业务未提供，默认不开放。
5. 不包含任务创建、任务指派、任务状态流转。
6. 不包含消息通知、邮件发送。
7. 不包含文件上传、成员头像管理。

### 1.4 涉及角色

| 角色 | 说明 |
|---|---|
| `admin` | 成员管理员，可创建成员、查询成员列表与详情。 |
| `member` | 普通成员，可查询成员列表与详情，用于协作与任务指派选择。 |
| 系统服务 / 任务应用 | `task` 应用在创建任务时通过平台服务调用 `member.get`，校验指派成员是否存在。 |

> 权限控制由 FDE 平台统一实现，`member` 应用本身不进行鉴权。

## §2 用户故事

### US-1 创建成员

**故事描述**：  
作为成员管理员，我希望能够创建成员主数据，以便后续任务可以指派给该成员。

**独立测试方式**：  
准备一组合法成员信息，调用 `member.create`，验证成员创建成功；再使用非法参数调用，验证系统返回 `FdeError`。

**前置条件**：

1. 平台已部署 `member` 应用。
2. 调用方具备创建成员权限。
3. 待创建成员编号未被占用。

**后置条件**：

1. 成员主数据持久化成功。
2. 成员编号全局唯一。
3. 后续可通过 `member.get` 查询该成员。
4. 后续任务应用可引用该成员编号进行任务指派。

#### US-1-AC1 合法参数创建成员成功

**Given** 成员编号 `M001` 尚未存在  
**When** 调用 `member.create(member_no="M001", name="张三", email="zhangsan@example.com", role="member")`  
**Then** 系统创建成员成功  
**And** 返回成员信息包含 `member_no="M001"`、`name="张三"`、`email="zhangsan@example.com"`、`role="member"`

#### US-1-AC2 成员编号为空创建失败

**Given** 调用方提交成员创建请求  
**When** 调用 `member.create(member_no="", name="张三", email="zhangsan@example.com", role="member")`  
**Then** 系统抛出 `FdeError`  
**And** 错误信息说明 `member_no` 必填

#### US-1-AC3 成员编号重复创建失败

**Given** 成员编号 `M001` 已存在  
**When** 再次调用 `member.create(member_no="M001", name="李四", email="lisi@example.com", role="member")`  
**Then** 系统抛出 `FdeError`  
**And** 错误信息说明成员编号已存在

#### US-1-AC4 成员角色非法创建失败

**Given** 调用方提交非法角色 `superuser`  
**When** 调用 `member.create(member_no="M002", name="李四", email="lisi@example.com", role="superuser")`  
**Then** 系统抛出 `FdeError`  
**And** 错误信息说明角色只能为 `admin` 或 `member`

#### US-1-AC5 邮箱格式非法创建失败

**Given** 调用方提交非法邮箱 `zhangsan.example.com`  
**When** 调用 `member.create(member_no="M003", name="张三", email="zhangsan.example.com", role="member")`  
**Then** 系统抛出 `FdeError`  
**And** 错误信息说明邮箱格式非法

### US-2 查询成员详情

**故事描述**：  
作为普通成员或任务应用，我希望能够按成员编号查询成员详情，以便确认成员是否存在并获取成员基础信息。

**独立测试方式**：  
先创建成员，再调用 `member.get` 验证可查询成功；使用不存在成员编号调用，验证抛出 `FdeError`。

**前置条件**：

1. `member` 应用已存在至少一个成员，或测试前创建成员。
2. 调用方具备查询成员权限。

**后置条件**：

1. 查询成功时返回完整成员信息。
2. 查询失败时抛出 `FdeError`，不返回空对象。

#### US-2-AC1 按存在成员编号查询成功

**Given** 成员 `M001` 已存在  
**When** 调用 `member.get(member_no="M001")`  
**Then** 系统返回成员详情  
**And** 返回结果包含 `member_no="M001"`、`name`、`email`、`role`

#### US-2-AC2 按不存在成员编号查询失败

**Given** 成员 `M999` 不存在  
**When** 调用 `member.get(member_no="M999")`  
**Then** 系统抛出 `FdeError`  
**And** 错误信息说明成员不存在

#### US-2-AC3 成员编号为空查询失败

**Given** 调用方请求查询成员详情  
**When** 调用 `member.get(member_no="")`  
**Then** 系统抛出 `FdeError`  
**And** 错误信息说明 `member_no` 必填

---

### US-3 查询成员列表

**故事描述**：  
作为成员管理员或普通成员，我希望能够按关键字或角色查询成员列表，以便选择任务指派对象或查看成员主数据。

**独立测试方式**：  
准备多个成员数据，分别使用关键字、角色、组合条件调用 `member.list`，验证返回结果符合过滤规则。

**前置条件**：

1. `member` 应用已存在若干成员数据。
2. 调用方具备查询成员列表权限。

**后置条件**：

1. 查询成功时返回成员列表。
2. 无匹配数据时返回空列表，不抛错。
3. 角色参数非法时抛出 `FdeError`。

#### US-3-AC1 无条件查询全部成员

**Given** 系统中存在成员 `M001`、`M002`  
**When** 调用 `member.list()`  
**Then** 系统返回成员列表  
**And** 列表包含 `M001`、`M002`

#### US-3-AC2 按关键字查询成员

**Given** 系统中存在成员 `member_no="M001", name="张三", email="zhangsan@example.com"`  
**When** 调用 `member.list(keyword="张三")`  
**Then** 系统返回包含 `M001` 的成员列表

#### US-3-AC3 按角色查询成员

**Given** 系统中存在管理员成员 `M001` 和普通成员 `M002`  
**When** 调用 `member.list(role="admin")`  
**Then** 系统返回仅包含管理员成员的列表  
**And** 列表不包含 `role="member"` 的成员

#### US-3-AC4 关键字与角色组合查询

**Given** 系统中存在多个成员，其中 `M001` 为 `admin` 且姓名包含“张三”  
**When** 调用 `member.list(keyword="张三", role="admin")`  
**Then** 系统返回同时满足关键字与角色条件的成员列表

#### US-3-AC5 角色参数非法查询失败

**Given** 调用方提交非法角色 `superuser`  
**When** 调用 `member.list(role="superuser")`  
**Then** 系统抛出 `FdeError`  
**And** 错误信息说明角色只能为 `admin` 或 `member`

#### US-3-AC6 无匹配数据返回空列表

**Given** 系统中不存在姓名、邮箱或成员编号包含 `NotExist` 的成员  
**When** 调用 `member.list(keyword="NotExist")`  
**Then** 系统返回空列表  
**And** 不抛出异常

## §3 业务场景

### 3.1 成员主数据创建流程

1. 成员管理员提交成员创建请求。
2. `member` 应用校验成员编号、姓名、邮箱、角色等基础信息。
3. 校验通过后，将成员主数据持久化。
4. 创建成功后，成员可被任务应用引用。

### 3.2 任务指派前成员校验流程

1. `task` 应用创建任务时，请求中携带 `assignee_member_no`。
2. `task.create` 通过 `self.fde.call` 调用 `member.get`。
3. `member.get` 返回成员详情，表示成员存在。
4. `task` 应用继续创建任务。
5. 若 `member.get` 抛出 `FdeError`，`task` 应用终止任务创建。

### 3.3 成员列表查询流程

1. 调用方提交可选查询条件：`keyword`、`role`。
2. `member` 应用校验角色参数合法性。
3. `member` 应用根据条件过滤成员数据。
4. 返回符合条件的成员列表。

### 3.4 业务规则

> 以下业务规则均为可校验规则。除特别说明外，违反规则时系统抛出 `FdeError`。

| 规则编号 | 规则描述 | 违反处理 |
|---|---|---|
| `BR-1` | `member_no` 必填，不能为空字符串或 `null`。 | 抛 `FdeError` |
| `BR-2` | `member_no` 全局唯一，不允许重复创建。 | 抛 `FdeError` |
| `BR-3` | `name` 必填，不能为空字符串或 `null`。 | 抛 `FdeError` |
| `BR-4` | `email` 必填，不能为空字符串或 `null`。 | 抛 `FdeError` |
| `BR-5` | `email` 必须符合基本邮箱格式，至少包含 `@` 与域名部分。 | 抛 `FdeError` |
| `BR-6` | `role` 必填，且取值只能为 `admin` 或 `member`。 | 抛 `FdeError` |
| `BR-7` | `member.get` 查询时，`member_no` 必填。 | 抛 `FdeError` |
| `BR-8` | `member.get` 查询不到成员时，视为业务异常。 | 抛 `FdeError` |
| `BR-9` | `member.list` 查询时，若传入 `role`，必须为 `admin` 或 `member`。 | 抛 `FdeError` |
| `BR-10` | `member.list` 查询无匹配结果时返回空列表，不视为异常。 | 正常返回空列表 |
| `BR-11` | 成员创建后，默认不开放修改、删除、停用能力。 | 未定义写操作由平台拒绝；如触发非法写操作，抛 `FdeError` |
| `BR-12` | `member` 应用不主动调用其他应用服务。 | 不适用 |
| `BR-13` | `task.create` 可调用 `member.get` 校验成员存在性。 | 成员不存在时由 `member.get` 抛 `FdeError` |

### 3.5 状态机

`member` 为主数据应用，无业务状态机。

```text
无状态流转
```

## §4 功能清单 + 字段表

### 4.1 功能清单

| 功能编号 | 功能名称 | 对应服务 | 说明 |
|---|---|---|---|
| `FUNC-1` | 创建成员 | `member.create` | 创建成员主数据。 |
| `FUNC-2` | 查询成员详情 | `member.get` | 按成员编号查询成员。 |
| `FUNC-3` | 查询成员列表 | `member.list` | 按关键字、角色查询成员列表。 |

### 4.2 实体字段表：`Member`

> 本表直接作为 `_init_db` 建表依据。

**表名**：`member`

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `member_no` | `TEXT` | `PRIMARY KEY`，`NOT NULL` | 成员编号，唯一标识，创建后不可变更。 |
| `name` | `TEXT` | `NOT NULL` | 成员姓名。 |
| `email` | `TEXT` | `NOT NULL`，`UNIQUE` | 成员邮箱，全局唯一，应用层校验邮箱格式。 |
| `role` | `TEXT` | `NOT NULL`，`CHECK (role IN ('admin', 'member'))` | 成员角色，取值 `admin` / `member`。 |
| `created_at` | `TIMESTAMP` | `NOT NULL`，`DEFAULT CURRENT_TIMESTAMP` | 创建时间，由平台或数据库默认生成。 |

### 4.3 字段补充说明

1. `member_no` 为业务主键，不使用自增 ID。
2. `email` 设置唯一约束，避免同一邮箱重复注册为多个成员。
3. `role` 使用文本枚举存储，数据库层通过 `CHECK` 约束限制取值。
4. `created_at` 用于审计与排序，不参与业务规则判断。
5. 本表不包含 `updated_at`，因为成员主数据默认不开放修改。

### 4.4 对外服务签名

#### 4.4.1 `member.create`

```text
member.create(member_no: str, name: str, email: str, role: str) -> dict
```

**参数说明**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `member_no` | `str` | 是 | 成员编号，全局唯一。 |
| `name` | `str` | 是 | 成员姓名。 |
| `email` | `str` | 是 | 成员邮箱。 |
| `role` | `str` | 是 | 成员角色，取值 `admin` / `member`。 |

**返回**：

```json
{
  "member_no": "M001",
  "name": "张三",
  "email": "zhangsan@example.com",
  "role": "member"
}
```

**异常**：

1. `member_no` 为空：抛 `FdeError`。
2. `member_no` 已存在：抛 `FdeError`。
3. `name` 为空：抛 `FdeError`。
4. `email` 为空：抛 `FdeError`。
5. `email` 格式非法：抛 `FdeError`。
6. `role` 非法：抛 `FdeError`。

---

#### 4.4.2 `member.get`

```text
member.get(member_no: str) -> dict
```

**参数说明**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `member_no` | `str` | 是 | 成员编号。 |

**返回**：

```json
{
  "member_no": "M001",
  "name": "张三",
  "email": "zhangsan@example.com",
  "role": "member"
}
```

**异常**：

1. `member_no` 为空：抛 `FdeError`。
2. 成员不存在：抛 `FdeError`。

---

#### 4.4.3 `member.list`

```text
member.list(keyword: str | None = None, role: str | None = None) -> list[dict]
```

**参数说明**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `keyword` | `str \| None` | 否 | 关键字，模糊匹配 `member_no`、`name`、`email`。 |
| `role` | `str \| None` | 否 | 角色过滤，取值 `admin` / `member`。 |

**返回**：

```json
[
  {
    "member_no": "M001",
    "name": "张三",
    "email": "zhangsan@example.com",
    "role": "member"
  }
]
```

**查询规则**：

1. `keyword` 为空时，不按关键字过滤。
2. `role` 为空时，不按角色过滤。
3. `keyword` 非空时，匹配以下任一字段即视为命中：
   - `member_no`
   - `name`
   - `email`
4. `keyword` 与 `role` 同时存在时，取交集。
5. 无匹配结果时返回空数组。

**异常**：

1. `role` 非空且不在 `admin` / `member` 范围内：抛 `FdeError`。

### 4.5 跨应用依赖

#### 4.5.1 本应用主动调用

`member` 应用无主动跨应用调用。

```text
无 self.fde.call 依赖
```

#### 4.5.2 本应用被其他应用调用

| 调用方应用 | 调用方操作 | 被调应用.服务 | 用途 |
|---|---|---|---|
| `task` | `task.create` | `member.get` | 校验任务指派成员是否存在。 |

## §5 权限矩阵

> 以下权限仅为需求描述。实际鉴权由 FDE 平台统一实现，`member` 应用不承担权限判断职责。

| 权限编号 | 角色 | 功能 / 数据 | 操作 | 说明 |
|---|---|---|---|---|
| `PERM-1` | `admin` | `member.create` | 允许 | 成员管理员可创建成员主数据。 |
| `PERM-2` | `admin` | `member.get` | 允许 | 成员管理员可查询任意成员详情。 |
| `PERM-3` | `admin` | `member.list` | 允许 | 成员管理员可查询成员列表。 |
| `PERM-4` | `member` | `member.get` | 允许 | 普通成员可查询成员详情，用于协作与任务查看。 |
| `PERM-5` | `member` | `member.list` | 允许 | 普通成员可查询成员列表，用于选择任务指派对象。 |
| `PERM-6` | `member` | `member.create` | 禁止 | 普通成员不可创建成员。 |
| `PERM-7` | 系统服务 / `task` 应用 | `member.get` | 允许 | 任务应用创建任务时校验成员存在性。 |
| `PERM-8` | 系统服务 / `task` 应用 | `member.list` | 允许 | 任务应用可在指派成员选择场景查询成员列表。 |
| `PERM-9` | 未认证调用方 | 全部功能 | 禁止 | 未通过平台认证的调用方不可访问。 |
