# member 前端详设

> 来源：app/e2e/_contracts.md（冻结契约）+ app/e2e/member/应用详设.md；产出供 fde-view-testgen（步骤8）/ fde-view-gen（步骤9）
> 落地文件：`app/e2e/member/view.js` + `app/e2e/member/view.html`（与 `member.py` 同文件夹，落盘即进启动清单与授权清单，零接线）
> 页面定位：**主数据页，只有「创建 + 查」**——后端不开放 update / delete / 停用（BR-11），故解剖结构裁剪为：列表区 + 详情模态 + 创建表单，**无编辑入口、无行内操作列**；角色为静态二值枚举 `admin` / `member`。

## 2. 区块构成

### 2.1 列表区（查）

**用途**：成员主数据全量浏览 + 条件检索 + 新建入口。本页为非看板页，**不设 KPI 指标带**（验收断言无 `.kpi`）。

**列表列**（`.tbl.tight`；列 = 详情字段子集，字段序与详情/表单一致）：

| 列 | 来源字段 | 渲染 |
|---|---|---|
| 成员编号 | `member_no` | `.b-link`，点击打开详情模态 |
| 姓名 | `name` | 文本 |
| 邮箱 | `email` | 文本 |
| 角色 | `role` | 徽章 `hue(role)`，文案映射 `admin→管理员` / `member→成员` |
| 创建时间 | `created_at` | `fmtTime()`；若 list 项未含则 `dash()` 兜底 |

**过滤区**（与 `member.list` 可过滤参数一一对应，不自造前端假过滤）：

| 控件 | 对应参数 | 形态 |
|---|---|---|
| 关键字输入框 | `keyword` | placeholder「编号 / 姓名 / 邮箱」，Enter 或「查询」按钮触发（后端模糊匹配 member_no/name/email） |
| 角色 chips | `role` | `全部` / `管理员(admin)` / `成员(member)`，单选互斥，点击即查 |
| 分页条 | `page`, `page_size` | `pageable()`，**integer 传参**（契约类型） |

**工具栏**：「查询」「+ 新建成员」（打开 2.3 创建模态）。**无操作列**——BR-11 不开放改/删/停用，行内无任何动作按钮。

### 2.2 详情模态（查全）

**用途**：点编号弹出，展示 `member.get()` 全部字段。沿用模态三段式：

- **头带**：墨青头带 + 标题「成员详情 · M001」+ **角色徽章**（本应用无状态机，以角色徽章充当头带状态位）。
- **体（`.kv` 按语义分 `.sec`）**：
  - `.sec` 基本信息：成员编号 `member_no`、姓名 `name`
  - `.sec` 联系方式：邮箱 `email`
  - `.sec` 角色权限：角色 `role`（徽章着色）
  - `.sec` 审计信息：创建时间 `created_at`（`fmtTime()`；审计字段允许展示，仅不进表单）
  - 底部折叠「原始数据」：`get()` 完整返回 JSON（默认收起）
- **页脚 `.modal-ft`**：仅「关闭」按钮（无写操作可放）。

### 2.3 创建表单（增）——模态

**用途**：覆盖 `member.create` 的全部 4 个业务参数。**4 项全必填 → 不设「更多字段 ▾」折叠区**；后端无 update/set_*/import_batch → **无编辑态、无 `mode='edit'`**（BR-11）。

| 字段 | 控件 | 必填 | 校验 / 提示 |
|---|---|---|---|
| 成员编号 `member_no` | text，placeholder「如 M001」 | ★ | 提示「创建后不可变更 · 全局唯一」 |
| 姓名 `name` | text | ★ | — |
| 邮箱 `email` | email 输入，placeholder「name@example.com」 | ★ | 提示「全局唯一」；格式校验在后端 |
| 角色 `role` | select，选项 `member=成员`（默认）/ `admin=管理员` | ★ | 选项值与后端 CHECK 完全一致（`admin`/`member`） |

布局：必填先行、按语义分组 `frow`——第一行（成员编号 + 姓名）、第二行（邮箱 + 角色）；底部右对齐「取消」「创建」。前端仅做必填校验（空值 → toast 警告、不提交）；**邮箱格式、编号/邮箱唯一性、角色合法性全部由后端校验**，`FdeError` 经 api.js 以错误 toast 呈现。

## 3. svc 字面量清单（授权派生依据——必须字面量 `svc("应用","服务")`）

| 区块 | 调用（应用.服务） | 参数 | 说明 |
|---|---|---|---|
| 列表区 | `svc("member","list")` | `keyword, role, page, page_size` | 分页查询成员列表；过滤控件与参数一一对应 |
| 详情模态 | `svc("member","get")` | `member_no` | 点编号拉取全量字段渲染 kv |
| 创建表单 | `svc("member","create")` | `member_no, name, email, role` | 新建成员主数据 |

> 三处调用在 view.js 中逐项以字面量书写（可包在闭包里），**严禁变量拼名**——这是隐式放行派生扫描的唯一来源。

## 4. 数据来源与下拉

- **无跨应用主数据下拉**：`member` 不主动外调（BR-12），本页不依赖 task 或其他应用，故无需 quiet 探测性拉取下拉；角色选项为**静态枚举**（来源：应用详设 BR-6 / 建表 CHECK），不经 svc。
- **契约 payload → 区块字段映射**：

| 契约 | 载荷字段 | 映射区块 |
|---|---|---|
| `member.list` 返回项 | `member_no, name, email, role, created_at` | 2.1 列表列 |
| `member.get` 返回 | `member_no, name, email, role, created_at` | 2.2 详情模态 kv + 原始数据 |
| `member.create` 入参 | `member_no, name, email, role` | 2.3 创建表单（`created_at` 为审计/库默认生成，不进表单） |

- 注：`_contracts.md` 中 member 返回示例标注「暂无数据 —— 字段读源码 get()/INSERT」，字段集以应用详设 §4.2 实体字段表为准（`SELECT *` 含 `created_at`）；`list` 的 `page/page_size` 契约类型为 **integer**。

## 5. 交互要点

- **加载**：首载正常拉取 list（非看板页，失败喷 toast，区别于看板的 quiet 探测）；列表重载期间沿用 CRM 参考实现的加载态；详情模态 `get()` 期间体显加载、完成后渲染。
- **过滤**：角色 chips 点击即查并重置 `page=1`；keyword 以 Enter/「查询」触发；翻页仅改 `page/page_size`，不清过滤条件。
- **微交互**（全部使用 `styles.css` 既有类，不新增组件）：表格行 hover 高亮；编号 `.b-link` hover 下划线；角色徽章 `hue()` 着色；「创建」按钮提交期 loading 防重复点击。
- **成功流**：创建成功 → 关闭模态并清空表单 → toast「成员 M001 创建成功」→ 列表保留 keyword/role 过滤、回第 1 页重载。
- **错误流**：重复编号 / 非法邮箱等后端 `FdeError` → toast 错误信息，创建模态保持打开便于修改后重试。
- **空态**：无任何成员时「暂无成员 —— 点『新建成员』创建」；过滤无命中时「无符合条件的成员」（BR-10 空列表不抛错）。
- **原始数据**折叠默认收起；`created_at` 等审计信息详情可见、表单不收。

## 6. 验收关注点（供 fde-view-testgen）

- **路由渲染**：`#/member` 挂载成功，页面含成员列表表格；**断言无 `.kpi`**（非看板页防挂载粘滞假过）。
- **造数回显**：REST 创建 `M001 张三 zhangsan@example.com member`、`M002 李四 li@e2e.dev admin` 后，列表 2 行，编号/姓名/邮箱/角色徽章/创建时间齐全。
- **过滤与分页**：`keyword=张` → 命中 M001；角色 chips 选 `admin` → 仅 M002；组合 `keyword=张 + role=member` → 仅 M001；`keyword=NotExist` → 空列表且不报错（BR-10）；请求实际携带 `page/page_size`（integer）。
- **模态全字段**：点 M001 编号 → 模态含 `member_no / name / email / role / created_at` 五字段 + 「原始数据」JSON。
- **表单完备性**：创建模态含 4 项输入，`role` select 选项恰为 `admin` / `member`；必填项红星齐全。
- **写落库**：UI 新建 `M003` → 成功 toast → 列表可见该行 → `member.get` 回显与表单一致。
- **负向路径**（建议手工验证，自动化 happy path 保持 0 HTTP≥400）：重复 `member_no` 创建 → 错误 toast；非法邮箱 → 错误 toast；UI 无法提交非法 role（select 收敛）。
- **会话基线**：全程 0 console error / 0 pageerror / 0 非预期 HTTP≥400；受限用户菜单收敛与直访回落由壳层统一断言，本页无任何鉴权实现。
