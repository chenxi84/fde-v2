## 2. 区块构成

### 2.1 KPI 指标带

一排 `.kpi` 卡片（每卡「数字 `.v` + 中文标签 `.k`」），**恒 4 张**：

| 卡片 | 指标 | svc 探测 | 取值 |
|---|---|---|---|
| 成员总数 | `member.list` 的 `total` | `member.list({})` | `total` |
| 任务总数 | `task.list` 的 `total` | `task.list({})` | `total` |
| 进行中任务 | `task.items` 里 `status == 进行中` 的行数 | 复用同一次 `task.list` | 客户端统计 |
| 已完成任务 | `task.items` 里 `status == 已完成` 的行数 | 复用同一次 `task.list` | 客户端统计 |

> ⚠ **本页的 `task.list({})`（不带 `page`/`size`）依赖「不分页也返回 `{total, items}`」** ——
> 2026-09-18 前 `task.list` 在这个分支返回**裸数组**，本页按 `{total, items}` 取值 ⇒
> 上面三张卡与下方状态分布**恒 0**（详设与代码同源同错，被 `0 == 0` 的组级断言放行）。
> 后端已按 CONVENTION §7 统一为 `{"total","items"}`；本页**不做**裸数组兜底 ——
> 兜底会让下一个违约者继续蒙混，取值口径必须与契约一致。

- 两次探测用 `Promise.all` 并发；任一失败 → `catch(() => ({total: 0, items: []}))` ⇒ **零值兜底**。
- 无数据时数字显示 `0`（数量型指标语义为 0，**不显示 `—`**）。

### 2.2 任务状态分布

一个 `.overline` 标题（「任务状态分布」）+ 一个 `.pipe` 容器，内含 **2 个 `.pipe-col`**：

| `.pipe-col` | 标题 | 内容 |
|---|---|---|
| ① | `☑ 任务 · 按状态` | 三行 `.sline`：每行一个 `.st` 状态徽章（`待办 / 进行中 / 已完成`，`hue()` 上色）+ `<b>` 计数 |
| ② | `👥 成员主数据` | 说明性文字两行（「创建后只读 · 供任务指派」「详见左侧菜单『成员管理』」） |

- 状态计数与 KPI 的「进行中/已完成」**同源**（都来自那一次 `task.list`）⇒ 两者必然一致（可对账）。

## 3. 字段映射（契约 → 页面）

| 契约字段 | 来源服务 | 展示位置 | 说明 |
|---|---|---|---|
| `total` | `member.list` | KPI「成员总数」`.v`、**第 2 个** `.pipe-col`（成员主数据）右上角 `.right.mono` | 两处同值 |
| `total` | `task.list` | KPI「任务总数」`.v`、**第 1 个** `.pipe-col`（任务·按状态）右上角 `.right.mono` | 两处同值 |
| `items[].status` | `task.list` | 状态分布的 `.st` + 计数 | 客户端按 `status` 分组计数，**未识别的状态不新增列**（只听 `待办/进行中/已完成`） |

> ⚠ **两个 `.pipe-col` 各有一个 `.right.mono`**（第 1 个 = 任务总数、第 2 个 = 成员总数，见 `dashboard.html`）。
> 写用例/断言时**必须指明是第几个** —— 只写"状态分布右上角的那个数"会让「任务」与「成员」两列混为一谈，
> 这正是 2026-09-18 修掉的那个 `0 == 0` 恒真断言的成因之一。

> 本页**不展示** `member` / `task` 的任何明细字段（无表格、无模态）—— 明细在各自应用页。

## 4. svc 清单（全字面量）

```js
svc("member", "list", {}, { quiet: true })     // KPI 成员总数
svc("task",   "list", {}, { quiet: true })     // KPI 任务总数 + 状态分布
```

- **必须字面量**：后端靠扫描前端源码里的字面量派生「页 → 服务」的隐式放行边；变量拼名会让受限会话 403。
- `quiet: true`：探测失败不弹 toast（本页对受限用户恒显，无权限时静默落零值）。

## 5. 验收关注点（供第⑧步写用例）

1. **渲染**：`#/dashboard` 落地即可见；`.kpi` 数 **== 4**（与逐应用页「`.kpi` == 0 防粘滞」互为镜像）。
2. **零值兜底**：空库时 4 张 KPI 均显示 `0`、状态分布三行计数为 0，**且 0 报错**（不喷 toast）。
3. **一致性**：KPI「任务总数」 == 第 1 个 `.right.mono`（**任务**列）、KPI「成员总数」 == 第 2 个 `.right.mono`（**成员**列）——
   逐列对账，不做"某一个数"的模糊比对；
   状态分布三行计数之和 == 任务总数（当所有任务状态都合法时）；
   且**造数必须让这些数互不相同**（如 1 成员 + 3 任务 = `1/3/1/1`）—— 否则 `0 == 0`、`1 == 1` 之类的恒真断言会把真缺陷放行。
4. **跳转**：本页 KPI 不做点击跳转（与 PSC 看板不同）—— 明细经左侧菜单进入。

## 6. 组级第二页：流程总览（`process`）

> e2e 的组级页有两张：`dashboard`（本节以上）与 `process`（本组**范式演示页**）。
> 它的设计要点同样落在这里，供第⑧步一起写用例。

| 字段 | 值 |
|---|---|
| key / name / order | `process` / 流程总览 / 15 |
| title / crumb | 流程总览 / 数据驱动 SVG 流程图 |
| svc 清单 | **无**（硬编码一条 3 阶段链路，**不聚合任何后端服务**） |

**区块**：一张 `.card`（`padding:0`）+ `.tagline` 标题行 + `.scroll-x` 容器，内含

- `.loadbox`（`x-show="loading"` 的载入态，加载结束消失）；
- `div[@click="onSvgClick($event)"]` 内 **`x-html` 注入的 SVG**：每个可点节点带 **`g[data-page]`**
  （阶段胶囊 + 步骤节点，数量由 `computeLayout()` 决定，硬编码链路 ⇒ **常量**）；
- 底部**图例**一行（`绿 已完成 / 灰 未开始 · 点击节点进入对应页面`）。

**范式要点**（正本 `design-plus/view-convention/patterns.md` §8）：SVG **不在模板里用 `x-for`**，
而在 JS 拼字符串 + `x-html` 注入；点击用 **`data-page` 事件委托**；坐标在 `computeLayout()` 里算；
连线为正交直角 `elbow` + 横向箭头 `hArrow`；暗色主题。

**验收关注点**：① 路由 `#/process` 渲染出 `main svg g[data-page]`（数量 == 硬编码链路的节点数）；
② 载入态 `.loadbox` 消失后再断言（防抢跑）；③ 点击某节点 → 跳到其 `data-page` 对应的页面 key；
④ 本页 0 报错（它不发任何 svc，报错只可能来自壳）。
